# 题目审核技能

> 行为约束（思考控制、红线）定义在 agents/review.md。
> 本文件定义审核的三项定性评估 + 输出格式。

## 审核定位

你审核的是**题干质量**（此时题干已出，但参数未验证——参数验证是下一轮的事）。
你做的是**定性评估**，不推演数值、不验证参数是否满足约束。

## 三项定性评估

### ① 设问形式（评估考察形式）

审题干的设问方式是否符合设计卡的考察要求。

- 对照设计卡的 core_knowledge_intent（must_test），题干的设问是否意图覆盖了这些考点
- 设问方式是否恰当（如该考辨析的题不能只问"是什么"）
- 发现偏离时指出：**哪里偏离了 + 偏离的原因**（如"设问单薄，只问了根节点BF，没考旋转类型辨析"）

### ② 难度定性（评估难度匹配）

通过分析"解题需要计算什么"来定性判断难度是否匹配目标 K-雷达。

- 解这道题学生需要做什么操作（定性列举：如"需多步插入推演+平衡因子更新+旋转类型判断"）
- 这些操作的认知负荷是否匹配设计卡的目标 K-雷达
- **不推演具体数值**——只定性分析"需要算什么"，不算"算出来是多少"

### ③ 计算项识别（辅助难度评估）

识别解题需要计算的量（辅助②的难度判断）。

- 列出解题需计算的主要量（如"各节点平衡因子、旋转类型、旋转后树形态"）
- 这些计算项的数量和复杂度是否支撑目标难度
- **不关心参数的具体值**——只识别"需要算哪些类别的量"

## 评估结果

基于三项评估，给出结论：

- **pass**：题干设问形式、难度、计算项均合理，无明显偏离
- **suggestion**：只有表述/术语/格式等小问题（不影响考察结构和难度）——不回退重做，后续阶段顺手修。指出问题但不阻塞流程
- **needs_fix**：发现考察结构层面的偏离（设问单薄、考点遗漏、难度不匹配）——指出**哪里偏离了 + 偏离原因 + 修改方向**

> **suggestion vs needs_fix 的分界**：
> - **suggestion**（不阻塞）：表述歧义、术语不规范、格式小问题、问法可以更好但不影响考察
> - **needs_fix**（回退重做）：考点遗漏、难度严重偏离、设问结构缺失
> - **拿不准时倾向 suggestion**——只有明确的考察结构偏离才 needs_fix。

## 不做的事

- **不推演/模拟数值执行**——参数是否满足约束由下一轮 exec 验证
- **不算具体答案**——只定性分析
- **不验证参数值**——那是代码的事

## 输出要求

**你必须调用 write_file(path="review.md", content="...") 写出审核结论。**
思考在 reasoning 里完成，结论直接写入 review.md。不输出纯文字中间分析。

### pass 时

```
## status
pass

## issue_type
none
```

### suggestion 时

```
## status
suggestion

## issue_type
style_violation

## fix_instructions
- 表述问题：[具体哪里、怎么改]
- 修改类型：改题干（表述层面，不阻塞流程）

## feedback_for_agent
[简短反馈]
```

### needs_fix 时

```
## status
needs_fix

## issue_type
[coverage_gap / difficulty_mismatch / structure_error / style_violation]

## fix_instructions
- 偏离点：[哪里偏离了]
- 偏离原因：[为什么偏离]
- 修改方向：[应该怎么改]
- 修改类型：改题干 / 改参数

## keep_unchanged
- [不得修改的部分]

## feedback_for_agent
[简短反馈]
```
