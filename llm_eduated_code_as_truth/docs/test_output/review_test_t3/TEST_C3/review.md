## evidence

### 1. hard_constraints 未满足："至少2种旋转类型"

设计卡 `core_knowledge_intent.must_test` 明确要求考察"四种旋转类型（LL/RR/LR/RL）的触发条件判定与执行方法"，`design_rationale` 强调"LL/RR/LR/RL四种情况的触发条件极易混淆"。

**题目实际结构**：初始树插入关键字 `1` 后，推演过程如下：
- 1 作为节点 2 的左孩子插入
- 自底向上更新：节点 2 的 BF=1，节点 5 的 BF=2（失衡）
- 节点 5 的左孩子节点 2 的 BF=1 → **LL型，执行右旋**
- 旋转后节点 2 的 BF=0，节点 5 的 BF=0
- 继续向上：节点 10 的 BF=1，节点 20 的 BF=1 → 均未失衡，**无需继续旋转**

**结论**：整道题目只触发 **1种旋转（LL型右旋）**，不满足"至少2种旋转类型"的约束。

### 2. should_be 未满足："需精准辨析四种旋转类型的触发条件"

设计卡 `should_be` 要求"需精准辨析四种旋转类型的触发条件"。但题目只涉及 LL 型一种旋转，学生只需识别"左子树高且左孩子的左子树高"这一种情况，**不存在在多种旋转类型间辨析的认知需求**。

### 3. K4 难度偏差 ≥2 级

设计卡目标 K4=4（条件路由/辨析），要求"隐含前提很深，必须依靠对机制本质的理解才能路由"。但题目只有 1 条解题路径（LL型旋转），学生不需要在多条路径间辨析，**实际 K4 约为 1-2**（无辨析需求或仅有常规注意点），偏差 ≥2 级。

### 4. 设计说明与题目不一致

设计说明声称"通过完整模拟AVL插入→更新平衡因子→定位失衡→判定旋转类型→执行旋转→重新计算的多步流程，区分学生对四种旋转类型触发条件的掌握程度"，但题目实际只涉及 LL 型一种旋转，**设计说明"说一套做一套"**。
