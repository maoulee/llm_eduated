## core_knowledge_intent

- must_test:
  1. 最小不平衡子树的定位能力——从插入点向上回溯，找到第一个平衡因子绝对值超过 1 的节点
  2. 四种旋转类型（LL / RR / LR / RL）的触发条件辨析与正确选择——依据新插入节点相对于最小不平衡子树根的路径方向（左-左 / 左-右 / 右-左 / 右-右）进行判断
  3. 旋转后树结构的正确调整——单旋的子树重新挂接，双旋的两步分解，旋转后必须保持 BST 性质
- must_not_shift_to:
  1. AVL 删除操作及其平衡调整（本题仅考察插入）
  2. 纯概念辨析——仅问"LR 旋转适用于什么情况"而不涉及具体树结构操作
- coverage_success_criteria:
  1. 学生能够在给定树结构中正确定位最小不平衡子树，并基于路径方向选择唯一正确的旋转类型
  2. 学生能够正确画出旋转后的完整树结构，并通过平衡因子验证其满足 AVL 条件

## design_rationale

本题考察 AVL 树插入后的平衡调整全流程，属于"结构操作与状态维护模拟"模式。选择这个考点组合的原因是：AVL 插入调整本质上是一个"检测失衡→判断旋转类型→执行旋转→验证平衡"的闭环流程，其中每一步都依赖前一步的正确性，天然具备高 K3（多步串行推演 + 动态状态更新）和高 K4（条件路由——必须根据新节点与最小不平衡子树根之间的路径方向，从四种旋转中正确选择）的特征。K3-K4 平衡型意味着本题既要有足够的推演步数（K3=4），又要有清晰的条件判断节点（K4=3-4），两者缺一不可。

考点融合：本题将"旋转类型辨析""平衡因子计算""树结构推演"三个考察项融合在同一道综合题中。融合能提高考察深度的原因在于：AVL 平衡调整不是孤立的步骤，而是上述三者的耦合——学生必须在动态变化的树状态中同时维护平衡因子信息、判断旋转条件、执行结构调整并验证结果。拆开考察会失去对流程完整性的检验。具体地，第 1 问以双旋（LR 或 RL）为核心，要求学生在"之"字形失衡路径中正确识别需要两步旋转；第 2 问在第 1 问结果的基础上叠加单旋（LL 或 RR），形成从复杂到简单的递进，同时引入平衡因子的最终计算，闭环整个流程。

本题要区分的是"能完整走完插入—失衡检测—旋转类型判断—旋转执行—平衡验证全流程的学生"与"只记得四种旋转名称但无法在具体树结构中正确定位失衡节点和执行旋转的学生"。难度 4 对于综合题是合适的——它要求学生具备完整的流程掌控能力，但不设置反直觉陷阱（K4 控制在 3-4 而非 5），旋转类型通过标准路径方向分析即可确定。

## expected_reasoning_actions

1. 将给定关键字按 BST 性质插入当前 AVL 树的正确叶位置
2. 从新插入节点沿父指针逐层向上回溯，计算每一层祖先节点的平衡因子（左子树高度 − 右子树高度）
3. 定位最小不平衡子树——回溯过程中第一个平衡因子绝对值超过 1 的节点即为该子树的根
4. 分析从最小不平衡子树根到新插入节点的两步路径方向（左/右、左/右），据此判断旋转类型（LL→右单旋、RR→左单旋、LR→先左后右双旋、RL→先右后左双旋）
5. 执行对应的旋转操作：单旋直接围绕失衡节点旋转并重新挂接子树；双旋分两步，先旋转中间子树再旋转根
6. 验证旋转后的树同时满足 BST 性质和 AVL 平衡条件（所有节点平衡因子 ∈ {-1, 0, 1}）
7. 以第 1 问旋转后的树为初始状态，对第二个关键字重复步骤 1–6
8. 计算最终树中指定节点（如根节点）的平衡因子

## question_structure_plan

- shared_context: 以树形图给出一棵由 7–9 个节点构成的合法 AVL 树，标注各节点关键字值
- sub_question_chain:
  1. 在给定 AVL 树中插入关键字 X 后，指出最小不平衡子树的根节点，说明需要进行何种类型的旋转，并画出旋转后的 AVL 树。（约 5 分）
  2. 在第 1 问所得 AVL 树的基础上，再插入关键字 Y 后，需要进行何种类型的旋转？画出旋转后的 AVL 树，并给出根节点的平衡因子。（约 5 分）
- dependency_pattern: 严格链式依赖——第 2 问的初始树是第 1 问旋转后的结果，若第 1 问旋转错误则第 2 问必然错误，体现了状态维护的持续性

考点融合说明：第 1 问侧重"旋转类型辨析 + 树结构推演"（建议设置为 LR 或 RL 双旋，考察学生对之字形失衡路径的识别能力）；第 2 问在第 1 问结果上叠加"单旋（LL 或 RR）+ 平衡因子计算"，形成从双旋到单旋、从结构推演到数值计算的完整闭环。

干扰策略（预期学生错误路径，供评分标准参考）：
1. 最小不平衡子树定位错误——回溯时跳过了真正的第一个失衡节点，定位到更高层的节点
2. 旋转类型误判——将双旋（LR/RL）误判为单旋（LL/RR），或反之；本质是路径方向判断错误
3. 旋转执行不完整或不正确——双旋只执行第一步；或旋转后子树挂接位置错误（丢失或重复节点）

## parameter_plan

- parameter_slots:
  1. name: initial_tree
     role: 初始 AVL 树结构（节点关键字值及父子关系，以树形图呈现）
     candidate_range: 7–9 个节点，高度 3 的平衡二叉搜索树；存在至少一个平衡因子为 ±1 且其子节点平衡因子也为 ±1 的"临界失衡"路径
     used_by: 子问题 1（作为操作对象）
  2. name: insert_key_1
     role: 第一个插入的关键字
     candidate_range: 插入后沿"左-右"或"右-左"路径导致失衡的键值，触发 LR 或 RL 双旋
     used_by: 子问题 1
  3. name: insert_key_2
     role: 第二个插入的关键字
     candidate_range: 基于第 1 问旋转后的树结构，插入后沿"左-左"或"右-右"路径导致失衡的键值，触发 LL 或 RR 单旋
     used_by: 子问题 2
- validation_targets:
  1. initial_tree 必须是合法 AVL 树——所有节点平衡因子 ∈ {-1, 0, 1}，且满足 BST 性质
  2. insert_key_1 插入后触发的旋转类型必须唯一确定——不能存在"既可以解释为 LL 也可以解释为 LR"的歧义
  3. 第 1 问旋转后的树必须是合法 AVL 树且保持 BST 性质
  4. insert_key_2 插入后触发的旋转类型必须唯一确定
  5. 最终根节点的平衡因子必须可通过推演唯一确定
  6. 所有中间树结构须经代码验证（构造树 → 插入 → 检查平衡因子 → 执行旋转 → 验证结果）
- adjustment_priority: initial_tree > insert_key_1 > insert_key_2
  （先确定合法的初始树结构，再选择能触发目标旋转类型的插入键值；若初始树调整，后续键值需同步调整）

## terminology_and_expression_constraints

- required_terms: 平衡二叉树（AVL 树）、平衡因子、最小不平衡子树、LL 旋转 / RR 旋转 / LR 旋转 / RL 旋转
- required_qualifiers:
  - "最小"不平衡子树（强调从插入点向上回溯时遇到的第一个失衡子树，而非任意失衡子树）
  - 平衡因子定义须在题干中明确约定方向（建议：左子树高度 − 右子树高度）
- avoid_phrases:
  - 避免使用"调整"代替"旋转"（"调整"含义模糊，可能是旋转也可能是其他操作）
  - 避免使用"左旋 / 右旋"代替"LL / RR / LR / RL 旋转"（"左旋"在不同教材中可能指代不同操作，易产生歧义）
  - 避免在未定义平衡因子方向的情况下直接使用"平衡因子"
- standard_rewrites:
  - bad: "对树进行左旋" → good: "对以 X 为根的最小不平衡子树进行 RR 旋转（左单旋）"
  - bad: "找到不平衡的节点" → good: "找到最小不平衡子树的根节点"
  - bad: "平衡因子为 1"（未定义方向） → good: "平衡因子（左子树高度 − 右子树高度）为 1"

## audit_focus

- final_review_must_check:
  1. 初始树是否为合法 AVL 树（须用代码验证每个节点的平衡因子 ∈ {-1, 0, 1}）
  2. 每次插入后触发的旋转类型是否唯一确定——不能存在多种合理解释
  3. 子问题 2 是否严格基于子问题 1 的正确旋转结果（链式依赖完整性）
  4. 旋转后的树结构是否同时满足 BST 性质和 AVL 平衡条件
  5. 所有参数（初始树、两次插入键值、旋转结果）是否经过代码验证
- solve_output_should_contain:
  1. 插入后逐层回溯的平衡因子计算过程（至少展示从插入点到最小不平衡子树根的路径上各节点的平衡因子变化）
  2. 最小不平衡子树根节点的明确定位
  3. 旋转类型的判断依据——明确说明两步路径方向（如"从根节点 A 向左到 B，再向右到 C，故为 LR 型"）
  4. 旋转前后的完整树结构对比（以树形图或节点关系描述呈现）
  5. 第二次插入后的完整推演过程（定位 + 判断 + 旋转 + 验证）
  6. 最终根节点平衡因子的明确数值及其计算过程
- fail_if_missing:
  1. 缺少旋转类型的判断依据——只给结论（如"LR 旋转"）但不说明路径方向分析
  2. 旋转后树结构不满足 AVL 条件——存在平衡因子绝对值 > 1 的节点
  3. 子问题之间依赖断裂——子问题 2 未基于子问题 1 的正确树结构
  4. 初始树或中间结果完全未经代码验证——solver 未提供任何验证证据
