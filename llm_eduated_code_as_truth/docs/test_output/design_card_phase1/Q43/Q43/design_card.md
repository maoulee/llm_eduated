## core_knowledge_intent

- must_test:
  - 定点数补码表示法：给定十进制数，在指定位宽下写出补码二进制/十六进制表示
  - 硬件加法器运算模拟：逐位执行补码加法，跟踪进位链，正确判定 CF（进位标志）和 OF（溢出标志）
  - 有符号溢出与无符号溢出的本质差异：同一硬件加法结果，按有符号解释与按无符号解释时溢出状态不同
- must_not_shift_to:
  - 不偏移为纯十进制算术计算（必须走位级推演路径）
  - 不偏移为浮点数运算或 IEEE 754 相关考点
- coverage_success_criteria:
  - 学生必须完成从十进制→补码位模式→硬件加法→标志位判定→语义解释的完整推演链
  - 学生必须正确区分 CF 与 OF 的判定规则，并解释同一位模式在不同语义下的不同含义

## expected_reasoning_actions

1. 根据给定位宽，将十进制操作数转换为补码二进制表示（正数直接转换，负数取反加一）
2. 将补码二进制表示转换为十六进制形式（按4位一组分组）
3. 在指定位宽下逐位执行补码加法运算，记录每一位的进位输出
4. 根据最高位进位输出判定 CF（无符号进位标志）
5. 根据次高位进位与最高位进位的异或关系判定 OF（有符号溢出标志）
6. 将加法结果的位模式分别按有符号补码和无符号数两种语义解释为十进制值
7. 对比两种语义解释下的结果，分析 CF 与 OF 状态差异的硬件本质原因
8. 判断在给定位宽下运算结果是否有效，若溢出则说明溢出类型及原因

## question_structure_plan

- shared_context:
  - 给定一个固定位宽（如8位或16位）的寄存器环境
  - 给出两个十进制操作数 A 和 B
  - 要求在该位宽下执行补码加法 A + B
  - 提供硬件加法器的标志位定义（CF、OF 的判定规则）

- sub_question_chain:
  - (1) 表示转换：写出 A 和 B 的补码二进制表示及十六进制表示
  - (2) 硬件运算：执行补码加法，写出结果的位模式（二进制+十六进制），给出 CF 和 OF 的值
  - (3) 语义解释：将结果位模式分别按有符号数和无符号数解释为十进制值
  - (4) 边界分析：说明 CF 与 OF 是否一致，解释不一致的硬件本质原因；判断运算结果在两种语义下是否均有效

- dependency_pattern:
  - 串行依赖：(1)→(2)→(3)→(4)，前一步结果为后一步输入
  - (1) 的补码表示是 (2) 加法运算的输入
  - (2) 的位模式和标志位是 (3)(4) 语义分析的基础
  - (4) 需要综合 (2)(3) 的结论进行对比分析

## parameter_plan

- parameter_slots:
  | 参数名 | 角色 | 候选范围 | used_by |
  |--------|------|----------|---------|
  | bit_width | 寄存器位宽 | 8 或 16 | 全题 |
  | operand_A | 第一个操作数（十进制） | 正数，接近位宽上限的一半 | (1)(2) |
  | operand_B | 第二个操作数（十进制） | 正数，使 A+B 在有符号语义下溢出但在无符号语义下不溢出 | (1)(2) |

- validation_targets:
  - operand_A 和 operand_B 在给定位宽下均能合法表示为正数（不溢出）
  - A + B 的十进制真值超过有符号数表示范围（触发 OF=1）
  - A + B 的十进制真值不超过无符号数表示范围（CF=0 或 CF=1 但与 OF 不同）
  - 确保 CF ≠ OF，以凸显有符号与无符号溢出判断的差异
  - 加法结果的位模式按有符号补码解释后为一个合理的负数（体现溢出后的位模式回绕）

- adjustment_priority:
  1. 首先确定 bit_width（8位计算简洁，16位更贴近实际）
  2. 其次确定 operand_A 和 operand_B，确保 CF ≠ OF
  3. 最后验证所有中间结果的位模式转换正确性

## terminology_and_expression_constraints

- required_terms:
  - 补码（two's complement）
  - 进位标志 CF（Carry Flag）
  - 溢出标志 OF（Overflow Flag）
  - 有符号数 / 无符号数
  - 位宽 / 字长
  - 符号位
  - 位模式（bit pattern）

- required_qualifiers:
  - 提及溢出时必须明确"有符号溢出"或"无符号溢出"
  - 提及标志位时必须说明判定规则（CF看最高位进位，OF看最高位与次高位进位异或）
  - 提及位宽时必须明确"n位补码"或"n位寄存器"

- avoid_phrases:
  - "加法器知道这是有符号还是无符号"（错误暗示）
  - "结果溢出了"（未区分有符号/无符号）
  - "补码加法就是十进制加法"（忽略位级机制）

- standard_rewrites:
  | 错误表述 | 标准改写 |
  |----------|----------|
  | 结果溢出了 | 有符号溢出（OF=1）/ 无符号进位（CF=1） |
  | 加法器判断溢出 | 硬件根据进位链状态设置标志位，不区分数值类型 |
  | 补码就是负数 | 补码是一种编码方式，同一位模式可按有符号或无符号解释 |
  | 最高位是符号 | 在有符号补码解释下，最高位为符号位 |

## audit_focus

- final_review_must_check:
  - 题干是否明确给出了位宽、操作数、标志位定义
  - 四个子问题是否覆盖"表示转换→硬件运算→语义解释→边界分析"完整推演链
  - 参数是否满足 CF ≠ OF 的核心区分条件
  - 是否避免了"加法器能区分类型"等误导性表述
  - 分值分配是否合理（10分，建议 2+3+3+2 或类似分布）

- solve_output_should_contain:
  - operand_A 和 operand_B 的补码二进制表示（逐位）
  - operand_A 和 operand_B 的十六进制表示
  - 加法运算的逐位过程（含进位链）
  - 结果的位模式（二进制+十六进制）
  - CF 和 OF 的值及判定依据
  - 结果按有符号和无符号两种语义的十进制解释
  - CF 与 OF 差异的硬件本质分析

- fail_if_missing:
  - 缺少 CF 与 OF 的区分判定
  - 缺少同一位模式在两种语义下的对比解释
  - 参数导致 CF = OF（无法考察核心区分点）
  - 推演链不完整（跳过表示转换或跳过语义解释）
  - 出现"硬件能区分有符号/无符号"等错误暗示
