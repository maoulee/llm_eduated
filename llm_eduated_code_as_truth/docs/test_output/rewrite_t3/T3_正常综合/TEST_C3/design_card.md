## core_knowledge_intent

**must_test:**
- AVL 树插入操作的完整流程（插入→更新平衡因子→定位失衡节点→判断失衡类型→执行旋转→重新计算平衡因子）
- 四种旋转类型（LL/RR/LR/RL）的触发条件辨析与正确执行
- 最低失衡节点的定位规则与旋转后平衡因子的重新计算

**must_not_shift_to:**
- 不得退化为仅考察旋转名称与方向的记忆题
- 不得仅考察单次旋转操作而不涉及插入流程的完整推演

**coverage_success_criteria:**
- 学生需完整走完"插入→失衡判断→旋转→再平衡"的多步流程（>5步）
- 学生需在不同插入节点处正确路由到不同的旋转类型（LL/RR/LR/RL）

## design_rationale

本题考察 AVL 树插入与旋转的完整机制理解，而非碎片化知识记忆。选择"结构操作与状态维护模拟"模式，是因为 AVL 树的核心能力在于：在动态插入过程中持续维护平衡性，这要求学生不仅知道四种旋转"叫什么"，更要理解"何时触发"和"如何执行"。K3-K4 平衡型的设计意图是：K3 要求学生能按固定流程走完多步推演（插入→更新平衡因子→定位失衡→判断类型→旋转→再平衡），K4 要求学生能在不同插入场景下正确路由到对应的旋转类型（如 LL 型与 LR 型的区分依赖于子树平衡因子的符号判断）。这种设计要区分的是：能完整走完旋转流程并回溯检查平衡性的学生（真正理解 AVL 机制）与只记得旋转名称和方向的学生（机械记忆）。难度 4 是合适的，因为多步串行推演本身消耗工作记忆，而四种旋转的触发条件辨析又增加了条件路由的复杂度，两者叠加形成自然的认知负荷，无需额外设置反直觉陷阱。

## expected_reasoning_actions

- 在初始 AVL 树中插入第一个节点，更新从插入点到根路径上各节点的平衡因子
- 检查插入后是否存在失衡节点（平衡因子绝对值 > 1），定位最低失衡节点
- 根据最低失衡节点及其子节点的平衡因子符号，判断失衡类型（LL/RR/LR/RL）
- 执行对应类型的旋转操作，更新旋转涉及节点的指针关系
- 旋转后重新计算相关节点的平衡因子，验证整棵树是否恢复平衡
- 若插入序列包含多个节点，重复上述流程，注意前一次旋转对后续插入的影响
- 最终汇总旋转次数、旋转类型序列或最终树的关键结构特征

## question_structure_plan

**shared_context:**
- 给出一棵初始 AVL 树（以图形或节点列表形式描述，包含节点值与初始平衡因子）
- 给出待插入的节点序列（3-4个节点）

**sub_question_chain:**
- 子问题1：插入第一个节点后，指出是否发生旋转、旋转类型、旋转后的根节点（或关键结构特征）
- 子问题2：继续插入第二个节点，指出是否发生旋转、旋转类型、旋转后的根节点
- 子问题3：继续插入后续节点，指出是否发生旋转、旋转类型
- 子问题4（可选）：汇总整个插入过程中的旋转次数、旋转类型序列，或画出最终 AVL 树结构

**dependency_pattern:**
- 串行依赖：子问题2依赖子问题1的结果（插入后的树结构作为下一轮插入的初始状态）
- 子问题4依赖前面所有子问题的结果

**干扰策略（供选项组装参考）：**
- 概念混淆：LL 型与 LR 型触发条件混淆（仅看子节点位置，不看子节点平衡因子符号）
- 偏移错误：旋转后平衡因子计算错误（如忘记更新祖父节点的平衡因子）
- 中间值：将旋转过程中的中间树结构当作最终答案
- 条件遗漏：忽略"最低失衡节点"规则，对非最低失衡节点执行旋转

## parameter_plan

**parameter_slots:**

| 参数名 | 角色 | 候选范围 | used_by |
|--------|------|----------|---------|
| initial_tree_nodes | 初始 AVL 树的节点集合 | 5-8 个节点，已平衡 | 共享题干 |
| initial_tree_structure | 初始树的结构（父子关系） | 需保证初始状态为合法 AVL 树 | 共享题干 |
| insert_sequence | 待插入节点序列 | 3-4 个节点，数值与初始树不重复 | 子问题链 |
| rotation_trigger_points | 触发旋转的插入位置 | 至少 2 个不同位置触发旋转 | 子问题1-3 |
| rotation_types_needed | 需要的旋转类型组合 | 至少包含 2 种不同类型（如 LL+LR、RR+RL 等） | 子问题1-3 |

**validation_targets:**
- 初始树必须是合法的 AVL 树（所有节点平衡因子 ∈ {-1, 0, 1}）
- 插入序列中的节点值不得与初始树节点重复
- 插入序列必须触发至少 2 次旋转，且旋转类型不单一
- 每次旋转后，整棵树必须恢复为合法 AVL 树
- 最终答案（旋转次数/类型/根节点）必须唯一确定

**adjustment_priority:**
1. 优先调整 insert_sequence 以满足"至少 2 种旋转类型"的约束
2. 其次调整 initial_tree_structure 以控制推演步数在合理范围
3. 最后微调节点数值以避免与常见例题完全一致

## terminology_and_expression_constraints

**required_terms:**
- 平衡因子（balance factor）
- 左旋（left rotation）/ 右旋（right rotation）
- LL 型 / RR 型 / LR 型 / RL 型（失衡类型）
- 最低失衡节点（lowest unbalanced node）
-  AVL 树 / 平衡二叉排序树

**required_qualifiers:**
- 提及旋转时必须说明"以 XX 节点为根进行左旋/右旋"
- 提及失衡时必须说明"最低失衡节点为 XX"
- 平衡因子定义必须明确为"左子树高度 - 右子树高度"（或明确说明采用的定义）

**avoid_phrases:**
- ❌ "把树转一下" → ✅ "执行左旋/右旋操作"
- ❌ "不平衡了" → ✅ "平衡因子绝对值大于 1，发生失衡"
- ❌ "旋转后就好了" → ✅ "旋转后重新计算平衡因子，验证树恢复平衡"

**standard_rewrites:**

| 错误表述 | 标准改写 |
|---------|---------|
| 对节点 A 做 LL 旋转 | 以节点 A 为最低失衡节点，执行右旋操作（LL 型调整） |
| 插入后树不平衡 | 插入后节点 XX 的平衡因子变为 ±2，定位最低失衡节点 |
| 旋转一次 | 执行一次左旋/右旋操作，更新相关节点的平衡因子 |

## audit_focus

**final_review_must_check:**
- 初始 AVL 树是否为合法 AVL 树（所有节点平衡因子 ∈ {-1, 0, 1}）
- 插入序列是否触发至少 2 次旋转，且旋转类型不单一（满足 should_be 约束）
- 是否涉及四种旋转类型的触发条件辨析（满足 should_be 约束）
- 子问题链是否为串行依赖（后一步依赖前一步结果）
- 是否避免了"仅考察旋转名称记忆"（满足 should_not_be 约束）

**solve_output_should_contain:**
- 初始 AVL 树的验证结果（确认初始状态合法）
- 每次插入后的树结构变化（或关键节点平衡因子变化）
- 每次旋转的触发原因（最低失衡节点、失衡类型判断依据）
- 每次旋转后的平衡因子重新计算结果
- 最终汇总：旋转次数、旋转类型序列、最终根节点

**fail_if_missing:**
- 缺少初始树合法性验证
- 旋转类型少于 2 种（违反 should_be 约束）
- 缺少最低失衡节点的定位过程
- 缺少旋转后平衡因子的重新计算
- 子问题之间无串行依赖关系（违反考察模式要求）
