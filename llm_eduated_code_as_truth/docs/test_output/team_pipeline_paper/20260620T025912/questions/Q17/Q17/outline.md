## 考点
- **单链表基本操作**：考察带头结点单链表的遍历、删除操作
- **指针操作**：前驱结点维护、指针更新、内存释放
- **边界条件处理**：头结点后第一个结点、连续相同值、空链表
- **算法设计能力**：从问题描述到完整代码实现的跨域联动

## 难度目标
- **K1=1（微弱）**：链表基本概念为数据结构基础，概念模糊也能顺着题干做
- **K2=2（较低）**：几乎无数值计算，主要是指针操作逻辑
- **K3=2（较低）**：算法流程为遍历+条件判断+删除，路径唯一，步数少
- **K4=3（标准）**：存在明确陷阱——删除结点后指针更新、连续相同值处理、头结点特殊处理
- **K5=4（较高）**：需跨越结点定义、算法思想、代码实现三个子系统，状态互影响（指针操作错误导致后续全部错误）

## 考察模式
**算法设计型——链表操作算法设计**

理由：
- 经典数据结构算法设计题，考察完整算法设计能力
- 要求"定义+思想+代码"三段式输出，是408数据结构大题标准形式
- 链表删除操作是高频考点，历年多次出现变体

## 出题要求
- **题型**：综合题（算法设计）
- **总分**：14分
- **条件设计原则**：
  - 明确说明"带头结点"
  - 明确说明"删除所有值为x的结点"（强调"所有"）
  - 不给出具体链表内容，保持通用性
- **参数取值范围**：
  - 链表长度：不指定具体值，保持通用算法
  - 值x：不指定具体类型，由结点定义决定

## 子问题规划

### 子问题1：结点类型定义（约2分）
- **类型**：定义
- **考察目标**：单链表结点结构定义能力
- **与前后问关系**：为后续代码提供类型基础

### 子问题2：算法思想描述（约4分）
- **类型**：分析/描述
- **考察目标**：算法设计思路、边界条件意识
- **与前后问关系**：指导代码实现，体现设计思维

### 子问题3：C/C++代码实现（约8分）
- **类型**：实现
- **考察目标**：指针操作正确性、边界处理、代码规范性
- **与前后问关系**：算法思想的具体实现，需与子问题2一致

## 参数约束
- **链表结构**：带头结点的单链表（必须明确）
- **删除条件**：data域值等于x（强调"所有"匹配结点）
- **参数间一致性**：结点定义中的数据类型需与x的类型一致
- **可调自由度**：
  - 结点数据类型可由出题人选择（int/char等）
  - 链表初始状态不指定（保持算法通用性）
  - 是否要求释放内存可由出题人决定

## 参考经验

### 考察模式
- 链表操作算法设计是数据结构大题经典模式
- "定义+思想+代码"三段式是408标准答题格式
- 删除操作比插入操作更考察边界处理

### 难度锚点
- K5=4：需跨子系统联动（定义→思想→代码），指针错误连锁反应
- K4=3：陷阱明确但需主动识别（连续相同值、头结点后第一个结点）

### 典型陷阱
1. **删除后指针未更新**：删除结点后p未指向下一结点，导致漏删或死循环
2. **连续相同值处理**：连续多个值为x的结点，删除第一个后指针指向错误
3. **头结点处理**：误删头结点或未利用头结点简化边界
4. **内存泄漏**：删除结点后未free（若题目要求）
5. **空链表/单结点**：边界情况未处理
