## 考点
- **单链表结构**：考察对链表节点结构（data + next指针）的理解
- **递归函数机制**：考察递归调用栈的执行顺序（先递后归）
- **递归逆序输出**：考察"先递归到末尾，再回溯输出"的核心逻辑
- **递归终止条件**：考察对空指针判断（base case）的掌握

## 难度目标
- **K1=2（较低）**：需掌握链表、递归等基础名词，但概念模糊也能顺着代码逻辑做
- **K2=3（标准）**：需理解递归函数的执行流程，分析代码逻辑填补关键语句
- **K3=2（较低）**：仅需2步以内的推导（理解递归→确定填空），路径唯一
- **K4=2（较低）**：存在常规注意点（递归终止条件、输出位置），408考生基本不会踩坑
- **K5=1（微弱）**：单一知识点（链表+递归）内部解决，不涉及其他系统

## 考察模式
**代码阅读型——链表递归函数分析**

理由：
- 题干给出含空白的递归函数代码
- 要求学生分析代码逻辑，填补关键语句
- 同时要求简述函数功能，考察对整体逻辑的理解
- 这是数据结构代码阅读题的经典模式，与slot定义的examination_mode一致

## 出题要求
- **题型**：综合题（代码填空 + 功能简述）
- **分值**：5分（填空3分 + 功能简述2分）
- **条件设计原则**：
  - 给出完整的链表节点结构定义
  - 给出含1-2个空白的递归函数代码
  - 代码风格清晰，符合标准递归模式
- **参数取值范围要求**：
  - 链表节点数：3-5个（用于示例或辅助理解，非必须）
  - 空白数量：1-2个（关键语句位置）

## 子问题规划
- **第1问（3分）**：代码填空
  - 类型：代码分析/填空
  - 考察目标：理解递归逆序输出的核心逻辑，填补关键语句（递归调用语句或输出语句）
  - 与前后问关系：独立，但为第2问提供代码上下文

- **第2问（2分）**：功能简述
  - 类型：分析/描述
  - 考察目标：准确描述函数的整体功能（逆序输出链表元素）
  - 与前后问关系：基于第1问的代码上下文

## 参数约束
- **链表节点结构**：标准结构（data域 + next指针），data类型可为int或char
- **递归函数签名**：函数名自定，参数为链表头指针（LinkList/ListNode*）
- **空白位置**：
  - 空白1：递归调用语句（如 `ReversePrint(p->next)`）
  - 空白2（可选）：输出语句（如 `printf("%d ", p->data)`）
  - 至少1个空白，最多2个空白
- **递归终止条件**：代码中已给出（`if(p == NULL) return;`），不作为填空
- **代码行数**：函数体5-8行（含注释），保持简洁

## 参考经验
- **考察模式**：代码阅读型是数据结构高频题型，递归函数分析是经典考点
- **难度锚点**：K2=3为标准难度，需理解递归执行流程但不需复杂计算
- **典型陷阱**：
  - 学生可能混淆"先输出后递归"（正序）与"先递归后输出"（逆序）
  - 学生可能忽略递归终止条件的重要性
  - 功能描述可能过于笼统（只说"操作链表"而非"逆序输出"）
