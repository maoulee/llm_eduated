## 考点
- **单链表基本操作**（核心）：遍历、删除结点、指针操作
- **带头结点链表处理**（核心）：头结点的特殊地位、首元结点删除
- **内存管理**（辅助）：删除结点后释放内存（free）
- **边界条件处理**（辅助）：空链表、全匹配、连续匹配、尾结点删除

## 难度目标
- **K1=1（微弱）**：链表基本概念为数据结构常识，无需精准记忆特殊定义即可入题
- **K2=2（较低）**：无复杂计算，仅需指针赋值和比较操作
- **K3=2（较低）**：遍历+删除为标准流程，路径唯一，2步以内推导
- **K4=3（标准）**：存在明确陷阱——连续删除相同值结点时指针更新错误、删除后未free、头结点误删
- **K5=4（较高）**：删除操作改变链表结构（A系统状态变化），直接影响后续遍历逻辑（B系统执行），需正确处理指针链的断裂与重连

## 考察模式
**算法设计型——链表操作算法设计**

理由：
- 题干给定带头结点单链表，要求设计完整算法
- 输出包含三部分：结点类型定义、算法思想描述、C/C++代码实现
- 考察重点在于指针操作的正确性和边界条件处理
- 典型陷阱：连续删除时前驱指针更新、删除后内存释放、空链表/全匹配处理

## 出题要求
- **题型**：综合题（14分）
- **总条件数**：2-3个显式条件（链表结构说明、带头结点说明、x的取值说明）
- **条件设计原则**：
  - 明确链表带头结点
  - 明确结点类型包含data域和next域
  - x为给定值，可能出现在链表中0次、1次或多次
- **参数取值范围要求**：
  - 链表长度：建议5-15个结点（足够展示连续删除场景）
  - x的值：与链表中部分结点data值相同，且至少存在连续两个相同值的情况

## 子问题规划

### 子问题1：结点类型定义（约2分）
- **类型**：定义
- **考察目标**：带头结点单链表的结点结构定义（typedef struct）
- **分值**：2分
- **与前后问关系**：为后续代码提供类型基础，独立可答

### 子问题2：算法思想描述（约4分）
- **类型**：分析/描述
- **考察目标**：
  - 使用双指针（前驱指针+当前指针）遍历链表
  - 匹配时删除当前结点并释放内存，前驱指针不动
  - 不匹配时两指针同步后移
  - 处理边界：空链表、全匹配、连续匹配
- **分值**：4分
- **与前后问关系**：为代码实现提供逻辑框架，独立可答但影响代码评分

### 子问题3：C/C++代码实现（约8分）
- **类型**：计算/实现
- **考察目标**：
  - 正确的指针操作（p->next、q->next等）
  - 删除时的内存释放（free）
  - 连续删除时前驱指针不后移的关键逻辑
  - 代码注释完整性
- **分值**：8分
- **与前后问关系**：依赖子问题1的类型定义，实现子问题2的算法思想

## 参数约束
- **链表长度 n**：取值范围 5-15，需足够展示连续删除场景
- **x 的值**：与链表中至少2个结点data值相同，且至少存在连续两个结点data值均为x
- **链表初始状态**：带头结点，头结点data域无意义或为特殊值
- **参数间一致性**：x的值必须在链表中出现，但不能所有结点都是x（避免退化）
- **可调自由度**：链表长度、x的具体值、链表中x出现的次数和位置

## 参考经验
- **考察模式**：链表操作算法设计题，标准三问结构（定义+思想+代码）
- **难度锚点**：K5=4为主导，体现删除操作对链表结构的改变影响后续遍历
- **典型陷阱**：
  1. 连续删除时前驱指针错误后移（最常见错误）
  2. 删除结点后忘记free（内存泄漏）
  3. 误删头结点
  4. 空链表或全匹配时未正确处理
- **历史经验**：此类题目区分度主要来自代码实现的正确性，尤其是连续删除场景的指针处理
