## 模式B: 概念辨析型——符号与语义陷阱（补码与类型转换）
- **出现频率**: 4/14 (2010, 2012, 2016, 2021)
- **考察方式**: 题干给出特定数据表示（如补码、无符号数、C语言变量定义），要求考生判断数值大小、溢出状态或类型转换后的值。核心在于辨析“机器位模式”与“数学真值/语义”之间的关系。
- **选项架构**: 四选一竞争或命题判断。选项通常是数值、大小关系或“是否溢出”的判断。
- **常见参数类型**: 8位/16位/32位补码值、C语言 `signed/unsigned` 关键字、强制类型转换语句。
- **常见陷阱类型**: 
  1. **符号位权重误判**: 混淆补码最高位是负权重（-2^n）还是正权重（2^n），导致大小比较错误。
  2. **扩展规则混淆**: `unsigned short` 到 `int` 是零扩展还是符号扩展。
  3. **溢出边界认知**: 补码范围的非对称性（-128~127），特别是-128不溢出而128溢出的特性。
  4. **语义 vs 位模式**: 认为类型转换会改变比特流，而非仅改变解释方式。
- **典型干扰策略**: 嵌套陷阱。干扰项往往针对对底层原理一知半解的考生（如只记得符号位是1，但不知道它是负权重）。
- **适用知识点范围**: 补码表示范围与比较、定点数溢出判断、C语言强制类型转换（零扩展/符号扩展）、有符号与无符号数混合运算。
- **参考题**: 2010, 2012, 2016, 2021
- **难度范围**: K3~K5 (看似简单，实则极易掉入直觉陷阱)

# 2010年 Q13 — 补码乘法溢出判断

**知识点**: 补码表示范围, 十六进制转十进制, 溢出判断 | **雷达形状**: K4陷阱型

**K值**:
  - K1=4: 需精准记忆 8 位补码的表示范围（-128~127）及十六进制到十进制真值的转换规则。若是 3 分则只需知道补码定义，但本题需处理具体数值；若为 5 分则涉及纯概念辨析，本题有计算成分。
  - K2=3: 需将四个十六进制数转换为十进制真值，并执行乘法运算（或估算数量级）。涉及非 2 的幂次计算（如 254, 242 等），但并非极度繁杂的单步计算，属于标准难度。
  - K3=2: 无需多步串行推演，路径唯一：转真值 -> 乘 -> 比范围。两步以内即可得出结论。
  - K4=4: 存在极强的隐含前提陷阱：题目要求结果存放在**8位寄存器**中，且考察的是**溢出**判断。学生极易陷入“做补码乘法竖式”的误区，而忽略了“先转真值判断范围”这一本质逻辑。若按竖式计算，低8位结果可能看似合理，但实际真值已溢出。必须依靠对溢
  - K5=1: 单一知识点（数据表示与运算）内部解决，不涉及其他系统。

**题干**: 假定有4个整数用8位补码分别表示为r_1=FEH,r_2=F2H,r_3=90H,r_4=F8H。若将运算结果存放在一个8位寄存器中，则下列运算中会发生溢出的是()。
A.r_1×r_2
B.r_2×r_3
C.r_1×r_4
D.r_2×r_4

**选项分析**:
- **选项A**: [干扰] — $r_1 \times r_2 = (-2) \times (-14) = 28$。28 在 -128~127 范围内，未溢出。针对未熟练掌握补码转真值的学生，若误算为无符号数乘积则可能误选，但通常此类选项数值较小，易排除。
- **选项B**: [正确] — $r_1 \times r_3 = (-2) \times (-112) = 224$。224 远超 8 位补码最大值 127，发生正溢出。这是本题的唯一正确答案。
- **选项C**: [干扰] — $r_1 \times r_4 = (-2) \times (-8) = 16$。16 在范围内，未溢出。数值极小，极易排除。
- **选项D**: [干扰] — $r_2 \times r_4 = (-14) \times (-8) = 112$。112 在 -128~127 范围内，未溢出。虽然接近上限，但未溢出。针对对边界值敏感但计算不精确的学生。

**干扰策略**: 渐进陷阱

核心陷阱: 诱导进行低效的补码乘法竖式计算，而非高效的真值范围估算。

# 2012年 Q13 — C语言无符号数扩展

**知识点**: 强制类型转换, 零扩展与符号扩展, 无符号数表示 | **雷达形状**: K1概念辨析型

**K值**:
  - K1=4: 本题核心在于精准辨析“有符号数符号扩展”与“无符号数零扩展”的本质区别。若只记忆了“短变长要扩展”这一模糊概念，而无法区分 `unsigned` 和 `signed` 在硬件层面的不同处理逻辑（补0 vs 补符号位），极易选错。这属于极易混
  - K2=1: 计算量极微弱。核心难点不在进制转换（65530 -> FFFAH 是基础常识或计算器可得），而在扩展规则的应用。一旦规则明确，直接高位补0即可，无复杂算术运算。
  - K3=1: 无需多步串行推演。这是一个单一的状态转换操作：定义初始状态（16位无符号） -> 应用规则（零扩展至32位） -> 得到结果。没有动态过程或长链条逻辑。
  - K4=3: 存在明确的陷阱词 `unsigned`。考生若忽略该关键字，默认按照有符号数（补码）的思维惯性进行符号扩展（高位补1），则会掉入陷阱。这是典型的“不触发特定条件识别就会用错规则”的陷阱，属于标准级陷阱（3）。若题目更隐晦（如C代码隐式转换）
  - K5=1: 单一知识点内部解决（数据类型表示与转换），不涉及指令系统、存储器或总线等其他子系统。

**题干**: 假定编译器规定int和short 型长度分别为32位和16位，执行下列C语言语句：
unsigned short x=65530;
unsigned.int:y=X7 
得到y的机器数为
A. 0000 7FFAH 
B. 0000 FFFAH 
C. FFFF 7FFAH 
D. FFFF FFFAH

**选项分析**:
- **选项A**: [干扰] — **数值计算错误**。学生可能正确进行了零扩展，但在将 `65530` 转换为十六进制时出错（如算成 `FFFF` 或其他），导致最终结果高位虽对，低位数值错误。针对计算不熟练的学生。
- **选项B**: [正确] — **零扩展**。`unsigned short` 到 `unsigned int` 属于无符号数扩位，遵循“零扩展”规则。16位 `FFFAH` (即65530) 扩展为32位 `0000FFFAH`。这是符合C语言标准和计算机组成原理底层逻辑的正确操作。
- **选项C**: [干扰] — **误用符号扩展**。学生知道要扩展，但混淆了 `unsigned` 和 `signed`，误以为所有短变长都是符号扩展（高位补符号位）。`FFFAH` 的最高位是1，若进行符号扩展，结果会是 `FFFFFFFAH`。针对概念混淆，未能区分数据属性影响扩展策略的学生。
- **选项D**: [干扰] — **误用符号扩展且数值计算错误**。结合了上述两个错误：既错误地进行了符号扩展，又在进制转换或位填充上出现偏差。针对基础薄弱，逻辑混乱的学生。

**干扰策略**: 并行陷阱（各干扰项独立）

核心陷阱: 无符号数（Unsigned）与有符号数（Signed）在类型扩展时的规则差异。

# 2016年 Q13 — C语言有符号与无符号转换

**知识点**: 强制类型转换, 有符号数与无符号数表示, 补码与无符号数转换 | **雷达形状**: K4陷阱型

**K值**:
  - K1=4: 需精准辨析“有符号转无符号”在机器级层面的语义（位模式不变），而非C语言逻辑值不变。若仅记忆概念定义（K3）而不知底层实现机制，无法解题；若需推导（K2/K3）则难度降低，但此题核心在于对“转换”本质的准确记忆与辨析。
  - K2=1: 几乎无计算。补码形式已知（-32767的补码易得或无需完全写出），转为无符号数只需将最高位视为数值位进行按权展开，或直接用公式 $2^{16} + (-32767)$，属于极简心算。
  - K3=1: 无需多步推演。从有符号到无符号的转换在C标准中定义为位模式保留，一步到位，无中间状态。
  - K4=4: 存在深层隐含前提。陷阱在于学生容易用“数学值”思维（认为-32767转为unsigned还是负数或报错）或“符号扩展”思维（误以为要补0或补1改变位宽）来干扰。必须依靠对“强制类型转换”在计算机组成原理层面（位解释）的本质理解才能正确路由到
  - K5=1: 单一知识点内部解决，仅涉及数据表示与类型转换，不涉及其他子系统。

**题干**: 有如下C语言程序段
 short si =-32767;
unsigned short usi=si; 执行上述两条语句后，usi的值为_____。
 A.-32767
 B.32767
 C.32768
 D.32769


**选项分析**:
- **选项A**: [干扰] — 针对认知错误：认为有符号数转无符号数时，数值符号会丢失或变为0，或者误以为C语言会自动截断/报错导致值异常。也可能针对计算错误：误将最高位符号位去掉后直接计算剩余位的值（即原码数值部分 32767，但符号位处理错误）。具体到本题，若学生误以为 `unsigned` 不能表示负数，可能会选一个看似“合法”的正数但数值不对，或者因为混淆补码计算导致错误。*注：根据常见真题选项设置，A通常是一个错误的计算结果，如仅取低15位或错误进位*。针对“符号位扩展误解”或“原码转无符号误解”的学生。
- **选项B**: [干扰] — 针对认知错误：典型的“符号位误判”或“计算错误”。例如，学生可能错误地认为转换时要对符号位做特殊处理（如清零），或者在计算 $2^{16}-32767$ 时算错。针对粗心或概念模糊的学生。
- **选项C**: [干扰] — 针对认知错误：针对“补码转无符号”计算过程中的进位或借位错误。或者误用了 $2^{15}$ 而不是 $2^{16}$ 作为模值。针对计算不熟练的学生。
- **选项D**: [正确] — 针对正确认知：明确知道 `short` 到 `unsigned short` 转换时，机器位模式（补码）保持不变。$-32767$ 的16位补码为 `1000 0000 0000 0001`。将其视为无符号数，最高位权重为 $2^{15}$。计算过程：$2^{15} + 1 = 32768 + 1 = 32769$。或者利用模运算性质：$x_{unsigned} = x_{signed} + 2^{16}$ (若为负)。$-32767 + 65536 = 32769$。

**干扰策略**: 并行陷阱

核心陷阱: 语义陷阱——混淆“逻辑值”与“位模式”。初学者常认为类型转换会改变数据的“数学意义”或触发异常，而忽略了在固定位宽下，有符号到无符号的转换仅仅是解释方式的改变（Reinterpretation），底层比特流不发生任何变化。

# 2021年 Q13 — 无符号与带符号整数比较

**知识点**: 补码与真值转换, 无符号数与有符号数比较, 机器数表示 | **雷达形状**: K4陷阱型（伴随K1高概念依赖）

**K值**:
  - K1=5: 极高。本题本质是纯概念辨析，全凭对“补码”、“无符号数”定义及“符号位含义”的记忆准确度。没有任何计算或推演可以绕过，必须准确知道FFFDH在两种解释下的真值/大小关系，无法通过常识模糊推导。
  - K2=1: 微弱。仅需识别十六进制数的大小顺序（FF > FD > 7F 等），无需实际进行二进制转换或算术运算。数字本身作为十六进制字符串，其字典序与无符号数值序一致，几乎无计算负担。
  - K3=1: 微弱。无需多步串行推演，直接根据数的表示形式得出大小结论。
  - K4=4: 较高。隐含前提极深且反直觉：同一串机器码，在“无符号”和“补码”解释下，大小关系完全可能反转（特别是最高位为1的负数与最高位为0的正数/小数之间）。必须依靠对机制本质（符号位权重差异）的理解才能正确路由，常规思维容易掉坑。
  - K5=1: 微弱。单一知识点内部解决，不涉及其他系统联动。

**题干**: 已知带符号整数用补码表示，变量x,y,z的机器数分别为FFFDH,FFDFH,7FFCH,下列结论中，正确的是(  )。
A.若x,y和z为无符号整数，则z<x<y
B.若x,y和z为无符号整数，则x<y<z

C.若x,y和z为带符号整数，则x<y<z
D.若x,y和z为带符号整数，则y<x<z

**选项分析**:
- **选项A**: [干扰] — 针对“无符号比较逻辑错误”或“完全混淆符号”。若学生误认为无符号数也是看最高位符号，或者记反了补码/无符号的大小规则，可能误选。实际上无符号数 FFFD > FFDF > 7FFC，故 z<x<y 错误（应为 z<y<x）。
- **选项B**: [干扰] — 针对“带符号比较逻辑错误”。若学生误将补码当作无符号数比较，或者对补码负数大小比较规则不清（如认为FFFD比FFDF小，因为FD>DF但在负数区反之），可能误选。实际上补码下 FFDF(-33) < FFFD(-3) < 7FFC(正数)，故 x>y>z 错误。
- **选项C**: [干扰] — 针对“无符号比较逻辑正确但带符号判断错误”或反之。此选项通常设计为混合错误，例如无符号比较对了但符号判断错了，或者反之。具体需看原题选项设置，但根据参考，C往往是带符号判断正确但无符号判断错误，或者反之。在此题语境下，若C是“若...则 x<y<z”，则无符号判断错误（7FFC最小）。
- **选项D**: [正确] — 正确描述了带符号整数的大小关系。补码表示下，最高位为1表示负数，为0表示正数。FFFD(H) = -3, FFDF(H) = -33, 7FFC(H) = +32764。因此 -33 < -3 < 32764，即 y < x < z。

**干扰策略**: 并行陷阱（各干扰项独立）

核心陷阱: 符号位的权重陷阱。在补码表示中，最高位（符号位）具有负权重（-2^n），而在无符号数中，最高位具有正权重（2^n）。这导致最高位为1的数在补码中是最小的（负数），而在无符号数中是最大的。

## K1-K5 认知雷达评分标准

K1 基础认知需求（需要调用概念/术语/公式记忆的程度）:
  1=微弱: 仅需日常常识词汇，几乎不需要 408 专业记忆
  2=较低: 需要 408 基础名词，但概念模糊也能顺着题干做
  3=标准: 必须准确记忆某个核心概念/公式的定义才能入题
  4=较高: 需精准辨析极易混淆的概念，或提取冷门细节公式
  5=极高: 纯概念辨析题，全凭记忆准确度，毫无推演绕过余地
  判定锚点：看学生不记忆任何408知识能否入题 → 能则1，需一个核心定义则3，需辨析两个以上易混概念则4-5

K2 单步代入需求（需要执行单次直接计算/转换的程度）:
  1=微弱: 几乎无计算，或仅需极简单心算
  2=较低: 需一步简单公式代入，数字友好（多为 2 的幂）
  3=标准: 需代入常规公式计算，可能涉及非 2 的幂次或小数
  4=较高: 单步计算繁杂/易算错，或需多级单位统一换算
  5=极高: 整题核心就是卡这一步复杂计算，算错全盘皆输
  判定锚点：看最复杂的单步计算是否可能算错 → 2的幂友好计算则2，非2幂次则3，多级换算或精度敏感则4-5

K3 机制推演需求（需要在明确规则下多步串行推演的程度）:
  1=微弱: 无需推演流程，得出答案不需走多步
  2=较低: 仅需 2 步以内的极简推导，路径唯一
  3=标准: 需按固定"说明书"走完 3-5 步流程，路径唯一
  4=较高: 推演步数 >5 步，或需维持动态状态更新
  5=极高: 极长程推演，极度消耗工作记忆，中间错一步全盘皆输
  判定锚点：数从输入到输出需几步 → 1-2步则1-2，3-5步标准流程则3，>5步或需记忆中间状态则4-5

K4 条件路由需求（需要识别隐含前提/避开暗坑/切换机制的程度）:
  1=微弱: 题面字面意思即全部，无任何隐藏陷阱
  2=较低: 存在常规注意点，408 考生基本不会踩坑
  3=标准: 存在明确的陷阱词，不触发就会用错公式
  4=较高: 隐含前提很深，必须依靠对机制本质的理解才能路由
  5=极高: 整题专为反直觉设计，顺向常规思维 100% 掉坑
  判定锚点：看有没有"题面没说但解题必须意识到的条件" → 无则1，有常规注意点则2，有陷阱词则3，隐含前提深则4，反直觉则5

K5 跨域联动需求（需要跨越不同子系统/模块传递状态的程度）:
  1=微弱: 单一知识点内部解决，不涉及其他系统
  2=较低: 提及其他系统名词，但无数据/逻辑实质性关联
  3=标准: 两系统单向拼接，A 的输出直接当 B 的输入
  4=较高: A 系统的状态/异常会改变 B 系统的执行逻辑
  5=极高: 多系统深度耦合，需来回交叉推演与双向验证
  判定锚点：看是否需要在不同子系统之间传递数据或状态 → 单系统则1，提及无关则2，单向传数据则3，状态互影响则4，深度耦合则5
