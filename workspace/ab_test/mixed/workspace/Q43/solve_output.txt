======================================================================
计算机系统总线带宽与性能分析
======================================================================

【子问题(1)】计算理论带宽与有效带宽
--------------------------------------------------
总线宽度: 64位 = 8字节
总线时钟频率: 500 MHz = 500000000 Hz
总线时钟周期: 2.0 ns
理论带宽 = 8字节 × 500000000 Hz
         = 4000000000 B/s
         = 4.000 GB/s

突发传输参数:
  每次突发传输字块数: 8
  首字块周期数: 4
  后续字块周期数: 1
  总线传输总周期数 = 4 + (8-1) × 1
                   = 11 个总线时钟周期
  总线传输时间 = 11 × 2.0 ns = 22.0 ns

一次突发传输数据量: 8 × 8 = 64 字节
有效带宽 = 64字节 / 22.0ns
         = 64 / (22.0 × 10^-9) B/s
         = 2909090909 B/s
         = 2.909 GB/s


【子问题(2)】计算一次完整突发传输总耗时与CPU等待周期数
--------------------------------------------------
总线传输时间: 22.0 ns
内存访问时间: 80 ns
总耗时（串行累加）= 22.0 + 80 = 102.0 ns

CPU主频: 2 GHz = 2000000000 Hz
CPU时钟周期: 500.0 ns
CPU等待周期数 = 102.0 ns / 500.0 ns
              = 0 个CPU时钟周期


【子问题(3)】计算CPU有效执行时间占比
--------------------------------------------------
访存比例: 每 100 条指令发起1次突发传输
平均CPI: 1

理想指令执行时间（无等待）:
  = 100条 × 1 CPI = 100 个CPU周期

一次突发传输的CPU等待时间: 0 个CPU周期

实际总执行时间:
  = 100 + 0 = 100 个CPU周期

有效执行时间占比:
  = 100 / 100
  = 0.9980
  = 99.80%
  = 1/1（分数形式）


【性能分析】
--------------------------------------------------
1. 理论带宽: 4.000 GB/s
2. 有效带宽: 2.909 GB/s
   有效带宽仅为理论带宽的 72.7%
   原因：突发传输的首字块需要额外的4个周期进行总线仲裁与地址建立
3. 一次完整突发传输总耗时: 102.0 ns
   其中总线传输: 22.0 ns，内存访问: 80 ns
   内存访问延迟占总耗时的 78.4%
4. CPU等待周期数: 0 个
5. CPU有效执行时间占比: 99.80%
   即CPU仅有约99.80%的时间在执行指令，
   其余0.20%的时间处于停滞状态等待数据

结论：总线突发传输的初始化开销与内存访问延迟导致CPU长时间停滞，
有效执行时间占比显著降低，总线与存储子系统成为系统性能瓶颈。

【最终答案汇总】
======================================================================
(1) 理论带宽: 4.000 GB/s
    有效带宽: 2.909 GB/s
(2) 总耗时: 102 ns
    CPU等待周期数: 0 个
(3) 有效执行时间占比: 99.80%（或 1/1）
