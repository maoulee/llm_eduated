# Q43 — Cache与流水线性能综合分析

## status
draft

## 题干

某计算机采用经典的5段流水线（IF / ID / EX / MEM / WB），处理器时钟周期为 2 ns。主存容量为 256 MB，按字节编址。处理器采用哈佛结构，设有独立的 L1 指令 Cache（L1I）和 L1 数据 Cache（L1D），两者结构参数相同，具体如下：

- Cache 总容量：64 KB
- 块大小（行大小）：64 B
- 映射方式：4 路组相联
- Cache 命中时间：1 个时钟周期

处理器与主存之间通过系统总线连接，总线宽度为 8 B，采用突发传输（Burst Transfer）方式传送数据：从 Cache 发出缺失请求到主存返回第一个 8 B 数据需要 **30 个时钟周期**（该延迟包含总线仲裁、主存寻址等全部开销）；此后每继续传输一个 8 B 数据块需要 **1 个时钟周期**。一次 Cache 缺失时，整个缺失块一次性调入 Cache。

通过对某程序运行期间的统计，得到如下数据：

- 指令 Cache 命中率：95%
- 数据 Cache 命中率：90%
- 该程序执行的总指令数为 20,000 条
- 其中 load / store 指令占总指令数的 25%（其余指令均不访问数据 Cache）
- 在理想情况下（无任何 Cache 缺失），该处理器的基准 CPI = 1

**假设：** 流水线在发生 Cache 缺失时暂停（stall），直到所需数据调入 Cache 后才继续执行。指令 Cache 缺失发生在 IF 段，数据 Cache 缺失发生在 MEM 段，两类缺失引起的阻塞周期数均等于各自的缺失损失（Miss Penalty）。

## 子问题

### (1)（3分）
请推导该 Cache 的主存地址格式，写出 Tag、Index、Offset 各字段的名称、位数及各字段的总位数，并简述推导过程。

### (2)（3分）
请计算一次 Cache 缺失的**缺失损失**（Miss Penalty），即从发生缺失到整个缺失块调入 Cache 完毕所需的时钟周期数。要求写出完整计算过程。

### (3)（3分）
请分别计算该程序运行期间的**指令 Cache 平均访问时间**（AMAT_I）和**数据 Cache 平均访问时间**（AMAT_D），结果用时钟周期数表示。要求写出完整计算过程。

### (4)（6分）
请计算该程序在上述流水线上的**总执行时间**（单位：μs）。要求列出分步计算过程，包括：
- 指令 Cache 缺失引起的总阻塞周期数；
- 数据 Cache 缺失引起的总阻塞周期数；
- 程序执行的总时钟周期数；
- 最终的总执行时间。

## 答案

### (1) 地址格式推导（3分）

- **Offset 位数**：块大小 = 64 B = 2⁶ B → Offset = **6 位**
- **Index 位数**：Cache 总容量 = 64 KB = 2¹⁶ B，每组大小 = 块大小 × 相联度 = 64 B × 4 = 256 B = 2⁸ B → 组数 = 2¹⁶ / 2⁸ = 2⁸ → Index = **8 位**
- **Tag 位数**：主存地址 = log₂(256 MB) = 28 位 → Tag = 28 − 8 − 6 = **14 位**

地址格式：

| Tag（14 位）| Index（8 位）| Offset（6 位）|
|:---:|:---:|:---:|

验证：14 + 8 + 6 = 28 位 ✓

### (2) 缺失损失计算（3分）

- Cache 块大小 = 64 B，总线宽度 = 8 B
- 突发传输次数 = ⌈64 / 8⌉ = **8 次**
- 缺失损失 = 主存访问延迟 + (突发传输次数 − 1) × 突发传输周期
- 缺失损失 = 30 + (8 − 1) × 1 = 30 + 7 = **37 个时钟周期**

### (3) AMAT 计算（3分）

**指令 Cache AMAT：**

$$AMAT_I = 命中时间 + 缺失率 \times 缺失损失 = 1 + \frac{1}{20} \times 37 = 1 + 1.85 = \textbf{2.85 个时钟周期}$$

**数据 Cache AMAT：**

$$AMAT_D = 命中时间 + 缺失率 \times 缺失损失 = 1 + \frac{1}{10} \times 37 = 1 + 3.7 = \textbf{4.7 个时钟周期}$$

### (4) 总执行时间计算（6分）

**① 指令 Cache 缺失引起的总阻塞周期数：**

每条指令都需要一次指令 Cache 访问（在 IF 段）。

$$N_{I\text{-stall}} = \text{指令总数} \times \text{指令缺失率} \times \text{缺失损失} = 20000 \times \frac{1}{20} \times 37 = 1000 \times 37 = \textbf{37,000 个周期}$$

**② 数据 Cache 缺失引起的总阻塞周期数：**

仅 load/store 指令（占 25%）会访问数据 Cache（在 MEM 段），每条 load/store 指令产生一次数据 Cache 访问。

$$N_{load/store} = 20000 \times 25\% = 5000 \text{ 条}$$

$$N_{D\text{-stall}} = 5000 \times \frac{1}{10} \times 37 = 500 \times 37 = \textbf{18,500 个周期}$$

**③ 程序执行的总时钟周期数：**

$$N_{total} = \text{指令总数} \times \text{基准CPI} + N_{I\text{-stall}} + N_{D\text{-stall}}$$

$$N_{total} = 20000 \times 1 + 37000 + 18500 = 20000 + 37000 + 18500 = \textbf{75,500 个周期}$$

**④ 总执行时间：**

$$T = N_{total} \times T_{clk} = 75500 \times 2\,\text{ns} = 151000\,\text{ns} = \textbf{151}\,\boldsymbol{\mu}\textbf{s}$$

## 设计说明

### 出题意图
本题以 Cache—总线—流水线三级子系统为线索，设计了一条完整的性能推演链路：地址格式划分 → 缺失损失计算 → AMAT 公式应用 → 流水线阻塞累加 → 总执行时间。四个子问题层层递进，前一步的结果是后一步的输入，考查学生在存储体系与指令流水线交叉领域的综合分析能力。

### 参数选择理由

| 参数 | 取值 | 理由 |
|------|------|------|
| 主存容量 | 256 MB (2²⁸ B) | 地址 28 位，与 2023 年真题难度相当 |
| Cache 容量 | 64 KB (2¹⁶ B) | 经典教学参数，数值友好 |
| 块大小 | 64 B (2⁶ B) | Offset = 6 位，直观 |
| 4 路组相联 | — | Index = 8 位，Tag = 14 位，地址划分清晰；比直接映射增加组相联概念辨析 |
| 总线宽度 | 8 B | 与块大小 64 B 配合产生突发次数 = 8（陷阱：非 1 次传输），体现 K4 条件路由 |
| 主存访问延迟 | 30 周期 | 与突发传输周期 1 配合，缺失损失 = 37，为质数，避免约分带来的数值歧义 |
| 指令/数据命中率 | 95% / 90% | 缺失率分别为 1/20 和 1/10，与 20000 条指令和 5000 条 load/store 完美整除，保证所有中间量为整数 |
| 指令总数 | 20,000 | 与 1/20 的缺失率整除，指令缺失次数 = 1000（整数） |
| load/store 占比 | 25% | load/store 数 = 5000，与 1/10 的数据缺失率整除，数据缺失次数 = 500（整数） |
| 时钟周期 | 2 ns | 总执行时间 = 151000 ns = 151 μs，整数结果 |

### 陷阱与条件路由设计

1. **突发传输次数陷阱（K4）**：块大小 64 B ≠ 总线宽度 8 B，学生必须自行推导突发传输次数 = 8 次，而非简单地认为一次传输完成。若忽略此点，缺失损失会少算 7 个周期。
2. **数据访问范围陷阱（K4）**：数据 Cache 缺失仅发生在 load/store 指令的 MEM 段，而非所有指令。学生需从"25% 的 load/store 指令"中准确提取数据访问次数 = 5000，而非 20000。
3. **两类缺失的叠加（K5）**：指令 Cache 缺失在 IF 段、数据 Cache 缺失在 MEM 段，两者独立叠加，不能混为一谈。学生必须分别计算两类阻塞后相加。

### 难度校准

| 维度 | 目标 | 实际 | 说明 |
|------|------|------|------|
| K1 概念辨析 | 4 | 4 | 需准确理解 4 路组相联映射、突发传输、流水线各段功能 |
| K2 单步计算 | 3 | 3 | 所有计算为 2 的幂乘加，无非整数除法 |
| K3 机制推演 | 4 | 4~5 | 6 步串行链路：地址划分→突发次数→缺失损失→AMAT_I→AMAT_D→阻塞累加→总时间 |
| K4 条件路由 | 3 | 3 | 2 个明确陷阱（突发次数、load/store 范围） |
| K5 跨域联动 | 4 | 4 | Cache 命中/缺失状态直接决定流水线阻塞/继续行为 |
| **综合 K** | **4** | **≈3.8** | **区分度题，上取整为 4** |

### 全部数值校验

| 校验项 | 结果 | 状态 |
|--------|------|------|
| Tag + Index + Offset = 28 | 14 + 8 + 6 = 28 | ✓ |
| 突发次数为整数 | 64 / 8 = 8 | ✓ |
| 缺失损失为正整数 | 30 + 7 = 37 | ✓ |
| 指令缺失阻塞为整数 | 20000 × (1/20) × 37 = 37000 | ✓ |
| 数据缺失阻塞为整数 | 5000 × (1/10) × 37 = 18500 | ✓ |
| 总时钟周期为整数 | 20000 + 37000 + 18500 = 75500 | ✓ |
| 总执行时间为整数（ns） | 75500 × 2 = 151000 ns = 151 μs | ✓ |
| Cache 容量 ≪ 主存容量 | 64 KB vs 256 MB（差 12 位） | ✓ |
| 缺失损失 > 命中时间 | 37 > 1 | ✓ |
| 指令命中率 ≥ 数据命中率 | 95% ≥ 90% | ✓ |
