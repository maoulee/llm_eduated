======================================================================
Q43 — Cache与流水线性能综合分析
======================================================================

======================================================================
基本参数
======================================================================
主存容量: 256 MB = 268435456 B = 2^28 B
主存地址位数: 28 位

Cache总容量: 64 KB = 65536 B = 2^16 B
块大小: 64 B = 2^6 B
映射方式: 4路组相联
Cache命中时间: 1 个时钟周期

总线宽度: 8 B
首次突发传输延迟: 30 个时钟周期
后续突发传输延迟: 1 个时钟周期/次

指令Cache命中率: 95.0%
数据Cache命中率: 90.0%
总指令数: 20000
load/store指令占比: 25.0%
基准CPI: 1

======================================================================
子问题 (1): Cache 主存地址格式推导
======================================================================

【推导 Offset 位数】
  块大小 = 64 B = 2^6 B
  → Offset = 6 位
  说明: 块内寻址需要 6 位来定位每个字节

【推导 Index 位数】
  每组大小 = 块大小 × 相联度 = 64 B × 4 = 256 B = 2^8 B
  组数 = Cache总容量 / 每组大小 = 65536 / 256 = 256 = 2^8
  → Index = 8 位

【推导 Tag 位数】
  主存地址位数 = log₂(268435456) = 28 位
  Tag = 地址位数 - Index - Offset = 28 - 8 - 6 = 14 位

【验证】
  Tag(14) + Index(8) + Offset(6) = 28 位
  28 = 28 ✓ 验证通过!

  地址格式:
  ┌──────────────┬──────────┬──────────┐
  │ Tag(14位)  │Index(8位)│Offset(6位)│
  └──────────────┴──────────┴──────────┘

======================================================================
子问题 (2): 缺失损失 (Miss Penalty) 计算
======================================================================

【计算突发传输次数】
  Cache块大小 = 64 B
  总线宽度 = 8 B
  突发传输次数 = ⌈64 / 8⌉ = 8 次

【计算缺失损失】
  缺失损失 = 首次传输延迟 + (突发传输次数 - 1) × 后续传输延迟
  缺失损失 = 30 + (8 - 1) × 1
  缺失损失 = 30 + 7 × 1
  缺失损失 = 30 + 7
  缺失损失 = 37 个时钟周期

======================================================================
子问题 (3): AMAT 计算 (平均访问时间)
======================================================================

  AMAT 公式: AMAT = 命中时间 + 缺失率 × 缺失损失

【指令 Cache AMAT (AMAT_I)】
  指令Cache命中率 = 0.95 = 95%
  指令Cache缺失率 = 1 - 0.95 = 0.050000000000000044 = 5%
  AMAT_I = 1 + 0.050000000000000044 × 37
  AMAT_I = 1 + 1.8500000000000016
  AMAT_I = 2.8500000000000014 个时钟周期

【数据 Cache AMAT (AMAT_D)】
  数据Cache命中率 = 0.9 = 90%
  数据Cache缺失率 = 1 - 0.9 = 0.09999999999999998 = 9%
  AMAT_D = 1 + 0.09999999999999998 × 37
  AMAT_D = 1 + 3.6999999999999993
  AMAT_D = 4.699999999999999 个时钟周期

======================================================================
子问题 (4): 总执行时间计算
======================================================================

【① 指令Cache缺失引起的总阻塞周期数】
  每条指令都需要一次指令Cache访问（在IF段）
  指令总数 = 20000
  指令Cache缺失率 = 0.050000000000000044 = 1/20
  指令Cache缺失次数 = 20000 × 0.050000000000000044 = 1000
  N_I_stall = 缺失次数 × 缺失损失 = 1000 × 37 = 37000 个周期

【② 数据Cache缺失引起的总阻塞周期数】
  仅load/store指令（占25.0%）会访问数据Cache（在MEM段）
  load/store指令数 = 20000 × 0.25 = 5000
  数据Cache缺失率 = 0.09999999999999998 = 1/10
  数据Cache缺失次数 = 5000 × 0.09999999999999998 = 499
  N_D_stall = 缺失次数 × 缺失损失 = 499 × 37 = 18463 个周期

【③ 程序执行的总时钟周期数】
  基准周期数 = 指令总数 × 基准CPI = 20000 × 1 = 20000
  N_total = 基准周期 + I-stall + D-stall
  N_total = 20000 + 37000 + 18463
  N_total = 75463 个时钟周期

【④ 总执行时间】
  T = N_total × T_clk = 75463 × 2 ns = 150926 ns
  T = 150926 ns = 150.926 μs

======================================================================
最终结果汇总
======================================================================

  (1) 地址格式: Tag(14位) | Index(8位) | Offset(6位)  共28位
  (2) 缺失损失 (Miss Penalty) = 37 个时钟周期
  (3) AMAT_I = 2.8500000000000014 个时钟周期
      AMAT_D = 4.699999999999999 个时钟周期
  (4) 总执行时间 = 150.926 μs
          = 150926 ns
          = 75463 个时钟周期
