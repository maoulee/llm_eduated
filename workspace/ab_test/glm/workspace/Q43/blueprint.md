## 知识点

### 核心知识点
1. **主存与Cache地址格式字段划分**：根据Cache容量、块大小、映射方式（直接映射/组相联/全相联）推导地址的 Tag、Index、Offset 字段位数。
2. **Cache缺失损失（Miss Penalty）计算**：通过总线宽度和总线传输特性，计算一次Cache缺失需要多少个时钟周期才能将缺失块从主存调入Cache。
3. **平均访问时间 AMAT 公式应用**：`AMAT = 命中时间 + 缺失率 × 缺失损失`，需区分指令Cache与数据Cache分别计算。
4. **指令流水线阻塞时钟周期数累加计算**：将AMAT或缺失损失映射到流水线每个时钟周期的执行代价，累加得出总执行时间。

### 考察范围
- Cache的三种基本映射方式（重点：直接映射或组相联映射）
- 地址格式中各字段位数的推导与二进制地址拆分
- 总线传输的突发传输模式（Burst Transfer）对缺失损失的影响
- AMAT公式的准确理解与代入
- 经典5段流水线（IF/ID/EX/MEM/WB）中Cache命中/缺失对流水线阻塞的影响
- 指令总数、CPI与总时钟周期数的关系

### 关联知识点（不交叉但需理解）
- 存储器层次结构的基本设计思想
- 局部性原理对Cache性能的影响
- 流水线基本原理与数据通路

## 出题要求

### 题型
综合应用题（解答题），无选项，需写出完整解答过程与最终数值结果。

### 子问题数量
4 个子问题，由浅入深递进排列。

### 条件设计要求
1. **题干必须提供的条件**：
   - 主存容量与地址位数
   - Cache总容量、块大小、映射方式（建议直接映射或2-way/4-way组相联）
   - 总线宽度和总线传输模式（突发传输每次传输的字节数）
   - Cache命中率（分别给出指令Cache和数据Cache的命中率）
   - 指令总数及其中load/store指令占比
   - 流水线时钟周期（基准CPI）
   - 主存访问延迟（从发出请求到第一个数据返回的延迟周期数）

2. **隐藏条件/陷阱设计**：
   - Cache块大小 ≠ 总线宽度时，一次缺失需要多次总线传输 → 需学生自行推导突发传输次数
   - 数据访问（load/store指令）会产生额外的数据Cache访问，需叠加到总缺失次数中
   - 流水线中Cache缺失的阻塞位置：指令缺失在IF段阻塞，数据缺失在MEM段阻塞

3. **数字友好性约束**：
   - 所有容量参数为2的幂次
   - 命中率设计为简单分数（如 90% = 9/10，或 95% = 19/20）
   - 最终结果必须为整数或简单分数

## 参数约束

### 数值参数一致性约束

#### 约束1：地址字段位数一致性
```
Offset位数 = log₂(块大小)
Index位数 = log₂(Cache总容量 / (块大小 × 相联度))
Tag位数 = 主存地址位数 - Index位数 - Offset位数
```
**要求**：三个字段位数之和必须等于主存地址位数，且每个字段位数 ≥ 1。

#### 约束2：突发传输次数必须为整数
```
突发传输次数 = ⌈块大小 / 总线宽度⌉
```
**要求**：块大小必须能被总线宽度整除，或向上取整后为整数。推荐设计使块大小是总线宽度的整数倍（如块大小=64B，总线宽度=8B → 突发8次）。

#### 约束3：缺失损失为整数
```
缺失损失 = 主存访问延迟 + (突发传输次数 - 1) × 突发传输周期
```
**要求**：结果必须为正整数。

#### 约束4：AMAT结果为友好数值
```
AMAT = 命中时间 + 缺失率 × 缺失损失
```
**要求**：命中率设计为使得缺失率为简单分数（如1/10、1/20），命中时间通常为1个时钟周期，AMAT结果为简单分数或小数。

#### 约束5：最终执行时间为整数
```
总缺失阻塞 = 指令总数 × 指令缺失率 × 指令缺失损失 + load/store数 × 数据缺失率 × 数据缺失损失
总时钟周期 = 指令总数 × 基准CPI + 总缺失阻塞
```
**要求**：所有中间量和最终结果必须为正整数。需验证：
- 指令总数 × 指令缺失率 为整数
- load/store数 × 数据缺失率 为整数
- 所有乘积累加后为整数

#### 约束6：参数合理性约束
- Cache总容量 < 主存容量（至少差4个数量级）
- 缺失损失 > 命中时间（否则Cache无意义）
- 指令Cache命中率 ≥ 数据Cache命中率（符合局部性原理的一般规律）
- 基准CPI = 1（经典流水线理想情况）
