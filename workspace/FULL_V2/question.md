## 题干
某计算机系统采用 32 位物理地址，主存容量为 1GB，Cache 总容量为 64KB，数据块大小为 32B，Cache 采用 4 路组相联映射方式。Cache 每行（Line）除数据块外，额外配置 1 位有效位（Valid）与 2 位 LRU 替换标记位。

## 子问题
### (1)（4分）
根据上述系统参数，计算主存块号总位数、Cache 总行数与组数；给出物理地址中标记（Tag）、组号（Index）、块内偏移（Offset）三个字段的精确位数，并标注各字段在 32 位地址中的位号范围（bit[31] 为最高有效位）。

### (2)（4分）
现有两个物理地址：$A_1 = \text{0x1A234000}$ 与 $A_2 = \text{0x1A23C000}$。分别计算其映射目标组号，并判断两者是否会在同一组内产生映射冲突。请从索引字段与标记字段匹配角度给出严谨理由。

### (3)（4分）
① 计算该 Cache 所需的标记存储器（Tag RAM）总容量（需包含 Tag、Valid、LRU 所有标记位），结果以 Byte 为单位。
② 若将映射方式改为直接映射（保持 Cache 总容量 64KB 与块大小 32B 不变），定性分析其对容量未命中率与冲突未命中率的综合影响。

## 答案
### (1) 答案：
- 主存块号总位数：25 位（$1\text{GB} / 32\text{B} = 2^{25}$ 块）
- Cache 总行数：2048 行（$64\text{KB} / 32\text{B} = 2^{11}$ 行）
- Cache 总组数：512 组（$2048 / 4 = 2^9$ 组）
- Offset 字段：5 位，bit[4:0]
- Index 字段：9 位，bit[13:5]
- Tag 字段：18 位，bit[31:14]

### (2) 答案：
- $A_1$ 的 Index（bit[13:5]）：二进制 `000000000`，组号 = 0
- $A_2$ 的 Index（bit[13:5]）：二进制 `000000000`，组号 = 0
- 结论：两者会映射到同一组（组0）
- 理由：两地址的 Index 字段完全相同（bit[13:5] 均为 `000000000`），但 Tag 字段不同（$A_1$ 的 bit[31:14] = `00011010001000110100`，$A_2$ 的 bit[31:14] = `00011010001000111100`）。在 4 路组相联映射中，当两地址映射到同一组且该组已满载时，若 Tag 不匹配则触发替换，因此存在映射冲突风险。

### (3) 答案：
① Tag RAM 容量计算：
- 每行标记位数 = Tag(18位) + Valid(1位) + LRU(2位) = 21 位
- 总标记位数 = $2048 \times 21 = 43008$ 位
- Tag RAM 容量 = $43008 / 8 = 5376$ Byte

② 映射方式改为直接映射的影响：
- 冲突未命中率：**增大**。直接映射下每主存块仅能映射到唯一固定位置，相比 4 路组相联的灵活性大幅降低，相同地址访问序列下更易发生不同块争用同一行的冲突未命中。
- 容量未命中率：**基本不变**。容量未命中率取决于 Cache 总容量，映射方式变更不改变 Cache 总容量（仍为 64KB），故对容量未命中率无直接影响。

## 设计说明
### 出题意图
本题以 Cache 地址映射为核心，考查考生对"系统参数→地址字段划分→映射行为分析→存储开销计算"这一完整逻辑链的掌握能力。区别于简单公式套算，题目要求考生自主完成参数推导、二进制地址解析、冲突机理分析，体现 K3 级别的分析计算能力要求。

### 参数选择理由
1. **32 位地址 + 1GB 主存**：保证主存块号位数（25 位）> Cache 行数（11 位），确保 Tag 字段存在且非零，考察意义明确。
2. **64KB Cache + 32B 块大小**：计算简洁（行数为 $2^{11}$），且符合现代计算机系统常见配置比例。
3. **4 路组相联**：介于直接映射与全相联之间，既能体现组相联映射的灵活性优势，又保留冲突分析空间，是工程实践中的典型折中方案。
4. **1 位 Valid + 2 位 LRU**：标记位设计符合 LRU 近似算法（比较 4 路中 2 位即可判断最久未使用）的常见实现，避免过度简化或过度复杂。

### 干扰项设计策略
1. **子问题(1)**：
   - 错误风险点：将组数误认为行数（忘记除以路数 4），导致 Index 位数算成 11 位而非 9 位。
   - 位号范围标注要求迫使考生明确字段边界，避免模糊表达。

2. **子问题(2)**：
   - 地址精心设计：$A_1$ 与 $A_2$ 的 Index 位完全相同（bit[13:5] 均为全 0），但 Tag 位不同，且 Offset 位均为 0（便于观察）。两地址在十进制上相差 $0x8000 = 32768$，恰好为主存块号的 $2^{10}$ 个块差，确保 Index 相同的数学正确性。
   - 易错点：考生可能仅比较 Tag 不同就认为不冲突，而忽略 Index 相同导致映射到同一组的前提条件。

3. **子问题(3)**：
   - 计算干扰：忘记将位换算为 Byte（忘记除以 8），或遗漏 Valid/LRU 位仅计算 Tag 位。
   - 分析干扰：混淆"容量未命中"与"冲突未命中"的影响因素，错误认为直接映射会改变容量未命中率。
