## core_knowledge_intent
- must_test:
  1. 快速排序一趟 Partition 的完整过程：枢轴选取 → 双向扫描比较 → 交换 → 枢轴归位
  2. 两趟 Partition 的连续模拟：第一趟对全表划分后，第二趟对（其中一个）子表继续划分
  3. "一趟"的概念辨析：一趟 = 对一个待排序子表执行一次完整的 Partition，而非对所有未排序子表各执行一次
- must_not_shift_to:
  - 快速排序的时间/空间复杂度分析
  - 枢轴选取策略优劣比较
  - 其他排序算法的模拟
  - 逆向判断题（"不可能是结果"）
- coverage_success_criteria:
  - 学生能正确执行一趟 Partition（含枢轴归位交换），得到第一趟后的序列
  - 学生能正确判断第二趟作用于哪个子表，并完整执行第二趟 Partition
  - 四个选项对应四种不同错误路径，正确选项唯一且可由完整正确的两趟模拟得出

## design_rationale

**考察意图**：本题正面考察快速排序 Partition 过程的手动模拟能力。与 2014_Q11、2019_Q10 等逆向判断题（"哪个不可能是第k趟结果"）不同，本题要求学生正向执行两趟 Partition，直接产出序列——更考验操作的准确性和对 Partition 机制的理解，而非逆向推理能力。

**为什么是两趟而非一趟**：单趟 Partition 只需执行一次扫描-交换过程，区分度有限。两趟模拟引入了"第二趟作用于哪个子表"的决策点——学生必须理解快速排序的递归结构（先处理左子表或先处理右子表），才能正确选择第二趟的操作范围。这恰好命中 K2（单步计算+操作选择）和 K3（过程规划）的双重负荷。

**难度定位**：8-12 个元素的序列，两趟 Partition 约涉及 15-25 步比较与若干次交换，手工模拟工作量大但每步逻辑清晰。difficulty=4 适中：不至于因元素过多而出错率畸高，也不至于因元素过少而缺乏操作步骤。

**区分什么样的学生**：
- 完全掌握：能准确执行两趟 Partition，包括枢轴归位交换和正确选择第二趟子表 → 选正确答案
- 部分掌握：能做第一趟但漏掉枢轴归位交换，或第二趟选错子表 → 落入对应干扰项
- 概念模糊：混淆"一趟"的含义（以为一趟=对所有子表各划分一次）→ 落入干扰项
- 未掌握：只做一趟就停 → 落入"只做一趟"干扰项

## question_structure_plan
- 复用骨架来源：参考 simulation_00264（给定序列+多趟结果的过程展示）、2014_Q11 / 2019_Q10（快速排序第k趟结果的概念考察）。提炼设问句式：给定初始序列 → 问"经过前两趟划分后的序列是什么"。
- 设问形式（选择题，单一设问）：
  - 题干给出 n 个（8 ≤ n ≤ 12）互不相同的正整数组成的初始序列
  - 题干明确指定枢轴选取策略（取首元素 或 取尾元素，二选一，须明确写出）
  - 题干明确使用标准 Partition（以枢轴为基准，将序列划分为"左侧均小于枢轴、右侧均大于枢轴"两部分，枢轴归位）
  - 问题：经过前两趟（two passes）Partition 后，序列的状态是？
  - 四个选项各为一个完整序列（n 个数的排列）
- dependency_pattern：无子问依赖（选择题单一设问），但考察内容内部有递进：第一趟 Partition 结果 → 确定第二趟操作的子表 → 第二趟 Partition 结果

## option_plan（选择题选项锚定）
- 考察的量：前两趟 Partition 完成后的完整序列（n 个元素的排列）
- 选项A（正确）：正确执行两趟完整 Partition 后的序列——第一趟对全表划分并枢轴归位，第二趟对正确子表（默认先处理左子表）执行 Partition 并枢轴归位
- 选项B（干扰·只做一趟）：仅执行第一趟 Partition 后的序列——学生停在第一趟结果，未继续第二趟
- 选项C（干扰·漏枢轴归位交换）：在正确两趟结果的基础上，遗漏了某次 Partition 末尾枢轴与指针相遇位置的交换（枢轴未归位），导致序列中枢轴位置错误
- 选项D（干扰·第二趟作用于错误子表）：第一趟正确，但第二趟对错误的子表执行 Partition（如本应对左子表却对右子表操作，或对整表重新操作），导致序列状态偏离正确结果

**区分度保障**：四种错误路径（正确 / 只做一趟 / 漏枢轴归位 / 第二趟错误子表）产生的序列须互不相同。gen.py 选取参数时须验证四个序列两两不同。若某两条路径产生相同序列，则换参数。

## terminology_and_expression_constraints
- 必须用词：
  - "快速排序"——明确指定算法
  - "一趟划分"或"一次 Partition"——明确"趟"的定义
  - "枢轴"（pivot）——不可省略枢轴选取策略的说明
  - "前两趟"——明确要求两趟，而非一趟或全部完成
- 题干须明确的内容：
  - 枢轴选取策略：须写出"以序列的第一个元素作为枢轴"或"以序列的最后一个元素作为枢轴"
  - Partition 的方向约定（若取首元素为枢轴，须明确是从右端开始扫描还是从左端开始）
  - "一趟"的含义：对单个待排序子表执行一次完整 Partition
- 禁止表述：
  - 不得使用"第k趟排序结果"而不定义"趟"——须避免与"对所有未定位子表各执行一次"的歧义
  - 不得含混"前两趟"的范围——须明确第二趟作用于第一趟划分后的哪个子表（如"默认优先处理左子表"）
  - 不得在题干中透露枢轴的最终位置或子表划分情况

## audit_focus
1. **选项区分度（最高优先级）**：四个选项（正确 / 只做一趟 / 漏枢轴归位 / 第二趟错误子表）产生的序列是否两两不同？若有重合，题目失效，须换参数。
2. **"趟"的定义清晰度**：题干是否明确"一趟 = 对单个子表执行一次 Partition"？是否明确第二趟作用于哪个子表？若不明确，学生会因"趟"的歧义而无法作答。
3. **枢轴策略明确性**：题干是否明确写出枢轴选取方式（首元素 / 尾元素）和扫描方向？缺失则题目不成立。
4. **参数有效性**：第一趟划分后左右子表是否均非空？第二趟是否有实际操作（非平凡）？若某子表为空或长度为1，第二趟无内容，题目退化。
5. **元素值域**：是否为互不相同的正整数？有无重复元素导致比较结果歧义？
6. **考点不偏移**：确认题目不涉及时间复杂度、空间复杂度、枢轴优化等内容。
