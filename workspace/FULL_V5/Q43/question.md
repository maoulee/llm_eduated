## 题干
假设某计算机系统的存储器系统参数如下：主存地址长度为 32 位，Cache 容量为 2KB，主存和 Cache 均按块编制，块大小为 64B。

## 子问题
### (1)（4分）
若 Cache 采用直接映射方式，请计算主存地址中标记（Tag）、组索引（Index）、块内偏移（Offset）三部分的位数。并给出主存地址 `12345678H` 对应的这三级字段的值（用十六进制表示）。

### (2)（4分）
若 Cache 改为 2 路组相联映射（每组 2 行），请计算此时 Tag、Index、Offset 的位数，并说明与直接映射相比各字段位数的变化。

### (3)（4分）
在 2 路组相联映射方式下，Cache 初始为空，组内采用 LRU 替换算法（访问命中与缺失均更新最近使用状态）。给出如下 5 个主存地址的访问序列：
`00000080H, 00000100H, 00000080H, 00000180H, 00000080H`
请分析每次访问的命中/缺失情况，并计算该序列的 Cache 命中率。

## 选项
（本题为综合计算与分析题，无选项）

## 答案
### (1)
- **位数计算**：
  - 块大小 64B，故 Offset = $\log_2{64} = 6$ 位。
  - Cache 容量 2KB = 2048B，直接映射下 Cache 行数 = $2048 / 64 = 32$ 行，故 Index = $\log_2{32} = 5$ 位。
  - 主存地址 32 位，故 Tag = $32 - 5 - 6 = 21$ 位。
- **地址解析**（`12345678H`）：
  - Offset（低6位）：`38H`
  - Index（中间5位）：`13H`
  - Tag（高21位）：`12345H`

### (2)
- **位数计算**：
  - 2 路组相联，组数 = $32 / 2 = 16$ 组，故 Index = $\log_2{16} = 4$ 位。
  - Offset 保持不变，仍为 6 位。
  - Tag = $32 - 4 - 6 = 22$ 位。
- **变化说明**：
  - 与直接映射相比，Index 位数减少 1 位（从 5 位变为 4 位），Tag 位数增加 1 位（从 21 位变为 22 位），Offset 位数不变。

### (3)
- **地址块号与映射分析**：
  - 块号 = 主存地址 >> 6。组号 = 块号 & 0FH（低4位）。Tag = 块号 >> 4。
  - `00000080H` -> 块号 `0x10` -> 组号 `0`，Tag `1`
  - `00000100H` -> 块号 `0x20` -> 组号 `0`，Tag `2`
  - `00000180H` -> 块号 `0x30` -> 组号 `0`，Tag `3`
  - 所有地址均映射到 **第 0 组**。
- **访问过程推演**（LRU算法，命中/缺失均更新状态）：
  1. 访问 `00000080H` (Tag=1)：**缺失**。Cache 第0组装入 [Tag1]。最近使用序列：[Tag1]
  2. 访问 `00000100H` (Tag=2)：**缺失**。Cache 第0组装入 [Tag1, Tag2]。最近使用序列：[Tag2, Tag1]（Tag2最近）
  3. 访问 `00000080H` (Tag=1)：**命中**。更新状态。最近使用序列：[Tag1, Tag2]
  4. 访问 `00000180H` (Tag=3)：**缺失**。组满，替换最老的 Tag2。装入 [Tag1, Tag3]。最近使用序列：[Tag3, Tag1]
  5. 访问 `00000080H` (Tag=1)：**命中**。更新状态。最近使用序列：[Tag1, Tag3]
- **命中率计算**：
  - 5 次访问中共命中 2 次，缺失 3 次。
  - 命中率 = $2 / 5 = 40\%$。

## 设计说明
- **出题意图**：本题综合考察 Cache 地址映射原理与替换算法。通过直接映射与组相联的对比，强化学生对地址结构（Tag/Index/Offset）划分逻辑的理解；通过特定访问序列的推演，检验 LRU 算法在实际冲突场景下的执行细节。
- **参数选择理由**：选用 32 位地址、64B 块大小、2KB Cache 为典型考研参数，保证计算量适中（Offset 6位、Index 4/5位、Tag 21/22位），便于手算验证。地址 `12345678H` 结构规整，十六进制切分清晰。
- **干扰项/易错点设计**：
  1. **位数混淆**：学生易将组相联的 Index 与直接映射混淆，或错误认为 Tag 位数减少。题目要求明确写出变化，直击此误区。
  2. **LRU 更新时机**：第 3 次访问命中 `00000080H` 时，若未更新 LRU 状态，会导致第 4 次替换错误（误认为 Tag1 最老）。题干明确“命中与缺失均更新”，考察细节严谨性。
  3. **地址换算**：序列地址均落在同一组但不同块，刻意构造“真冲突”而非随机访问，确保计算过程聚焦替换逻辑而非地址转换本身。
