# 骨架设计技能

## 目标
设计题目骨架：考什么、怎么分问、每问考察什么。不设计具体参数/数值。

## 必须包含 7 个 section
1. status
2. blueprint_contract
3. core_knowledge_intent
4. design_rationale（含考点融合意图，如有）
5. question_structure_plan（经验驱动的子问链）
6. terminology_and_expression_constraints
7. audit_focus

## 已移除的 section（不再需要）
- ~~route~~：系统根据 complexity 判断，不是骨架的事
- ~~expected_reasoning_actions~~：解题步骤是下游 solve 的事
- ~~parameter_plan~~：具体参数是下游 gen.py 的事

## blueprint_contract
从蓝图原样摘取。不得修改 should_be / should_not_be / K目标 / 难度。

## core_knowledge_intent
- must_test：本题必须考什么（2-3项）
- must_not_shift_to：不允许偏移到什么
- coverage_success_criteria：覆盖成功的标准

## design_rationale（设计理念 + 考点融合）

回答：**"为什么这样考？"**

写清楚：
- 本题考察意图：为什么选这个考点组合、这种设问方式
- 区分什么样掌握程度的学生
- 为什么这个难度合适

**考点融合**（仅 K3-K4 高难度，可选）：
- 同一知识点的不同考察项融合（如既考机制辨析又考定量计算）
- 不是跨考点融合，不是强行要求
- 在这里决定，写入此段。下游看到多个考察项直接实现

## question_structure_plan（往年题锚定的设问结构）

**设问结构 = 基于往年题复用，不发明**（spec §16.1 核心原则）。

人类专家出题时，先看往年同类题怎么设问，再套用其结构。你也一样：

### 步骤 1：读往年题参考（优先）

assembled.md 的「往年真题参考」段（前段已检索好，直接读）包含同知识点的往年题：
- **题干设问句式**：往年题是怎么问的——这是你设问结构的锚点
- **子问组织方式**：几个子问、子问间怎么递进（基础→进阶→区分度）
- **K值雷达**：往年同类题的认知负荷分布，佐证难度定位

从往年题的设问句式中**提炼可复用的设问骨架**（去特化，留结构）。

### 步骤 2：基于往年骨架 + 本次要求定设问结构

把提炼的设问骨架套到本次考点：
- 复用往年的设问句式和子问递进结构（这是"体型结构"）
- 根据本次 design_rationale 的考察意图微调（如考点融合需加子问）
- **不发明新结构**——骨架从往年复用，发明会触发脑内验证（过度思考根因）

### 步骤 3：缓存不足时自检索（fallback，最多 1 次）

**默认直接用 assembled.md 的往年真题参考**——它已经由前段检索好并注入。
读完缓存就直接进步骤2定结构，**不要因为"想再多找几道"而重复 grep**。

只有当 assembled.md 的「往年真题参考」段**完全缺失**（不是"觉得不够"）时，才 grep：
- **只调 1 次** grep_search，query 用考点核心术语组合，一次覆盖
- **不拆成多个短关键词多次搜**（一次组合 query 搜完）
- 检索到后读取题干，提炼设问骨架，立即定结构
- grep 是 fallback，不是常规步骤——缓存有就用缓存

### 输出格式

```
- 复用骨架来源：[往年题文件名 + 提炼的设问句式]
- 子问1：考[考察点]（基础层）—— 参考往年[X题]的问法："..."
- 子问2：基于子问1的结果，考[考察点]（进阶层）—— 参考往年[X题]的问法："..."
- 子问3（可选）：汇总/分析（区分度层）
- dependency_pattern：串行依赖
```

**只写"考什么 + 参考往年怎么问"，不写"怎么算"。不写具体数值/节点/参数。**

## 选择题选项锚定（仅 single_choice）

选择题在骨架层锚定**每个选项对应什么参数**——定好选项的考察内容，不设具体值。

在 question_structure_plan 后增加选项锚定段：
```
## option_plan（仅选择题）
- 考察的量：[本题要求学生求什么量]
- 选项A（正确）：[正确值对应的参数]
- 选项B（干扰）：[错误模式——对正确值做什么变换，如"符号取反"]
- 选项C（干扰）：[错误模式——如"off-by-one（差1）"]
- 选项D（干扰）：[错误模式——如"用了操作前的值"]
```

**骨架层只锚定"选项考什么参数 + 干扰项的错误模式"，不设具体值。** 下游 gen.py 在求解路径上自然打印出这些参数的正确值，LLM 再对正确值做变换得到干扰项。

## 通用干扰模式库（供 option_plan / audit_focus 参考）

### 计算型干扰
- 单位换算陷阱、符号错误、偏移错误(off-by-one)、中间值、倒置

### 概念型干扰
- 概念混淆、过度推断、条件遗漏、张冠李戴

### 组合判断型干扰
- I/II/III 各代表独立命题，干扰项是"真+假"混合组合

## 教师说明与排除项
- teacher_annotation 必须在 blueprint_contract 或 audit_focus 中体现
- excluded.modes / excluded.knowledge 不得进入 must_test

## 关键约束
- 不得出现具体数值/答案/最终计算结果
- question_structure_plan 只写考察方向，不写解题步骤
- 不设计具体参数（节点值/插入序列/资源矩阵）
- 当往年经验与本次要求冲突时，以本次出题要求为最高优先级
