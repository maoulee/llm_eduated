# 考察形式技能（具体逻辑，§17.3）

> 通用行为（角色、思考控制、红线）定义在 agents/exam_form.md。
> 本文件定义判定流程、K-雷达形状映射、形式候选库。

## 判定流程（窄任务）

### Step 1：读上游约束

读取 design_card.md（或 assembled.md）：
- core_knowledge_intent（必须考什么 KP）
- k_target / 目标 K-雷达形状
- examination_mode（经验卡的考察模式，作为形式候选参考）

### Step 2：按 K-雷达形状选定考察形式

按主导维度（雷达图最高/关键维度）选形式：

| 主导维度 | 典型考察形式 | 说明 |
|---------|------------|------|
| K3（机制推演）主导 | 多步串行推演 | 过程模拟、状态跟踪、串行子问 |
| K4（条件路由）主导 | 陷阱辨析 | 隐含前提、反直觉条件、边界讨论 |
| K1（基础认知）主导 | 概念辨析 | 定义判断、易混概念区分 |
| K2（单步代入）主导 | 单点计算 | 单步参数代入计算 |
| K5（跨域联动）主导 | 跨域组合 | 多子系统数据/状态传递 |

混合形状 → 混合形式（注明主+辅）。

### Step 3：落地 K-雷达值 + 写理由

- 把目标 K-雷达形状落到 5 维数值（1-5 each）
- 一句话理由：基于 KP + 主导维度为何选此形式
- 不脑内构造具体题目，不验证形式"成立"

## 形式候选库（不发明，只选定）

- **多步串行推演**：基础问→核心问→区分度问，子问串行依赖（综合题典型）
- **陷阱辨析**：设陷阱条件，考生需识别隐含前提/反直觉点
- **概念辨析**：定义判断、易混概念（A 是 X 但不是 Y 类）
- **单点计算**：给参数→单步算结果（选择题典型计算题）
- **组合判断**：命题 I/II/III 组合，选正确组合
- **跨域组合**：多子系统联动（如 OS+存储、数据结构+算法分析）

若经验卡 examination_mode 已指定形式，优先采用并与 K-雷达核对一致。

## 禁止（重申）

- 不写题干、不写子问、不写答案、不写选项
- 不脑内模拟具体题目
- 不自创形式名
- 判定形式后即止，不延伸到骨架/求解
