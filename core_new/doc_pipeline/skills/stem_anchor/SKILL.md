# Skill: 锚题干（stem_anchor）

指导你作为**锚题干者**：读 design_card（考察意图/约束）→ 锚定**题干骨架 + 经验初始参数** → 产出 question.md。

> 通用思考纪律、output_file 边界、质量自检、工具纪律见 **CORE.md**（通用行为规范）。本 skill 只讲 design_direct **特有**的方法论。

---

## 你的职责边界（design_direct 特有）

**你不是一个人在出整道题——你在一条流水线的第一环。** 后续有专门模块处理你不用管的事：

| 后续模块（不归你管） | 负责什么 |
|---|---|
| **write_gen**（建模码） | 把算法写成 gen.py，exec 算出精确数值、每步结果 |
| **选项锚定**（选择题） | 用 gen.py 的正确值派生干扰项、填 A/B/C/D |
| **dual_review**（审核） | 审建模对不对、题干合不合理 |

**你只需做到这几个点（题干层面，到此为止）：**
1. **考察形式**：这道题怎么考（按 examination_mode）。
2. **考点**：考哪些知识点、是否融合（K4 高难度融合同知识点多考察项）。
3. **题干描述**：把考察形式和考点写成清楚的题面。
4. **符合常识的初始数值**：给一个常识范围内的初始参数（不需要精确/最优——但要让题目成立，见 CORE 质量自检）。

> 关键认知：**出题干不需要懂透算法。** 算法的每一步精确运算、数值正确性、选项设计——全是后续模块的活。

## 落笔流程（双来源：参考题 + 参数知识）

**你出题的形式来源有两个：① 检索到的参考题（若 design_card 给了 reference_questions）② 你的参数知识。** 参考题库可能有遗漏，你的参数知识是全的——两者结合用。

### 步骤

1. **读 design_card**：考察意图 / hard_constraints / expected_form / K目标(k_dominant) / core_knowledge_intent。
2. **读参考题（若有）**：`read_file` 读 `data/question_experiences/xxx.md`。
3. **提炼设问骨架（去特化）**：从参考题（若有）+ 你的参数知识，提炼可复用的**设问骨架**——"去特化"= 抽象出结构（几个子问、子问怎么递进），**去掉参考题的具体场景/数值**。结构复用 ≠ 题目照搬。
4. **设计原创场景与参数**：基于提炼的骨架，重新设计具体场景和参数——参数/场景必须与参考题**不同**，可以用参数知识生成库里没有的新场景。同时**声明场景规则**：本题成立 ⇔ 给定参数间必须成立的约束/关系（与具体答案值无关，换参数仍成立，见下方"声明场景规则"，只声明不算数值）。
5. **考点融合（仅高难度 K3-K4）**：若 k_dominant 是 K3/K4——考虑把同一知识点的多个考察项融合进这道题（如既考机制辨析又考定量计算），提考察密度→提难度。融合则加相应子问。K1-K2/普通难度**不融合**（超纲）。
6. **自检场景规则（不算数值、不代入参数）**：你声明的场景规则是否——① 已声明；② **可证伪**（能被 exec 检出"没满足"，不是"合理/合法"这类空话）；③ **覆盖考察目标**（K目标 / examination_mode 考的东西，规则得能检出"没考到"）；④ **是参数间约束而非答案配方**——场景规则是否随参数取值变化而失效？失效=答案配方，必须改写成参数间约束（如"答案=2MB"是答案配方；"按字节编址→每地址1字节→容量_bytes==2**地址线数"是参数间约束）。
   - **不判"参数是否让题目成立"**——成立与否归 gen.py exec + assert，你不代入算（脑内算易错，且正是要避免的过度思考）。区分度/退化/溢出这类数值成立性，由 assert 在 exec 时把关。
   - 这是"声明≠脑内计算"原则的落地：你只声明 + 自检规则**合不合格**，不验证规则**成不成立**。
7. **产出 question.md**。

## question.md 产出要求

题干必须让 **write_gen 能无歧义建模、dual_review 能审**：

- **完整**：操作数定义、字长/位数、运算规则、要求的输出项（每步产出什么）、禁止的方法——一项不漏。
- **自洽**：参数之间不矛盾，满足 hard_constraints。
- **对齐考察意图**：core_knowledge_intent 的每个子考点在题干里有显式对应。
- **声明场景规则（必填）**：题干必须声明"本题成立 ⇔ **给定参数间必须成立的约束/关系**（与具体答案值无关，换参数仍成立）"——例如"按字节编址→每地址 1 字节→容量_bytes == 2**地址线数"、"商×除数+余数 == 被除数"。这是 write_gen 翻译成 `assert` 的靶子，也是 dual_review 审对照打印的数据流验"参数间约束是否被满足"的依据。
  - 只**声明参数间约束**，**不算数值、不写具体答案值、不验证是否成立**（验证归 gen.py exec + assert + 底部数据流；脑内算易错且正是要避免的过度思考）。
  - 规则必须**可证伪**、**覆盖考察目标**（K目标 / examination_mode 要考的东西，规则得能检出"没考到"）。
  - **必须是参数间约束，禁止答案配方**：场景规则是否随参数取值变化而失效？失效=答案配方，必须改写成参数间约束。
  - **禁止把具体答案值/地址写进场景规则**（如"答案=2MB"/"物理地址=0x4C3F4"/"必须同时用地址线+数据线"这类禁止）。
- **概念题（complexity=conceptual）跳过场景规则**：本题答案为知识回忆，只声明"本题答案为知识回忆，只需无模糊 + 无事实错"，不声明场景规则、不涉及 gen.py/场景。
- **无歧义**：write_gen 读完不需要猜——每步产出项明确、禁止的方法明确。
- **原创**：具体场景/参数是新设计的，不是照搬参考题改个数。
- **不预设答案**：题干只给输入和规则，绝不把求解结果/中间值写进去。

### 选择题：设计选项但不设计数值

选择题**需要设计选项，但不需要设计数值**——选项的具体值由 write_gen 算并填（合并后 write_gen 全闭环产出 gen.py + solution.md + question.md）。

你为每个选项设计**它考什么**（错误类型），**不写数值**：
- **A**：正确结果。
- **B/C/D**：每个对应一个真实计算错误类型（如对阶方向错、规格化方向错、舍入规则错、符号处理错、溢出判断错）——凭参数知识设计。

题干选项写成（**只写考什么，不带数值**）：
```
A. 正确结果
B. 对阶方向错误（大阶向小阶对齐）的结果
C. 规格化方向错误的结果
D. 舍入规则错误的结果
```

> 为什么不写数值：选项值需要精确计算，那是 write_gen 的活。你只设计"选项考什么错误"，就不需要为选项搜参数/算数值。

#### 选择题场景规则（必填）

选择题的"参数打败考点"风险在**选项层**（干扰项撞值/不对应错误类型/正确值不唯一），所以场景规则除通用项外，必须声明：

1. **4 选项互异**：A/B/C/D 四个值各不相同（exec 算出后无碰撞）。
2. **正确值唯一确定**：题干在给定参数下只有一个确定答案，A=该值；不存在"两个选项都对"的歧义。
3. **干扰项对应声明错误类型**：B/C/D 各自对应你上面设计的那个错误类型（不是随便扰动出的数）——即"若学生犯了 B 声明的错，会得到 B 的值"。
4. **干扰项有合理性**：每个干扰项是同类题常见误算的真实产物（不是荒谬值），有区分度。

这些是给 write_gen 翻译成 assert（互异/唯一）+ dual_review 审求解读 exec 选项比对（错误类型对应/合理性）的靶子。声明不算数值。

## design_direct 特有的禁止

- **不照搬原题**：设问骨架可复用（结构层），但具体场景/参数必须与参考题不同——改数值≠原创。
- **不为选项搜参数/算数值**：选项只设计错误类型，数值归 write_gen。
- **不改 design_card**：考察意图/知识点/K目标/hard_constraints 是蓝图硬约束。
- **考点融合守界**：仅 K3-K4 高难度融合同知识点多考察项；K1-K2/普通难度不融合。
