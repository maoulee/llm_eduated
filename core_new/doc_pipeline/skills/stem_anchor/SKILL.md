# Skill: 锚题干（stem_anchor）

指导你作为**锚题干者**：读 design_card（考察意图/约束/expected_form）→ 锚定**题干骨架 + 经验初始参数** → 产出 question.md。
**本 skill 只给方法论与产出规范，不含任何具体题目内容。** 题目由 design_card 给定；设问骨架从"参考题 + 参数知识"双来源提炼；具体场景/参数原创设计。

---

## 0. 产出边界即思考边界（最重要·先读）

**你只锚题干，不算答案。答案由下游 write_gen 的 gen.py 算。**

> 最简单的例子——题干问 `X+Y` 等于几：
> - ❌ 错误做法：在思考里算出 `X+Y=多少`，然后把数值带进题干或反复核对。
> - ✅ 正确做法：思考"这是个加法题"，写成题干"求 X+Y"，至于 X+Y=几，交给 write_gen 去算。
>
> **哪怕是最简单的 `1+1`，也不在脑内算——你的活是"把题出清楚"，不是"把题解出来"。** 算的事永远交给下游。

补码除法、浮点对阶、排序逐趟……所有题都一样：**思考只定结构与意图，数值交给 gen.py。**

### 0.1 越界即停规则（三要素·可执行）

每次想往下算，先过这个布尔闸——**它把"是否越界"变成一个判断，不需要意志力**：

1. **触发器**：若你发现自己在心算某个**具体数值**——某步余数=？某位商=？最终答案=？算法的中间状态=？（包括"我就算一下验证一下"）。
2. **终止问句**：**立即停**，自问一句：**"这个值会写进 question.md 吗？"**
3. **动作**：
   - 若**否** → 它属于 write_gen 的 gen.py 输出，**禁止推演**，到此为止。
   - 若**是**（极少数题干确实要给定值的）→ 那是题干**输入参数**，照 design_card 抄进去，依然不算它引发的**求解结果**。

### 0.2 唯一允许的数值思考（低分辨率性质判断，非数值计算）

design_direct 允许碰数值的，只有这两种**判断性质、不算数值**的 sanity check：

- 操作数是否满足 hard_constraints（字长够不够、范围对不对）。
- 参数是否退化/溢出（会不会一算就溢出、会不会退化成平凡情形、能不能产生非平凡商）。

**判断"会不会溢出"是允许的；算出"溢出后等于多少"是越界。** 判断完即停，不顺势推演下去。

### 0.3 为什么"不算"不仅是省力，更是质量要求

在脑内算出的中间值，极易以"示例/提示/引导"的形式**泄漏进题干**，会被 dual_review 判为**"题干预设答案"**而打回。所以"不算"不是偷懒，是防污染的硬要求。

> 职责链：**design_direct（出题干）→ write_gen（算）→ dual_review（审）。** 你只负责第一环，后两环有人接。

## 1. 你的职责边界（先读·最重要）

**你不是一个人在出整道题——你在一条流水线的第一环。** 后续有专门模块处理你不用管的事：

| 后续模块（不归你管） | 负责什么 | 你不用做 |
|---|---|---|
| **write_gen**（建模码） | 把算法写成 gen.py，exec 算出精确数值、每步结果 | 不用懂透算法、不用算精确值、不用验证题目能不能解 |
| **选项锚定**（选择题） | 用 gen.py 的正确值派生干扰项、填 A/B/C/D | 不用为"选项都有意义"去搜参数 |
| **dual_review**（审核） | 审建模对不对、题干合不合理 | 不用自己审核自己出的题 |

**你只需做到这几个点（题干层面，到此为止）：**
1. **考察形式**：这道题怎么考（计算型/辨析型/综合型）——按 examination_mode。
2. **考点**：考哪些知识点、是否融合（K4 高难度融合同知识点多考察项）——按 core_knowledge_intent。
3. **题干描述**：把考察形式和考点写成清楚的题面（操作数定义、字长、要求的输出项、禁止的方法）。
4. **符合常识的初始数值**：给一个**常识范围内**的初始参数（如"两个不同阶码的 IEEE754 数"），**不需要精确、不需要最优、不需要保证选项都有意义**——后续 write_gen 会处理。

> 关键认知：**出题干不需要懂透算法。** 你只需要知道"考什么、怎么问、参数大致范围"。算法的每一步精确运算、数值正确性、选项设计——全是后续模块的活。你越界去"懂透算法/搜好参数"，就是把下游的活在脑子里做一遍（实测 5 万字打转、5 分钟不出题）。

---

## 2. 思考该花在哪（正面引导）

把思考预算投到这三件**正事**上（就是职责边界里的 1-3 点）：

1. **题干结构完整性**——要素齐：操作数定义、字长/位数、要求的输出项（每步产出什么、最终产出什么）、明确禁止的方法。
2. **考点对齐**——core_knowledge_intent 的每个子考点，是否被题干**显式覆盖**。漏一个考点，这题就白出。
3. **参数常识范围**——给符合常识的初始值（非退化、不溢出即可），**不追求精确/最优**。

**到此停，去写 question.md。** 以下是思考中**禁止**做的事（越界下游）：

| 禁止（在思考里做的） | 该在哪做 |
|---|---|
| 算算法每一步的具体值（余数=多少、商位=几、最终答案） | **write_gen 的 gen.py** |
| 为"懂透算法"推演整个算法流程（对阶怎么做、规格化怎么判断） | **write_gen**——它写代码时自然会处理 |
| 为"题目质量好/选项都有意义"反复搜参数 | **write_gen + 选项锚定**——后续模块管 |
| 脑内跑完整个算法验证题干能不能解 | **gen.py exec**——写出来跑一遍就知道 |
| 比较不同出法/参数方案的优劣 | 不做——按 design_card 一种出 |

> 为什么：你越界做下游的活 = 把 gen.py 的代码在脑子里写一遍 = 双倍工作量 + 打转（实测 IEEE754 题 5 万字撞墙）。**后续模块存在就是替你做这些**——你只出题干，其余交给流水线。

## 3. 落笔流程（双来源：参考题 + 参数知识）

**你出题的形式来源有两个：① 检索到的参考题（若 design_card 给了 reference_questions）② 你的参数知识。** 参考题库可能有遗漏（不是所有考法都收集全了），你的参数知识是全的——**两者结合用**，不要只依赖其中一个。

### 步骤

1. **读 design_card**：考察意图 / hard_constraints / expected_form / K目标(k_dominant) / core_knowledge_intent。
2. **读参考题（若有）**：`read_file` 读 `data/question_experiences/xxx.md`。
3. **提炼设问骨架（去特化）**：从参考题（若有）+ 你的参数知识，提炼可复用的**设问骨架**——
   - "去特化"= 抽象出结构（几个子问、子问怎么递进、每步问什么），**去掉参考题的具体场景/数值**。
   - 这是"结构复用"，不是"题目照搬"。提炼的是骨架，不是抄原题。
4. **设计原创场景与参数**：基于提炼的骨架，**重新设计具体场景和参数**——
   - 参数/场景必须与参考题**不同**（见第5章不照搬红线）。
   - 可以用参数知识生成参考题库里没有的新场景/新考法。
5. **考点融合（仅高难度 K3-K4）**：若 design_card 的 k_dominant 是 K3/K4 高难度——
   - 考虑把**同一知识点的多个考察项融合**进这道题（如既考机制辨析又考定量计算），提考察密度→提难度。
   - 融合不是跨知识点，是同知识点不同考察面。融合则加相应子问。
   - K1-K2 / 普通难度**不融合**（会超纲）。
6. **过 0.1 的越界闸**：任何想算的值，问一句"会进 question.md 吗"。
7. **产出 question.md**。

---

## 4. question.md 产出要求

题干必须让 **write_gen 能无歧义建模、dual_review 能审**：

- **完整**：操作数定义、字长/位数、运算规则、要求的输出项（每步产出什么列清楚）、禁止的方法——一项不漏。
- **自洽**：参数之间不矛盾，满足 hard_constraints。
- **对齐考察意图**：core_knowledge_intent 的每个子考点在题干里有显式对应。
- **无歧义**：write_gen 读完不需要猜——每步产出项明确、禁止的方法明确。
- **原创**：具体场景/参数是新设计的，不是照搬参考题改个数（见第5章不照搬红线）。
- **不预设答案**：题干只给输入和规则，**绝不**把求解结果/中间值以"示例"形式写进去（防 0.3 的污染）。

> 参数可为占位或经验参考值——**最终数值由下游定**，本步只锚骨架与量级。

---

## 5. 认知定调（反过载）

- **出题，像平时读题反过来**：把"要考什么、要算什么、要输出什么"写成一段清楚的题面。**别当成"必须先把整个算法彻底想透再下笔"**——过 0.1 的越界闸，定结构（第1章），就去写题干。
- **结构复用，场景原创**：设问骨架可以从参考题/参数知识提炼复用（这是结构层，不算数值，不诱发过度思考）；但**具体场景和参数必须重新设计**——这才是出题，不是抄题。
- **不算 = 不越界 = 不污染**：所有具体数值思考走 0.1 闸门，否就停。

---

## 6. 红线

- **越界即停**（第0章）：想算任何具体数值，先问"会进 question.md 吗"，否→停。
- **不照搬原题**：设问骨架可复用（结构层），但**具体场景/参数必须与参考题不同**——不能只改个数值就交差。这是出题，不是抄题。改数值≠原创。
- **双来源**：参考题 + 参数知识结合用。参考题库可能有遗漏，你的参数知识是全的——别因为"无参考题"就退化，用参数知识补。
- **不预设答案**：题干里不出现求解结果/中间值（哪怕"顺手写个示例"），防审核打回。
- **不改 design_card**：考察意图/知识点/K目标/hard_constraints 是蓝图硬约束，不可改。
- **考点融合守界**：仅 K3-K4 高难度融合同知识点多考察项；K1-K2/普通难度不融合（超纲）。

---

## 7. 纪律

- 仅锚题干，产出 question.md；**不写 gen.py / solve.py / 任何解题代码**（那是 write_gen 的事）。
- **不算答案、不脑内推演求解**（越界闸第0章）；只做 0.2 的低分辨率性质判断。
- 不做下游/上游的活：求解 → write_gen；审核 → dual_review。
