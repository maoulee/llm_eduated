# 骨架分析技能（具体逻辑，§16.2/§17.3）

> 通用行为（角色、思考控制、红线）定义在 agents/skeleton_design.md。
> 本文件定义骨架复用流程、符号化模板、solve.py 正确算法 DAG 写法。

## 出题流程

### Step 1：读上游

读取：
- exam_form.md（考察形式 + K-雷达形状）
- design_card.md（blueprint_contract、core_knowledge_intent、question_structure_plan、parameter_plan、术语约束）
- assembled.md（经验卡 should_be/should_not_be、往年真题经验）

### Step 2：检索同题型往年题 → 提炼骨架（§16.1 核心）

- 按**题型 + 考点**检索往年同类型题（综合题别取成选择题）。
- 分析其结构（不是抄内容）：子问组织、考察递进、设问方式。
- 提炼成可复用骨架（去特化，留结构）。
- **分析 = 提取（已知成立，无需验证）；不发明新结构（发明才需脑内验证）。**

### Step 3：按难度选/调骨架（§16.3）

- 基于 K-雷达形状选骨架（K3 主导→多步串行骨架；K4 主导→陷阱辨析骨架；K1 主导→概念辨析骨架）。
- 骨架可缩放：增/减串行步数（调 K3）、加/去陷阱（调 K4）、加/去跨域联动（调 K5）、改概念辨析深度（调 K1）。
- 缩放的是雷达各维，不是单一难度档。

### Step 4：条件融合（§17.6，仅 K3-K4 高难度）

- K1-K2 / K3 简单·正常题：**不融合**，单骨架直接用。
- 仅 K3-K4 高难度且单骨架不足以达难度：融合同考点多侧重（非跨考点）。
- 难度已达标 → 不额外融合（避免超纲）。

### Step 5：符号化题干（套骨架）

把骨架套到本题，参数用**符号占位**（`N`、`K`、序列首项等），不写死具体数值答案：
- 综合题：共享题干（系统状态/数据结构/配置，符号占位）+ 子问链（### (N) （X分），串行依赖）。
- 选择题：符号化题干 + 提问，**不出 A/B/C/D 选项**（选项由 solve 后组装）。

### Step 6：写 solve.py（正确算法 DAG，§17.5）

把考察形式写成参数化确定性计算路径：

```python
# solve.py 契约（不给具体骨架，结构自主决定）：
# 1. 参数化确定性 DAG：initial_params → 中间参数 → 正确答案
# 2. 只算正确答案（选择题 1 值 / 综合题各子问）
# 3. 不编码错误算法、不输出干扰值
# 4. print 正确答案 + 逻辑标签
```

模型给 1-2 个初始参数（经验预设，2^n 友好值），代码传播出全部正确参数 + 结果。

### Step 7：输出

- write_file(question.md) — 符号化题干 + 设计说明（不含答案值/选项值）
- write_file(solve.py) — 正确算法 DAG（只算正确，无错误算法）
- **不写答案/选项值** — 答案由 solve 阶段执行 solve.py 得出

## 骨架复用纪律（§16.1）

| 做法 | 是否触发脑内模拟 |
|------|----------------|
| 分析往年题→提取骨架（复用） | 否（提取，已知成立） |
| 发明新结构→验证它成立 | 是（脑内模拟，过度思考） |

**只复用，不发明。** 这是消除综合题过度思考的治本落点。

## 符号化题干模板

### 综合题
```
[共享题干：系统状态/数据结构/配置，参数符号占位]
请回答下列问题：
### (1) （2分）[基础问：参数计算/机制推导]
### (2) （3分）基于(1)的结果，[核心问：过程模拟/状态跟踪]
### (3) （2分）基于(2)的结果，[区分度问：结果分析/边界讨论]
```

### 选择题
```
[符号化题干：给参数（符号占位）+ 场景 + 提问]
（不出 A/B/C/D——选项由 solve 后组装）
```

## 设计说明必写项

```markdown
## 设计说明
- 复用骨架来源：[往年题类型 / 骨架名]
- 考察形式：[来自 exam_form]
- 子问依赖链 / 设问结构
- solve.py 正确算法 DAG 路径：输入 → 中间参数 → 正确答案
- 初始参数选择理由（为何 2^n 友好值）
- 与目标 K-雷达的对齐
- 是否融合（仅 K3-K4 高难度时）+ 理由
```
