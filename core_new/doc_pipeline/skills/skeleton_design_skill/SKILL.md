# 骨架分析技能（具体逻辑，§16.2/§18）

> 通用行为（角色、思考控制、红线）定义在 agents/skeleton_design.md。
> 本文件定义骨架复用流程、题干模板。**设计聚焦题干 + 设问 + 初步参数，不验证（纪律①）。**

## 出题流程

### Step 1：读上游

读取：
- exam_form.md（考察形式 + K-雷达形状）
- design_card.md（blueprint_contract、core_knowledge_intent、question_structure_plan、parameter_plan、术语约束）
- assembled.md（经验卡 should_be/should_not_be、往年真题经验）

### Step 2：消费上游经验缓存 → 提炼骨架（§16.1 核心，**缓存优先**）

> 上游规划/设计阶段已经负责粗粒度检索和经验归纳。你的第一步是**读取缓存并复用**，不是重新检索。

1. **优先读缓存**：从 assembled.md / design_card.md 中提取：
   - 往年真题经验 / 参考经验摘要 / 模式概览
   - should_be / should_not_be
   - examination_mode、question_structure_plan、parameter_plan
2. **粗粒度理解**：基于缓存理解"这类题一般怎么考、怎么设问、难度锚点是什么"；不要为了找更贴合的细碎案例重复检索。
3. **提炼骨架（去特化，留结构）**：把缓存中的具体表述抽象成可复用骨架（去特化，留结构）。
4. **fallback grep（仅缓存缺失/完全无关时）**：
   - 只允许一次粗粒度 `grep_search`，按知识域/核心考点/题型检索。
   - 示例：`{"query":["DS-5","树与二叉树","二叉树遍历"],"subject":"数据结构","question_type":"综合题","max_results":20}`。
   - 不按"前序/中序/后序/还原"等细碎子技能反复检索。
5. **分析 = 提取（已知成立，无需验证）；不发明新结构（发明才需脑内验证）。**

缓存/检索纪律：
- **缓存存在则不 grep**：assembled/design_card 已有往年经验或参考经验摘要时，直接用缓存。
- **粗粒度 fallback**：缓存缺失时最多一次，用知识域/核心考点/题型，不做细粒度追搜。
- **分析结构不抄内容**：提炼组织/递进/设问方式，不抄数值、不抄场景。
- **去特化**：骨架是通用结构模板，不是某道具体题。

### Step 3：按难度选/调骨架（§16.3）

- 基于 K-雷达形状选骨架（K3 主导→多步串行骨架；K4 主导→陷阱辨析骨架；K1 主导→概念辨析骨架）。
- 骨架可缩放：增/减串行步数（调 K3）、加/去陷阱（调 K4）、加/去跨域联动（调 K5）、改概念辨析深度（调 K1）。
- 缩放的是雷达各维，不是单一难度档。

### Step 4：条件融合（§17.6，仅 K3-K4 高难度）

- K1-K2 / K3 简单·正常题：**不融合**，单骨架直接用。
- 仅 K3-K4 高难度且单骨架不足以达难度：融合同考点多侧重（非跨考点）。
- 难度已达标 → 不额外融合（避免超纲）。

### Step 5：题干 + 设问 + 初步参数（套骨架，大胆给）

把骨架套到本题，**大胆给初步参数**（基于骨架+经验，敢给不算，纪律①）：
- 综合题：共享题干（系统状态/数据结构/配置 + 具体初始参数）+ 子问链（### (N) （X分），串行依赖）。
- 选择题：题干（参数+场景+提问）+ 初步参数，**不出 A/B/C/D 选项**（选项由第2遍设计组装）。
- **不验证**：参数给具体值后**不脑内算、不脑内验证结构成立**。验证是 solve 代码的事。

### Step 6：输出

- write_file(question.md) — 题干 + 设问 + 初步参数 + 设计说明（不含答案值/选项值）
- **不写答案/选项值** — 答案由 solve 阶段执行解题代码得出

## 骨架复用纪律（§16.1）

| 做法 | 是否触发脑内模拟 |
|------|----------------|
| 分析上游经验缓存/往年题→提取骨架（复用） | 否（提取，已知成立） |
| 发明新结构→验证它成立 | 是（脑内模拟，过度思考） |

**只复用，不发明。** 这是消除综合题过度思考的治本落点。

## 设计纪律（§18.2 纪律①：大胆不验证）

- **大胆给初步参数**：基于骨架+经验给具体值（2^n 友好值等），敢给不算。
- **不脑内验证**：不算、不验证参数/结构是否成立。验证归 solve 代码 exec。
- 设计快 = 不背验证负担。过度思考（54k+）源于"既给参数又验证"，修正为"大胆给不验证"。

## 题干模板

### 综合题
```
[共享题干：系统状态/数据结构/配置 + 具体初始参数]
请回答下列问题：
### (1) （2分）[基础问：参数计算/机制推导]
### (2) （3分）基于(1)的结果，[核心问：过程模拟/状态跟踪]
### (3) （2分）基于(2)的结果，[区分度问：结果分析/边界讨论]
```

### 选择题
```
[题干：给具体参数 + 场景 + 提问]
（不出 A/B/C/D——选项由第2遍设计基于答案组装）
```

## 设计说明必写项

```markdown
## 设计说明
- 复用骨架来源：[往年题类型 / 骨架名]
- 考察形式：[来自 exam_form]
- 子问依赖链 / 设问结构
- 初步参数选择理由（基于骨架+经验，大胆给）
- 与目标 K-雷达的对齐
- 是否融合（仅 K3-K4 高难度时）+ 理由
```
