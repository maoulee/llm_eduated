# 融合出题技能（§22 两轮代码先行）

> 代码即推演：所有数值计算/结构构造/合法性校验由 gen.py 代码 exec 完成。
> 你不脑内算、不脑内构造。你只做：规划 → 写代码 → 组装题目。

## 两轮流程

系统会调用你两次（两个角色相同的 design agent 调用）：
- **第一轮**：构造参数 + 写 gen.py + 写 question.md（题干），**然后停止**。
- **第二轮**（审核通过后）：exec gen.py 验证约束 + 算答案 + 写 solution.md。

根据当前是否存在 solution.md 判断你在哪一轮。

---

## 第一轮（出题干）

**判断**：如果 solution.md 不存在，你在第一轮。

**目标**：基于设计卡 + 缓存 + 知识，给出合理的初步题干和参数。后面有审核者会给建议，不用一次到位。

### 做

1. **读上游**：design_card.md（hard_constraints + design_rationale）+ assembled.md（经验缓存）+ exam_form.md（考察形式）
2. **写 gen.py**：构造题目所需的数据结构/参数。gen.py exec 后 print：
   ```
   ===== 参数 =====
   [构造的具体数据：节点集合、插入序列、资源矩阵等]

   ===== 题干描述 =====
   [人类可读的题干，含数据描述 + 设问。可直接复制进 question.md]
   ```
3. **exec gen.py**：验证参数合理（如初始树合法、约束可满足）
4. **write question.md**：复制 gen.py 输出的「题干描述」段 + 设计说明。**不含答案**。

### 边界

- **允许**：基于知识的轻量判断（"这题怎么出考察深度才够"）
- **禁止**：脑内算数值/推演旋转过程（归 gen.py exec）
- **心态**：先基于经验给出合理的，审核者会给建议优化

### exec 失败

edit gen.py 改 bug → 再 exec。循环直到通过。

---

## 第二轮（验证 + 求解）

**判断**：如果收到审核通过的信号（收到 form_gate 的 pass / 审核修改清单），你在第二轮。

**目标**：验证参数满足约束 + 算答案 + 写 solution.md。

### 做

1. **exec gen.py**：更新 gen.py 使其额外 print 求解路径和答案：
   ```
   ===== 求解路径 =====
   [逐步推演过程：每次操作后的状态变化]

   ===== 答案 =====
   [每个设问的最终答案值]
   ```
2. **exec 验证**：确认参数满足 hard_constraints（如触发≥2种旋转）
3. **write solution.md**：复制 gen.py 输出的「求解路径」+「答案」段
4. **更新 question.md**：如审核建议调整设问，更新题干使其与求解对齐

### 边界

- **允许**：调整 gen.py 的参数/求解逻辑
- **禁止**：脑内算答案（gen.py exec 即真值）
- **gen.py 就是求解代码**：不写 solve.py

---

## 收到审核建议时（任一轮）

审核给的是**建议**（差距+建议），不是否决。逐条看：
- 标注「改题干」的：改 question.md 设问/表述
- 标注「改参数」的：改 gen.py 参数重 exec

**先改题干（轻量），硬性约束才改参数。改问法能解决的不改参数。**

## 红线

- 不得脑内算数值/构造结构/推演过程 — 全部由 gen.py exec
- 不得跳过 exec — gen.py 写完必须 exec 验证
- 不得在 question.md 写答案 — 答案只在 solution.md
- 不得写 solve.py — gen.py 就是求解
- 不得使用非标准库（仅 math/decimal/fractions/itertools/collections/struct/random）
