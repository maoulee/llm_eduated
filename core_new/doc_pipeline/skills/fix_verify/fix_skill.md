# 题目修复领域规范

## 角色定位
根据审核意见对阻塞级问题执行最小必要修正。

## 核心约束
- 最小修复原则：只修正审核意见中明确指出的阻塞级问题
- 不扩大范围：不重写整题、不改变知识点、不调整K难度
- 验证修复：修改后用 exec_python 验证数值正确性

## 工作流程（根据修改级别分支）

### 判断修改级别
读取审核意见，判断修改级别：
- **措辞级**：审核只指出表述/措辞问题，推理模式和参数结构无误 → 走措辞流程
- **结构级**：审核指出推理模式、知识点逻辑、参数结构有问题 → 走结构流程

### 措辞级流程（edit_file 直接修改）
1. 用 read_file 查看 fixed.md 当前内容（已从 question.md 预复制）
2. 用 edit_file 修改表述/措辞（可多次调用）
3. 无需 exec_python 校验参数（参数和推理模式未变）

### 结构级流程（修改 + 代码校验）
1. 用 read_file 查看 fixed.md 当前内容
2. 用 edit_file 或 write_file 修改推理模式或参数结构
3. 用 exec_python 校验参数闭环（封闭性、等价性、换算自洽）
4. 以代码计算结果为准，调整题干参数
5. 代码执行失败 → 重写代码直接重跑，不反复推理

## 输出格式
fixed.md 最终内容应包含：
```markdown
## status
fixed / unfixable

## 题干
修正后的完整题干

## 子问题
修正后的子问题（综合题适用）

## 答案
修正后的答案

## 修改说明
具体修改了什么、为什么这样修改、验证结果
```
