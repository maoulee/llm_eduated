# 求解技能

## 输出格式（必须严格遵循）

```markdown
## status
solved

## 求解过程
（分步骤的求解/推理过程）

## 最终答案
（选择题: 正确选项及答案值，如 "C: 5ms"）
（综合题: 各子问题答案汇总）
```

**`## status` 固定为 `solved`，`## 最终答案` 必须单独成段**，不要将答案混在求解过程中。

## solve.py 输出要求

**只要题目涉及任何数值（参数、公式计算、单位换算、查表枚举），都必须编写 `solve.py`**。

判断标准：题干中出现具体数字 → 必须输出 solve.py。唯一例外：纯概念辨析题（题干不含任何数值参数，如"以下关于XX的说法正确的是"）。

### solve.py 规范

```python
# ===== 题目参数定义 =====
param_a = ...  # 题干给定值
param_b = ...  # 题干给定值

# ===== 子问题(1) =====
# (子问题描述)
result_1 = ...
print(f"子问题(1): ...")
print(f"  中间步骤: ...")
print(f"  答案: {result_1}")

# ===== 最终输出 =====
print(f"ANSWER: {final_answer}")
```

**solve.py 必须通过 write_file 持久化为文件**，不要只调用 exec_python 验证后丢弃代码。工作流：
1. exec_python 验证参数 → 看结果 → 2. write_file 写入 solve.py → 3. write_file 写入 solution.md

### 验证规则
- 代码执行无错误
- 所有子问题都有对应代码段
- 参数与题干完全一致
- 无硬编码答案
- 无 TODO 或占位符
- 必须打印 `ANSWER: ...` 行

## 概念题处理（无任何数值）

仅当题干完全不包含数值参数时，才不需要 solve.py，直接推理：

### 推理结构
```markdown
### 子问题(1) / 选项A
**分析**: 基于XX定义/定理/机制...
**推理**: ...
**结论**: 正确/错误，理由...

### 子问题(2) / 选项B
...
```

### 推理规则
- 必须引用标准教材的定义或机制
- 推理链完整，不跳步
- 选择题：4个选项逐一分析
- 综合题：每个子问题独立分析

## 通用规则

1. 所有结果从题干参数/条件推导
2. 不阅读设计说明
3. 不假设题目以外的条件
4. 变量命名体现物理含义
5. 每步有清晰输出
6. **有数值就必须有 solve.py** — 这是硬性要求，不可跳过
