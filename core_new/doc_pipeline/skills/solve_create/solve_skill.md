# 求解技能

> 行为约束（标准库限制、禁止硬编码、edit_file修改规则、自检标准）已定义在 agents/solve.md。
> 本文件定义求解执行步骤、策略选择和代码模板。

## 权责边界

求解智能体负责：
- **参数校验**：验证题目数值参数是否自洽
- **参数修订**：发现参数不自洽时，edit_file 修改 question.md 中的数值
- **求解**：产出完整求解过程和答案
- **代码验证**：数值题用代码验证答案正确性

## 四步工作流程

### Step 1：读取题目，判断类型

1. **read_file(question.md)** — 读取题干和子问题/选项（跳过设计说明）
2. 判断题目类型：
   - **数值题**：题干包含具体数值参数、需要计算
   - **概念题**：纯文字描述、考察概念理解
   - **混合题**：数值部分用代码，概念部分直接推理

### Step 2：参数校验（仅数值题）

**前提**：Step 1 已读取题目。

**目标**：验证题目数值参数是否自洽。参数校验在求解之前，不自洽的参数不求解。

1. **write_file(verify.py)** — 写参数校验脚本，硬编码题干中的参数值
2. **exec_file(verify.py)** — 执行并检查输出

**校验内容**：
- 参数封闭性：求解所需的参数是否都在题干中给出
- 推导路径等价：同一参数的不同推导路径结果是否一致
- 单位换算链：单位转换是否自洽
- 整除性检查：参数之间的除法是否整除
- 子问依赖链（综合题）：前问输出作为后问输入时，类型和单位是否匹配

**校验结果处理**：
- 参数自洽 → 进入 Step 3 求解
- 参数不自洽（代码逻辑正确但参数矛盾）→ **edit_file** 修改 question.md 中的具体数值参数，然后进入 Step 3
- 代码逻辑有误 → edit_file 修复 verify.py → exec_file 重新验证

**参数修订规则**：
- **只改数值参数**，不改题干结构、考察形式、子问逻辑
- 用 edit_file 做最小修改（改具体数值），不重写整个 question.md
- 修正后直接求解，不需要再次校验

**纯概念辨析题跳过此步骤** — 无数值参数则直接进入 Step 3。

### Step 3：求解（写 solution.md）

**目标**：产出完整求解过程和答案。

1. 基于校验通过的参数（数值题）或直接分析（概念题）进行求解
2. **write_file(solution.md)** — 写出完整求解过程和答案

**数值题**：先写 solution.md（基于思考推导），然后进入 Step 4 代码验证。
**概念题**：直接推理，写出每个选项/子问题的分析。此步即为最终产出。

### Step 4：代码验证（仅数值题）

**前提**：solution.md 已在 Step 3 中写入。

**目标**：用代码验证数值题的计算结果。

1. **write_file(solve.py)** — 写完整求解脚本，覆盖所有子问题
2. **exec_file(solve.py)** — 执行并检查输出
3. 对比代码输出与 solution.md 中的答案

**不一致则修正**：
- 验证失败（代码逻辑正确但 solution.md 答案有误）→ **edit_file** 修正 solution.md
- 验证失败（代码逻辑有误）→ edit_file 修复 solve.py → exec_file 重新验证
