# 求解技能（具体逻辑，§18：解题代码）

> 通用行为（角色、思考控制、红线）定义在 agents/solve.md。
> 本文件定义解题流程（brief-think-then-code）和 solve.py 契约。**不给代码模板。**

## 解题流程（§18.6，简单快速迭代）

### Step 1：brief 想解法（不深推）

- read_file 读题干（question.md / question_public.md）。
- **短暂想**这道题怎么解（brief-think）：用什么算法、按什么步骤算。
- **不深推、不脑内模拟整个数据结构**——想清楚解法就直接写代码。深度重复思考是 54k 过度思考的根因。

### Step 2：写 solve.py（解题代码，直接写）

write_file(solve.py)——**这道题的解题代码**：
- 拿题干参数，brief 想，直接写 Python 实现，算出答案。
- **是**：解题代码（compute answer）——能求解题目、算出答案即可。
- **不是**：参数化 DAG、计算路径、有向无环图、完整数据结构模拟、参数搜索（全是过度架构，不要这样写）。
- 只算**正确答案**（选择题 1 个正确值；综合题各子问正确答案）。**不编码错误算法、不算干扰值**。
- print 正确答案 + 逻辑标签（`正确: <value>` / 各子问 `子问1: <value>`）。
- **输出必须直接回答题干设问**：先读清设问问的是哪个具体值（如"关键字10的平衡因子"），solve.py 必须打印**该设问要求的值**（带标签），不能只打印中间过程（树结构/遍历/旋转类型）而漏掉设问目标值。终审会核对 solve_output 是否含设问答案。

代码结构由你自主决定，本技能不给骨架。

### Step 3：exec → fix 代码（纪律②，不改题面）

- exec_file(solve.py)。
- **出错 → 只改 solve.py**（解题代码 bug），**绝不改 question.md 题干**（避免凑答案循环）。快速迭代：fix 代码 → 再 exec，直到算出答案。
- **没错 → 读 exec 输出**，正确答案即真值。

### Step 4：写 solution.md

基于 exec 输出写推理过程：
- 每个子问题逐一分析（综合题）/ 给出正确答案与推理（选择题）
- 数值必须与 exec 输出逐字一致
- 选择题只写正确答案与推理；4 个选项（含干扰）由第2遍设计组装

## 两纪律（§18.2）

**① 设计大胆不验证**（设计 agent 的事）：设计给题干+设问+初步参数，不脑内验证。

**② 代码验证纠错**（你的事）：写解题代码 → exec → 错了改**代码**（绝不改题面）→ 快速迭代 → 算出答案 + solution。

分工本质：设计"敢给"（经验驱动），代码"把关"（exec 验证 + 纠错）。

## solve.py 契约（§18.3，不给模板）

solve.py（你写）必须满足：
1. 是**这道题的解题代码**：拿到题干参数，算出正确答案。
2. 只算正确答案（选择题 1 值；综合题各子问答案）。
3. 不编码错误算法、不输出干扰值（干扰项由第2遍设计给）。
4. print 正确答案 + 逻辑标签。

代码只需能求解题目（算出答案），不需完整模拟整个数据结构。

## exec 失败处理（纪律②：改代码不改题面）

exec 报错时：
- **改 solve.py**（解题代码 bug），**绝不改 question.md 题干**。
- 快速迭代：fix 代码 → 再 exec，直到算出答案。
- 若反复修不好（参数本身无解/题面矛盾），标记 code_error 回退让设计调参——**不是你改题面凑答案**。

exec 失败的判定标准（反复修不好时标记 code_error）：
- 非零退出码，且多次 fix 仍报错
- 无标准输出
- 输出缺少正确答案（选择题无正确值 / 综合题缺子问答案）

## solution.md 叙述要点

- 推理过程基于 exec 输出的数值，不引入脑内计算
- 综合题每个子问题独立分析
- 最终答案与 exec 输出一致
- 选择题只写正确答案；不在此处设计干扰项
