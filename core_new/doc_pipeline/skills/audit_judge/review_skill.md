# 题目审核技能

> 行为约束（判定规则、最小修改原则、输出格式、禁止行为）已定义在 agents/review.md。
> 本文件定义审核执行步骤、审核维度详解和K难度评分标准。

## 审核边界

**审核范围**：题干设计质量 — 风格、知识点、考察形式、条件充分性。
**不审核**：数值参数正确性（由求解智能体负责）、答案正确性（此阶段无答案）。

## 审核执行步骤

### Step 1：知识点覆盖检查
- 列出规划中要求的所有知识点
- 逐一检查题目是否覆盖
- 标记遗漏和新增

### Step 2：K难度评估
- 根据K1-K5评分标准评估实际K值
- 与规划目标对比
- 差异>=2级标记 needs_fix

### Step 3：条件充分性
- 列出题干所有给定条件
- 检查每个条件是否被子问题/选项使用
- 检查是否有缺失条件

### Step 4：题干清晰度
- 是否有歧义表述
- 参数符号是否一致
- 隐含假设是否显式声明

### Step 5：选项/子问题质量
- 选择题：4选项1正确，干扰项有效
- 综合题：编号连续，分值合理

### Step 6：风格合规
- **选择题**：题干1-3句话、无子问题拆分、无A/B/C/D出现在子问中、无背景故事、无编程代码
- **综合题**：子问有串行依赖、无选项格式、无背景故事、无编程代码
- 违反任何格式红线应标记 needs_fix

### Step 7：题干风格与考察形式审核
- **考察形式匹配**：题目考察形式是否与蓝图规划一致
- **408真题风格还原度**：题干读起来是否像真实408真题
  - 真题特征：设问直接、参数服务于考察目标、无过度铺垫
  - 反面特征：教科书式引导、参数过于"干净"、题干读完就知道答案
- **区分度评估**：题目是否有效区分不同水平考生
- **考察形式有效性**：选项/子问模式是否真正测到了目标能力

### Step 8：经验卡对齐
- should_be 逐项核对
- should_not_be 逐项排查
- 考察模式是否在经验卡建议范围内
- 触犯 should_not_be 或严重偏离应标记 needs_fix

## K难度评分标准

K1 基础认知需求: 1=微弱 2=较低 3=标准 4=较高 5=极高
锚点：不记忆408知识能否入题 → 能则1，需一个核心定义则3，需辨析两个以上易混概念则4-5

K2 单步代入需求: 1=微弱 2=较低 3=标准 4=较高 5=极高
锚点：最复杂的单步计算是否可能算错 → 2的幂友好则2，非2幂次则3，多级换算则4-5

K3 机制推演需求: 1=微弱 2=较低 3=标准 4=较高 5=极高
锚点：从输入到输出需几步 → 1-2步则1-2，3-5步则3，>5步或需记忆中间状态则4-5

K4 条件路由需求: 1=微弱 2=较低 3=标准 4=较高 5=极高
锚点：有没有"题面没说但解题必须意识到的条件" → 无则1，常规注意点则2，陷阱词则3，隐含前提深则4，反直觉则5

K5 跨域联动需求: 1=微弱 2=较低 3=标准 4=较高 5=极高
锚点：是否需在不同子系统间传递数据或状态 → 单系统则1，提及无关则2，单向传数据则3，状态互影响则4，深度耦合则5

## 审核维度详解

### 选项质量检查（选择题）
- 4个选项是否恰好1个正确
- 干扰项是否有效（针对常见错误认知）
- 干扰项之间是否有明显的排除规律

### 子问题结构检查（综合题）
- 子问题编号连续无遗漏
- 分值分配合理
- 子问题之间的依赖关系清晰

### 经验卡对齐检查
审核时必须对照蓝图（规划）中经验卡的"出题指导"部分：
- **should_be 检查**：逐项核对
- **should_not_be 检查**：逐项排查
- **考察模式对齐**：是否在建议分布中
- **选项风格对齐**（选择题）：是否符合建议分布

## 输出格式

**长度限制：review.md 总内容不超过 2000 字。** 详细分析过程留在思考中，输出只写结论。

```markdown
## status
pass 或 needs_fix

## summary
1-2句话总结：最终裁定 + 关键发现

## corrections（仅 needs_fix 时）
每个问题1行：位置 → 当前值 → 应改为 → 不要动的部分

## detailed_feedback
每个维度1行，仅写结论+少量关键词理由：
- 知识点覆盖：[通过/偏差] （关键词）
- K难度：[通过/偏差] 实际K1-K5 vs 目标
- 条件充分性：[通过/偏差] （关键词）
- 题干清晰度：[通过/偏差] （关键词）
- 选项/子问题质量：[通过/偏差] （关键词）
- 风格合规：[通过/偏差] （关键词）
- 考察形式：[通过/偏差] （关键词）
- 经验卡对齐：[通过/偏差] （关键词）

## quality_score
overall: N/10, knowledge: N/10, difficulty: N/10, condition: N/10, expression: N/10

## improvement_suggestions
1-2条建议。
```
