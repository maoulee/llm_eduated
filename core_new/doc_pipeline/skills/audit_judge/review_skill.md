# 题目审核技能

> 行为约束（审核边界、输出格式、禁止行为）定义在 agents/review.md。
> 本文件定义审核思考方向 + fix_instructions 格式规范。

## 审核思考方向

你不是在填表打勾。你是**专业教师审核一道题是否真正达到考察目标**。
读题干时，问自己以下几个问题（不是固定 checklist，而是思考方向）：

### 约束真的满足了吗？

对照设计卡的 hard_constraints，**深入判断题目结构是否真正实现**了每条约束。
- 例如 hard_constraint 写"至少2种旋转"——你要想：题干设定的插入场景，真的会触发2种不同旋转吗？如果只插1个节点，只能触发1种，不满足。
- 例如"至少3个子问"——题干真的有3个有依赖关系的子问吗？
- **不是检查"题干有没有提到这个约束"，而是判断"题目结构是否真的做到了"。**

### 考察覆盖度够吗？

设计卡 should_be 要求的考察方向，题目都覆盖了吗？
- 例如 should_be 写"需精准辨析四种旋转类型的触发条件"——题目是否真的设置了需要辨析多种旋转的场景？如果只有1种旋转，学生不需要辨析，should_be 没满足。

### 难度匹配吗？

题目实际的认知负荷与目标 K-雷达匹配吗？
- 如果目标 K4=4（条件路由/辨析），但题目只有1条解题路径，学生不需要在多条路径间辨析，K4 实际可能只有 1-2——偏差≥2 级。
- K-雷达评分标准参考下方。

### 设计说明与题目一致吗？

设计说明描述的考察意图，与题目实际结构是否一致？
- 设计说明不能"说一套做一套"。例如设计说明写"区分学生对四种旋转的掌握"，但题目实际只涉及1种——说明是空话，题目没做到。

## K-雷达评分参考

K1 基础认知: 不记忆408知识能否入题 → 能则1, 需核心定义则3, 需辨析易混概念则4-5
K2 单步代入: 最复杂单步计算是否可能算错 → 2幂友好则2, 非2幂则3, 多级换算则4-5
K3 机制推演: 从输入到输出需几步 → 1-2步则1-2, 3-5步则3, >5步则4-5
K4 条件路由: 有没有隐含前提需辨析 → 无则1, 常规注意则2, 陷阱则3, 隐含深则4-5
K5 跨域联动: 是否需跨子系统传状态 → 单系统则1, 单向传则3, 互影响则4-5

## fix_instructions 格式

每个 fix 条目：
```
- 修改对象：哪个条件/参数/措辞/子问/干扰意图
- 修改位置：第N段/第N个子问题/设计说明
- 当前问题：哪条约束/should_be没满足，题目当前怎么设定的
- 修改目标：应该怎么改才能满足约束
- 最小修改指令：具体操作（描述逻辑，不给答案数值）
```

## 红线

- fix_instructions 不得出现答案/选项数值
- 不得因选择题缺选项值打回
- 禁止笼统反馈（必须指出具体哪条约束没满足）
