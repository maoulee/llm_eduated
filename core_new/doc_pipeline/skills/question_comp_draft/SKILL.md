# 综合应用题出题技能（具体逻辑）

> 通用行为（角色、思考控制、核心原则、红线）定义在 agents/question_comp.md。
> 本文件定义出题流程、领域模板、经验卡消费规范。**不放通用干扰模式**（那些归 design_card_v1/SKILL.md）。

## 出题流程（code-as-truth 标准题）

### Step 1：读设计卡

优先读取 design_card.md：
- blueprint_contract（考点范围）
- core_knowledge_intent（核心知识点意图）
- question_structure_plan（题型结构和子问规划）
- parameter_plan（参数规划）
- terminology_and_expression_constraints（术语约束）
- 干扰策略（设计卡已选定用哪些干扰类型，你只实现，不自己选）

assembled.md 仅用于补充经验卡的 should_be / should_not_be 与考察结构模式，**不得**把 design_card 未选的知识点加入题目。

### Step 2：设计题干 + 子问结构

按综合题题干标准格式（见下）设计题干，并按子问设计模式规划子问链。题干给参数、给系统状态、给提问，**不给答案值**。

### Step 3：写 solve.py（计算逻辑）

编写 solve.py：参数定义 + 正确算法 + 错误算法（覆盖所有子问）。

**solve.py 输出契约**（不给代码模板，结构由你自主决定）：
1. 从题干参数 + 前序子问结果计算每个子问的正确答案
2. 串行子问：前问输出作为后问输入
3. 干扰/中间量由"错误算法"产生（对应设计卡选定的干扰策略），**非硬编码常量**
4. print 每个子问的正确值（+ 必要的干扰/中间值）+ 对应逻辑标签

代码结构、函数组织方式由你自主决定。本技能不给代码骨架。

### Step 4：输出

- write_file(question.md) — 题干 + 子问 + 设计说明（不含答案值）
- write_file(solve.py) — 计算逻辑（正确算法 + 错误算法，覆盖所有子问）
- **不写子问答案值** — 答案由 solve 阶段执行 solve.py 后确定

## 题干风格模板

### 综合题题干标准格式
1. 先给出完整的系统参数/配置/数据结构描述
2. 再给出现象或操作序列
3. 最后说"请回答下列问题："

示例（组成原理类）：
"某计算机按字节编址，虚拟地址为32位，物理地址为24位，页大小为4KB。TLB采用全相联映射，有8个表项。Cache数据区大小为32KB，采用4路组相联映射，块大小为64B。请回答下列问题："

示例（数据结构类）：
"已知一棵二叉树的先序遍历序列为ABCDEFGH，中序遍历序列为CBDAEGFH。请回答下列问题："

### 子问题标准格式
- 格式固定为 "### (N) （X分）"
- 子问题用"计算"、"判断"、"说明"、"分析"等动词开头
- 后续子问题可写"基于(1)的结果，..."或"利用(2)中得到的..."

### 串行依赖模板
在设计说明中声明每个子问题的依赖关系：

```
| 子问题 | 依赖 | 说明 |
|--------|------|------|
| (1) | 无（题干条件） | 基础参数计算 |
| (2) | (1)的输出 | 使用(1)的结果作为输入 |
| (3) | (2)的输出 | 基于(2)进一步分析 |
```

## 子问设计模式

### 基础问（2-3分）
- 参数计算：从给定条件计算基础参数
- 机制推导：确定系统的工作机制
- 格式转换：二进制↔十进制、地址↔页号等

### 核心问（3-4分）
- 过程模拟：模拟算法执行/指令流水线/页面置换等过程
- 状态跟踪：跟踪数据结构/缓存/路由表的状态变化
- 结果推导：基于前问结果推导中间结论

### 区分度问（2-3分）
- 结果分析：分析最终结果的含义
- 比较判断：比较不同方案的优劣
- 边界讨论：讨论极端情况或特殊条件

## 经验卡消费规范

assembled.md 中包含经验卡的考察结构模式分析和出题指导，作为 design_card 的补充。出题前必须先提取以下信息：

### 必提取项
1. **should_be**：这个题位应该出什么样的综合题
2. **should_not_be**：这个题位不应该出什么样的题
3. **考察结构模式**：从经验卡中选择一种结构模式作为本题框架

### 执行步骤
1. 选取一种考察结构模式，按其"第一步→第二步→第三步"设计子问链
2. 严格按照模式的子问角色分布设计（基础→核心→区分度）
3. 从该模式的"典型陷阱"中选择至少1种

### 设计说明必写项

```markdown
## 设计说明
- 考察结构模式：[选用的模式名称]（来自经验卡）
- 子问依赖关系（表格形式）
- should_be对照：逐条说明本题如何满足
- should_not_be排查：逐条确认未触犯
- 知识点选取理由
- 参数选择理由（为何选 2^n 基底）
- solve.py 错误算法实现（每个干扰/中间量对应的错误算法，对应设计卡选定的干扰类型）
- 与契约 K 值的对齐说明
```

## 概念题出题（complexity == "conceptual"）

综合题极少为概念题；若 complexity == "conceptual"，走轻量路径：正常设计题干 + 子问，直接写 solution.md（推理基于标准教材定义），不写 solve.py、不脑内算。
