# 综合应用题领域规范

> 行为约束（契约忠实、K难度忠实、子问结构忠实、格式红线）已定义在 agents/question_comp.md。
> 本文件仅包含408综合题领域特定的设计模板和经验卡消费规范。

## 题干风格模板

### 综合题题干标准格式
1. 先给出完整的系统参数/配置/数据结构描述
2. 再给出现象或操作序列
3. 最后说"请回答下列问题："

示例（组成原理类）：
"某计算机按字节编址，虚拟地址为32位，物理地址为24位，页大小为4KB。TLB采用全相联映射，有8个表项。Cache数据区大小为32KB，采用4路组相联映射，块大小为64B。请回答下列问题："

示例（数据结构类）：
"已知一棵二叉树的先序遍历序列为ABCDEFGH，中序遍历序列为CBDAEGFH。请回答下列问题："

### 子问题标准格式
- 格式固定为 "### (N) （X分）"
- 子问题用"计算"、"判断"、"说明"、"分析"等动词开头
- 后续子问题可写"基于(1)的结果，..."或"利用(2)中得到的..."

### 串行依赖模板
在设计说明中声明每个子问题的依赖关系：

```
| 子问题 | 依赖 | 说明 |
|--------|------|------|
| (1) | 无（题干条件） | 基础参数计算 |
| (2) | (1)的输出 | 使用(1)的结果作为输入 |
| (3) | (2)的输出 | 基于(2)进一步分析 |
```

## 子问设计模式

### 基础问（2-3分）
- 参数计算：从给定条件计算基础参数
- 机制推导：确定系统的工作机制
- 格式转换：二进制↔十进制、地址↔页号等

### 核心问（3-4分）
- 过程模拟：模拟算法执行/指令流水线/页面置换等过程
- 状态跟踪：跟踪数据结构/缓存/路由表的状态变化
- 结果推导：基于前问结果推导中间结论

### 区分度问（2-3分）
- 结果分析：分析最终结果的含义
- 比较判断：比较不同方案的优劣
- 边界讨论：讨论极端情况或特殊条件

## 经验卡消费规范

蓝图（assembled.md）中包含经验卡的考察结构模式分析和出题指导。出题前必须先提取以下信息：

### 必提取项
1. **should_be**：这个题位应该出什么样的综合题
2. **should_not_be**：这个题位不应该出什么样的题
3. **考察结构模式**：从经验卡中选择一种结构模式作为本题框架

### 执行步骤
1. 选取一种考察结构模式，按其"第一步→第二步→第三步"设计子问链
2. 严格按照模式的子问角色分布设计（基础→核心→区分度）
3. 从该模式的"典型陷阱"中选择至少1种

### 设计说明必写项

```markdown
## 设计说明
- 考察结构模式：[选用的模式名称]（来自经验卡）
- 子问依赖关系（表格形式）
- should_be对照：逐条说明本题如何满足
- should_not_be排查：逐条确认未触犯
- 知识点选取理由
- 参数选择理由（为何选 2^n 基底）
- 代码验证结果摘要
- 与契约 K 值的对齐说明
```

## 参数验证关注点

exec_python 验证脚本应检查（不计算最终答案）：
- **参数封闭性**：所有子问题所需的参数是否都在题干中给出？
- **子问依赖链**：前问输出作为后问输入时，类型和单位是否匹配？
- **推导路径等价**：同一参数的不同推导路径结果是否一致？
- **单位换算链**：单位转换是否自洽？
- **整除性检查**：参数之间的除法是否整除？
- **分值合理性**：总分是否匹配契约要求？
