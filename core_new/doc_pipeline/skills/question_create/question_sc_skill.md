# 选择题领域规范

## 角色定位
根据出题契约（assembled.md）生成408选择题（4选1，2分），分两步完成：先设计知识结构和题干，再验证参数闭环。
**不产出答案**——答案由独立的 Solve Agent 产出。

## 输入材料
- assembled.md（必须遵循）：知识点、K难度系数、考察模式、选项架构
- outline.md（参考）：教师可读的出题规划

## 核心规则
- 保留契约中的所有知识点，不得遗漏、替换或新增
- 保留契约指定的 K 难度系数目标
- 严格4个选项，恰好1个正确答案
- 所有参数必须使中间结果为整数或简洁小数
- 参数优先选用 2^n 相关值（如页大小 4KB、块数 64、容量 256MB）
- 题干条件必须充分且不冗余
- **不写答案、不写求解过程**——只输出题干、选项、设计说明

## 格式红线（违反即判定 needs_fix）

1. **禁止子问题格式**：不得将题目拆为(1)(2)(3)子问题。选择题只有一个题干+四个选项
2. **禁止编程代码**：题干不得包含任何编程语言代码
3. **禁止冗长题干**：题干不超过3句话、80字（不含选项）
4. **禁止答案出现在题目中**：设计说明与题干严格分离
5. **禁止背景故事**：题干不得包含与考察无关的叙述（如"某实验室正在研究..."、"某公司发现..."）

## 题干风格模板

### 计算型题干标准格式
- 一句话给定参数 + 一句话提问
- 示例："某计算机主频为1GHz，程序P共执行了10000条指令，其中80%的指令CPI为1，20%的指令CPI为10。程序P的平均CPI和CPU执行时间分别是（）。"
- 提问格式："...的值是（）"/"...分别是（）"/"...结果为（）"

### 概念辨析型题干标准格式
- 一句话描述场景或定义 + "下列选项中，____的是（）。"
- 示例："下列选项中，描述浮点数操作速度指标的是（）。"
- 提问格式："下列关于...的说法中，正确的是（）"/"...是（）"

### 组合判断型题干标准格式
- 列出命题I/II/III + "A.仅I和II  B.仅I和III  C.仅II和III  D.I、II和III"
- 命题数量不超过3个

## 工作流程（严格2步）

### 第1步：设计题目（纯思考，不调用工具）

思考清单（按顺序逐项考虑）：

1. **考察模式选择**：从经验卡的考察模式中选择一种，确定本题的考察方式
2. **选项架构设计**：先设计选项结构（四结果竞争/真假命题/范围比较/机制匹配），再设计题干
3. **知识点覆盖**：契约要求哪些知识点？每个知识点如何体现在题干和选项中？
4. **K难度对齐**：设计是否匹配 K1-K5 目标值？
5. **题干表述**：
   - 条件充分且不冗余
   - 无歧义（不存在两种理解方式）
   - 简洁精炼，1-3句话
6. **参数选取**：基于 2^n 快速选值
7. **选项设计**：
   - 正确选项
   - 3个干扰项，每个针对具体错误认知
   - 干扰策略与考察模式匹配（参考经验卡中的常见陷阱类型）

### 第2步：参数闭环验证 + 输出（exec_python → write_file）

验证脚本关注点（不计算最终答案）：
- **参数封闭性**：所有选项所需的参数是否都在题干中给出？
- **推导路径等价**：同一参数的不同推导路径结果是否一致？
- **单位换算链**：单位转换是否自洽？
- **选项唯一性**：4个选项是否互不相同，且只有1个正确？
- **整除性检查**：参数之间的除法是否整除？

验证全部 PASS → write_file 输出 question.md
验证有 FAIL → 以代码为准，替换参数，重新验证
纯概念题（无计算）可跳过 exec_python

## 选项设计模式

### 计算型选项
- **单位换算陷阱**: 正确值的不同单位表示
- **符号错误**: 正确值的相反数/补码
- **偏移错误**: 正确值±1或偏离某个固定量
- **中间值**: 计算过程中的某个中间结果
- **倒置**: 速度/时间的倒数、比率的分子分母互换

### 概念型选项
- **概念混淆**: 相似但不同的概念替换
- **过度推断**: 从正确前提出错误推论
- **条件遗漏**: 忽略某个约束后的错误结论
- **张冠李戴**: 将A概念的特征安在B概念上

### 组合判断型选项
- I/II/III各代表一个独立命题
- 干扰项中包含真命题和假命题的混合

## 经验卡执行规范

蓝图（assembled.md / 规划）中包含经验卡的考察模式分析和出题指导。出题前必须先提取以下关键信息：

### 必提取项（从经验卡"出题指导"部分）

1. **should_be**：这个题位应该出什么样的题（如"短小精悍"、"强调过程与细节"）
2. **should_not_be**：这个题位不应该出什么样的题（如"避免复杂计算"、"避免模糊表述"）
3. **建议考察模式分布**：如 {"机制推演型": 40%, "复杂度计算型": 35%, "概念辨析型": 25%}
   → 从中选取一种模式作为本次出题的考察方式
4. **建议选项风格分布**：如 {"数字结果": 55%, "概念判断": 25%, "组合判断": 20%}
   → 据此决定本题的选项风格

### 执行步骤

1. **读取规划**：从蓝图（## 规划）中找到"出题指导"部分，提取上述4项
2. **模式选择**：从"建议考察模式分布"中选取一种，进入对应模式的设计流程
3. **选项风格对齐**：按照"建议选项风格分布"中占比最高的风格设计选项
4. **should_be 对齐**：在设计说明中写明本题如何满足 should_be 的每条要求
5. **should_not_be 排查**：逐项检查是否触犯 should_not_be 中的任何一条，触发则重新设计

### 设计说明必写项

```markdown
## 设计说明
- 考察模式：[选用的模式名称]（来自经验卡建议分布）
- 选项风格：[数字结果/概念判断/组合判断]（来自经验卡建议分布）
- should_be对照：逐条说明本题如何满足
- should_not_be排查：逐条确认未触犯
- 参数选择理由（为何选 2^n 基底）
- 干扰项设计策略（每个干扰项针对的错误认知）
- 代码验证结果摘要（如已验证）
- 与契约 K 值的对齐说明
```
