# Skill: 题干→代码翻译（func_model）

**你在做代码翻译，不是在做算法研究。**

把题干（描述性的运算规则）翻译成可执行代码 `solve(符号参数)`——输入参数就能得到答案。就像把英文翻译成中文：源文本（题干规则）已给，你只是换一种语言（Python）表达它。

---

## 0. 这是什么任务（决定思考模式·先读）

**代码翻译任务 = 轻思考。** 题干已经描述了运算规则（"同号减Y异号加Y""左移""末位恒置1"），你把它翻译成 Python 代码（`if 同号: ... `、`R = R << 1`、`q[-1] = 1`）。这是翻译，不是推导——**你不需要理解算法为什么这样算，只需要把题干说的翻译成代码**。

| 你做的（翻译）| 你不做的（研究）|
|---|---|
| 题干说"同号减Y" → 写 `if same: R += negY` | 为什么同号要减Y？ |
| 题干说"左移" → 写 `R = (R << 1) % mod` | 左移的数学证明？ |
| 题干说"末位恒置1" → 写 `q[-1] = 1` | 恒置1法的误差分析？ |

**翻译 = 逐句对应，不需要深度思考。** 题干怎么描述，你就怎么写代码——一句规则对应一段代码。

> 触发器：若你发现自己在"理解算法/推导规则/验证算法对错"——**停**。那不是翻译，是研究。题干规则是源文本，直接翻译，不研究。

---

## 1. 核心范式：一次性建模 + 底部打印数据流（不拆段）

**gen.py 是一次性的、不拆段的模型：建模与"检查"不分开。** 整个 gen.py = 一个模型从头算到尾，**在文件底部把完整数据流 print 出来**（所有输入参数、中间值、各步骤过程、最终结果），检查就内含在这条数据流里。

- **不拆"建模段 / assert 段"**：没有独立的"验证段"。建模完成后，底部 print 数据流——审核靠读这条打印的数据流对照场景规则验证（触发有没有发生 / 定律成不成立），gen.py 自己不需要也不应该再写一组 `assert` 去重复检验。
- **检查 = gen.py 内部的自然一部分**：底部 `print` 数据流即是检查载体。中间值、过程、结果都在数据流里裸露，审核一眼对照场景规则。
- **底部数据流必须完整**：足以让审核独立验证"模型是否忠实于场景规则"——任何被场景规则约束的量、任何一次触发、任何一条守恒定律，都能在打印的数据流中找到对应值。

### 底部数据流 print 的内容（必备）

gen.py 末尾 print 出来的数据流至少覆盖：

1. **PARAMS**：注入的输入参数（符号参数已被实际值替换）。
2. **PROCESS / 中间值**：建模过程中每一步的中间值（触发计数、符号位、各次迭代结果、移位结果……），让审核能逐步追踪。
3. **RESULT**：最终答案。

> 数据流的写法是 print，不是 assert。审核阶段是"读 print 的数据流 + 对照场景规则"判断模型是否忠实，而不是看 gen.py 自检 exit code。

## 2. 翻译步骤

1. **读题干 + 读场景规则**：题干描述了什么运算规则？question.md 里声明的"场景规则"是什么（per-question，给定参数间必须成立的约束/关系，与具体答案值无关）？
2. **逐句翻译成代码**：题干的每一步规则 → 对应的 Python 代码段。**同时忠实实现场景规则**——场景规则要求成立的约束，建模时就要真的实现它（不是事后 assert）。
3. **组装成 `solve(符号参数)`**：把翻译好的代码段组装进一个函数。
4. **底部 print 完整数据流**：函数跑完后，在 gen.py 底部把 PARAMS / PROCESS（中间值）/ RESULT 全部 print 出来，使审核能直接对照场景规则验证（触发是否发生 / 定律是否成立 / 约束是否满足，统一看数据流）。
5. **注入参数跑**：用题干给的参数调用 `solve()`，exec 跑。

> 第 4 步替代了旧版"加 assert 段打通过条件"。检查不再单独成段，而是 gen.py 一次性建模 + 底部数据流打印的自然一部分。

---

## 3. 场景规则 vs answer-recipe（术语统一）

建模时区分两类东西：

- **场景规则（要忠实实现）** = 给定参数间必须成立的约束/关系，与具体答案值无关。
  - 正例："按字节编址 → 每地址 1 字节 → 容量_bytes == 2**地址线数"
  - 正例："商 × 除数 + 余数 == 被除数"
  - 正例："插入序列至少触发 1 次旋转"
  gen.py 建模时忠实实现这些关系，并在底部数据流中 print 出对应的量（旋转计数、商/除数/余数/被除数、地址线数与容量），让审核能验证模型是否忠实于场景。
- **answer-recipe（禁止）** = 把答案的具体值当作"通过条件"硬编码。
  - 反例（禁止）："答案 = 2MB" / "物理地址 = 0x4C3F4" / "必须同时用地址线 + 数据线"
  - 反例（禁止）：`assert A == correct_value`（先把某个选项假定为正确，再 assert 它等于算出的正确值——这是 answer-recipe，不是场景规则）。
  这些不能进 gen.py。

**建模忠实的对象是"场景规则"，不是"answer-recipe"。**

## 4. 翻译示例（补码除法）

题干说：
```
用补码加减交替法计算 x÷y：
- 异号第一步加[y]补，同号第一步加[-y]补
- 余数与y同号→商1，异号→商0
- 左移后，上一步商1→加[-y]补，商0→加[y]补
- 末位恒置1
- 余数与x异号→恢复余数
```

场景规则（示例，来自 question.md）：`商 × 除数 + 余数 == 被除数`（与具体答案值无关的守恒关系）。

翻译成代码（一次性建模 + 底部 print 数据流）：
```python
def solve(x_bits, y_bits, n=5):
    mod = 1 << n
    x = int(x_bits, 2) % mod
    y = int(y_bits, 2) % mod
    neg_y = (-y) % mod

    # 翻译："异号第一步加[y]补，同号加[-y]补"
    if x_sign != y_sign:
        r = (x + y) % mod
    else:
        r = (x + neg_y) % mod

    # 翻译："余数与y同号→商1，异号→商0"
    q = 1 if same_sign(r, y) else 0

    # 翻译："左移后，商1→加[-y]补，商0→加[y]补"
    for i in range(n - 1):
        r = (r << 1) % mod
        if last_q == 1:
            r = (r + neg_y) % mod
        else:
            r = (r + y) % mod
        q = ...

    # 翻译："末位恒置1"
    q_bits[-1] = 1

    # 翻译："余数与x异号→恢复"
    if not same_sign(r, x):
        ...

    return q, r

# ---- 注入参数跑 ----
q_val, r_val = solve(x_bits="...", y_bits="...", n=5)

# ---- 底部：打印完整数据流（不拆 assert 段，检查内含于此）----
print("PARAMS:", {"x_bits": "...", "y_bits": "...", "n": 5})
print("PROCESS:", {...每步中间值、各次迭代后的 r/q...})
print("RESULT:", {"商": q_val, "余数": r_val})
# 场景规则可直接在数据流里读出：q_val * y + r_val == x —— 审核看 print 验证
print("RULE_CHECK_view:", {"商*除数+余数": q_val * y + r_val, "被除数": x})
```

**看到了吗？每行代码都是题干一句话的直接翻译；底部 print 出完整数据流让审核对照场景规则（商×除数+余数==被除数）直接验。不需要理解算法，只需要逐句对应。不拆 assert 段。**

## 5. 选择题：所有选项先算正确值（不假定 A 对）

**选择题的建模原则：对 4 个选项 A/B/C/D 都先算各自正确值，不是"假定 A 对再 assert A==correct"。**

1. **核心问题先算正确值**：用题干参数跑 `solve()` 得到核心问题的正确值。A 选项标的就是这个正确值。
2. **B/C/D 也各算其正确值**：每个干扰项先按"它本应问的东西"算出正确值，再按设计把它改错（走错误路径：对阶方向错 / 概念混淆 / 单位错 ……）。gen.py 里用 `solve_with_error(错误类型)` 算出干扰项的真实产物。
3. **gen.py 底部打印每个选项**：正确值 + 实际标的值 + 改错方式，全部进数据流：
   ```python
   print("OPTION_A:", {"正确值": correct, "实际值": correct, "改错方式": "无（正确选项）"})
   print("OPTION_B:", {"正确值": correct_b, "实际值": solve_with_error("对阶方向错"), "改错方式": "对阶方向取反"})
   print("OPTION_C:", {"正确值": correct_c, "实际值": solve_with_error("概念混淆X"), "改错方式": "把X当Y"})
   print("OPTION_D:", {"正确值": correct_d, "实际值": solve_with_error("单位错"),   "改错方式": "bit/byte搞反"})
   ```
4. **删掉 `assert A == correct_value`**：那是 answer-recipe（把 A 假定为正确再 assert），不是场景规则。选择题不允许写这种 assert。审核靠读上面打印的"每选项正确值/实际值/改错方式"数据流，判断每个干扰项是否真的由声明错误路径产出。
5. 干扰项由其声明的错误路径产出，不是随机扰动——数据流里能对得上就对得上。

---

## 6. 建模方式

- **整数取模建模**：补码/原码用取模运算（`(a+b)%mod`），不逐位模拟硬件。
- **符号参数**：`solve(X, Y)` 的 X、Y 是符号（占位），翻译时不碰具体数值，调用时注入。
- **一次性建模**：建模从函数入口跑到 return，不拆"建模段/assert 段"。检查 = 底部 print 数据流。

---

## 7. 纪律

- 仅标准库。**不用 numpy。**
- **底部必须 print 完整数据流**（PARAMS/PROCESS/RESULT + 场景规则相关量），这是检查的载体，不是可选装饰。
- **不写独立 assert 段去重复检验场景规则**——场景规则靠审核读数据流验证，不在 gen.py 里再写一组 assert。
- **禁 answer-recipe**：不能把答案的具体值（"答案=2MB"/"物理地址=0x4C3F4"/`assert A==correct_value`）当条件写进 gen.py。
- **禁恒真废 print**：print 的内容必须有信息量，不能 print 一堆永远成立的东西凑数。
- exec 跑不过（语法错 / 运行错） → 改代码（对照题干规则检查哪句翻译错了），再跑。**不脑内算/不重新研究算法。**
- output_file：gen.py（建模码）。gen.py exec 跑通、底部数据流 print 完整后，你还负责转写 solution.md（见下「8」）。

## 8. 写 solution.md（gen.py exec 跑通后）

gen.py exec 跑通、底部数据流 print 完整后，把 exec 输出整理成 solution.md。**这是整理 exec 输出，不是重算：**

1. **逐字对照 exec stdout**：solution.md 的每步数值、推理、答案，都必须来自 gen.py exec 的实际输出（PARAMS/PROCESS/RESULT 标签段），不凭记忆、不脑内补、不重新推导。
2. **结构对齐 gen.py**：求解步骤的顺序、变量、运算与 gen.py 一致。
3. **答案落结论**：exec 的 RESULT 作为最终结论。
4. **选择题**：A=核心问题正确值；B/C/D=各错误路径的真实产物（gen.py 里 `solve_with_error(...)` 算出的值），solution 里说明每个干扰项为什么错（对应错误类型 + 该选项的"正确值 vs 实际值"），不随机扰动。
5. **禁幻觉**：solution 里不得出现 exec 没产出的步骤/数值/操作。

> 转写 ≠ 重算。gen.py 已算过，你只整理它的输出。若 solution 与 exec 输出不一致，以 exec 为准、改 solution。
