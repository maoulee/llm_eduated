# Skill: 题干→代码翻译（func_model）

**你在做代码翻译，不是在做算法研究。**

把题干（描述性的运算规则）翻译成可执行代码 `solve(符号参数)`——输入参数就能得到答案。就像把英文翻译成中文：源文本（题干规则）已给，你只是换一种语言（Python）表达它。

---

## 0. 这是什么任务（决定思考模式·先读）

**代码翻译任务 = 轻思考。** 题干已经描述了运算规则（"同号减Y异号加Y""左移""末位恒置1"），你把它翻译成 Python 代码（`if 同号: ... `、`R = R << 1`、`q[-1] = 1`）。这是翻译，不是推导——**你不需要理解算法为什么这样算，只需要把题干说的翻译成代码**。

| 你做的（翻译）| 你不做的（研究）|
|---|---|
| 题干说"同号减Y" → 写 `if same: R += negY` | 为什么同号要减Y？ |
| 题干说"左移" → 写 `R = (R << 1) % mod` | 左移的数学证明？ |
| 题干说"末位恒置1" → 写 `q[-1] = 1` | 恒置1法的误差分析？ |

**翻译 = 逐句对应，不需要深度思考。** 题干怎么描述，你就怎么写代码——一句规则对应一段代码。

> 触发器：若你发现自己在"理解算法/推导规则/验证算法对错"——**停**。那不是翻译，是研究。题干规则是源文本，直接翻译，不研究。

---

## 1. 翻译步骤

1. **读题干**：题干描述了什么运算规则？（如"用补码加减交替法""对阶→尾数求和→规格化→舍入"）
2. **逐句翻译成代码**：题干的每一步规则 → 对应的 Python 代码段。
3. **组装成 `solve(符号参数)`**：把翻译好的代码段组装进一个函数。
4. **加验证段（打到"通过条件"）**：question.md 声明了"通过条件"——本题成立 ⇔ 期待结果的可机检特征。**把每个条件翻译成 `assert`**：
   - 题干说"插入序列至少触发 1 次旋转" → `assert rotation_count >= 1`
   - 题干说"商×除数+余数=被除数" → `assert q * d + r == x`
   - 题干说"最终结果落在 [a,b]" → `assert a <= result <= b`
   - **选择题**（A=正确，B/C/D=干扰项）：声明的选项通过条件要翻成
     - `assert len({A, B, C, D}) == 4`（4 选项互异，防撞值——也间接保证正确值不重复出现）
     - `assert A == correct_value`（A 标的是算出的正确值，防"正确选项标错"）
     - 每个干扰项应由其声明的错误路径产出（`B = solve_with_error(对阶方向错)`），不是随机扰动——能对得上就 assert 对得上。
   这是翻译的一部分（题干声明的特征 → 代码断言），不是研究。条件没被 assert 覆盖 = 漏译。
5. **注入参数跑**：用题干给的参数调用 `solve()`，exec 跑。

## 2. 翻译示例（补码除法）

题干说：
```
用补码加减交替法计算 x÷y：
- 异号第一步加[y]补，同号第一步加[-y]补
- 余数与y同号→商1，异号→商0
- 左移后，上一步商1→加[-y]补，商0→加[y]补
- 末位恒置1
- 余数与x异号→恢复余数
```

翻译成代码：
```python
def solve(x_bits, y_bits, n=5):
    mod = 1 << n
    x = int(x_bits, 2) % mod
    y = int(y_bits, 2) % mod
    neg_y = (-y) % mod

    # 翻译："异号第一步加[y]补，同号加[-y]补"
    if x_sign != y_sign:
        r = (x + y) % mod
    else:
        r = (x + neg_y) % mod

    # 翻译："余数与y同号→商1，异号→商0"
    q = 1 if same_sign(r, y) else 0

    # 翻译："左移后，商1→加[-y]补，商0→加[y]补"
    for i in range(n - 1):
        r = (r << 1) % mod
        if last_q == 1:
            r = (r + neg_y) % mod
        else:
            r = (r + y) % mod
        q = ...

    # 翻译："末位恒置1"
    q_bits[-1] = 1

    # 翻译："余数与x异号→恢复"
    if not same_sign(r, x):
        ...

    return q, r
```

**看到了吗？每行代码都是题干一句话的直接翻译。不需要理解算法，只需要逐句对应。**

## 3. 建模方式

- **整数取模建模**：补码/原码用取模运算（`(a+b)%mod`），不逐位模拟硬件。
- **符号参数**：`solve(X, Y)` 的 X、Y 是符号（占位），翻译时不碰具体数值，调用时注入。

---

## 4. 纪律

- 仅标准库。**不用 numpy。**
- 验证段用 **assert**（不只 print）——验证不过 assert 报错→exit≠0→系统检测→退回改码。
- **assert 必须打到"通过条件"，禁弱化**：题干声明"考旋转"→ 必须有 `assert rotation_count >= 1`，**不能**弱化成 `assert is_balanced(tree)` 这种结构判据（零旋转的坏题也会过）。弱化 = 让坏题静默放行，是这次要堵的根因。题干声明的特征是什么，你就 assert 什么——漏 assert 一个条件 = 漏译。
- **assert 禁恒真**：不能写 `assert True` / `assert len(x) >= 0` 这类永远成立的废话断言凑数。
- exec 验证不过 → 改代码（对照题干规则检查哪句翻译错了），再跑。**不脑内算/不重新研究算法。**
- output_file：gen.py（建模码）。gen.py exec 通过后，你还负责转写 solution.md（见下「5」）。

---

## 5. 写 solution.md（gen.py exec 通过后）

gen.py 的 assert 全过、exec 结果满足通过条件后，把 exec 输出整理成 solution.md。**这是整理 exec 输出，不是重算：**

1. **逐字对照 exec stdout**：solution.md 的每步数值、推理、答案，都必须来自 gen.py exec 的实际输出（PARAMS/REASONING/ANSWER 标签段），不凭记忆、不脑内补、不重新推导。
2. **结构对齐 gen.py**：求解步骤的顺序、变量、运算与 gen.py 一致。
3. **答案落结论**：exec 的 ANSWER 作为最终结论。
4. **选择题**：A=exec 正确值；B/C/D=各错误路径的真实产物（gen.py 里 `solve_with_error(...)` 算出的值），在 solution 里说明每个干扰项为什么错（对应错误类型），不要随机扰动。
5. **禁幻觉**：solution 里不得出现 exec 没产出的步骤/数值/操作。

> 转写 ≠ 重算。gen.py 已算过，你只整理它的输出。若 solution 与 exec 输出不一致，以 exec 为准、改 solution。
