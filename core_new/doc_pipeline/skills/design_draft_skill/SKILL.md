# 题目设计 P1 技能（出题，§19.8）

> 通用行为（角色、思考控制、红线）定义在 agents/design.md。
> 本文件定义 **P1 出题**：读上游定案→直接套骨架写题干+设问+经验值参数。**纪律①：给经验值，不脑内算。**

## 核心原则：上游已定案，你只实现

**上游（design_card + exam_form + assembled）已经把"考什么、怎么考、为什么这么考"全定好了。** 你的工作是**直接把定案实现成题干**，不是重新分析/提炼/推演。

- 骨架 → design_card 的 `question_structure_plan` 已给（直接用）
- K-雷达/难度 → exam_form 已定（直接用）
- 设计理念 → design_card 的 `design_rationale` 已论证（读完即定案，不重推）
- 参数 → 经验值表取第一个友好值（不对照推演）

**你只做三件事：①读上游定案 ②套骨架写题干 ③给经验值参数。** 不分析、不提炼、不推演、不算。

## 出题（三步，直接做）

### ① 读上游定案（直接读，不复述/不分析）

读取并**直接采用**（不要在脑内复述或重新分析这些内容）：
- design_card.md：`question_structure_plan`（骨架，直接套）、`design_rationale`（为什么这样考，读完即定案）、`parameter_plan`（参数槽位）
- exam_form.md：考察形式 + K-雷达（直接用）
- assembled.md：should_be/should_not_be（避坑）

> **不要**在正文/思考里"提炼骨架""分析考法""理解难度锚点"——上游已定，直接用。重新分析 = 过度思考（纪律①）。

### ② 套骨架写题干（直接写，不验证结构成立）

把 `question_structure_plan` 的骨架套到本题：
- 综合题：共享题干（系统状态/数据结构/配置）+ 子问链（### (N) （X分））
- 选择题：题干（场景+提问），**不出 A/B/C/D 选项**（选项由 P2 基于解设）

**不验证**结构是否成立、不脑内模拟。骨架来自上游定案，已知成立。

### ③ 给经验值参数（取第一个友好值，不对照推演）

从经验值表**直接取第一个命中题型的友好值**，不逐项对照约束推演：

| 题型/考点 | 经验值参数 | 友好值（直接取） |
|-----------|-----------|----------------|
| AVL / 平衡二叉树 | 节点数 n | 7 |
| 二叉树遍历/还原 | 节点数 n | 7 |
| 页表/地址映射 | 页框数 frames | 4 |
| Cache 映射 | 块数 | 8 |
| 进程调度 | 进程数 | 4 |
| 文件系统/索引 | 索引级数 | 2 |
| 位运算/移位 | 位数 | 8 |
| 排序/查找 | 数据规模 n | 8 |

**命中即取第一个值，不命中的题按"2^n 友好值"给一个。** 不对照 parameter_plan 的 candidate_range 逐项筛选——那是推演，不是给经验值。算交 solve。

### ④ 结构自检（轻量，不算数值）

参数给完后，做一个**轻量的结构判断**——"我选的参数组合能否满足设计卡的 hard_constraints？"

这是结构判断（够不够/全不全），**不是数值推演**（不算具体 BF/旋转过程）：
- ✅ 正确："我设了1个插入点，只能触发1种旋转，hard_constraint 要求≥2种——不满足，需要加插入点"
- ✅ 正确："我设了3个子问，hard_constraint 要求≥3——满足"
- ❌ 错误："插入1后节点5的BF变为2，执行LL右旋，旋转后节点20的BF变为..."（这是数值推演，归代码）

**如果结构自检发现参数不满足约束**，直接调整参数（如增加插入节点数），不要脑内模拟验证调整后的结果——调整后是否真的满足，由 form_gate 审核 + solve 代码验证。

> 核心分界：判断"够不够"是 design 的事（结构层）；验证"算什么"是代码/solve 的事（数值层）。
> design 只做结构判断，不做数值推演。

## 收到审核修改清单时的修改策略

收到 form_gate 的修改清单后，**先判断每条问题的类型，再决定怎么改**：

### 第一优先：改题干设问/结构（轻量，不需验证参数）

很多审核问题可以通过**改题干问法**解决，不必改参数：
- 例：review 说"区分度不够（叶子全在同一层）"→ 改设问为"节点X的路径长度是多少"（不用总WPL），区分度自然提升
- 例：review 说"只问根节点BF，未辨析旋转类型"→ 改设问为"插入过程中发生了哪些旋转操作"（自然涉及多种旋转辨析）

**改问法能解决的，优先改问法**——不需要验证参数，修改即提交。

### 第二优先：必须改参数的（hard_constraint 硬性要求参数满足）

如果约束硬性要求参数本身满足（如"至少2种旋转类型"——不是问法问题，而是题目场景必须真的触发2种旋转）：
- 调整参数（如增加插入节点、改变初始树结构）
- **不要脑内验证调整后是否满足**——你无法脑内算出"插入这些节点后触发几种旋转"
- 调整方向参考 review 的 fix_instructions（它会给出"应该怎么改"的建议）
- 调整后直接提交，由 form_gate 判断是否满足

### 修改决策树

```
收到修改清单 → 逐条判断问题类型：
  │
  ├─ 题干问法/结构问题 → 改题干设问（轻量，不需验证）
  │
  ├─ 参数约束问题 → 能改问法解决吗？
  │   ├─ 能 → 改题干设问
  │   └─ 不能（硬性约束）→ 改参数（不脑内验证，直接提交）
  │
  └─ 设计说明不符 → 同步修改设计说明
```

**关键原则：先修题干（结构/问法），再修参数。改问法能解决的不改参数。**

## 缓存优先 + fallback（§16.1）

- **缓存优先**：assembled/design_card 有经验缓存时直接用，**缓存存在则不 grep**。
- **粗粒度 fallback**：仅缓存完全缺失时，一次粗粒度 grep_search（按知识域/核心考点/`question_type`，不细碎追搜）。

> 考点融合（同知识点多考察项）由骨架层（design_card）决定，你读到多个考察项就直接实现。

## 纪律（§19.2 纪律①）

- **给经验值**：取经验值表第一个友好值，甩值不算。
- **不脑内算**：不算数值、不推演参数、不验证结构成立。验证归 solve exec。
- **不重新分析上游**：骨架/K-雷达/理念上游已定，直接用，不提炼不分析。
- **不写答案值**：答案由 solve 算。**绝不把答案算出来写进题干**（算答案 = 脑内算 = 违反纪律①）。

> 发明新结构→验证它成立 = 脑内模拟（过度思考根因）。上游已定骨架，只复用不发明。
