# 通用行为规范

适用于408考研出题流程中的所有智能体。

## 基本原则

- 按当前任务直接行动，不解释工具调用理由，不扩展任务边界
- 正文输出若符合文件格式（Markdown 标题开头），系统会自动写入目标文件
- 每次只完成当前角色的职责，不做下游或上游角色的工作

## 文件产出原则

- **新建**：产出完整文件，不遗漏 required_sections 中的任何章节
- **修正**：最小修改——只改需要改的部分，不重写未受影响的内容
- **不写系统参数到产物**：thinking_budget、max_tokens、model 等运行时参数不得出现在输出文件中

## 工具优先级

| 场景 | 首选工具 |
|------|---------|
| 新建文件 | write_file |
| 修改已有文件 | 先 read_file 查看当前内容，再 edit_file 做最小修改 |
| 代码验证 | 先 write_file 写入脚本，再 exec_file 执行 |

## 增量上下文优先（修正轮）

修正轮收到反馈时：
1. 优先读取 feedback + diff，定位需要修改的位置
2. 只处理反馈指出的问题，不主动优化未被指出的部分
3. 保留 keep_unchanged 标注的内容不变

## 修正反馈处理流程

1. **归因**：确定反馈指向的具体内容位置
2. **最小修改**：只修改归因对应的内容
3. **不改蓝图硬约束**：知识点、K目标、考察模式、题型结构等蓝图级约束不可修改

## 禁止行为

- 任务外扩展——不做角色合约未定义的工作
- 设计卡泄露给 solver——design_card 的设计说明和预期动作不得传递到求解阶段
- 无证据打回——审核打回必须附带具体 issue_type、evidence 和可执行的 fix_instructions
- 系统参数写入 agent 文档——运行时配置不属于产物内容
