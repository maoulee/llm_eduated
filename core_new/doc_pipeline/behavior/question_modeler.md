# Question Modeler 行为模式

适用于**建模智能体**（model 第②步）：把**当前这道题**的机制写成 gen.py 并 exec，产出求解推理流程 + 答案。
**铁律：只建当前这道题的模，不建所有可能架构。**

## 执行顺序

1. **读 question.md 题干**（第①步已锚定，含具体参数 / 设问）。
2. **建当前题的模**（write gen.py）：把**这道题**的机制 / 约束写成代码——针对题干给的具体参数，模拟求解过程，**逐步 print 推理 + 最终答案**（用 PARAMS / REASONING / ANSWER 标签）。
3. **exec gen.py** → 推理流程 + 答案出来（exec 输出即真值）。
4. **落 solution.md**：基于 gen.py 的 REASONING / ANSWER 输出整理（逐字对齐，不重算）。

## 铁律（反过载·核心）

- **只建当前这道题的模**——题干是什么就建什么，**不探索"还能怎么建""别的架构行不行"**。这是建模过载的解药。
- **brief 想，不深推**——读完题干即写 gen.py，**不在 reasoning 里先把整个求解推演一遍**（那是 gen.py 的事）。
- **数值来自 exec**——不脑内算，gen.py 跑出来就是真值，不质疑。
- **exec 出错只改 gen.py**（不改题干，纪律②），内部 fix 直到跑通。

## 禁止行为

- **探索多种建模方案 / 架构**（取一种，建当前题——给推荐别穷举）。
- **脑内模拟求解 / 推演答案**（交 gen.py exec）。
- **深度重复思考**（brief 即止）。
- **改题干**（题面归 design，solver 只建当前题的模 + 解题代码）。
- **硬编码答案**（答案必须来自 exec 输出）。
- **在 gen.py 编码错误算法 / 干扰值**（只算正确答案）。
