# 教师组卷交互工作台 — UI 设计文档

> 版本: 1.0 | 日期: 2026-06-10
> 状态: 设计就绪，可直接交付前端开发或设计工具
> 前置文档: `interact-web-api-design.md`（后端 API 设计）

---

## 1. 产品定位

面向高校教师的 AI 辅助出题工作台。教师通过自然语言对话描述出题需求，系统生成可裁剪的草案卡片，教师通过**删除不想要的选项**完成标注，系统最终生成交接文档供下游出题流水线使用。

**核心理念**：教师不需要编辑文件、不需要理解 K 值、不需要打开 YAML。所见即所得，点击即标注。

**功能**：管理所有出题会话

**状态标签颜色**：
| 状态 | 颜色 | 文字 |

### 4.2 中间 — 聊天对话区

**功能**：教师与 AI 助手对话，收集需求、展示回复

#### 4.2.1 顶部栏

```
┌──────────────────────────────────────────┐
│ ← 返回   出一道Cache映射选择题   🟠审阅中 │
│                                          │
│  ●──●──◉──○──○──○                        │
│  空闲 收集 审阅 标注 确认 完成              │
└──────────────────────────────────────────┘
```

**6步进度条**：
- 已完成步骤：实心蓝圆 + 蓝色连线
- 当前步骤：蓝色脉冲动画圆点
- 未到达步骤：灰色空心圆 + 灰色连线
- 步骤名称：空闲→收集→审阅→标注→确认→完成

**状态到步骤映射**：
| session_state | 步骤索引 |
|---------------|---------|
| (初始) | 0 空闲 |
| collecting | 1 收集 |
| reviewing | 2 审阅 |
| reviewing (有draft) | 3 标注 |
| confirming | 4 确认 |
| confirmed | 5 完成 |

#### 4.2.2 消息列表

**教师消息**（右对齐）：
```
                              ┌─────────────────────┐
                              │ 出一道Cache映射选择题  │  蓝底(#4F46E5)白字
                              │                     │    圆角12px
                              └─────────────────────┘
```

**助手消息**（左对齐）：
```
┌─────────────────────────────────────┐
│ 好的，我已为您检索到Cache映射相关的  │  白底灰边框
│ 考察模式，草案已生成，请在右侧面板   │    圆角12px
│ 操作。                              │
│                                     │
│ 💡 草案已生成，请在右侧面板操作       │  ← 蓝色提示条
└─────────────────────────────────────┘
```

- 支持 markdown 渲染（代码块、加粗、列表）
- 长消息自动折叠，点击展开
- 包含 `[✓]`/`[✗]` 标记的草案内容折叠为蓝色提示条

#### 4.2.3 输入区

```
┌─────────────────────────────────────────┐
│ [输入你的出题需求，Shift+Enter换行]  [➤] │
└─────────────────────────────────────────┘
```

- textarea，最小1行，最大4行自适应
- Enter 发送，Shift+Enter 换行
- 发送后显示加载动画（三个跳动圆点）
- `canSendMessage` 为 false 时禁用（generating/confirmed 状态）

**API 调用**：
```
POST /api/v2/interact/sessions/{id}/turn
Body: { "message": "教师输入的文本" }
Response: InteractTurnResponse
```

**确认提交流程**：
1. 点击 "确认提交" → 弹出确认对话框

3. 确认 → `POST /api/v2/interact/sessions/{id}/annotate` 提交标注数据
4. 然后自动发送 `POST /api/v2/interact/sessions/{id}/turn` message="已标注，请生成交接文档"
5. 面板切换到结果模式

**提交的标注数据结构**：

## 5. 数据模型（前端 ↔ 后端）

### 5.1 会话创建

```typescript
// POST /api/v2/interact/sessions
// Request:
interface CreateSessionRequest {
  provider: "api_vllm" | "glm5.1" | "glm4flash"  // 模型选择
  thinking: boolean    // 是否开启思考模式（仅GLM生效）
  ui_mode: "api"       // 固定为 "api"
}

// Response:
interface SessionInfo {
  session_id: string    // "abc123def456"
  state: "collecting" | "reviewing" | "confirmed"
  scenario: "A" | "B" | "C" | "unknown"
  provider: string
  created_at: number
  turn_count: number
}
```

### 5.2 发送消息

```typescript
// POST /api/v2/interact/sessions/{id}/turn
interface TurnRequest {
  message: string
}

interface TurnResponse {
  response_text: string      // 助手回复文本
  session_state: "collecting" | "reviewing" | "confirmed"
  has_draft: boolean         // 是否有可展示的草案
  has_result: boolean        // 是否有交接YAML
  files_written: string[]    // 本轮写入的文件
}
```

### 5.3 获取草案

```typescript
// GET /api/v2/interact/sessions/{id}/draft
interface DraftOption {
  id: string                // "opt_1_2"
  text: string              // "命中/不命中判断"
  cognitive_desc: string    // "需多步推演"（自然语言，无K值）
  status: "unselected" | "kept"
}

interface DraftSlot {
  slot_id: string           // "Q1"
  title: string             // "Q1（选择题·2分）— 拓扑排序"
  options: DraftOption[]
  annotation: string        // 教师批注
}

interface DraftData {
  draft_id: string          // "abc123_turn2"
  title: string             // "试卷大纲草案"
  scenario: "A" | "B" | "C"
  current_round: number     // 场景C: 1 或 2
  sections: DraftSlot[]
  raw_md: string            // 原始markdown（回退渲染用）
}
```

### 5.4 提交标注

```typescript
// POST /api/v2/interact/sessions/{id}/annotate
interface SlotAnnotation {
  slot_id: string
  kept_options: string[]      // 保留的 option_id
  removed_options: string[]   // 删除的 option_id
  annotation: string          // 教师批注
  modified_text?: Record<string, string>  // {option_id: 修改后文本}
}

interface AnnotationSubmission {
  draft_id: string            // 必须匹配当前草案ID
  slots: SlotAnnotation[]
}
```

### 5.5 获取结果

```typescript
// GET /api/v2/interact/sessions/{id}/result
// 返回解析后的 YAML dict
interface YamlResult {
  schema_version: string
  slots: Array<{
    slot_id: string
    primary_target_name: string
    examination_mode: string
    k_radar: { K1: number; K2: number; K3: number; K4: number; K5: number }
    k_dominant: string
    teacher_annotation: string
  }>
}
```

## 6. 交互流程（完整用户旅程）

### 6.1 场景 A：有经验卡（408 组卷）

```
教师操作                          系统响应                      UI 状态
───────                          ──────                      ──────
1. 点击 "新建会话"              → 创建会话                    步骤0→1, collecting
   选择模型: GLM-5.1

2. 输入: "出一套408模拟卷"       → 检索经验卡，生成草案        步骤1→2, reviewing
                                 返回 has_draft=true          右侧面板出现草案

3. 查看草案卡片                  → —                          步骤2→3, 标注模式
   Q1-Q5 各 3-5 个选项

4. 点击 ✕ 删除不想要的选项       → 本地状态更新               卡片变红/绿
   每个题位裁剪到 1 个

5. 输入批注（可选）              → 本地状态更新               批注框填入

6. 点击 "确认提交"              → POST /annotate              步骤3→4
   → POST /turn "已标注"          → 生成交接YAML              步骤4→5, confirmed

7. 查看结果                      → GET /result                右侧面板切换到结果模式
   下载 YAML
```

### 6.2 场景 B：单题出题

```
教师输入: "出一道AVL树旋转题"
→ 系统检索题库，生成考察模式草案
→ 教师裁剪选一个考察模式
→ 生成 slot_blueprint.yaml
```

### 6.3 场景 C：自由组卷（两轮）

```
Round 1: 教师输入 "出一套数据结构期末卷"
→ 系统用内部知识列出知识点候选
→ 教师为每个题位选一个知识点

Round 2: 系统对选中的知识点检索题库
→ 展示考察模式候选
→ 教师为每个题位选一个考察模式
→ 生成 paper_request.yaml
```

## 9. API 端点汇总（前端调用清单）

| 方法 | 端点 | 用途 | 调用时机 |
|------|------|------|---------|
| POST | `/api/v2/interact/sessions` | 创建会话 | 点击"新建会话" |
| GET | `/api/v2/interact/sessions` | 会话列表 | 侧边栏加载 |
| GET | `/api/v2/interact/sessions/{id}` | 会话详情 | 切换会话 |
| POST | `/api/v2/interact/sessions/{id}/turn` | 发送消息 | 输入框发送 |
| GET | `/api/v2/interact/sessions/{id}/draft` | 获取草案 | turn 返回 has_draft=true |
| POST | `/api/v2/interact/sessions/{id}/annotate` | 提交标注 | 点击"确认提交" |
| GET | `/api/v2/interact/sessions/{id}/result` | 获取结果 | turn 返回 has_result=true |

**轮询策略**：
- 发送消息后，如果 `has_draft=true`，立即调用 `GET /draft` 获取结构化数据
- 如果 `has_result=true`，立即调用 `GET /result` 获取 YAML

## 10. 关键约束

1. **K 值不可见**：API 返回的 draft 数据中不含 K1-K5，只含 `cognitive_desc` 自然语言描述。结果页面展示 K-radar 是因为那是最终交接文档，教师已不需要操作。
2. **裁剪式标注**：教师删除不想要的，保留的 = 选择。不需要 [✓]/[✗] 标记。
3. **draft_id 校验**：提交标注时 `draft_id` 必须匹配，防止旧草案覆盖新草案。
4. **Scheduler 零改动**：所有适配在前端 API Client 和后端 Service 层完成。
5. **中文界面**：所有 UI 文案使用中文。
