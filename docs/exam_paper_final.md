## 答案解析

### 选择题解析

**1.(Q12) 答案：A**

本题考查计算机性能指标中的CPU执行时间公式计算及单位换算。CPU执行时间 $T = \frac{\text{指令条数} \times \text{CPI}}{\text{主频}}$。
根据题目条件：
指令条数为 100万 = $10^6$；
平均CPI为 4；
主频为 2GHz = $2 \times 10^9$ Hz。
代入公式得：$T = \frac{10^6 \times 4}{2 \times 10^9} = 2 \times 10^{-3} \text{ s} = 2 \text{ ms}$。
干扰项中，B项是将频率与周期关系倒置，误用 $2 \times 10^6 \times 4 / (10^9)$；C项是错误代入数量级计算；D项则是错误地将周期数（$4 \times 10^6$）除以主频时发生了数量级误判，或者将毫秒与微秒混淆。

**2.(Q13) 答案：A**

本题考查补码的符号扩展以及进制转换。
首先求真值 -100 的 8 位补码原码表示：100的十六进制为 64H，二进制为 01100100。因此 -100 的原码为 11100100，求其补码（除符号位外按位取反，末位加 1）得到 10011100，即十六进制的 9CH。
当把 8 位补码赋值给 16 位补码变量时，需要进行符号扩展。因为 9CH 的最高位（符号位）为 1，所以高 8 位全部补 1，即变为 11111111 10011100。
将其转换为十六进制，即为 FF9CH。
**选项分析**：
- A选项：FF9CH，是正确的符号扩展结果。
- B选项：009CH，错在进行了“零扩展”。无符号数才会高位补 0，有符号负数补 0 会导致真值变成正数 156，而不是 -100。
- C选项：809CH，错在符号扩展时高位补了 10000000（即 80H）。这往往是因为混淆了“在最高位添加一个1”的错误概念，或者按照权值错误的错误计算方法。
- D选项：FF64H，错在只进行了符号位扩展，而未将原 8 位原码转换为补码。

**3.(Q14) 答案：A**

本题主要考查IEEE 754规格化浮点数的隐藏位机制以及单精度向双精度的转换过程。由于题目限定了尾数全为1，绝对值部分的二进制科学计数法表示为 $1.111...1$（小数点后23个1）。在转换为双精度时，隐含的整数位“1”依旧不包含在52位尾数中，因此原尾数后23个“1”直接作为高23位，剩下的低位全部用“0”补齐。此时52位尾数域为 111...1(共23个)000...0(共29个)。将这52位按4位一组转为十六进制，1111(即F)可分5组共20位，剩余3位“111”加上补齐的“0000”中的最高1位“0”，组成“1110”(即E)。后续全为0。因此尾数域的十六进制表示为 F F F F F E 0 0 0 0 0 0 0，即 FFFFE0000000H。选项B是典型的隐藏位遗漏陷阱，误将包含整数1的值放入尾数（即将尾数误认为24个1和28个0，即FFFFFF0000000H）；选项C和D则是由于阶码计算使用偏置值127或1023发生混淆导致的符号位误判（将阶码全1视为了负数并取反，或阶码多加了1024导致最高位进位溢出）。

**4.(Q15) 答案：B**

本题考察主存储器容量计算及字位扩展的综合应用。

**推导过程：** 按字（32位=4字节）编址，256MB对应的总字数为 $256\text{MB}/4\text{B} = 64\text{M}$ 字。主存总容量为 $64\text{M} \times 32$ 位。

ROM占最高地址段的1/4，容量为 $64\text{M} \times 32 / 4 = 16\text{M} \times 32$ 位。RAM占3/4，容量为 $48\text{M} \times 32$ 位。芯片容量均为 $1\text{M} \times 8$ 位。

ROM芯片数 = $(16\text{M} \times 32)/(1\text{M} \times 8) = 16 \times 4 = 64$ 片。RAM芯片数 = $(48\text{M} \times 32)/(1\text{M} \times 8) = 48 \times 4 = 192$ 片。

**选项分析：**
- A选项：ROM 16片，RAM 48片，漏算了位扩展的4倍关系（$32/8=4$），仅用字数除以1M得到16和48，犯了"只看地址不看数据位宽"的错误。
- B选项：ROM 64片，RAM 192片，计算正确。
- C选项：ROM 16片，RAM 192片，ROM部分犯了与A相同的位扩展遗漏错误。
- D选项：ROM 64片，RAM 48片，RAM部分犯了位扩展遗漏错误，仅计算了字扩展。

**5.(Q16) 答案：D**

本题考查扩展操作码设计原理。

**推导过程：** 16位指令字中，三地址指令操作码占4位（三个地址码各占4位共12位），最多可表示 $2^4=16$ 种状态。三地址指令使用了15条，剩余1种状态（1111）作为二地址指令的前缀。二地址指令拥有 $1 \times 2^4 = 16$ 种状态（前缀4位 + 第二个地址码4位 = 8位操作码）。单地址指令64条需占用 $64/16 = 4$ 个前缀块。因此二地址指令最多 $16 - 4 = 12$ 条。

- C选项：13条，错误计算 $16-3=13$，多减了一个前缀块。

**6.(Q17) 答案：C**

本题考查指令寻址方式与数据寻址方式的辨析。
- **A选项错误**：相对寻址的转移目标地址是通过将**当前PC的值**（而非当前指令地址，取指后PC已自增）与形式地址（位移量）相加得到的。同时，直接寻址范围是由指令中地址码字段的位数决定的，而在相对寻址中，形式地址（位移量）位数决定的是相对于当前PC的偏移范围，并非直接寻址范围。
- **B选项错误**：在基址寻址中，基址寄存器的内容（即基准值）由操作系统设定，形式地址（位移量）的位数较短。但是，**操作数的寻址范围是由基址寄存器的位数决定的**，形式地址的位数仅仅决定了在基址附近的偏移范围。
- **C选项正确**：变址寻址中，形式地址提供固定的基准地址（如数组首地址），变址寄存器提供变化的位移量（如数组下标），非常适合处理数组和循环程序。
- **D选项错误**：位移量寻址（包括基址寻址、相对寻址等）的有效地址确实由基准值加上补码表示的位移量得到，但其寻址范围是以基准值为起点的一段连续空间，并非以基准值为对称中心上下对称分布。只有形式地址作为偏移量时其可取值范围（补码）是关于0对称的，而最终的寻址空间完全取决于基准值和偏移范围的叠加。

**7.(Q18) 答案：A**

**11.(Q22) 答案：C**

本题考查DMA方式的工作机制及其与CPU的交互时机。

**推导过程：** DMA方式分为预处理、数据传送和后处理三阶段。CPU仅在传送前执行预处理程序（设置传送参数等）和传送后执行后处理程序（如数据校验等），数据传送阶段由DMAC硬件控制完成，CPU可继续执行不访存的指令。

**选项分析：**
- A选项：错误。DMA的数据传送路径是直接由I/O接口经总线到主存，不经过CPU寄存器，这是DMA与程序查询/中断方式的根本区别。
- B选项：错误。周期挪用（窃取）方式下，DMAC是在CPU不访存时窃取周期，或在每个存取周期结束后交替使用总线，并非全过程独占。该描述混淆了停止CPU法与周期挪用法。
- C选项：正确。DMA传送前需CPU执行预处理程序设置参数，传送后需CPU执行后处理程序进行校验等操作。
- D选项：错误。DMA传送期间CPU可继续执行不访存的指令，若采用周期挪用法CPU仅是在访存时稍有延迟，绝非完全暂停。

**Q43 (审核评分：9/10)**

本题综合考察浮点数加减运算的底层机制与强制类型转换原理。

**问题1：对阶过程**
浮点数加减必须保证阶码相同。已知 `f1 = 20.0` 和 `f2 = 1.0`：
- `f1 = 20.0 = 10100.0_B = 1.0100_B × 2^4`。其阶码 $E_1 = 4 + 127 = 131$（即 `1000 0011_B`）。尾数绝对值为 `1.0100...0`。
- `f2 = 1.0 = 1.0_B = 1.0_B × 2^0`。其阶码 $E_2 = 0 + 127 = 127$（即 `0111 1111_B`）。尾数绝对值为 `1.0000...0`。
- 对阶原则为“小阶向大阶看齐”。计算阶差 $\Delta E = E_1 - E_2 = 4$。
- 将 `f2` 的阶码变为 `1000 0011_B`，同时尾数向右算术移位4位，移出的高位补0。
对阶后两操作数状态如下：
- 操作数1（来自 `f1`）：阶码 `1000 0011` (131)，尾数绝对值 `1.01000000000000000000000`。
- 操作数2（来自 `f2`）：阶码 `1000 0011` (131)，尾数绝对值 `0.00010000000000000000000`。

**问题2：尾数求和**
将对阶后的两个尾数绝对值进行原码加法：
$$ \begin{array}{r} 1.01000000000000000000000 \\ +\ 0.00010000000000000000000 \\ \hline 1.01010000000000000000000 \end{array} $$
尾数求和的二进制结果为 `1.01010000000000000000000`。

**问题3：规格化及类型转换机制**
- **规格化与舍入**：由于求和结果 `1.0101...` 是规格化数（最高有效位为1），无需进行左规或右规。尾数小数部分截取前23位，即 `01010000000000000000000`。
组合符号位(0)、阶码(`10000011`)和尾数，得 `f3` 的机器码为：
`0 10000011 01010000000000000000000_B`。
转换为十六进制：每4位一组，`0100 0001 1010 1000 0000 0000 0000 0000_B` = **`41A80000H`**。
- **强制类型转换底层机制**（精度与溢出）：
1. **`int` -> `float`**：`float` 尾数仅23位，而 `int`（32位）可表示高达31位的有效精度。当 `int` 的数值超过 $2^{24}$ 时，转换为 `float` 必定发生**精度丢失**（低位被舍入），但一般不会溢出（因为 `float` 表示范围更大）。
2. **`float` -> `int`**：当 `float` 的真实值带有小数部分时，转换为 `int` 会截断小数，发生**精度丢失**；当 `float` 的值超出 `int` 可表示的范围（$[-2^{31}, 2^{31}-1]$）或为 `NaN`/`Infinity` 时，发生**溢出**（结果通常被定义为不定值或边界值）。
3. **`int` -> `double`**：`double` 尾数长达52位，足够覆盖32位 `int` 的所有精度，既不发生精度丢失，也不发生溢出。
4. **`float` -> `double`**：由于 `double` 的尾数和阶码范围完全包含 `float`，转换过程绝对精确，无精度丢失，也无溢出。
5. **`double` -> `float`**：`double` 精度高、范围大。若 `double` 的小数部分超出23位，发生**精度丢失**；若 `double` 的真实值超出 `float` 能表示的极大/极小值范围，则发生**溢出**。

**Q44** 难度：4/5
- 考点："虚拟地址与物理地址结构, TLB与Cache的映射机制, 组相联映射的地址划分, 平均访问时间(AMAT)计算"
- 参数设计说明：- **虚拟/物理地址**：32位和28位是典型配置，页大小4KB意味着页内偏移为12位，虚拟页号(VPN)为20位，物理页号(PPN)为16位。
- **TLB参数**：16项4路组相联，意味着有4个TLB组，需要2位作为TLB索引。因此TLB Tag位数为 20 - 2 = 18位。
- **Cache参数**：总容量32KB，行大小64B，计算出共有512个Cache行。采用8路组相联，意味着共有 512 / 8 = 64个Cache组，需要6位作为Cache索引。块内偏移需6位。因此Cache Tag位数为 28 - 6 - 6 = 16位。
- **时间参数设计**：数据通路为顺序结构。AMAT计算涉及4种排列组合（TLB命中/缺失 × Cache命中/缺失），能够完美考察多级存储层次的时间开销推演。
- sub q1 intent：
**期望考察**：虚拟存储系统的基础地址划分能力。
**预期解题路径**：根据页大小4KB（$2^{12}$B）得出页内偏移为12位。32位虚拟地址减去12位页内偏移，得出虚拟页号为20位。物理地址28位，同理划分出物理页号16位和页内偏移12位。
- sub q2 intent：
**期望考察**：TLB和Cache硬件结构参数与地址字段位数的换算关系（机制深度）。
**预期解题路径**：

2. 对于Cache：先计算Cache总行数 = 32KB / 64B = 512行。8路组相联求得Cache组数 = 64组，需6位索引。块内地址6位。Cache标记 = 物理地址位数(28) - 索引位(6) - 块内偏移(6) = 16位。
