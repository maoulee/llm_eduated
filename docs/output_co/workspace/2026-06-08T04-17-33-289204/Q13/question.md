## 题干
设 short 为16位，int 和 unsigned int 均为32位，带符号整数用补码表示。若 `short x = -128; unsigned int y = (unsigned int)x;`，则 y 的机器数和十进制值分别为（）。

## 选项
A. 00000080H，128  
B. 0000FF80H，65408  
C. FFFFFF80H，4294967168  
D. FFFFFF80H，-128  

## 设计说明
- 考察模式：概念辨析型——符号与语义陷阱（补码与类型转换）（来自经验卡建议分布）
- 选项风格：数字结果（机器数 + 十进制值），符合经验卡中“数值、大小关系或转换后值判断”的选项架构
- should_be对照：本题围绕有符号数到无符号数转换，要求考生在补码位模式、符号扩展、无符号语义之间切换；题干给出 short、int、unsigned int 位宽，保证转换规则有明确前提；选项集中考察“机器位模式”和“数学真值/语义”的差异
- should_not_be排查：未设计多子问题；未引入复杂程序逻辑；未考查浮点数、存储器或指令系统等非目标知识点；未把题目变成冗长计算题；未在题干或选项中标出答案
- 参数选择理由：选用 -128 和 16/32 位，均为 2^n 边界相关参数，便于心算；-128 的补码低8位为 80H，能有效触发“符号位为1但位宽改变后语义变化”的陷阱
- 干扰项设计策略：A 针对“忽略负号、只取绝对值”的错误认知；B 针对“只把16位补码零扩展为32位”的错误认知；D 针对“机器数正确但仍按有符号数解释十进制值”的错误认知；各选项共同覆盖位模式保持、扩展规则和无符号解释三类常见误区
- 与契约 K 值的对齐说明：K1 较高，需要准确掌握补码、符号扩展和无符号解释；K2 较低，计算仅涉及 2^7、2^16、2^32 相关心算；K3 中等，需要经历“16位补码表示 → 扩展到32位 → 按无符号数解释”的链式推演；K4 较高，核心陷阱在于区分“值转换”和“位模式解释”以及短字长到长字长时的扩展规则；K5 较低，限定在数据表示与强制类型转换单一知识域内。
