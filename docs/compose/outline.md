# 试卷大纲

## 整体规划
- **difficulty_target**: 4
- **composition_rationale**: 本卷综合应用题部分旨在通过高K3（机制推演）和高K4（条件路由）的题目，考查学生在复杂场景下对数据结构和操作系统核心机制的深度理解与动态分析能力。Q41侧重线性表与树的综合结构操作与逻辑边界处理，Q45侧重进程同步与资源管理的时序推演与死锁避免逻辑，共同构成对“逻辑严密性”与“系统状态管理”能力的双重考查。

## 1. 教师阅读版总览

本部分为408考研综合应用题模拟卷的规划大纲，包含Q41（数据结构）和Q45（操作系统）两题。

**知识点覆盖策略**：
- **Q41 (数据结构)**：选取“树与二叉树”中的**平衡二叉树 AVL**作为核心考点，结合插入与旋转机制。这是数据结构中逻辑最严密、状态变化最丰富的考点之一，适合考查学生对节点平衡因子变化、旋转条件判断（LL/RR/LR/RL）以及树高维护能力的掌握。避免选择简单的遍历或静态性质计算，以提升区分度。
- **Q45 (操作系统)**：选取“进程与线程”中的**死锁避免**与**银行家算法**，并结合**PV操作**进行综合考查。通过模拟资源分配过程，要求学生在动态变化的资源状态下判断系统安全性，并设计同步机制。此考点能极好地体现K3（多步推演资源状态）和K4（识别安全序列与非安全状态）的要求。

**难度分布逻辑**：
- **Q41**：难度定位为4。学生需准确执行AVL树的插入操作，并在每一步后判断平衡因子，决定是否需要旋转。风险点在于旋转方向的判断错误（特别是LR/RL型双重旋转）或旋转后父子指针链接错误。
- **Q45**：难度定位为4。学生需理解银行家算法的核心逻辑（Need vs Available），并在多进程竞争资源时，通过推演寻找安全序列。风险点在于对“安全状态”定义的误解，或在PV操作代码编写中遗漏信号量初始化或边界条件检查。

## Q41（综合应用题）

### 教师可读说明
本题考查数据结构中**平衡二叉树（AVL Tree）**的核心机制。题目将给出一个初始的平衡二叉树（或为空），并要求学生插入一系列关键码，每插入一个节点后，需画出当前的树结构，并简要说明是否需要旋转及旋转类型（LL、RR、LR、RL）。
- **考查能力**：学生对AVL树平衡因子变化的敏感性，以及在失衡情况下正确执行单旋转或双旋转的能力。
- **难度定位**：K3较高（需多步插入并维持树结构状态），K4较高（需准确判断旋转触发条件，避免漏转或误转）。
- **风险点**：学生在进行LR/RL型旋转时容易混淆中间节点的左右子树归属；或在旋转后忘记更新节点的平衡因子/高度。

## Q45（综合应用题）

### 教师可读说明
本题考查操作系统中**死锁避免**的核心算法——**银行家算法**，并结合**PV操作**进行综合应用。题目设定一个多进程共享有限资源的场景，给出进程的最大需求矩阵和当前分配矩阵。
1. 首先要求判断当前系统状态是否安全，并给出一个安全序列。
2. 接着，若有进程发出资源请求，要求利用银行家算法判断是否可立即分配，若不能分配，说明原因。
3. 最后，可能要求用PV操作实现该资源分配过程中的互斥或同步（或分析一段包含PV操作的代码是否存在死锁风险）。
- **考查能力**：对Need矩阵、Available向量的动态更新能力，安全序列的搜索算法（K3高），以及对系统安全状态本质的理解（K4高）。
- **难度定位**：K3极高（需模拟整个资源分配和回收的流程，步骤繁琐），K4较高（需识别隐含的非安全状态，避免直观上看似可行但实际会导致死锁的分配）。
- **风险点**：计算Need矩阵时出错；在寻找安全序列时遗漏某个可行序列导致错误判断为不安全；对PV操作的原子性和顺序理解偏差。
