# 题目难度抽取 与 知识图谱构建 — 核心机制讲解

> 本文档讲透支撑出题系统的两个**数据基础设施**：
> 1. **难度抽取** —— 怎么把"难度"从主观词变成可量化、可检索的客观量。
> 2. **知识图谱构建** —— 怎么把 408 大纲变成可检索、可注入的考点结构树。
>
> 两者共同回答一个问题：**出题时，凭什么知道"这道题考什么、有多难"？** 靠的就是这两套机制沉淀的客观数据。
> 所有内容来自项目代码与数据文件，面向讲解，不含实现细节。

---

# 机制一 · 题目难度抽取

## 1.1 为什么需要重新定义"难度"

传统说法"这道题难度中等"是**不可复现的**——换个人、换个模型，评判都不一样。这导致出题时三个顽疾：

| 顽疾 | 表现 | 根因 |
|------|------|------|
| 难度跑偏 | 要"中等"，出成常识题或偏怪题 | 没有"中等"的客观定义 |
| 考点偷换 | 要考 A，结果考成 B | 考点和难度没有绑定 |
| 无法检索 | 想找一道"同类难度参考题"找不到 | 题库里没有可对比的难度标签 |

**我们的解决思路：把"难度"拆成五个正交的认知维度，每维 1–5 分，从真题里客观抽取。**

## 1.2 难度的五维定义：K1–K5 认知雷达

难度不是单一标量，而是**一道题消耗考生哪类认知资源、消耗多少**。五个维度各管一种认知需求：

```
                      K1 基础认知需求
                  (需调用概念/术语/公式记忆)
                          5
                         /|\
                          |
   K5 跨域联动需求 ───────┼────── K2 单步代入需求
   (跨子系统传递状态)      │      (执行单次计算/换算)
                          |
                         \|/
                          1
                 K3 机制推演需求  ←  K4 条件路由需求
              (明确规则下多步串行) (识别隐含前提/避开陷阱)
```

**每个维度的 1–5 分标准（节选）：**

| 维度 | 1 分 | 3 分（标准） | 5 分 |
|------|------|-------------|------|
| K1 基础认知 | 仅需常识 | 必须准确记核心概念 | 纯概念辨析，无绕过余地 |
| K2 单步代入 | 几乎不算 | 常规公式代入 | 整题卡这一步复杂计算 |
| K3 机制推演 | 无需推演 | 3–5 步固定流程 | 极长程，错一步全盘输 |
| K4 条件路由 | 题面即全部 | 有明确陷阱词 | 专为反直觉设计 |
| K5 跨域联动 | 单一知识点 | 两系统单向拼接 | 多系统深度耦合双向推演 |

> **设计原则：floor = 1。** 任何题至少消耗最小认知资源，没有"零分"题。
> 评分还产出 `radar_shape_name`（雷达形状命名），如"K4 陷阱型""K3 推演型"——一句话概括这道题的**主导难度类型**。

**为什么是这五个维度？** 它们覆盖了 408 解题的全部认知活动：记忆（K1）、计算（K2）、推演（K3）、辨陷阱（K4）、跨域（K5）。两道"中等题"可能完全不同——一道是"计算难"（K2 高），一道是"推演长"（K3 高）。五维拆分让难度变得**可区分**。

## 1.3 难度怎么从真题里"抽取"出来（核心流程）

这是数据驱动的核心。完整链路分**三步：打分 → 聚合 → 检索**。

```
┌─────────────────────────────────────────────────────────────┐
│  第①步：单题打分（per question）                              │
│                                                             │
│  题库真题 (2000+)                                           │
│      │                                                      │
│      │  LLM 按 K1–K5 量表逐题打 1–5 分                       │
│      │  （量表见 1.2，输出含 radar_shape_name）              │
│      ▼                                                      │
│  每题一个 K 雷达，如                                         │
│  {K1:4, K2:2, K3:4, K4:3, K5:1, shape:"K3推演型"}          │
│  存入 per_question_k_ratings.json                           │
└─────────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│  第②步：题位聚合（per slot）                                  │
│                                                             │
│  按"题位"(如选择题 Q12) 把该位多年的真题聚合                  │
│      │                                                      │
│      │  每个维度统计：众数(mode) + 范围(range)                │
│      ▼                                                      │
│  题位难度锚点（difficulty anchor），写入经验卡：              │
│      - **K1**: 众数=1 [1,5]                                 │
│      - **K4**: 众数=1 [2,4]                                 │
│      ...                                                    │
│  含：考点分布、考察模式分布、陷阱类型分布、参考年份            │
└─────────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────────────┐
│  第③步：K 值检索（出题时）                                    │
│                                                             │
│  目标题位 K 雷达 ──▶ 知识点命中 ──▶ 难度门 ──▶ MAE 排序       │
│                                       D(候选)≤D(目标)+ε      │
│      │                                                      │
│      ▼                                                      │
│  从题库挑出认知负荷最接近的往年题作参考（reference_questions）│
│  出题锚定往年同类题的难度，不凭空生成                         │
└─────────────────────────────────────────────────────────────┘
```

### 第①步单题打分 —— 产出"原始 K 雷达"

用 LLM 按 `cognitive_radar` 量表对每道真题打分。模型对每题输出 K1–K5 各一个 1–5 整数 + 形状命名。这是一道题的"难度指纹"。

### 第②步题位聚合 —— 产出"难度锚点"

这一步是**难度客观化的关键**。同一个题位（比如选择题 Q12）考了十几年，把这些年的 K 雷达聚合：

```
Q12 题位聚合（13 道真题）：
  K1 分布: 众数=1, 范围[1,5]    ← K1 多数题只要常识，但偶尔出纯概念题
  K2 分布: 众数=1, 范围[1,3]
  K3 分布: 众数=1, 范围[1,2]
  K4 分布: 众数=1, 范围[2,4]    ← K4 至少有陷阱，是 Q12 的特色
  K5 分布: 众数=1, 范围[1,2]
  典型雷达形状: K1-K2 平衡型
```

聚合后的**题位难度锚点**回答两个问题：
- **这个题位"通常"多难？** → 看众数（mode）
- **这个题位"允许"多难？** → 看范围（range）

出题时，目标 K 值必须落在锚点的合理范围内，否则就是"难度偏离"。

### 第③步 K 值检索 —— MAE 找最接近的参考题

出某道题时，知道目标 K 雷达（来自题位锚点），就到题库里找认知负荷**最接近**的往年题作参考。检索算法（代码实现，不让 LLM 脑算）：

```
输入: 目标 K 雷达  t = {K1:3, K2:1, K3:2, K4:2, K5:1}

① 知识点命中  → 先按知识点关键词过滤题库（只留同考点的题）
② 难度门控    → D(候选) ≤ D(目标) + ε
                 （候选难度总和不超过目标 + 容差，候选不许比目标更难）
③ MAE 排序    → 对每个候选算平均绝对误差:
                 MAE = 平均( |候选K1 - 目标K1|, |候选K2 - ...|, ... )
                 MAE 越小，认知形状越接近 → 排越前
④ 截断        → 取前 N 条作 reference_questions
```

**为什么用 MAE 而不是直接比"难度总分"？** 因为两道总分相同的题，难度形状可能完全不同。MAE 比的是**五个维度的逐维差距**，能找到"不仅难度相当、连难度类型（推演/陷阱/计算）都相似"的参考题。这是更精确的难度匹配。

## 1.4 难度锚点怎么用：进入设计卡

题位锚点最终进入单题的**设计卡**（design_card），成为整道题的"难度宪法"，下游不得修改：

```yaml
k_target:                    # 从题位锚点的众数/范围来
  K1: 3
  K2: 1
  K3: 2
  K4: 2
  K5: 1
difficulty_level: 3          # 综合难度
radar_shape: "K1-K2平衡型"   # 主导难度类型
should_be: ...               # 该考什么（来自锚点 + 考察模式）
should_not_be: ...           # 不许偏移到哪
```

审核时，逐维核对生成题的实际 K 雷达是否贴合 `k_target`、是否落在锚点范围内。**难度偏离 → 路由回退重设。**

## 1.5 一个真实例子（Q12 计算机系统概述）

题库聚合后的 Q12 经验卡（真实数据）：

```
题位: Q12  科目: 计算机系统概述  题型: 选择题

K值锚点:
  K1 众数=1 [1,5]   K2 众数=1 [1,3]   K3 众数=1 [1,2]
  K4 众数=1 [2,4]   K5 众数=1 [1,2]
典型雷达形状: K1-K2平衡型（概念与计算并重）

考察模式分布:
  计算型——单结果竞争    53.8% (7/13)
  概念辨析型——四选一定义 23.1% (3/13)
  组合判断型——I/II/III  23.1% (3/13)
```

这张卡告诉出题系统：**Q12 通常考"性能指标计算"或"概念辨析"，难度偏易（K 众数多=1），但 K4 必带陷阱。** 出题时套这个画像，而不是拍脑袋。这就是难度客观化的最终价值。

# 机制二 · 知识图谱构建

## 2.1 我们要的"知识图谱"是什么

不是一张节点连线的炫酷大图，而是一棵**可检索、可注入的考点结构树**，解决三个实际问题：

| 问题 | 知识图谱怎么解决 |
|------|----------------|
| 教师说"出 AVL 的题"，系统不知道 AVL 是什么、在哪一章、有哪些子考点 | 知识图谱把"AVL"定位到 `DS-5 树与二叉树 > 平衡二叉树`，并给出它的完整子考点 |
| 出题时考点跑偏（要考 A 考成 B） | 图谱锁定考点的边界，`should_be`/`should_not_be` 来自这里 |
| 找参考题时无法按知识点过滤 | 图谱标签作为题库的索引键 |

**一句话：知识图谱是出题系统的"考点地图 + 索引"。**

## 2.2 知识图谱的数据来源与结构

图谱有**三层来源**，由粗到细：

```
┌──────────────────────────────────────────────────────────┐
│ 第①层：考试大纲（dagang.md）—— 顶层结构                    │
│   • 2025 408 大纲，定义四科目分值、题型结构                  │
│   • 数据结构 45 / 组成原理 45 / 操作系统 35 / 网络 25        │
│   • 单选 80 分 + 综合 70 分                                │
└──────────────────────────────────────────────────────────┘
      │ 细化
      ▼
┌──────────────────────────────────────────────────────────┐
│ 第②层：四科目思维导图式知识点库（kg/*.md）—— 主体内容        │
│   • data_structure.md / computer_organization.md           │
│     operating_system_knowledge.md / computer_network.md    │
│   • 按 "章 > 节 > 知识点 > 叶子属性" 层级组织               │
│   • 粒度到"可出题的概念/结构/操作/机制/计算任务/边界条件"     │
│   • 只存知识点名词+属性，不展开定义/公式（避免污染出题）      │
└──────────────────────────────────────────────────────────┘
      │ 锚定
      ▼
┌──────────────────────────────────────────────────────────┐
│ 第③层：知识点标签（target_family）—— 索引键                 │
│   • 形如 "DS-5 > 树与二叉树 > 平衡二叉树"                   │
│   • 每个标签定位到图谱的一个子树                             │
│   • 题库真题、题位经验卡都挂这个标签 → 形成反向索引           │
└──────────────────────────────────────────────────────────┘
```

### 图谱的文件格式（以数据结构为例）

```markdown
## 5. 树与二叉树                    ← 章（顶层，对应 DS-5）
### 二叉树的概念                    ← 节
#### 满二叉树                       ← 知识点
- 属性: 特殊形态                    ← 叶子属性（可出题的最小单元）
#### 完全二叉树
- 属性: 特殊形态
### 树与二叉树的应用
#### 平衡二叉树（AVL）
- 属性: 旋转操作、平衡因子          ← 这就是"AVL"被定位到的地方
#### 哈夫曼树
...
```

**关键设计：只存知识点名词和属性，不写定义、公式、组合方式。** 原因：知识图谱是给出题系统看"考点边界"的，不是给学生背的教材。写满定义反而会诱导模型抄图谱、不出新题。

## 2.3 知识图谱怎么"查"：子树抽取

出题时，交互层或出题层拿一个 `target_family`（如 `DS-5 > 树与二叉树`），图谱返回**对应的整棵子树**。这是纯 Python 字符串切片（不用 LLM，确定性强）：

```
输入: target_family = "DS-5 > 树与二叉树"
        │
        │  ① 解析 → 域(DS) + 章号(5) + 子节(树与二叉树)
        │  ② 定位 kg 文件 → data_structure.md
        │  ③ 找到 "## 5. 树与二叉树" 标题
        │  ④ 切到下一个同级 "## " 为止 = 整棵子树
        │  ⑤ 若有更深子节，进一步缩到该子节
        ▼
输出: "树与二叉树" 下的全部考点
       （二叉树概念/遍历/线索化/AVL/哈夫曼树/并查集...）
```

抽取出的子树进入设计卡的"相关知识点细纲"段，给出题系统划定**这道题只能在哪些考点里选**。如果教师指定要排除某些子考点，还能就地标记排除（`_mark_excluded_knowledge`）。

## 2.4 知识图谱怎么"用"：三级检索体系

图谱不是被动的字典，而是**主动的检索入口**。系统按精度从高到低有三级检索：

```
┌──────────────────────────────────────────────────────────┐
│ 第①级：标签精确命中（KnowledgeIndex，首选，最快最准）       │
│   • 题库每道题的元数据里存了知识点标签                       │
│   • 按标签做反向索引：标签段 → [文件列表]                    │
│   • 教师说"AVL" → 立刻命中所有标了 AVL 的往年题             │
│   • O(1) 级查找，无 LLM 参与                                │
└──────────────────────────────────────────────────────────┘
      │ 标签查不到时降级
      ▼
┌──────────────────────────────────────────────────────────┐
│ 第②级：grep 关键词检索（topic_search，兜底）                │
│   • LLM 根据"AVL树旋转操作"生成 3–5 个 grep 关键词           │
│   • Python grep 扫题库文件全文                               │
│   • LLM 再把命中结果分类成"考察模式卡片"(topic_mode_card)    │
│   • 比①慢，但能捞到标签没覆盖的题                           │
└──────────────────────────────────────────────────────────┘
      │ 仍查不到
      ▼
┌──────────────────────────────────────────────────────────┐
│ 第③级：启发式兜底（基于题位 + 考察模式推断）                 │
│   • 实在没检索到，用题位经验卡的考察模式分布兜底              │
│   • 保证出题流程不因"查不到"而中断                          │
└──────────────────────────────────────────────────────────┘
```

检索结果（往年题 + K 雷达 + 陷阱）回流到出题层，作为 `reference_questions`。**这把"出题"从无中生有，变成"有据可依"** ——参考往年同类考点怎么考的。

## 2.5 一个完整场景：从"出 AVL 题"到落地

```
教师: "出一道 AVL 的题"
  │
  ① 图谱定位  "AVL" → DS-5 > 树与二叉树 > 平衡二叉树
  │
  ② 子树抽取  返回 AVL 全部考点（旋转操作/平衡因子/插入删除调整）
  │
  ③ 标签检索  命中题库里所有 AVL 往年题
  │
  ④ 难度锚定  查 AVL 所在题位(综合题 Q41)的难度锚点
  │            → K3(推演)主导, K 众数=4
  │
  ⑤ K值检索   用目标 K 雷达 {K3:4,...} 做 MAE 检索
  │            → 找到认知形状最接近的往年 AVL 题作参考
  │
  ⑥ 进入设计卡  考点边界(子树) + 难度(K锚点) + 参考(检索题) 三者汇合
  │            → should_be: AVL 旋转辨析 / should_not_be: 红黑树
  │
  ⑦ 出题       出题智能体在"宪法"约束下生成题干
```

**这个流程里，知识图谱管"考什么（边界）"，难度抽取管"多难（标尺）"，两者合一回答了"这道题到底考什么、有多难"。**

# 两个机制的关系：考点的"地图"与"标尺"

```
                    知识图谱（机制二）          难度抽取（机制一）
                    ──考点的"地图"             ──难度的"标尺"
                         │                          │
                    考什么(边界)                多难(标尺)
                         │                          │
                         └──────────┬───────────────┘
                                    ▼
                         ┌─────────────────────┐
                         │     设计卡           │
                         │  (题目的"宪法")      │
                         │  • 考点边界(来自图谱) │
                         │  • K目标(来自难度锚点)│
                         │  • 参考题(K值检索)   │
                         │  • should_be/not_be  │
                         └─────────────────────┘
                                    │
                                    ▼
                              出题/审核/求解
                          （全程不得修改设计卡）
```

| | 知识图谱 | 难度抽取 |
|---|---------|---------|
| **解决** | 考点定位、边界、检索 | 难度量化、对比、锚定 |
| **数据形态** | 四科目考点结构树 | 每题 K1–K5 雷达 + 题位锚点 |
| **构建** | 大纲 → 思维导图式知识点库 → 标签索引 | 真题打分 → 题位聚合（众数+范围） |
| **检索方式** | 子树抽取 + 标签/grep 三级 | 难度门 + MAE 排序 |
| **落地到** | 设计卡的"相关知识点细纲" + `should_be` | 设计卡的 `k_target` + `radar_shape` |

# 总结

> **知识图谱构建** 解决"考什么"：把 408 大纲变成一棵可检索、可注入的考点结构树，配三级检索（标签/grep/兜底），让系统知道每个考点在哪、边界是什么、往年怎么考。
>
> **难度抽取** 解决"多难"：用 K1–K5 五维认知雷达把难度从主观词变成客观量，从真题打分聚合出题位锚点（众数+范围），出题时用 MAE 检索认知形状最接近的参考题。

两者汇入**设计卡**，把"考什么、多难、参考谁"全部钉死成客观约束。这就是系统出题不漂移的数据根基——**不靠模型自觉，靠机制和数据兜底**。
