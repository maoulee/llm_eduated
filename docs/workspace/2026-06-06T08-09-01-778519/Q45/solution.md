## 求解过程

### 子问题(1)：求 Need 矩阵和 Available 向量

**Need = Maximum − Allocation**，逐进程逐资源计算：

| 进程 | Maximum (A,B,C) | Allocation (A,B,C) | Need (A,B,C) |
|------|-----------------|--------------------|--------------|
| P0   | 8, 5, 4         | 1, 1, 0            | **7, 4, 4**  |
| P1   | 3, 2, 2         | 2, 0, 0            | **1, 2, 2**  |
| P2   | 9, 0, 3         | 3, 0, 2            | **6, 0, 1**  |
| P3   | 2, 2, 2         | 1, 1, 1            | **1, 1, 1**  |
| P4   | 4, 3, 3         | 0, 0, 2            | **4, 3, 1**  |

**Available = Total − ΣAllocation**

- ΣAllocation = (1+2+3+1+0, 1+0+0+1+0, 0+0+2+1+2) = (7, 2, 5)
- Available = (10, 6, 8) − (7, 2, 5) = **(3, 4, 3)**

### 子问题(2)：安全性算法判断

初始：Work = Available = (3, 4, 3)，Finish = [F, F, F, F, F]

**第 1 轮：**

| 检查进程 | Need      | Work      | Need ≤ Work? | 操作                     |
|----------|-----------|-----------|--------------|--------------------------|
| P0       | 7, 4, 4   | 3, 4, 3   | ❌ (7>3)     | —                        |
| **P1**   | **1,2,2** | **3,4,3** | **✅**       | Work += Alloc(P1)=(2,0,0) → **(5,4,3)**，Finish[P1]=T |
| P2       | 6, 0, 1   | 5, 4, 3   | ❌ (6>5)     | —                        |
| **P3**   | **1,1,1** | **5,4,3** | **✅**       | Work += Alloc(P3)=(1,1,1) → **(6,5,4)**，Finish[P3]=T |
| **P4**   | **4,3,1** | **6,5,4** | **✅**       | Work += Alloc(P4)=(0,0,2) → **(6,5,6)**，Finish[P4]=T |

**第 2 轮：**

| 检查进程 | Need      | Work      | Need ≤ Work? | 操作                     |
|----------|-----------|-----------|--------------|--------------------------|
| P0       | 7, 4, 4   | 6, 5, 6   | ❌ (7>6)     | —                        |
| **P2**   | **6,0,1** | **6,5,6** | **✅**       | Work += Alloc(P2)=(3,0,2) → **(9,5,8)**，Finish[P2]=T |

**第 3 轮：**

| 检查进程 | Need      | Work      | Need ≤ Work? | 操作                     |
|----------|-----------|-----------|--------------|--------------------------|
| **P0**   | **7,4,4** | **9,5,8** | **✅**       | Work += Alloc(P0)=(1,1,0) → **(10,6,8)**，Finish[P0]=T |

全部 Finish = T，最终 Work = (10, 6, 8) = Total。

> **结论：系统处于安全状态。一个安全序列为 P1 → P3 → P4 → P2 → P0。**

### 子问题(3)：P0 请求 Request₀ = (3, 4, 3) 的判定

**步骤 1：检查 Request₀ ≤ Need[P0]**

- Request₀ = (3, 4, 3)，Need[P0] = (7, 4, 4)
- 逐分量：3≤7 ✅，4≤4 ✅，3≤4 ✅
- **判定：通过 ✅**（请求未超过最大需求）

**步骤 2：检查 Request₀ ≤ Available**

- Request₀ = (3, 4, 3)，Available = (3, 4, 3)
- 逐分量：3≤3 ✅，4≤4 ✅，3≤3 ✅（等号成立）
- **判定：通过 ✅**（当前可用资源足以满足请求）

**步骤 3：假装分配后执行安全性检查**

假装分配，更新状态：

- Available' = (3,4,3) − (3,4,3) = **(0, 0, 0)**
- Allocation'[P0] = (1,1,0) + (3,4,3) = (4, 5, 3)
- Need'[P0] = (7,4,4) − (3,4,3) = (4, 0, 1)

更新后的完整状态：

| 进程 | Allocation' (A,B,C) | Need' (A,B,C) |
|------|---------------------|---------------|
| P0   | 4, 5, 3             | 4, 0, 1       |
| P1   | 2, 0, 0             | 1, 2, 2       |
| P2   | 3, 0, 2             | 6, 0, 1       |
| P3   | 1, 1, 1             | 1, 1, 1       |
| P4   | 0, 0, 2             | 4, 3, 1       |

执行安全性算法：初始 Work = (0, 0, 0)

| 检查进程 | Need'     | Work      | Need' ≤ Work? |
|----------|-----------|-----------|---------------|
| P0       | 4, 0, 1   | 0, 0, 0   | ❌ (4>0)      |
| P1       | 1, 2, 2   | 0, 0, 0   | ❌ (1>0)      |
| P2       | 6, 0, 1   | 0, 0, 0   | ❌ (6>0)      |
| P3       | 1, 1, 1   | 0, 0, 0   | ❌ (1>0)      |
| P4       | 4, 3, 1   | 0, 0, 0   | ❌ (4>0)      |

**没有任何进程的 Need ≤ Work，安全性算法第一轮即失败，找不到安全序列。**

> **判定：不安全，不能批准该请求。P0 必须等待。**

核心原因：虽然 Request₀ 通过了 Request ≤ Need 和 Request ≤ Available 两步检查，但假装分配后 Available 归零为 (0,0,0)，所有进程的 Need 都不为零向量，无任何进程可启动完成，系统进入不安全状态。因此安全性检查不可省略，**最终拒绝该请求**。

## 最终答案

**(1)** Need 矩阵为：

| 进程 | Need (A,B,C) |
|------|--------------|
| P0   | 7, 4, 4      |
| P1   | 1, 2, 2      |
| P2   | 6, 0, 1      |
| P3   | 1, 1, 1      |
| P4   | 4, 3, 1      |

Available 向量 = **(3, 4, 3)**

**(2)** 系统处于**安全状态**。一个安全序列为 **P1 → P3 → P4 → P2 → P0**。

**(3)** P0 的请求 Request₀ = (3, 4, 3) **不能批准**。判定过程：步骤 1（Request ≤ Need）通过 ✅；步骤 2（Request ≤ Available）通过 ✅；步骤 3（安全性检查）不通过 ❌——假装分配后 Available = (0,0,0)，无任何进程可完成，系统不安全。因此拒绝请求，P0 须等待。
