# AVL 平衡二叉树的插入与旋转调整

## 题干

将关键字序列 ⟨P1⟩ 中的各元素依次插入到一棵初始为空的 AVL 平衡二叉树中。每次插入后，从插入点沿父指针逐层向上检查各结点的平衡因子。若发现某结点的平衡因子绝对值大于 1，则立即对该结点为根的子树执行相应的旋转操作（LL / LR / RL / RR），使该子树恢复平衡。

约定：结点的平衡因子 BF = 左子树高度 − 右子树高度；空树高度为 0，叶子结点高度为 1。

## 子问题

**(1)**（6分）在依次插入过程中，首次导致 AVL 树失衡的是插入哪个关键字？请指出失衡的最小子树的根结点关键字，并判断应执行的旋转类型（LL / LR / RL / RR）。

**(2)**（8分）在完成全部插入与旋转操作后，写出该 AVL 树的**前序遍历序列**，并给出根结点的平衡因子值。

**(3)**（6分）下面是 AVL 树插入后自底向上调整平衡的核心代码片段。结构体 `AVLNode` 含字段 `key`、`lchild`、`rchild`、`height`。函数 `getHeight(node)` 返回结点高度（空结点高度为 0），`rotateRight(node)` 对 `node` 执行右旋并返回新子树根，`rotateLeft(node)` 对 `node` 执行左旋并返回新子树根。请在 `___①___`、`___②___`、`___③___` 处填写正确内容，使代码能正确处理左子树过高的情况。

```c
// balanceFactor(node) = getHeight(node->lchild) - getHeight(node->rchild)
AVLNode* rebalance(AVLNode* node) {
    int bf = balanceFactor(node);
    if (bf > 1) {    // 左子树过高
        if (balanceFactor(node->lchild) >= 0)
            return ___①___;           // LL 型
        else {
            node->lchild = ___②___;   // LR 型第一步
            return ___③___;           // LR 型第二步
        }
    }
    // 右子树过高的情况对称处理，此处省略
    return node;
}
```

## 参数规格

⟨P1⟩: 一个由互不相同的正整数组成的插入序列，满足以下约束：
- 序列长度足以保证插入过程中触发多次旋转操作，且旋转类型涵盖多种（至少包含一次双旋转，即 LR 型或 RL 型）
- 首次失衡发生在序列前半段，使考生较早进入核心考点
- 各关键字取值为合理范围的正整数，便于手算推演
- 最终 AVL 树高度足够，保证子问题(2)的前序遍历序列具有区分度

## 设计说明

- **考察结构模式**：过程追踪（子问题 1–2）+ 代码实现（子问题 3）混合，与蓝图考察模式一致
- **子问依赖关系**：(1) → (2) 递进——(1) 的旋转结果是 (2) 最终树状态的中间快照；子问题 (3) 独立考察旋转代码的逻辑理解
- **should_be**：覆盖 AVL 插入流程、平衡因子计算、LL/LR/RL/RR 旋转类型判定、前序遍历输出、旋转代码的指针调整逻辑
- **should_not_be**：不涉及 AVL 删除操作、不涉及红黑树或其他平衡策略、不涉及 B/B+ 树
- **K 值对齐说明**：
  - K1=3：需准确记忆平衡因子定义及四种旋转类型的判定规则
  - K2=2：平衡因子与高度的算术计算简单，数字友好
  - K3=4–5：多次插入叠加多次旋转的长程推演，需持续维护中间树状态，步数多
  - K4=3–4：需根据失衡结点及其孩子的平衡因子符号正确路由到对应旋转类型；代码部分需理解双旋转的指针调整顺序
  - K5=1：单一知识点（AVL 平衡二叉树）内部解决
- **参数约束推导理由**：⟨P1⟩ 须保证至少触发包含双旋转在内的多种旋转，才能在子问题(1)中考察旋转类型判定的区分度；序列需足够长以产生多次失衡，提升 K3 推演难度；首次失衡在序列前半段，避免前置步骤冗长
