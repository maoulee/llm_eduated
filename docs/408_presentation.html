solve_pipeline.py
# Route → classify question type
route = classify_route(question)  # no thinking, 14.5/s

# Path 1: Pure reasoning (concept)
reason_answer = reason(question, thinking=True)

# Path 2: Reason + Code (computational)
if route == "code":
    code_result = generate_and_exec(question)

# Consensus check
if reason_answer == code_answer:
    return consensus(reason_answer)

// knowledge extraction · P1-P5

五遍渐进式知识抽取

P1 题目结构

已知条件 / 求解目标
隐含约束 / 干扰项分析
正确答案诊断

→

P2 知识单元

knowledge: 概念/定义/公式
mechanism: 机制影响推理
common_misunderstanding

→

P3 触发规则

source_signals → 信号映射
activation_condition
wrong_if_missing
diagnostic_value

→

P4 推理模式

steps: 有序原子操作
common_breakpoints
can_verify_with_code

→

P5 审核

RuleChecker: schema/一致性
DomainCritic: 学术审查
readiness + confidence

遍次连接关系

P1 提供题干结构 → P2 识别知识点 → P3 建立信号映射 → P4 抽取解题程序 → P5 交叉验证。后四遍互相引用，形成知识图谱。

审核模式

fast: RuleChecker + DomainCritic (无思考)
deep: RuleChecker + DomainCritic (思考开启)
legacy: 单遍 LLM 自审核

// demo · P1 浮点数+Cache 混合主观题

出题结果演示

question.md
// 20分主观题 · 混合知识点
某计算机中，浮点数采用 IEEE 754 单精度格式
（1+8+23位，偏置值127）。
Cache采用直接映射，128行，每行16字节。

float a = -13.75, b = 7.375;
float c;  c = a - b;
// c @ 0x0848, a @ 0x0800

（1）8分 a和b的IEEE 754十六进制表示
（2）8分 变形补码(双符号位)求a-b
（3）4分 a和c的Cache行号+冲突判断

参考答案

a = 0xC15C0000
b = 0x40EC0000
a-b = 0xC1A90000
尾数求和: 11.10110100
双符号位: 11 (负无溢出)
a→Cache行0, c→Cache行4, 无冲突

Pipeline 验证结果

CodeSolver: 全部数值通过
Reviewer: 通过
Solver盲解: 6/6 匹配
答案唯一性: 确认
