### A. 正确的原码表示

原码规则：符号位表示正负（负数为 1），数值位为绝对值的二进制。

- 符号位 = 1（负数）
- 数值位 = |x| 的二进制 = 1001011

因此：**A = 11001011**

### B. 符号位取反（误判为正数）

符号位误判为 0，数值位仍为 75 的二进制：

- 符号位 = 0，数值位 = 1001011

因此：**B = 01001011**

### C. 补码混淆

误按补码规则求负数机器数：先写 +75 的 8 位原码，再逐位取反后加 1。

- +75 的 8 位原码：01001011
- 逐位取反：10110100
- 加 1：10110101

因此：**C = 10110101**

### D. 反码混淆

误按反码规则求负数机器数：先写 +75 的 8 位原码，逐位取反（不加 1）。

- +75 的 8 位原码：01001011
- 逐位取反（不加 1）：10110100

因此：**D = 10110100**

| 选项 | 二进制值 | 说明 |
|------|---------|------|
| **A（正确）** | **11001011** | 符号位=1，数值位=|75|的二进制 |
| B | 01001011 | 符号位误判为 0（按正数处理） |
| C | 10110101 | 误用补码规则（取反+1） |
| D | 10110100 | 误用反码规则（取反不加 1） |

**正确选项：A. 11001011**

四个选项互异验证：
- A = 11001011
- B = 01001011
- C = 10110101
- D = 10110100

四个值各不相同。补码结果（C）与反码结果（D）仅末位差 1，恰好因 75 的二进制非全 1 而不同，体现了编码辨析的区分度。

### 6.

### 正确路径

强制类型转换 `(unsigned short)s` 的核心规则：**位模式不变，只是把相同的 16 位位模式按无符号解读**。

$$
(\text{unsigned short})\,s = s \bmod 2^{16}
$$

代入 $s = -100$：

$$
(\text{unsigned short})(-100) = -100 \bmod 65536 = 65536 - 100 = 65436
$$

验证：$-100$ 的 16 位补码位模式为 $65436 = \text{0xFF9C}$，按无符号解释即为 $65436$。

### 干扰项分析

| 选项 | 值 | 错误类型 | 错误根源 |
|------|-----|---------|---------|
| **A** | $65436$ | **正确** | 位模式不变，$65536 + (-100) = 65436$ |
| B | $100$ | 绝对值型 | 直接取 $|-100| = 100$，忽略了位模式的无符号重解读 |
| C | $65435$ | 补码混淆型（反码） | 对 $100$ 的 16 位表示逐位取反（反码）得 $65535 - 100 = 65435$，未加 1；与 A 相差 1 |
| D | $32668$ | 符号范围混淆型 | $-100 + 32768 = 32668$，错误使用了 $32768$ 偏移量（应为 $65536$） |

- **B 为什么错**：绝对值路径完全忽略了"位模式不变"这一核心规则。$-100$ 转 unsigned short 后，结果应为大正数，而非正数 $100$。
- **C 为什么错**：反码路径求出 $65535 - 100 = 65435$，比正确补码结果少 1（补码 = 反码 + 1）。这是一个典型的"忘记补码末尾加 1"的错误。
- **D 为什么错**：偏移量混淆路径用了 $s + 32768$ 而非 $s + 65536$。$32768$ 是 short 范围 $[-32768, 32767]$ 到 $[0, 65535]$ 的映射偏移，但 unsigned short 的正确转换是 $s \bmod 65536$，即偏移量 $65536$。

$$
\boxed{A = 65436}
$$

printf 输出的值为 **65436**。

### 8.

1. **地址空间**：20 根地址线可寻址 $2^{20}$ 个地址单元，即 $2^{20} = 1{,}048{,}576$ 个地址。

2. **数据位宽**：16 根数据线，每个地址可读/写 16 bit = 2 Byte。

3. **总容量（bit）**：
$$2^{20} \times 16\ \text{bit} = 16{,}777{,}216\ \text{bit}$$

4. **换算为 Byte**：
$$16{,}777{,}216\ \text{bit} \div 8 = 2{,}097{,}152\ \text{Byte}$$

5. **换算为 MB**：
$$2{,}097{,}152\ \text{Byte} \div 1{,}048{,}576 = 2\ \text{MB}$$

> 等价理解：按字节编址下，每个地址对应 2 Byte，故可寻址字节数 = $2^{20} \times 2 = 2^{21}$ Byte = 2 MB。

### B. 1 MB（忽略数据线位宽）

- **错误路径**：仅用地址线数计算地址空间 $2^{20} = 1$ M，默认每个地址 1 Byte，忽略 16 根数据线带来的 2 字节/地址因子。
- **结果**：$2^{20} \times 1\ \text{Byte} = 1{,}048{,}576\ \text{Byte} = 1\ \text{MB}$。
- **错误类型**：漏乘数据位宽，得到正确值的一半。

### C. 1310720 bit（地址线数与数据线数混淆）

- **错误路径**：将 16 当作地址线数、20 当作数据线位宽进行计算。
- **结果**：$2^{16} \times 20\ \text{bit} = 1{,}310{,}720\ \text{bit} = 163{,}840\ \text{Byte}$（≈ 0.156 MB）。
- **错误类型**：条件混淆，两个参数互换后量级与正确值明显不同。

### D. 16 MB（bit/Byte 单位混淆）

- **错误路径**：算出总容量 $2^{24}$ bit 后，未除以 8，直接将 bit 数当作 Byte 数。
- **结果**：$16{,}777{,}216\ \text{Byte} = 16{,}777{,}216 \div 1{,}048{,}576 = 16\ \text{MB}$。
- **错误类型**：bit/Byte 单位混淆，数值放大 8 倍。

| 选项 | 数值 | 对应路径 |
|------|------|----------|
| **A** ✅ | **2 MB** | 正确：$2^{20} \times 16\ \text{bit} = 2^{24}\ \text{bit} = 2^{21}\ \text{B} = 2\ \text{MB}$ |
| B | 1 MB | 忽略数据线位宽（漏乘 2 字节因子） |
| C | 1310720 bit | 地址线/数据线互换（$2^{16} \times 20$ bit） |
| D | 16 MB | bit/Byte 混淆（bit 当 Byte，放大 8 倍） |

**正确答案：A. 2 MB**

### 10.

### A. 相对寻址（正确答案）

相对寻址中，取指后 PC 已自动加上当前指令长度，因此：

$$EA = (PC + \text{指令长度}) + D = (1A0H + 2) + 248H = 1A2H + 248H = \boxed{3EAH}$$

关键点：PC 指向本条指令起始地址 1A0H，取指后 PC 更新为 1A0H + 2 = 1A2H，再加形式地址 D = 248H，得到 EA = 3EAH。

### B. 变址寻址（干扰项——直接寻址误用）

该选项将变址寻址误当作直接寻址，忽略了变址寄存器 Rx 的加法：

$$EA = D = 248H$$

**错误原因**：变址寻址的正确公式应为 EA = Rx + D = 6C0H + 248H，但此处直接取形式地址作为有效地址，漏掉了变址寄存器 Rx 的贡献。

### C. 基址寻址（干扰项——加法方向取反）

该选项将基址寻址的加法方向取反并取绝对值：

$$EA = |D - Rb| = |248H - 3B0H| = |-168H| = 168H$$

**错误原因**：基址寻址的正确公式应为 EA = Rb + D = 3B0H + 248H = 5F8H，但此处将加法误算为减法并取绝对值，得到 168H。

### D. 一次间接寻址（干扰项——多取一级间接）

该选项对形式地址做了两次访存取址（相当于二次间接寻址）：

$$EA = Mem[Mem[D]] = Mem[Mem[248H]] = Mem[8E0H] = 056H$$

**错误原因**：一次间接寻址只需一次访存，EA = Mem[D] = Mem[248H] = 8E0H。但此处多执行了一级访存，取到了 Mem[8E0H] = 056H，相当于二次间接寻址。

**A. 相对寻址：EA = 3EAH**

相对寻址是四种寻址方式中计算路径唯一正确的选项，EA = (PC + 指令长度) + D = (1A0H + 2) + 248H = 3EAH。其余三个选项分别犯了忽略变址寄存器、基址加法方向取反、间接寻址多取一级的不同错误。

| 总线宽度 W（第1问） | 64 bit |
| 总线宽度 W（第2问） | 32 bit |
| 每次传输所需周期数 N | 4 |

**公式**：总线带宽（MB/s）= 总线宽度（Byte）× 有效传输频率（MHz）

其中：有效传输频率 = 总线时钟频率 ÷ 每次传输所需周期数 = f ÷ N

---

## 第 1 问（4 分）：计算数据传输带宽

**步骤 1：将总线宽度从 bit 换算为 Byte**

$$W = 64\ \text{bit} \div 8 = 8\ \text{Byte}$$

**步骤 2：计算有效传输频率**

$$\text{有效传输频率} = \frac{f}{N} = \frac{200\ \text{MHz}}{4} = 50\ \text{MHz}$$

**步骤 3：计算总线带宽**

$$\text{带宽} = 8\ \text{Byte} \times 50\ \text{MHz}$$

$$= 8 \times 50 \times 10^6\ \text{Byte/s}$$

$$= 400 \times 10^6\ \text{Byte/s}$$

$$= 400\ \text{MB/s}$$

> 说明：MHz 中的 $10^6$ 与 MB/s 中的 $10^6$ 自动相消，结果为简洁整数。

### ✅ 第 1 问答案：带宽 = **400 MB/s**

---

## 第 2 问（2 分）：W 减小为 32 bit 后重新计算

W 从 64 bit 减小为 32 bit，时钟频率 f = 200 MHz、传输周期数 N = 4 均不变。

**步骤 1：将总线宽度从 bit 换算为 Byte**

$$W' = 32\ \text{bit} \div 8 = 4\ \text{Byte}$$

**步骤 2：有效传输频率（不变）**

$$\text{有效传输频率} = 50\ \text{MHz}$$

**步骤 3：计算总线带宽**

$$\text{带宽} = 4\ \text{Byte} \times 50\ \text{MHz} = 200\ \text{MB/s}$$

### ✅ 第 2 问答案：带宽 = **200 MB/s**

**带宽变化原因**：带宽与总线宽度成正比。总线宽度从 64 bit 减半为 32 bit（8 Byte → 4 Byte），而有效传输频率不变（50 MHz），因此带宽从 400 MB/s 降至 200 MB/s，恰好减半。

$$\frac{\text{新带宽}}{\text{原带宽}} = \frac{200}{400} = 0.5 = 50\%$$

### 1.

主存地址总位数 = log₂(M) = **20 位**。

**(1) 块内地址（offset）位数**

$$\text{offset} = \log_2(b) = \log_2(64) = 6 \text{ 位}$$

**(2) Cache 行号（行地址）位数**

Cache 行数 = C / b = 16384 / 64 = 256

$$\text{行号位数} = \log_2(256) = 8 \text{ 位}$$

**(3) 标记（Tag）位数**

$$\text{Tag} = 20 - 6 - 8 = 6 \text{ 位}$$

验证：6 + 8 + 6 = 20 ✓

**直接映射地址结构：**

| Tag（标记） | 行号 | 块内地址 |
|:-----------:|:----:|:--------:|
| 6 位 | 8 位 | 6 位 |

---

**(1) 块内地址（offset）位数**

$$\text{offset} = \log_2(b) = \log_2(64) = 6 \text{ 位}$$

（块内地址仅由块大小决定，与映射方式无关。）

**(2) 组号（组地址）位数**

关键公式：组数 = Cache 行数 ÷ 路数 = 256 ÷ 4 = 64

$$\text{组号位数} = \log_2(64) = 6 \text{ 位}$$

**(3) 标记（Tag）位数**

$$\text{Tag} = 20 - 6 - 6 = 8 \text{ 位}$$

验证：6 + 6 + 8 = 20 ✓

**组相联映射地址结构：**

| Tag（标记） | 组号 | 块内地址 |
|:-----------:|:----:|:--------:|
| 8 位 | 6 位 | 6 位 |

---

### 地址结构对比表

| 映射方式 | 标记 Tag 位数 | 行号/组号 位数 | 块内地址 位数 | 地址总位数 |
|----------|:------------:|:-------------:|:------------:|:---------:|
| 直接映射 | 6 | 8（行号） | 6 | 20 |
| 4 路组相联 | 8 | 6（组号） | 6 | 20 |

> 两种映射的地址总位数均为 20 位，块内地址均为 6 位。差异在于中间字段：直接映射行号 8 位 vs 组相联组号 6 位，差值 2 位恰好 = log₂(路数) = log₂(4) = 2，这 2 位转移到了 Tag 中，因此直接映射 Tag = 6 位而组相联 Tag = 8 位。

### 映射过程描述

**直接映射：**

主存块号 = 主存地址 ÷ 块大小（去掉块内地址的 6 位，剩下 14 位即主存块号）。
- 主存块号 mod Cache 行数（256）→ 确定唯一映射到的 Cache 行号（0~255）。
- 每个主存块只能映射到唯一的一行，检查 Tag 是否匹配即可判断命中。
- 冲突率高，但查找速度快（只需比较一行）。

**4 路组相联映射：**

- Cache 的 256 行被划分为 64 组，每组 4 路（4 行）。
- 主存块号 mod 组数（64）→ 确定映射到的 Cache 组号（0~63）。
- 组内 4 路中任意一路均可放置该主存块（替换时组内 4 路任选）。
- 查找时需同时比较该组内 4 路的 Tag，冲突率低于直接映射，灵活性更高。
