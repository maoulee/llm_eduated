## 一、单项选择题（5×2=10分）


### 1.

**答案**：C

**解析**：主存容量为 4KB = 4096B = 2^12 B，按字节编址则每个存储单元对应一个字节地址，共需 2^12 个地址，地址线位数 n = log2(4096) = 12 位。

- A 错误：10 位对应容量 2^10 B = 1KB，少了 4 倍。
- B 错误：11 位对应容量 2^11 B = 2KB，少了一半（常见 off-by-one 偏差）。
- D 错误：16 位对应 64KB，将 4KB 与 64KB 混淆或误用 KB↔bit 单位换算导致。

---


### 2.

### 第一步：确定帧总位数 n

一帧包含：起始位 + 数据位 + 校验位 + 停止位

$$n = 1 + 8 + 1 + 1 = 11 \text{ bit}$$

### 第二步：计算有效数据传输率

每个码元携带 1 bit，波特率 9600 baud 意味着每秒传输 9600 bit 的总信息。其中只有数据位部分（8 bit）是有效数据，故：

$$\text{有效数据传输率} = B \times \frac{d}{n} = 9600 \times \frac{8}{11} = \frac{76800}{11} \approx 6981.82 \text{ bps}$$

### 第三步：验证

- 9600 × 8 = 76800
- 76800 ÷ 11 ≈ 6981.8182

**A. 6981.82 bps**

| 选项 | 值 (bps) | 错误类型 |
|------|----------|----------|
| **A** | **6981.82** | ✅ 正确：9600 × 8 / 11 |
| B | 9600.00 | ❌ 忽略附加位开销：直接取波特率本身，未乘以数据位占比 |
| C | 7680.00 | ❌ 漏算起始位：帧总位数误计为 10（8+1+1），得 9600 × 8 / 10 = 7680 |
| D | 13200.00 | ❌ 比例方向颠倒：将帧总位数做分子、数据位数做分母，得 9600 × 11 / 8 = 13200 |

四选项互异（6981.82 / 9600 / 7680 / 13200），区分度充分。

**答案**：A

**解析**：存储层次按速度从快到慢依次为：通用寄存器（在 CPU 内部，速度最快）→ Cache（高速缓存，位于 CPU 与主存之间）→ 主存（DRAM）→ 磁盘（辅存，机械硬盘最慢）。

### 5.

**答案**：C

**解析**：寄存器寻址的操作数直接存放在 CPU 寄存器中，取操作数时只需访问寄存器，无需访问主存，因此速度最快。

- A 错误：直接寻址需要一次访问主存来获取操作数，慢于寄存器寻址。

- D 错误：基址寻址需要访问主存且需要计算有效地址，慢于寄存器寻址。

## 二、判断题（5×2=10分）


### 1.

**答案**：①√ ②× ③√ ④√

**解析**：
- ①√：冯·诺依曼原始方案确实以运算器为中心，输入设备的数据需经运算器送存储器，存储器的数据也需经运算器送输出设备，运算器是信息传送的必经中枢。
- ②×：现代计算机以存储器为中心，与冯·诺依曼结构（以运算器为中心）在中心部件上根本不同。"未改变其中心部件"是错误描述，将冯·诺依曼结构与现代结构混为一谈是典型概念混淆。
- ③√：存储程序是冯·诺依曼结构的核心特征，指令和数据同等存放在存储器中，机器按地址顺序自动执行。
- ④√：五大部件（运算器、控制器、存储器、输入设备、输出设备）是冯·诺依曼结构的基本组成，控制器（CU）负责产生控制信号协调各部件工作。


### 2.

**答案**：①√ ②× ③√ ④×

**解析**：
- ①√：全互锁方式中主模块发请求等从模块回答，从模块发回答等主模块撤销请求，双方互锁等待，传输最可靠但速度最慢。
- ②×：半互锁方式中，主模块锁定（需等待从模块回答才能撤销请求），但从模块不锁定（回答信号由自身固定延迟决定撤销，不依赖主模块请求撤销）。陈述中"从模块的回答信号由主模块的请求撤销来触发撤销"描述错误——若从模块也等待主模块撤销，则成为全互锁而非半互锁。
- ③√：不互锁方式中主模块发出请求后自行经固定延迟撤销，从模块也自行撤销回答，双方互不等待，速度最快但可靠性最低。
- ④×：异步通信虽无公共时钟，但速度差异过大会导致握手超时或传输效率严重下降。声称"不会对可靠性产生任何影响"是过度绝对化的错误推断。


### 3.

**答案**：①√ ②√ ③× ④√

**解析**：
- ①√：Cache—主存层次解决CPU与主存间的速度差距，主存—辅存层次解决存储容量不足，这是存储系统层次结构的基本设计目标。
- ②√：从寄存器→Cache→主存→辅存，速度递减、容量递增、单位价格递减，这是层次结构的基本规律。
- ③×：主存—辅存层次的地址变换和页面调换由硬件（MMU）和操作系统共同完成，操作系统参与缺页处理和页面替换策略，并非"完全由硬件自动完成"。将Cache的完全硬件透明性错误推广到主存—辅存层次是概念混淆。
- ④√：Cache对程序员（包括汇编程序员）完全透明，程序只面向主存地址编程，Cache的管理（映射、替换、写策略）由硬件自动完成。


### 4.

**答案**：①√ ②√ ③× ④√

**解析**：
- ①√：水平型微指令字较长，一条微指令可同时发出多个微命令，并行操作能力强，通常采用直接编码或字段直接编码。
- ②√：垂直型微指令类似于机器指令格式，操作码指定微操作类型，一条微指令通常只执行一个微操作，并行能力弱。
- ③×："具有操作码和地址码字段、格式类似机器指令"是垂直型微指令的特征，不是水平型微指令的特征。将垂直型特征张冠李戴到水平型是典型概念混淆。水平型微指令采用控制字段直接表示微命令，不使用操作码/地址码格式。
- ④√：微指令类型（水平型或垂直型）在微程序控制器设计阶段确定，属于硬件设计决策，运行时一条微指令的类型是固定的。


### 5.

**答案**：①√ ②√ ③× ④√

**解析**：
- ①√：指令周期定义即为取出并执行一条指令所需的全部时间，通常划分为取指周期、间址周期、执行周期、中断周期等若干机器周期。
- ②√：间接寻址需要额外的访存操作来获取有效地址（再据此取操作数），相比直接寻址多了一次访存，执行时间更长。
- ③×：变长指令集（如x86）中不同长度的指令需要不同次数的访存才能完整取出，取指周期并非完全相同。"所有指令的取指周期时间完全相同"是过度概括的错误。即使在定长指令集中，取指周期相同仅是简化假设，并非普遍规律。
- ④√：机器周期通常以主存读/写周期为基准定义，因为访存是最频繁且最耗时的操作，以它为基准保证机器周期的合理性。

# 存储器字位同时扩展 — 求解过程

## 参数（来自题干）

| 参数 | 值 |
|------|-----|
| 目标总容量 C_target | 64KB = 65536 B = 2¹⁶ B |
| 目标存储字长 W_target | 16 位 |
| 芯片规格 | 8K × 4 位（N_chip = 8192，W_chip = 4）|

---

## 第 1 问（2 分）：地址线根数 与 数据线根数

**按字节编址**，总字节数 = 65536 = 2¹⁶。

**地址线根数**：

$$\text{地址线根数} = \lceil \log_2(65536) \rceil = 16 \text{ 根}$$

地址线由**存储器总容量**决定（覆盖全部存储字节）。

**数据线根数**：

$$\text{数据线根数} = \text{存储字长} = 16 \text{ 根}$$

数据线由**存储字长**决定，与芯片位宽无关。

> **答**：地址线 **16 根**，数据线 **16 根**。

---

## 第 2 问（4 分）：字扩展倍数、位扩展倍数、总芯片数

### ① 字扩展倍数（地址维度扩展）

字扩展解决"芯片地址单元数不够"的问题，用目标容量除以芯片单元数：

$$\text{字扩展倍数} = \frac{C_{target}}{N_{chip}} = \frac{65536}{8192} = 8$$

### ② 位扩展倍数（数据维度扩展）

位扩展解决"芯片位宽不够"的问题，用目标字长除以芯片位宽：

$$\text{位扩展倍数} = \frac{W_{target}}{W_{chip}} = \frac{16}{4} = 4$$

### ③ 总芯片数

总芯片数 = 字扩展倍数 × 位扩展倍数（**乘积关系**，因为字扩展组与位扩展组在两个独立维度上同时展开）：

$$\text{总芯片数} = 8 \times 4 = 32 \text{ 片}$$

> **答**：字扩展 **8** 倍，位扩展 **4** 倍，总共需要 **32** 片 8K×4 位的 RAM 芯片。

---

## 常见陷阱提示

| 错误类型 | 错误计算 | 错误结果 | 正确结果 |
|---------|---------|---------|---------|
| 字扩展 + 位扩展（相加） | 8 + 4 | 12 片 ❌ | 32 片 ✅ |
| 地址线由芯片单元数决定 | log₂(8192) = 13 | 13 根 ❌ | 16 根 ✅ |
| 数据线 = 芯片位宽 | 4 根 ❌ | — | 16 根 ✅ |

**核心要点**：
- 总芯片数是字扩展与位扩展的**乘积**（8×4=32），不是相加（8+4=12）。
- 地址线由**总容量**决定（log₂64KB = 16），数据线由**字长**决定（16），两者各自独立，不可混淆。

# 中断屏蔽字设计 —— 求解

## 参数

- 中断源：L₁、L₂、L₃、L₄、L₅（共 5 个）
- 响应优先级（高→低）：L₁ > L₂ > L₃ > L₄ > L₅
- 处理优先级（高→低）：L₃ > L₁ > L₂ > L₅ > L₄
- 对应处理优先级名次（rank 越小越高）：L₃=1, L₁=2, L₂=3, L₅=4, L₄=5
- 屏蔽位规则：$M_i = 1$ 屏蔽（禁止响应）$L_i$；$M_i = 0$ 允许响应 $L_i$
- 设置规则：处理优先级高于自身 → 位 = 0（允许）；不高于自身 → 位 = 1（屏蔽）；自身屏蔽位 = 1

---

## 问题 1：5×5 中断屏蔽字表

### 逐行推导

对每个中断源 $L_i$，逐一检查 $M_1$~$M_5$：

**L₁（处理优先级 rank=2，仅低于 L₃）：**
- M₁=1（自身屏蔽位）
- M₂=1（L₂ 处理优先级不高于 L₁，屏蔽）
- M₃=0（L₃ 处理优先级高于 L₁，允许）
- M₄=1（L₄ 处理优先级不高于 L₁，屏蔽）
- M₅=1（L₅ 处理优先级不高于 L₁，屏蔽）
- → **L₁：1 1 0 1 1**

**L₂（处理优先级 rank=3，低于 L₃ 和 L₁）：**
- M₁=0（L₁ 处理优先级高于 L₂，允许）
- M₂=1（自身屏蔽位）
- M₃=0（L₃ 处理优先级高于 L₂，允许）
- M₄=1（L₄ 处理优先级不高于 L₂，屏蔽）
- M₅=1（L₅ 处理优先级不高于 L₂，屏蔽）
- → **L₂：0 1 0 1 1**

**L₃（处理优先级 rank=1，最高，无更高者）：**
- M₁=1（L₁ 处理优先级不高于 L₃，屏蔽）
- M₂=1（L₂ 处理优先级不高于 L₃，屏蔽）
- M₃=1（自身屏蔽位）
- M₄=1（L₄ 处理优先级不高于 L₃，屏蔽）
- M₅=1（L₅ 处理优先级不高于 L₃，屏蔽）
- → **L₃：1 1 1 1 1**

**L₄（处理优先级 rank=5，最低，所有其他中断源均高于它）：**
- M₁=0（L₁ 处理优先级高于 L₄，允许）
- M₂=0（L₂ 处理优先级高于 L₄，允许）
- M₃=0（L₃ 处理优先级高于 L₄，允许）
- M₄=1（自身屏蔽位）
- M₅=0（L₅ 处理优先级高于 L₄，允许）
- → **L₄：0 0 0 1 0**

**L₅（处理优先级 rank=4，仅高于 L₄）：**
- M₁=0（L₁ 处理优先级高于 L₅，允许）
- M₂=0（L₂ 处理优先级高于 L₅，允许）
- M₃=0（L₃ 处理优先级高于 L₅，允许）
- M₄=1（L₄ 处理优先级不高于 L₅，屏蔽）
- M₅=1（自身屏蔽位）
- → **L₅：0 0 0 1 1**

### 完整屏蔽字表

| 中断源 | M₁ | M₂ | M₃ | M₄ | M₅ |
|--------|----|----|----|----|----|
| L₁     | 1  | 1  | 0  | 1  | 1  |
| L₂     | 0  | 1  | 0  | 1  | 1  |
| L₃     | 1  | 1  | 1  | 1  | 1  |
| L₄     | 0  | 0  | 0  | 1  | 0  |
| L₅     | 0  | 0  | 0  | 1  | 1  |

## 问题 2：中断处理顺序

### 到达时序

| 时刻  | 事件 |
|-------|------|
| t = 0 | L₄ 请求到达，CPU 响应并开始执行 L₄ |
| t = t₁| L₂ 请求到达 |
| t = t₂| L₁ 请求到达 |
| t = t₃| L₃ 请求到达 |

### 逐步分析

**t = 0：L₄ 请求到达**
- CPU 直接响应 L₄，开始执行 L₄ 的中断服务程序。
- 执行栈：L₄

**t = t₁：L₂ 请求到达**
- 当前正在执行 L₄，其屏蔽字为 **0 0 0 1 0**。
- 检查 M₂（L₂ 的屏蔽位）= **0**（允许）。
- L₂ 中断 L₄，开始执行。
- 执行栈：L₄ → L₂

**t = t₂：L₁ 请求到达**
- 当前正在执行 L₂，其屏蔽字为 **0 1 0 1 1**。
- 检查 M₁（L₁ 的屏蔽位）= **0**（允许）。
- L₁ 中断 L₂，开始执行。
- 执行栈：L₄ → L₂ → L₁

**t = t₃：L₃ 请求到达（关键陷阱）**
- 当前正在执行 L₁，其屏蔽字为 **1 1 0 1 1**。
- 检查 M₃（L₃ 的屏蔽位）= **0**（允许）。
- **关键**：L₃ 的响应优先级排第 3，低于当前正在执行的 L₁（响应优先级第 1）。按响应优先级判断，L₃ 不应中断 L₁。但 L₃ 的**处理优先级排第 1（最高）**，L₁ 的屏蔽字中 M₃=0（允许 L₃），因此 **L₃ 必须中断 L₁**。
- L₃ 中断 L₁，开始执行。
- 执行栈：L₄ → L₂ → L₁ → L₃

**逐层完成：**
- L₃ 是处理优先级最高的中断源（屏蔽字全 1），不会被任何中断打断。L₃ 执行完毕，返回到 L₁。
- L₁ 恢复执行后，剩余挂起的中断源中无更高处理优先级者（L₂、L₄ 均被 L₁ 的屏蔽字屏蔽），L₁ 执行完毕，返回到 L₂。
- L₂ 恢复执行，无更高处理优先级者被允许（L₄ 被 L₂ 屏蔽），L₂ 执行完毕，返回到 L₄。
- L₄ 执行完毕，返回 CPU。

### 结论

**执行（开始）顺序：L₄ → L₂ → L₁ → L₃**

**完成顺序：L₃ → L₁ → L₂ → L₄**

嵌套关系：L₃ 中断 L₁，L₁ 中断 L₂，L₂ 中断 L₄。

**判断依据**：每个新到达的中断请求是否中断当前正在执行的中断源，取决于当前执行中断源的屏蔽字中该请求对应位是否为 0（允许），而非响应优先级的高低。完成顺序按处理优先级从高到低：L₃（rank 1）→ L₁（rank 2）→ L₂（rank 3）→ L₄（rank 5），与屏蔽字表完全一致。

### 7.

**结束地址 = 起始地址 + 容量 − 1。**

### 区域①（ROM，4 KB，起始 0000H）

- 容量 = 4 KB = 4096 B = 0FFFH（容量减1后的偏移）
- 结束地址 = 0000H + 0FFFH = **0FFFH**
- **地址范围：0000H ～ 0FFFH**

### 区域②（RAM，8 KB，起始 4000H）

- 容量 = 8 KB = 8192 B = 1FFFH（容量减1后的偏移）
- 结束地址 = 4000H + 1FFFH = **5FFFH**
- **地址范围：4000H ～ 5FFFH**

### 验证

- ROM 结束地址（0FFFH）< RAM 起始地址（4000H），两区域不重叠。✅
- 0000H 是 4 KB 的整数倍，4000H 是 8 KB 的整数倍，地址对齐。✅
- 总容量 4 KB + 8 KB = 12 KB ≤ 64 KB（可寻址空间）。✅
