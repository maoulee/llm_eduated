## 一、单项选择题（5×2=10分）


### 1.

### 第一步：判断符号位

机器数 10110101 的**符号位（最高位）= 1**，因此该数为**负数**。

### 第二步：正确转换——负数补码求真值（取反加一法）

对负数补码，求真值的标准方法：**数值位取反，再加 1，取负号**。

```
补码机器数：10110101
```

**方法验证（位权法）**：

8 位补码的无符号整数值 raw = 181，真值 = raw − 256 = 181 − 256 = **−75**。

**取反加一法验证**：

- 按位取反：~10110101 = 01001010 = 74
- 加 1：74 + 1 = 75
- 取负号：**−75**

两种方法一致，正确真值为 **−75**。

| 选项 | 值 | 错误类型 | 说明 |

机器数 10110101 是 8 位补码负数。数值位取反得 01001010 = 74，加 1 得 75，所以真值为 **−75**。

## 二、判断题（5×2=10分）


### 1.

**答案**：①✓ ②✗ ③✓ ④✓ ⑤✗

**解析**：
- ① ✓：DRAM 的存储元是电容 + 一个 MOS 管（1T1C），电容存储的电荷会随时间自然泄漏，导致数据丢失，因此必须定期刷新来补充电荷。
- ② ✗：SRAM 的存储元是触发器（通常 6 个晶体管，6T 结构），只要不断电数据就能稳定保持，不需要刷新。这是 SRAM 与 DRAM 的根本区别之一。
- ③ ✓：DRAM 刷新以行为单位，刷新一行只需给出行地址并读出再写回（再生），占用一个刷新周期，无需列地址。刷新与正常的读/写操作类似但不输出数据。
- ④ ✓：SRAM 采用触发器存储，速度快但集成度低、功耗大、成本高，适合 Cache；DRAM 采用电容存储，集成度高、成本低但速度较慢，适合做主存。
- ⑤ ✗：DRAM 的刷新由刷新控制逻辑自动完成（可以是集中刷新、分散刷新或异步刷新），不需要 CPU 介入控制每一步。CPU 只是在集中刷新方式下可能需要等待（死区）。


### 2.

**答案**：①✓ ②✓ ③✗ ④✓ ⑤✓

**解析**：
- ① ✓：虚拟存储器的最大虚拟地址空间由 CPU 支持的虚拟地址位数决定，例如 32 位地址对应 4GB 虚拟地址空间。

- ③ ✗：虚拟地址空间和物理地址空间大小通常不同。虚拟地址空间由 CPU 地址位数决定，物理地址空间由实际内存容量决定，两者是独立的。例如 32 位系统中虚拟地址空间为 4GB，但物理内存可能只有 2GB。

- ⑤ ✓：虚拟存储器为每个进程提供独立的虚拟地址空间，不同进程的相同虚拟地址可以映射到不同的物理地址，实现进程间的地址空间隔离。


### 3.

**答案**：①✗ ②✓ ③✓ ④✓ ⑤✓

**解析**：
- ① ✗：链式查询方式中，离总线控制器物理位置最近的设备，其总线请求优先级**最高**（信号最先到达），离得越远优先级越低。
- ② ✓：计数器定时查询方式中，总线控制器内部有一个计数器，设备的编号与计数器值匹配时获得总线使用权。计数器初始值（从 0 开始递增或从上次的值继续）决定了设备的优先级顺序。
- ③ ✓：独立请求方式中每个设备有独立的请求线和允许线，总线控制器可以立即知道哪个设备发出请求并快速响应，因此响应速度最快，但控制线数与设备数成正比，线数最多。
- ④ ✓：链式查询方式只需 3 根控制线（总线请求、总线忙、总线允许），硬件简单，但固定优先级导致远离控制器的设备可能长期得不到总线使用权（"饿死"现象）。
- ⑤ ✓：独立请求方式的核心特征就是每个设备都有自己的请求线（BR）和允许线（BG），因此控制线数为 2N+1（N 个设备），远多于链式查询和计数器查询。


### 4.

**答案**：①✓ ②✗ ③✓ ④✓ ⑤✗

**解析**：
- ① ✓：DMA（直接存储器存取）方式的核心特征就是数据传输不需要 CPU 干预，由 DMA 控制器直接控制主存与外设之间的数据传输路径。
- ② ✗：DMA 传输时 CPU 不需要完全暂停。在周期挪用（周期窃取）方式中，DMA 控制器在 CPU 不使用总线时利用空闲周期传输数据，CPU 可以继续执行不需要总线的操作。只有当 CPU 和 DMA 同时需要总线时，DMA 才挪用一个或几个周期。
- ③ ✓：DMA 传送过程中，DMA 控制器向 CPU 发出总线请求（BR/HOLD），CPU 响应后释放总线控制权（BG/HLDA），由 DMA 控制器接管总线。传输结束后 DMA 控制器归还总线控制权。
- ④ ✓：DMA 方式的优势在于批量数据传输效率高、不占用 CPU 时间，因此特别适合磁盘、网卡等高速外设的大批量数据传输场景。低速设备的中断方式反而更高效。
- ⑤ ✗：DMA 方式下，整个数据块的传输由 DMA 控制器自动完成，不需要为每个数据执行中断服务程序。只有在整个数据块传输结束后，DMA 控制器才向 CPU 发出一次中断，通知 CPU 数据传输已完毕。每传送一个数据都中断 CPU 是程序中断方式的特征，不是 DMA。


### 5.

**答案**：①✓ ②✗ ③✓ ④✗ ⑤✗

**解析**：
- ① ✓：流水线的核心原理就是将指令执行过程分为多个阶段，使不同指令在同一时刻处于不同阶段，实现时间上的重叠执行，从而提高单位时间内完成的指令数（吞吐率）。
- ② ✗：引入流水线后，单条指令的执行时间不会缩短，甚至可能因为流水线寄存器的建立时间/锁存延迟而略有增加。流水线提高的是吞吐率（单位时间完成指令数），而非单条指令的延迟。
- ③ ✓：结构冲突（资源冲突，如多条指令争用同一部件）、数据冲突（后面指令依赖前面指令的结果）和控制冲突（分支指令改变执行流程）是流水线的三种基本冲突类型，是计算机组成原理中的标准分类。
- ④ ✗：数据旁路（转发）技术可以解决大多数 RAW（写后读）数据冲突，但不能解决所有数据冲突。例如 Load-Use 冒突（前一条是访存指令，后一条立即使用其结果）无法通过旁路完全消除，仍需要一个 stall（暂停）周期。
- ⑤ ✗：流水线的加速比不会随段数线性增长。根据 Amdahl 定律和流水线特性，随着段数增加，每段的执行时间减小但流水线寄存器开销（建立时间+锁存延迟）占比增大，且冲突带来的气泡增多，加速比的增长趋于平缓，存在一个最优段数。理论最大加速比趋近于流水线段数，但实际加速比远低于此。

# 求解：指令执行微操作序列与控制信号

## 指令字段解码

指令二进制：`0000 01 00 10000000`，存储地址 `0x2000`。

| 字段 | 位 | 编码 | 解码结果 |
|------|----|------|----------|
| 操作码 Opcode [15:12] | 4 位 | `0000` | LDA（R ← M[EA]） |
| 寻址方式 AM [11:10] | 2 位 | `01` | 间接寻址 |
| 寄存器 R [9:8] | 2 位 | `00` | R0 |
| 形式地址 A [7:0] | 8 位 | `10000000` | 0x0080 |

即 `LDA R0, (0x80)`。

## PC 增量分析

- 字长 16 位 = 2 字节，按字节编址。
- 16 位指令占 2 个字节 → PC 增量 = **PC + 2**。

---

## Q1：机器周期分析

**需经过的机器周期：取指周期 → 间址周期 → 执行周期（共 3 个周期）。包含间址周期。**

**理由：** 指令寻址方式字段 AM = `01` = **间接寻址**（依据 AM 字段编码值判断，而非助记符中的括号）。形式地址 A = 0x0080 指向的存储单元（地址 0x0080）中存放的不是操作数本身，而是有效地址指针（0x3000），因此需要额外的间址周期访存读取有效地址。

---

## Q2：完整微操作序列

### 取指周期（Fetch Cycle）— 4 条

| 序号 | 微操作 | 说明 |
|------|--------|------|
| 1 | `MAR ← PC` | 将指令地址送入 MAR |
| 2 | `MDR ← M[MAR]` | 从存储器读取指令字到 MDR |
| 3 | `PC ← PC + 2` | PC 增量（16 位指令 = 2 字节，按字节编址） |
| 4 | `IR ← MDR` | 指令送入 IR |

### 间址周期（Indirect Cycle）— 3 条

| 序号 | 微操作 | 说明 |
|------|--------|------|
| 5 | `MAR ← IR[7:0]` | 形式地址 A（=0x0080）送入 MAR |
| 6 | `MDR ← M[MAR]` | 从 0x0080 读出有效地址指针（0x3000）到 MDR |
| 7 | `MAR ← MDR` | 有效地址指针（0x3000）送入 MAR |

### 执行周期（Execute Cycle）— 2 条

| 序号 | 微操作 | 说明 |
|------|--------|------|
| 8 | `MDR ← M[MAR]` | 从有效地址 0x3000 读出操作数（0x1234）到 MDR |
| 9 | `R0 ← MDR` | 操作数写入目标寄存器 R0 |

**统计：** 取指 4 条 + 间址 3 条 + 执行 2 条 = **共 9 条**。

## Q3：控制信号一一对应

| 序号 | 微操作 | 周期 | 所需控制信号 |
|------|--------|------|-------------|

- 每个微操作至少有 1 条控制信号，共 9 个微操作、合计 22 条控制信号。

- 单总线结构中，每个数据传输路径需显式的输出控制信号（Xout）和打入控制信号（Xin）协同完成。

## 第 1 问（中断方式）

### 1) 中断请求次数与 CPU 总开销

- **中断请求次数** = B / u₁ = 4096 / 4 = **1024 次**

- 每次中断的 CPU 开销 = C_resp + C_isr = 30 + 200 = **230 周期**

- **中断方式总 CPU 开销** = 1024 × 230 = **235520 个时钟周期**

- 折合微秒：235520 × (1/500MHz) = 235520 × 0.002 μs = **471.04 μs**（≈ 0.4710 ms）

### 2) 总传送时间

从两个角度分析：

- **设备端产生数据角度**：全部数据产生时间 = B / R = 4096 / (2×10⁶) = 0.002048 s = **2.048 ms**，折算 = 1024000 个时钟周期

- **CPU 处理中断角度**：中断处理总时间 = 235520 个时钟周期 = **471.04 μs ≈ 0.4710 ms**

取较大者：max(2.048 ms, 0.4710 ms) = **2.048 ms**

> 由于设备速率较慢（2 MB/s），设备端产生 4096 B 数据需 2.048 ms，远大于 CPU 处理全部 1024 次中断的 0.4710 ms，因此**总传送时间 = 2.048 ms**，由设备端产生数据的速度决定。

---

## 第 2 问（DMA 周期挪用方式）

### 1) 周期挪用次数与 DMA CPU 开销

- **DMA 周期挪用次数** = B / u₂ = 4096 / 4 = **1024 次**

- DMA 预处理 + 后处理 = C_pre + C_post = 100 + 100 = **200 周期**

- 每次周期挪用窃取 1 个存储周期 = 1 个时钟周期，CPU 损失 = 1024 × 1 = **1024 周期**

- **DMA 总 CPU 开销** = 预处理(100) + 后处理(100) + 挪用损失(1024) = **1224 个时钟周期**

### 2) 总传送时间与 CPU 损失

- **DMA 总传送时间** = 设备端产生数据时间 = B / R = 4096 / (2×10⁶) = **2.048 ms**

  （DMA 方式下数据传送由设备速率决定，周期挪用仅在存储周期内完成，不额外延长传送时间）

- **CPU 损失（被挪用）总周期数** = 1024 × 1 = **1024 个时钟周期**

---

## 第 3 问（对比分析）

### 1) CPU 时间开销对比

| 方式 | 总 CPU 开销 |
|------|------------|
| 中断方式 | 235520 周期 |
| DMA 方式 | 1224 周期 |
| **差异** | 235520 − 1224 = **234296 个时钟周期**（约 192.4 倍） |

**DMA 周期挪用方式的 CPU 开销更小**，仅为中断方式的 1/192。

### 2) 为什么 DMA 周期挪用方式更适合

在大数据块（4 KB）、高速设备场景下，DMA 方式更适合的原因：

1. **中断方式 CPU 开销巨大**：每传送 4 B 就需要一次中断（响应 30 周期 + 服务程序 200 周期 = 230 周期），1024 次中断共需 235520 周期，CPU 大量时间被中断处理占用。

2. **DMA 方式 CPU 参与极少**：数据传送由 DMAC 硬件完成，CPU 仅需预处理(100 周期)、每次挪用损失 1 周期、后处理(100 周期)，总开销仅 1224 周期，CPU 可在绝大部分时间执行其他任务。

3. **周期挪用对 CPU 影响极小**：每次挪用仅窃取 1 个存储周期（1 个时钟周期），CPU 损失总计仅 1024 周期，远小于中断方式的 235520 周期，CPU 利用率大幅提升。

4. **大数据块时优势更明显**：数据块越大、传输单位越小，中断方式的中断次数越多、CPU 负担越重，而 DMA 方式的 CPU 开销几乎不随数据量增长（仅预处理和后处理固定开销 + 每字 1 周期挪用），因此数据量越大 DMA 优势越显著。
