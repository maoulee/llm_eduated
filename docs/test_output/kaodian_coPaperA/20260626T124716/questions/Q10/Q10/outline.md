## 考点
- **核心知识点：中断I/O方式的可行性判断**
  - 考察侧重点：中断服务程序执行时间与外设数据到达间隔之间的比较，判断设备能否采用中断I/O方式
- **辅助知识点：时钟周期与时间换算**
  - 考察侧重点：CPU主频→时钟周期→中断处理耗时的多级单位换算
- **辅助知识点：中断I/O方式的工作原理**
  - 考察侧重点：理解中断响应与中断服务程序的关系，以及中断开销在高速外设场景下的瓶颈效应

## 难度目标
- **K1=2（较低）**：需要记忆"时钟周期=1/主频""中断I/O方式需在中断服务时间内完成数据搬运"等基础概念，但概念本身不算冷门，题干引导性强
- **K2=4（较高）**：核心卡点在多级换算——主频→时钟周期、时钟周期数→中断服务时间、数据率→数据到达间隔，涉及非2幂次的除法与单位统一，易算错
- **K3=3（标准）**：需走完3-5步固定流程（换算主频→计算中断耗时→换算传输率→比较判断），路径唯一但步骤较多
- **K4=3（标准）**：存在隐含前提——中断I/O方式可行的条件是"中断服务时间 < 两个数据到达的间隔"，若忽略此前提或混淆方向则会得出相反结论
- **K5=2（较低）**：涉及CPU（主频、时钟周期）与外设（数据传输率）两个子系统，但为单向数据传递，无状态互影响

## 考察模式
**分析型——I/O方式性能计算与判断**

理由：这是中断I/O可行性分析的经典考察模式。给定CPU主频、中断服务程序所需时钟周期数和外设数据传输率，要求考生通过多步换算得出中断服务耗时，再与数据到达间隔比较，最终判断设备能否采用中断I/O方式。该模式同时覆盖了K2（多级换算）和K3（固定流程推演），且通过两种设备的数据率对比考察可行性判断的边界意识，与slot的difficulty_rationale一致。

## 出题要求
- **题型**：分析题（综合题）
- **总分**：10分
- **总条件数**：3-4个显式条件
  - 条件1：CPU主频（给定具体数值）
  - 条件2：某外设的数据传输率（给定具体数值）
  - 条件3：中断服务程序执行所需的时钟周期数（给定具体数值）
  - 条件4（可选）：第二个外设的数据传输率，用于对比分析
- **条件设计原则**：
  - 参数应能产生"一个设备可行、另一个不可行"的对比效果，体现可行性判断的区分度
  - CPU主频与中断服务时钟周期数的乘积应转化为可量化的毫秒/微秒级时间
  - 外设数据传输率应使得换算后的数据到达间隔与中断服务时间形成明确的"大于/小于"关系
- **参数取值范围要求**：
  - CPU主频：数百MHz量级（如100-500MHz），使时钟周期为纳秒级
  - 中断服务时钟周期数：数百至数千周期
  - 外设数据传输率：覆盖KB/s级（慢速设备）和MB/s级（快速设备），使两种设备的中断可行性结论不同

## 子问题规划
- **第1问（计算题，约3分）**：计算CPU时钟周期及中断服务程序的一次执行时间
  - 考察目标：时钟周期与主频的换算，时钟周期数到实际时间的转换
  - 关系：为后续问提供基础数据
- **第2问（计算+分析题，约4分）**：计算外设A的数据到达间隔，与中断服务时间比较，判断能否采用中断I/O方式
  - 考察目标：数据传输率到数据到达间隔的换算，可行性判断条件的应用
  - 关系：依赖第1问的中断服务时间结果
- **第3问（分析题，约3分）**：对外设B（更高数据传输率）进行同样的可行性分析，或讨论在什么条件下中断I/O方式不再适用
  - 考察目标：边界判断能力，理解中断I/O方式的适用范围限制
  - 关系：与第2问并列对比，深化对可行性边界的理解

## 参数约束
- **CPU主频 f**：取值范围 100MHz-500MHz，要求能整除为简洁的时钟周期值
- **中断服务时钟周期数 N**：取值范围 200-2000 cycles
- **外设A数据传输率 R_A**：取值范围 1-50 KB/s，使得数据到达间隔 > 中断服务时间（设备A可行）
- **外设B数据传输率 R_B**：取值范围 0.5-5 MB/s，使得数据到达间隔 < 中断服务时间（设备B不可行）
- **一致性约束**：
  - 中断服务时间 T_ISR = N / f
  - 数据到达间隔 T_arrival = 1 / R（或按字节/字粒度换算）
  - A设备：T_arrival_A > T_ISR（中断I/O可行）
  - B设备：T_arrival_B < T_ISR（中断I/O不可行）
  - 参数选择需保证两种结论有明显差距，而非临界值

## 参考经验
- **考察模式**：中断I/O可行性分析是CO-7的经典综合题型，核心逻辑为"计算中断服务耗时 → 比较数据到达间隔 → 判断可行性"
- **难度锚点**：K2=4为主导难度，多级单位换算（Hz→s、B/s→间隔、cycles→s）是区分度核心
- **典型陷阱**：
  - 混淆数据到达间隔与数据传输率的方向（间隔 = 1/传输率的字节粒度，而非比特粒度）
  - 忽略中断服务时间包含中断响应开销，仅计算服务程序执行部分（本题可简化处理，仅给服务程序周期数）
  - 对"可行"的判断条件方向搞反（服务时间 < 到达间隔 才可行）
