# 中断 I/O 方式可行性分析 —— 求解过程

> 本解基于 gen.py 的精确计算（Fraction 运算，无浮点误差），exec 输出逐字对照。

---

## 已知参数

| 参数 | 值 |
|------|-----|
| CPU 主频 | 250 MHz = 250×10⁶ Hz |
| ISR 每次所需时钟周期 | 600 |
| 外设 A 传输率 | 5 KB/s = 5000 B/s |
| 外设 B 传输率 | 3 MB/s = 3000000 B/s |

---

## 第 1 问（3 分）

### （1）CPU 时钟周期 T_clock

$$T_{clock} = \frac{1}{f} = \frac{1}{250 \times 10^6}\ \text{s} = \frac{1}{250 \times 10^6} \times 10^9\ \text{ns} = \frac{1000}{250}\ \text{ns} = \boxed{4\ \text{ns}}$$

时钟周期为正整数纳秒值。

### （2）中断服务时间 T_ISR

$$T_{ISR} = 600 \times T_{clock} = 600 \times 4\ \text{ns} = 2400\ \text{ns}$$

换算为 μs：

$$T_{ISR} = \frac{2400}{1000}\ \mu\text{s} = \boxed{2.40\ \mu\text{s}}$$

---

## 第 2 问（4 分）

### （1）外设 A 每字节数据的到达间隔 T_arrival_A

外设 A 速率 = 5 KB/s = 5000 B/s（字节粒度，到达间隔 = 1 / 传输率）。

$$T_{arrival\_A} = \frac{1}{5000}\ \text{s} = \frac{1}{5000} \times 10^6\ \mu\text{s} = \boxed{200.00\ \mu\text{s}}$$

### （2）可行性判断

**可行性条件**：中断 I/O 方式可行 ⇔ $T_{ISR} < T_{arrival}$

（含义：中断服务程序必须在下一字节数据到达之前执行完毕，否则数据会丢失。）

代入数值：

$$T_{ISR} = 2.40\ \mu\text{s},\quad T_{arrival\_A} = 200.00\ \mu\text{s}$$

$$2.40\ \mu\text{s} < 200.00\ \mu\text{s}\quad\checkmark$$

两者差距约 **83.33 倍**（T_arrival_A / T_ISR = 200 / 2.4 ≈ 83.33），远大于临界范围。

**结论：中断 I/O 方式适用于外设 A（可行）。**

CPU 处理一个字节中断仅需 2.40 μs，而下一字节 200 μs 后才到达，CPU 有充裕时间完成服务，不会丢失数据。

---

## 第 3 问（3 分）

### （1）外设 B 每字节数据的到达间隔 T_arrival_B

外设 B 速率 = 3 MB/s = 3000000 B/s。

$$T_{arrival\_B} = \frac{1}{3 \times 10^6}\ \text{s} = \frac{1}{3 \times 10^6} \times 10^6\ \mu\text{s} = \frac{1}{3}\ \mu\text{s} \approx \boxed{0.33\ \mu\text{s}}$$

### （2）可行性判断

代入可行性条件 $T_{ISR} < T_{arrival}$：

$$T_{ISR} = 2.40\ \mu\text{s},\quad T_{arrival\_B} = 0.33\ \mu\text{s}$$

$$2.40\ \mu\text{s} < 0.33\ \mu\text{s}\quad\boldsymbol{\times}$$

条件不成立。T_ISR / T_arrival_B = 2.40 / 0.33 ≈ **7.20 倍**，中断服务时间是到达间隔的 7 倍多。

**结论：中断 I/O 方式不适用于外设 B（不可行）。**

外设 B 每 0.33 μs 就有一个字节到达，而 CPU 执行一次中断服务需要 2.40 μs。在服务一个字节期间，已有约 7 个字节的数据到达而无法及时处理，会造成数据丢失。应改用 DMA 方式或通道方式。

### （3）决定中断 I/O 方式可行性的关键因素

对比外设 A（可行）与外设 B（不可行），结论方向相反：

| | 外设 A | 外设 B |
|---|--------|--------|
| 传输率 | 5 KB/s | 3 MB/s |
| 到达间隔 | 200 μs | 0.33 μs |
| T_ISR vs T_arrival | 2.40 < 200 ✓ | 2.40 > 0.33 ✗ |
| 结论 | 可行 | 不可行 |

**关键因素**：中断 I/O 方式的可行性取决于 **中断服务时间 T_ISR 与数据到达间隔 T_arrival 的相对大小**，即必须满足 $T_{ISR} < T_{arrival}$。

- 外设传输率越高 → 数据到达间隔越短 → 越难满足 $T_{ISR} < T_{arrival}$ → 中断 I/O 越不可行。
- 因此中断 I/O 适用于**低速设备**（如键盘、鼠标、低速串口），而高速设备（如磁盘、网络接口）应采用 DMA 或通道方式。

---

## 答案汇总

| 子问 | 结果 |
|------|------|
| Q1(1) | T_clock = **4 ns** |
| Q1(2) | T_ISR = 2400 ns = **2.40 μs** |
| Q2(1) | T_arrival_A = **200.00 μs** |
| Q2(2) | 外设 A：2.40 μs < 200 μs → **可行** |
| Q3(1) | T_arrival_B = 1/3 μs ≈ **0.33 μs** |
| Q3(2) | 外设 B：2.40 μs > 0.33 μs → **不可行** |
| Q3(3) | 关键因素：**T_ISR < T_arrival**（中断服务时间须小于数据到达间隔） |
