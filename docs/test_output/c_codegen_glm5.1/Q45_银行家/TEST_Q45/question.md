# Q45 银行家算法——资源分配与安全性推演

## 题目

某系统中有 5 个进程 P0~P4 和 3 类资源 A、B、C，系统采用银行家算法进行死锁避免。当前时刻系统的资源分配状态如下表所示：

| 进程 | Max(A,B,C) | Allocation(A,B,C) |
|------|------------|-------------------|
| P0   | (5, 5, 5)  | (2, 1, 2)         |
| P1   | (3, 2, 2)  | (1, 0, 0)         |
| P2   | (4, 0, 2)  | (2, 0, 2)         |
| P3   | (2, 2, 2)  | (2, 1, 1)         |
| P4   | (4, 3, 3)  | (0, 0, 2)         |

当前可用资源向量 Available = (3, 3, 2)。

请回答以下问题：

（1）进程 P1 发出资源请求 Request1 = (1, 0, 2)，系统是否可以满足该请求？若可以，请给出一个安全序列；若不可以，请说明理由。

（2）在问题（1）的请求被满足后，进程 P4 发出资源请求 Request2 = (3, 3, 0)，系统是否可以满足该请求？请说明理由。

（3）有人说"系统处于不安全状态就一定会发生死锁"，这种说法是否正确？请简述理由。

---

## 设计说明

| 维度 | 说明 |
|------|------|
| 考点 | 银行家算法——资源请求审批与安全性检查 |
| K3 机制推演 | 设问(1)需完成"三步检查 + 五步安全性算法"，全程维护动态 Work 向量 |
| K4 条件路由 | 设问(2)考察 Request ≤ Available 的第二步检查（A 资源 3 > 可用 2，请求被拒）；设问(3)考察安全状态与死锁状态的隐含关系辨析 |
| 难度定位 | 4/5——多步推演 + 条件路由混合 |
