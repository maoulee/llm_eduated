## 题目
在 C 语言中，`short` 类型占 16 位，`unsigned short` 类型同样占 16 位。有以下代码：

```c
short s = -100;
unsigned short u = (unsigned short)s;
printf("%u\n", u);
```

已知 `short` 采用补码表示，`unsigned short` 的取值范围为 0 ～ 65535。执行上述代码后，`printf` 输出的 `u` 的十进制值是多少？


## 选项
A. 65436
B. −100
C. 100
D. 65336


## 求解过程
# solution.md

## 答案

**A. 65436**

## 解题过程

### 1. 参数（PARAMS）

| 参数 | 值 |
|------|-----|
| short 位数 WIDTH | 16 |
| 模 MOD = 2^16 | 65536 |
| short 变量初值 S | −100 |
| abs(S) | 100 |

### 2. 核心建模（PROCESS）

**步骤 1 — 求 S 的 16 位补码位模式**

`short` 采用补码表示，S = −100 的 16 位补码位模式为：

$$\text{bits} = S \bmod 2^{16} = (-100) \bmod 65536 = 65436$$

二进制表示：`1111 1111 1001 1100`

**步骤 2 — 同宽度转换 = 位模式重解读**

`short` → `unsigned short` 是 16 位 → 16 位转换，**位模式完全不变**，仅按无符号语义重新解读。因此：

$$u = \text{bits} = 65436$$

**步骤 3 — 验证公式**

负数 S（S < 0）的 16 位补码位模式按无符号解读的数值满足：

$$U = 2^{16} + S = 65536 + (-100) = 65436$$

与步骤 2 的结果一致。

### 3. 结果（RESULT）

$$\boxed{u = 65436}$$

`printf("%u\n", u)` 输出 **65436**。

### 4. 场景规则验证（RULE_CHECK）

| 规则 | 验证 | 结果 |
|------|------|------|
| 规则1：位模式不变 | bits(S) = 65436, u = 65436 | 相同 ✓ |
| 规则2：U == MOD + S | u = 65436, MOD + S = 65436 | 相等 ✓ |

### 5. 选项分析（OPTIONS）

| 选项 | 实际标的值 | 正误 | 说明 |
|------|-----------|------|------|
| **A** | **65436** | ✅ 正确 | 位模式重解读，U = 65536 + (−100) = 65436 |
| B | −100 | ❌ | 忽略 unsigned 语义，直接保留原负值，未做位模式重解读 |
| C | 100 | ❌ | 误取绝对值，误以为转换仅去掉符号位 |
| D | 65336 | ❌ | 错误补码公式 65536 − 2×100 = 65336，多减了一次 |S| |

**四选项互异**：A=65436、B=−100、C=100、D=65336，四个值各不相同，无碰撞。

## 关键知识点

- **同宽度有符号→无符号转换**是**位模式重解读**，不是数值运算：16 位补码位模式原样保留，仅按无符号语义读取。
- 负数 S 的 16 位补码位模式按无符号解读：**U = 65536 + S**。
- `%u` 以无符号十进制输出，结果落在 0 ～ 65535 范围内。
