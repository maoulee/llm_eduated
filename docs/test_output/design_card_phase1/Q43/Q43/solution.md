## 求解过程

### 子问题(1)：R1和R2的真值转换

**R1 = 0001H**
- 二进制：`0000 0000 0000 0001`
- 有符号整数（补码）：最高位为0，为正数，真值 = +1
- 无符号整数：真值 = 1

**R2 = 7FFFH**
- 二进制：`0111 1111 1111 1111`
- 有符号整数（补码）：最高位为0，为正数，真值 = 2^15 - 1 = 32767
- 无符号整数：真值 = 2^15 - 1 = 32767

### 子问题(2)：R3、R4、R5的十六进制内容及CF/OF标志位

**运算1：R3 = R1 + R2 = 0001H + 7FFFH**

```
  0000 0000 0000 0001  (R1 = 0001H)
+ 0111 1111 1111 1111  (R2 = 7FFFH)
-------------------
  1000 0000 0000 0000  (R3 = 8000H)
```

- **R3 = 8000H**
- **CF（进位标志）**：第15位（最高位）无进位输出 → CF = 0
- **OF（溢出标志）**：第15位进位输入 = 1（低15位相加产生进位），第15位进位输出 = 0 → OF = 1 ⊕ 0 = 1

**运算2：R4 = R3 + R2 = 8000H + 7FFFH**

```
  1000 0000 0000 0000  (R3 = 8000H)
+ 0111 1111 1111 1111  (R2 = 7FFFH)
-------------------
  1111 1111 1111 1111  (R4 = FFFFH)
```

- **R4 = FFFFH**
- **CF**：第15位无进位输出 → CF = 0
- **OF**：第15位进位输入 = 0（低15位：000...000 + 111...111 = 111...111，无进位），第15位进位输出 = 0 → OF = 0 ⊕ 0 = 0

**运算3：R5 = R4 + R2 = FFFFH + 7FFFH**

```
  1111 1111 1111 1111  (R4 = FFFFH)
+ 0111 1111 1111 1111  (R2 = 7FFFH)
-------------------
1 0000 0000 0000 0000  (进位输出)
  0111 1111 1111 1110  (R5 = 7FFEH)
```

- **R5 = 7FFEH**
- **CF**：第15位有进位输出 → CF = 1
- **OF**：第15位进位输入 = 1（低15位：111...111 + 111...111 = 111...110，进位为1），第15位进位输出 = 1 → OF = 1 ⊕ 1 = 0

**汇总：**

| 寄存器 | 十六进制 | CF | OF |
|--------|----------|----|----|
| R3 | 8000H | 0 | 1 |
| R4 | FFFFH | 0 | 0 |
| R5 | 7FFEH | 1 | 0 |

### 子问题(3)：溢出判断

**有符号整数溢出判断（依据OF标志位）：**

- **R3：OF = 1 → 溢出**
  - 判断依据：1 + 32767 = 32768，超出16位有符号整数范围[-32768, 32767]。两个正数相加结果为负数（8000H解释为-32768），符号异常。

- **R4：OF = 0 → 不溢出**
  - 判断依据：-32768 + 32767 = -1，在范围[-32768, 32767]内。一正一负相加，不可能溢出。

- **R5：OF = 0 → 不溢出**
  - 判断依据：-1 + 32767 = 32766，在范围[-32768, 32767]内。一正一负相加，不可能溢出。

**无符号整数溢出判断（依据CF标志位）：**

- **R3：CF = 0 → 不溢出**
  - 判断依据：1 + 32767 = 32768，在16位无符号整数范围[0, 65535]内。

- **R4：CF = 0 → 不溢出**
  - 判断依据：32768 + 32767 = 65535，在范围[0, 65535]内（恰好等于最大值）。

- **R5：CF = 1 → 溢出**
  - 判断依据：65535 + 32767 = 98302，超出16位无符号整数范围[0, 65535]。

**关键观察：** 同一位模式在不同语义解释下溢出状态不同。例如R3（8000H）：有符号解释下溢出（OF=1），无符号解释下不溢出（CF=0）；R5（7FFEH）：有符号解释下不溢出（OF=0），无符号解释下溢出（CF=1）。

### 子问题(4)：同一加法器电路执行有符号/无符号加法的原因

计算机内部可以使用同一个加法器电路执行有符号整数加法和无符号整数加法，原因如下：

1. **位级运算的同一性**：加法器电路在硬件层面仅执行二进制位的逐位加法操作（含进位链传递），不感知也不区分操作数的语义类型（有符号或无符号）。对于相同的两个位模式输入，无论解释为有符号补码还是无符号数，加法器产生的位模式结果完全相同。

2. **溢出标志的硬件独立性**：CF（进位标志）和OF（溢出标志）均由加法器的进位链状态直接产生——CF取自最高位的进位输出，OF取自最高位进位输入与进位输出的异或。这两个标志位的生成是纯硬件行为，与操作数的语义解释无关。

3. **语义解释的软件层职责**：有符号溢出和无符号溢出的判断差异完全由软件层决定——编译器/程序员根据数据类型选择检查OF还是CF。硬件只需同时提供两个标志位，由上层语义决定使用哪一个。

4. **补码设计的数学基础**：补码表示法使得有符号整数加法在模2^n意义下与无符号整数加法具有相同的位级运算规则，这是同一电路可复用的数学保证。

## 最终答案

**(1) R1和R2的真值：**
- R1 = 0001H：有符号整数 = 1，无符号整数 = 1
- R2 = 7FFFH：有符号整数 = 32767，无符号整数 = 32767

**(2) R3、R4、R5的十六进制内容及CF/OF：**
- R3 = 8000H，CF = 0，OF = 1
- R4 = FFFFH，CF = 0，OF = 0
- R5 = 7FFEH，CF = 1，OF = 0

**(3) 溢出判断：**
- 有符号整数：R3溢出（OF=1），R4不溢出（OF=0），R5不溢出（OF=0）
- 无符号整数：R3不溢出（CF=0），R4不溢出（CF=0），R5溢出（CF=1）
- 判断依据：有符号溢出看OF标志位（最高位进位输入⊕进位输出），无符号溢出看CF标志位（最高位进位输出）

**(4) 同一加法器电路的原因：**
加法器在硬件层面仅执行二进制位级加法，不感知操作数的语义类型；CF和OF标志位由进位链状态独立产生；有符号/无符号的语义解释差异由软件层通过检查不同标志位来解决；补码表示法在数学上保证了两种解释下位级运算规则的一致性。
