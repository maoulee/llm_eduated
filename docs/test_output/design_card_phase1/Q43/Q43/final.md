## 题目

某计算机字长为16位，带符号整数采用补码表示。已知两个16位寄存器R1和R2的初始内容分别为：
- R1 = 0001H
- R2 = 7FFFH

执行以下运算序列：
1. R3 = R1 + R2
2. R4 = R3 + R2
3. R5 = R4 + R2

请回答下列问题：

### (1) （2分）
将R1和R2的内容分别解释为有符号整数和无符号整数，写出对应的十进制真值。

### (2) （3分）
写出R3、R4、R5的十六进制内容，并说明每次运算后CF和OF标志位的值。

### (3) （3分）
基于(2)的结果，分别判断：若将R1、R2解释为有符号整数，R3、R4、R5中哪些运算结果发生了溢出？若解释为无符号整数，哪些发生了溢出？说明判断依据。

### (4) （2分）
基于(2)和(3)的分析，说明计算机内部为何可以使用同一个加法器电路执行有符号整数加法和无符号整数加法。

---

## 子问题

(1) R1和R2的真值转换（2分）
(2) R3、R4、R5的十六进制内容及CF/OF标志位（3分）
(3) 有符号/无符号溢出判断及依据（3分）
(4) 同一加法器电路复用原因（2分）

---

## 求解过程

### (1) R1和R2的真值转换

**R1 = 0001H**
- 二进制：`0000 0000 0000 0001`
- 有符号整数（补码）：最高位为0，为正数，真值 = +1
- 无符号整数：真值 = 1

**R2 = 7FFFH**
- 二进制：`0111 1111 1111 1111`
- 有符号整数（补码）：最高位为0，为正数，真值 = 2^15 - 1 = 32767
- 无符号整数：真值 = 2^15 - 1 = 32767

### (2) R3、R4、R5的十六进制内容及CF/OF标志位

**运算1：R3 = R1 + R2 = 0001H + 7FFFH**
```
  0000 0000 0000 0001  (R1 = 0001H)
+ 0111 1111 1111 1111  (R2 = 7FFFH)
-------------------
  1000 0000 0000 0000  (R3 = 8000H)
```
- R3 = 8000H，CF = 0（最高位无进位输出），OF = 1（最高位进位输入1 ⊕ 进位输出0 = 1）

**运算2：R4 = R3 + R2 = 8000H + 7FFFH**
```
  1000 0000 0000 0000  (R3 = 8000H)
+ 0111 1111 1111 1111  (R2 = 7FFFH)
-------------------
  1111 1111 1111 1111  (R4 = FFFFH)
```
- R4 = FFFFH，CF = 0，OF = 0（最高位进位输入0 ⊕ 进位输出0 = 0）

**运算3：R5 = R4 + R2 = FFFFH + 7FFFH**
```
  1111 1111 1111 1111  (R4 = FFFFH)
+ 0111 1111 1111 1111  (R2 = 7FFFH)
-------------------
1 0000 0000 0000 0000  (进位输出)
  0111 1111 1111 1110  (R5 = 7FFEH)
```
- R5 = 7FFEH，CF = 1（最高位有进位输出），OF = 0（最高位进位输入1 ⊕ 进位输出1 = 0）

### (3) 溢出判断

**有符号整数溢出（依据OF）：**
- R3：OF = 1 → 溢出（1 + 32767 = 32768，超出[-32768, 32767]）
- R4：OF = 0 → 不溢出（-32768 + 32767 = -1，在范围内）
- R5：OF = 0 → 不溢出（-1 + 32767 = 32766，在范围内）

**无符号整数溢出（依据CF）：**
- R3：CF = 0 → 不溢出（1 + 32767 = 32768，在[0, 65535]内）
- R4：CF = 0 → 不溢出（32768 + 32767 = 65535，在范围内）
- R5：CF = 1 → 溢出（65535 + 32767 = 98302，超出[0, 65535]）

### (4) 同一加法器电路复用原因

1. **位级运算同一性**：加法器仅执行二进制位级加法，不感知操作数的语义类型；相同位模式输入产生相同位模式输出。
2. **溢出标志硬件独立**：CF（最高位进位输出）和OF（最高位进位输入⊕进位输出）由进位链状态直接产生，与语义无关。
3. **语义解释由软件层决定**：编译器/程序员根据数据类型选择检查OF还是CF。
4. **补码的数学基础**：补码表示法使有符号加法在模2^n意义下与无符号加法具有相同的位级运算规则。

---

## 答案

**(1)** R1 = 0001H：有符号 = 1，无符号 = 1；R2 = 7FFFH：有符号 = 32767，无符号 = 32767

**(2)** R3 = 8000H（CF=0, OF=1）；R4 = FFFFH（CF=0, OF=0）；R5 = 7FFEH（CF=1, OF=0）

**(3)** 有符号溢出：R3溢出；无符号溢出：R5溢出。判断依据：有符号看OF（最高位进位输入⊕进位输出），无符号看CF（最高位进位输出）。

**(4)** 加法器在硬件层面仅执行二进制位级加法，不感知语义类型；CF和OF由进位链状态独立产生；语义解释差异由软件层通过检查不同标志位解决；补码表示法在模2^n意义下保证了两种解释的位级运算规则一致。

---

## 设计说明

**考察模式**：底层机制语义推演（Low-Level Mechanism Semantics Deduction）

**知识点**：补码加减运算、无符号数与有符号数的表示、溢出判断（CF/OF）、ALU基本功能

**核心陷阱**：
1. 混淆OF与CF的溢出判断规则
2. 误以为溢出后结果"不可用"
3. 误以为硬件加法器能区分有符号/无符号语义

**参数设计**：R1=0001H（种子值）、R2=7FFFH（16位有符号正数最大值），三次连续加法形成溢出/不溢出交替模式，R3有符号溢出但无符号不溢出，R5无符号溢出但有符号不溢出，形成鲜明对比。
