# Q43 综合应用题

某计算机字长为16位，带符号整数采用补码表示。已知两个16位寄存器R1和R2的初始内容分别为：
- R1 = 0001H
- R2 = 7FFFH

执行以下运算序列：
1. R3 = R1 + R2
2. R4 = R3 + R2
3. R5 = R4 + R2

请回答下列问题：

### (1) （2分）
将R1和R2的内容分别解释为有符号整数和无符号整数，写出对应的十进制真值。

### (2) （3分）
写出R3、R4、R5的十六进制内容，并说明每次运算后CF和OF标志位的值。

### (3) （3分）
基于(2)的结果，分别判断：若将R1、R2解释为有符号整数，R3、R4、R5中哪些运算结果发生了溢出？若解释为无符号整数，哪些发生了溢出？说明判断依据。

### (4) （2分）
基于(2)和(3)的分析，说明计算机内部为何可以使用同一个加法器电路执行有符号整数加法和无符号整数加法。

---

## 设计说明

### 考察结构模式
选用模式B：**底层机制语义推演 (Low-Level Mechanism Semantics Deduction)**（来自经验卡）

- **第一步（数据表示转换）**：子问题(1)要求将十六进制位模式分别解释为有符号整数和无符号整数，考察补码表示与真值转换。
- **第二步（硬件操作模拟）**：子问题(2)要求模拟三次连续加法运算，跟踪寄存器内容和CF/OF标志位状态变化。
- **第三步（语义解释与边界分析）**：子问题(3)要求将同一位模式结果分别代入有符号和无符号语义模型，判断溢出情况；子问题(4)要求从硬件本质层面解释"同一电路复用"的原因。

### 子问依赖关系

| 子问题 | 依赖 | 说明 |
|--------|------|------|
| (1) | 无（题干条件） | 基础参数计算：十六进制→十进制真值转换 |
| (2) | 无（题干条件） | 核心过程模拟：三次连续加法+标志位跟踪 |
| (3) | (2)的输出 | 语义解释：基于(2)的位模式结果判断有符号/无符号溢出 |
| (4) | (2)和(3)的分析 | 机制本质理解：基于标志位差异解释硬件复用原理 |

### should_be对照

1. **给定高级语言代码或特定数据，推演底层表示、运算过程及最终状态**：✓ 给定寄存器初始位模式，推演三次加法运算的位模式结果和标志位状态。
2. **重点考察"表示"与"语义"的差异**：✓ 同一位模式（如8000H）在有符号解释下为-32768（溢出结果），在无符号解释下为32768（正常结果），形成鲜明对比。
3. **数据表示转换→硬件操作模拟→语义解释与边界分析**：✓ 三个步骤完整覆盖，子问(1)→(2)→(3)→(4)形成递进链。

### should_not_be排查

1. **混淆有符号数与无符号数的溢出判断规则（OF vs CF）**：✓ 本题核心陷阱正是此点，R3运算OF=1（有符号溢出）但CF=0（无符号不溢出），R5运算CF=1（无符号溢出）但OF=0（有符号不溢出）。
2. **误以为硬件加法器能区分数据语义**：✓ 子问题(4)直接考察此本质理解。
3. **忽略循环变量溢出的副作用**：本题不涉及循环，但通过连续三次加法体现了溢出后继续运算的状态累积效应。

### 知识点选取理由

- **补码加减运算**：核心考点，覆盖补码加法、溢出判断（单符号位判溢出）。
- **无符号数与有符号数的表示**：同一位模式的不同语义解释。
- **溢出判断（CF/OF）**：进位标志与溢出标志的区别与应用场景。
- **ALU基本功能**：加法器电路的语义无关性。

### 参数选择理由

- **16位字长**：比8位更贴近实际系统，比32位更便于手工计算。
- **R1 = 0001H（十进制1）**：小正数，有符号/无符号解释一致，作为"种子"值。
- **R2 = 7FFFH（有符号32767，无符号32767）**：16位有符号正数最大值，是关键参数。
  - 第一次加法：1 + 32767 = 32768，恰好超出16位有符号正数范围（-32768~32767），触发有符号溢出。
  - 后续加法在补码环上继续推进，形成有趣的溢出/不溢出交替模式。
- **连续三次加法**：形成串行依赖链，R3→R4→R5，每次运算依赖前一次结果，符合综合题"连续推演"特征。

### 与契约 K 值的对齐说明

- **K1=3~5（目标3-4）**：需准确记忆补码表示规则、CF/OF标志位定义、溢出判断方法。需辨析"有符号溢出"与"无符号溢出"两个易混概念，K1≈4。
- **K2=2（目标2）**：计算为16位十六进制加法，数字友好（0001H和7FFFH均为规整值），K2≈2。
- **K3=4（目标4）**：需维持动态状态更新——三次连续加法，每次需跟踪寄存器内容和两个标志位，推演步数>5步，K3≈4。
- **K4=4~5（目标4）**：隐含前提深——同一位模式在不同语义下的溢出状态不同（R3有符号溢出但无符号不溢出，R5无符号溢出但有符号不溢出），需理解"硬件加法器不区分语义"这一本质，K4≈4。
- **K5=3（目标3）**：两系统单向拼接——将"软件层面的数据类型（有符号/无符号）"映射到"硬件层面的标志位（OF/CF）"和"位模式解释"，K5≈3。

### 典型陷阱设计

1. **OF与CF混淆**：学生可能用OF判断无符号溢出，或用CF判断有符号溢出。
2. **溢出即错误**：学生可能认为溢出后结果"不可用"，而忽略补码环上结果在模运算意义下的正确性。
3. **硬件区分语义**：学生可能认为加法器"知道"自己在做有符号还是无符号加法。
