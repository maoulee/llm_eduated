## 考点
- **循环队列基本结构**：数组存储、front/rear 指针含义、maxsize 容量定义
- **判空条件**：front == rear 时队列为空
- **判满条件**：(rear + 1) % maxsize == front（牺牲一个存储单元法）
- **入队操作**：判满 → 存入元素 → rear = (rear + 1) % maxsize
- **出队操作**：判空 → 取出元素 → front = (front + 1) % maxsize
- **考察侧重点**：代码补全，要求准确填写判满/判空条件、指针更新语句

## 难度目标
- **K1=2（较低）**：需掌握循环队列基础名词（front/rear/maxsize），但概念模糊也能顺着代码框架推断
- **K2=3（标准）**：需代入取模运算理解指针更新逻辑，涉及 (rear+1)%maxsize 这类非平凡表达式
- **K3=2（较低）**：入队/出队流程为 2-3 步固定流程（判条件→操作→更新指针），路径唯一
- **K4=2（较低）**：存在常规注意点（如判满需牺牲一个单元、取模运算），408 考生基本不会踩坑
- **K5=1（微弱）**：单一知识点内部解决，不涉及其他数据结构或系统

## 考察模式
**代码补全型——循环队列操作实现**

理由：参考 2011_Q3 和 2014_Q3 历史经验，该题位固定采用代码填空形式，考查循环队列核心操作的代码实现。此模式能直接检验学生对判满/判空条件、指针更新规则的理解，且填空位置可精准控制考察深度。

## 出题要求
- **题型**：综合题（代码填空）
- **分值**：5 分
- **填空数量**：3-5 个空，每个空 1-2 分
- **条件设计原则**：给出完整的循环队列结构定义和函数框架，仅将关键语句替换为下划线
- **参数取值范围要求**：
  - 队列容量 maxsize：建议 10-100 范围内的整数（非 2 的幂，增加取模运算的非平凡性）
  - 初始状态：可为空队列或含少量元素
  - 操作序列：入队和出队操作的组合

## 子问题规划
本题为代码填空型综合题，不设传统子问题，而是通过多个填空位置构成考察单元：

| 填空位置 | 考察目标 | 建议分值 | 依赖关系 |
|---------|---------|---------|---------|
| 空1 | 判满条件（或判空条件） | 1-2 分 | 独立 |
| 空2 | rear/front 指针更新语句 | 1-2 分 | 独立 |
| 空3 | 元素存入/取出操作 | 1 分 | 独立 |
| 空4（可选） | 另一操作的判条件或指针更新 | 1 分 | 独立 |

**说明**：各填空位置相互独立，学生可分别作答。建议覆盖入队和出队两个操作，或深入考查单一操作的关键步骤。

## 参数约束
- **maxsize（队列容量）**：取值范围 [10, 100]，建议非 2 的幂（如 13、17、23），使取模运算结果非平凡
- **front 初始值**：通常为 0
- **rear 初始值**：通常为 0（空队列时 front == rear）
- **元素类型**：可为 int、char 等基础类型
- **一致性约束**：
  - 判满条件必须与判空条件兼容（牺牲一个单元法：(rear+1)%maxsize == front 为满，front == rear 为空）
  - 指针更新必须使用取模运算：(rear+1)%maxsize 或 (front+1)%maxsize
  - 函数框架中的变量名需与填空处一致

## 参考经验
- **历史模式**：2011_Q3 和 2014_Q3 均为循环队列代码填空，考查入队/出队操作的完整实现
- **难度锚点**：K2 为主导维度（取模运算理解），K3 较低（流程固定），整体难度 3
- **典型陷阱**：
  - 判满条件写成 rear == maxsize - 1（未考虑循环）
  - 指针更新忘记取模：rear = rear + 1
  - 判空/判满条件混淆
  - front/rear 更新方向搞反
