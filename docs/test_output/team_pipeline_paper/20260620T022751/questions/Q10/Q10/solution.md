## 干扰项分析

### 选项 B：指针移动方向错误

错误规则：i++ 直到 A[i] ≤ pivot，j-- 直到 A[j] ≥ pivot（与正确规则相反）

**第一趟（pivot=45）：**
- i=0, a[0]=45 ≤ 45 ✓；j=5, a[5]=34 ≥ 45？否 → j=4, a[4]=89 ≥ 45 ✓；交换 → `[89, 23, 67, 12, 45, 34]`
- i=1, a[1]=23 ≤ 45 ✓；j=3, a[3]=12 ≥ 45？否 → j=2, a[2]=67 ≥ 45 ✓；交换 → `[89, 67, 23, 12, 45, 34]`
- i=2, a[2]=23 ≤ 45 ✓；j=1, a[1]=67 ≥ 45 ✓；i≥j，返回 j=1

第一趟后：`[89, 67, 23, 12, 45, 34]`，j=1

**第二趟左子数组（low=0, high=1, pivot=89）：**
- i=0, a[0]=89 ≤ 89 ✓；j=1, a[1]=67 ≥ 89？否 → j=0, a[0]=89 ≥ 89 ✓；i≥j，返回 j=0

**第二趟右子数组（low=2, high=5, pivot=23）：**
- i=2, a[2]=23 ≤ 23 ✓；j=5, a[5]=34 ≥ 23 ✓；交换 → `[89, 67, 34, 12, 45, 23]`
- i=3, a[3]=12 ≤ 23 ✓；j=4, a[4]=45 ≥ 23 ✓；交换 → `[89, 67, 34, 45, 12, 23]`
- i=4, a[4]=12 ≤ 23 ✓；j=3, a[3]=45 ≥ 23 ✓；i≥j，返回 j=3

**选项 B 结果：** `[89, 67, 34, 45, 12, 23]`

> **错误原因：** 指针移动方向与正确规则相反，导致大元素被移到左侧、小元素被移到右侧，完全颠倒了 partition 的排序方向。

### 选项 C：只做了第一趟

第一趟 Hoare partition 结果：`[34, 23, 12, 67, 89, 45]`

**选项 C 结果：** `[34, 23, 12, 67, 89, 45]`

> **错误原因：** 遗漏了第二趟对左右子数组的 partition 操作。题目明确要求做两趟，只完成一趟属于过程不完整。

### 选项 D：误用 Lomuto 方案

Lomuto 方案：pivot 选最后一个元素，i=low-1，遍历 j 从 low 到 high-1。

**第一趟（pivot=a[5]=34）：**
- i=-1
- j=0: a[0]=45 ≤ 34？否
- j=1: a[1]=23 ≤ 34？是 → i=0, 交换 a[0]↔a[1] → `[23, 45, 67, 12, 89, 34]`
- j=2: a[2]=67 ≤ 34？否
- j=3: a[3]=12 ≤ 34？是 → i=1, 交换 a[1]↔a[3] → `[23, 12, 67, 45, 89, 34]`
- j=4: a[4]=89 ≤ 34？否
- 最后交换 a[i+1]↔a[high] → a[2]↔a[5] → `[23, 12, 34, 45, 89, 67]`
- 返回 p=2

第一趟后：`[23, 12, 34, 45, 89, 67]`，p=2

**第二趟左子数组（low=0, high=1, pivot=a[1]=12）：**
- i=-1
- j=0: a[0]=23 ≤ 12？否
- 最后交换 a[0]↔a[1] → `[12, 23, 34, 45, 89, 67]`
- 返回 p_left=0

**第二趟右子数组（low=3, high=5, pivot=a[5]=67）：**
- i=2
- j=3: a[3]=45 ≤ 67？是 → i=3, 交换 a[3]↔a[3]（自交换）→ `[12, 23, 34, 45, 89, 67]`
- j=4: a[4]=89 ≤ 67？否
- 最后交换 a[4]↔a[5] → `[12, 23, 34, 45, 67, 89]`
- 返回 p_right=4

**选项 D 结果：** `[12, 23, 34, 45, 67, 89]`

> **错误原因：** Lomuto 方案与 Hoare 方案在 pivot 选择（最后一个 vs 第一个）、扫描方式（单向遍历 vs 双向扫描）上完全不同，导致 partition 结果不同。值得注意的是，Lomuto 方案在此例中恰好产生了完全有序的结果，但这只是巧合，不代表 Lomuto 方案等价于 Hoare 方案。
