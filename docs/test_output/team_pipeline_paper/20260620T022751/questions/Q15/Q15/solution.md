# 循环队列入队操作代码填空 - 解析

## 答案

| 填空编号 | 答案 |
|---------|------|
| ① | `(Q->rear + 1) % MAXSIZE == Q->front` |
| ③ | `(Q->rear + 1) % MAXSIZE` |
| ④ | `1` |

> 注：填空②在题干中已给出 `Q->data[Q->rear] = e;`，无需填写。

---

## 解析

### 填空①：判满条件

**答案**：`(Q->rear + 1) % MAXSIZE == Q->front`

**解析**：
- 循环队列采用**少用一个存储单元**的策略来区分队空和队满。
- 队空条件：`front == rear`
- 队满条件：`(rear + 1) % MAXSIZE == front`
- 当队尾指针的下一个位置（取模后）等于队头指针时，说明队列已满，不能再入队。
- 此时返回 `0` 表示入队失败。

### 填空③：更新队尾指针

**答案**：`(Q->rear + 1) % MAXSIZE`

**解析**：
- 元素入队后，队尾指针需要向后移动一位。
- 由于是**循环队列**，当 `rear` 到达数组末尾（`MAXSIZE - 1`）时，下一个位置应回到 `0`。
- 使用取模运算 `(Q->rear + 1) % MAXSIZE` 可以保证 `rear` 始终在 `[0, MAXSIZE-1]` 范围内循环。
- 本题中 `MAXSIZE = 7`（非 2 的幂），取模运算不会退化为位运算，能真实考察取模逻辑。

### 填空④：返回成功标志

**答案**：`1`

**解析**：
- 元素成功入队后，返回 `1` 表示操作成功。
- 与填空①中队列满时返回 `0` 形成对比，符合题目要求的返回值约定。

---

## 关键设计要点

### 1. 少用一个单元策略
- 牺牲一个存储单元来区分队空和队满，避免 `front == rear` 时无法判断是空还是满。
- 实际可用空间为 `MAXSIZE - 1 = 6` 个单元。

### 2. 判满与更新策略一致
- 判满条件使用 `(rear + 1) % MAXSIZE == front`
- 更新语句使用 `rear = (rear + 1) % MAXSIZE`
- 两者都使用相同的取模策略，逻辑一致无矛盾。

### 3. 取模运算的必要性
- `MAXSIZE = 7` 不是 2 的幂，因此 `% MAXSIZE` 不能简化为 `& (MAXSIZE - 1)`。
- 这确保了题目真实考察取模运算，而非位运算的退化情况。
