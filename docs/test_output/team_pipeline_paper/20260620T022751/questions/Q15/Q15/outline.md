## 考点
- **循环队列判满条件**：考察 `(rear + 1) % MAXSIZE == front` 的理解，区分"少用一个存储单元"的判满策略
- **循环队列判空条件**：考察 `rear == front` 的理解
- **rear/front 更新操作**：考察 `(rear + 1) % MAXSIZE` 和 `(front + 1) % MAXSIZE` 的取模运算逻辑
- **入队/出队操作完整性**：考察操作前判满/判空、操作后指针更新的完整流程

## 难度目标
- **K1=2（较低）**：需掌握循环队列基础名词（front/rear/MAXSIZE），但代码框架已给出，概念模糊也能顺着填
- **K2=3（标准）**：需正确代入取模运算公式，涉及非平凡取模计算（如 rear+1 后取模）
- **K3=2（较低）**：每个填空点仅需 1-2 步推导（如"判满→写条件"或"更新→写取模"），路径唯一
- **K4=2（较低）**：存在常规注意点（如判满用 rear+1 而非 rear，判空用 rear==front），408 考生基本不会踩坑
- **K5=1（微弱）**：纯循环队列内部操作，不涉及其他数据结构或系统

## 出题要求
- **题型**：综合题（代码填空）
- **总条件数**：3-4 个填空点
- **条件设计原则**：
  - 每个空考察一个独立知识点（判满/判空/更新/返回）
  - 填空点之间无强依赖，可独立作答
  - 代码框架完整，仅关键语句留空
- **参数取值范围要求**：
  - MAXSIZE：取 5-10 之间的值（不宜过大，便于验证；不宜过小，避免退化）
  - 初始状态：front=rear=0（标准初始化）

## 子问题规划
本题为代码填空题，不设传统子问题，而是按填空点划分考察维度：

| 填空点 | 类型 | 考察目标 | 分值 | 说明 |
|--------|------|----------|------|------|
| 空① | 条件判断 | 判满/判空条件 | 1-1.5分 | 考察 `(rear+1)%MAXSIZE==front` 或 `rear==front` |
| 空② | 赋值语句 | 元素插入/删除 | 1-1.5分 | 考察 `data[rear]=x` 或 `x=data[front]` |
| 空③ | 指针更新 | rear/front 更新 | 1-1.5分 | 考察 `(rear+1)%MAXSIZE` 或 `(front+1)%MAXSIZE` |
| 空④（可选） | 返回值 | 操作结果返回 | 0.5-1分 | 考察 return true/false 或 return x |

**依赖关系**：填空点之间弱依赖（代码逻辑上串行，但每个空可独立推导）

## 参数约束
- **MAXSIZE**：取值范围 [5, 10]，整数，不宜为 2 的幂（避免取模退化）
- **front 初始值**：固定为 0
- **rear 初始值**：固定为 0
- **操作类型**：入队（EnQueue）或出队（DeQueue）二选一
- **填空数量**：3-4 个空
- **一致性约束**：
  - 若考察入队，填空点应覆盖：判满→插入→更新 rear→返回
  - 若考察出队，填空点应覆盖：判空→取值→更新 front→返回
  - 判满条件必须使用 `(rear+1)%MAXSIZE==front`（少用一个单元策略）

## 参考经验
- **历史模式**：2011_Q3、2014_Q3 均为循环队列代码填空，考察入队/出队操作
- **难度锚点**：K2 为主导维度（取模运算代入），K1/K3/K4 均为较低水平
- **典型陷阱**：
  - 判满写成 `rear==front`（与判空混淆）
  - 更新写成 `rear++`（忘记取模）
  - 判满写成 `rear==MAXSIZE-1`（未考虑循环）
  - 更新写成 `rear=(rear+1)%MAXSIZE` 但判满用 `rear==front`（策略不一致）
