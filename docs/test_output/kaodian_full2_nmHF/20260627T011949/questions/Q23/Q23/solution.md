# 水平型微指令格式设计与控存容量计算 —— 求解过程

## 第 1 问（5 分）：操作控制字段格式设计

采用**字段直接编码**，每个互斥类对应一个操作控制字段。每字段需额外预留 1 个**不操作码**（全 0），因此字段位数公式为：

$$\text{字段位数} = \lceil \log_2(\text{组内微命令数} + 1) \rceil$$

| 字段 | 对应互斥类 | 微命令数 | +1（不操作码） | 字段位数 | 计算依据 |
|------|-----------|---------|--------------|---------|---------|
| F₁（数据通路控制字段） | 第一类 | 5 | 6 | **3** | ⌈log₂6⌉ = ⌈2.585⌉ = 3 |
| F₂（ALU 运算控制字段） | 第二类 | 7 | 8 | **3** | ⌈log₂8⌉ = ⌈3.000⌉ = 3 |
| F₃（存储器控制字段） | 第三类 | 3 | 4 | **2** | ⌈log₂4⌉ = ⌈2.000⌉ = 2 |
| F₄（寄存器读写控制字段） | 第四类 | 4 | 5 | **3** | ⌈log₂5⌉ = ⌈2.322⌉ = 3 |
| F₅（状态标志控制字段） | 第五类 | 3 | 4 | **2** | ⌈log₂4⌉ = ⌈2.000⌉ = 2 |

操作控制字段格式（从高位到低位排列）：

```
| F₁(3位) | F₂(3位) | F₃(2位) | F₄(3位) | F₅(2位) |
```

**操作控制字段总位数** = 3 + 3 + 2 + 3 + 2 = **13 位**

## 第 2 问（3 分）：微指令字长与控存最大容量

### 微指令字长

微指令字长由三部分组成：

| 组成部分 | 计算过程 | 位数 |
|---------|---------|------|
| 操作控制字段 | 3 + 3 + 2 + 3 + 2 | 13 位 |
| 判别测试字段（P 字段） | 题目给定 | 2 位 |
| 下址字段 | ⌈log₂256⌉ = ⌈8.0⌉ = 8 | 8 位 |

下址字段位数计算依据：下址法中下址字段宽度由控存中微指令条数决定。控存放 256 条微指令，地址范围为 0~255，需 ⌈log₂256⌉ = 8 位地址。

**微指令字长** = 13 + 2 + 8 = **23 位**

### 控存最大容量

$$\text{控存最大容量} = \text{微指令条数} \times \text{微指令字长} = 256 \times 23 = \boxed{5888 \text{ 位}}$$

## 第 3 问（2 分）：不操作码的必要性

**预留不操作码的原因：**

字段直接编码中，每个字段对应一个互斥类。在实际执行微指令时，并非每个字段都需要发出微命令——某个互斥类在当前微周期可能**不需要任何微命令**（即不操作）。因此必须为每个字段预留一个编码（通常为全 0 码，即"不操作码"），用来表示"该字段不发出任何微命令"。

**7 个微命令仅用 3 位编码、不预留不操作码的问题：**

7 个微命令恰好可以用 3 位编码（2³ = 8 ≥ 7），编码空间刚够容纳 7 个微命令。但如果不预留不操作码，3 位编码的所有 8 种组合中，除去 7 个微命令只剩 1 个空闲编码。这会导致：

- **无法区分"不操作"状态**：当该字段在某一微周期不需要发出任何微命令时，3 位编码已全部用于微命令，无法用一个合法编码表示"不操作"。这将使得该互斥类在任何微指令中都**被迫发出一个微命令**，无法处于空闲状态，导致微指令设计错误。

因此，7 个微命令的字段应使用 ⌈log₂(7+1)⌉ = 3 位（8 种编码 = 7 个微命令 + 1 个不操作码），全 0 码保留为不操作码。
