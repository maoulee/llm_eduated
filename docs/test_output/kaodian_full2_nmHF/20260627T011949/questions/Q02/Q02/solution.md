# 解题过程：IEEE 754 单精度浮点加法运算结果判断

> 以下所有数值均逐字对照 gen.py exec 输出（PARAMS / OPTION A-D / 场景规则验证）转写，不重算。

---

## 一、参数解析

| 参数 | 值 |
|------|-----|
| 操作数 A | `0x41266666` → float = 10.399999618530273 |
| 操作数 B | `0x3F8CCCCC` → float = 1.0999999046325684 |
| A + B（Python 精确参考） | 11.499999523162842 |
| A + B（Python float hex） | `0x41380000` |

### 分解各操作数（exec OPTION A 数据）

| 字段 | 操作数 A | 操作数 B |
|------|---------|---------|
| 符号位 | 0 | 0 |
| 阶码字段（8 位） | 130 | 127 |
| 真值指数（阶码 − 127） | 3 | 0 |
| 24 位完整尾数（含隐含 1） | `101001100110011001100110` | `100011001100110011001100` |

- 两操作数阶码差 ediff = true_exp_a − true_exp_b = 3 − 0 = **3**，满足 ∈ [2, 5]。
- 对阶方向：小阶向大阶看齐 → B 的尾数右移 3 位。

## 二、选项 A：正确流程（对阶 → 尾数运算 → 规格化 → 舍入 → 再规格化）

### 步骤 1：对阶

B 的尾数右移 3 位，A 的尾数左移 3 位对齐到 27 位扩展位宽：

- man_a_shifted = `101001100110011001100110000`（27 位）
- man_b（24 位原值，放在 27 位低 24 位）

### 步骤 2：尾数运算（相加）

- sum_ext = man_a_shifted + man_b = `101101111111111111111111100`（27 位）
- sum_ext_width = 27

### 步骤 3：截取 24 位 + 舍入判定

- sum_24（高 24 位）= `101101111111111111111111`
- low_bits（低 3 位，被移出）= `100`（十进制 4）
- half（舍入阈值）= 1 << (3−1) = **4**
- lsb_24（sum_24 最低位）= **1**
- **舍入判定**（round to nearest even）：low_bits == half（4 == 4）且 lsb_24 == 1 → 向偶数舍入 → **round_up = True**
- sum_rounded = sum_24 + 1 = `101110000000000000000000`

### 步骤 4：再规格化检查

- sum_rounded = `101110000000000000000000`（24 位，最高位为 1，未超过 24 位）→ **right_norm = False**（不需要右规）
- result_exp = true_exp_a = 3（不 +1）

### 步骤 5：组装结果

- result_sign = 0
- result_exp_field = 3 + 127 = **130**
- result_mant（低 23 位）= `01110000000000000000000`
- result_bits = `01000001001110000000000000000000`

**选项 A = `0x41380000`** ✓

## 三、选项 B：对阶方向错误（大阶向小阶对齐）

**错误类型**：将对阶方向颠倒——A 左移 ediff 位（大阶向小阶对齐），以 B 的指数（0）作为公共指数。

- man_a_wrong_shifted = `101001100110011001100110000`（A 左移 3 位）
- sum_wrong = `101101111111111111111111100`
- common_exp = 0（B 的指数）
- 舍入后 sum_rounded = `101110000000000000000000`
- 在 common_exp = 0 下规格化 → 最终阶码字段与正确流程完全不同

**选项 B = `0x3FB80000`**

**为什么错**：IEEE 754 规定对阶只能"小阶向大阶看齐"（小阶尾数右移），不能大阶向小阶对齐（左移会导致高位丢失或需不合理扩展），用错误的公共指数组装出完全不同的结果。

---

## 四、选项 C：忽略隐含位（尾数按 0.xxxx 处理）

**错误类型**：不补前导隐含 1，将 24 位有效尾数 1.xxxx 误当作 23 位纯小数 0.xxxx 处理。

- man_a_wrong（23 位）= `01001100110011001100110`
- man_b_wrong（23 位）= `00011001100110011001100`
- sum_ext = `01001111111111111111111100`（26 位）
- 舍入后 sum_rounded = `10100000000000000000000`（23 位）
- 规格化后 common_exp = 2（比正确值偏小，因为尾数规模缩小导致左规）

**选项 C = `0x40D00000`**

**为什么错**：规格化 IEEE 754 数的有效尾数为 1.xxxx（隐含前导 1，共 24 位有效位），忽略隐含位使尾数少了一位整数位，运算结果数量级和编码均错误。

---

## 五、选项 D：不执行舍入（truncation，直接丢弃移出低位）

**错误类型**：执行对阶、尾数运算后，直接截断丢弃对阶时移出的低位（truncation / 向零截断），不采用 round to nearest even 规则修正。

- sum_ext = `101101111111111111111111100`（与正确流程相同）
- sum_24_truncated = `101101111111111111111111`（高 24 位，不 +1）
- low_bits_dropped = `100`（被丢弃的低位，十进制 4）
- round_up_correct = True（正确流程应舍入进位，但 D 不执行）
- sum_trunc = `101101111111111111111111`（保持截断值，不加 1）
- 不需要右规，result_exp_field = 130
- result_mant = `01101111111111111111111`

**选项 D = `0x4137FFFF`**

**为什么错**：移出位 `100` 恰好等于半值（half=4）且 sum_24 末位为 1（奇数），按 round to nearest even 应向上舍入到偶数（+1）。D 直接截断导致尾数末段为 `…11111111111111111111111`（全 1）而非正确的 `…10000000000000000000000`，结果少了 1 ULP。

---

## 六、最终答案

| 选项 | 十六进制值 | 描述 | 判定 |
|------|-----------|------|------|
| **A** | **`0x41380000`** | 正确结果 | ✅ **正确** |
| B | `0x3FB80000` | 对阶方向错误 | ❌ |
| C | `0x40D00000` | 忽略隐含位 | ❌ |
| D | `0x4137FFFF` | 不执行舍入（truncation） | ❌ |

**答案：A（`0x41380000`）**
