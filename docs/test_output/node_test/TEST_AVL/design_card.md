## core_knowledge_intent
- must_test:
  - 单链表结点结构的 C/C++ 定义
  - 快慢指针（Floyd判圈算法）的核心机制：快指针步长为2，慢指针步长为1
  - 环检测的终止条件：快指针为空或快指针的next为空（无环），或快慢指针相遇（有环）
  - 算法的时间复杂度 $O(n)$ 和空间复杂度 $O(1)$ 分析
- must_not_shift_to:
  - 不得偏移至使用额外空间（如哈希集合）的判环方法作为主要解法
  - 不得偏移至寻找环入口点的算法（除非作为扩展，但本题核心是判断有无）
  - 不得偏移至双链表或循环链表的特定操作
- coverage_success_criteria:
  - 学生能正确定义链表结点结构
  - 学生能清晰描述快慢指针的移动规则及相遇含义
  - 学生能编写出处理边界条件（空表、无环）的正确代码
  - 学生能准确分析时空复杂度

## design_rationale
- 考察意图：
  - 本题旨在考察学生对单链表底层指针操作的理解以及经典算法（Floyd判圈算法）的设计能力。
  - 难度定位为4，要求学生不仅记忆算法步骤，还要理解其背后的逻辑：为什么快慢指针在有环时必然相遇？为什么需要检查快指针的next是否为空？
  - 通过“定义-思想-代码”的三段式结构，全面评估学生的工程实现能力和理论分析能力。
- 区分度：
  - 低水平学生：可能无法正确处理边界条件（如空链表），或混淆快慢指针的步长。
  - 中等水平学生：能写出基本逻辑，但可能遗漏对 `fast->next` 的空指针检查，导致运行时错误。
  - 高水平学生：能严谨处理所有边界，代码简洁，注释清晰，复杂度分析准确。
- 考点融合：
  - 本题不涉及跨考点融合，但融合了“指针操作”与“算法复杂度分析”两个维度。
  - 在算法思想描述中，隐含考察对“时间换空间”策略的理解（相比哈希表法）。

## question_structure_plan
- 复用骨架来源：
  - 参考往年综合题常见结构：如“单链表逆置”、“单链表合并”等题目，通常要求：①定义结构 ②描述算法 ③编写代码。
  - 具体句式参考：
    - “设线性表 L 采用带头结点的单链表保存... 请设计算法..."
    -I have to give the solution based on the reasoning directly now.</think>... 要求：① 定义链表结点数据类型；② 描述算法基本设计思想；③ 编写算法（关键处给注释）”
- 子问1：定义链表结点数据类型（基础层）
  - 考察点：struct 定义，data 域与 next 指针域
  - 参考往年问法：“定义链表结点数据类型”
- 子问2：描述算法基本设计思想（进阶层）
  - 考察点：快慢指针初始化、移动规则、相遇判断、无环判断
  - 参考往年问法：“描述算法基本设计思想”
- 子问3：编写算法代码（区分度层）
  - 考察点：C/C++ 语法、指针操作、边界条件处理、注释
  - 参考往年问法：“编写算法（关键处给注释）”
- dependency_pattern：串行依赖（先定义结构，再描述思想，最后实现代码）

## terminology_and_expression_constraints
- 必须用词：
  - “快指针”、“慢指针”
  - “步长”、“相遇”
  - “时间复杂度”、“空间复杂度”
  - “空指针”、“边界条件”
- 限定语：
  - 算法思想描述需简洁明了，避免冗长代码式描述
  - 代码注释需针对关键逻辑（如循环条件、指针移动）
- 禁止表述：
  - 不得使用“哈希表”、“集合”等额外空间数据结构作为主要解法
  - 不得省略对空链表或无环链表的处理

## audit_focus
- 审核重点：
  - 结点定义是否完整（包含 data 和 next）
  - 算法思想是否清晰描述了快慢指针的移动规则和终止条件
  - 代码是否正确处理了 `fast == NULL` 和 `fast->next == NULL` 的情况
  - 代码是否包含必要的注释
  - 复杂度分析是否准确（时间 $O(n)$，空间 $O(1)$）
- 排除项：
  - 排除使用额外空间的解法
  - 排除寻找环入口点的扩展算法（除非作为额外加分项，但本题不要求）
