# 指令流水线性能与冒险分析（综合题，10分）

## 题干

某 RISC 处理器采用 **5 级指令流水线**，各级名称及功能如下：

| 级 | 名称 | 功能 |
|----|------|------|
| IF | 取指 | 从存储器取指令 |
| ID | 译码 / 读寄存器 | 指令译码，从寄存器堆读源操作数 |
| EX | 执行 | ALU 运算、地址计算 |
| MEM | 访存 | Load 读存储器 / Store 写存储器 |
| WB | 写回 | 将结果写入寄存器堆 |

各级段时间如下（同一时钟信号驱动所有级，时钟周期取各级最长时间）：

- IF = **300 ps**，ID = **200 ps**，EX = **500 ps**，MEM = **400 ps**，WB = **200 ps**

**寄存器堆内部约定：** WB 级在时钟周期前半段写入寄存器堆，ID 级在后半段读寄存器堆。因此，若写回与读出发生在同一时钟周期，读出的是新写入的值。

现有一段由 4 条指令组成的程序依次执行（按给定顺序进入流水线）：

| 编号 | 指令 | 功能说明 |
|------|------|----------|
| I1 | `LW R1, 0(R2)` | R1 ← Mem[R2]，从存储器加载到 R1 |
| I2 | `ADD R3, R1, R4` | R3 ← R1 + R4 |
| I3 | `SUB R5, R3, R6` | R5 ← R3 − R6 |
| I4 | `SW R5, 8(R2)` | Mem[R2+8] ← R5，将 R5 存入存储器 |

**转发（Forwarding）条件：**
- **ALU→ALU 转发：** 当前指令 EX 级所需源操作数，可由上一条指令的 EX/MEM 流水线寄存器直接转发（即 EX/MEM → EX），无需停顿。
- **Load-use 转发：** Load 指令的数据在 MEM 级末尾才可用，通过 MEM/WB 流水线寄存器转发到后续指令的 EX 级。但由于数据在 MEM 级结束时才就绪，紧接 Load 的指令仍需插入 **1 个停顿周期（bubble）**。

## 问题

### 第（1）题（2分）
该流水线的时钟周期（操作周期）为多少 ps？写出计算依据。

### 第（2）题（3分）
假设流水线**无冒险**（ideal pipeline），计算：
- （a）4 条指令全部执行完毕所需的总时间（ps）；
- （b）该流水线相对于**非流水线**执行方式的**加速比 S**（非流水线方式下，每条指令串行完成全部 5 级，取各级时间之和）；
- （c）流水线的**吞吐率**（单位：指令/ns，保留两位小数）。

### 第（3）题（2分）
分析上述 4 条指令序列中存在的**数据冒险**（data hazard）：
- 逐对指出哪些指令之间存在数据相关，并说明相关寄存器；
- 判断每对相关的具体类型（如 Load-use 相关、一般 RAW 相关等）；
- 说明在按序流水线中，该序列是否存在 WAR 或 WAW 冒险，并简述理由。

### 第（4）题（3分）
分别计算以下两种情况下的**总停顿周期数**和**实际执行总周期数**：

- （a）**无转发**机制时：依赖指令必须等到产生结果的指令完成 WB 级后，才能在 ID 级读到正确值。计算全部数据冒险引起的总停顿周期数及实际执行总周期数。
- （b）**有转发**机制时（条件如上述转发约定）：计算全部数据冒险引起的总停顿周期数及实际执行总周期数。

> 要求：列出每对相关指令导致的停顿周期，再汇总。

## 场景规则（本题成立 ⇔ 以下参数间约束被满足）

以下约束与具体答案值无关，换参数仍成立，供 gen.py `assert` 检验：

### 规则 R1：时钟周期定义
```
clock_cycle == max(IF, ID, EX, MEM, WB)
```
流水线时钟周期等于各段时间的最大值。

### 规则 R2：非流水线执行时间
```
non_pipeline_time == L * (IF + ID + EX + MEM + WB)
```
其中 L 为指令条数（本题为 4）。非流水线方式每条指令串行完成全部 5 级。

### 规则 R3：理想流水线执行时间
```
ideal_pipeline_time == (n + L - 1) * clock_cycle
```
其中 n 为流水线级数（本题为 5），L 为指令条数。

### 规则 R4：加速比定义
```
speedup == non_pipeline_time / ideal_pipeline_time
```
加速比 = 非流水线时间 / 理想流水线时间，须满足 S > 1 且 S 为非整数。

### 规则 R5：吞吐率定义
```
throughput == L / ideal_pipeline_time   （单位：条/ps，结果可换算为条/ns）
```

### 规则 R6：无转发停顿计算
每对 RAW 相关（producer → consumer），consumer 在 ID 级检测到 hazard 后停顿，直到 producer 的 WB 级完成后方可读寄存器：
```
stall_no_fwd_per_pair = max(0, WB_cycle(producer) - ID_cycle(consumer_original))
```
- `WB_cycle(producer)`：producer 原始调度中的 WB 周期号
- `ID_cycle(consumer_original)`：consumer 在无任何停顿时的 ID 周期号

实际执行总周期 = 理想周期 + 总停顿周期。**总停顿周期须 ≥ 2。**

### 规则 R7：有转发停顿计算
- **Load-use 相关对**（producer 为 Load）：需插入 **1** 个停顿周期。
- **一般 ALU→ALU 相关对**（producer 为非 Load 指令）：通过 EX/MEM → EX 转发，**0** 个停顿周期。

实际执行总周期 = 理想周期 + 总停顿周期。**Load-use 残留停顿须 ≥ 1。**

### 规则 R8：数据完整性约束
```
实际执行总周期 == 理想周期(n+L-1) + 总停顿周期
```
无论有无转发，实际总周期必须等于理想周期与停顿周期之和（时序自洽）。
