## 考点
- **Booth算法（补码一位乘）**：核心考点。要求考生完整执行 Booth 算法迭代流程，包括判断位识别、部分积加/减/移位操作、乘数与附加位的同步移位。
  - 考察侧重点：判断位规则（y_i y_{i-1} = 00→移位，01→加x→移位，10→减x→移位，11→移位）、部分积累加精度、符号位自然参与运算。
- **补码小数表示**：辅助考点。考生需将十进制小数或真值转换为补码小数表示，确定数值位数与符号位。
- **双符号位部分积**：辅助考点。Booth 算法中部分积采用变形补码（双符号位）参与运算，考生需正确处理符号位扩展。

## 难度目标
- **K1=2**（较低）：需知道 Booth 算法判断位规则和补码表示，属于标准核心概念，但规则给定后即可执行，不需要辨析易混概念。
- **K2=3**（标准）：每趟迭代涉及加法/减法运算，数值非2的幂次友好数，存在单步算错可能。
- **K3=4**（较高）：核心维度。需执行 n+1 趟迭代（n为数值位数），每趟需判断→运算→移位三步，步数>5步且需动态维护部分积和乘数两个寄存器的状态更新。
- **K4=2**（较低）：主要注意点为"最后一趟只判断不加减只移位"以及"双符号位参与运算"，属常规注意点。
- **K5=1**（微弱）：单一知识点内部解决，不涉及跨子系统。

## 考察模式
**推演型——Booth算法逐步计算**
- 与 slot 指定的 examination_mode 一致。
- 要求考生列表展示每趟迭代的判断位、操作、部分积、乘数（含附加位）的完整变化过程。
- 最终给出乘积的补码表示和真值。
- 此模式直接测出 K3（多步串行推演能力），是期末/考研核心算法题的标准考法。

## 出题要求
- **题型**：主观题（应用题），总分8分。
- **总条件数**：2个核心条件（被乘数x、乘数y的真值或十进制小数），可能附加机器字长说明。
- **条件设计原则**：
  - 给出 x 和 y 的真值（十进制小数形式），要求考生自行转换为补码小数表示后再执行 Booth 算法。
  - 或者直接给出 x 和 y 的补码二进制形式，考生直接进入迭代。
  - 二选一均可，由 Question Agent 决定；若要求转换，则分值中需体现转换步骤。
- **参数取值范围要求**：
  - x、y 均为补码纯小数，数值部分 4 位（含1位符号位共5位），使迭代趟数适中（5趟）。
  - x 和 y 一正一负或两者均含负数，确保符号位运算被测试。
  - 乘数 y 的二进制序列中必须同时出现相邻位 "01" 模式和 "10" 模式，确保加法和减法两种路径都被触发。
  - 避免 y 为全 0 或全 1 等退化为纯移位的情况。

## 参数约束
1. **x（被乘数）**：
   - 真值范围：[-0.9375, 0.9375]（对应5位补码小数，含1位符号位）。
   - 不能为 0（否则无计算意义）。
   - 可正可负，建议一正一负或均非零。

2. **y（乘数）**：
   - 真值范围：[-0.9375, 0.9375]。
   - 不能为 0。
   - **硬约束**：y 的补码二进制序列中必须同时包含 "01" 和 "10" 相邻位对，保证加法路径和减法路径都被触发。

3. **机器字长**：建议明确给出"采用5位补码小数（1位符号+4位数值）"，部分积采用双符号位（6位）。

4. **参数间一致性约束**：
   - x 的补码位数与 y 的补码位数相同。
   - 乘积结果应在双倍字长（10位）范围内，无溢出异常。
   - 乘积真值应可被精确表示（分母为16的简单分数），避免无限循环。

5. **可调自由度**：
   - Question Agent 可自由选择 x、y 的正负组合（建议一正一负）。
   - Question Agent 可选择"给真值要求转换"或"直接给补码"两种条件呈现方式。
   - 具体的 x、y 数值由 Question Agent 根据上述约束自行确定。

## 参考经验
- 本 slot 无历史 question_experiences（reference_questions 为空），k_source 为 heuristic。
- Booth 算法是组成原理期末核心算法题，标准考法为"给定两数→补码表示→逐趟迭代→给乘积"。
- 典型陷阱：
  1. 最后一趟（第 n+1 趟）：判断后只移位、不加减——考生易遗漏或错误执行加/减。
  2. 双符号位部分积：加/减运算时符号位需正确参与，单符号位会导致溢出错误。
  3. 附加位 y_{-1} 初始为 0，移位时与乘数最低位同步右移。
  4. 减法操作实际为加 [-x]_补，需先求 [-x]_补。
- 难度锚点：K3=4 是核心驱动维度，需保证迭代趟数足够（≥5趟）且操作类型多样。
