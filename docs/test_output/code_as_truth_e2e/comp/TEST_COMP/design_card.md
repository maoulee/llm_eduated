## core_knowledge_intent

- must_test:
  - 在逐次插入过程中动态计算各节点平衡因子，识别最小不平衡子树
  - 根据新插入节点相对于最小不平衡子树根的位置，正确判断 LL/RR/LR/RL 四种旋转类型并执行
  - 旋转后树结构的精确表示（父子关系、左右子树分配），并能描述旋转前后指定节点的子节点变化
- must_not_shift_to:
  - 退化为纯 BST 插入操作（仅判断大小关系，不涉及平衡因子和旋转）
  - 偏移到红黑树的着色规则或其他自平衡树的调整机制
- coverage_success_criteria:
  - 学生能正确识别每次失衡发生时的最小不平衡子树根节点
  - 学生能对至少 2 次失衡事件分别给出正确的旋转类型和旋转后结构
  - 学生能准确计算旋转后关键节点的平衡因子

## expected_reasoning_actions

1. 按给定顺序逐个插入关键字，遵循 BST 性质（左小右大）构建初始树结构
2. 每次插入后，沿插入路径自底向上计算各祖先节点的平衡因子（左子树高度 − 右子树高度）
3. 检测到 |平衡因子| > 1 时，定位最小不平衡子树（最低的失衡节点为根的子树）
4. 判断新插入节点位于最小不平衡子树根的哪条路径（LL/RR/LR/RL），据此确定旋转类型
5. 执行对应旋转（单旋或双旋），更新相关节点的父子指针和子树归属
6. 确认旋转后该子树恢复平衡，继续处理后续插入操作
7. 在所有插入完成后，描述最终树结构或指定节点的平衡因子/子节点

## question_structure_plan

- shared_context: 给定一组关键字的插入顺序，初始树为空，要求学生逐次插入并维护 AVL 平衡
- sub_question_chain:
  - 子问题 1（概念+计算，K3）：要求学生推演到第一次失衡发生，指出最小不平衡子树的根节点，并说明触发的是哪种旋转类型
  - 子问题 2（计算，K3+K4）：要求学生执行第一次旋转，画出（或描述）旋转后的树结构，并给出旋转后指定节点的平衡因子
  - 子问题 3（计算+概念，K3+K4）：继续插入后续关键字，要求学生识别第二次失衡并判断旋转类型，给出旋转后的树结构
  - 子问题 4（综合，K3）：要求给出所有关键字插入完毕后的最终树形态（或根节点的左/右子节点）
- dependency_pattern: 子问题之间为线性依赖——子问题 2 依赖子问题 1 的旋转结果，子问题 3 依赖子问题 2 的树结构，子问题 4 依赖全部前置操作完成后的状态
- 认知负荷分布设计:
  - 子问题 1-2 对应第一次旋转事件，K3 ≈ 3-4（3-5步推演 + 状态维护），K4 ≈ 3（需识别旋转类型条件）
  - 子问题 3 对应第二次旋转事件，K3 ≈ 4（在已旋转的树上继续推演 > 5 步），K4 ≈ 3-4（需排除已平衡节点的干扰）
  - 子问题 4 为全局汇总，K3 ≈ 3（从初始到最终的完整链路回顾）

## parameter_plan

- parameter_slots:
  - name: insertion_sequence
    role: 核心驱动参数，决定整道题的推演路径和旋转事件
    candidate_range: 6-8 个互不相同的关键字，取值为正整数，建议范围 1-50
    used_by: 全部子问题
  - name: initial_tree_state
    role: 初始树状态，决定插入起点
    candidate_range: 空树 或 已有 2-3 个节点的初始 AVL 树
    used_by: 子问题 1
  - name: focus_node_for_bf_query
    role: 子问题中要求计算平衡因子的指定节点
    candidate_range: 插入序列中的某个已插入关键字
    used_by: 子问题 2, 子问题 4
  - name: rotation_count
    role: 整个插入过程触发的旋转事件总数
    candidate_range: 2-3 次
    used_by: 子问题 1-3
  - name: rotation_type_coverage
    role: 需要覆盖的不同旋转类型种类
    candidate_range: 至少 2 种（如 LL+LR 或 RR+RL）
    used_by: 子问题 1, 子问题 3
- validation_targets:
  - insertion_sequence 必须触发至少 2 次旋转事件（|BF| > 1 至少出现 2 次）
  - 两次旋转事件必须是不同类型（不能都是 LL 或都是 RR）
  - 至少一次双旋（LR 或 RL）以确保 K4 条件路由的深度
  - 旋转后树的平衡因子全部恢复为 {-1, 0, 1}，无残留失衡
  - 所有子问题的答案可通过程序化模拟 AVL 插入过程唯一确定
- adjustment_priority:
  1. rotation_type_coverage（若仅触发单旋类型，需调整序列使第二次为双旋）
  2. rotation_count（若仅触发 1 次旋转，需增加序列长度或调整关键字顺序）
  3. insertion_sequence（确保关键字互不相同且 BST 插入路径明确无歧义）

## terminology_and_expression_constraints

- required_terms:
  - "平衡因子"（必须使用，定义：左子树高度 − 右子树高度）
  - "最小不平衡子树"（必须使用，指以插入路径上离插入节点最近的失衡节点为根的子树）
  - "LL 旋转 / RR 旋转 / LR 旋转 / RL 旋转"（必须使用标准旋转名称，不得用"左旋/右旋"替代双旋描述）
  - "单旋 / 双旋"（描述旋转性质时必须使用）
- required_qualifiers:
  - 描述旋转类型时必须指明"以 XX 为根的最小不平衡子树"
  - 描述平衡因子时必须注明"左子树高度 − 右子树高度"或等价定义，不可省略方向
  - 插入操作必须说明"按 BST 性质"确定插入位置
- avoid_phrases:
  - "左旋/右旋"单独使用替代旋转类型（因"左旋"可能指 RR 旋转的操作，容易混淆）
  - "重新平衡"（过于笼统，应明确为具体旋转操作）
  - "调整"（应明确为"旋转"或"重新连接"）
- standard_rewrites:
  - bad: "对树进行左旋操作"
    good: "对该最小不平衡子树执行 RR 旋转（右单旋）"
  - bad: "树不平衡了所以要调整"
    good: "节点 X 的平衡因子为 -2，以其为根的子树失衡，需要执行 RR 旋转"
  - bad: "旋转后树就好了"
    good: "旋转后，最小不平衡子树恢复平衡，所有节点平衡因子满足 |BF| ≤ 1"

## audit_focus

- final_review_must_check:
  - insertion_sequence 是否确实触发 ≥ 2 次旋转事件，且至少涉及 2 种不同旋转类型
  - 至少包含一次双旋（LR 或 RL），以确保 K4 条件路由深度达标
  - 子问题链是否为线性依赖，前一问的答案是否为后一问的必要输入
  - 每个子问题的分值分配是否与推演步数和认知负荷匹配
  - 题干是否清晰给出了插入顺序、初始树状态和每个子问题的具体要求
  - 平衡因子定义方向（左−右）是否在题干中明确
- solve_output_should_contain:
  - 每次失衡事件的：失衡节点、平衡因子值、最小不平衡子树根节点
  - 每次旋转的：旋转类型名称、旋转前后涉及的节点父子关系变化
  - 旋转后指定节点的平衡因子数值
  - 最终树结构（至少包含根节点及其左右子节点）
  - 插入序列的程序化 AVL 模拟结果，用于验证手推答案的正确性
- fail_if_missing:
  - 旋转事件不足 2 次 → 难度不达标
  - 所有旋转为同一类型 → K4 条件路由不足
  - 子问题之间无依赖关系 → 考察模式偏离"状态维护模拟"
  - 题干未定义平衡因子方向 → 答案存在歧义
  - 插入序列存在重复关键字 → BST 插入路径不唯一
