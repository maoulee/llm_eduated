## 考点
- **核心考点**：删除带头结点单链表中所有值为 x 的结点
  - 考察侧重点：单链表遍历与删除操作的指针操作能力；前驱指针维护；循环边界条件处理
- **辅助考点**：单链表结点类型定义（typedef struct LNode）
  - 考察侧重点：struct 定义语法、指针域 data 域正确声明、typedef 别名规范
- **辅助考点**：算法思想描述
  - 考察侧重点：能否用自然语言准确描述遍历+删除的逻辑流程

## 难度目标
- **K1=1**：仅需单链表基础定义（struct LNode、指针域），属数据结构入门级概念，无需辨析
- **K2=2**：涉及少量指针赋值操作，但无复杂数值计算，数字友好
- **K3=2**：算法逻辑路径较清晰（遍历→判断→删除→后移），步骤≤3步，路径基本唯一
- **K4=3**：存在明确注意点——删除结点需维护前驱指针、释放内存、连续删除时指针回退或while判断处理
- **K5=4**：需跨结点维护前驱/后继关系，涉及动态指针状态在多个操作间保持一致性，属于链表内部较高耦合的指针联动

## 考察模式
**算法设计型——链表操作算法设计**（与 slot 指定 examination_mode 一致）。
- 选择理由：删除链表中值为 x 的结点是线性表章节的经典算法设计题型，408 综合题中高频出现。此模式要求考生从结点定义到算法思想到代码实现全流程输出，能全面考察链表操作的代码能力。
- 该模式侧重：指针操作正确性、边界条件（表空/首结点/尾结点/连续命中）、内存管理（free 释放）。

## 参考经验
- **考察模式**：链表删除操作是 408 算法设计题的高频模式，核心在于前驱指针维护
- **难度锚点**：此类题在 408 中定位为中等偏上（对应 K4=3, K5=4），区分度在于边界处理（连续命中 x 的情况）
- **典型陷阱**：
  1. 连续两个结点值均为 x 时，删除第一个后指针未回退导致漏删
  2. 忘记 free 被删除结点（内存泄漏）
  3. 用 while 循环遍历时混淆 `p->next` 与 `p` 的移动逻辑
  4. 头结点处理：带头结点时，第一个数据结点是 `L->next`，不应删除头结点本身
