## 考点
- **核心考点**：二叉树的二叉链表存储与遍历——要求考生定义结点类型并基于遍历框架设计算法
- **核心考点**：叶子结点判定与路径保存——从叶子到根逆向输出路径，需结合递归回溯或显式栈保存路径
- **辅助考点**：路径的概念理解——"叶子到根"的路径方向与遍历方向的关系（自底向上 vs 自顶向下记录后反转输出）

## 难度目标
- **K1=1**（微弱）：仅需二叉树遍历和叶子结点的基础概念，属于数据结构核心常识，概念门槛极低。
- **K2=2**（较低）：可能涉及简单的结点计数或层次判断，计算量极小。
- **K3=2**（较低）：遍历流程路径唯一，无需复杂多步串行推演；主要考察设计而非模拟执行。
- **K4=3**（标准）：需识别"叶子到根"方向与遍历自然方向（根到叶子）的矛盾，需设计路径保存或逆序输出的机制，存在明确的思维暗坑。
- **K5=4**（较高）：算法设计需综合遍历框架（递归/栈）与路径保存逻辑，跨多个子机制（结点定义、递归遍历、路径数组管理、叶子判定、输出控制）协同。
- **整体难度=4**：算法设计题，要求完整的结点定义、算法思想描述和带注释的 C/C++ 代码实现，综合设计能力要求高。

## 考察模式
**算法设计型——二叉树遍历与路径算法设计**
理由：2014年第41题考察了二叉树遍历相关的算法设计，本题沿用"遍历框架 + 路径保存"的经典综合题模式，重点考察考生将遍历与路径管理结合的设计能力。该模式在408综合题中出现频率高，区分度好。

## 出题要求
- **题型**：综合题，16分
- **总条件数**：2-3个显式条件
  - 条件1：二叉树采用二叉链表存储（给出结点结构或要求考生自行定义）
  - 条件2：要求输出所有叶子结点到根结点的路径（路径上的结点值序列）
  - 条件3（可选）：对输出格式或路径方向的具体要求
- **条件设计原则**：
  - 明确存储结构为二叉链表
  - 明确"叶子到根"的方向（路径序列从叶子结点开始到根结点结束）
  - 不限定具体算法方法（递归或非递归均可），给考生设计空间
- **要求考生产出**：
  1. 结点类型定义
  2. 算法设计思想（文字描述）
  3. C/C++ 代码实现（含注释）

## 子问题规划
- **第1问（4分）— 定义与思想**：
  - 类型：分析/设计
  - 考察目标：定义二叉链表结点类型，描述求所有叶子到根路径的算法思想
  - 与后问关系：为第2问的代码实现提供设计基础，串行依赖
- **第2问（12分）— 代码实现**：
  - 类型：算法实现（C/C++ 编码）
  - 考察目标：基于第1问的设计思想，写出完整的算法代码并给出注释
  - 与前问关系：承接第1问，需与思想描述一致

## 参数约束
- **二叉树形态**：由考生在算法中处理任意形态的二叉树，题目不给具体二叉树实例（算法设计题不需要固定输入实例）
- **结点数据类型**：建议为整型或字符型，由 Question Agent 决定
- **结点值范围**：无特殊限制，考生自行约定即可
- **路径输出格式**：路径序列从叶子到根，各路径之间换行或空格分隔——由 Question Agent 明确
- **算法方法**：不限定递归或非递归，考生自行选择
- **自由度**：Question Agent 可自主决定是否给出具体二叉树示例辅助说明、结点结构是否给定（给定 vs 要求考生定义均可）

## 参考经验
- **历史模式**：2014年Q41为二叉树遍历相关算法设计题，要求定义结点、描述思想、编写代码，本题沿用此经典三段式结构
- **难度锚点**：算法设计综合题通常K5（跨域联动）为主导维度，因需整合结点定义、遍历、路径保存等多模块；K4（条件路由）中等，因需处理路径方向问题
- **典型陷阱**：
  1. 路径方向混淆——考生可能输出根到叶子的路径而非叶子到根
  2. 递归回溯时路径数组的维护——需要在回退时弹出当前结点
  3. 叶子结点判定遗漏——仅判断左子树为空而忽略右子树
