## 出题契约

### 基本信息
- target_subject: 计算机组成原理
- target_family: 计算机组成原理 > CO-7 输入输出系统 > I/O方式
- primary_target_name: 中断I/O方式可行性分析
- question_type: comprehensive
- examination_mode: 分析型——I/O方式性能计算与判断

### 难度目标
- k_target: K1=2,K2=4,K3=3,K4=3,K5=2
- difficulty_level: 3
- difficulty_rationale: 分析题，核心负载在多级换算链（主频→时钟周期→中断耗时→传输率比较），K2=4因涉及非2幂次运算和多级单位统一；K3=3因需走完3-5步固定流程；K4=3因存在中断响应开销是否计入的陷阱

### 结构要求
- sub_question_count: 3
- sub_question_structure:
  - 第1问: 计算——中断响应+服务总时间, 3分
  - 第2问: 计算——设备数据到达间隔, 3分
  - 第3问: 分析判断——两种设备中断I/O可行性, 4分
- dependency: 串行（1→2→3）
- distractor_strategy: 不适用（综合题，非选择题）
- condition_count: 3-4

### 参数约束
- CPU主频 f: 1~3 GHz, 取500MHz整数倍便于换算
- 中断服务程序时钟周期数 C: 使中断服务时间落在1~100 μs范围
- 中断响应开销 O: 使总中断开销增加10%~50%, 用于增大区分度
- 设备A传输率 R_A: 使数据到达间隔/中断总时间 ≥ 3（可行）
- 设备B传输率 R_B: 使数据到达间隔/中断总时间 在0.8~1.5范围（不可行或边界判断）
- 一致性约束: T_service / (1/R_B) 不得为整数, 避免边界模糊

### 参考经验摘要
- 历史模式: 408真题I/O可行性分析固定结构——给参数→算中断时间→算数据间隔→比较判断
- 难度锚点: K2通常3-4（换算链长），K3通常3（步骤多），K4通常2-3（中断响应开销陷阱）
- 典型陷阱:
  1. 忽略中断响应开销（保护/恢复现场）导致低估总时间
  2. 数据传输率单位混淆（B/s vs bit/s）
  3. 比值接近1时的安全裕度判断
