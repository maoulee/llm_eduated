# 中断I/O方式可行性分析 —— 参考解答

## 第（1）问：处理一次中断所需的总时间 $T_{\text{total}}$（3 分）

中断处理分为三个阶段，所需时钟周期数之和为总周期数：

$$C_{\text{total}} = C_{\text{resp}} + C_{\text{serv}} + C_{\text{rest}} = 500 + 4000 + 500 = 5000 \text{ 个时钟周期}$$

CPU 主频 $f = 2\;\text{GHz} = 2 \times 10^9\;\text{Hz}$，即每秒 $2 \times 10^9$ 个时钟周期。

$$T_{\text{total}} = \frac{C_{\text{total}}}{f} = \frac{5000}{2 \times 10^9} = 2.5 \times 10^{-6}\;\text{s}$$

$$\boxed{T_{\text{total}} = 2.5\;\mu\text{s}}$$

> **关键点**：中断响应开销（保护/恢复现场各 500 周期）必须计入，不能只算中断服务的 4000 周期。三个阶段开销缺一不可。

---

## 第（2）问：设备 A、B 两次中断之间的最小时间间隔 $T_{\text{A}}$、$T_{\text{B}}$（3 分）

每次中断传输的数据量 $D = 4\;\text{B}$。缓冲寄存器两次填满之间的时间间隔为：

$$T_{\text{interval}} = \frac{D}{R}$$

其中 $R$（B/s）$=$ $R$（KB/s）$\times\;1024$。

**设备 A**（$R_{\text{A}} = 512\;\text{KB/s}$）：

$$R_{\text{A}} = 512 \times 1024 = 524288\;\text{B/s}$$

$$T_{\text{A}} = \frac{4}{524288} = 7.62939453125 \times 10^{-6}\;\text{s}$$

$$\boxed{T_{\text{A}} \approx 7.63\;\mu\text{s}}$$

**设备 B**（$R_{\text{B}} = 2048\;\text{KB/s}$）：

$$R_{\text{B}} = 2048 \times 1024 = 2097152\;\text{B/s}$$

$$T_{\text{B}} = \frac{4}{2097152} = 1.9073486328125 \times 10^{-6}\;\text{s}$$

$$\boxed{T_{\text{B}} \approx 1.91\;\mu\text{s}}$$

> **关键点**：单位换算链为 传输率（KB/s）→ 字节率（B/s，乘以 1024）→ 时间间隔（$D/R$，秒）→ 微秒（乘以 $10^6$）。注意 $1\;\text{KB} = 1024\;\text{B}$（二进制换算）。

## 第（3）问：中断 I/O 方式可行性判断（4 分）

不丢失数据的条件：$T_{\text{total}} \leq T_{\text{interval}}$（CPU 处理一次中断的总时间不超过两次中断之间的间隔时间）。

### 设备 A：可行

$$T_{\text{total}} = 2.5\;\mu\text{s} \leq T_{\text{A}} = 7.63\;\mu\text{s}$$

CPU 在缓冲寄存器下一次填满之前能完成中断处理，**不会丢失数据，采用中断 I/O 方式与设备 A 通信可行**。

安全裕度：$T_{\text{A}} / T_{\text{total}} = 7.63 / 2.5 \approx 3.05$，间隔时间是处理时间的约 3 倍，裕度充足。

### 设备 B：不可行

$$T_{\text{total}} = 2.5\;\mu\text{s} > T_{\text{B}} = 1.91\;\mu\text{s}$$

CPU 处理一次中断需要 $2.5\;\mu\text{s}$，但设备 B 每隔 $1.91\;\mu\text{s}$ 就会产生一次中断请求（缓冲寄存器填满）。当 CPU 还在处理上一次中断时，下一次中断已经到来，缓冲寄存器中的数据会被覆盖，**造成数据丢失，采用中断 I/O 方式与设备 B 通信不可行**。

比值：$T_{\text{total}} / T_{\text{B}} = 2.5 / 1.91 \approx 1.31$，处理时间已超出间隔时间的 31%，无法及时处理。

**改进方案**：设备 B 数据传输率高、中断间隔短，应考虑改用 **DMA（直接存储器存取）方式**。DMA 方式下，数据在外设与内存之间直接传送，仅在传送开始和结束时需要 CPU 介入（预处理和后处理），传送过程中由 DMA 控制器接管总线、直接完成批量数据传输，避免了频繁中断 CPU 所带来的开销，能够满足高速设备的数据传输需求。
