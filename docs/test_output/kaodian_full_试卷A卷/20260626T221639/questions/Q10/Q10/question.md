# 中断I/O方式可行性分析

## 题目信息

- **科目**: 计算机组成原理
- **知识点**: CO-7 输入输出系统 > I/O方式 > 中断I/O方式可行性分析
- **题型**: 综合题（分析型）
- **分值**: 10 分
- **难度目标**: K1=2, K2=4, K3=3, K4=3, K5=2

## 题干

某计算机系统的 CPU 主频为 **2 GHz**，采用中断驱动 I/O 方式与两台外设 A、B 进行数据通信。系统中断处理过程分为三个阶段：

| 阶段 | 说明 | 所需时钟周期数 |
|------|------|----------------|
| 中断响应 | 保护 CPU 现场（寄存器压栈）、保存断点 | 500 |
| 中断服务 | 执行中断服务程序（读取数据、置标志等） | 4000 |
| 中断恢复 | 恢复 CPU 现场（寄存器出栈）、恢复断点 | 500 |

两台外设的参数如下（1 KB = 1024 B）：

| 设备 | 数据传输率 | 每次中断传输的数据量（缓冲寄存器宽度） |
|------|-----------|--------------------------------------|
| 设备 A | 512 KB/s | 4 B |
| 设备 B | 2048 KB/s | 4 B |

当缓冲寄存器填满时，外设向 CPU 发出中断请求；CPU 接收并处理完一次中断后，缓冲寄存器被清空，等待下一批数据。

**问题：**

**（1）（3 分）** 计算该系统处理**一次中断**所需的总时间 $T_{\text{total}}$（包含中断响应、中断服务、中断恢复三个阶段）。要求给出以微秒（μs）为单位的结果。

**（2）（3 分）** 计算设备 A 和设备 B 各自产生**两次中断之间的最小时间间隔** $T_{\text{A}}$ 和 $T_{\text{B}}$（即缓冲寄存器两次填满之间的时间）。要求给出以微秒（μs）为单位的结果。

**（3）（4 分）** 若要求采用中断 I/O 方式与某外设通信时**不丢失数据**，则需要保证 CPU 处理一次中断的总时间 $T_{\text{total}}$ 不超过两次中断之间的时间间隔。请分别判断采用中断 I/O 方式与设备 A、设备 B 通信是否可行，并说明理由。若不可行，请简要说明应考虑改用何种 I/O 方式。

## 设计意图

- **第（1）问** 考察中断处理全流程的时间计算。关键陷阱（K4=3）：学生容易忽略**中断响应开销**（保护/恢复现场各 500 周期），仅计算中断服务程序的 4000 周期，从而低估总时间。三个阶段开销必须全部计入。
- **第（2）问** 考察数据传输率到时间间隔的换算（K2=4）。学生需正确处理单位转换链：传输率（KB/s）→ 字节率（B/s）→ 每次传输数据量（B）→ 时间间隔（s→μs），且需注意 1 KB = 1024 B 的二进制换算。
- **第（3）问** 考察可行性判断（K3=3）。需将第（1）问结果与第（2）问结果对比，判断 $T_{\text{total}} \leq T_{\text{interval}}$ 是否成立。设备 A 应可行（间隔远大于处理时间），设备 B 应不可行或处于边界（间隔接近甚至小于处理时间）。不可行时需指出改用 DMA 方式。

## 场景规则（通过条件）

本题成立需要满足以下参数间约束关系（与具体答案值无关，换参数仍成立）：

1. **中断总时间一致性**：$T_{\text{total}} = (C_{\text{resp}} + C_{\text{serv}} + C_{\text{rest}}) / f$，其中 $C_{\text{resp}}$、$C_{\text{serv}}$、$C_{\text{rest}}$ 分别为中断响应、中断服务、中断恢复三个阶段的时钟周期数，$f$ 为 CPU 主频。三个阶段周期数之和即为总周期数，除以主频得到总时间。

2. **数据到达间隔一致性**：$T_{\text{interval}} = D / R$，其中 $D$ 为每次中断传输的数据量（字节），$R$ 为设备数据传输率（字节/秒）。注意 $R$ 的单位换算：$R$（KB/s）$\times 1024$ = $R$（B/s）。

3. **可行性判断一致性**：对设备 $i$，中断 I/O 可行 $\Leftrightarrow$ $T_{\text{total}} \leq T_i$（中断处理总时间 $\leq$ 两次中断间隔时间）。设备 A 必须满足 $T_{\text{total}} \leq T_{\text{A}}$（可行），设备 B 必须满足 $T_{\text{total}} > T_{\text{B}}$ 或 $T_{\text{total}} / T_{\text{B}}$ 接近 1（不可行或边界），以体现区分度。

4. **非整数比值约束**：$T_{\text{total}} / T_{\text{B}}$ 不等于整数（避免边界判断模糊，如恰好等于 1 时无法明确判断可行与否）。

5. **设备 A 安全裕度**：$T_{\text{A}} / T_{\text{total}} \geq 3$，确保设备 A 明确可行，不存在歧义。

## 给定参数汇总

| 参数 | 符号 | 值 | 说明 |
|------|------|-----|------|
| CPU 主频 | $f$ | 2 GHz | $2 \times 10^9$ Hz |
| 中断响应时钟周期 | $C_{\text{resp}}$ | 500 | 保护现场 + 保存断点 |
| 中断服务时钟周期 | $C_{\text{serv}}$ | 4000 | 中断服务程序执行 |
| 中断恢复时钟周期 | $C_{\text{rest}}$ | 500 | 恢复现场 + 恢复断点 |
| 设备 A 传输率 | $R_{\text{A}}$ | 512 KB/s | $512 \times 1024$ B/s |
| 设备 B 传输率 | $R_{\text{B}}$ | 2048 KB/s | $2048 \times 1024$ B/s |
| 每次中断传输数据量 | $D$ | 4 B | 缓冲寄存器宽度，两设备相同 |
