## 考点
- **核心考点**：Cache 全相联映射规则
  - 考察侧重点：主存块如何映射到 Cache 任意行、Tag（标志）的构成与计算、行替换概念
- **辅助考点**：主存地址分解
  - 考察侧重点：块内地址、主存块号的分离计算
- **辅助考点**：数据装入分析
  - 考察侧重点：给定一组主存地址序列，分析每个地址命中/未命中、装入后 Cache 行的标志字段与数据内容

## 难度目标
- **K1=2**：需要"全相联映射""Tag""主存块号"等408基础概念，但概念定义清晰后即可顺着推演，不需辨析易混概念
- **K2=3**：需代入公式计算块号、块内地址、Tag，涉及对数运算和非2幂次的数值转换，单步可能算错
- **K3=4**：需对多个主存地址逐一执行"分解地址→查Tag→判断命中/装入→更新Cache行状态"的串行推演流程，步数>5且需维持Cache行表动态更新
- **K4=3**：全相联映射中Tag=主存块号（不同于直接映射Tag需去掉行号），考生若混淆映射方式会算错Tag；同时需注意Cache容量与行数的换算隐含条件
- **K5=1**：单一知识点（Cache映射）内部解决，不涉及跨子系统数据传递

## 考察模式
**分析型——Cache地址映射与数据装入**
理由：该题位要求学生理解全相联映射机制后，对给定主存地址序列逐步推演映射结果，属于"规则明确+多步推演+状态维护"的经典分析模式。K3=4主导，要求考生维持Cache行表状态的动态更新，体现对映射机制的深入理解。

## 出题要求
- **题型**：综合分析题，10分
- **总条件数**：4-5个显式条件（Cache容量、Cache行长、主存地址位数、访问地址序列）
- **条件设计原则**：
  - Cache总容量和行长需给出，让考生自行计算Cache行数
  - 主存地址位数给出，让考生分解为"主存块号 + 块内地址"
  - 给出一组4-6个主存地址的访问序列（含重复访问），要求逐个分析
  - 初始状态Cache为空
- **参数取值范围要求**：
  - Cache总容量：2KB~8KB范围，行长：32B~64B，保证行数为2的幂次（32~256行）
  - 主存地址位数：16~24位
  - 访问序列中包含至少1次命中、至少1次替换（序列长度>Cache行数时可简化为>2即需关注状态）
  - 地址序列中应有2个地址映射到同一Cache行的情况（全相联下任何行均可装，但需体现装入和替换分析）

## 子问题规划
- **子问题1（计算，3分）**：根据Cache容量和行长，计算Cache行数；根据主存地址位数和行长，计算主存块号位数和块内地址位数；说明全相联映射下Tag的构成。
  - 考察目标：基础参数分解 + Tag定义
  - 与后问关系：为子问题2的逐行分析提供前置计算
  - 依赖关系：独立计算，无前置依赖

- **子问题2（分析，4分）**：给定一组主存地址访问序列，逐个分析每个地址在Cache中是命中还是未命中；对于未命中的地址，说明装入哪个Cache行（按空闲行优先、无空闲行时按FIFO/LRU替换策略）。
  - 考察目标：全相联映射规则应用、命中判断、数据装入与替换分析
  - 与前后问关系：依赖子问题1的地址分解结果
  - 依赖关系：串行——各地址按访问顺序逐个分析，需维持Cache状态表

- **子问题3（分析，3分）**：给出访问序列执行完毕后Cache中各行（或被请求的行）的Tag值和数据内容；或分析命中率。
  - 考察目标：对最终Cache状态的综合归纳
  - 与前后问关系：依赖子问题2的推演结果
  - 依赖关系：串行——基于子问题2的结果

## 参数约束
- **Cache总容量 C**：2KB ≤ C ≤ 8KB，C为2的幂次
- **Cache行长 L**：32B 或 64B
- **Cache行数 N = C/L**：需为2的幂次，范围32~256行
- **主存地址位数 A**：16 ≤ A ≤ 24
- **块内地址位数 b = log₂(L)**：由行长决定（5或6位）
- **主存块号位数 m = A - b**：由地址位数和行长决定
- **全相联映射Tag**：Tag = 主存块号（m位）
- **访问地址序列**：4-6个地址，需满足：
  - 至少1对地址的主存块号相同（体现命中）
  - 序列中地址的主存块号互不相同的情况占多数（体现装入）
  - 给出的地址需保证其十六进制值合理（在主存地址空间范围内）
- **初始状态**：Cache全空
- **替换策略**：FIFO或LRU（需在题干中明确指定，建议FIFO以降低复杂度）
- **可调自由度**：C、L、A的具体取值由Question Agent在约束内选定；地址序列的具体数值由Question Agent设计

## 参考经验
- **考察模式参考**：Cache映射分析题的典型模式为"给参数→分解地址→逐个地址分析命中/装入→总结状态"，408真题中常见
- **难度锚点**：K3=4对应多步推演+状态维护，需控制地址序列长度在4-6个以避免推演负担过重；K4=3对应映射方式混淆陷阱
- **典型陷阱**：
  1. 全相联映射Tag=全部主存块号，而非去掉行号的部分（区别于直接映射）
  2. 块内地址位数由行长决定，非由Cache总容量决定
  3. 命中判断时需比较Tag而非比较完整地址
  4. 替换策略的适用时机——全相联映射中任何行都可能被装入，替换发生在Cache满时
