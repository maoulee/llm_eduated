# 指令执行微操作序列与控制信号——参考解答

## 基本参数

| 参数 | 值 |
|------|-----|
| 编址方式 | 按字节编址 |
| 地址线位数 | 16 位 |
| 总线宽度 | 16 位 |
| 存储字长 | 16 位 |
| 指令字长 | 16 位 = 2 字节 |
| PC 增量（取指后） | **PC + 2** |

> 控制信号清单：PCin、PCout、MARin、MDRin、MDRout、IRin、R0in–R7in、R0out–R7out、Yin、Zin、Zout、ALU_ADD、ALU_SUB、ALU_AND、ALU_OR、Read、Write。

---

## 第 1 问（3 分）：取指周期微操作序列

| 节拍 | 微操作 | 控制信号 |
|------|--------|---------|
| T1 | PC → MAR | PCout, MARin |
| T2 | PC + 2 → PC | PCout, Yin, ALU_ADD, Zin, Zout, PCin |
| T3 | Mem[MAR] → MDR → IR | Read, MDRout, IRin |

**说明：**
- T1：将 PC 内容送 MAR，选中指令所在的主存单元。
- T2：PC 通过 ALU 完成 +2 运算（PC→Y 锁存器→ALU A 端，常数 2 经总线→ALU B 端，ALU_ADD，结果存 Z 锁存器，Z→总线→PC 回写）。按字节编址、指令字长 2 字节，故 PC 增量为 2。
- T3：发出 Read 信号，主存将指令读入 MDR，再由 MDR 经总线送入 IR。

## 第 2 问（4 分）：LDR R1, @40 间址周期 + 执行周期

LDR R1, @40 采用**间接寻址**：形式地址 40 是主存单元地址，该单元的内容才是操作数的有效地址 EA。因此取指后需要**间址周期**取出有效地址，再进入**执行周期**取操作数。

### 间址周期（取有效地址 EA）

| 节拍 | 微操作 | 控制信号 |
|------|--------|---------|
| T1 | IR 地址字段（形式地址 40）→ MAR | MARin |
| T2 | Mem[MAR] → MDR | Read |
| T3 | MDR（= 有效地址 EA）→ MAR | MDRout, MARin |

**说明：**
- T1：IR 中形式地址 40（经控制器内部通路）送入 MAR，指向存放有效地址的主存单元。
- T2：发出 Read 信号，读出主存[40] 的内容（即有效地址 EA）到 MDR。
- T3：将 MDR 中的有效地址 EA 送回 MAR，为执行周期访存做准备。

### 执行周期（按 EA 取操作数 → R1）

| 节拍 | 微操作 | 控制信号 |
|------|--------|---------|
| T1 | Mem[MAR]（EA 处）→ MDR | Read |
| T2 | MDR → R1 | MDRout, R1in |

**说明：**
- T1：此时 MAR 中已是有效地址 EA，发出 Read 信号，读出操作数到 MDR。
- T2：MDR 中的操作数经总线送入目的寄存器 R1，完成装入。

## 第 3 问（3 分）：ADD R2, R3 执行周期 + 对比分析

ADD R2, R3 采用**寄存器直接寻址**，两操作数均在寄存器中，不需要访存。

### 执行周期微操作序列

| 节拍 | 微操作 | 控制信号 |
|------|--------|---------|
| T1 | R2 → Y 锁存器 | R2out, Yin |
| T2 | R3 → 总线 → ALU B 端；Y → ALU A 端；ADD → Z | R3out, ALU_ADD, Zin |
| T3 | Z → 总线 → R2 | Zout, R2in |

**说明：**
- T1：第一操作数 R2 的内容经总线送入 Y 锁存器（ALU 的 A 端输入）。
- T2：第二操作数 R3 的内容经总线直接送入 ALU 的 B 端，与 Y 锁存器中的 A 端数据执行加法（ALU_ADD），结果存入 Z 锁存器（Zin）。
- T3：Z 锁存器中的运算结果经总线写回目的寄存器 R2。

> 该序列是单总线数据通路描述下的**唯一合理微操作安排**：单总线同一时刻只能有一个部件输出，因此两个源操作数必须分两步——先送一个到 Y 锁存器，再送另一个到总线——这不存在二义性。

### ADD 不经过访存控制信号（Read/Write）的原因

ADD 指令的执行周期控制信号集合为：**{R2out, Yin, R3out, ALU_ADD, Zin, Zout, R2in}**，**不含 Read 或 Write**。

原因：ADD R2, R3 的两个操作数分别在 R2 和 R3 中，运算结果也写回 R2，整个过程的数据通路路径为 **寄存器 → 总线 → ALU → 总线 → 寄存器**，全部在 CPU 内部完成，不需要访问主存。而 LDR R1, @40 的操作数存放在主存中，必须通过 MAR/MDR 并发出 Read 信号才能取得操作数，因此 LDR 的执行过程涉及访存控制信号。
