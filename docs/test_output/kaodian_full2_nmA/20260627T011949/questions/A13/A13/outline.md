## 考点
- **Cache 命中率**：给定访存序列，计算命中率（命中次数 / 总访问次数）
- **Cache 平均访问时间**：基于命中率、命中时间、缺失代价，用公式 t = h·t_c + (1-h)·t_m 计算
- **Cache 映射方式**：理解直接映射/组相联映射下地址划分，判断某次访问是否命中
- **辅助考点：Cache 效率**：e = t_c / t_a 或加速比 S = t_m / t_a 的计算

## 难度目标
- **K1=3**：需要准确记忆命中率公式、平均访问时间公式、效率定义，属于标准概念入题需求。
- **K2=3**：涉及非 2 的幂次数计算（命中率小数、平均时间乘法），需多步公式代入，数字不刻意友好。
- **K3=3**：核心主导维度。需按 Cache 映射规则走完"地址划分 → 逐次访问判断命中 → 统计命中次数 → 代入公式"的 3-5 步固定流程，路径唯一。
- **K4=2**：存在常规注意点（如缺失代价 vs 主存访问时间的关系、命中率小数精度），但不设深层陷阱。
- **K5=3**：Cache 与主存两级系统的单向拼接，Cache 命中率直接影响平均访问时间的计算。

## 考察模式
**计算题——Cache 命中率/平均访问时间/效率**
理由：slot 指定 examination_mode 即为此模式。该模式是 408 存储系统高频考法：给出 Cache 结构参数和一段访存序列，要求考生先判断命中情况再进行数值计算。K3 为主导，强调按映射规则逐次推演的流程性。

## 出题要求
- **题型**：综合题（计算题），总分 7 分
- **总条件数**：建议 4-5 个显式条件
  - Cache 容量 / 块大小 / 映射方式（结构参数）
  - 主存访问时间 / Cache 访问时间（时间参数）
  - 一段访存地址序列（用于计算命中率）
- **条件设计原则**：
  - 结构参数需能确定地址划分方式（标记位、行号、块内偏移）
  - 访存序列长度适中（6-10 次访问），需包含至少 2 次重复访问以产生命中
  - 时间参数应使平均访问时间计算结果为非平凡值（非整数或需保留小数）
- **参数取值范围要求**：
  - Cache 块数：2 的幂（4-32 块），便于地址划分
  - 块大小：2 的幂字节（16B-64B）
  - 映射方式：直接映射或 2 路组相联
  - Cache 访问时间 t_c：1-2 个时间单位
  - 主存访问时间 t_m（或缺失惩罚）：t_m 的 5-20 倍于 t_c
  - 访存序列地址：应在有效主存地址范围内，覆盖多个 Cache 行/组

## 子问题规划
本题设 **3 个子问题**，串行依赖，分值共 7 分。

| 子问题 | 类型 | 考察目标 | 分值 | 与前后问关系 |
|--------|------|---------|------|-------------|
| 第1问 | 计算 | 根据映射方式分析地址划分，逐次判断访存序列中的命中/缺失，计算命中率 | 3 | 基础问，结果供第2问使用 |
| 第2问 | 计算 | 利用命中率和给定的 Cache/主存访问时间，计算 Cache 的平均访问时间 | 2 | 依赖第1问的命中率结果 |
| 第3问 | 计算 | 计算 Cache 效率或加速比，或分析某参数变化对命中率/平均时间的影响 | 2 | 依赖第2问结果或独立分析 |

**依赖关系**：串行（1→2→3），第1问是第2问的前提，第3问在第2问基础上延伸。

## 参数约束
| 参数 | 取值范围 | 约束关系 | 自由度 |
|------|---------|---------|--------|
| Cache 总容量 | 256B - 2KB | = 块大小 × 块数 | 可拆分为块大小 × 块数 |
| 块大小 | 16B - 64B（2的幂） | 块内偏移位数 = log₂(块大小) | 独立选择 |
| Cache 块数 | 4 - 32（2的幂） | 若组相联，组数 = 块数/路数 | 独立选择 |
| 映射方式 | 直接映射 或 2路组相联 | 决定地址位划分方式 | 二选一 |
| t_c（Cache访问时间）| 1-2 ns（或时钟周期） | t_c < t_m，严格小于 | 独立选择 |
| t_m（缺失代价/主存访问时间）| 10-40 ns（或时钟周期）| t_m ≥ 5 × t_c，使命中率影响显著 | 独立选择 |
| 访存序列长度 | 6-10 次访问 | 含至少 2 次重复（产生命中）| Question Agent 设计 |
| 命中率 h | 0.2 ≤ h ≤ 0.7 | 序列设计需保证命中率为非平凡小数 | 由序列隐式决定 |

**一致性要求**：
- 访存序列地址必须落在有效主存地址范围内
- 序列中至少 2 次访问映射到同一 Cache 行（产生命中）
- 至少 1 次访问因冲突被替换（直接映射下）或因容量不足缺失
- 命中率结果应使后续平均时间计算有意义（h 不为 0 或 1）

## 参考经验
- **历史模式**：408 真题中 Cache 综合题的标准流程为"给结构→给访存序列→判断命中→算命中率→算平均时间"，此模式稳定且高频。
- **难度锚点**：K3=3 对应固定流程 3-5 步推演（地址划分、逐次判断、统计、代入公式），是标准难度综合题的典型 K3 水平。
- **典型陷阱**：
  - 缺失代价与主存访问时间的区别（部分题目中缺失代价 = 主存访问时间，部分需加上 Cache 访问时间）
  - 命中率的小数精度要求（需明确保留几位小数）
  - 直接映射下的冲突缺失容易被误判为命中
  - 访存序列中同一地址的连续访问应判定为命中（时间局部性）
