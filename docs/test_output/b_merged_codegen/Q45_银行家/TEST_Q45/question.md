# Q45 银行家算法 — 资源分配与安全性推演

## 题干

某系统中有 5 个进程 P0～P4 和 3 类资源 A、B、C，资源总量分别为 A=10、B=5、C=7。在 T0 时刻的资源分配情况如下表所示：

| 进程 | Max(A,B,C) | Allocation(A,B,C) |
|:----:|:-----------:|:------------------:|
| P0   | (7, 5, 3)   | (0, 1, 0)          |
| P1   | (3, 2, 2)   | (2, 0, 0)          |
| P2   | (9, 0, 2)   | (3, 0, 2)          |
| P3   | (2, 2, 2)   | (2, 1, 1)          |
| P4   | (4, 3, 3)   | (0, 0, 2)          |

## 设问

**(1)** 计算 T0 时刻系统的 Available 向量，并判断系统是否处于安全状态。若安全，请给出一个安全序列。（8分）

**(2)** 若进程 P4 发出资源请求 Request4 = (3, 3, 0)，系统能否立即为该请求分配资源？请说明理由。（7分）

## 设计说明

| 项目 | 内容 |
|------|------|
| 考点 | 银行家算法（死锁避免） |

| 考察模式 | 资源分配与安全性推演 |
| K-雷达 | K1=3, K2=2, K3=4, K4=4, K5=1 |
| 题型 | 综合题 |
| 分值 | 15分 |

### K-雷达说明

- **K1=3（标准）**：需准确记忆银行家算法中 Max/Allocation/Need/Available 的概念及安全算法流程
- **K2=2（较低）**：计算为矩阵加减和向量比较，数字友好
- **K3=4（较高）**：安全算法需多步串行推演（5个进程逐轮扫描），需维持 Work 和 Finish 动态状态
- **K4=4（较高）**：第(2)问隐含前提——"Request ≤ Need 且 Request ≤ Available"仅是必要条件，还需验证试分配后系统仍安全；常规思维易忽略第三步验证
- **K5=1（微弱）**：单一操作系统知识点内部解决

### 参数来源

参数由 `param_gen.py` 生成并校验：
- Need = Max - Allocation，所有元素 ≥ 0 ✓
- Available = Total - ΣAllocation，所有元素 ≥ 0 ✓
- 初始状态存在安全序列 ✓
