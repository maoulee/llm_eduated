# 银行家算法 — 概念选择题解析

---

## 第 1 题解析

**答案：C**

**正确项分析：**

**C 正确。** 安全状态的定义是存在至少一个安全序列（即能按某种顺序依次满足所有进程的最大资源需求并使其顺利完成）。既然存在这样的序列，所有进程最终都能获得所需资源并执行完毕，因此安全状态下一定不会发生死锁。这是安全状态的核心保证。

**干扰项分析：**

- **A 错误**——不安全状态仅表示当前不存在安全序列，但进程仍有可能按某种实际执行顺序顺利完成而不发生死锁。不安全 ≠ 死锁，只是死锁的可能性增大。
- **B 错误**——安全状态的保证是绝对的：只要系统处于安全状态，无论进程以何种顺序请求资源（只要请求量不超过其声明的最大需求），都不会导致死锁。安全状态不依赖于进程的实际执行顺序。
- **D 错误**——不安全状态意味着当前不存在安全序列，银行家算法无法凭空"恢复"安全状态。算法的作用是在分配前预防性地避免进入不安全状态，而非在不安全状态后进行修复。

## 第 2 题解析

**答案：A**

**正确项分析：**

**A 正确。** 银行家算法处理资源请求的标准三步检查流程为：

1. **第一步**：检查 $Request_i \le Need_i$。若不满足，说明进程请求的资源超过了它事先声明的最大需求，属于非法请求，直接报错拒绝。
2. **第二步**：检查 $Request_i \le Available$。若不满足，说明系统当前没有足够的可用资源，进程必须等待。
3. **第三步**：试探性地分配资源（修改 $Available$、$Allocation_i$、$Need_i$），然后执行安全性算法。若分配后系统仍处于安全状态，则正式分配；否则回滚，进程等待。

这三步的顺序不可调换：必须先确认请求合法（不超过最大需求），再确认资源充足，最后才做安全性检查。

**干扰项分析：**

- **B 错误**——先检查 $Available$ 再检查 $Need$ 颠倒了合法性检查的优先级。应先确认请求本身是否合法（不超过声明最大需求），再判断资源是否够用。
- **C 错误**——将资源充足性检查（$Request_i \le Available$）放在安全性算法之后，逻辑上不成立：若资源都不够分配，执行安全性检查无意义。
- **D 错误**——先执行安全性算法再检查请求合法性和资源充足性，完全颠倒了流程。安全性算法是在试探性分配之后才执行的，不是第一步。

## 第 3 题解析

**答案：B**

**正确项分析：**

**B 正确。** 安全序列的严格定义是：一个进程执行序列 $\langle P_{i_1}, P_{i_2}, \dots, P_{i_n}\rangle$，使得对每个进程 $P_{i_k}$，其尚需资源 $Need_{i_k}$ 不超过系统当前可用资源与序列中排在它前面的所有进程释放的资源之和。即每个进程都能获得所需资源、执行完毕并释放其占有的全部资源。安全序列保证所有进程都能顺利完成。

**干扰项分析：**

- **A 错误**——安全序列不唯一，也不要求按进程编号顺序。只要满足安全性条件的任意排列都是合法安全序列。一个安全状态可能对应多个安全序列。
- **C 错误**——不存在安全序列意味着系统处于不安全状态，但不安全状态不等于死锁。不安全状态下，进程仍有可能因实际请求模式而顺利执行完成，只是无法保证一定不死锁。这是"不安全"与"死锁"的关键区别。
- **D 错误**——恰恰相反，安全序列中排在前面的进程优先获得资源并完成，完成后释放资源供后面的进程使用。安全序列的本质就是前面进程先完成、释放资源、为后面进程创造条件。

## 第 4 题解析

**答案：D**

**正确项分析：**

**D 正确。** 银行家算法中，$Need[i][j] = Max[i][j] - Allocation[i][j]$。这是核心关系式：进程 $P_i$ 对第 $j$ 类资源的尚需量 = 最大需求量 − 已分配量。安全性算法中正是用 $Need$ 与 $Available$ 比较来判断是否可以满足某进程。

**干扰项分析：**

- **A 错误**——$Available[j]$ 表示系统中第 $j$ 类资源的**当前可用（剩余）数量**，而非总数量。总数 = 已分配之和 + 可用量。随着资源的分配和回收，$Available$ 是动态变化的。
- **B 错误**——$Max[i][j]$ 表示进程 $P_i$ 对第 $j$ 类资源的**最大需求量**（声明值），而非当前已拥有量。当前已拥有量由 $Allocation[i][j]$ 表示。
- **C 错误**——$Need$ 是差值（最大需求减去已分配），不是和值。若写成 $Need = Max + Allocation$，则 $Need$ 会大于 $Max$，这在逻辑上不成立，因为"尚需量"不可能超过"最大需求量"。

## 第 5 题解析

**答案：B**

**逐条分析：**

**Ⅰ 正确。** 银行家算法是经典的死锁**避免**（Avoidance）策略，与死锁预防、死锁检测不同。它在系统运行期间，每次收到资源请求时动态执行安全性检查，只有在分配后系统仍处于安全状态时才允许分配。这体现了"运行时动态检查"的核心特征。

**Ⅱ 正确。** 银行家算法的前提条件之一是：每个进程在开始执行前必须事先声明其对各类资源的最大需求量 $Max$。算法依赖 $Max$ 来计算 $Need$ 并进行安全性判断。若进程不声明最大需求，算法无法运行。

**Ⅲ 错误。** 银行家算法的判断依据是"分配后系统是否仍处于安全状态"，而非"当前系统是否处于不安全状态"。即使当前系统处于不安全状态（理论上不应发生，因为算法保证不会进入不安全状态），算法仍会检查具体请求分配后的安全性，而非一律拒绝。此外，"一定会拒绝所有新请求"的说法过于绝对，且不安全状态本身就意味着算法此前已被违反。

**Ⅳ 正确。** 只要严格遵循银行家算法，系统永远不会进入不安全状态，因此永远不会死锁。但代价是算法偏保守：某些在分配后实际不会导致死锁的请求，可能因无法找到安全序列而被拒绝，导致进程等待，从而降低资源利用率和系统吞吐量。

**正确组合：Ⅰ、Ⅱ、Ⅳ → 选 B。**
