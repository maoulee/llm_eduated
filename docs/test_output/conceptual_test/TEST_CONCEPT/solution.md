# Q45 概念题解析（考点：银行家算法与死锁避免）

---

## 第 1 题 解析

**答案：C（仅 I 和 III）**

**I 正确**——安全状态的定义：存在至少一个安全序列 <Pi₁, Pi₂, …, Piₙ>，使得对每个进程 Pij，其剩余需求量 Need 可以被当前可用资源加上排在其前面的所有进程释放的资源所满足。因此，安全状态下所有进程都能按序顺利完成，不会死锁。

**II 错误**——这是最经典的认知陷阱。不安全状态的定义是"不存在安全序列"，但这**不等于**死锁。不安全只是意味着系统**无法保证**所有进程都能完成，但在实际执行中，进程可能恰好按照某种顺序释放资源，从而避免了死锁。简言之：不安全 ⟹ 有死锁的**可能**，但 ≠必然死锁。

**III 正确**——系统状态是动态的。即使当前处于不安全状态，后续的进程执行（释放已占有资源使 Available 增加）完全有可能使系统重新产生安全序列，回到安全状态。安全/不安全是瞬态属性，随资源分配与释放不断变化。

> **干扰分析**：选项 B（I 和 II）利用了"不安全 = 死锁"的常见误解，是高频错误选项。

## 第 2 题 解析

**答案：B**

**A 错误**——虽然两者都在分配前有所动作，但机制本质不同。死锁预防通过施加静态限制（破坏必要条件）来杜绝死锁发生的可能；死锁避免则是在运行时动态评估每次分配后的系统安全性。前者是"事前设限"，后者是"实时检查"。

**B 正确**——这是死锁预防与避免的核心区别：
- **死锁预防**：破坏死锁的四个必要条件之一（互斥、占有并等待、不剥夺、循环等待），例如有序资源分配法破坏循环等待。
- **死锁避免**：不限制资源申请方式，而是在每次资源分配前，利用银行家算法等检查分配后系统是否仍处于安全状态，仅在安全时才分配。

**C 错误**——限制进程申请资源的顺序（有序资源分配法）是**死锁预防**策略，通过破坏循环等待条件来预防死锁，而非死锁避免。

**D 错误**——银行家算法是**死锁避免**策略的典型代表。它在资源分配时通过安全性检查来避免进入不安全状态，而非通过破坏必要条件来预防死锁。

> **干扰分析**：选项 D 是"概念混淆"型干扰（避免↔预防张冠李戴）；选项 C 是"过度推断"型干扰（将预防的具体手段错误归为避免）。

## 第 3 题 解析

**答案：B**

在银行家算法的安全性检查中，当进程 Pi 的 Need_i ≤ Work 时，Pi 可以完成执行。进程完成后**释放的是它实际占有的资源**，即已分配量 Allocation_i。

因此更新方式为：**Work = Work + Allocation_i**

**A 错误**——Max_i 是进程声明的最大需求量。进程运行期间未必获得了 Max_i 这么多资源（通常 Allocation_i < Max_i），因此释放量不等于 Max_i。

**B 正确**——进程完成执行后，归还其所有已分配资源 Allocation_i 给系统。

**C 错误**——Need_i = Max_i − Allocation_i，是进程"还需要"的资源量，不是它占有的、可以释放的资源量。

**D 错误**——Max_i − Allocation_i = Need_i，与选项 C 相同，同样错误。

> **干扰分析**：本题考察对安全性检查机制中"资源回收"步骤的精确理解。常见错误是将 Need（还需量）或 Max（声明最大量）误认为释放量。

## 第 4 题 解析

**答案：D（I、II 和 III 均正确）**

银行家算法处理资源请求 Request_i 的完整流程如下：

**I 正确**——检查 ① Request_i ≤ Need_i：若不成立，说明进程请求的资源超过了它预先声明的最大需求量，这是非法请求（进程"说话不算数"），系统直接报错拒绝。该检查确保进程不会超额申请。

**II 正确**——检查 ② Request_i ≤ Available：若不成立，说明当前系统可用资源不足以满足该请求，进程 Pi 必须阻塞等待，系统暂不分配资源。该检查确保不会分配不存在的资源。

**III 正确**——只有当 ① 和 ② 都满足时，系统才进行**试探性分配**：临时更新 Available = Available − Request_i、Allocation_i = Allocation_i + Request_i、Need_i = Need_i − Request_i，然后运行安全性算法检查分配后的新状态是否安全。若安全，则正式分配；若不安全，则回滚（恢复原值），进程 Pi 等待。

三步检查层层递进：①合法性检查 → ②资源充足性检查 → ③安全性检查，缺一不可。

> **考察要点**：本题考察对银行家算法请求处理完整流程的理解，重点是三步检查的**顺序与逻辑关系**（短路求值：前序不通过则不执行后续检查）。
