## examination_form
- 考察形式：多步串行推演（主）+ 陷阱辨析（辅）
- 设问方向：给定资源矩阵与进程请求，要求考生完整执行银行家算法的安全性推演流程（Need 计算 → 合法性检查 → 试探性分配 → 安全性算法 → 安全序列输出），并在概念层面辨析"安全状态≠无死锁的反面"这一隐含前提

## k_radar
- K1（基础认知）: 3
- K2（单步代入）: 2
- K3（机制推演）: 4
- K4（条件路由）: 4
- K5（跨域联动）: 1
- 形状主导维度：K3-K4 平衡型（K3=4, K4=4 并列主导）

## rationale
- 为何选此形式：银行家算法的核心认知价值在于两维——K3 侧需 5 进程以上多轮安全性扫描并维护动态 Work 向量，步数 5–7 步且中间错一步全盘偏离，这是"多步串行推演"的典型场景；K4 侧需理解"安全状态一定无死锁但不安全状态不一定死锁"的深层隐含前提，以及合法性检查的两步顺序（Request≤Need 先于 Request≤Available），这是"陷阱辨析"的典型特征。两维并重，故取主+辅混合形式。
- 与目标 K-雷达的对齐说明：目标 K-雷达为 K3-K4 平衡型且 K3≥4、K4≥4，本判定 K3=4（多步动态状态推演）、K4=4（深层隐含前提）精确对齐；K1=3（需准确回忆 Need/Available/安全序列等核心定义才能入题）、K2=2（仅涉及简单整数减法代入）、K5=1（题目完全在死锁避免单一子系统内闭环），与设计卡的 should_be/should_not_be 约束一致。
