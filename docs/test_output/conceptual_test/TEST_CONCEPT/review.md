## 问题概述

蓝图明确要求考察模式为 **"资源分配与安全性推演"**，难度说明为 **"需多步推演资源状态变化以寻找安全序列，且需深入理解安全状态的隐含前提"**，K目标为 **K3-K4 平衡型**。

实际题目为 **3 道纯概念辨析选择题**，不包含任何资源分配表、需求矩阵、可用资源向量，无需执行安全性算法，无多步推演过程。题目实际 K3（机制推演）≈1-2，与目标 K3-K4（3-4级）偏差 ≥2 级。

## blocking_issues

### Issue 1：考察模式严重不匹配（examination_mode_mismatch）

- **evidence**：蓝图 `考察模式: 资源分配与安全性推演`；蓝图 `难度说明: 需多步推演资源状态变化以寻找安全序列`；question.md 标题为"概念辨析题"，三道子题均为纯概念/定位辨析，无任何资源分配数据或安全性检查过程。

### Issue 2：K3 机制推演维度偏差 ≥2 级（structure_error）

- **evidence**：蓝图 K目标 K3-K4 平衡型。实际三道题均为单步概念判断：第1题为定义辨析（安全状态≠不死锁），第2题为分类定位（银行家算法属于死锁避免），第3题为安全序列定义复述。从输入到输出仅 1 步概念回忆，K3 实际 ≈1-2，与目标 3-4 偏差 ≥2 级。

### Issue 3：缺少推演所需的题面条件（condition_error）

- **evidence**：考察模式"资源分配与安全性推演"要求题面给出资源分配场景（如进程数量、资源类型、Max/Allocation/Need 矩阵、Available 向量）。question.md 第3题虽提及 P₁/P₂/P₃，但未给出任何资源数据，仍为概念题。

## fix_instructions

### Fix 1：重构题目为资源分配与安全性推演题

- **修改对象**：question.md 全文
- **修改位置**：第1题至第3题整体结构
- **当前问题**：三道纯概念辨析题与蓝图"资源分配与安全性推演"考察模式完全不匹配，K3 维度严重偏低
- **修改目标**：改为基于具体资源分配场景的安全性推演题，要求考生执行银行家算法的安全性检查流程（多步推演资源状态变化），体现 K3-K4 平衡型难度
- **最小修改指令**：
  1. 设计一道资源分配场景题：给出若干进程（如 3-5 个）对某类/多类资源的 Max、Allocation 矩阵和 Available 向量
  2. 题干提问应要求考生执行安全性算法，判断系统是否处于安全状态，或判断某次资源请求是否可以批准
  3. 选择题的提问应指向"安全序列存在性""某请求能否批准"等推演结论，而非纯概念复述
  4. 干扰选项应体现推演过程中的典型认知错误（如忽略 Need 的计算、混淆 Allocation 与 Need、误判安全序列方向等）
  5. 删除现有的三道概念辨析题

### Fix 2：确保 K4 隐含前提维度

- **修改对象**：题干设计中的隐含条件/陷阱点
- **修改位置**：新题干的条件设置
- **当前问题**：现有题目无 K4 意义上的隐含前提考察
- **修改目标**：新题应包含需考生深入理解安全状态本质才能正确路由的隐含条件（如：不安全状态≠死锁、安全性检查须基于 Need 而非 Max、请求批准后须回滚检查等）
- **最小修改指令**：在新设计的资源分配场景中，至少设置一个需理解机制本质才能避开的隐含前提作为区分项
