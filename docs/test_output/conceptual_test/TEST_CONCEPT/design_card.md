## core_knowledge_intent

- must_test:
  - 安全状态与死锁的充要关系辨析——"系统处于安全状态⇒当前无死锁"为真，但"系统处于不安全状态⇒必然死锁"为假。这是 K4 条件路由的核心陷阱点。
  - 银行家算法的预检机制本质——在资源分配前进行安全性检查，而非分配后检测或事前预防。考察学生对"避免（avoidance）"这一策略定位的准确理解。
  - 安全状态的判定前提——存在至少一个安全序列（所有进程能按某种顺序完成），而非要求所有序列都安全。
- must_not_shift_to:
  - 死锁四个必要条件的逐条记忆默写（偏离安全性推演目标）
  - 死锁预防的具体策略（如资源有序分配）与避免策略的全面比较
- coverage_success_criteria:
  - 学生能准确判断"不安全状态≠死锁态"并解释原因
  - 学生能说清银行家算法的检查时机（分配前预检）和检查内容（是否存在安全序列）

## design_rationale

本题将 K3-K4 平衡型雷达设计在"概念辨析+条件路由"交叉点：K3 体现在学生需要理解安全序列的推演逻辑（至少存在一条完成路径即可），K4 体现在必须识破"不安全状态=死锁"这一反直觉陷阱。选择概念辨析形式而非数值计算，是因为数值计算会让学生陷入矩阵运算而掩盖核心理解——真正的难点不在算安全序列，而在理解"安全状态"与"死锁"之间的非对称关系。本题要区分的是"能说清为什么不安全不一定死锁"的学生（真正理解机制本质）与"只记得安全状态公式定义"的学生（表面记忆）。难度 4 的定位通过设置似是而非的命题组合实现——每个干扰项都对应一个真实的认知错误路径，而非随机编造。

## question_structure_plan

- stem_style: 命题判断型——给出关于银行家算法/安全状态的若干陈述（I/II/III），要求判断哪些正确。题干可设置一个简短的资源分配场景作为语境锚定，但不要求学生执行完整计算。
- asking_method: "下列关于银行家算法和安全状态的叙述中，正确的有哪些？"
- option_architecture:
  - correct: 仅包含真命题的组合
  - distractor_1（过度推断）: 将"安全状态⇒无死锁"错误逆推为"无死锁⇒安全状态"，混合一条真命题增加迷惑性
  - distractor_2（张冠李戴）: 将银行家算法描述为"死锁预防"策略（实际为死锁避免），混淆 prevention 与 avoidance 的概念边界
  - distractor_3（条件遗漏）: 安全序列的判定中遗漏"至少存在一条"这一充分条件，错误表述为"所有可能的进程完成顺序都必须安全"
- 命题池（供 design 从中选取 I/II/III 组装）:
  - "系统处于安全状态时，一定不会发生死锁"（真）
  - "系统处于不安全状态时，一定会发生死锁"（假——不安全只是可能死锁）
  - "银行家算法在每次资源请求时都进行安全性检查"（真）
  - "银行家算法属于死锁预防策略"（假——属于死锁避免策略）
  - "安全状态要求所有进程执行顺序都能顺利完成"（假——只要求存在至少一个安全序列）
  - "若 Available 能满足某个进程的 Need，则系统一定处于安全状态"（假——需要验证该进程完成后能否找到完整安全序列）

## terminology_and_expression_constraints

- required_terms:
  - "安全状态"（safe state）——必须使用此标准术语
  - "安全序列"（safe sequence）——必须使用此标准术语
  - "死锁避免"（deadlock avoidance）——描述银行家算法的策略定位时必须使用此术语
  - "死锁预防"（deadlock prevention）——作为干扰项中的错误归类时使用
- required_qualifiers:
  - 描述安全状态与死锁关系时必须使用方向性限定语："安全状态保证不会死锁"而非"安全状态与死锁无关"
  - 描述不安全状态时必须使用概率性/可能性限定语："可能导致死锁"而非"导致死锁"
  - 描述安全序列时必须使用存在性量词："至少存在一个安全序列"
- avoid_phrases:
  - "银行家算法可以预防死锁"——应改为"银行家算法可以避免死锁"
  - "不安全状态就是死锁状态"——应改为"不安全状态可能导致死锁"
- standard_rewrites:
  - bad: "安全状态说明系统没有死锁" → good: "系统处于安全状态时，一定不会发生死锁"
  - bad: "银行家算法通过预防来防止死锁" → good: "银行家算法通过在分配前进行安全性检查来避免死锁"

## audit_focus

- final_review_must_check:
  - 每个命题的真假判断必须概念准确，不得出现"真命题被标假"或"假命题被标真"的错误
  - "不安全状态≠死锁"这一核心辨析点必须在命题池中体现，且正确答案中不含将其错误判真的选项
  - 干扰项必须对应明确的认知错误路径（过度推断/张冠李戴/条件遗漏），不得是随机编造的无关叙述
  - "死锁避免"与"死锁预防"的术语区分必须在题面或选项中体现
- solve_output_should_contain:
  - 对每个命题逐一进行真假判定并给出判定理由
  - 明确指出"不安全状态可能导致死锁但不必然死锁"的推理依据
  - 明确区分"避免"与"预防"在死锁处理策略中的定位差异
- fail_if_missing:
  - 缺少对"安全状态⇒无死锁"与"无死锁⇏安全状态"非对称关系的解释
  - 将银行家算法归类为死锁预防策略
  - 干扰项无逻辑依据（纯随机错误叙述）
