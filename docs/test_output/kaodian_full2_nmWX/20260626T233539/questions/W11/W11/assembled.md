## 出题契约

### 基本信息
- target_subject: 计算机组成原理
- target_family: 中央处理器 > 微程序控制器
- primary_target_name: 水平型微指令格式设计与控存容量
- question_type: comprehensive
- examination_mode: 设计题——给定微命令互斥类，设计水平型编码微指令格式并算控存最大容量

### 难度目标
- k_target: K1=3,K2=3,K3=3,K4=4,K5=2
- difficulty_level: 4
- difficulty_rationale: K4 为主导维度，核心难点在于字段直接编码需预留"无操作"状态（位数 = ⌈log₂(组内微命令数+1)⌉）以及控存容量由下地址字段宽度决定的隐含前提。整体难度 4，适合标准综合题题位。

### 结构要求
- sub_question_count: 3
- question_score: 10
- score_distribution: 4+3+3
- sub_question_details:
  - Q1(4分, 设计+计算): 根据互斥类分组确定操作控制字段各子字段位数及总位数
  - Q2(3分, 分析+计算): 确定判别测试字段与下地址字段位数，给出完整微指令格式
  - Q3(3分, 计算): 计算控存最大容量
- sub_question_dependency: 串行（Q1→Q2→Q3）
- condition_count: 4-5
- distractor_strategy: 不适用（综合设计题无选项干扰，难度通过参数设计和隐含前提实现）

### 参数约束
- 微命令总数: 8-16 个
- 互斥类组数: 3-5 组
- 每组微命令数: 2-4 个，至少一组满足 ⌈log₂(微命令数+1)⌉ 需要进位（如组内 4 个微命令→3 位）
- 判别测试条件数: 2-5 个（P字段位数 = ⌈log₂(条件数+1)⌉）
- 下地址字段位数: 6-10 位（Question Agent 自选具体值）
- 一致性约束: 操作控制字段位数 + P字段位数 + 下地址字段位数 = 微指令字长
- 控存最大容量: 微指令字长 × 2^(下地址字段位数)

### 参考经验摘要
- 历史模式: 给定互斥类→分段直接编码→算各字段位数→算微指令字长→算控存最大容量，标准流程题
- 难度锚点: K4=4，核心陷阱为字段编码"无操作"状态的预留
- 典型陷阱:
  1. 位数计算忽略"+1"状态（⌈log₂(n)⌉ vs ⌈log₂(n+1)⌉）
  2. 控存容量误用操作控制字段位数而非下地址字段位数
  3. 漏算判别测试字段导致微指令字长错误
