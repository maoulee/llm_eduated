## 考点
1. **水平型微指令格式设计**（核心）：操作控制字段采用字段直接编码（分段直接编码），根据微命令互斥关系分组，每组分配一个字段，每字段位数 = ⌈log₂(组内微命令数+1)⌉（+1 留出"不发出微命令"的状态）
2. **下地址字段宽度与控存容量的关系**：下地址字段的位数决定控存可寻址的微指令最大条数，即控存最大容量 = 微指令字长 × 2^(下地址字段位数)
3. **微指令总字长组成**：微指令字长 = 操作控制字段位数 + 判别测试字段位数 + 下地址字段位数
4. **判别测试字段（P字段）**：用于条件转移测试，位数 = ⌈log₂(判别测试条件数+1)⌉

## 难度目标
- **K1=3**（标准）：必须准确记忆水平型微指令三段式格式（操作控制+判别测试+下地址）及字段直接编码规则，概念模糊无法入题
- **K2=3**（标准）：需代入公式计算各字段位数，涉及 log₂ 运算和 2 的幂，可能涉及非 2 的幂次取整
- **K3=3**（标准）：按固定流程走 4-5 步（分组→算各字段位数→求和→算控存容量），路径唯一
- **K4=4**（较高）：隐含前提深——①字段编码必须预留"无操作"状态导致位数比组内微命令数多算一个状态；②控存最大容量由下地址字段宽度决定而非操作控制字段；③互斥类分组与字段分配的对应关系必须正确理解才能路由
- **K5=2**（较低）：单一知识点（微程序控制器）内部解决，不涉及跨子系统

## 考察模式
**设计题——给定微命令互斥类，设计水平型编码微指令格式并算控存最大容量**

理由：这是微程序控制器最经典的综合考法，将微指令格式设计（分段编码）与控存容量计算串联，考察学生对水平型微指令完整结构的理解。给定微命令互斥类信息，学生需自主完成分组→定字段→算位数→算容量全流程。该模式在历年 408 及教材习题中反复出现，难度可控且区分度好。

## 出题要求
- **题型**：综合设计题，总分 10 分
- **总条件数**：4-5 个显式条件
  - 条件1：机器采用水平型微程序控制器，微指令操作控制字段采用字段直接编码
  - 条件2：给出全部微命令及互斥类分组关系（以表格或文字列表形式）
  - 条件3：判别测试条件数（P字段对应的测试条件数量）
  - 条件4：下地址字段相关信息——或给出控存中微指令条数让反推位数，或给出位数让算容量
  - 条件5（可选）：微指令总字长的对齐约束（如字长为字节的整数倍）
- **条件设计原则**：互斥类分组信息必须明确，每组微命令数量要有差异（至少一组需 +1 状态导致位数进位，测试学生是否正确处理"无操作"状态）
- **参数取值范围要求**：微命令总数 8-16 个；互斥类 3-5 组；判别测试条件 2-5 个

## 子问题规划
| 子问 | 类型 | 考察目标 | 分值 | 关系 |
|------|------|----------|------|------|
| 第1问 | 设计+计算 | 根据互斥类分组，确定操作控制字段各子字段位数及操作控制字段总位数 | 4分 | 独立，后续问的基础 |
| 第2问 | 分析+计算 | 确定判别测试字段和下地址字段的位数，给出完整微指令格式（字长） | 3分 | 依赖第1问的操作控制字段结果 |
| 第3问 | 计算 | 计算控存最大容量（字长×最大微指令条数） | 3分 | 依赖第2问的字长和下地址字段位数 |

**依赖关系**：串行，第1问→第2问→第3问，层层递进。

## 参数约束
1. **微命令总数**：8-16 个，分为 3-5 个互斥类
2. **互斥类每组微命令数**：2-4 个，其中至少一组的微命令数满足 ⌈log₂(该组数+1)⌉ 需要进位（如 3 个微命令 → 2 位，4 个微命令 → 3 位），以测试学生对"无操作"状态的处理
3. **判别测试条件数**：2-5 个（P字段位数 = ⌈log₂(条件数+1)⌉）
4. **下地址字段**：题目给定下地址字段位数（范围 6-10 位），让学生据此计算控存最大微指令条数 = 2^(下地址位数)；或反过来给定微指令条数让学生反推位数
5. **一致性约束**：操作控制字段总位数 + P字段位数 + 下地址字段位数 = 微指令字长
6. **可调自由度**：互斥类具体分组方案、各组微命令数量、判别条件数、下地址位数均可由 Question Agent 在约束范围内自主确定

## 参考经验
- **历史模式**：微指令格式设计题通常以"给定互斥类→分段编码→算字长→算容量"为标准流程，是微程序控制器章节的高频考法
- **难度锚点**：K4 难度主要体现在"字段编码需预留无操作状态"这一隐含前提，历年考生常犯错误是直接用 ⌈log₂(微命令数)⌉ 而非 ⌈log₂(微命令数+1)⌉
- **典型陷阱**：① 忽略"无操作"状态导致位数少算；② 将控存容量直接用操作控制字段位数而非下地址字段位数来算；③ 漏掉判别测试字段导致字长算错
