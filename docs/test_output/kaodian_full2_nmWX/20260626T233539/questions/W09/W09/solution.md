# 指令流水线性能分析 — 求解

> 以下数值均由 gen.py 计算产出，逐字对照 exec 数据流输出。

---

## 基本参数

| 参数 | 值 |
|------|----|
| 段数 k | 5 |
| 各段时间 | IF=10, ID=10, EX=20, MEM=10, WB=10（单位 ns） |
| 瓶颈段 | EX = 20 ns |
| 指令条数 N | 200 |

---

## Q1（3分）

### （1）确定流水线周期 T

流水线周期由**瓶颈段**（各段时间最大值）决定：

$$T = \max(\Delta t_i) = \max(10, 10, 20, 10, 10) = 20 \text{ ns}$$

**依据**：各段在同一时钟周期内并行工作，流水线时钟必须迁就最慢的段，否则该段无法在单个周期内完成操作。因此 T = 瓶颈段时间 = 20 ns。

### （2）总执行时间

$$\text{总时间} = (k + N - 1) \times T = (5 + 200 - 1) \times 20 = 204 \times 20 = 4080 \text{ ns}$$

- 第 1 条指令需 5 个周期（k=5）才能走完全部段（**填充**阶段）。
- 之后每条指令只需 1 个周期（每周期流出 1 条）。
- 排空时间 = (k−1)×T = 4×20 = 80 ns，占比 = 80/4080 ≈ 1.96% < 5%。

> **总执行时间 = 4080 ns**

---

## Q2（3分）

### （1）实际吞吐率 TP

$$TP = \frac{N}{\text{总时间}} = \frac{200}{4080} = 0.04902 \text{ 条/ns} = 49.02 \text{ MIPS}$$

### （2）最大吞吐率 TP_max

$$TP_{\max} = \frac{1}{T} = \frac{1}{20} = 0.05 \text{ 条/ns} = 50.00 \text{ MIPS}$$

### （3）差距原因

实际吞吐率（49.02 MIPS）< 最大吞吐率（50.00 MIPS），TP/TP_max ≈ 0.9804。

**原因**：最大吞吐率假设流水线稳定运行（每周期恒流出 1 条指令）。但实际执行中，第一条指令需要 k=5 个周期才能通过全部段（**填充/排空阶段**），这 (k−1)=4 个周期没有指令流出，导致实际吞吐率低于理论最大值。当 N→∞ 时，排空占比趋近于 0，TP→TP_max。

---

## Q3（2分）

### 加速比 S

顺序执行时，每条指令需经过全部 5 段，单条时间 = ΣΔt = 10+10+20+10+10 = 60 ns。

$$\text{顺序执行总时间} = N \times \sum \Delta t_i = 200 \times 60 = 12000 \text{ ns}$$

$$S = \frac{\text{顺序时间}}{\text{流水线时间}} = \frac{12000}{4080} = 2.941$$

> **加速比 S ≈ 2.94**

**验证**：1 < S=2.94 < k=5（流水线优于顺序执行，但未达理想 k 倍加速，因各段时间不等、存在排空开销）。

---

## Q4（2分）

### （1）优化后指标

将瓶颈段 S₃（EX, 20 ns）拆分为 S₃ₐ 和 S₃ᵦ 各 10 ns，流水线变为 6 段、各段均为 10 ns。

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 段数 | k=5 | k'=6 |
| 流水线周期 | T=20 ns | **T'=10 ns** |
| 总执行时间 | 4080 ns | **(6+200−1)×10 = 2050 ns** |
| 吞吐率 | 49.02 MIPS | **200/2050 = 97.56 MIPS** |

计算：
- T' = max(各新段) = 10 ns
- 总时间' = (k'+N−1)×T' = (6+200−1)×10 = 2050 ns
- TP' = N/总时间' = 200/2050 = 0.09756 条/ns = **97.56 MIPS**

### （2）优化前后对比及段数对排空的影响

**吞吐率变化**：TP 从 49.02 → 97.56 MIPS，提升约 99%（接近翻倍）。原因是周期减半（T: 20→10 ns）使最大吞吐率翻倍（1/T': 50→100 MIPS），而段数仅增加 1 段，排空时间的微量增加远不抵周期减半带来的收益。

**段数对排空时间的影响**：

| | 优化前 | 优化后 |
|--|--------|--------|
| 排空时间 = (k−1)×T | 4×20 = 80 ns | 5×10 = 50 ns |
| 排空占比 | 80/4080 ≈ 1.96% | 50/2050 ≈ 2.44% |

段数增加（5→6）会使排空周期数从 4 增到 5（多 1 个周期），但由于周期 T' 同时减半（20→10 ns），排空的**绝对时间反而减少**（80→50 ns）。排空占比虽从 1.96% 略升至 2.44%，但影响极小。

> **结论**：段数增加会增多排空周期数（+1），但不会降低整体性能——瓶颈段消除带来的周期减半使总执行时间大幅缩短（4080→2050 ns），吞吐率近乎翻倍。排空时间的绝对值反而下降。
