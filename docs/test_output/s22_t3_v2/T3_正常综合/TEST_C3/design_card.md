## design_rationale

**考察意图**：
AVL树的插入与旋转是数据结构中"结构操作与状态维护模拟"考察模式的典型代表。本题选择此考点组合，是因为它天然具备多步串行推演的特性——每次插入都可能触发失衡，失衡后需定位失衡节点、计算平衡因子、判断旋转类型、执行旋转并更新整棵树的形态。这一过程完美契合K3（机制推演）和K4（条件路由）的平衡型要求。

**区分度设计**：
- 掌握程度浅的学生：能记住四种旋转的名称，但无法在动态插入过程中准确判断何时触发何种旋转
- 掌握程度中等的学生：能处理单一旋转场景，但在连续插入、多次失衡的场景下容易混淆LR/RL旋转的触发条件
- 掌握程度深的学生：能精准跟踪每次插入后的平衡因子变化，正确路由到对应的旋转类型，并维护旋转后的完整树形态

**难度合理性**：
难度4（K3-K4平衡型）要求推演步数>5步且需维持动态状态更新（K3高），同时隐含前提深、需依靠对机制本质的理解才能正确路由（K4高）。AVL插入旋转天然满足这两点：多节点插入产生长程推演链，而LR/RL旋转的触发条件（需区分是"左孩子的右子树过高"还是"右孩子的左子树过高"）是经典暗坑，必须理解平衡因子的本质含义才能正确判断。

**考点融合意图**：
本题融合同一知识点的两个核心考察项：
1. **旋转类型辨析**：LL/RR/LR/RL四种旋转的触发条件判断
2. **平衡因子计算与状态维护**：插入后各节点平衡因子的动态变化跟踪

融合方式：在子问链中，前问侧重插入后的失衡检测与平衡因子计算（状态维护），后问在此基础上要求判断旋转类型并推演旋转后的树形态（旋转辨析+形态更新）。两考察项在同一知识域内自然衔接，不强行拼凑。

## question_structure_plan

- 子问1：考AVL树插入操作后的失衡检测与平衡因子计算（基础层）
  - 给定初始AVL树和插入序列，要求跟踪插入过程中的平衡因子变化
  - 定位首次失衡节点，计算其平衡因子

- 子问2：基于子问1的失衡状态，考旋转类型判断与旋转后树形态推演（进阶层）
  - 根据失衡节点的平衡因子和子树结构，判断应执行的旋转类型
  - 推演旋转操作后的完整树形态

- 子问3：基于子问2的结果，考连续插入场景下的多轮失衡处理与旋转类型辨析（区分度层）
  - 继续插入新节点，可能触发第二次失衡
  - 要求辨析与前问不同的旋转类型（如前问为LL/RR，此问为LR/RL或反之）
  - 推演最终树形态

- dependency_pattern：串行依赖（前问的树形态作为后问的输入）

## terminology_and_expression_constraints
- 必须使用术语：平衡因子、失衡节点、LL旋转、RR旋转、LR旋转、RL旋转、最小不平衡子树
- 限定语要求：
  - 描述旋转时必须明确"以XX节点为根的最小不平衡子树"
  - 描述平衡因子时必须说明"左子树高度减右子树高度"或"右子树高度减左子树高度"（与教材定义一致）
- 禁止表述：
  - 不得使用"顺时针旋转/逆时针旋转"等模糊表述替代LL/RR/LR/RL
  - 不得省略"最小不平衡子树"而直接说"旋转XX节点"

## audit_focus
1. **K3-K4平衡性验证**：
   - 检查推演步数是否>5步（插入→失衡检测→平衡因子计算→旋转判断→形态更新→后续插入）
   - 检查是否存在隐含前提（如LR/RL旋转需区分"左孩子的右子树过高"vs"右孩子的左子树过高"）

2. **考点融合验证**：
   - 检查是否同时考察了"旋转类型辨析"和"平衡因子计算与状态维护"
   - 检查两考察项是否自然衔接而非强行拼凑

3. **干扰项设计方向**（供下游参考）：
   - 计算型干扰：平衡因子符号错误（左减右vs右减左混淆）、off-by-one（高度计算差1）
   - 概念型干扰：LR与RL旋转触发条件混淆、失衡节点定位错误（定位到父节点而非最小不平衡子树根）
   - 组合判断型干扰：多轮插入中某轮旋转类型判断错误导致后续全部错误

4. **should_not_be 合规检查**：
   - 确认不是纯概念记忆题（有推演过程）
   - 确认考察了至少两种不同类型的旋转场景

5. **难度4合规检查**：
   - 确认需要多步串行推演树的形态变化
   - 确认需要精准辨析四种旋转类型的触发条件
