## 出题契约

### 基本信息
- target_subject: 组成原理
- target_family: 组成原理 > CO-4 指令系统 > 指令格式 > 操作码编码 > 扩展操作码
- primary_target_name: 扩展操作码
- question_type: comprehensive（应用题）
- examination_mode: 计算型——扩展操作码数量计算

### 难度目标
- k_target: K1=3,K2=3,K3=2,K4=4,K5=1
- difficulty_level: 3
- difficulty_rationale: 扩展操作码需理解编码空间分配与预留前缀机制，K4 为主导区分维度；推演步数少故 K3 低；单知识点无跨域故 K5 低

### 结构要求
- sub_question_count: 2
- sub_question_details:
  - 第1问: 计算题, 3分, 某类指令最大可定义数量, 基本空间分配
  - 第2问: 计算+分析, 3分, 另一类可扩展指令最大数量, 预留前缀理解
- dependency: 第2问逻辑上依赖第1问的扩展框架（串行），但数值可独立计算
- distractor_strategy: N/A（主观题无干扰项，陷阱内嵌于题目条件的隐含预留要求中）
- condition_count: 3~4

### 参数约束
- 指令字长 L: 16~32 位, 偶数
- 每个地址码位数 a: 4~8 位, 满足 n×a < L（n 为地址码个数）
- 操作码位数 op: op = L - n×a, 由 L 和 a 隐含确定
- 扩展层级数: ≥2 级
- 已知某类指令数量 N: 1 ≤ N ≤ 2^op - 1（须预留 ≥1 个编码用于扩展）
- 一致性约束: 各级操作码位数之和 ≤ L; 每级预留 1 个前缀编码用于下一级扩展

### 参考经验摘要
- 历史模式: 2022_Q19 扩展操作码数量计算，给定指令格式和已知指令数，求可扩展指令数
- 难度锚点: K4=4（主导）, K1=3, K2=3, K3=2, K5=1
- 典型陷阱: 忽略高段编码须预留 1 个值作为下一级扩展前缀，直接用 2^op 计算导致多算
