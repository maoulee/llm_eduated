# 中断屏蔽字设计 —— 求解

## 参数

- 中断源：L₁、L₂、L₃、L₄、L₅（共 5 个）
- 响应优先级（高→低）：L₁ > L₂ > L₃ > L₄ > L₅
- 处理优先级（高→低）：L₃ > L₁ > L₂ > L₅ > L₄
- 对应处理优先级名次（rank 越小越高）：L₃=1, L₁=2, L₂=3, L₅=4, L₄=5
- 屏蔽位规则：$M_i = 1$ 屏蔽（禁止响应）$L_i$；$M_i = 0$ 允许响应 $L_i$
- 设置规则：处理优先级高于自身 → 位 = 0（允许）；不高于自身 → 位 = 1（屏蔽）；自身屏蔽位 = 1

---

## 问题 1：5×5 中断屏蔽字表

### 逐行推导

对每个中断源 $L_i$，逐一检查 $M_1$~$M_5$：

**L₁（处理优先级 rank=2，仅低于 L₃）：**
- M₁=1（自身屏蔽位）
- M₂=1（L₂ 处理优先级不高于 L₁，屏蔽）
- M₃=0（L₃ 处理优先级高于 L₁，允许）
- M₄=1（L₄ 处理优先级不高于 L₁，屏蔽）
- M₅=1（L₅ 处理优先级不高于 L₁，屏蔽）
- → **L₁：1 1 0 1 1**

**L₂（处理优先级 rank=3，低于 L₃ 和 L₁）：**
- M₁=0（L₁ 处理优先级高于 L₂，允许）
- M₂=1（自身屏蔽位）
- M₃=0（L₃ 处理优先级高于 L₂，允许）
- M₄=1（L₄ 处理优先级不高于 L₂，屏蔽）
- M₅=1（L₅ 处理优先级不高于 L₂，屏蔽）
- → **L₂：0 1 0 1 1**

**L₃（处理优先级 rank=1，最高，无更高者）：**
- M₁=1（L₁ 处理优先级不高于 L₃，屏蔽）
- M₂=1（L₂ 处理优先级不高于 L₃，屏蔽）
- M₃=1（自身屏蔽位）
- M₄=1（L₄ 处理优先级不高于 L₃，屏蔽）
- M₅=1（L₅ 处理优先级不高于 L₃，屏蔽）
- → **L₃：1 1 1 1 1**

**L₄（处理优先级 rank=5，最低，所有其他中断源均高于它）：**
- M₁=0（L₁ 处理优先级高于 L₄，允许）
- M₂=0（L₂ 处理优先级高于 L₄，允许）
- M₃=0（L₃ 处理优先级高于 L₄，允许）
- M₄=1（自身屏蔽位）
- M₅=0（L₅ 处理优先级高于 L₄，允许）
- → **L₄：0 0 0 1 0**

**L₅（处理优先级 rank=4，仅高于 L₄）：**
- M₁=0（L₁ 处理优先级高于 L₅，允许）
- M₂=0（L₂ 处理优先级高于 L₅，允许）
- M₃=0（L₃ 处理优先级高于 L₅，允许）
- M₄=1（L₄ 处理优先级不高于 L₅，屏蔽）
- M₅=1（自身屏蔽位）
- → **L₅：0 0 0 1 1**

### 完整屏蔽字表

| 中断源 | M₁ | M₂ | M₃ | M₄ | M₅ |
|--------|----|----|----|----|----|
| L₁     | 1  | 1  | 0  | 1  | 1  |
| L₂     | 0  | 1  | 0  | 1  | 1  |
| L₃     | 1  | 1  | 1  | 1  | 1  |
| L₄     | 0  | 0  | 0  | 1  | 0  |
| L₅     | 0  | 0  | 0  | 1  | 1  |

## 问题 2：中断处理顺序

### 到达时序

| 时刻  | 事件 |
|-------|------|
| t = 0 | L₄ 请求到达，CPU 响应并开始执行 L₄ |
| t = t₁| L₂ 请求到达 |
| t = t₂| L₁ 请求到达 |
| t = t₃| L₃ 请求到达 |

### 逐步分析

**t = 0：L₄ 请求到达**
- CPU 直接响应 L₄，开始执行 L₄ 的中断服务程序。
- 执行栈：L₄

**t = t₁：L₂ 请求到达**
- 当前正在执行 L₄，其屏蔽字为 **0 0 0 1 0**。
- 检查 M₂（L₂ 的屏蔽位）= **0**（允许）。
- L₂ 中断 L₄，开始执行。
- 执行栈：L₄ → L₂

**t = t₂：L₁ 请求到达**
- 当前正在执行 L₂，其屏蔽字为 **0 1 0 1 1**。
- 检查 M₁（L₁ 的屏蔽位）= **0**（允许）。
- L₁ 中断 L₂，开始执行。
- 执行栈：L₄ → L₂ → L₁

**t = t₃：L₃ 请求到达（关键陷阱）**
- 当前正在执行 L₁，其屏蔽字为 **1 1 0 1 1**。
- 检查 M₃（L₃ 的屏蔽位）= **0**（允许）。
- **关键**：L₃ 的响应优先级排第 3，低于当前正在执行的 L₁（响应优先级第 1）。按响应优先级判断，L₃ 不应中断 L₁。但 L₃ 的**处理优先级排第 1（最高）**，L₁ 的屏蔽字中 M₃=0（允许 L₃），因此 **L₃ 必须中断 L₁**。
- L₃ 中断 L₁，开始执行。
- 执行栈：L₄ → L₂ → L₁ → L₃

**逐层完成：**
- L₃ 是处理优先级最高的中断源（屏蔽字全 1），不会被任何中断打断。L₃ 执行完毕，返回到 L₁。
- L₁ 恢复执行后，剩余挂起的中断源中无更高处理优先级者（L₂、L₄ 均被 L₁ 的屏蔽字屏蔽），L₁ 执行完毕，返回到 L₂。
- L₂ 恢复执行，无更高处理优先级者被允许（L₄ 被 L₂ 屏蔽），L₂ 执行完毕，返回到 L₄。
- L₄ 执行完毕，返回 CPU。

### 结论

**执行（开始）顺序：L₄ → L₂ → L₁ → L₃**

**完成顺序：L₃ → L₁ → L₂ → L₄**

嵌套关系：L₃ 中断 L₁，L₁ 中断 L₂，L₂ 中断 L₄。

**判断依据**：每个新到达的中断请求是否中断当前正在执行的中断源，取决于当前执行中断源的屏蔽字中该请求对应位是否为 0（允许），而非响应优先级的高低。完成顺序按处理优先级从高到低：L₃（rank 1）→ L₁（rank 2）→ L₂（rank 3）→ L₄（rank 5），与屏蔽字表完全一致。
