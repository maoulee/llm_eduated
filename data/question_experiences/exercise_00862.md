# 练习题 Q1 — IP分片与重组机制

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/网络层
- **难度**: 待评估

## 题干原文
考虑三个 IP 网络 A、B 和 C。网络 A 中的主机 HA 向网络 C 中的主机 HC 发送消息，每条消息包含 180 字节的应用层数据。TCP 层在消息前添加 20 字节的头部。该消息通过中间网络 B 传输。每个网络的最大分组大小（包括 20 字节的 IP 头部）为：
A : 1000 字节
B : 100 字节
C : 1000 字节
网络 A 与 B 通过 1 Mbps 链路连接，而 B 与 C 通过 512 Kbps 链路连接（bps = bit/s）。假设分组正确交付，在最佳情况下，一个应用层消息到达目的地时，IP 层总共接收多少字节（含头部）？仅考虑数据分组。（ ）
------------- 1 Mbps ------------- 512 Kbps -------------
| network A |----------------| network B |------------------| newtork C |
------------- ------------- -------------

- 选项:
  A: 200
  B: 220
  C: 240
  D: 260
- 正确答案: D
- 解析（参考）: 网络 B 从网络 A 接收到 220 字节的数据（180 字节应用层数据 + 20 字节 TCP 头部 + 20 字节 IP 头部）。由于网络 B 的最大分组大小为 100 字节（80 字节数据 + 20 字节 IP 头部），对于网络 B 来说，220 字节中 200 字节是数据或有效载荷（180 字节应用层数据 + 20 字节 TCP 头部），20 字节是 IP 头部。网络 B 移除 20 字节的 IP 头部后，剩余 200 字节数据。它使用其中 80 字节数据，因此第一个离开 B 的分组为 100 字节（数据 80 字节，IP 头部 20 字节）。此时剩余 120 字节数据，第二个分组同样

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 IP 分片的基本概念（MTU、IP 头部开销、分片字段），属于标准的核心定义记忆。不是 4 分因为不需要辨析多个易混的高级概念，只需知道“分片时 IP 头部会重新添加”这一基本规则。
- **K2 = 3**: 评分理由。涉及简单的加减法和除法（200/80），计算量不大，但需要处理非 2 的幂次对齐问题（虽然本题数据恰好整除，但逻辑上需考虑对齐），属于标准计算难度。
- **K3 = 4**: 评分理由。推演步骤较多：1. 计算 A 发出的总包大小；2. 判断 A 到 B 是否需要分片（不需要）；3. 路由器 B 接收后去 IP 头；4. 根据 B 的 MTU 计算 B 发出的分片数量及每个分片的大小；5. 判断 B 到 C 是否需要再次分片（不需要）；6. 汇总 C 接收到的总字节数。超过 5 步且需记忆中间状态（剩余数据量），故为 4 分。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。1. “IP 层总共接收”指的是目的主机 IP 层接收到的所有分片之和，而非重组后的原始数据。2. 必须意识到路由器 B 在转发时会**剥离**旧的 IP 头部并**添加**新的 IP 头部，导致总字节数增加。3. 必须忽略链路带宽（1Mbps/512Kbps）这一干扰信息。这些隐含条件若未识别，极易出错。
- **K5 = 3**: 评分理由。涉及网络层（IP）与传输层（TCP）数据的封装关系，以及不同网络段（A-B, B-C）之间的状态传递。属于单向传数据并伴随协议头变化的场景。

- **雷达形状**: K4 陷阱型（高条件路由需求，伴随中高推演需求）

## 考察模式
- **模式**: 综合型
- **理由**: 本题结合了概念理解（IP 分片机制）、流程推演（跨网络传输过程）和细节计算（头部开销累加）。它不是单纯的公式代入，也不是纯概念辨析，而是要求考生在模拟网络传输过程中，准确追踪数据包的形态变化。

## 选项级分析
- **选项 A (200)**: [干扰] — 针对“忽略 IP 头部开销”的错误认知。学生可能只计算了应用层数据（180）+ TCP 头（20）= 200，或者认为分片后总数据量不变且忽略了新增的 IP 头。这类学生通常不理解 IP 分片会导致头部冗余。
- **选项 B (220)**: [干扰] — 针对“无分片”或“仅计算原始包”的错误认知。学生计算出 A 发出的包大小（180+20+20=220），并认为中间网络 B 只是透传，没有发生分片，或者认为分片不增加总字节数。这类学生忽略了网络 B 的 MTU 限制（100 字节 < 220 字节）。
- **选项 C (240)**: [干扰] — 针对“分片数量计算错误”或“对齐错误”的认知。例如，学生可能认为 200 字节数据分成 3 个包（80+80+40），但错误地计算头部，或者误以为最后一个包也需要完整的 100 字节（200+20*3=260? 不对，240 可能是 200 数据 + 2 个头？逻辑不通，更可能是误算为 2 个分片但头部计算错误，或者认为 200/100=2 个包，2*100+20=220? 也不对。最可能的错误路径是：认为分片后总大小 = 原始数据 200 + 2 个 IP 头 40 = 240？这忽略了第一个分片也带头。或者误以为 200 字节数据，每片 100 字节（含头），则数据部分 80，200/80=2.5 -> 3 片？3*100=300? 不对。另一种可能是：学生算出 3 个分片，但认为只有最后两个有头？或者误将 MTU 当作纯数据载荷。实际上，240 是一个较弱的干扰项，可能源于对分片后总字节数的粗略估算错误，如 200(数据) + 20(原头) + 20(新头) = 240，即认为只增加了一个头。）
- **选项 D (260)**: [正确] — 正确计算了分片后的总字节数。200 字节有效载荷，MTU 100（数据 80），需 3 个分片（80+80+40 数据）。每个分片加 20 字节 IP 头。总大小 = 3 * (20 + 数据部分) = 3 * 100 (前两包) + (20 + 40) (第三包) = 100 + 100 + 60 = 260 字节。

- **干扰策略**: 渐进陷阱。从最简单的原始包大小（220）到忽略头部（200），再到部分理解分片但计算错误（240），最后到正确理解分片机制及头部累加（260）。

## 核心陷阱
- **核心陷阱**: **IP 分片导致的头部冗余累加**与**干扰信息屏蔽**。
    1.  **头部累加**: 许多学生误以为分片只是切割数据，总字节数不变。实际上，每个分片都需要独立的 IP 头部，导致总传输字节数增加。本题中，200 字节数据被分为 3 个分片，产生了 3 个 IP 头部（共 60 字节），而非原始的 1 个头部（20 字节）。
    2.  **干扰信息**: 题干给出的链路带宽（1 Mbps, 512 Kbps）是典型的干扰项，用于测试学生是否能区分“传输延迟/吞吐量”与“协议开销/字节数”这两个无关概念。
    3.  **MTU 定义**: 必须明确 MTU 包含 IP 头部。网络 B 的 MTU 为 100 字节，意味着每个分片的数据载荷最大为 80 字节。

## 考察能力
本题核心考察考生对 **IP 分片机制中头部开销变化** 的深入理解，以及在复杂网络拓扑中**排除干扰信息、精确追踪数据包状态**的综合分析能力。
