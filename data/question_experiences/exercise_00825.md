# 练习题 Q1 — 指令级并行与数据依赖分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 计算机组成原理/流水线
- **难度**: 待评估

## 题干原文
考虑以下包含五条指令 I1 到 I5 的代码序列。每条指令的格式为：
OP Ri, Rj, Rk
其中操作
OP
对寄存器 Rj 和 Rk 的内容进行运算，结果存储在寄存器 Ri 中。
I1 : ADD R1, R2, R3
I2 : MUL R7, R1, R3
I3 : SUB R4, R1, R5
I4 : ADD R3, R2, R4
I5 : MUL R7, R8, R9
考虑以下三个陈述：
S1: 指令 I2 和 I5 之间存在反向依赖（anti-dependence）。
S2: 指令 I2 和 I4 之间存在反向依赖。
S3: 在指令流水线中，反向依赖总是会导致一个或多个停顿（stall）。
上述陈述中哪些是正确的？（ ）
- 选项:
  A: 仅 S1 正确
  B: 仅 S2 正确
  C: 仅 S1 和 S2 正确
  D: 仅 S2 和 S3 正确
- 正确答案: B
- 解析（参考）: 给出的指令可以表示为：
I1: R1 = R2 + R3
I2: R7 = R1 * R3
I3: R4 = R1 - R5
I4: R3 = R2 + R4
I5: R7 = R8 * R9
反向依赖（Anti-dependence）定义
反向依赖（也称为写后读，WAR）是指某条指令需要某个值，但该值随后被更新的情况。
陈述分析
S1
: 指令 I2 和 I5 之间存在反向依赖。
❌ 错误。I2 和 I5 都写入 R7，不存在读后写的情况。
S2
: 指令 I2 和 I4 之间存在反向依赖。
✅ 正确。I2 读取 R3，而 I4 写入 R3。
S3
: 在指令流水线中，反向依赖总是导致停顿。
- 知识标签: ['计算机组成原理/流水线']
- 知识域: CO-1

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。本题需要精确区分三种数据依赖类型：真依赖（RAW）、反向依赖（WAR）和输出依赖（WAW）。考生不仅需记忆定义，还需辨析易混概念（如S1中的WAW误判为WAR，S3中的硬件机制误解）。若仅记忆一个核心定义（K3）不足以解题，必须辨析多个易混概念，故评为4。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行算术或逻辑运算，仅涉及逻辑判断，故为微弱。
- **K3 = 3**: 评分理由。解题过程需要多步串行推演：第一步解析指令格式确定读写寄存器；第二步针对S1、S2、S3分别提取相关指令的读写集合；第三步比对集合判断依赖类型；第四步结合流水线技术（如寄存器重命名）判断S3的真伪。步骤在3-5步之间，且需保持中间状态（寄存器读写关系），故评为3。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。S3的陷阱在于“总是”二字，考生必须意识到现代流水线技术（如寄存器重命名）可以消除WAR依赖导致的停顿，这是题面未直接说明但解题必须意识到的深层条件。S1的陷阱在于混淆WAW和WAR。这种反直觉（WAR不一定导致停顿）和隐含前提（重命名技术）使得条件路由需求较高，故评为4。
- **K5 = 2**: 评分理由。本题主要局限于指令级并行（ILP）和流水线这一单一子系统内部。虽然涉及寄存器文件，但未跨越到内存管理、中断处理等其他子系统，仅提及无关或单向影响，故评为较低。
- **雷达形状**: K4陷阱型（K1和K4较高，K2极低，呈现不对称的陷阱特征）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非简单的概念回忆（概念型），也不是数值计算（计算型）。它要求考生根据给定的指令序列，运用数据依赖的定义进行逻辑推导，并结合计算机体系结构的深层机制（寄存器重命名）对陈述的真伪进行推理判断。

## 选项级分析
- **选项A**: [干扰] — 针对错误认知：混淆WAW（输出依赖）与WAR（反向依赖）。这类学生看到I2和I5都写R7，误以为这是“写后读”或某种依赖，或者错误地认为I2读R3而I5写R7（无关联）却强行关联。更可能的是，他们正确判断了S2错误（或没看清），但错误地认为S1正确（将WAW误判为WAR），从而排除B。
- **选项B**: [正确] — 正确识别了S2为WAR依赖（I2读R3，I4写R3），并正确识别S1为WAW（非WAR），且正确识别S3错误（WAR可通过重命名消除停顿）。
- **选项C**: [干扰] — 针对错误认知：同时混淆WAW与WAR，且未意识到S3的错误。这类学生认为I2和I5的WAW也是某种“反向”依赖，或者对依赖类型定义模糊，认为只要涉及同一寄存器就有依赖。同时，他们可能认为WAR必然导致停顿，从而认为S3也正确（但选项C只选S1和S2，说明他们可能认为S3错，但S1对）。更常见的情况是，学生正确判断S2，错误判断S1（认为WAW是WAR），并错误判断S3（认为WAR必停顿，但选项C不含S3，这逻辑不通）。实际上，选C的学生通常认为S1对（WAW=WAR），S2对，S3错。
- **选项D**: [干扰] — 针对错误认知：正确识别S2，但错误认为S3正确。这类学生知道WAR的定义，但缺乏对现代流水线优化技术（寄存器重命名）的了解，认为任何数据依赖都会导致流水线冒险和停顿。这是典型的“理论脱离实际”或知识更新不足的错误。

- **干扰策略**: 概念混淆（WAW vs WAR）与 机制误解（WAR是否必导致停顿）相结合。通过S1测试基础定义辨析，通过S3测试深层机制理解。

## 核心陷阱
- **核心陷阱**: S3中的“总是”一词。许多考生知道WAR（写后读）是一种数据冒险，在经典5段流水线中若不加处理会导致停顿。但现代处理器普遍采用**寄存器重命名（Register Renaming）**技术来消除WAR和WAW依赖，因此WAR**并不总是**导致停顿。这是区分基础记忆与深度理解的关键点。

## 考察能力
本题核心考察考生对指令级并行中数据依赖类型（RAW, WAR, WAW）的精确辨析能力，以及对现代流水线技术（如寄存器重命名）如何消除特定依赖冒险的理解能力。
