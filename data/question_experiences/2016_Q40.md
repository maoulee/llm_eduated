# 2016 Q40 — DNS迭代查询次数极值分析

## 基本信息
- **年份**: 2016  **题位**: Q40  **题型**: 选择题
- **知识点**: CN-6 > 应用层 > 域名系统 DNS > 域名解析过程
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
假设所有域名服务器均采用迭代查询方式进行域名解析。当 H4 访问规范域名为 www.abc.xyz.com 的网站时，域名服务器 201.1.1.1 在完成该域名解析过程中，可能发出 DNS 查询的最少和最多次数分别是（ ）。

A. 0，3
B. 1，3
C. 0，4
D. 1，4

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆DNS解析的基本概念，特别是“迭代查询”与“递归查询”的区别，以及DNS服务器的层级结构（根、顶级、权威）。不是4分因为不需要辨析极其细微的协议字段差异，核心定义清晰。
- **K2 = 1**: 评分理由。本题不涉及数值计算，仅涉及步骤计数，属于最基础的逻辑计数，无计算错误风险。
- **K3 = 3**: 评分理由。需要推演两种极端情况下的查询路径。最少情况需判断缓存命中逻辑；最多情况需按层级（本地->根->TLD->权威）逐步推演查询流向，涉及3-4步逻辑串联。
- **K4 = 4**: 评分理由。存在显著的隐含前提和易错点。首先，题目问的是“域名服务器 201.1.1.1”发出的查询，而非主机H4发出的查询，这要求考生明确主体转换。其次，“最少0次”依赖于对“缓存”这一隐含状态的识别，若忽略缓存机制极易误判为至少1次。这是典型的隐含前提深陷阱。
- **K5 = 2**: 评分理由。主要局限于DNS应用层子系统内部，虽然涉及主机与服务器交互，但状态传递简单，不涉及跨层（如TCP/IP联动）或复杂的状态机耦合。
- **雷达形状**: K4陷阱型（K4显著突出，K1中等，其余较低）

## 考察模式
- **模式**: 推理型
- **理由**: 题目并非直接考查定义记忆，而是要求考生基于“迭代查询”规则，构建“最少”和“最多”两种边界场景的逻辑模型，并通过推演得出具体数值。

## 选项级分析
- **选项A**: [干扰] — 针对“最少次数”的错误认知。选A的学生可能认为即使有缓存，本地DNS服务器也必须向某处确认，或者混淆了主机查询和服务器查询的主体，认为最少也要查一次根服务器。
- **选项B**: [干扰] — 针对“最少次数”和“最多次数”的双重错误。选B的学生通常忽略了“缓存命中”的可能性（认为最少1次），同时在计算最多次数时，可能漏掉了向“根域名服务器”的查询，或者误以为本地DNS服务器直接知道顶级域名服务器地址。
- **选项C**: [正确] — 正确识别了缓存命中时本地DNS无需外发查询（0次），以及在完全无缓存且严格迭代查询下，本地DNS需依次查询根、顶级、权威服务器（3次？不，参考解析指出是4次，这里需仔细核对参考解析逻辑。参考解析说：本地->根->TLD->权威。注意：题目问的是**域名服务器201.1.1.1**发出的查询。
    *   *修正分析*：参考解析中“最多发出4次”的逻辑是：本地DNS(201.1.1.1) -> 根 -> .com -> xyz.com -> abc.xyz.com。
    *   让我们重新梳理层级：
        1.  域名：www.abc.xyz.com
        2.  根服务器 (.)
        3.  顶级域名服务器 (.com)
        4.  二级域名服务器 (xyz.com) —— *注意：xyz.com 是二级域名，abc.xyz.com 是三级域名*
        5.  权威域名服务器 (abc.xyz.com)
    *   查询路径（迭代）：
        1.  201.1.1.1 问 根服务器：.com 在哪？ (1次)
        2.  201.1.1.1 问 .com 服务器：xyz.com 在哪？ (2次)
        3.  201.1.1.1 问 xyz.com 服务器：abc.xyz.com 在哪？ (3次)
        4.  201.1.1.1 问 abc.xyz.com 服务器：www.abc.xyz.com 的IP是多少？ (4次)
    *   因此最多是4次。最少是0次（缓存命中）。
- **选项D**: [干扰] — 针对“最少次数”的错误认知。选D的学生正确计算了最多次数（4次），但错误地认为最少次数至少为1次（忽略了本地DNS缓存可能直接返回结果，无需向外发送查询请求）。

**干扰策略**: 概念混淆（主体混淆：主机vs服务器）、隐含条件遗漏（缓存机制）、层级计数错误（漏算根或顶级）。

## 核心陷阱
1.  **查询主体陷阱**：题目问的是“域名服务器 201.1.1.1”发出的查询次数，而不是主机 H4 发出的查询次数。主机 H4 向本地 DNS 发起请求不算作 DNS 服务器发出的查询。
2.  **缓存机制陷阱**：在计算“最少”次数时，必须考虑到本地 DNS 服务器缓存中可能已经存在该域名的记录，此时无需向任何外部服务器发起查询，次数为 0。许多考生会默认至少需要查询一次根服务器。
3.  **域名层级陷阱**：域名 `www.abc.xyz.com` 的层级结构为：根 -> .com -> xyz.com -> abc.xyz.com。在迭代查询中，本地 DNS 需要依次询问根、.com、xyz.com、abc.xyz.com 这四台服务器，因此最多为 4 次。容易漏掉根服务器或混淆 xyz.com 和 abc.xyz.com 的层级关系。

## 考察能力
本题核心考察考生对 DNS 迭代查询机制的深层理解，特别是能够区分查询主体、识别缓存对查询次数的影响，并准确推演多级域名解析的完整路径。
