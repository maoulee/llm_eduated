# 练习题 Q1 — 死锁避免与安全序列判定

## 基本信息
- **来源**: 练习题  **题型**: 选择题

- **知识点**: 操作系统/死锁

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握银行家算法的核心概念（最大需求、已分配、可用资源、安全序列），属于标准的基础概念记忆。不是4分因为不需要辨析多个易混概念（如死锁检测与避免的区别），只需应用单一算法。
- **K2 = 3**: 评分理由。涉及简单的加减法运算（计算Need矩阵，计算Available资源变化）。虽然不是2的幂次友好型计算，但数值较小，单步计算出错概率低，属于标准计算难度。
- **K3 = 4**: 评分理由。需要在明确规则下进行多步串行推演。从初始状态开始，尝试P4，更新状态；再尝试P3，更新状态；再尝试P1，更新状态；最后P2。每一步都依赖上一步的结果，且需要记忆中间状态（Available资源的变化），步骤超过3步，符合4分标准。
- **K4 = 3**: 评分理由。存在常规注意点，即“最大需求”与“还需要多少资源（Need）”的区别。题目给出的是Max和Allocation，考生必须先计算Need = Max - Allocation。这是一个常见的隐含前提，若直接拿Max与Available比较则会出错，属于陷阱词/隐含前提中等难度。
- **K5 = 1**: 评分理由。本题仅涉及操作系统内部的资源管理模块，不涉及文件系统、内存管理或网络等其他子系统的状态传递，属于单系统内部逻辑。

- **雷达形状**: K3推演主导型，K4陷阱辅助型。整体呈现中间高（推演和陷阱），两头低（基础记忆和跨域联动）的特征。

## 考察模式
- **模式**: 推理型
- **理由**: 本题不仅仅是简单的公式代入，而是要求考生模拟操作系统调度器的行为，通过假设-验证-更新状态的逻辑链条，推导出系统是否存在一个可行的执行序列。核心在于逻辑推演而非单纯计算。

## 选项级分析
- **选项A**: [干扰] — 针对认为系统处于死锁状态或无法找到安全序列的错误认知。这类学生可能在计算Need时出错，或者在推演过程中过早放弃（例如发现P1、P2当前无法满足就认为死锁，忽略了P4、P3可以先执行）。
- **选项B**: [干扰] — 针对未正确计算Need矩阵或推演顺序错误的认知。如果考生直接用Max与Available比较，P1(8)>2, P2(9)>2, P3(5)>2, P4(3)>2，所有进程都无法启动，从而误选A；或者如果考生错误地认为P1可以先运行（可能误算Need），则会选B。更可能的情况是，考生知道要算Need，但在推演时顺序混乱，或者误以为P1的Need(5)可以在后续某个时刻满足而强行将其排在前面，导致逻辑断裂。
- **选项C**: [正确] — 正确执行了银行家算法。
    1. 计算Need: P1=5, P2=5, P3=3, P4=2。
    2. 初始Available = 12 - (3+4+2+1) = 2。
    3. 检查P4: Need(2) <= Available(2)，可行。P4执行完毕，释放资源1，Available = 2 + 1 = 3。
    4. 检查P3: Need(3) <= Available(3)，可行。P3执行完毕，释放资源2，Available = 3 + 2 = 5。
    5. 检查P1: Need(5) <= Available(5)，可行。P1执行完毕，释放资源3，Available = 5 + 3 = 8。
    6. 检查P2: Need(5) <= Available(8)，可行。P2执行完毕，释放资源4，Available = 8 + 4 = 12。
    7. 序列 P4→P3→P1→P2 成立。
- **选项D**: [干扰] — 针对推演顺序错误的认知。P2的Need为5，初始Available为2，P2无法首先执行。选择此选项的学生可能忽略了初始资源不足的限制，或者错误地计算了P2的Need。

- **干扰策略**: 计算陷阱（Need vs Max）与 顺序陷阱（未满足条件强行排序）。

## 核心陷阱
- **核心陷阱**: **混淆“最大需求（Max）”与“还需资源（Need）”**。
    题目给出的是Max和Allocation，考生必须首先计算 `Need[i] = Max[i] - Allocation[i]`。如果直接用Max与Available比较，会发现所有进程的Max都大于初始Available(2)，从而错误地得出“系统不安全”或“无安全序列”的结论（选A）。此外，另一个陷阱是**推演过程中的状态更新**，即每执行完一个进程，Available资源必须加上该进程已分配的资源，很多考生容易忘记累加释放的资源，导致后续进程判断错误。

## 考察能力
本题核心考察考生运用**银行家算法**进行**死锁避免**分析的能力，具体包括正确计算资源需求矩阵、模拟资源分配与释放过程以及寻找安全序列的逻辑推演能力。
