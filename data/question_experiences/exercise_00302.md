# 练习题 Q1 — DNS协议传输层选择机制

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
通常 TCP 是可靠的，而 UDP 不可靠。DNS 需要可靠性却使用 UDP 的原因是（ ）：

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆 DNS 协议的基本特性（默认使用 UDP，端口 53）以及 TCP/UDP 的核心区别。不是 2 分因为仅靠直觉无法判断，需调用“DNS 报文大小限制”这一具体知识点；不是 4 分因为不需要辨析多个易混概念，只需回忆标准协议行为。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，属于纯概念性判断。
- **K3 = 2**: 评分理由。推演步骤较少：1. 识别 DNS 对速度和延迟敏感；2. 识别 DNS 报文通常很小（<512字节）；3. 结合 UDP 无连接、开销小的特点得出结论。无需多步串行逻辑推演。
- **K4 = 3**: 评分理由。存在隐含前提和反直觉陷阱。题干强调“DNS 需要可靠性”，这容易诱导学生认为必须使用 TCP（因为 TCP 可靠）。解题必须意识到“可靠性”在 DNS 语境下可以通过应用层重传机制弥补，且“速度/开销”优于“传输层可靠性”。这是一个典型的条件路由陷阱，需避开“可靠=TCP”的思维定势。
- **K5 = 2**: 评分理由。主要涉及传输层（TCP/UDP）与应用层（DNS）之间的接口关系。虽然涉及跨层，但逻辑是单向的（应用层需求决定传输层选择），不涉及复杂的状态互影响或深度耦合。
- **雷达形状**: K4 陷阱型（K4 显著高于 K2/K3，K1 中等，整体呈现对概念辨析和陷阱识别要求较高的特征）

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心在于考察学生对网络协议设计原则（权衡可靠性与效率）以及特定协议（DNS）工作机制的理解，而非计算或复杂逻辑推理。

## 选项级分析
- **选项A**: [干扰] — 针对“UDP 性能误解”。这类学生可能错误地认为 UDP 比 TCP 慢，或者混淆了“速度”与“可靠性”的关系。实际上 UDP 通常比 TCP 快（无握手、无拥塞控制），且速度慢绝不是选择 UDP 的理由。
- **选项B**: [干扰] — 针对“连接状态误解”。这类学生可能误以为 DNS 服务器需要保持长连接以维持状态。实际上 DNS 是无状态的，且 UDP 本身是无连接的，TCP 才需要保持连接。此选项与 UDP 的特性完全背道而驰。
- **选项C**: [正确] — 针对“协议开销与报文大小匹配”。DNS 查询和响应报文通常很小（传统限制为 512 字节），使用 UDP 可以避免 TCP 三次握手和头部开销，显著降低延迟。这是选择 UDP 的核心工程原因。
- **选项D**: [干扰] — 针对“不确定型”。当学生无法确定具体原因时，容易选择此项。
- **干扰策略**: 概念混淆。利用“可靠性”这一关键词制造认知冲突，诱导学生忽略“效率/开销”这一更关键的决策因素。

## 核心陷阱
- **核心陷阱**: **“可靠性”定义的语境陷阱**。题干指出“DNS 需要可靠性”，容易让学生陷入“只有 TCP 才能提供可靠性”的思维定势。实际上，DNS 通过应用层简单的重传机制即可满足可靠性需求，而 UDP 的低开销和高速度对于频繁、小数据的 DNS 查询更为重要。陷阱在于未能权衡“传输层可靠性”与“应用层效率”之间的取舍。

## 考察能力
一句话概括本题核心考察的能力：理解网络协议设计中可靠性与效率的权衡原则，以及 DNS 协议基于报文大小和延迟敏感性选择 UDP 的根本原因。
