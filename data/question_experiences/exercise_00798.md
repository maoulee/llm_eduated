# 练习题 Q1 — 临界区算法正确性分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/死锁
- **难度**: 待评估

## 题干原文
考虑以下针对临界区问题的解决方案。共有 $n$ 个进程：$P_0, P_1, \dots, P_{n-1}$。在代码中，函数 $pmax$ 返回一个不小于其任何参数的整数。对于所有 $i$，$t[i]$ 被初始化为零。关于上述解决方案，以下哪一项是正确的？（ ）

```c
do {
    c[i] = 1;
    t[i] = pmax(t[0], ..., t[n-1]) + 1;
    c[i] = 0;
    for every j != i in {0, ..., n-1} {
        while (c[j]);
        while (t[j] != 0 && t[j] <= t[i]);
    }
    Critical Section;
    t[i] = 0;
    Remainder Section;
} while (true);
```

- 选项:
  A: 任何时候最多只有一个进程可以在临界区中
  B: 满足有界等待条件
  C: 满足进展条件
  D: 不会导致死锁
- 正确答案: A
- 解析（参考）: 解析
互斥性分析
互斥性得到满足
：所有在进程
i
之前启动的其他进程
j
必须具有较小的值（即
t[j] < t[i]
），因为函数
pMax()
返回一个不小于其任何参数的整数。
执行机制
：当
j

t[j]

0
；随后循环会选择下一个进程。因此，当
i

i
进程之前启动的进程

都不在其临界区中。
结论
：同一时间只有一个进程在执行其临界区。

- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。需要深入理解临界区问题的三个核心条件（互斥、进展、有界等待）以及死锁的定义。不仅仅是记忆概念，还需要辨析“互斥”与“无死锁/有进展”之间的细微差别。不是3分因为仅靠定义无法判断代码逻辑，需结合算法机制。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行算术运算或单位换算。
- **K3 = 5**: 评分理由。需要在脑海中模拟多进程并发执行的复杂时序。特别是需要推演当两个进程几乎同时执行 `t[i] = pmax(...) + 1` 时，由于内存访问的原子性假设缺失或竞争条件，可能导致 `t[i] == t[j]` 的情况，进而推演后续的 `while` 循环行为。步骤多且需记忆中间状态（如 `c` 数组和 `t` 数组的状态变化）。
- **K4 = 5**: 评分理由。存在极强的反直觉陷阱。通常考生认为“互斥算法”默认就是“无死锁”的。但本题的核心陷阱在于：该算法虽然保证了互斥，但在特定竞争条件下（`t[i] == t[j]`）会导致死锁，从而违反进展条件。识别出“互斥成立但死锁可能发生”这一隐含前提需要极高的洞察力。
- **K5 = 3**: 评分理由。主要涉及进程间通过共享变量（`c` 和 `t` 数组）进行状态传递和同步。属于典型的单系统内进程同步问题，不涉及跨子系统（如文件系统、网络）的深度耦合，但状态互影响明显。
- **雷达形状**: K3/K4 双高峰型（高推演、高陷阱），K2 极低。

## 考察模式
- **模式**: 推理型
- **理由**: 题目给出一段具体的并发控制代码，要求考生通过逻辑推演判断其是否满足临界区问题的各项性质。重点不在于背诵结论，而在于分析代码执行流在并发环境下的行为。

## 选项级分析
- **选项A**: [正确] — 针对互斥性的正确认知。只要 `t[i]` 是严格递增的（在正常无竞争或竞争后重新获取更大值的情况下），或者即使发生竞争导致相等，`while (t[j] != 0 && t[j] <= t[i])` 会阻塞直到对方释放（`t[j]=0`）。实际上，如果 `t[i] == t[j]`，两者都会阻塞对方，导致死锁，但在死锁发生前，确实没有两个进程能*同时*进入临界区（因为进入前必须通过检查）。更严谨地说，互斥性是指“如果P在CS中，Q不能在CS中”。该算法通过 `t` 值的比较和 `c` 标志位确保了这一点。即使死锁发生，也是阻塞在入口，而非同时在CS中。
- **选项B**: [干扰] — 针对“有界等待”的错误认知。如果发生 `t[i] == t[j]` 的死锁，等待是无限的，不满足有界等待。即使不死锁，如果新进程不断获取更大的 `t` 值，旧进程可能长期被阻塞（虽然此算法中 `t` 值重置为0，主要风险在于死锁）。
- **选项C**: [干扰] — 针对“进展条件”的错误认知。进展条件要求：如果没有进程在临界区，且有意愿进入的进程存在，则选择进入的进程不能在无限期推迟。由于存在 `t[i] == t[j]` 导致死锁的可能性，进展条件被违反。
- **选项D**: [干扰] — 针对“无死锁”的错误认知。这是本题最大的陷阱。当进程 $i$ 和 $j$ 几乎同时执行 `t[i] = pmax(...) + 1` 时，它们可能读取到相同的 `pmax` 值，从而获得相同的 `t` 值。随后，$i$ 等待 $j$ 的 `t[j] <= t[i]` 结束，$j$ 等待 $i$ 的 `t[i] <= t[j]` 结束。由于两者 `t` 值相等且非零，且都在等待对方，形成循环等待，导致死锁。

**干扰策略**: 概念混淆。利用考生对“互斥算法”通常隐含“无死锁”的刻板印象，设置一个看似完美但存在竞争条件漏洞的算法，诱导考生选择D或C。

## 核心陷阱
- **核心陷阱**: **竞争条件导致的死锁**。考生容易忽略 `t[i] = pmax(...) + 1` 这一行代码在并发执行时可能产生相同的 `t` 值。一旦 `t[i] == t[j]`，两个进程将互相等待对方退出（`t` 变为0），从而陷入死锁。因此，该算法**不满足**进展条件，也**会导致死锁**，但依然**满足互斥性**（因为死锁发生在进入临界区之前，且逻辑上不允许两个进程同时通过检查进入）。

## 考察能力
一句话概括本题核心考察的能力：在并发环境下，通过代码级推演识别竞争条件（Race Condition）及其对系统安全性（死锁）和活性（进展）影响的能力。
