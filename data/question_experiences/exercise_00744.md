# 练习题 Q1 — 数组原地交换与双重遍历效应

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/数组
- **难度**: 待评估

## 题干原文
设 A 是一个 n×n 的方阵。考虑以下程序。预期输出是什么？
C = 100
for i = 1 to n do
 for j = 1 to n do
 {
 Temp = A[i][j] + C
 A[i][j] = A[j][i]
 A[j][i] = Temp - C
 }
for i = 1 to n do
 for j = 1 to n do
 Output(A[i][j])

## K1-K5 评分与解析
- **K1 = 2**: 评分理由。本题主要考察对基本赋值语句和循环结构的理解，不需要记忆复杂的数据结构定义或公式。虽然涉及数组索引，但属于编程基础认知，而非深层数据结构理论，因此低于标准分3。
- **K2 = 2**: 评分理由。单步计算仅涉及简单的加减法和赋值操作（`Temp = A[i][j] + C` 等），没有复杂的数学运算或位运算，计算错误概率极低，属于较低难度。
- **K3 = 4**: 评分理由。这是本题的核心难点。考生需要在脑海中模拟双重循环的执行过程，特别是追踪 `A[i][j]` 和 `A[j][i]` 在 `i≠j` 时的状态变化。由于循环遍历了所有 `(i, j)` 对，每个非对角线元素会被访问两次（一次作为 `A[i][j]`，一次作为 `A[j][i]`），需要推演这两次交换如何相互抵消。这种多步串行推演且需记忆中间状态（第一次交换后的值）的过程，符合4分的标准。
- **K4 = 4**: 评分理由。存在明显的隐含前提和反直觉陷阱。常规思维中，`A[i][j] = A[j][i]` 通常用于矩阵转置，但标准的转置算法通常只遍历上三角或下三角（`j > i`）。本题遍历了整个矩阵，导致“双重交换”。考生必须意识到“遍历全矩阵”这一条件会导致交换被撤销，这是一个典型的反直觉陷阱，因此评分较高。
- **K5 = 1**: 评分理由。本题仅涉及单一系统（二维数组）内部的状态变化，没有跨越不同子系统或模块的数据传递，属于单系统问题。

- **雷达形状**: K3-K4 双高型（推演与陷阱主导）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖复杂的公式计算，也不仅仅是概念记忆，而是要求考生通过逻辑推理，模拟代码执行流程，分析循环边界和交换逻辑对最终状态的影响。

## 选项级分析
- **选项A**: [正确] — 矩阵 A 本身。正确理解了双重遍历导致的“交换-再交换”抵消效应，以及常数 C 在加减运算中的抵消作用。
- **选项B**: [干扰] — 矩阵 A 的转置。针对那些只看到 `A[i][j] = A[j][i]` 这一行代码，而忽略了循环范围（`1 to n`）和后续 `A[j][i] = Temp - C` 影响的学生。他们误以为这是标准的转置算法。
- **选项C**: [干扰] — 将 A 的上三角元素加 100，对角线元素减 100。针对那些注意到常数 C 的存在，但未能正确追踪 C 在 `Temp` 中如何被加回和减去的细节，或者错误地认为对角线元素（`i=j`）的处理逻辑与非对角线不同且未抵消的学生。实际上，当 `i=j` 时，`Temp = A[i][i] + C`, `A[i][i] = A[i][i]`, `A[i][i] = Temp - C = A[i][i]`，对角线元素也不变。
- **选项D**: [干扰] — 矩阵 A 的逆。针对完全不懂代码逻辑，仅凭“矩阵”、“变换”等关键词进行盲目猜测的学生。

- **干扰策略**: 概念混淆（将全矩阵遍历误认为转置算法）+ 细节遗漏（忽略常数 C 的抵消和双重交换的抵消）

## 核心陷阱
- **核心陷阱**: **双重交换抵消效应**。考生容易看到 `A[i][j] = A[j][i]` 就联想到矩阵转置，却忽略了循环遍历了所有 `i, j`，导致每一对非对角线元素 `(i, j)` 和 `(j, i)` 都被交换了两次，最终恢复原值。同时，常数 C 的引入增加了视觉干扰，但其加减操作也相互抵消。

## 考察能力
本题核心考察考生对**循环边界条件**的敏感度以及**模拟代码执行流程**的逻辑推演能力，特别是识别“操作可逆性”和“状态抵消”的能力。
