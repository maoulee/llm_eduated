# 练习题 Q1 — 信号量死锁避免与资源有序获取

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
考虑两个进程 P1 和 P2 访问受二进制信号量 SX 和 SY 保护的共享变量 X 和 Y，SX 和 SY 均初始化为 1。P 和 V 表示通常的信号量操作符，其中 P 减少信号量值，V 增加信号量值。P1 和 P2 的伪代码如下：
P1 : While true do {
 L1 : ................
 L2 : ................
 X = X + 1;
 Y = Y - 1;
 V(SX);
 V(SY);
 }

P2 : While true do {
 L3 : ................
 L4 : ................
 Y = Y + 1;
 X = Y - 1;
 V(SY);
 V(SX);
}
为了避免死锁，L1、L2、L3 和 L4 处的正确操作符分别是（ ）？
- 选项:
  A: P(SY), P(SX); P(SX), P(SY)
  B: P(SX), P(SY); P(SY), P(SX)
  C: P(SX), P(SX); P(SY), P(SY)
  D: P(SX), P(SY); P(SX), P(SY)
- 正确答案: D

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握信号量 P/V 操作的基本定义（P为申请/减1，V为释放/加1）以及死锁产生的四个必要条件（特别是循环等待）。属于标准的基础概念记忆，无需辨析极细微的易混概念，但必须准确理解“互斥”和“持有并等待”的含义。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行任何算术运算或单位换算。
- **K3 = 3**: 评分理由。需要进行多步逻辑推演。考生需模拟 P1 和 P2 的执行流程：假设 P1 执行 L1 获取资源 A，P2 执行 L3 获取资源 B，然后 P1 尝试获取 B，P2 尝试获取 A。需要推演这种交错执行是否会导致双方都阻塞（即死锁）。这涉及 3-4 步的状态转换推理。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。题面中 P1 和 P2 释放信号量的顺序不同（P1: V(SX), V(SY); P2: V(SY), V(SX)），这容易误导考生认为获取顺序也必须不同或随意。核心陷阱在于识别“避免死锁”的关键策略是**资源有序获取**（Resource Ordering），即所有进程必须以相同的顺序申请资源。考生必须意识到，尽管释放顺序可以不同，但申请顺序必须一致才能打破循环等待条件。这是一个典型的“反直觉”或“隐含前提深”的考点，因为初学者常误以为只要配对 P/V 即可，忽略了全局顺序的一致性。
- **K5 = 2**: 评分理由。主要涉及进程管理子系统内部的同步机制。虽然涉及两个进程间的交互，但不需要跨越文件系统、内存管理或网络等其他子系统传递状态，属于单系统内的经典同步问题。

- **雷达形状**: K4 陷阱型（K4 显著高于其他维度，K2 极低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖公式计算，也不仅仅是概念回忆，而是要求考生基于死锁产生的条件（特别是循环等待），通过逻辑推理判断哪种资源申请顺序能够打破死锁循环。核心在于理解“有序资源分配”这一机制的原理。

## 选项级分析
- **选项 A**: [干扰] — 针对“随意配对”的错误认知。P1 先 P(SY) 后 P(SX)，P2 先 P(SX) 后 P(SY)。如果 P1 拿到 SY，P2 拿到 SX，随后 P1 等待 SX，P2 等待 SY，形成经典的循环等待死锁。这类学生可能没有意识到申请顺序必须全局一致。
- **选项 B**: [干扰] — 针对“局部对称”的错误认知。P1 先 P(SX) 后 P(SY)，P2 先 P(SY) 后 P(SX)。这与 A 类似，只是资源角色互换。同样会导致 P1 持有 SX 等待 SY，P2 持有 SY 等待 SX 的死锁。这类学生可能误以为只要每个进程内部 P/V 配对正确即可，忽略了进程间的交互。
- **选项 C**: [干扰] — 针对“资源重复申请”或“逻辑混乱”的错误认知。P1 连续 P(SX) 两次，P2 连续 P(SY) 两次。由于 SX 和 SY 是二进制信号量（初始为 1），第二次 P 操作会立即阻塞，导致进程无法进入临界区执行后续代码，或者造成逻辑错误（如 P1 永远拿不到 SY）。这类学生可能对信号量的计数特性理解不清，或试图通过重复加锁来“强化”保护。
- **选项 D**: [正确] — 针对“资源有序获取”的正确认知。P1 先 P(SX) 后 P(SY)，P2 也先 P(SX) 后 P(SY)。所有进程都以相同的顺序（先 SX 后 SY）申请资源。如果 P1 拿到 SX，P2 申请 SX 时会阻塞，直到 P1 释放 SX。P2 无法在持有 SY 的情况下等待 SX，从而打破了“持有并等待”和“循环等待”条件，避免了死锁。

- **干扰策略**: 概念混淆（混淆申请顺序与释放顺序的重要性）、渐进陷阱（A/B 选项看似对称合理，实则构成死锁）

## 核心陷阱
- **核心陷阱**: **释放顺序与申请顺序的解耦**。题目中 P1 和 P2 的 V 操作（释放）顺序是不同的（P1: SX->SY, P2: SY->SX），这容易让考生产生错觉，认为 P 操作（申请）的顺序也可以不同，或者认为必须与 V 操作顺序严格对应。实际上，避免死锁的关键在于**所有进程申请资源的顺序必须一致**，而释放资源的顺序通常不影响死锁（只要不违反其他约束），但为了代码清晰通常建议逆序释放。本题的核心是识别出 D 选项中两个进程申请资源的顺序完全一致（SX -> SY），从而消除了循环等待的可能性。

## 考察能力
一句话概括本题核心考察的能力：
考生能否运用“资源有序获取”原则，通过分析进程间资源申请顺序的一致性，识别并避免由循环等待引起的死锁。
