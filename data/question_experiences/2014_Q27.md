# 2014 Q27 — 外存位图法空间计算

## 基本信息
- **年份**: 2014  **题位**: Q27  **题型**: 选择题
- **知识点**: 外存空间管理, 位图法, 簇, 操作系统>位图法, 操作系统>外存空间管理
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
现有一个容量为 10GB 的磁盘分区，磁盘空间以簇 (Cluster) 为单位进行分配，簇的大小为 4KB，若采用位图法管理该分区的空闲空间，即用一位 (bit) 标识一个簇是否被分配，则存放该位图所需簇的个数为（ ）。

A. 80
B. 320
C. 80K
D. 320K

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“位图法”的核心定义（1 bit 对应 1 个分配单元）以及存储单位换算的基本概念（Bit, Byte, KB, MB, GB）。属于标准的基础知识调用，不涉及复杂概念辨析。
- **K2 = 4**: 评分理由。涉及多级单位换算（GB -> KB -> Bit -> Byte -> KB -> Cluster）。虽然都是2的幂次，但步骤较多（至少3-4步换算），且中间涉及 Bit 到 Byte 的除以8操作，容易在数量级上出错，属于较高难度的单步/多步代入计算。
- **K3 = 2**: 评分理由。逻辑链条清晰：总容量/簇大小=簇总数 -> 簇总数=位图总位数 -> 位图总位数/8=位图字节数 -> 位图字节数/簇大小=位图占用簇数。属于标准的2-3步串行推演，无分支。
- **K4 = 2**: 评分理由。存在常规注意点，即“位图本身也占用磁盘空间”这一隐含前提（虽然题目问的是“存放该位图所需簇”，暗示了位图是存储在磁盘上的，但学生需意识到位图大小是动态计算出来的，且单位必须统一）。没有深层陷阱，主要是单位换算的细心程度。
- **K5 = 1**: 评分理由。仅涉及操作系统外存管理单一模块内的计算，无需跨越文件系统、内存管理或CPU调度等其他子系统。
- **雷达形状**: K2计算主导型（K2突出，K1/K3中等，K4/K5较低）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的参数（磁盘容量、簇大小、位图映射规则）进行数值计算，最终得出一个具体的整数结果。虽然涉及概念，但解题的关键路径是数学换算。

## 选项级分析
- **选项A**: [正确] — 正确计算结果。10GB/4KB = 2.5M 簇；2.5M bit / 8 = 320KB 位图大小；320KB / 4KB = 80 簇。
- **选项B**: [干扰] — 针对“忘记除以8”或“单位混淆”的错误认知。学生可能计算出位图需要 2.5M bit，然后错误地认为 2.5M bit 直接对应 2.5M 字节，或者在计算簇数时混淆了 Bit 和 Byte 的关系。另一种可能是算出了 320KB 后，误以为题目问的是 KB 数但看错了选项单位，或者在 320KB/4KB 时算错。更常见的错误路径是：算出位图大小为 320KB，然后忘记最后一步除以簇大小，或者错误地认为 1KB=1024Bit 等混乱换算。实际上，B选项 320 很可能是学生算出位图大小为 320KB 后，误以为答案就是 320（忽略了最后除以簇大小4KB的步骤，或者误以为簇大小是1KB）。
- **选项C**: [干扰] — 针对“数量级错误”或“未进行最后一步除法”的错误认知。如果学生算出位图大小为 320KB，可能直接选 C (80K 是 80*1024，数值不对，但量级接近)。或者，如果学生错误地用 10GB 直接除以 4KB 得到 2.5M，然后除以 8 得到 320K (这里K指1024)，即 320KB，如果题目问的是字节数或KB数，可能会混淆。但 C 是 80K，即 81920，这与 80 相差甚远。更可能的错误路径是：学生算出 80 个簇，但误以为题目问的是字节数或其他单位，或者在换算过程中多乘了一个 1024。例如，算出 80 后，误以为 80 是 KB，然后转换成字节？不，C 是 80K。如果学生算出位图占用 320KB，然后错误地认为 320KB / 4KB = 80KB (单位错误)，再转换成某种形式？最可能的错误是：学生算出位图大小为 320KB，然后忘记除以簇大小，或者错误地认为簇大小是 1KB，得出 320 个簇，然后看错选项。或者，学生算出 80 个簇，但误以为 1 簇 = 1KB，然后得出 80KB，再误选 C。
- **选项D**: [干扰] — 针对“完全未进行位图压缩”或“单位换算彻底混乱”的错误认知。320K 即 327,680。如果学生直接用 10GB / 4KB = 2.5M = 2560K 簇，然后忘记除以 8，直接选一个接近的？或者，学生算出位图大小为 320KB，然后误以为题目问的是位图占用的字节数（320KB = 327,680 Bytes ≈ 320K Bytes），从而选 D。这是非常典型的“答非所问”陷阱，算出了中间结果（位图大小 320KB）就停止思考，看到选项中有 320K 就选了。

- **干扰策略**: 计算陷阱（中间结果干扰）、单位混淆（Bit/Byte/KB/Cluster 之间的换算错误）

## 核心陷阱
- **核心陷阱**: **中间结果干扰与单位换算链断裂**。
    1.  **中间结果陷阱**：计算出位图大小为 320KB 后，学生容易误以为这就是答案，从而选择 D (320K) 或 B (320，如果忽略单位)。
    2.  **Bit 到 Byte 的转换**：忘记 1 Byte = 8 Bits，导致结果扩大 8 倍。
    3.  **最终单位转换**：忘记将位图的字节大小（KB）转换为簇的个数（除以簇大小 4KB）。

## 考察能力
本题核心考察考生对**外存位图法存储机制的理解**以及**计算机存储单位（Bit, Byte, KB, MB, GB）之间多级换算的准确性**。
