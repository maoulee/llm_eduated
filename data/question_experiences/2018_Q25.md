# 2018 Q25 — 并发执行序列与临界区原子性

## 基本信息
- **年份**: 2018  **题位**: Q25  **题型**: 选择题
- **知识点**: 进程和线程, 操作系统>进程和线程
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
属于同一进程的两个线程 thread1 和 thread2 并发执行，共享初值为 0 的全局变量 x。thread1 和 thread2 实现对全局变量 x 加 1 的机器级代码描述如下：
thread1
mov R1, x // (x) → R1
inc R1 // (R1) + 1 → R1
mov x, R1 // (R1) → x
thread2
mov R2, x // (x) → R2
inc R2 // (R2) + 1 → R2
mov x, R2 // (R2) → x
在所有可能的指令执行序列中，使 x 的值为 2 的序列个数是（）。
进程和线程
- 选项:
  A: 1
  B: 2
  C: 3
  D: 4
- 正确答案: B
- 解析（参考）: 仔细阅读两个线程代码可知，threadl 和 thread2 均是对 x 进行加 1 操作，x 初始值为 0，若要使得最终 x = 2，只有先执行 thread1 再执行 thread2，或先执行 thread2 再执行 threadl，故只有 2 种可能，选 B。
- 知识标签: ['进程和线程', '操作系统>进程和线程']
- 知识域: CO-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“线程并发”、“共享变量”、“指令级执行”以及“原子性缺失”等核心概念。不是4分因为不需要辨析多个易混的高级同步原语，只需理解基本的指令交错概念。
- **K2 = 1**: 评分理由。本题不涉及数值计算，仅涉及逻辑状态的追踪。
- **K3 = 4**: 评分理由。推演步骤较多且需记忆中间状态。两个线程各3条指令，共6条指令。要得出x=2，必须保证两个线程的指令块不交错（即原子执行）。需要枚举所有可能的交错情况，或者反向推导哪些交错会导致x=1（丢失更新），从而排除错误序列。从输入（6条指令）到输出（筛选出特定序列）需要多步串行推演，且需跟踪寄存器R1/R2和内存x的状态变化。
- **K4 = 4**: 评分理由。存在隐含前提和反直觉陷阱。陷阱在于“所有可能的指令执行序列”这一表述。学生容易误以为只要最终结果对就行，或者误以为只有完全串行（Thread1全完再Thread2）才算。实际上，题目问的是“序列个数”，需要识别出导致x=2的**唯一**逻辑结构是“无交错”。如果学生没有意识到“mov, inc, mov”这三条指令作为一个整体必须连续执行才能保证x=2，就会陷入复杂的排列组合陷阱。此外，需避开“x=1”的干扰，理解为什么交错会导致x=1。
- **K5 = 2**: 评分理由。主要涉及操作系统内部的线程调度与内存访问，属于单系统内的状态传递，不涉及跨子系统（如网络、文件系统）的深度耦合。

- **雷达形状**: K3/K4 双高型（推理与陷阱主导）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖公式计算，也不单纯考察概念记忆，而是要求考生基于给定的机器指令序列，模拟并发执行的过程，通过逻辑推理排除导致数据竞争（Race Condition）的交错序列，从而确定满足特定结果（x=2）的执行路径数量。

## 选项级分析
- **选项A**: [干扰] — 针对认为“只有Thread1先执行完，Thread2再执行”这一种顺序的学生。忽略了Thread2先执行完，Thread1再执行也是合法的并发序列。
- **选项B**: [正确] — 正确识别出只有两种“无交错”的执行序列：(T1_1, T1_2, T1_3, T2_1, T2_2, T2_3) 和 (T2_1, T2_2, T2_3, T1_1, T1_2, T1_3)。
- **选项C**: [干扰] — 针对部分理解交错但计算错误的学生。可能误以为存在某种特定的交错（如只交错一条指令）也能得到x=2，或者在排列组合时算错。
- **选项D**: [干扰] — 针对完全未理解原子性重要性的学生。可能认为只要两个线程都执行了加1，无论怎么交错，只要不出现极端情况，或者简单地认为有几种常见的交错模式（如完全串行2种 + 某种特定交错2种）。

- **干扰策略**: 概念混淆（原子性与非原子性操作的后果）+ 排列组合陷阱（误以为部分交错也能保持结果正确）

## 核心陷阱
- **核心陷阱**: **指令交错的原子性破坏**。
  考生容易忽略 `mov, inc, mov` 这三条指令在硬件层面不是原子的。如果两个线程的指令发生交错（例如 T1 执行完 mov 后，T2 执行 mov，此时两者都读到 x=0），最终写回时会导致“丢失更新”，使得 x=1 而不是 2。
  题目问的是“使 x 的值为 2 的序列”，这意味着必须**避免**任何导致数据竞争的交错。因此，只有当一个线程的三条指令**连续执行完毕**，另一个线程才开始执行时，x 才能正确累加为 2。
  陷阱在于：学生可能会去计算所有可能的交错序列总数（6!/(3!3!) = 20种），然后试图从中找出哪些是x=2，这非常复杂且容易出错。正确的思路是反向思考：什么情况下 x != 2？只要发生交错，x 就可能为 1（实际上对于这种简单的加1，任何交错都会导致至少一次读取旧值，从而丢失一次更新，最终结果必为1）。因此，只有“完全不交错”的2种序列能使 x=2。

## 考察能力
本题核心考察考生对**并发执行中指令交错（Interleaving）导致数据竞争（Race Condition）机制**的深度理解，以及通过**状态推演**识别原子性操作必要性的能力。
