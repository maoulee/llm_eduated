# 练习题 Q1 — HTTP交互流程与协议分层顺序

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/应用层
- **难度**: 待评估

## 题干原文
确定以下操作在浏览器与 Web 服务器交互过程中的正确顺序。
浏览器使用 HTTP 请求网页。
浏览器与 Web 服务器建立 TCP 连接。
Web 服务器使用 HTTP 发送所请求的网页。
浏览器通过 DNS 解析域名以获取 IP 地址。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆“DNS解析 -> TCP连接 -> HTTP请求/响应”这一标准网络通信流程的核心概念。不是2分因为仅靠直觉容易混淆DNS和TCP的先后；不是4分因为不需要辨析多个易混的底层细节（如三次握手的具体报文），只需掌握宏观流程。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，属于纯逻辑排序。
- **K3 = 3**: 评分理由。需要在明确规则（OSI/TCP-IP模型分层及依赖关系）下进行多步串行推演。步骤为：1. 域名转IP（DNS）；2. 建立传输层连接（TCP）；3. 应用层请求（HTTP GET）；4. 应用层响应（HTTP Response）。共4个关键步骤，符合3-5步的标准。
- **K4 = 2**: 评分理由。存在常规注意点，即“应用层依赖传输层，传输层依赖网络层/地址解析”。没有深奥的隐含前提或反直觉陷阱，只要理解协议分层依赖关系即可避开错误。
- **K5 = 3**: 评分理由。需要跨越不同子系统（应用层DNS、传输层TCP、应用层HTTP）传递状态。DNS解析出的IP地址是建立TCP连接的前提，TCP连接建立是发送HTTP请求的前提，体现了单向的数据/状态传递依赖。

- **雷达形状**: K3推演主导型（K1基础记忆支撑，K3流程推演为核心，K5跨层联动辅助，K2计算缺失）

## 考察模式
- **模式**: 推理型
- **理由**: 虽然涉及概念记忆，但解题核心在于理解各协议之间的**依赖关系**和**执行时序**。考生必须推理出“没有IP无法建连”、“没有连接无法传HTTP数据”的逻辑链条，而非单纯背诵定义。

## 选项级分析
- **选项A (4, 2, 1, 3)**: [正确] — 符合标准流程：先DNS解析(4)获取IP，再TCP建连(2)，然后HTTP请求(1)，最后HTTP响应(3)。
- **选项B (1, 2, 3, 4)**: [干扰] — 针对“完全倒置”或“无逻辑”的错误认知。这类学生可能完全不清楚网络通信的基本步骤，或者误以为HTTP请求是第一步，忽略了底层连接和地址解析。
- **选项C (4, 1, 2, 3)**: [干扰] — 针对“应用层优先”的错误认知。这类学生知道要先DNS解析(4)，但错误地认为可以先发送HTTP请求(1)再建立TCP连接(2)。这违反了TCP/IP模型中“应用层数据必须封装在传输层段中”的基本原理，即“先建路，后通车”。
- **选项D (2, 4, 1, 3)**: [干扰] — 针对“连接优先于地址”的错误认知。这类学生可能误以为浏览器可以直接与服务器建立TCP连接，而忽略TCP连接需要目标IP地址这一前提。实际上，没有DNS解析(4)得到的IP，TCP SYN包无法发出。

- **干扰策略**: 概念混淆（主要混淆DNS、TCP、HTTP三者的依赖顺序，特别是C选项混淆了应用层动作与传输层动作的先后）

## 核心陷阱
- **核心陷阱**: **协议分层的依赖关系**。最关键的陷阱在于判断“DNS解析”与“TCP连接”的先后，以及“TCP连接”与“HTTP请求”的先后。许多初学者容易忽略DNS是网络通信的起点（针对域名访问），或者误以为HTTP请求可以独立于TCP连接存在。

## 考察能力
一句话概括本题核心考察的能力：理解并推演TCP/IP协议栈中从应用层到传输层再到网络层的**分层依赖关系**及**标准通信时序**。
