# 模拟题 Q综合题 — 进程同步与互斥（竞态条件分析）

## 基本信息
- **来源**: 模拟题  **题型**: 综合题
- **科目**: 操作系统
- **知识点**: OS-2 > 2.3 进程同步 > 同步与互斥基本概念, OS-2 > 2.3 进程同步 > 临界资源, OS-2 > 2.3 进程同步 > 临界区, OS-2 > 2.3 进程同步 > 互斥
- **难度**: 中等

## 题干原文
（7 分）兄弟俩共同使用一个账号，每次限存或取 10 元，存钱与取钱的进程分别如下所示：
```c
int amount = 0;
SAVE() {
    int m1;
    m1 = amount;
    m2 = m1 + 10; // 注意：原题代码此处变量名可能有误，逻辑应为局部变量累加
    amount = m1;   // 注意：原题代码此处逻辑有误，应为 amount = m2 或类似写回操作
}
TAKE() {
    int m2;
    m2 = amount;
    m2 = m2 - 10;
    amount = m2;
}
```
由于兄弟俩可能同时存钱和取钱，因此这两个进程是并发的。若哥哥先存了两次钱，但在第三次存钱时，弟弟在取钱。请问：
（1）最后账号 `amount` 上面可能出现的值？
（2）如何用 P、V 操作实现两并发进程的互斥执行？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“临界资源”、“临界区”、“互斥”以及“信号量 P/V 操作”的核心定义。不是4分因为不需要辨析多个易混的高级同步原语（如管程、信号量集等），只需基础概念。
- **K2 = 2**: 评分理由。涉及简单的整数加减运算（0+10, 20+10, 20-10等）。不是3分因为计算量极小，且数值友好，几乎不可能算错，主要难点不在计算本身。
- **K3 = 4**: 评分理由。需要推演并发执行时的指令交错情况。从输入（初始状态20，并发执行SAVE和TAKE）到输出（最终值），需要列举多种指令交错序列（如读-读-写-写，读-写-读-写等），步骤超过3步且需记忆中间状态（局部变量m1, m2的值）。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。首先，题目给出的代码逻辑存在明显笔误（SAVE中`amount=m1`未更新，且变量名混乱），考生需具备“透过代码表象看逻辑本质”的能力，识别出这是典型的“读-改-写”原子性破坏问题。其次，需意识到“并发”意味着指令级交错，而非进程级串行。
- **K5 = 2**: 评分理由。仅涉及操作系统进程同步这一单一子系统。虽然涉及两个进程，但状态传递仅限于共享变量`amount`，属于单向或简单的双向状态影响，未跨越内存管理、文件系统等其他模块。
- **雷达形状**: 偏向“推演与条件识别”型。K3和K4较高，K1中等，K2和K5较低。图形呈现为右侧（K3, K4）突出的不对称形状。

## 考察模式
- **模式**: 分析论证型
- **理由**: 题目不要求编写复杂算法或进行大量数值计算，而是要求考生分析并发执行过程中的状态变化（竞态条件），并论证可能的结果，最后给出标准的同步解决方案。重点在于对并发机制的理解和逻辑推导。

## 解题思路分析
- **核心思路**: 
  1. **修正与理解代码逻辑**：忽略代码中的语法/变量名笔误，提取核心逻辑：SAVE是`amount = amount + 10`，TAKE是`amount = amount - 10`。
  2. **确定初始状态**：哥哥先存两次，`amount`初始值为20。
  3. **枚举并发交错**：分析第三次SAVE和TAKE并发执行时，指令（Load, Add/Sub, Store）的所有可能交错顺序，计算最终`amount`。
  4. **应用同步机制**：使用互斥信号量保护临界区。

- **关键步骤**:
  1. **初始状态**：`amount = 20`。
  2. **并发操作分析**：
     - SAVE进程指令：`R1 = amount` (20), `R1 = R1 + 10` (30), `amount = R1` (30)。
     - TAKE进程指令：`R2 = amount` (20), `R2 = R2 - 10` (10), `amount = R2` (10)。
  3. **交错情况推演**：
     - **情况A（串行化-先存后取）**：SAVE完整执行 -> `amount=30`；TAKE执行 -> `amount=20`。
     - **情况B（串行化-先取后存）**：TAKE完整执行 -> `amount=10`；SAVE执行 -> `amount=20`。
     - **情况C（交错-丢失更新）**：
       - SAVE读(20) -> TAKE读(20) -> SAVE写(30) -> TAKE写(10)。结果：10。
       - SAVE读(20) -> TAKE读(20) -> TAKE写(10) -> SAVE写(30)。结果：30。
       - *注：题目参考答案给出10, 20, 30。需仔细检查是否还有其他交错。*
       - 实际上，如果SAVE和TAKE都完整执行，净变化应为0，结果应为20。但并发导致“丢失更新”。
       - 若SAVE读20，TAKE读20，SAVE写30，TAKE写10 -> 结果10。
       - 若SAVE读20，TAKE读20，TAKE写10，SAVE写30 -> 结果30。
       - 若SAVE完整执行(30)，TAKE读30，TAKE写20 -> 结果20。
       - 若TAKE完整执行(10)，SAVE读10，SAVE写20 -> 结果20。
       - 因此可能值为10, 20, 30。
  4. **P/V操作实现**：
     - 定义 `semaphore mutex = 1;`
     - SAVE: `P(mutex); ...临界区... V(mutex);`
     - TAKE: `P(mutex); ...临界区... V(mutex);`

- **易错点**:
  1. **被代码笔误误导**：直接按照题目中错误的`amount=m1`（未加10）或变量名错误去计算，导致结果完全错误。
  2. **遗漏交错情况**：只考虑串行执行（结果20），忽略了并发导致的“丢失更新”现象（结果10或30）。
  3. **P/V操作位置错误**：将P/V操作放在整个函数外部而非临界区（访问共享变量）前后，或者忘记初始化信号量。

## 核心陷阱
- **核心陷阱**: **代码逻辑的“表象”与“意图”不符**。题目给出的C代码片段存在明显的逻辑错误（SAVE函数中`amount`并未真正增加，且变量名混用）。考生必须识别出这是一道考察“并发竞态条件”的经典模型题，其核心意图是考察`Read-Modify-Write`非原子性带来的问题，而不是考察C语言语法纠错。若拘泥于代码字面意思，将无法得出参考答案中的10, 20, 30。

## 考察能力
本题核心考察考生对**进程并发执行中竞态条件（Race Condition）的推演能力**以及**使用信号量实现互斥同步的工程实践能力**。
