# 练习题 Q1 — 递归逻辑推演与边界条件分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
考虑以下 C 函数定义：
```c
int Trial(int a, int b, int c) {
    if ((a >= b) && (c < b))
        return b;
    else if (a >= b)
        return Trial(a, c, b);
    else
        return Trial(b, a, c);
}
```
该函数 `Trial` 的作用是（ ）：
- 选项:
  A: 找出 a、b 和 c 中的最大值
  B: 找出 a、b 和 c 中的最小值
  C: 找出 a、b 和 c 中的中间数
  D: 以上都不正确

## K1-K5 评分与解析
- **K1 = 2**: 评分理由。本题主要考察对C语言基本语法（if-else结构、递归调用）的理解，属于基础认知。不需要记忆复杂的数据结构定义或算法公式，仅需理解代码字面含义即可入题，故为较低难度。
- **K2 = 1**: 评分理由。本题不涉及数值计算、幂次运算或单位换算，没有“算错”的风险，只有逻辑判断，故为微弱需求。
- **K3 = 4**: 评分理由。考生需要在脑海中模拟递归过程。对于一般情况（如 a=3, b=2, c=1），需要追踪参数交换和递归层级，步骤较多（3-5步以上）。更关键的是，要发现“无限递归”这一特性，需要推演特定边界条件（如 a=b=c）下的执行流，这属于多步串行推演且需记忆中间状态（参数变化），故难度较高。
- **K4 = 5**: 评分理由。本题存在极强的隐含前提和反直觉陷阱。常规思维会认为这是一个求中位数的算法（因为逻辑上它在尝试排序），但忽略了递归终止条件的完备性。当 a=b=c 时，`a>=b` 为真，`c<b` 为假，进入 `else if (a>=b)` 分支，调用 `Trial(a, c, b)` 即 `Trial(a, a, a)`，导致无限递归。这种“看似正确实则崩溃”的反直觉特性，以及需要意识到“算法正确性包含终止性”这一深层隐含前提，使得条件路由需求极高。
- **K5 = 1**: 评分理由。本题仅涉及单一函数内部的逻辑控制，不涉及不同子系统、模块间的数据传递或状态耦合，故为微弱需求。

- **雷达形状**: K4陷阱型（K4极高，K3较高，其余较低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖记忆或计算，而是要求考生通过逻辑推演模拟代码执行过程，并识别出算法在特定边界条件下的缺陷（无限递归），从而否定表面上的功能描述。

## 选项级分析
- **选项A**: [干扰] — 针对认为该函数通过比较返回最大值的错误认知。学生可能看到 `return b` 且 `b` 在某些条件下较大，误以为是求最大值。
- **选项B**: [干扰] — 针对认为该函数返回最小值的错误认知。类似地，学生可能混淆比较逻辑。
- **选项C**: [干扰] — 针对认为该函数是求中位数算法的错误认知。这是最强的干扰项。因为从逻辑上看，该函数试图通过交换参数将 `b` 置于中间位置（当 `a>=b` 且 `c<b` 时，`b` 确实可能是中位数，或者通过递归调整）。大多数学生会推导出“它在找中位数”，从而忽略边界情况。
- **选项D**: [正确] — 针对能够识别出算法存在缺陷（无限递归）的考生。当 `a=b=c` 时，程序无法终止，因此不能正确返回任何值，故“以上都不正确”是严谨的答案。

- **干扰策略**: 渐进陷阱。先让考生推导出“正常情况下的功能”（求中位数），诱导其选择C，然后利用“边界条件缺失”这一深层陷阱，使C选项在严格意义上不成立，从而指向D。

## 核心陷阱
- **核心陷阱**: **递归终止条件的完备性缺失**。考生容易只关注“正常输入”下的逻辑功能（求中位数），而忽略“相等元素”导致的无限递归（栈溢出）。在算法分析中，正确性不仅指输出结果正确，还指算法必须终止。

## 考察能力
本题核心考察考生对递归算法执行流程的模拟能力，以及对算法正确性（包括终止性）的严谨分析能力，特别是识别边界条件陷阱的能力。
