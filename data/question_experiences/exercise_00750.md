## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握数组的基本索引概念（0-based indexing）以及循环结构的基本语法。不是2分因为仅靠直觉难以确定边界条件，需明确“数组大小为n，有效索引为0到n-1”这一核心定义。
- **K2 = 2**: 评分理由。本题不涉及复杂的数值计算，主要是逻辑条件的判断。最复杂的单步是判断循环次数和数组边界，属于基础逻辑判断，不易算错。
- **K3 = 3**: 评分理由。需要在脑海中模拟代码执行流程：外层循环控制旋转次数，内层循环执行元素前移，最后处理首尾元素交换。从输入到输出需经历“判断外层条件 -> 保存首元素 -> 内层循环移位 -> 填补末尾 -> 更新计数器”约4-5步串行推演。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。首先，数组索引越界是常见陷阱（如选项B中的`arr[n]`）；其次，循环边界条件（`<` vs `<=`，`n` vs `n-1`）极易混淆；最后，变量`p`的初始值为1而非0，这要求考生必须结合初始值判断循环终止条件，稍有不慎就会陷入“off-by-one”错误。
- **K5 = 1**: 评分理由。本题仅涉及单一数据结构（数组）的操作，无需在不同子系统或模块间传递状态，属于单系统内部逻辑。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，主要考察对边界条件和隐含前提的识别能力）

## 考察模式
- **模式**: 推理型
- **理由**: 题目并非直接考查概念记忆或公式计算，而是要求考生通过阅读残缺代码，推理出算法的执行逻辑，特别是循环的边界控制和数据流动的方向，属于典型的代码逻辑推理。

## 选项级分析
- **选项A**: [正确] — `p <= d` 确保循环执行d次（因为p从1开始）；`i < n - 1` 确保内层循环将 `arr[1]` 移到 `arr[0]` ... `arr[n-1]` 移到 `arr[n-2]`，避免越界且留出位置给last；`arr[n - 1] = last` 将原首元素放到末尾，完成一次左旋。
- **选项B**: [干扰] — 针对“数组索引从1开始”或“忽略数组边界”的错误认知。`arr[n]` 会导致数组越界访问（Valid indices are 0 to n-1）。此外 `p < d` 会导致只旋转 d-1 次。这类学生可能混淆了C语言数组索引与日常计数习惯，或者对内存布局理解不深。
- **选项C**: [干扰] — 针对“循环方向搞反”或“条件判断逻辑混乱”的错误认知。`p >= d` 在 p=1, d>1 时直接不执行或逻辑错误；`i > n` 导致内层循环不执行。这类学生可能完全未理解左旋算法的移位方向。
- **选项D**: [干扰] — 针对“不确定感”或“过度怀疑”的学生。当考生对边界条件犹豫不决时，容易选择此项。
- **干扰策略**: 概念混淆（数组索引边界）与 计算陷阱（循环次数与初始值的关系）

## 核心陷阱
- **核心陷阱**: **数组越界与Off-by-One错误**。
    1.  **索引越界**：C语言数组大小为n，合法索引为0~n-1。选项B中的 `arr[n]` 是典型的越界错误。
    2.  **循环边界**：内层循环 `arr[i] = arr[i+1]`，当 `i` 达到 `n-2` 时，`arr[n-2] = arr[n-1]`，这是最后一次有效移动。若 `i` 继续增加到 `n-1`，则 `arr[n-1] = arr[n]` 越界。因此条件必须是 `i < n - 1`。
    3.  **计数器初始值**：`p` 初始为1，若要执行d次，条件应为 `p <= d`。若误以为 `p` 从0开始，可能会选 `p < d`。

## 考察能力
本题核心考察考生对**数组内存布局、索引边界控制以及循环结构逻辑推演**的综合掌握能力，特别是识别和避免“Off-by-One”错误的能力。
