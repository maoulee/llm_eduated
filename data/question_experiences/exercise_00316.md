# 练习题 Q1 — TCP拥塞控制窗口演化

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文

- 选项:
  A: 33
  B: 44
  C: 55
  D: 50
- 正确答案: B

第 10 次传输：42 KB

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 TCP 拥塞控制的核心概念（慢启动、拥塞避免、ssthresh、cwnd、rwnd），属于标准的基础认知需求。若未记忆这些术语定义无法入题，但无需辨析极度易混的深层概念。
- **K2 = 3**: 评分理由。涉及简单的算术运算（2的幂次增长、线性增长、除法），计算量不大，但需要精确执行每一步的数值更新，非2幂次后的线性累加容易出错，属于标准计算难度。
- **K3 = 4**: 评分理由。需要从 t=0 到 t=60ms 进行多步串行推演。60ms / 6ms = 10个RTT，需要模拟10个阶段的窗口变化。步骤超过5步，且需记忆每个阶段结束时的中间状态（cwnd值），属于较高的机制推演需求。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。首先，需判断“所有确认应答处理完毕后”意味着当前时刻的cwnd已经根据上一轮收到的ACK进行了更新；其次，需识别接收方窗口（rwnd=50KB）对拥塞窗口（cwnd）的限制作用（虽然本题中cwnd未超过50KB，但需有此意识）；最后，需明确慢启动到拥塞避免的切换点是在发送前判断还是收到ACK后判断（通常408考题默认收到ACK后更新cwnd用于下一轮，或发送时cwnd已达阈值则下一轮进入线性增长）。本题陷阱在于对“t+60ms时刻”状态的定义，是第10轮发送前的窗口，还是第10轮ACK回来后的窗口。
- **K5 = 2**: 评分理由。主要涉及传输层内部机制，虽然提到了接收方通告窗口（涉及接收端状态），但本题中rwnd仅作为上限约束，未发生复杂的跨层或跨子系统状态耦合，属于较低程度的跨域联动。
- **雷达形状**: K3/K4 突出型（推演与陷阱主导）

## 考察模式
- **模式**: 综合型
- **理由**: 本题既需要记忆 TCP 拥塞控制的算法规则（概念），又需要进行多步数值模拟（计算/推演），同时需要处理时间轴与状态更新的对应关系（逻辑推理），属于典型的综合考察模式。

## 选项级分析
- **选项A (33)**: [干扰] — 针对错误认知：可能误以为在第5轮达到阈值后，第6轮只增加1个MSS（即32+2=34? 不对，33怎么来的？可能是误算线性增长起点或步长）。或者误以为慢启动阶段计算错误。更可能的错误路径：在第5轮结束时cwnd=32，误以为进入拥塞避免后每RTT增加1KB（而非1MSS=2KB），则32+1=33。这类学生混淆了“每RTT增加1个MSS”与“每RTT增加1KB”或单位换算错误。
- **选项B (44)**: [正确] — 正确推演结果。
    - RTT 1: cwnd=2 (发送2) -> ACK -> cwnd=4
    - RTT 2: cwnd=4 (发送4) -> ACK -> cwnd=8
    - RTT 3: cwnd=8 (发送8) -> ACK -> cwnd=16
    - RTT 4: cwnd=16 (发送16) -> ACK -> cwnd=32
    - RTT 5: cwnd=32 (发送32, 达到ssthresh) -> ACK -> 进入拥塞避免, cwnd=32+2=34
    - RTT 6: cwnd=34 (发送34) -> ACK -> cwnd=34+2=36
    - RTT 7: cwnd=36 (发送36) -> ACK -> cwnd=36+2=38
    - RTT 8: cwnd=38 (发送38) -> ACK -> cwnd=38+2=40
    - RTT 9: cwnd=40 (发送40) -> ACK -> cwnd=40+2=42
    - RTT 10: cwnd=42 (发送42) -> ACK -> cwnd=42+2=44
    - 注意：题目问的是“所有确认应答处理完毕后”，即第10轮ACK回来后的cwnd。
- **选项C (55)**: [干扰] — 针对错误认知：可能忽略了接收方窗口（rwnd=50KB）的限制，或者错误地认为拥塞避免阶段增长更快。如果一直按慢启动指数增长：2,4,8,16,32,64... 显然不对。如果误以为线性增长步长更大，或者计算轮数错误（如算成11轮？42+2=44, 44+2=46... 也不对）。另一种可能是误将MSS当作1KB计算，或者在拥塞避免阶段误用指数增长。
- **选项D (50)**: [干扰] — 针对错误认知：直接选择了接收方通告窗口（rwnd）的大小。这类学生可能认为拥塞窗口最终会等于接收窗口，或者忽略了具体的拥塞控制算法过程，直接取上限值。

- **干扰策略**: 概念混淆（慢启动与拥塞避免的切换条件）、计算陷阱（线性增长的步长是MSS而非固定值）、边界条件误解（rwnd的限制作用）。

## 核心陷阱
- **核心陷阱**: 
    1. **状态更新时机**：题目问的是“所有确认应答处理完毕后”，这意味着需要计算第10个RTT结束时的cwnd值，而不是第10个RTT开始发送时的cwnd值。
    2. **拥塞避免的增长步长**：在拥塞避免阶段，每经过一个RTT，cwnd增加 1 MSS（即2 KB），而不是增加 1 KB 或其他值。
    3. **阈值切换点**：当 cwnd 达到 ssthresh 时，下一轮进入拥塞避免。本题中第5轮发送时 cwnd=32=ssthresh，收到ACK后 cwnd 变为 34，进入线性增长。

## 考察能力
本题核心考察考生对 TCP 拥塞控制算法（慢启动与拥塞避免）在多轮传输中窗口大小动态演化的精确模拟与计算能力。
