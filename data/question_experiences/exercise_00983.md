# 练习题 Q1 — 递归与链表逆序遍历

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/链表
- **难度**: 待评估

## 题干原文
以下函数对于给定的链表（第一个节点为 head）执行什么操作？
```c
void fun1(struct node *head) {
    if (head == NULL) return;
    fun1(head->next);
    printf("%d ", head->data);
}
```
- 选项:
  A: 打印链表的所有节点
  B: 以逆序打印链表的所有节点
  C: 打印链表的交替节点
  D: 以逆序打印链表的交替节点
- 正确答案: B
- 解析（参考）: 此函数 fun1 通过递归方式以逆序打印链表的元素。其执行逻辑如下：
递归终止条件：当传入的 head 为 NULL 时，函数直接返回，表示已到达链表末尾。
递归调用：函数优先调用自身处理下一个节点（head→next），这一过程会持续到链表最后一个节点。
回溯打印：当递归调用栈开始回退时，依次从最后一个节点向第一个节点打印每个节点的值（printf("%d ", head→data);）。
因此，该函数通过 先递归遍历至链表末尾，再在回溯阶段按逆序访问节点 的方式，实现链表的逆序输出。
- 知识标签: ['数据结构/链表']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握链表的基本结构（节点包含数据和指针）以及递归函数的基本执行流程（调用栈、终止条件）。这不是简单的定义记忆，而是对代码结构的认知，属于标准的基础认知需求。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、幂次运算或复杂的公式转换，仅涉及逻辑判断和指针移动，计算需求微弱。
- **K3 = 4**: 评分理由。考生需要在脑海中模拟递归的“深入”过程（直到NULL）和“回溯”过程（从NULL返回时执行printf）。对于长度为N的链表，需要推演N次递归调用和N次回溯打印的顺序关系。这种多步串行推演且需记忆中间状态（调用栈深度）的过程，难度较高。
- **K4 = 3**: 评分理由。存在一个常见的思维陷阱：初学者容易忽略递归调用的位置（在printf之前还是之后）。如果误以为先打印再递归，就会选A。识别“递归调用在前，打印在后”这一隐含的执行顺序逻辑是解题关键，属于常规注意点但易错。
- **K5 = 1**: 评分理由。本题仅涉及链表这一单一数据结构子系统，没有跨越操作系统、网络或其他模块的状态传递，属于单系统问题。
- **雷达形状**: K3推演主导型（K3高，K1中等，其余低）。

## 考察模式
- **模式**: 推理型
- **理由**: 题目不直接考察定义或公式，而是给出一段具体的代码实现，要求考生通过逻辑推理（模拟程序执行流程）来推导其最终行为。核心在于理解递归机制在链表遍历中的具体表现。

## 选项级分析
- **选项A**: [干扰] — 针对“忽略递归顺序”的错误认知。这类学生可能只看到了`printf`和`head->next`，认为只要遍历了就会打印，没有意识到递归调用在打印语句之前，导致顺序颠倒。
- **选项B**: [正确] — 正确理解了递归的“后序”特性：先深入到底，再在返回途中处理当前节点，从而实现逆序。
- **选项C**: [干扰] — 针对“对递归步长误解”的错误认知。这类学生可能误以为递归跳过了某些节点，或者混淆了“交替”与“逆序”的概念，通常是因为对代码逻辑完全陌生而进行的随机猜测。
- **选项D**: [干扰] — 针对“概念堆砌”的错误认知。结合了“逆序”和“交替”两个概念，试图迷惑那些知道是逆序但不确定是否完整遍历的学生，或者完全不懂代码的学生。
- **干扰策略**: 概念混淆（正序vs逆序）与 逻辑缺失（是否遍历所有节点）。

## 核心陷阱
- **核心陷阱**: **递归执行顺序的误判**。考生极易将 `fun1(head->next); printf(...);` 误读为 `printf(...); fun1(head->next);`。前者是后序遍历（逆序打印），后者是前序遍历（正序打印）。这是本题唯一的、也是最核心的逻辑陷阱。

一句话概括本题核心考察的能力：
**理解递归函数在链表遍历中的执行时序（调用栈深入与回溯）及其对数据访问顺序的影响。**
