# 练习题 Q1 — 直接映射缓存地址划分

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 计算机组成原理/存储系统
- **难度**: 待评估

## 题干原文
考虑一个大小为 32 KB 的直接映射缓存，块大小为 32 字节。CPU 生成 32 位地址。需要多少位用于缓存索引和标记位？（ ）
A: 10, 17
B: 10, 22
C: 15, 17
D: 5, 17

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握直接映射缓存（Direct Mapped Cache）的基本结构概念，即地址分为 Tag（标记）、Index（索引/行号）、Offset（块内偏移）三部分。属于标准的核心定义记忆，不涉及复杂概念辨析。
- **K2 = 2**: 评分理由。计算过程主要涉及 2 的幂次换算（$32KB = 2^{15}B$, $32B = 2^5B$）和简单的减法运算。由于数据均为 2 的整数次幂，计算友好，不易出错。
- **K3 = 2**: 评分理由。解题步骤清晰且串行：1. 计算 Offset 位数；2. 计算 Index 位数（通过 Cache 总行数或总大小推导）；3. 计算 Tag 位数。总共 3 步左右，逻辑线性，无需回溯或状态记忆。
- **K4 = 2**: 评分理由。存在常规注意点，即区分“Cache 总大小”与“Cache 行数”。题目给出的是 Cache 总容量（32KB），而非行数，考生需意识到需先除以块大小得到行数，或者通过总地址位减去 Offset 和 Index 的关系来推导。这是一个常规的逻辑转换点，非深层陷阱。
- **K5 = 1**: 评分理由。本题仅涉及存储系统内部的地址映射机制，不涉及 CPU 流水线、中断、多核同步等其他子系统的状态传递或耦合。

- **雷达形状**: K2/K3 主导的均衡偏计算型。整体难度较低，主要考察基础公式的应用和位运算逻辑。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于根据给定的硬件参数（Cache 大小、块大小、地址宽度），通过数学计算（对数运算、减法）得出具体的位数分配。虽然基于概念，但解题过程以数值推导为主。

## 选项级分析
- **选项 A**: [正确] — 正确计算了 Index (10位) 和 Tag (17位)。
  - 推导：Offset = $\log_2(32) = 5$ 位；Cache 行数 = $32KB / 32B = 1024 = 2^{10}$，故 Index = 10 位；Tag = $32 - 10 - 5 = 17$ 位。
- **选项 B**: [干扰] — 针对**忘记减去 Offset** 的错误认知。
  - 错误逻辑：考生可能正确计算了 Index 为 10 位，但在计算 Tag 时，误以为 Tag = 地址总长 - Index，即 $32 - 10 = 22$。忽略了块内偏移（Offset）也占用了地址位。
- **选项 C**: [干扰] — 针对**混淆 Cache 总大小与行数**的错误认知。
  - 错误逻辑：考生可能直接用 Cache 总大小对应的位数（15位）作为 Index，即认为 Index = 15。然后 Tag = $32 - 15 = 17$。这里 Tag 碰巧算对了（因为 $32-15=17$ 且 $32-10-5=17$，数学上 $Index+Offset=15$，所以如果误把 $Index+Offset$ 当作 Index，Tag 的计算结果在数值上可能因巧合或错误逻辑路径而接近，但此处 C 选项的 Tag 是 17，Index 是 15。若 Index=15，则 Tag 应为 $32-15-5=12$。等等，让我们重新检查 C 的干扰逻辑。
  - 修正 C 的干扰逻辑：如果考生误以为 Index 位数等于 Cache 总容量的对数位数（15位），那么 Tag = $32 - 15 - 5 = 12$。选项 C 是 15, 17。这看起来像是考生认为 Index=15，且 Tag = $32-15=17$（再次忽略 Offset）。或者，考生可能混淆了“索引位”和“缓存寻址位”的概念，认为需要 15 位来定位缓存中的字节，从而错误地将这 15 位全归为索引。
- **选项 D**: [干扰] — 针对**混淆 Offset 与 Index** 的错误认知。
  - 错误逻辑：考生正确计算了 Offset 为 5 位，但可能误将 Offset 的位数当作 Index 的位数，或者在计算 Index 时出错。例如，如果考生认为 Index = Offset = 5，那么 Tag = $32 - 5 - 5 = 22$（无此选项）。或者，考生可能计算出 Index=10，但错误地报告了 Offset=5 作为第一个数字？不，选项 D 是 5, 17。如果 Index=5，Tag=17，则 Offset 必须是 $32-5-17=10$，这与块大小 32B (5位) 矛盾。
  - 更可能的 D 选项干扰逻辑：考生可能计算出 Offset=5，然后错误地认为 Index 也是 5（可能误以为行数=块大小？），或者单纯看错了数字。另一种可能是：考生计算出 Tag=17，然后看到选项中有 17，随意搭配了一个小的数字 5（Offset 的值）作为 Index。

- **干扰策略**: 概念混淆（忽略 Offset 的存在）和 计算陷阱（混淆 Cache 容量位数与行数位数）。

## 核心陷阱
- **核心陷阱**: **忽略块内偏移（Offset）对地址位的占用**。
  许多初学者在计算 Tag 位数时，容易直接使用 `Tag = 地址总长 - Index`，而忘记了地址结构是 `Tag + Index + Offset`。正确的公式是 `Tag = 地址总长 - Index - Offset`。
  另一个次要陷阱是**混淆 Cache 总大小与 Cache 行数**。必须通过 `Cache 总大小 / 块大小` 得到行数，再对行数取对数得到 Index 位数，而不是直接对 Cache 总大小取对数。

## 考察能力
本题核心考察考生对**直接映射缓存地址结构（Tag-Index-Offset）的分解能力**以及**基于 2 的幂次进行位数换算的计算能力**。
