# 练习题 Q1 — Cache组相联映射与地址分解

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 计算机组成原理/存储系统
- **难度**: 待评估

## 题干原文
某计算机系统字长为 32 位，具有 16MB 的字节可寻址主存和 64KB、4 路组相联的高速缓存，块大小为 256 字节。考虑以下四个以十六进制表示的物理地址：
A1 = 0x42C8A4，A2 = 0x546888，A3 = 0x6A289C，A4 = 0x5E4880
以下哪一项是正确的（ ）？
- 选项:
  A: A1 和 A4 映射到不同的高速缓存组。
  B: A2 和 A3 映射到相同的高速缓存组。
  C: A3 和 A4 映射到相同的高速缓存组。
  D: A1 和 A3 映射到相同的高速缓存组。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握Cache映射的基本概念（组相联、块大小、组索引、字偏移），属于标准的核心定义记忆。不是4分因为不需要辨析多个易混的高级概念（如写策略、替换算法等），仅涉及映射结构。
- **K2 = 3**: 评分理由。涉及多级换算：首先计算组数（容量/块大小/路数），然后计算索引位数，最后进行十六进制到二进制的转换及位提取。虽然都是2的幂次，但步骤较多，容易在位数计算或位提取时出错，属于标准难度的计算。
- **K3 = 3**: 评分理由。解题过程包含明确的串行步骤：1. 计算Cache参数（块内偏移位、组索引位）；2. 确定物理地址中组索引对应的位域；3. 对四个地址分别提取该位域的值；4. 比较各组索引值。共3-4步逻辑推演，属于标准复杂度。
- **K4 = 2**: 评分理由。存在常规注意点，即“字节可寻址”意味着地址最低位是字节偏移，且块大小256B对应8位偏移。没有深层隐含前提或反直觉陷阱，只要按部就班计算即可避开错误。
- **K5 = 1**: 评分理由。本题完全局限于存储系统内部的Cache映射机制，不涉及CPU流水线、中断处理、文件系统或其他子系统的状态传递，属于单系统内部问题。
- **雷达形状**: K2/K3主导的计算推理型。K1基础扎实，K4陷阱较少，整体呈现均衡偏计算的特征。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的Cache参数（容量、路数、块大小）计算出地址的位域划分，并对具体地址进行二进制位提取和比较。虽然涉及概念，但最终答案依赖于精确的数值计算和位操作。

## 选项级分析
- **选项A**: [干扰] — 针对计算错误或位提取错误的学生。如果学生错误地认为A1和A4的组索引不同，可能会选此项。实际上A1组索引为8，A4组索引为8，它们映射到**相同**组，故A错误。这类学生可能混淆了标记位和索引位，或者在十六进制转二进制时出错。
- **选项B**: [正确] — A2 (0x...6888) 的中间字节68 (01101000) 的低6位是 101000 (十进制40)；A3 (0x...289C) 的中间字节28 (00101000) 的低6位是 101000 (十进制40)。两者组索引相同，故映射到相同组。
- **选项C**: [干扰] — 针对未仔细计算A3和A4组索引的学生。A3组索引为40，A4组索引为8，两者不同。学生可能仅看地址的高位或低位相似性而误判。
- **选项D**: [干扰] — 针对未仔细计算A1和A3组索引的学生。A1组索引为8，A3组索引为40，两者不同。学生可能因为地址高位不同而直觉认为组不同，或者计算失误。

- **干扰策略**: 计算陷阱。通过提供多个看似相似的十六进制地址，诱导学生在位提取时发生偏移错误（如多取一位或少取一位），或者在十六进制转二进制时出错，从而得出错误的组索引比较结果。

## 核心陷阱
- **核心陷阱**: **地址位域的精确划分与提取**。
  1. **块内偏移位数计算**：块大小256B = $2^8$，故低8位为块内偏移。
  2. **组索引位数计算**：Cache总块数 = 64KB / 256B = 256块。4路组相联，故组数 = 256 / 4 = 64组 = $2^6$，故组索引占6位。
  3. **位提取位置**：组索引位于地址的第8~13位（从0开始计数）。在十六进制表示中，这对应于从右往左数，跳过最低位十六进制数（4位）和次低位十六进制数的低4位（即第8-11位的一部分），实际上需要仔细对齐。
     - 更简单的技巧：将地址转为二进制，从右向左数，跳过8位（块内偏移），接下来的6位即为组索引。
