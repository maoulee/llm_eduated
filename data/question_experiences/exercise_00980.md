# 练习题 Q1 — 进程互斥机制与临界区安全性分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
进程 P1 和 P2 使用以下代码中的 critical_flag 实现互斥。假设主程序中将 critical_flag 初始化为 FALSE。
```c
get_exclusive_access()
{
    if (critical_flag == FALSE)
    {
        critical_flag = TRUE;
        critical_region();
        critical_flag = FALSE;
    }
}
```
考虑以下两个陈述：
i. P1 和 P2 可能同时访问临界区。
ii. 此方法可能导致死锁。
以下哪项正确？（ ）
- 选项:
  A: (i) 错误且 (ii) 正确
  B: (i) 和 (ii) 均错误
  C: (i) 正确且 (ii) 错误
  D: (i) 和 (ii) 均正确

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“临界区”、“互斥”、“死锁”以及“进程并发执行”的核心定义。不是4分因为不需要辨析多个复杂的同步原语（如信号量、管程等），只需理解基本的标志位机制。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算，无需执行算术或逻辑运算，仅涉及代码逻辑的理解。
- **K3 = 3**: 评分理由。需要推演进程调度的时序。从输入（两个进程并发）到输出（判断是否互斥/死锁），需要模拟“检查-设置”这一非原子操作在并发环境下的执行步骤（P1检查->P1被中断->P2检查->P2设置->P1恢复设置->两者进入）。这属于3-5步的串行推演，且需记忆中间状态（flag的值）。
- **K4 = 4**: 评分理由。存在显著的隐含前提和反直觉陷阱。题面未明确说明`if`判断和赋值是原子操作，考生必须意识到在操作系统底层，这两步通常是非原子的，且上下文切换可能发生在任意指令之间。这是解题的关键隐含条件，属于“隐含前提深”或“反直觉”（直觉上认为if-then是连贯的，但并发下不是）。
- **K5 = 2**: 评分理由。主要涉及进程管理子系统内部的同步问题。虽然涉及两个进程的状态交互，但未跨越到内存管理、文件系统等其他子系统，属于单系统内的状态互影响，但耦合度较低，故给2分（提及无关则2，单向传数据则3，此处为简单的状态竞争）。

- **雷达形状**: K4陷阱型（K4显著高于其他维度，K2极低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖公式计算，也不单纯考察概念记忆，而是要求考生基于并发执行的基本原理，推演特定代码片段在多进程环境下的执行轨迹，从而判断其正确性（互斥性）和安全性（死锁性）。

## 选项级分析
- **选项A**: [干扰] — 针对认为“该代码能实现互斥但会死锁”的错误认知。这类学生可能误以为`critical_flag = TRUE`后如果进程崩溃或异常退出会导致死锁，或者混淆了“忙等待”与“死锁”的概念。
- **选项B**: [干扰] — 针对认为“该代码完美实现互斥且无死锁”的错误认知。这类学生通常忽略了并发环境下的“检查-设置”非原子性问题，误以为`if`语句是一个原子操作，从而认为互斥是安全的。
- **选项C**: [正确] — 正确识别了互斥失效（i正确）和无死锁风险（ii错误）。
- **选项D**: [干扰] — 针对认为“既不能互斥又会死锁”的错误认知。这类学生可能认为一旦flag被设为TRUE，另一个进程永远无法进入，从而误判为死锁，同时正确识别了互斥问题。

- **干扰策略**: 概念混淆（将“互斥失效”与“死锁”混淆，或将“非原子操作”误认为“原子操作”）

## 核心陷阱
- **核心陷阱**: **“检查-设置”非原子性导致的互斥失效**。考生容易直觉地认为 `if (flag == FALSE) { flag = TRUE; }` 是一个连贯的动作，从而误判互斥是有效的。实际上，在并发环境下，P1执行完检查后、执行赋值前可能被中断，导致P2也能通过检查，从而破坏互斥。同时，考生需区分“互斥失效”（两个进程同时进入）与“死锁”（进程无限等待资源），本题中由于没有循环等待或持有资源不释放的逻辑，因此不会死锁。

## 考察能力
一句话概括本题核心考察的能力：在并发环境下分析非原子操作对进程互斥机制正确性与安全性的影响。
