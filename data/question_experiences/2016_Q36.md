# 2016 Q36 — CSMA/CD 冲突检测与最大网段长度计算

## 基本信息
- **年份**: 2016  **题位**: Q36  **题型**: 选择题
- **知识点**: CN-3 > 介质访问控制 > CSMA协议
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
若 Hub 再生比特流过程中，会产生 1.535μs 延时，信号传播速度为 200m/μs，不考虑以太网帧的前导码，则 H3 与 H4 之间理论上可以相距的最远距离是（ ）。
CSMA/CD限制条件

A. 200 m
B. 205 m
C. 359 m
D. 512 m

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆以太网最短帧长（64B）这一核心常数，以及 CSMA/CD 协议中“往返时延（RTT）≤ 帧传输时延”的基本原理。属于标准的基础概念调用，不涉及复杂概念辨析。
- **K2 = 3**: 评分理由。涉及单位换算（B 到 bit，Mbps 到 μs）和简单的加减乘除。虽然计算量不大，但涉及多级单位转换（64B -> 512bit -> 5.12μs -> 2.56μs），且数字非 2 的幂次友好型（1.535），容易在计算过程中出错，属于标准难度的单步代入。
- **K3 = 3**: 评分理由。解题逻辑链条清晰但步骤较多：1. 确定最短帧长对应的传输时延；2. 根据 CSMA/CD 原理确定单程最大允许时延（含传播+处理）；3. 扣除 Hub 处理时延得到纯传播时延；4. 计算距离。属于 3-5 步的标准推演。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。首先，题干未直接给出传输速率，需通过“100Base-T”或上下文隐含条件（通常此类题目默认 100Mbps，或者需从选项反推，但解析中明确指出了 100Mbps，这是关键隐含条件）；其次，最容易掉入的陷阱是忘记除以 2（混淆往返时延与单程时延），或者忘记扣除 Hub 的再生延时。这属于典型的“隐含前提深”和“陷阱词”场景。
- **K5 = 2**: 评分理由。主要考察数据链路层的介质访问控制机制，虽然涉及物理层的传播速度，但属于同一网络层次内的参数联动，未跨越不同子系统（如网络层或应用层），属于提及无关或单向传数据的低耦合度。

- **雷达形状**: K4 陷阱型（K4 显著高于其他维度，主要难点在于识别隐含条件和避开计算陷阱）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的物理参数（速度、延时）和协议参数（最短帧长、速率），利用公式计算出具体数值（距离）。虽然需要理解协议原理，但最终落脚点是精确的数值计算。

## 选项级分析
- **选项 A**: [干扰] — 针对忽略 Hub 延时或计算错误的学生。如果直接用 $200 \times 1 = 200$，或者粗略估算，可能会选此项。
- **选项 B**: [正确] — 正确计算结果。$200 \times (2.56 - 1.535) = 205$。
- **选项 C**: [干扰] — 针对忘记除以 2 的学生。如果误以为单程传输时延等于帧传输时延（即 $5.12\mu s$），则单程传播时延为 $5.12 - 1.535 = 3.585\mu s$，距离为 $200 \times 3.585 \approx 717m$（无此选项）。另一种可能是混淆了往返时延和单程时延的关系，或者在计算 $64B/100Mbps$ 时出错。更可能的错误路径是：直接用往返时延 $5.12\mu s$ 减去 Hub 延时 $1.535\mu s$ 得到 $3.585\mu s$，然后错误地认为这是单程传播时间，或者在计算过程中将 $64B$ 当作 $32B$ 等。实际上，C 选项 $359m$ 接近 $200 \times (5.12/2 + \text{error})$ 或类似错误组合。最常见的错误是忘记除以 2，算出 $5.12 - 1.535 = 3.585$，若此时再错误地乘以 2 或其他操作。*修正分析*：若学生忘记除以 2，认为单程最大时延就是帧传输时延 $5.12\mu s$，则传播时延 $= 5.12 - 1.535 = 3.585\mu s$，距离 $= 200 \times 3.585 = 717m$。若学生认为 Hub 延时是往返的，或者计算 $64B$ 时延为 $5.12\mu s$，直接 $5.12 - 1.535 = 3.585$，然后 $3.585 \times 100$? 不对。
    *重新推导 C 选项来源*：$359 / 200 = 1.795\mu s$。$1.795 + 1.535 = 3.33\mu s$。$3.33 \times 2 = 6.66\mu s$。这似乎没有明显的常见错误对应。
    *另一种可能*：如果误以为最短帧长是 128B？或者速率是 10Mbps？
    *最可能的干扰逻辑*：C 选项可能是针对那些在计算 $64B/100Mbps$ 时，误算为其他值，或者在扣除延时后，错误地使用了往返距离公式 $2 \times v \times t$ 但 $t$ 取值错误。
    *实际上*，很多学生会忘记“单程”这个概念，直接用 $RTT \le T_{frame}$。如果误以为 $2 \times t_{prop} + t_{hub} \le T_{frame}$ 中的 $t_{hub}$ 也是往返的？
    让我们看 D 选项。
- **选项 D**: [干扰] — 针对完全忽略 Hub 延时或公式记忆错误的学生。$512m$ 对应 $2.56\mu s$ 的传播时延。如果学生忘记扣除 Hub 的 $1.535\mu s$ 延时，直接计算 $200 \times 2.56 = 512m$。这是最典型的“忽略题目特定条件”的干扰项。

- **干扰策略**: 计算陷阱（忘记除以 2、忘记扣除 Hub 延时、单位换算错误）

## 核心陷阱
- **核心陷阱**: **单程与往返时延的混淆**以及**Hub 再生延时的扣除**。
    1.  CSMA/CD 要求的是**往返时延（RTT）**小于等于**帧传输时延**。即 $2 \times t_{prop} + t_{hub} \le T_{frame}$（注意：Hub 延时通常被视为单程处理延时，但在总线型或星型拓扑中，信号经过 Hub 转发，往返会经过两次 Hub 吗？题目表述“Hub 再生比特流过程中...延时”，通常指信号通过 Hub 的一次转发延时。在 H3-Hub-H4 结构中，信号从 H3 到 H4 经过一次 Hub 再生，从 H4 到 H3 碰撞信号返回也经过一次 Hub 再生？
    *深度辨析*：题目问的是 H3 与 H4 之间的最远距离。在 100Base-T 星型拓扑中，H3 发送数据，经过 Hub 转发到 H4。如果发生碰撞，碰撞信号从 H4 传回 Hub，再传回 H3。
    标准公式：$2 \times t_{prop} + t_{hub\_total} \le T_{frame}$。
    这里的 $t_{hub}$ 是 $1.535\mu s$。这个延时是单程经过 Hub 的延时吗？
    解析中给出的公式是：单程传输时延（指帧在链路上的发送时间的一半？不，解析写的是 $64B/100Mbps/2 = 2.56\mu s$。这里 $64B/100Mbps = 5.12\mu s$ 是帧传输时延 $T_{frame}$。解析认为 $T_{frame}/2 = 2.56\mu s$ 是允许的单程总时延（传播+Hub）。
    这意味着解析假设：$t_{prop} + t_{hub} \le T_{frame} / 2$。
    即 $2 \times (t_{prop} + t_{hub}) \le T_{frame}$。
    这隐含了碰撞检测的最坏情况是：A 发送，信号到达 Hub，Hub 转发到 B。B 发送，信号到达 Hub，Hub 转发到 A。
    如果 Hub 延时是单向的，那么往返确实经过两次 Hub。
    解析逻辑：$t_{prop} + 1.535 \le 2.56 \Rightarrow t_{prop} \le 1.025$。
    陷阱在于：学生容易直接用 $T_{frame}$ 作为单程限制，或者忘记 Hub 延时在往返中是否计算两次（题目通常简化为单程等效延时或总延时，需根据解析反推题意，本题解析明确将 Hub 延时视为单程路径的一部分，且与传播时延相加后乘以 2 等于帧长时延）。
    最核心的陷阱是：**忘记将帧传输时延除以 2 来得到单程最大允许时延**，以及**忘记从允许时延中扣除 Hub 的处理延时**。

## 考察能力
本题核心考察考生对 CSMA/CD 协议中“冲突检测窗口”原理的理解，以及在包含网络设备（Hub）处理延时情况下，准确计算网络最大物理直径的能力。
