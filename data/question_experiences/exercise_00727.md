# 练习题 Q1 — 滑动窗口协议与带宽时延积计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/数据链路层
- **难度**: 待评估

## 题干原文
站 A 使用 32 字节的数据包通过滑动窗口协议向站 B 发送消息。A 和 B 之间的往返延迟为 40 毫秒，路径上的瓶颈带宽为 64 kbps。A 的最优窗口大小是（ ）。
- 选项:
  A: 20
  B: 10
  C: 30
  D: 40

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“带宽时延积（BDP）”的概念以及“最优窗口大小”的定义（即为了填满管道，窗口大小应等于BDP包含的分组数）。这不是简单的术语记忆，而是对协议性能优化核心指标的理解。不是4分因为不需要辨析多个易混概念（如Go-Back-N与Selective Repeat的区别在此题中不影响BDP计算本身，只影响实现复杂度，但题目问的是理论最优窗口）。
- **K2 = 3**: 评分理由。涉及单位换算（kbps到bps，ms到s，bits到Bytes）和除法运算。虽然数字较小（40, 64, 32），但存在多级单位换算（时间、带宽、数据量），若粗心容易出错（如忘记除以8或时间单位未对齐）。不是2分因为不是纯2的幂次友好计算（40ms不是2的幂，64kbps是，32B是，混合计算增加了认知负荷）。
- **K3 = 2**: 评分理由。逻辑链条清晰：计算BDP（位）-> 转换为字节 -> 除以包大小得到包数。步骤为3步左右，属于标准线性推导，无需复杂的状态机推演或回溯。
- **K4 = 2**: 评分理由。隐含前提较少，主要陷阱在于“往返延迟”是否包含处理时间（通常题目给出的RTT即为总延迟）以及“最优窗口”的定义。常规注意点在于单位统一。没有明显的反直觉陷阱或深层隐含条件。
- **K5 = 1**: 评分理由。本题仅涉及数据链路层/传输层的滑动窗口机制与物理层/网络层的带宽延迟特性，属于单系统内的参数计算，不涉及跨子系统（如应用层与网络层）的状态传递或深度耦合。
- **雷达形状**: K2计算主导型，K1基础支撑，整体呈低维均衡偏计算特征。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的物理参数（带宽、延迟、包大小）进行数值计算，得出协议参数（窗口大小）。虽然基于概念，但解题过程完全依赖于公式代入和单位换算。

## 选项级分析
- **选项A (20)**: [干扰] — 针对单位换算错误。学生可能忘记将带宽从kbps转换为bps，或者忘记将比特转换为字节，导致结果翻倍。例如，若直接用 $40 \times 64 / 32 = 80$ (错误逻辑) 或类似错误路径。更可能的错误是：计算BDP时未除以8，得到3200位，再除以32字节（误以为32位），得100？不对。常见错误是：$40ms \times 64kbps = 2560 bits$。如果忘记除以8转为字节，直接用2560除以32（误以为包大小是32bit或混淆单位），得80。如果学生算出BDP为320字节，但误以为窗口大小是字节数而非包数，且混淆了其他系数。另一种可能是：误将RTT当作单程延迟，或者在计算中多乘了2。实际上，若学生计算出BDP为320字节，然后错误地认为窗口大小需要是BDP的2倍（某些特定协议误解），可能选64（无此选项）。最可能的错误路径：$40 \times 64 = 2560$ bits。$2560 / 32 = 80$。如果学生忘记单位换算，直接用数字相除，可能得到其他结果。让我们看选项A=20。如果学生算出BDP=320字节，然后除以16（误记包大小）？或者，如果学生认为最优窗口是BDP的一半？
    *修正分析*：若学生忘记将kbps转为bps（即认为64kbps=64bps），则 $40ms \times 64bps = 2.56 bits$，显然不对。
    *更可能的错误*：学生正确算出BDP=320字节。如果学生误以为“窗口大小”指的是字节数，而选项中没有320。
    *针对A=20的特定错误*：可能学生将RTT 40ms当作单程20ms计算？$20ms \times 64kbps = 1280 bits = 160 Bytes$。$160 / 32 = 5$。不对。
    *另一种可能*：学生计算 $40 \times 64 / 32 = 80$。然后除以4（误操作）？
    *最合理的干扰逻辑*：学生可能混淆了“带宽时延积”与“发送时延”。发送时延 $T_{trans} = 32B / 64kbps = 256bits / 64000bps = 4ms$。$RTT / T_{trans} = 40 / 4 = 10$。这是正确解法。如果学生误用 $RTT / (2 \times T_{trans})$ 或其他错误公式，可能得到5或20。若学生误以为窗口大小需覆盖往返两次（去和回都算发送？），可能乘以2得到20。
- **选项B (10)**: [正确] — 正确计算带宽时延积（BDP）并转换为数据包数量。
    1. 带宽 $B = 64 \text{ kbps} = 64,000 \text{ bps}$
    2. 延迟 $RTT = 40 \text{ ms} = 0.04 \text{ s}$
    3. BDP (bits) $= 64,000 \times 0.04 = 2,560 \text{ bits}$
    4. BDP (Bytes) $= 2,560 / 8 = 320 \text{ Bytes}$
    5. 窗口大小 (packets) $= 320 / 32 = 10$
- **选项C (30)**: [干扰] — 针对计算错误或概念混淆。可能是随机猜测，或者在单位换算中出现较大偏差（如将kbps误认为Mbps，或ms误认为s，导致数量级错误后强行凑数）。或者学生误将32字节当作32位计算，且其他步骤出错。
- **选项D (40)**: [干扰] — 针对直接数字匹配陷阱。题干中有“40毫秒”，学生可能直接选择与题干数字相同的选项，而不进行任何计算。这是典型的“数字敏感型”错误。

- **干扰策略**: 计算陷阱（单位换算遗漏）与数字匹配陷阱（直接选题干数字）。

## 核心陷阱
- **核心陷阱**: **单位不统一**。题目中带宽单位是 kbps (kilobits per second)，延迟是 ms (milliseconds)，数据包大小是 Bytes (Bytes)。解题必须将带宽转换为 bps，延迟转换为 s，并将最终的比特数转换为字节数，或者将数据包大小转换为比特数。任何一步单位换算错误都会导致答案偏差8倍或1000倍。

## 考察能力
本题核心考察考生对**带宽时延积（Bandwidth-Delay Product）**概念的理解，以及在滑动窗口协议背景下，通过**多单位换算**计算**最优窗口大小**以最大化链路利用率的能力。
