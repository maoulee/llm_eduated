# 模拟题 Q1 — 存储器扩展与地址空间计算

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 计算机组成原理
- **知识点**: 存储器扩展、地址空间计算、芯片位宽与字长匹配
- **难度**: 中等

## 题干原文
设某按字节编址的计算机已配有 00000H～07FFFH 的 ROM 区，MAR 为 20 位，现再用 16K×8 位的 RAM 芯片构成剩下的 RAM 区 08000H～FFFFFH，则需要这样的 RAM 芯片（ ）片。
- 选项:
  A: 61
  B: 62
  C: 63
  D: 64
- 正确答案: B

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“按字节编址”、“MAR位数决定地址空间”、“存储器容量计算公式”等核心概念。不记忆这些基础定义无法入题，但无需辨析极度易混的高级概念，属于标准的基础认知需求。
- **K2 = 4**: 评分理由。涉及多级换算和十六进制运算。需要计算地址范围大小（十六进制减法）、将十六进制容量转换为十进制KB、计算单片芯片容量、最后进行除法取整。其中 `FFFFFH - 08000H + 1` 以及 `F8000H` 到 `992KB` 的转换容易出错，且最终结果非整数需向上取整，计算复杂度较高。
- **K3 = 3**: 评分理由。解题步骤清晰但串行步骤较多：1. 确定总地址空间；2. 计算ROM占用空间；3. 计算剩余RAM所需空间；4. 计算单片RAM容量；5. 计算所需芯片数量。属于3-5步的标准推演。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。1. “按字节编址”意味着地址线直接对应字节，无需考虑字长转换；2. 地址范围计算必须“加1”（包含起始和结束地址）；3. 芯片数量必须“向上取整”（Ceiling），因为不能用半片芯片；4. 题目给出的RAM区范围 `08000H～FFFFFH` 是剩余空间，需验证其是否等于总空间减ROM空间（本题中恰好吻合，但需意识到位宽匹配问题，即RAM芯片是8位，系统也是按字节编址，位宽匹配，无需并联扩展位宽，只需串联扩展容量）。若忽略“向上取整”或“地址加1”，极易选错。
- **K5 = 1**: 评分理由。本题仅涉及存储器子系统内部的容量扩展计算，不涉及CPU、I/O或其他子系统之间的状态传递或耦合，属于单系统问题。
- **雷达形状**: K2-K4 突出型（计算与陷阱主导）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的地址范围和硬件参数，进行精确的数值计算以得出芯片数量。虽然涉及概念，但最终落脚点在于算术运算和逻辑取整。

## 选项级分析
- **选项A**: [干扰] — 针对“向下取整”或“计算错误”的认知。如果学生计算出需要61.4片，错误地向下取整为61，或者在十六进制减法中少算了一个单位，可能会选A。
- **选项B**: [正确] — 正确计算结果。RAM总需求992KB，单片16KB，992/16 = 62。恰好整除，无需向上取整的陷阱（或者说陷阱在于是否算对992KB）。*注：此处需仔细核对计算，见下文核心陷阱分析，实际上992/16=62，正好整除。*
- **选项C**: [干扰] — 针对“地址范围计算错误”或“向上取整误用”。如果学生错误地认为地址范围是 `FFFFFH - 08000H` (忘记加1)，得到 `F7FFFH` (991KB)，991/16 = 61.9375，向上取整得62。等等，如果算错成其他值？另一种可能是学生误以为总空间是1MB=1024KB，ROM是32KB，剩992KB。如果学生误算ROM大小为31KB或其他，导致剩余空间变大，或者误以为需要向上取整（即使整除也+1），可能选63。更常见的错误是：如果学生忘记“按字节编址”或混淆位宽，可能会引入额外的并联芯片，导致数量翻倍或变化。但在本题中，C选项63通常是计算误差或错误向上取整的结果。
- **选项D**: [干扰] — 针对“忽略ROM占用”或“粗略估算”。如果学生直接用总空间1MB (1024KB) 除以 16KB，得到 64片。这是最常见的错误，即忽略了题目中“已配有ROM区”这一条件，直接用总地址空间计算。

**干扰策略**: 计算陷阱（忽略ROM占用、地址范围计算错误、取整规则错误）

## 核心陷阱
1. **忽略已占用的ROM空间**：直接用总地址空间（1MB）除以单片容量，得出64片（选项D）。这是最大的陷阱，必须用“总空间 - ROM空间”得到RAM所需空间。
2. **地址范围计算错误**：计算地址空间大小时，公式应为 `End - Start + 1`。若忘记加1，会导致容量计算偏差。
3. **十六进制与十进制转换错误**：`07FFFH` 是 32767，加1后是 32768 (32KB)。`FFFFFH` 是 1048575，`08000H` 是 32768。`1048575 - 32768 + 1 = 1015808` 字节。`1015808 / 1024 = 992 KB`。
4. **取整规则**：虽然本题 `992 / 16 = 62` 恰好整除，但一般原则是芯片数量必须向上取整。如果计算结果有小数，必须进位。

## 考察能力
本题核心考察考生对存储器地址空间划分的理解，以及在不同进制下进行容量计算和芯片扩展数量推导的精确计算能力。
