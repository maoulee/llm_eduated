# 模拟题 Q1 — 折半查找过程模拟

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: DS-7 > 7.2 顺序查找和折半查找 > 折半查找过程
- **难度**: 待评估

## 题干原文
折半查找有序表 (2,10,25,35,40,65,70,75,81,82,88,100)，若查找元素 75，需依次与表中元素（ ）进行比较。
A: 65,82,75
B: 70,82,75
C: 65,81,75
D: 65,81,70,75

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆折半查找的核心公式 `mid = ⌊(low + high) / 2⌋` 以及查找区间更新规则（`low = mid + 1` 或 `high = mid - 1`）。如果不记忆这个核心定义和取整规则，无法入题，但无需辨析多个易混概念，属于标准的基础认知需求。
- **K2 = 3**: 评分理由。涉及多次整数除法及向下取整运算（如 `(1+12)/2=6`, `(7+12)/2=9` 等）。虽然数字较小，但非2的幂次，且每一步的计算结果直接影响下一步的区间，单步计算若出错会导致后续全盘皆错，属于标准的计算需求。
- **K3 = 4**: 评分理由。从输入到输出需要4步串行推演。每一步都需要根据上一步的比较结果（大于、小于或等于）来更新 `low` 和 `high` 指针，并重新计算 `mid`。步骤超过3步，且需要记忆中间状态（当前的 `low` 和 `high` 值），因此推演难度较高。
- **K4 = 3**: 评分理由。存在常规注意点作为陷阱。主要陷阱在于 `mid` 的取整方式（向下取整 vs 向上取整）以及区间更新时是否包含 `mid` 本身（通常折半查找比较后若不等，`mid` 位置不再参与后续查找，即 `low=mid+1` 或 `high=mid-1`）。如果考生误用向上取整或错误更新区间，会落入陷阱。
- **K5 = 1**: 评分理由。本题仅涉及数据结构中的查找算法单一模块，无需跨越不同子系统或模块传递状态，属于单系统问题。
- **雷达形状**: K3推演主导型（K3较高，K1/K2中等，K4有陷阱，K5极低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非单纯的概念记忆或简单公式代入，而是要求考生按照折半查找的算法逻辑，一步步模拟执行过程。考生必须在脑海中或草稿纸上维护查找区间的变化，并根据比较结果进行逻辑分支判断，最终得出比较序列。这种多步状态更新和逻辑判断的过程属于典型的推理型考察。

## 选项级分析
- **选项A**: [干扰] — 针对“向上取整”或“区间更新错误”的认知。如果考生使用 `mid = ⌈(low + high) / 2⌉`（向上取整），第一次 `mid` 为 7 (70)，若此时误判或计算错误，可能导向不同路径。或者，如果考生在第二次查找时，错误地将区间设为 `[7, 12]` 并计算 `mid` 为 9 (81)，但随后在第三次查找时错误地选择了右侧区间或计算错误，可能得到 82。更可能的情况是，考生记错了判定树的结构，或者在第二次比较 81 后，错误地认为 75 在 81 的右侧（逻辑错误），或者在计算第三次 `mid` 时出错。实际上，A选项的 82 出现在第二次比较后，暗示考生可能在第二次比较 65 后，错误地进入了右半区 `[7, 12]`，然后计算 `mid` 为 9 (81)，若此时考生误以为 75 > 81（不可能），或者在第三次计算时出错。更常见的错误路径是：第一次 65 (mid=6)，75>65，low=7；第二次区间 [7,12]，mid=9 (81)，75<81，high=8；第三次区间 [7,8]，mid=7 (70)，75>70，low=8；第四次区间 [8,8]，mid=8 (75)。A选项只有3次比较，且包含82，说明考生可能在某一步错误地扩大了搜索范围或计算错了mid。例如，若第二次 mid 算成 10 (82)，则需 75<82，high=9，第三次区间 [7,9]，mid=8 (75)，这样就是 65, 82, 75。这对应于 `mid = ⌈(low+high)/2⌉` 的情况：第一次 (1+12)/2=6.5->7 (70)? 不对。若用向上取整：第一次 mid=7 (70)，75>70，low=8；第二次区间 [8,12]，mid=10 (82)，75<82，high=9；第三次区间 [8,9]，mid=8 (75)。这样序列是 70, 82, 75 (选项B)。那A怎么来的？可能是第一次 mid=6 (65)，75>65，low=7；第二次区间 [7,12]，若错误地认为 mid 是 (7+12)/2=9.5->10 (82)（向上取整），则 75<82，high=9；第三次区间 [7,9]，mid=8 (75)。序列：65, 82, 75。这是混合错误：第一次向下，第二次向上。或者考生直接背错了判定树。
- **选项B**: [干扰] — 针对“向上取整”的认知。如果考生使用 `mid = ⌈(low + high) / 2⌉`（向上取整）：
    1. `low=1, high=12`, `mid=⌈6.5⌉=7`, 元素 70。75 > 70, `low=8`。
    2. `low=8, high=12`, `mid=⌈10⌉=10`, 元素 82。75 < 82, `high=9`。
    3. `low=8, high=9`, `mid=⌈8.5⌉=9`, 元素 81? 不对，mid=8.5向上是9? 不，(8+9)/2=8.5，向上取整是9。元素81。75 < 81, `high=8`。
    4. `low=8, high=8`, `mid=8`, 元素 75。
    序列：70, 82, 81, 75。这与B也不完全匹配。
    让我们重新检查B选项：70, 82, 75。
    如果第一次 mid=7 (70)，75>70，low=8。
    第二次区间 [8,12]，mid=10 (82)，75<82，high=9。
    第三次区间 [8,9]，mid=8 (75)。
    这需要：第一次向上取整得7，第二次向上取整得10，第三次向下或向上都得8。
    或者，考生可能错误地认为第一次 mid 是 7 (70)，然后错误地计算第二次 mid。
    更可能的错误路径：考生记错了数组索引或值。
    实际上，B选项是典型的“向上取整”策略下的常见错误结果之一，或者考生混淆了左右子树的划分。
- **选项C**: [干扰] — 针对“区间更新错误”或“漏步”的认知。序列 65, 81, 75。
    1. 65 (mid=6), 75>65, low=7。
    2. 81 (mid=9), 75<81, high=8。
    3. 此时区间 [7,8]。正确 mid 应为 7 (70)。但考生直接跳到了 75 (mid=8)。
    这暗示考生在第三次查找时，错误地认为区间是 [8,8] 或者错误地计算了 mid。例如，若考生错误地认为 `low` 更新为 `mid` 而不是 `mid+1`，或者在第二次比较后，错误地将 `low` 设为 8（认为 75 肯定在 81 左边且大于 70 的某个位置，直觉跳跃）。或者，考生可能误以为在比较 81 之后，因为 75 接近 81，直接查找 75。这反映了考生对折半查找“必须二分”的机械性理解不足，或者在计算 `mid = ⌊(7+8)/2⌋ = 7` 时出错，算成了 8。
- **选项D**: [正确] — 正确模拟了折半查找过程。
    1. `low=1, high=12`, `mid=6`, 元素 65。75 > 65, `low=7`。
    2. `low=7, high=12`, `mid=9`, 元素 81。75 < 81, `high=8`。
    3. `low=7, high=8`, `mid=7`, 元素 70。75 > 70, `low=8`。
    4. `low=8, high=8`, `mid=8`, 元素 75。找到。
    序列：65, 81, 70, 75。

- **干扰策略**: 计算陷阱与概念混淆。通过设置不同的取整规则（向上/向下）和区间更新错误（是否包含mid），生成看似合理但逻辑错误的比较序列。特别是选项C，通过减少一步比较，吸引那些对“二分”过程不严谨、试图“猜”答案的考生。

## 核心陷阱
- **核心陷阱**: `mid` 的取整规则（向下取整）以及查找区间更新时 `mid` 位置的排除（`low = mid + 1` 或 `high = mid - 1`）。考生容易在第三次查找时，面对区间 `[7, 8]`，错误地计算 `mid` 或跳过 70 直接查找 75，或者混淆向上/向下取整导致路径偏差。

## 考察能力
本题核心考察考生对折半查找算法执行过程的精确模拟能力，包括中间指针的更新逻辑和取整规则的应用。
