# 练习题 Q1 — TCP控制标志位功能辨析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
以下哪个 TCP 首部的控制栏位用於指定发送方没有更多数据要传输？（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。本题属于标准的基础概念记忆题。考生需要准确记忆 TCP 首部中各个标志位（Flag）的具体含义。虽然不需要复杂的推导，但需要区分 FIN、SYN、RST、PSH 这四个核心标志位的定义，符合“需一个核心定义则3”的锚点标准。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，完全属于定性判断，因此计算需求为微弱。
- **K3 = 1**: 评分理由。解题过程不需要多步串行推演。只要识别出题干中的关键词“没有更多数据”、“终止传输”，即可直接映射到 FIN 标志位，无需中间状态记忆或逻辑链条推导。
- **K4 = 2**: 评分理由。题干表述相对直白，没有明显的隐含前提或反直觉陷阱。唯一的“注意点”在于区分“正常关闭连接”（FIN）与“异常重置连接”（RST），这属于常规的概念辨析，而非深层陷阱，故评为较低。
- **K5 = 1**: 评分理由。本题仅涉及传输层 TCP 协议内部的首部字段定义，不需要跨越网络层、应用层或其他子系统传递状态，属于单系统内的知识考察。
- **雷达形状**: K1主导型（基础记忆型）。雷达图在 K1 维度突出，其他维度均处于低位，呈现典型的“概念识别”特征。

## 考察模式
- **模式**: 概念型
- **理由**: 题目直接询问协议字段的功能定义，考察的是对 TCP 协议规范中控制标志位（Control Flags）的标准定义的记忆和理解，不涉及计算或复杂逻辑推理。

## 选项级分析
- **选项A**: [正确] — FIN (Finish) 标志位用于发起连接的正常终止。当发送方数据发送完毕，希望关闭连接时，会发送带有 FIN 标志的报文段。这完全符合题干“没有更多数据要传输”的描述。
- **选项B**: [干扰] — RST (Reset) 标志位用于异常终止连接。通常用于处理错误情况（如端口不可达、序列号错误等）。虽然它也导致连接结束，但它不是用于“指定没有更多数据”的正常流程，而是强制中断。这类学生可能混淆了“结束连接”的两种不同场景（正常 vs 异常）。
- **选项C**: [干扰] — SYN (Synchronize) 标志位用于建立连接。在三次握手中，SYN 用于同步序列号。这类学生可能因为对 TCP 连接生命周期（建立-传输-释放）的整体印象模糊，将“开始”与“结束”的标志位记混，或者误以为 SYN 也参与结束过程（实际上 FIN 也涉及序列号消耗，但 SYN 专用于建立）。
- **选项D**: [干扰] — PSH (Push) 标志位用于提示接收方立即将数据交付给应用层，而不是等待缓冲区满。这类学生可能将“数据传输”的动作与“数据传输结束”的状态混淆，误以为 PSH 是数据发送的某种终结信号。
- **干扰策略**: 概念混淆。通过列出 TCP 首部中所有常见的控制标志位，利用它们都与“连接状态”或“数据流动”相关这一共性，制造混淆。特别是 RST 和 FIN 都涉及连接终止，PSH 涉及数据推送，容易让记忆不牢固的考生产生联想错误。

## 核心陷阱
- **核心陷阱**: **FIN 与 RST 的功能混淆**。考生容易知道这两个标志位都与“连接结束”有关，但难以区分“正常有序释放”（FIN，无更多数据）与“异常强制重置”（RST，出错或拒绝）。题干强调“没有更多数据”，暗示的是正常的、有序的数据流结束，而非错误中断。

## 考察能力
本题核心考察考生对 TCP 协议首部控制标志位（Flags）具体语义的准确记忆及区分能力，特别是对连接建立（SYN）、数据传输提示（PSH）、正常终止（FIN）和异常重置（RST）功能的辨析。
