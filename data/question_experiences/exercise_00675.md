# 练习题 Q1 — 停止等待协议链路利用率与帧长计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/数据链路层
- **难度**: 待评估

## 题干原文
假设在比特率为 64 kbit/s、传播延迟为 20 ms 的链路上使用停止等待协议。假设确认帧的传输时间和节点处理时间可忽略不计。则要实现至少 50% 的链路利用率，所需最小帧大小（单位：字节）为（ ）。
A: 160
B: 320
C: 640
D: 220

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆停止等待协议（Stop-and-Wait）的基本工作原理，特别是其发送窗口大小为1的特性，以及链路利用率（效率）的定义公式 $\eta = \frac{T_{trans}}{T_{total}}$。这属于数据链路层的核心基础概念，非死记硬背但需准确调用。
- **K2 = 3**: 评分理由。涉及单位换算（kbit/s 到 bit/s，ms 到 s，bit 到 Byte）和简单的代数不等式求解。虽然计算量不大，但涉及多级单位转换（$64 \times 10^3$, $20 \times 10^{-3}$, $/8$），若粗心易出错，属于标准难度的计算。
- **K3 = 2**: 评分理由。推演步骤较少：1. 确定总周期时间 $T_{total} = T_{trans} + 2 \times T_{prop}$；2. 代入利用率公式 $\eta \ge 0.5$；3. 求解 $T_{trans}$；4. 转换为帧长。逻辑线性，无需复杂的状态机推演。
- **K4 = 3**: 评分理由。存在常规注意点：1. 必须意识到停止等待协议的“空闲等待”时间是 $2 \times T_{prop}$（往返传播延迟）；2. 必须注意题目中“确认帧传输时间忽略不计”这一简化条件，否则公式会更复杂；3. 单位陷阱（bit vs Byte）。这些是解题必须意识到的隐含前提或常规注意点。
- **K5 = 1**: 评分理由。本题仅涉及数据链路层内部的协议机制计算，不涉及网络层、传输层或其他子系统的状态传递或耦合。

- **雷达形状**: K2/K4 主导型（计算与条件识别并重，基础概念支撑）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的物理层参数（带宽、延迟）和协议约束（停止等待），利用数学不等式求解具体的数据量（帧大小）。虽然涉及概念，但最终落脚点在于数值计算。

## 选项级分析
- **选项A (160)**: [干扰] — 针对**单位换算错误**或**公式理解偏差**。如果学生忘记将 bit 转换为 Byte（即算出 2560 bit 后直接选接近的数值，或者误以为 1 Byte = 1 bit），或者错误地认为利用率公式分母仅为 $T_{trans} + T_{prop}$（单程），可能会得出较小的数值。例如，若误算 $T_{trans} = 40ms$，则 $L = 64kbps \times 40ms = 2560 bit = 320 Byte$，若再除以2（错误逻辑）得 160。
- **选项B (320)**: [正确] — 正确计算结果。$T_{prop}=20ms$，往返 $40ms$。利用率 $\ge 50\%$ 意味着 $T_{trans} \ge T_{idle} = 2 \times T_{prop} = 40ms$。$L = R \times T_{trans} = 64 \times 10^3 \times 40 \times 10^{-3} = 2560 bit = 320 Byte$。
- **选项C (640)**: [干扰] — 针对**利用率阈值误解**或**计算翻倍错误**。如果学生误以为要达到 50% 利用率需要 $T_{trans} = 2 \times (2 \times T_{prop})$，或者在单位换算时出错（如忘记除以8，得到 2560 字节，虽无此选项，但可能误选较大值），或者误将 50% 理解为需要传输时间等于总时间的一半以上从而过度计算。更可能的情况是，学生正确算出 320，但误以为题目问的是“比特数”且混淆了数量级，或者在不等式方向上出错。另一种可能是误将往返延迟算作 $4 \times T_{prop}$。
- **选项D (220)**: [干扰] — 针对**随机猜测**或**严重计算错误**。无明显典型错误路径指向此特定数值，可能是为了凑齐四个选项而设置的随机干扰项，或者源于极其混乱的单位换算（如混合使用 $2^{10}$ 和 $10^3$ 且出错）。

- **干扰策略**: 计算陷阱（单位换算、公式系数）、概念混淆（单程vs往返延迟）

## 核心陷阱
- **核心陷阱**: **单位换算与往返延迟的识别**。
    1. **单位陷阱**：题目给出比特率（kbit/s）和帧大小单位（字节），中间必须经过 bit 到 Byte 的转换（除以8）。
    2. **时间构成陷阱**：停止等待协议的周期时间 $T_{total} = T_{trans} + 2T_{prop}$（因为ACK传输时间忽略，但信号往返需要 $2T_{prop}$）。很多学生容易漏掉系数 2，或者误以为 $T_{total} = T_{trans} + T_{prop}$。
    3. **利用率定义**：$\eta = \frac{T_{trans}}{T_{trans} + 2T_{prop}}$。当 $\eta = 0.5$ 时，意味着 $T_{trans} = 2T_{prop}$。

## 考察能力
本题核心考察考生对**停止等待协议时序模型**的理解，以及在**多单位环境下**进行**链路利用率定量分析**的能力。
