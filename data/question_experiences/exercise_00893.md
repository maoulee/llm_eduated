# 练习题 Q1 — 网络层端到端延迟计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/网络层
- **难度**: 待评估

## 题干原文
假设信道的传输速率为 32kbps。如果从源到目的地有‘8’条路由路径，且每个数据包 p 包含 8000 位。发送数据包 P 的总端到端延迟是（ ）。
- 选项:
  A: 2 秒
  B: 3 秒
  C: 4 秒
  D: 1 秒
- 正确答案: A
- 解析（参考）: 解析
已知信道的传输速率为 32kbps，从源到目的地有‘8’条路由路径，每个数据包 p 包含 8000 位。
总延迟 = 路由路径数 × 数据包大小 / 传输速率。
即：8 × 8000 b / 32 kbps
= 8 × 8000 b / 32000 bps
= 2 s
因此，选项（A）正确。
- 知识标签: ['计算机网络/网络层']
- 知识域: CN-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆“传输延迟”的基本公式（$L/R$）以及理解“路由路径数”在本题语境下代表跳数（Hops）或串行链路数。不是4分因为不需要辨析复杂的易混概念（如传播延迟、排队延迟等），只需调用核心定义。
- **K2 = 2**: 评分理由。计算过程为 $8 \times 8000 / 32000$，数字均为2的幂次或简单倍数，属于“2的幂友好”型计算，极难算错。
- **K3 = 1**: 评分理由。从输入到输出仅需一步直接代入公式计算，无需多步串行推演或记忆中间状态。
- **K4 = 4**: 评分理由。存在显著的隐含前提和反直觉陷阱。题干表述“8条路由路径”极易被误解为“8条并行路径”（从而误以为延迟不变或减半），或者忽略“存储转发”机制导致的串行累加效应。解题必须意识到这里的“路径”指的是经过的链路段数（即7个路由器+1段链路，或简化为8段链路），且延迟是累加的。这是一个典型的“题面没说但解题必须意识到的条件”（即存储转发机制下的串行累加）。
- **K5 = 1**: 评分理由。仅涉及网络层的数据包转发延迟计算，未跨越不同子系统（如链路层帧封装、应用层协议等）进行状态传递。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，表明题目难度主要来源于对题干隐含条件的正确解读，而非计算或记忆难度）。

## 考察模式
- **模式**: 计算型
- **理由**: 题目最终要求通过数值计算得出具体延迟时间，虽然涉及概念理解，但核心操作是代入公式进行算术运算。

## 选项级分析
- **选项A**: [正确] — 正确理解了“8条路由路径”意味着数据包需要经过8段链路的传输，且采用存储转发机制，总延迟为单段传输延迟乘以链路数。
- **选项B**: [干扰] — 可能是计算错误，或者误以为有某种额外的处理延迟（如每跳增加固定时间），但在本题简化模型中无依据。
- **选项C**: [干扰] — 可能是将速率单位换算错误（如误将32kbps当作32000bps但计算时出错），或者误以为路径数是16（双倍），或者混淆了比特和字节的换算（若误以为8000位是8000字节，则结果会大很多，但此处C选项数值较小，更可能是计算失误或误乘系数）。另一种可能是误以为总延迟 = 路径数 + 传输延迟（$8 + 0.25$ 无意义），或者误将8000位当作8000字节且速率单位搞错。最可能的错误路径是：误以为总延迟 = $8 \times (8000/32) = 2000$ 然后单位搞错？或者误算 $8 \times 8000 / 16000 = 4$（误将速率减半）。
- **选项D**: [干扰] — 针对“并行路径”或“忽略跳数”的错误认知。如果学生认为“8条路径”意味着并行发送，或者只计算了最后一跳的延迟（$8000/32000 = 0.25s$，接近0.25，但D是1，可能是误算 $32000/8000 = 4$ 取倒数？或者误以为总延迟就是单跳延迟但算错了？）。更可能的错误是：学生只计算了传输延迟 $8000/32000 = 0.25s$，然后可能因为某种原因（如误以为有4跳）选了1s？或者，如果学生误以为“8条路径”是干扰信息，只算单跳，但算错了单位（如 $8000/8000=1$?）。实际上，D选项最可能是针对那些**完全忽略“8条路径”这一条件**，且**计算错误**的学生；或者误以为总延迟等于单跳延迟的4倍（无逻辑）。但在常见错误中，D往往对应“只算单跳但单位换算错误”或“认为路径数不影响延迟”的极端错误。*修正分析*：若学生误以为总延迟 = 数据包大小 / (速率 * 路径数) [并行误解]，则 $8000 / (32000*8) = 0.03125$，无选项。若学生误以为总延迟 = 单跳延迟 = $8000/32000 = 0.25s$，无选项。若学生误算 $32000/8000 = 4$，选C。若学生误算 $8000/32 = 250$，无选项。D选项(1秒)可能是误将8000位当作32000位（1秒传输量），即认为数据包大小等于1秒的传输量，忽略了路径数。

- **干扰策略**: 概念混淆（并行vs串行）、计算陷阱（单位换算、乘法错误）。

## 核心陷阱
- **核心陷阱**: **“路由路径数”的语义歧义与存储转发机制的隐含应用**。
    1.  **语义歧义**：题干“8条路由路径”在自然语言中可能被理解为“有8条可选的并行路径”，而在网络层延迟计算语境下，它通常指“数据包经过的链路段数”（即跳数+1，或简化为跳数）。如果理解为并行，延迟不会累加；如果理解为串行跳数，延迟累加。
    2.  **机制隐含**：必须默认采用**存储转发（Store-and-Forward）**机制，即每一跳都必须完整接收数据包后才能转发，因此总延迟是各跳传输延迟之和。若采用切分转发（Cut-through），延迟计算方式不同。题目未明确说明，但根据408考研常规考点，默认存储转发。

## 考察能力
本题核心考察考生对**网络层存储转发机制下端到端传输延迟累加特性**的理解，以及在存在语义歧义时结合上下文（“总端到端延迟”）正确识别“路径数”为“串行链路数”的能力。
