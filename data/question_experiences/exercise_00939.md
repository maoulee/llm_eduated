# 练习题 Q1 — 死锁预防与进程饥饿分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题

- **知识点**: 操作系统/进程管理

## 题干原文
在某操作系统中，尝试使用以下策略进行死锁预防：为每个进程分配一个唯一的时间戳。如果一个进程被终止，则其在重新启动时仍保留原始时间戳。设 Ph 是当前持有资源 R 的进程，Pr 是请求该资源的进程，T(Ph) 和 T(Pr) 分别表示它们的时间戳。系统根据以下规则进行调度决策：

关于该策略的以下哪项说法是正确的？
- 选项:
  A: 该策略可以避免死锁，但可能导致进程饥饿
  B: 该策略不能避免死锁，但可以避免进程饥饿
  C: 该策略既不能避免死锁，也不能避免进程饥饿
  D: 该策略既能避免死锁，也能避免进程饥饿
- 正确答案: A
- 解析（参考）: 解析
死锁预防机制
请求进程的时间戳始终小于持有进程的时间戳
被终止的进程以相同时间戳重启，其时间戳不会超过当前最大值
新到达的较小时间戳进程会被直接终止，打破循环等待条件
饥饿可能性
较小时间戳的进程可能因持续被终止而无法获取资源
即使重启后仍保持原时间戳，可能导致无限等待
综上，该方案通过时间戳策略实现死锁预防，但存在进程长期无法执行的风险。答案选 A

- 知识域: OS-1

- **K2 = 1**: 评分理由。本题不涉及任何数值计算或公式推导，完全基于逻辑规则判断。

## 选项级分析
- **选项A**: [正确] — 该选项准确指出了 Wait-Die 策略的两个核心特征：通过强制终止年轻进程（或年老进程，取决于具体实现，此处为 Pr < Ph 时 Kill Pr，即年轻进程死亡，属于 Wait-Die 的一种变体或类似逻辑，实际上经典 Wait-Die 是 Pr < Ph 则 Wait，Pr > Ph 则 Die；本题规则是 Pr < Ph 则 Kill Pr，即**年轻进程死亡**，这实际上是 **Wound-Wait** 策略的逻辑，但题目描述为“Kill Pr”，我们需要仔细核对经典定义。
    *   *修正分析*：经典 **Wait-Die**：若 Pr < Ph (Pr更老)，Pr 等待；若 Pr > Ph (Pr更年轻)，Pr 被终止（Die）。
    *   经典 **Wound-Wait**：若 Pr < Ph (Pr更老)，Pr 抢占资源，Ph 被终止（Wound）；若 Pr > Ph (Pr更年轻)，Pr 等待。
    *   本题规则：`if T(Pr) < T(Ph) then kill Pr`。即：如果请求者比持有者**老**，请求者被杀。如果请求者比持有者**年轻**，请求者等待。
    *   这实际上是 **Wait-Die** 的反向？不，让我们重新梳理。
    *   若 Pr (老) < Ph (新) -> Kill Pr (老进程死)。
    *   若 Pr (新) > Ph (老) -> Wait (新进程等)。
    *   这意味着：**老进程必须让路给新进程？不，老进程死了。** 这意味着新进程（Ph）可以一直持有资源，老进程（Pr）想抢资源反而被杀。
    *   等等，通常时间戳越小越老。
    *   如果 Pr < Ph，Pr 更老。规则是 Kill Pr。即**老进程被杀**。
    *   如果 Pr > Ph，Pr 更新。规则是 Wait。即**新进程等待**。
    *   这会导致什么？新进程（Ph）持有资源，老进程（Pr）来抢，老进程被杀。新进程继续持有。
    *   这似乎打破了循环等待。因为资源总是流向时间戳更大的进程（或者说，时间戳小的进程无法通过抢占获得资源，只能死；时间戳大的进程可以等待时间戳小的进程释放？不，时间戳大的进程是 Wait）。
    *   让我们看死锁预防的核心：打破循环等待。
    *   如果存在循环 P1 -> P2 -> P1。
    *   P1 持有 R1，P2 请求 R1。若 T(P2) < T(P1)，P2 死。若 T(P2) > T(P1)，P2 等。
    *   这意味着资源请求的方向必须是从“小时间戳”指向“大时间戳”吗？
    *   如果 P2 (大) 等 P1 (小)，P1 持有。P1 请求 P3...
    *   关键在于：**被杀的进程重启后时间戳不变**。
    *   如果 Pr (老) 被杀，重启后还是老。它再次请求，如果 Ph 还是那个新进程，它再次被杀。
    *   这确实能打破死锁，因为不可能形成“老等老”或“新等新”的闭环，因为老进程永远抢不过新进程（会被杀），新进程永远等老进程（如果老进程持有）。
    *   但是，**饥饿**：老进程 Pr 永远比新到达的进程 Ph 老。Pr 请求资源，Ph 持有。Pr < Ph，Pr 被杀。Pr 重启，还是老。新的进程 P_new 到来，T(P_new) 更大。Pr 请求 P_new 的资源，Pr < P_new，Pr 被杀。
    *   结果：老进程 Pr 永远无法获得资源，因为它总是比当前持有资源的进程（无论是旧的还是新的）更老（或者至少，只要遇到比它新的进程，它就死；遇到比它老的进程，它等待。但如果系统中不断有新进程产生，或者它等待的老进程迟迟不释放，它可能陷入困境。特别是如果它等待的老进程也在等待其他更老的进程... 但最致命的是，如果它总是遇到比它新的进程，它就被无限重启/杀死，无法执行。这就是饥饿。
    *   因此，A 是正确的。

- **选项B**: [干扰] — 针对认为“杀死进程会破坏系统稳定性，导致死锁无法避免”或“时间戳机制能保证公平”的错误认知。学生可能误以为 Kill 操作会引入新的竞争条件导致死锁，或者误以为 Wait 操作保证了先来先服务从而避免饥饿。
- **选项C**: [干扰] — 针对完全不理解死锁预防机制的学生。他们可能认为只要涉及“Kill”和“Wait”这种复杂逻辑，既不能保证安全也不能保证公平。
- **选项D**: [干扰] — 针对理想化思维的学生。他们可能认为这是一个完美的算法，既解决了死锁又通过某种隐含的公平机制解决了饥饿。忽略了“时间戳不变”这一关键约束对老进程的不利影响。

- **干扰策略**: 概念混淆（混淆 Wait-Die 和 Wound-Wait 的具体行为）、理想化陷阱（忽略极端情况下的饥饿）。

## 核心陷阱
- **核心陷阱**: **“时间戳保留”导致的饥饿效应**。
    考生容易关注到该策略通过强制终止进程打破了循环等待（从而避免死锁），但往往忽略题目中“重新启动时仍保留原始时间戳”这一条件。在动态系统中，新进程的时间戳通常更大。如果老进程（小时间戳）总是请求被新进程（大时间戳）持有的资源，根据规则 `T(Pr) < T(Ph) -> Kill Pr`，老进程会被反复终止。由于时间戳不更新，它永远无法“变新”以抢占资源，从而导致无限期的饥饿。

本题核心考察考生对**死锁预防算法（特别是基于时间戳的 Wait-Die/Wound-Wait 策略）**的深层理解，以及评估算法在**公平性（饥饿问题）**方面副作用的能力。
