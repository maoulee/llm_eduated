# 2019 Q39 — TCP三次握手序列号确认机制

## 基本信息
- **年份**: 2019  **题位**: Q39  **题型**: 选择题
- **知识点**: CN-5 > TCP协议 > TCP三次握手
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
若主机甲主动发起一个与主机乙的 TCP 连接，甲、乙选择的初始序列号分别为 2018 和 2046，则第三次握手 TCP 段的确认序列号是（ ）。

A. 2018
B. 2019
C. 2046
D. 2047

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 TCP 三次握手中每个报文段携带的 Seq 和 Ack 字段的含义，特别是“确认号 = 期望收到的下一个字节的序号”这一核心定义。若仅模糊知道有三次握手但不知具体字段含义，无法解题。
- **K2 = 2**: 评分理由。计算过程极其简单，仅为 `2046 + 1 = 2047`。属于基础算术运算，几乎不存在计算错误风险，符合“2的幂友好”或简单整数加法的低难度特征。
- **K3 = 2**: 评分理由。推演步骤清晰且固定：第一步识别第一次握手（甲->乙，Seq=2018）；第二步识别第二次握手（乙->甲，Seq=2046, Ack=2019）；第三步确定第三次握手（甲->乙，Ack=?）。只需关注第二次握手中的 Seq 即可得出第三次握手的 Ack，逻辑链条短，无需复杂的状态机推演。
- **K4 = 2**: 评分理由。存在常规注意点，即区分“序列号（Seq）”和“确认号（Ack）”，以及区分“谁发给谁”。题目明确问的是“第三次握手 TCP 段”，考生需意识到这是甲发给乙的报文，其 Ack 字段是对乙之前发送数据的确认。若混淆方向或字段含义会出错，但无深层隐含前提或反直觉陷阱。
- **K5 = 1**: 评分理由。本题完全局限于 TCP 传输层内部的连接建立机制，不涉及 IP 层、应用层或其他子系统的状态传递，属于单系统内部机制考察。
- **雷达形状**: K1-K3 均衡偏低型，K4 略高（因需区分字段和方向），整体呈现基础概念应用特征，无明显高难度尖峰。

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心不在于复杂计算或长链路推理，而在于对 TCP 协议规范中“确认号”定义的理解。只要理解 Ack = 对方 Seq + 1 这一概念，即可直接得出答案，计算仅为辅助验证。

## 选项级分析
- **选项A**: [干扰] — 针对混淆“序列号”与“确认号”或混淆“第一次握手”与“第三次握手”的错误认知。学生可能误以为第三次握手的确认号是甲自己的初始序列号，或者误以为确认号是对方期望收到的（即甲的Seq+1，但这里问的是第三次握手，是对乙的确认）。更常见的错误是误以为确认号是甲的初始序列号 2018。
- **选项B**: [干扰] — 针对混淆“确认对象”的错误认知。2019 是甲的初始序列号 2018 + 1，这是乙在第二次握手中发送给甲的确认号（Ack）。学生可能误将第二次握手的 Ack 当作第三次握手的 Ack，或者误以为第三次握手是确认甲的数据（实际上第三次握手主要确认乙的连接请求，同时甲也发送自己的 Seq，但题目问的是 Ack 字段，通常指对前一个报文 Seq 的确认，即对乙 Seq 的确认）。*注：严格来说，第三次握手报文包含 Seq=2018, Ack=2047。若学生误以为 Ack 是对甲自己 Seq 的确认（逻辑错误），或记混了握手顺序，可能选 B。*
- **选项C**: [干扰] — 针对混淆“序列号”与“确认号”的错误认知。2046 是乙的初始序列号。学生可能误以为确认号就是对方发送的序列号本身，忘记了 TCP 确认号是“期望收到的下一个字节序号”，即需要 +1。
- **选项D**: [正确] — 正确应用 TCP 确认机制。第三次握手由甲发出，是对乙第二次握手报文（Seq=2046）的确认，因此 Ack = 2046 + 1 = 2047。
- **干扰策略**: 概念混淆（Seq vs Ack）、方向混淆（谁确认谁）、计算遗漏（忘记+1）。

## 核心陷阱
- **核心陷阱**: 混淆“序列号（Seq）”与“确认号（Ack）”的定义，特别是忘记确认号是“期望收到的下一个字节的序号”，即需要在对方序列号基础上 **+1**。此外，需明确第三次握手的 Ack 字段是对**第二次握手**中乙发送的 Seq 的确认，而非对甲自己 Seq 的确认。

## 考察能力
一句话概括本题核心考察的能力：准确理解并应用 TCP 三次握手中序列号与确认号的对应关系及计算规则。
