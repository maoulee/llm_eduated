# 2017 Q45 — 二级页表地址翻译与中断IO状态变迁

## 基本信息
- **年份**: 2017  **题位**: Q45  **题型**: 综合题
- **知识点**: 页表, 地址翻译, 中断IO, 操作系统>地址翻译, 操作系统>页表
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
假定题 44 给出的计算机 M 采用二级分页虚拟存储管理方式，虚拟地址格式如下：
页目录号（10 位）
页表索引（10 位）
页内偏移量（12 位）
请针对题 43 的函数 f1 和题 44 中的机器指令代码，回答下列问题。
(1) 函数 f1 的机器指令代码占多少页？
(2) 取第 1 条指令（push ebp）时，若在进行地址变换的过程中需要访问内存中的页目录和页表，则会分别访问它们各自的第几个表项（编号从 0 开始）？
(3) M 的 I/O 采用中断控制方式。若进程 P 在调用 f1 之前通过 scanf() 获取 n 的值，则在执行 scanf() 的过程中，进程 P 的状态会如何变化？CPU 是否会进入内核态？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握二级页表的基本结构（页目录、页表、页内偏移）、虚拟地址到物理地址的映射机制，以及进程状态转换（执行、阻塞、就绪）和中断处理的基本概念。属于标准的基础概念记忆与理解，不涉及复杂辨析。
- **K2 = 2**: 评分理由。计算较为简单。第(1)问只需判断代码长度是否超过页大小（通常4KB），第(2)问只需提取虚拟地址的高10位和中间10位作为索引，均为直接的位操作或简单的数值判断，无复杂多级换算。
- **K3 = 2**: 评分理由。推演步骤较少。第(2)问仅需一步地址分解即可得到表项索引；第(3)问需按时间顺序梳理“调用scanf -> 等待IO -> 中断唤醒 -> 调度”的状态流转，逻辑链条清晰且短，无需多步串行复杂推演。
- **K4 = 3**: 评分理由。存在隐含前提和易错点。第(1)问需隐含知道“函数代码通常连续存放”且需结合前题（题43/44）给出的代码长度或地址范围来判断是否跨页（参考答案暗示未跨页）；第(2)问需注意“编号从0开始”以及页目录号和页表索引的具体位对应关系；第(3)问需意识到scanf是阻塞式IO，且中断处理涉及用户态到内核态的切换。这些属于常规注意点，但需细心。
- **K5 = 3**: 评分理由。涉及操作系统不同子系统的联动。第(3)问将IO子系统（中断控制）与进程管理子系统（状态转换、调度）以及CPU模式（用户态/内核态）结合起来考察，体现了状态在不同模块间的传递和影响，但耦合度适中，非深度耦合。
- **雷达形状**: 整体呈均衡型，K1-K3略低，K4-K3中等，无明显短板或极高项，属于基础综合题。

## 考察模式
- **模式**: 综合型
- **理由**: 本题结合了内存管理（地址翻译、页表结构）和进程管理/IO管理（中断、状态转换、CPU模式）两个核心领域，要求考生在不同知识点间进行切换和综合应用，而非单一知识点的深度挖掘。

## 解题思路分析
- **核心思路**: 
  1.  **地址翻译**: 根据给定的虚拟地址格式（10-10-12），将虚拟地址分解为页目录号、页表索引和页内偏移。
  2.  **页表访问**: 利用页目录号访问页目录表项，利用页表索引访问页表表项。
  3.  **IO与进程状态**: 理解阻塞式IO（如scanf）的执行流程：发起请求 -> 阻塞等待 -> 中断发生 -> 唤醒 -> 调度执行。同时明确系统调用/中断处理需进入内核态。
- **关键步骤**: 
  1.  **第(1)问**: 回顾题43/44中函数f1的代码长度或地址范围。若代码长度小于页大小（2^12=4096字节）且起始地址未导致跨页，则占1页。参考答案指出“高20位相同”，意味着所有指令在同一页目录和页表项下，即同一页。
  2.  **第(2)问**: 获取`push ebp`指令的虚拟地址。提取最高10位作为页目录号（PDN），中间10位作为页表索引（PTI）。PDN即为页目录表项索引，PTI即为页表表项索引。注意编号从0开始，若二进制为`0000000001`，则索引为1。
  3.  **第(3)问**: 
      -   调用`scanf()`：进程从执行态变为阻塞态（等待输入）。
      -   输入完成：硬件中断触发，中断处理程序将进程从阻塞态改为就绪态。
      -   调度：进程被调度程序选中，从就绪态变为执行态。
      -   CPU状态：`scanf()`是库函数，最终通过系统调用进入内核；中断处理也在内核态执行。因此CPU会进入内核态。
- **易错点**: 
  1.  混淆页目录号和页表索引的位数分配。
  2.  表项索引计算错误（如未从0开始计数，或二进制转十进制错误）。
  3.  进程状态转换顺序错误（如忘记就绪态，直接从阻塞到执行）。
  4.  忽略`scanf()`涉及系统调用，误认为全程在用户态。

## 核心陷阱
- **核心陷阱**: 
  1.  **地址位域对应**: 考生需准确识别10位页目录号和10位页表索引在虚拟地址中的具体位置，避免颠倒。
  2.  **状态转换完整性**: 在描述进程状态变化时，容易遗漏“就绪态”这一中间状态，或混淆“阻塞”与“就绪”的触发条件。
  3.  **内核态切换**: 容易忽略`scanf()`作为标准库函数，其底层实现依赖于系统调用（如`read`），而系统调用和中断处理均需在**内核态**下进行，这是考察CPU模式切换的关键点。

## 考察能力
本题核心考察考生对**二级页表地址翻译机制**的精确理解，以及**中断驱动IO过程中进程状态与CPU模式动态变化**的综合分析能力。
