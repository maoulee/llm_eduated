# 练习题 Q1 — 屏障同步与竞态条件分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
屏障（Barrier）是一种同步构造，其中一组进程需要进行全局同步。即集合中的每个进程都必须到达屏障并等待其他所有进程也到达后，所有进程才能一起离开屏障。假设集合中进程数量为三个，S 是一个二进制信号量，具有常规的 P 和 V 操作。考虑以下带有行号的 C 语言实现：
void barrier(void) {
 1: P(S);
 2: process_arrived++;
 3: V(S);
 4: while(process_arrived != 3);
 5: P(S);
 6: process_left++;
 7: if(process_left == 3){
 8: process_arrived = 0;
 9: process_left = 0;
 10: }
 11: V(S);
}
变量
process_arrived
和
process_left
在所有进程中共享，并初始化为零。在并发程序中，当三个进程需要进行全局同步时会调用该屏障函数。
以下哪一项可以修正该实现中的问题？（ ）
- 选项:
  A: 将第 6 到 10 行简单替换为
process_arrived--
  B: 在屏障开始处，第一个进入屏障的进程会等待直到
process_arrived
变为零，然后继续执行 P(S)
  C: 在屏障开始处禁用上下文切换，在结束时重新启用
  D: 将变量
process_left
改为私有而非共享

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握信号量（P/V操作）、临界区、屏障（Barrier）同步原语的基本定义。不是4分因为不需要辨析多个易混的高级同步概念，核心概念较为单一。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行算术运算或单位换算。
- **K3 = 4**: 评分理由。需要在明确规则下多步串行推演。考生必须模拟三个进程并发执行该代码片段的过程，特别是关注“第一轮屏障结束”到“第二轮屏障开始”之间的状态转换。需要追踪 `process_arrived` 和 `process_left` 在临界区内外被修改的顺序，识别出当计数器重置时，新进入的进程可能错误地增加计数器的竞态条件。步骤超过5步且需记忆中间状态。
- **K4 = 5**: 评分理由。存在极深的隐含前提和反直觉陷阱。题面未直接说明“多次调用屏障”的场景，但这是屏障同步的核心应用场景。陷阱在于：代码看似在临界区内保护了计数器，但实际上 `process_arrived` 的递增（第2行）发生在第一次 P(S) 之后，而重置（第8行）发生在第二次 P(S) 之后。如果新进程在旧进程重置计数器之前进入第一次 P(S)，就会发生计数溢出。识别这一“时间窗口”漏洞需要极高的条件路由能力。
- **K5 = 3**: 评分理由。主要涉及进程管理子系统内的同步机制。虽然涉及共享变量和信号量，但不需要跨越内存管理、文件系统等不同子系统传递状态，属于单系统内的深度耦合逻辑。

- **雷达形状**: K4陷阱型（高K3、高K4，低K2）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖公式计算或单纯的概念记忆，而是要求考生通过逻辑推演，模拟并发执行流程，发现代码逻辑中的时序漏洞（Race Condition），并评估不同修复方案的有效性。

## 选项级分析
- **选项A**: [干扰] — 针对“简化逻辑”的错误认知。部分学生可能认为只需减少计数即可，忽略了 `process_left` 用于判断是否所有进程都已离开屏障以进行重置的关键作用。若仅替换为 `process_arrived--`，则无法正确重置状态，且破坏了原有的互斥逻辑结构。
- **选项B**: [正确] — 针对“轮次隔离”的正确认知。该选项引入了一个前置检查机制：在进入屏障逻辑前，确保上一轮屏障已经完全结束（即 `process_arrived` 为0）。这有效地将“新轮次的进入”与“旧轮次的清理”在时间上隔离开，防止了新进程在旧进程重置计数器之前错误地增加 `process_arrived`。
- **选项C**: [干扰] — 针对“禁用中断/切换”的极端手段认知。虽然禁用上下文切换可以消除竞态，但这违背了操作系统的并发设计原则，会导致严重的性能问题和死锁风险（如果某个进程在禁用切换期间阻塞），且通常用户态程序无法直接禁用内核的上下文切换。
- **选项D**: [干扰] — 针对“变量作用域”的误解。`process_left` 必须是共享的，因为需要统计所有进程离开的数量以触发重置。若改为私有，每个进程只能看到自己的离开计数，永远无法达到3，导致重置逻辑失效，屏障死锁。

- **干扰策略**: 概念混淆（A、D）与 极端方案（C）结合，利用学生对同步原语细节掌握不牢固的特点，设置看似合理但逻辑错误的选项。

## 核心陷阱
- **核心陷阱**: **屏障的“轮次”边界模糊导致的竞态条件**。
  具体表现为：当最后一个进程离开屏障并重置 `process_arrived` 和 `process_left` 为0时，如果有新的进程（或同一组进程再次调用）已经执行了第1行的 `P(S)` 但尚未执行第2行的 `process_arrived++`，或者正在等待第4行的 `while` 循环，此时重置操作会导致新进程的计数逻辑混乱。原代码没有机制区分“当前轮次”和“下一轮次”，导致新进入的进程可能将计数器从0加到1，而旧进程可能还在等待计数器达到3，或者新进程误以为计数器已满。选项B通过强制等待 `process_arrived == 0` 确保了轮次的清晰分隔。

## 考察能力
一句话概括本题核心考察的能力：
**在并发环境下，识别并修复基于共享计数器的同步原语中因轮次切换不清导致的竞态条件（Race Condition）的能力。**
