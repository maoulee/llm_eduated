# 2009年 Q16 — 相对寻址目标地址计算

## 基本信息
- **年份**: 2009  **题位**: Q16  **题型**: 选择题
- **知识点**: 相对寻址, PC自增机制, 有效地址计算
- **考纲对应**: 指令系统 -> 指令寻址方式 -> 数据寻址 -> 相对寻址, 指令系统 -> 指令寻址方式 -> 指令寻址 -> PC自增

## 题干原文
[2009年考研真题第16题]某机器字长为16位，主存按字节编址，转移指令采用相对寻址，由两个字节组成，第一个字节为操作码字段，第二个字节为相对位移量字段。假定取指令时，每取一个字节PC自动加1。若某

## K1-K5 评分与解析
- **K1 = 3**: 3 — 必须准确记忆“相对寻址”的定义（目标地址 = 当前PC + 位移量）以及“PC在取指令过程中的更新机制”。若仅知道相对寻址公式但忽略PC更新细节，无法入题。不是4分，因为不涉及冷门概念辨析，是核心基础概念。
- **K2 = 3**: 3 — 需要执行两步计算：1. 计算取完指令后的PC值（十六进制加法 2000H+2H）；2. 计算目标地址（2002H+06H）。涉及十六进制运算，数字虽简单但需准确。不是2分，因为涉及多步和地址变化；不是4分，因为计算量极小，无复杂进位或单位换算。
- **K3 = 3**: 3 — 需按固定逻辑走完流程：确定指令长度 -> 确定取指后PC状态 -> 应用相对寻址公式。这是标准的3步串行推演。不是2分，因为隐含了PC动态变化的步骤；不是4分，因为路径唯一，无状态分支。
- **K4 = 4**: 4 — **核心难点**。题面隐含前提“每取一个字节PC自动加1”与“指令长2字节”结合，考生必须识别出“执行相对寻址时，PC已指向下一条指令”这一隐含前提。若未识别此机制，会直接用指令起始地址计算，导致掉坑。不是5分，因为对于熟悉计组原理的考生，这是标准机制，非反直觉设计。
- **K5 = 2**: 2 — 主要涉及指令系统内部逻辑，虽涉及主存地址，但无数据/逻辑实质性跨系统关联（如不涉及Cache命中或中断上下文切换）。
- **雷达形状**: K4陷阱型

## 考察模式
- **模式**: 计算型
- **理由**: 题干给定了具体的地址参数和指令格式，选项为四个具体的十六进制地址结果，考生需通过计算得出唯一正确值。

## 选项级分析
- **选项A**: [干扰] — 针对“忽略PC自增”的认知错误。学生直接用指令起始地址 2000H 加上位移量 06H 得到 2006H。这类学生通常死记公式 $EA = PC + A$，但未理解公式中PC指的是“取指完成后”的PC。
- **选项B**: [干扰] — 针对“计算错误+逻辑错误”的认知错误。可能在 2000H+06H 基础上又做了错误的十六进制进位处理，或者误以为指令长度影响位移量符号。属于低概率误选，主要干扰对十六进制加法不熟练的学生。
- **选项C**: [正确] — 2008H。正确路径：指令占2字节，取指过程PC从 2000H 增至 2002H；相对寻址目标地址 = 当前PC(2002H) + 位移量(06H) = 2008H。
- **选项D**: [干扰] — 针对“严重逻辑混乱”的认知错误。可能是将位移量当作绝对地址，或混淆了字节编址与字编址的概念，导致结果完全偏离。
- **干扰策略**: 并行陷阱（各干扰项独立）

## 核心陷阱
- **核心陷阱**: 相对寻址公式中“PC”的瞬时值定义。很多学生误以为PC是指令的起始地址，而忽略了题目中明确指出的“每取一个字节PC自动加1”导致的PC更新。
- **错误路径**: 1. 识别出指令为2字节；2. 错误地认为计算相对地址时PC仍停留在指令起始处(2000H)；3. 计算 2000H + 06H = 2006H (选A)。

## 考察能力
考察考生对指令执行过程中程序计数器（PC）动态变化机制的理解，以及将“取指开销”与“寻址计算”结合进行多步推演的能力。
