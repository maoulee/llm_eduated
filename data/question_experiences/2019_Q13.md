# 2019 Q13 — 补码与类型转换

## 基本信息
- **年份**: 2019  **题位**: Q13  **题型**: 选择题
- **知识点**: 补码, 类型转换, 无符号, 组成原理>类型转换, 组成原理>补码
- **题位域**: 待标注  **科目**: 组成原理

## 题干原文
考虑以下 C 语言代码：
unsigned short usi = 65535;
short si = usi;
执行上述程序段后，si 的值是（ ）。

A. -1
B. -32767
C. -32768
D. -65535

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握两个核心概念：`unsigned short` 和 `short` 的位宽（均为16位）以及补码表示法。不记忆这些基础定义无法入题，但无需辨析多个易混概念，属于标准的基础认知需求。
- **K2 = 2**: 评分理由。计算过程非常直接。65535 是 $2^{16}-1$，其二进制全为1，这是计算机组成原理中非常友好的数值。无需复杂的多级换算，单步转换即可得出二进制序列，难度较低。
- **K3 = 1**: 评分理由。从输入到输出仅需一步逻辑：将无符号数的二进制位模式直接解释为有符号数的补码。没有多步串行推演，也没有中间状态需要记忆。
- **K4 = 3**: 评分理由。存在一个关键的隐含前提/陷阱：C语言中从 `unsigned` 到 `signed` 的转换是**位模式保留**（bit-pattern preservation），而不是数值保留。许多初学者会误以为数值不变或发生截断错误，需要识别这一“题面没说但解题必须意识到的条件”（即底层硬件视角的位操作而非高级语言语义视角的数值转换）。
- **K5 = 1**: 评分理由。本题仅涉及数据类型转换这一单一子系统，不涉及不同子系统（如CPU、内存、I/O）之间的状态传递或耦合。

- **雷达形状**: K4陷阱型（K4相对较高，其他维度较低，呈现明显的陷阱特征）

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心不在于复杂的计算，而在于对“数据类型转换底层机制”这一概念的理解。考生需要理解在机器级层面，类型转换往往只是对同一组比特位赋予不同的解释规则（无符号 vs 补码），而非改变比特位本身。

## 选项级分析
- **选项A**: [正确] — 对应正确理解。`usi` 为 65535，16位二进制为 `1111 1111 1111 1111`。赋值给 `short si` 时，位模式不变。在补码系统中，最高位为1表示负数，`1111...1111` 是 -1 的补码表示。
- **选项B**: [干扰] — 针对错误认知：可能混淆了 `short` 的范围边界或进行了错误的减法运算。例如，误以为 $65535 - 32768 = 32767$ 然后取反等错误逻辑，或者对补码转换规则记忆模糊。
- **选项C**: [干扰] — 针对错误认知：`-32768` 是 16位有符号数的最小值，其二进制为 `1000 0000 0000 0000`。选此项的学生可能误以为全1的位模式对应最小值，或者混淆了溢出后的结果。
- **选项D**: [干扰] — 针对错误认知：数值直觉错误。学生可能认为 `usi` 的值是 65535，转换后应该保持数值大小，但因为 `short` 无法表示正数 65535，所以强行取负号变成 -65535。这反映了学生试图在高级语言数值层面进行转换，而忽略了底层位模式不变的原则。

- **干扰策略**: 概念混淆（混淆数值转换与位模式转换）、数值直觉陷阱（D选项利用数值大小误导）

## 核心陷阱
- **核心陷阱**: **位模式保留 vs 数值保留**。考生容易从高级语言语义出发，认为赋值是数值的传递；而实际上在底层（及本题考察的组成原理视角），`unsigned short` 到 `short` 的转换是**位模式的直接拷贝**，解释规则从“无符号整数”变为“补码有符号整数”。全1的位模式在无符号下是最大值，在补码下是 -1。

## 考察能力
一句话概括本题核心考察的能力：理解C语言数据类型转换在机器级层面的位模式保留机制及补码表示法。
