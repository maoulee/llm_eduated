## K1-K5 评分与解析

- **K1 = 3**: 评分理由。需要掌握信号量 P/V 操作的基本语义（P 等待，V 释放）以及初始值为 0 时的阻塞特性。这是操作系统进程同步章节的核心定义，属于标准记忆需求。不是 4 分因为不需要辨析复杂的死锁或饥饿概念，只需理解基本的同步顺序。
- **K2 = 2**: 评分理由。涉及简单的整数加减运算（如 y=1+2, z=3+1 等）。计算量极小，且均为个位数运算，几乎不可能出现计算错误。属于较低的计算需求。
- **K3 = 4**: 评分理由。这是本题的核心难点。考生需要在脑海中构建两个进程的执行时间轴，并根据信号量的状态变化（s1, s2）动态切换当前活跃进程。从初始状态到最终状态，涉及 P1 部分执行 -> 阻塞 -> P2 部分执行 -> 阻塞 -> P1 继续执行 的多步串行推演，且每一步都依赖上一步的变量状态（y, z, x 的值在进程间共享并相互影响）。步骤超过 5 步且需记忆中间变量状态，故评为 4。
- **K4 = 3**: 评分理由。存在隐含前提：考生必须意识到 `P(s)` 在信号量为 0 时会阻塞进程，直到另一个进程执行 `V(s)`。这是一个常规的同步陷阱，如果忽略阻塞机制，直接按代码顺序执行，就会得出错误答案。属于“常规注意点”级别的陷阱。
- **K5 = 4**: 评分理由。本题涉及两个进程（P1, P2）之间的深度状态耦合。P1 修改了共享变量 `y` 和 `z`，P2 读取并修改 `x`, `y`, `z`，且通过信号量 `s1`, `s2` 控制执行流。数据状态（变量值）和控制状态（信号量值）在两个子系统（进程）间双向传递和相互影响，属于状态互影响的深度耦合。

- **雷达形状**: K3-K5 主导型（推演与联动能力强，基础计算弱）。图形呈现为右侧（K3, K4, K5）突出，左侧（K1, K2）平缓的形状。

## 考察模式

- **模式**: 推理型
- **理由**: 本题并非单纯考察概念记忆（概念型），也不是复杂的数学计算（计算型）。它要求考生根据给定的同步机制（信号量），逻辑推演两个并发进程在共享内存环境下的具体执行序列和变量变化轨迹。核心在于“推演”执行顺序。

## 选项级分析

- **选项 A (5,9,9)**: [干扰] — 针对**忽略同步阻塞，假设完全并行或乱序执行**的错误认知。如果考生认为 P1 和 P2 可以完全交错执行，或者错误地认为 P2 可以在 P1 执行 `V(s1)` 之前读取 `y`（此时 y 可能未初始化或为旧值，但题目隐含 y 初始未定义或为 0，若按顺序 P1 先跑完前半段，P2 再跑，但 P2 中 `x=x+y` 时若 y 取值错误），或者在计算 `y=z+y` 时使用了错误的 z 值。具体来看，若 P2 在 P1 更新 z 之前执行了 `z=x+z`，或者 P1 最后一步 `y=z+y` 使用了旧的 z，可能导致此类结果。更可能的情况是考生算对了 x=5，但在 y 和 z 的最终叠加计算上出错，例如 P1 最后一步 `y` 计算时，误用了 P2 修改前的 `z` 或 `y`。
- **选项 B (5,9,4)**: [干扰] — 针对**只关注 P2 对 z 的修改，忽略 P1 对 z 的后续依赖或 P1 最后一步对 y 的更新**的错误认知。x=5 正确。z=4 是 P1 执行 `z=y+1` 后的值，如果考生认为 P2 执行 `z=x+z` 后 z 变为 9，但最后输出时又看错了，或者认为 P1 最后的 `y=z+y` 没有改变 z。实际上 z 最终应为 9。此选项可能源于考生正确计算了 P1 前半段 z=4，但错误地认为 P2 的 `z=x+z` 没有发生，或者 P1 最后的 `y` 计算不影响 z，且误以为 z 保持为 4（忽略了 P2 对 z 的修改）。或者，考生正确算出 x=5, y=9 (错误), z=4 (错误)。
- **选项 C (5,12,9)**: [正确] — 严格遵循信号量同步逻辑推演的结果。
    1. P1: y=1, y=3, z=4, V(s1) -> s1=1. P1 阻塞于 P(s2).
    2. P2: x=1, x=2. P(s1) 成功 -> s1=0. x=2+3=5. z=5+4=9. V(s2) -> s2=1.
    3. P1: P(s2) 成功 -> s2=0. y=9+3=12.
    结果: x=5, y=12, z=9.
- **选项 D (5,12,4)**: [干扰] — 针对**正确计算了 y，但错误认为 z 没有被 P2 修改，或 P2 的 z 修改被覆盖**的错误认知。x=5, y=12 正确。z=4 是 P1 中间状态的值。如果考生忽略了 P2 中 `z = x + z` 这一行，或者认为 P2 执行完后 z 又变回了 4（不可能），就会选此项。这通常是因为考生只关注了 P1 对 z 的赋值，而漏看了 P2 对 z 的累加操作。

- **干扰策略**: 计算陷阱与状态遗漏。通过设置不同的变量组合，考察考生是否完整跟踪了所有共享变量（x, y, z）在所有进程中的所有赋值语句。特别是 z 被 P1 和 P2 都修改过，y 被 P1 修改两次，x 被 P2 修改两次，极易遗漏某一步。

## 核心陷阱

- **核心陷阱**: **信号量阻塞导致的执行顺序强制性与共享变量的时序依赖**。
    1. 必须明确 `P(s1)` 和 `P(s2)` 造成的阻塞点，从而确定 P1 和 P2 代码片段的执行先后顺序（P1 前半段 -> P2 中段 -> P1 后半段）。
    2. 在推演过程中，必须准确记录每一步执行后共享变量（x, y, z）的最新值，因为后续步骤依赖于这些最新值。例如，P2 计算 `x=x+y` 时，y 必须是 P1 更新后的 3；P1 最后计算 `y=z+y` 时，z 必须是 P2 更新后的 9。

## 考察能力

本题核心考察考生**在并发环境下，结合信号量同步机制，对多进程共享变量状态进行精确时序推演和跟踪的能力**。
