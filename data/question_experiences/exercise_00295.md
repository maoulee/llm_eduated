# 练习题 Q1 — TCP序列号与累积确认机制

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
考虑一个 TCP 连接，当前处于没有未确认 ACK 的状态。发送方连续发送了两个数据段，第一个段的序列号是 230，第二个段的序列号是 290。第一个段丢失了，但第二个段被接收方正确接收。设 X 表示第一个段中携带的数据量（以字节为单位），Y 表示接收方发送的确认号（ACK number）。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 TCP 序列号（Sequence Number）的定义（指代第一个字节的编号）以及确认号（ACK Number）的定义（期望收到的下一个字节的编号）。这是传输层最核心的基础概念，属于标准记忆需求。
- **K2 = 2**: 评分理由。计算过程仅为简单的减法（290 - 230 = 60），属于非常基础的算术运算，几乎不可能出错，计算负荷极低。
- **K3 = 3**: 评分理由。解题需要两步串行推演：第一步根据序列号差值计算数据长度；第二步根据 TCP 的累积确认机制和乱序到达规则，推导接收方应发送的 ACK 值。逻辑链条清晰但需结合协议行为。
- **K4 = 4**: 评分理由。存在明显的“反直觉”陷阱。许多初学者会误以为接收方收到了第二个段，就应该确认第二个段的序列号（290）或下一个序列号（291），或者误以为 ACK 是确认“已收到的最后一个字节”。必须意识到 TCP 的累积确认特性：ACK 永远指向期望收到的**下一个有序字节**，而非最后收到的字节。这是一个典型的隐含前提深坑。
- **K5 = 1**: 评分理由。本题仅涉及传输层内部的 TCP 协议机制，不涉及网络层、应用层或其他子系统的状态传递或耦合。

- **雷达形状**: K4陷阱型（K4显著高于其他维度，呈现单峰突出特征）

## 考察模式
- **模式**: 推理型
- **理由**: 虽然包含简单的计算，但题目的核心难点不在于计算本身，而在于对 TCP 协议在“丢包”和“乱序”场景下行为规则的逻辑推理。考生必须理解“累积确认”和“期望序列号”的概念才能得出正确结论。

## 选项级分析
- **选项A**: [干扰] — 针对“确认号等于收到段的序列号”的错误认知。这类学生可能认为既然收到了第二个段（Seq=290），就确认290。或者混淆了 Seq 和 ACK 的含义。
- **选项B**: [干扰] — 针对“确认号等于收到段的下一个序列号”的错误认知。这类学生知道 ACK 是期望的下一个字节，但错误地认为接收方应该跳过丢失的第一个段，直接确认第二个段之后的内容（290+1=291）。这忽略了 TCP 累积确认要求按序交付的特性。
- **选项C**: [干扰] — 针对“确认号等于收到段的最后一个字节+1”但计算错误的认知，或者混淆了 Seq 和 ACK 的起始点。如果学生误以为 ACK 是确认“已接收数据的末尾”，可能会选 230+60=290 附近的数，但 231 是第一个段期望的下一个字节，如果第一个段没丢，ACK 应该是 290。选 C 的学生可能逻辑混乱，既算对了长度，又在 ACK 上选择了第一个段的下一个字节，但没考虑到第二个段已到达的事实对 ACK 的影响（实际上 ACK 仍由缺失的第一个段决定）。更可能的情况是，学生误以为 ACK 是确认“第一个段的内容”，所以选了 231（即 230+1，假设第一个段只有1字节？不对，X=60）。或者学生认为 ACK 应该确认第一个段，所以是 230+60=290？不，C 是 231。这通常是一个随机干扰项，或者针对那些认为“ACK 是确认第一个字节的下一个”且完全忽略第二个段存在的极端错误理解。
- **选项D**: [正确] — X=60（290-230），Y=230（因为第一个段丢失，接收方仍期望收到从 230 开始的数据，故 ACK=230）。

- **干扰策略**: 概念混淆（主要混淆 ACK 的定义是“期望下一个”还是“已收到最后一个”）和 机制误用（误以为乱序到达会触发对乱序段的确认）。

## 核心陷阱
**TCP 累积确认机制与乱序处理**：考生容易误认为接收方在收到第二个段后，会发送确认第二个段的 ACK（如 290 或 291）。实际上，TCP 使用累积确认，ACK 号始终表示接收方**期望收到的下一个按序字节**。由于第一个段（Seq 230）丢失，接收方缓冲区中 230 之前的数据已确认，但 230 缺失，因此无论后续收到多少乱序段，ACK 号都保持为 230，直到第一个段重传并被接收。

## 考察能力
本题核心考察考生对 TCP 序列号计算规则及累积确认机制在丢包/乱序场景下行为的深刻理解。
