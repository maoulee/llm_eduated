# 2018 Q28 — 管程条件变量wait操作机制

## 基本信息
- **年份**: 2018  **题位**: Q28  **题型**: 选择题
- **知识点**: 管程, 条件变量, 操作系统>条件变量, 操作系统>管程
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
若 x 是管程内的条件变量，则当进程执行 x.wait() 时所做的工作是（）。

A. 实现对变量 x 的互斥访问
B. 唤醒一个在 x 上阻塞的进程
C. 根据 x 的值判断该进程是否进入阻塞态
D. 阻塞该进程，并将之插入 x 的阻塞队列中

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。本题属于标准的基础概念记忆。考生需要准确记忆管程中条件变量 `wait()` 操作的具体语义。虽然不需要辨析多个复杂概念（如信号量与管程的深层区别），但必须掌握核心定义，即“阻塞并加入队列”，而非简单的“判断”或“互斥”。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、公式代入或单位换算，完全属于定性分析。
- **K3 = 1**: 评分理由。解题过程无需多步推演。只要知道 `wait()` 的定义，即可直接得出结论。不需要模拟进程调度或状态流转的复杂过程。
- **K4 = 2**: 评分理由。存在轻微的隐含前提，即考生需意识到管程内部互斥锁与条件变量阻塞队列的关系。虽然题目未明说“释放锁”，但这是 `wait()` 操作的标准行为的一部分。主要陷阱在于区分“判断条件”与“执行阻塞”这两个步骤，属于常规注意点。
- **K5 = 1**: 评分理由。本题仅涉及操作系统中进程同步与互斥这一单一子系统内的概念，不涉及文件系统、内存管理或网络等其他子系统的状态传递。
- **雷达形状**: K1主导型（概念记忆型）。K1分数中等，其余维度极低，呈现典型的“定义考察”特征。

## 考察模式
- **模式**: 概念型
- **理由**: 题目直接询问特定操作（`x.wait()`）的功能定义，考察的是对管程机制中条件变量操作语义的准确记忆和理解，不涉及计算或复杂逻辑推理。

## 选项级分析
- **选项A**: [干扰] — 针对“管程整体功能”与“条件变量具体操作”的混淆。管程本身通过互斥锁实现对内部数据的互斥访问，但 `wait()` 操作本身是为了同步（等待条件满足），而非为了互斥。选此项的学生可能误以为所有管程内的操作都是为了互斥。
- **选项B**: [干扰] — 针对 `wait()` 与 `signal()` 功能的颠倒。`signal()` 才是唤醒操作。选此项的学生可能记反了这两个操作的作用，或者混淆了信号量中的 `V` 操作（唤醒）与管程中的 `signal`。
- **选项C**: [干扰] — 针对“条件判断”与“阻塞动作”的混淆。在管程中，条件判断通常由程序员在调用 `wait()` 之前通过 `while` 循环完成（因为存在虚假唤醒），`wait()` 本身不判断 x 的值，而是直接执行阻塞。选此项的学生可能误以为 `wait()` 内部包含了条件检查逻辑。
- **选项D**: [正确] — 准确描述了 `wait()` 的核心行为：阻塞当前进程，并将其放入条件变量 x 的等待队列中，同时释放管程锁（隐含在阻塞过程中，以便其他进程进入）。
- **干扰策略**: 概念混淆。通过混淆互斥（A）、唤醒（B）和条件判断（C）这三个与同步相关的不同概念，来干扰对 `wait()` 核心语义（阻塞+入队）的识别。

## 核心陷阱
- **核心陷阱**: 误认为 `wait()` 操作包含条件判断（选项C）或将其与唤醒操作（选项B）混淆。考生需明确：`wait()` 是“无条件”阻塞（前提是程序员已判断条件不满足），其核心动作是“挂起”和“入队”。

## 考察能力
准确记忆并区分管程中条件变量 `wait()` 与 `signal()` 操作的语义及副作用。
