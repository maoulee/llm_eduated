# 练习题 Q1 — TCP连接异常中断与状态恢复

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
一个 TCP 服务器应用程序被编程为在主机 S 上监听端口号 P。一个 TCP 客户端通过网络连接到该 TCP 服务器。假设当 TCP 连接处于活动状态时，服务器机器 S 发生崩溃并重新启动。假设客户端未使用 TCP 保活计时器。以下哪些行为是
不可能
发生的（ ）？
- 选项:
  A: 如果客户端正在等待接收数据包，它可能会无限等待
  B: S 上的 TCP 服务器应用程序在重启后可以继续监听 P 端口
  C: 如果客户端在服务器重启后发送数据包，它会收到一个 RST 段
  D: 如果客户端在服务器重启后发送数据包，它会收到一个 FIN 段

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。需要深入理解 TCP 协议中 RST（重置）与 FIN（终止）段的触发条件及语义区别，以及 TCP 保活机制的作用。不仅仅是记忆定义，还需要辨析在“非正常关闭”场景下协议的具体行为。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算或公式代入，属于纯概念与机制分析。
- **K3 = 3**: 评分理由。需要推演服务器崩溃->重启->客户端发送数据->服务器响应这一系列状态变化。涉及从“连接建立”到“异常中断”再到“新连接尝试/旧连接残留”的状态流转分析，步骤适中。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。首先，“不可能发生”是逆向提问，容易看错；其次，需要意识到服务器重启后，内核中的 TCP 连接表被清空，旧连接状态丢失，这是判断 RST 而非 FIN 的关键隐含条件；再次，需要理解“未启用保活”意味着客户端不会主动探测连接死活，从而可能陷入死锁（选项A）。
- **K5 = 3**: 评分理由。涉及应用层（服务器程序监听）、传输层（TCP 状态机、RST/FIN 生成）和操作系统内核（重启后资源释放）之间的联动。虽然主要是传输层内部机制，但需要理解重启对内核状态的影响。
- **雷达形状**: K4 陷阱型（高条件路由需求，高概念辨析需求，低计算需求）

## 考察模式
- **模式**: 推理型
- **理由**: 题目没有直接询问定义，而是设定了一个具体的故障场景（服务器崩溃重启），要求考生根据 TCP 协议的状态机规则和异常处理机制，推演客户端和服务端可能的交互结果，并找出逻辑上“不可能”的情况。

## 选项级分析
- **选项A**: [可能] — 针对“TCP 连接可靠性”的误解。如果客户端没有启用保活（Keep-Alive）机制，且服务器崩溃后不发送任何报文（因为重启了），客户端若处于阻塞接收状态（如 `recv()`），确实可能永远等待下去，因为它不知道连接已断开。这是可能发生的。
- **选项B**: [可能] — 针对“端口绑定”的误解。服务器重启后，操作系统会释放所有资源。只要服务器应用程序在重启后重新执行 `bind()` 和 `listen()` 系统调用，它完全可以继续监听端口 P。这是正常且可能发生的。
- **选项C**: [可能] — 针对“RST 触发条件”的考察。服务器重启后，内核中关于该旧连接的 PCB（协议控制块）已不存在。当客户端发送属于旧连接的数据包时，服务器 TCP 模块发现该连接不存在（或序列号不匹配），根据 RFC 规定，应回复 RST 段以通知对方重置连接。这是最标准的行为，是可能发生的。
- **选项D**: [不可能] — 针对“FIN 与 RST 语义混淆”的干扰。FIN 段用于正常、有序地关闭连接（四次挥手）。服务器崩溃属于异常中断，且重启后旧连接状态丢失，服务器无法执行正常的关闭流程（发送 FIN 并等待确认）。因此，服务器绝不会针对一个它“不认识”的旧连接发送 FIN 段。这是不可能发生的。
- **干扰策略**: 概念混淆。利用学生对 TCP 关闭流程（FIN）和异常重置流程（RST）的界限模糊，以及对于“服务器重启后状态”的不确定性进行干扰。

## 核心陷阱
- **核心陷阱**: **FIN 与 RST 的触发场景混淆** 以及 **逆向思维陷阱**。
    1.  学生容易认为“连接断开”就是“发送 FIN”，忽略了 FIN 是主动、有序关闭的标志，而崩溃重启导致的状态丢失必然引发 RST。
    2.  题目问的是“不可能”，学生容易惯性思维选“可能”的选项，或者在 A 和 D 之间犹豫，误以为 A 是不可能的（认为 TCP 总有超时机制），而忽略了题干明确给出的“未使用保活计时器”这一关键约束。

## 考察能力
本题核心考察考生对 TCP 协议异常处理机制（特别是 RST 的生成条件）与正常关闭机制（FIN）的区别，以及在特定约束条件（无保活、服务器重启）下对连接状态流转的逻辑推演能力。
