# 练习题 Q1 — 多进程RR调度与I/O并发推演

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/CPU调度
- **难度**: 待评估

## 题干原文
进程 A、B 和 C 各自执行一个包含 100 次迭代的循环。在每次迭代中，进程执行一次需要 $t_c$ ms CPU 时间的计算操作，然后发起一次持续 $t_{io}$ ms的 I/O 操作。假设运行这些进程的计算机具有足够的 I/O 设备，且操作系统为每个进程分配不同的 I/O 设备。此外，操作系统的调度开销可以忽略不计。各进程的特性如下：
Process id $t_c$ $t_{io}$
A 100 ms 500 ms
B 350 ms 500 ms
C 200 ms 500 ms
这三个进程分别在 0、5 和 10 ms时刻启动，在采用纯时间片轮转调度（时间片为 50 ms）的分时系统中运行。进程 C 完成其第一次 I/O 操作的时间是（  ）ms。
- 选项:
  A: 500
  B: 1000
  C: 2000
  D: 10000
- 正确答案: B
- 解析（参考）: 执行过程分析
三个进程 A、B 和 C 以时间片轮转方式运行，时间片为 50ms。
进程启动时间为 0、5 和 10 ms。
初始阶段执行顺序
A, B, C, A
每个进程执行 50ms CPU 时间
总耗时：50 + 50 + 50 + 50 = 200ms
此时 A 已完成 100ms 计算并开始 I/O
后续执行阶段
B, C, B, C, B, C
每个进程执行 50ms CPU 时间
总耗时：50 × 6 = 300ms
累计总时间：200ms + 300ms = 500ms
关键时间点
进程 C 在 500ms 时刻开始 I/O
I/O 持续时间为 500ms
因此 C 将在 1000ms 时刻完成 I/O。

- 知识标签: ['操作系统/CPU调度']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握RR调度算法的基本规则（时间片轮转、就绪队列管理）以及进程状态转换（运行->阻塞->就绪）的核心概念。不记忆这些定义无法入题，但无需辨析极复杂的易混概念，属于标准的基础认知需求。
- **K2 = 3**: 评分理由。涉及多次加法运算（时间累加）和简单的逻辑判断（是否耗尽时间片）。虽然单步计算简单，但由于步骤多，容易在累加过程中出现算术错误，属于标准的单步代入需求。
- **K3 = 5**: 评分理由。这是本题的核心难点。从输入到输出需要超过5步的串行推演，且必须记忆中间状态（每个进程剩余CPU时间、当前时间、就绪队列顺序）。推演链条长：A启动->B启动->C启动->A用完时间片->B用完时间片->C用完时间片->A再次运行并阻塞->B运行->C运行... 任何一步状态记录错误都会导致最终结果错误。
- **K4 = 4**: 评分理由。存在多个隐含前提和暗坑。1. 进程到达时间不同（0, 5, 10），需正确处理就绪队列的插入顺序；2. I/O设备独立，意味着I/O不阻塞其他进程的I/O，但CPU竞争依然存在；3. 进程A在第一次I/O后退出就绪队列，改变了后续轮转的节奏。这些条件若未意识到，极易陷入常规RR循环的误区。
- **K5 = 3**: 评分理由。主要涉及CPU调度子系统与I/O子系统的单向交互。进程发起I/O后进入阻塞状态，释放CPU，这影响了CPU调度队列的状态。虽然不涉及复杂的跨域数据传递，但状态（运行/阻塞）的切换直接影响调度逻辑，属于单向传数据/状态影响的范畴。
- **雷达形状**: K3-K4 突出型（高推演、高陷阱），K1-K2 中等，K5 较低。典型的“过程模拟”型题目。

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非直接套用公式计算，而是要求考生根据RR调度规则，逐步模拟三个进程在时间轴上的执行状态变化。核心在于逻辑推演和状态跟踪，而非单纯的数值计算或概念记忆。

## 选项级分析
- **选项A (500)**: [干扰] — 针对“混淆开始时间与完成时间”的错误认知。学生可能正确计算出C在500ms时刻*开始*I/O，但误以为题目问的是开始时间，或者忘记加上I/O持续时间。
- **选项B (1000)**: [正确] — 正确推演出C在500ms时刻完成CPU计算并发起I/O，加上500ms的I/O耗时，得到1000ms。
- **选项C (2000)**: [干扰] — 针对“忽略进程到达时间差异”或“错误计算CPU总耗时”的错误认知。例如，可能认为所有进程都需执行完所有CPU时间才轮到C，或者错误地认为C需要等待A和B的所有CPU时间片。
- **选项D (10000)**: [干扰] — 针对“完全误解题意”或“极端计算错误”。可能将100次迭代全部计算在内，或者将时间单位搞错，属于低概率的随机猜测或严重逻辑偏差。
- **干扰策略**: 渐进陷阱。通过复杂的调度过程，让考生在推演中途迷失，或者在最终步骤忘记加上I/O时间（选A），或者在前期推演中因队列顺序错误导致时间大幅偏差（选C）。

## 核心陷阱
- **核心陷阱**: **进程A的提前阻塞改变了RR轮转节奏**。
  许多考生会习惯性地认为RR是严格的A->B->C->A->B->C循环。然而，进程A在消耗完100ms CPU时间（即两个时间片）后，会发起I/O并进入阻塞状态，从而**退出就绪队列**。这导致后续的调度序列变为B->C->B->C...，而不是继续包含A。如果考生忽略了A的退出，会错误地计算C获得CPU的时间点，进而导致最终答案错误。此外，进程到达时间的微小差异（0, 5, 10ms）在RR调度中通常被时间片边界“吸收”，但需确认初始队列顺序。

## 考察能力
本题核心考察考生对**时间片轮转调度算法在动态进程到达和I/O阻塞场景下的精确状态模拟能力**。
