# 2021 Q36 — IP数据报分片计算与标志位判定

## 基本信息
- **年份**: 2021  **题位**: Q36  **题型**: 选择题
- **知识点**: CN-4 > IPv4 > IP数据报分片
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
若路由器向 MTU = 800B 的链路转发一个总长度为 1580B 的 IP 数据报（首部长度为 20B）时，进行了分片，且每个分片尽可能大，则第 2 个分片的总长度字段和 MF 标志位的值分别是（ ）

A. 796,0
B. 796, 1
C. 800,0
D. 800, 1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 IP 数据报分片的核心概念，包括 MTU 限制、IP 首部长度、片偏移单位（8字节对齐）以及 MF（More Fragments）标志位的含义。属于标准的基础概念记忆，不涉及深层辨析。
- **K2 = 3**: 评分理由。涉及具体的数值计算：数据部分长度 = 总长度 - 首部长度；最大数据载荷 = MTU - 首部长度；分片数量计算。虽然计算量不大，但涉及非 2 的幂次除法及取整逻辑，容易因粗心出错，属于标准难度的单步/多步代入。
- **K3 = 3**: 评分理由。解题过程需要串行推演：1. 计算原始数据载荷；2. 确定单个分片最大数据载荷（需满足 8 字节对齐）；3. 确定分片总数；4. 定位第 2 个分片的具体参数（长度、MF 值）。步骤在 3-5 步之间，逻辑链条清晰但需按顺序执行。
- **K4 = 4**: 评分理由。存在明显的隐含前提和易错点。首先，必须意识到“片偏移以 8 字节为单位”，因此分片的数据部分长度必须是 8 的倍数，这是最大的暗坑（直接导致误选 800 或 780 等错误值）。其次，需判断第 2 个分片是否为最后一个分片，从而确定 MF 标志位。若忽略对齐规则或误判分片数量，极易落入陷阱。
- **K5 = 1**: 评分理由。本题仅涉及网络层 IP 协议内部的分片机制，不涉及与其他子系统（如链路层帧结构细节、传输层端口等）的状态传递或深度耦合，属于单系统内的独立计算。
- **雷达形状**: K4 陷阱型。K4 评分较高，主要源于“8字节对齐”这一隐含规则的强制应用，是区分考生是否真正理解分片机制的关键。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的 MTU 和 IP 数据报长度，经过一系列算术运算和对齐规则约束，得出具体的字段值。虽然涉及概念，但最终答案依赖于精确的计算结果。

## 选项级分析
- **选项A**: [干扰] — 针对“计算正确但标志位判断错误”的认知。学生可能正确计算出第 2 个分片长度为 796B，但误以为第 2 个分片是最后一个分片（即认为总共只有 2 个分片），从而将 MF 设为 0。这通常源于对分片总数的估算错误（1560/776 ≈ 2.01，误以为 2 片即可）。
- **选项B**: [正确] — 正确计算了分片数据载荷（776B），总长度（776+20=796B），并正确判断出共有 3 个分片，因此第 2 个分片后还有第 3 个，MF=1。
- **选项C**: [干扰] — 针对“忽略 8 字节对齐规则”的认知。学生直接用 MTU 800B 作为分片总长度，或者认为数据部分可以是 780B（800-20），未考虑片偏移必须是 8 的倍数。同时误判 MF=0。
- **选项D**: [干扰] — 针对“忽略 8 字节对齐规则”的认知。学生直接用 MTU 800B 作为分片总长度，未考虑对齐。但正确判断了 MF=1（知道后面还有分片）。这是最常见的错误选项之一，因为 800 是 MTU 的直接数值，极具诱惑力。
- **干扰策略**: 概念混淆（对齐规则）与计算陷阱（分片数量）结合。选项 C/D 利用 MTU 数值直接干扰，选项 A 利用分片数量估算错误干扰。

## 核心陷阱
- **核心陷阱**: **片偏移的 8 字节对齐约束**。
  许多考生知道分片数据长度 = MTU - IP 首部长度，即 800 - 20 = 780B。但 IP 协议规定片偏移字段以 8 字节为单位，因此除最后一个分片外，所有分片的数据部分长度必须是 8 的倍数。780 不是 8 的倍数（780 / 8 = 97.5），因此必须向下取整到最近的 8 的倍数，即 776B。忽略这一点会导致总长度计算错误（选 800 或 780+20=800 等错误路径）。

## 考察能力
本题核心考察考生对 IP 数据报分片机制中**8字节对齐规则**的理解，以及在多步计算中准确判定**分片数量**与**MF标志位**状态的综合应用能力。
