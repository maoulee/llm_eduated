# 2019 Q29 — LRU页置换算法与缺页/置换次数辨析

## 基本信息
- **年份**: 2019  **题位**: Q29  **题型**: 选择题
- **知识点**: LRU
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
某系统采用 LRU 页置换算法和局部置换策略，若系统为进程 P 预分配了 4 个页框，进程 P 访问页号的序列为 0, 1, 2, 7, 0, 5, 3, 5, 0, 2, 7, 6，则进程访问上述页的过程中，产生页置换的总次数是（ ）。
A: 3
B: 4
C: 5
D: 6

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆LRU（最近最久未使用）算法的核心定义，即“淘汰最近一段时间内最久没有被访问过的页面”。同时需要区分“缺页中断”与“页置换”这两个易混概念。若仅知道LRU名字而不知其具体淘汰规则，或混淆缺页与置换，则无法解题。
- **K2 = 2**: 评分理由。本题不涉及复杂的数学计算，主要是状态的更新和判断。每一步的操作都是简单的“查找-判断-替换”逻辑，计算量极小，属于低难度的单步代入。
- **K3 = 4**: 评分理由。题目给出了12次页面访问序列，且页框数为4。考生需要在脑海中或草稿纸上维护一个长度为4的队列（或栈），随着每次访问更新队列顺序。这是一个典型的多步串行推演过程，步骤超过5步（实际为12步），且每一步的状态都依赖于上一步的结果，中间状态容易出错，因此推演难度较高。
- **K4 = 4**: 评分理由。本题存在一个非常隐蔽且关键的“暗坑”：题目问的是“页置换的总次数”，而不是“缺页次数”。前4次访问必然缺页，但因为是初始填充页框，并不涉及“置换”（即没有页面被换出）。许多考生会习惯性计算缺页次数（共9次，选项无此答案，可能误导选D或其他），或者在后续计算中忽略前4次不计入置换。识别出“前4次缺页不置换”这一隐含前提是本题得分的关键。
- **K5 = 1**: 评分理由。本题仅涉及操作系统内存管理中的页面置换算法，不涉及文件系统、进程调度或其他子系统的联动，属于单模块内的独立问题。

- **雷达形状**: K4陷阱型（K3推演与K4陷阱双高，K1中等，K2/K5低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非简单的概念回忆或公式计算，而是要求考生根据LRU算法的规则，对给定的页面访问序列进行逐步的状态模拟和逻辑推演，最终得出统计结果。

## 选项级分析
- **选项A**: [干扰] — 针对计算严重失误或完全误解LRU规则的学生。例如，可能只计算了后半段的置换，或者错误地认为某些访问命中了。
- **选项B**: [干扰] — 针对推演过程中出现1-2次状态更新错误的学生。例如，在访问序列中间某一步错误地判断了LRU页面，导致后续连锁错误，最终少算了一次置换。
- **选项C**: [正确] — 正确执行LRU算法并准确区分“置换”与“缺页”的学生所得出的结果。
- **选项D**: [干扰] — 针对混淆“缺页次数”与“置换次数”的学生。如果计算缺页次数：
  1. 0 (缺)
  2. 1 (缺)
  3. 2 (缺)
  4. 7 (缺)
  5. 0 (命中)
  6. 5 (缺, 换出1) -> 置换1
  7. 3 (缺, 换出2) -> 置换2
  8. 5 (命中)
  9. 0 (命中)
  10. 2 (缺, 换出7) -> 置换3
  11. 7 (缺, 换出5) -> 置换4
  12. 6 (缺, 换出3) -> 置换5
  总缺页次数为 4(初始) + 5(置换) = 9次。选项中没有9，但D选项6可能是部分学生错误计算置换次数（如多算或少算）后的结果，或者是将某些命中误判为缺页。更有可能的是，部分学生可能错误地认为前4次也算某种形式的“操作”或者在推演中出现了较大偏差。*注：实际上，若考生误以为问的是缺页次数，会发现没有9这个选项，从而被迫重新检查，但若考生计算错误得到6，也会选D。* 另一种常见的错误是：在访问5时，误以为换出的是0（最近访问过），导致后续状态全错。

- **干扰策略**: 概念混淆（缺页vs置换）与 计算陷阱（多步推演中的状态丢失）

## 核心陷阱
**“页置换次数”不等于“缺页次数”**。
前4次访问页面时，页框为空，虽然发生缺页中断，但属于“填充”而非“置换”。LRU置换算法仅在页框已满且发生缺页时才触发“置换”操作。本题共有9次缺页，但只有5次置换。

## 考察能力
本题核心考察考生对LRU页面置换算法执行过程的模拟能力，以及对“缺页中断”与“页面置换”这两个关键概念界限的精准辨析能力。
