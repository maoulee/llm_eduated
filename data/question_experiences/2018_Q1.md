# 2018 Q1 — 栈的基本概念与后缀表达式求值

## 基本信息
- **年份**: 2018  **题位**: Q1  **题型**: 选择题
- **知识点**: DS-3 > 3.1 栈 > 栈的基本概念
- **题位域**: DS-1  **科目**: 数据结构

## 题干原文
若栈 S1 中保存整数，栈 S2 中保存运算符，函数 F() 依次执行下述各步操作：
从 S1 中依次弹出两个操作数 a 和 b;
从 S2 中弹出一个运算符 op;
执行相应的运算 b op a;
将运算结果压入 S1 。
假定 S1 中的操作数依次是 5,8,3,2（2 在栈顶），S2 中的运算符依次是 ×,−,+ （ + 在栈顶）。调用 3 次 F() 后，S1 栈顶保存的值是（ ）。

A. -15
B. 15
C. -20
D. 20

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握栈“后进先出”（LIFO）的核心定义，以及后缀表达式（逆波兰表达式）求值的基本规则。不记忆栈的基本操作无法入题，但无需辨析复杂概念，属于标准的基础认知需求。
- **K2 = 2**: 评分理由。涉及的运算仅为加减乘，且数值较小（5, 8, 3, 2），计算过程简单，不易出错。属于较低的单步代入需求。
- **K3 = 3**: 评分理由。题目要求模拟函数 F() 调用 3 次的过程，每次调用涉及从两个栈弹出、计算、再压入一个栈的操作。需要串行推演 3 个步骤，并跟踪中间状态的变化，属于标准的机制推演需求。
- **K4 = 4**: 评分理由。存在明显的隐含前提和易错点：
    1. **操作数顺序陷阱**：题目明确指出“弹出 a 和 b”，但运算为 `b op a`。由于栈是 LIFO，先弹出的是栈顶元素（即 a），后弹出的是次栈顶元素（即 b）。许多考生容易误认为是 `a op b`，导致减法或除法结果错误。
    2. **初始状态理解**：需正确理解“5,8,3,2（2 在栈顶）”意味着栈底是 5，栈顶是 2。
    这些陷阱使得条件路由需求较高。
- **K5 = 2**: 评分理由。虽然涉及两个栈 S1 和 S2，但它们之间的交互是单向且明确的（S2 提供运算符，S1 提供操作数并接收结果），没有复杂的状态互影响或深度耦合，属于较低程度的跨域联动。
- **雷达形状**: K4 陷阱型。本题在基础概念（K1）和计算（K2）上难度不高，但在规则执行的细节（K4，特别是操作数顺序）上设置了较高的门槛，导致雷达图在 K4 维度突出。

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非单纯的概念记忆或复杂计算，而是要求考生根据给定的算法步骤（函数 F 的逻辑），结合栈的数据结构特性，逐步推演数据状态的变化。核心在于对“过程”的逻辑模拟。

## 选项级分析
- **选项 A**: [干扰] — 针对**操作数顺序错误**且**符号处理错误**的考生。如果考生误以为运算是 `a op b`，第一次运算变成 `2 + 3 = 5`（结果相同），第二次 `5 - 8 = -3`，第三次 `5 * (-3) = -15`。或者在减法时搞错正负号。
- **选项 B**: [正确] — 正确执行了 `b op a` 的逻辑。
    1. 第一次：弹出 a=2, b=3, op=+。计算 `3 + 2 = 5`。S1: [5, 8, 5]。
    2. 第二次：弹出 a=5, b=8, op=-。计算 `8 - 5 = 3`。S1: [5, 3]。
    3. 第三次：弹出 a=3, b=5, op=×。计算 `5 * 3 = 15`。S1: [15]。
- **选项 C**: [干扰] — 针对**操作数顺序错误**的考生。如果误用 `a op b`：
    1. 第一次：`2 + 3 = 5`。
    2. 第二次：`5 - 8 = -3`。
    3. 第三次：`3 * (-3) = -9` (不对，这里如果第三次也错序，是 `3 * 5` 还是 `5 * 3` 乘法交换律不影响)。
    让我们重新推导常见的错误路径：
    如果考生认为 `a` 是第一个弹出的（栈顶），`b` 是第二个弹出的，但误以为公式是 `a op b`：
    1. `2 + 3 = 5`。S1: [5, 8, 5]。
    2. `5 - 8 = -3`。S1: [5, -3]。
    3. `(-3) * 5 = -15`。这是选项 A。
    那选项 C (-20) 怎么来的？
    可能是初始栈理解错误，或者运算顺序完全混乱。例如：`5 * 8 = 40`, `40 - 3 = 37`... 不太像。
    另一种可能：考生忽略了栈顶方向，认为 5 在栈顶。
    如果 5 在栈顶：
    1. 弹出 5, 8, op=+。`8+5=13`。
    2. 弹出 13, 3, op=-。`3-13=-10`。
    3. 弹出 -10, 2, op=×。`2*-10=-20`。
    是的，**选项 C 是针对“栈顶方向理解错误”（认为 5 在栈顶）的考生**。
- **选项 D**: [干扰] — 针对**操作数顺序错误**且**忽略负号**或**其他计算错误**的考生。
    如果误用 `a op b` 且第二次算成 `8-5=3`（正确），但第三次算错？
    或者，如果考生认为运算是 `a op b`，且第一次 `2+3=5`，第二次 `5-8=-3`，第三次 `5 * (-3) = -15` (A)。
    如果考生认为运算是 `b op a` (正确)，但第一次算错？
    让我们看选项 D (20)。
    如果栈顶方向错误（5在顶），且运算顺序 `b op a`：
    1. 弹出 5(a), 8(b), op=+。`8+5=13`。
    2. 弹出 13(a), 3(b), op=-。`3-13=-10`。
    3. 弹出 -10(a), 2(b), op=×。`2*-10=-20` (C)。
    
    再看一种错误：忽略 `b op a` 的顺序，直接用 `a op b`，且栈顶方向正确：
    1. `2 + 3 = 5`。
    2. `5 - 8 = -3`。
    3. `(-3) * 5 = -15` (A)。
    
    那 D (20) 呢？
    可能是：`5 * 8 = 40`, `40 / 2 = 20`? 不对，运算符是 +, -, *。
    可能是：`3 * 2 = 6`, `8 - 6 = 2`, `5 * 2 = 10`?
    可能是：`5 + 8 = 13`, `13 - 3 = 10`, `10 * 2 = 20`。
    这对应的是：**完全忽略栈的 LIFO 特性，按照数组从左到右的顺序进行计算**，并且**忽略 `b op a` 的顺序，直接按出现顺序 `a op b`**（或者因为加减乘除大部分可交换，除了减法）。
    具体路径：
    1. 取 5, 8, +。`5 + 8 = 13`。
    2. 取 13, 3, -。`13 - 3 = 10`。
    3. 取 10, 2, *。`10 * 2 = 20`。
    是的，**选项 D 是针对“完全忽略栈结构，按线性顺序计算”的考生**。

- **干扰策略**: 
    - A: 操作数顺序陷阱 (`a op b` vs `b op a`)。
    - C: 栈顶方向陷阱 (5在顶 vs 2在顶)。
    - D: 数据结构本质陷阱 (忽略栈的 LIFO，按线性处理)。

## 核心陷阱
**操作数弹出的顺序与运算顺序的对应关系**。
题目中“弹出 a 和 b”意味着 a 是栈顶元素（后入先出），b 是次栈顶元素。但运算指定为 `b op a`。对于非交换运算（如减法 `-`），`b - a` 与 `a - b` 结果截然不同。这是本题最大的失分点。

## 考察能力
本题核心考察考生对**栈“后进先出”特性的动态模拟能力**，以及在具体算法实现中**严格遵循操作顺序（特别是非交换运算的操作数顺序）**的严谨性。
