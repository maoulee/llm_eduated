## K1-K5 评分与解析
- **K1 = 3**: 3 — 必须准确记忆 Cache 组相联映射的地址字段划分规则（Tag/组号/块内偏移）以及 LRU 替换算法的位宽计算逻辑（n路需要 log2(n) 位状态位）。若概念模糊，无法确定 Tag 位数和 LRU 位总数。不是4，因为不涉及冷门细节或极易混淆的冷门概念，是核心考点。
- **K2 = 2**: 2 — 计算过程主要是位运算（移位、掩码）和简单的对数计算（lg8=3）。数字友好（8路，32位地址），无复杂浮点或非2的幂次计算。不是3，因为不涉及繁琐的单位换算或复杂公式代入。
- **K3 = 3**: 3 — 需按固定流程执行：1.解析地址结构；2.计算Cache行/组索引；3.遍历数组访问序列，模拟 LRU 状态更新；4.统计 Miss 次数。流程清晰，步数适中（约3-5步核心逻辑），路径唯一。不是4，因为不涉及动态状态的大规模更新或超过5步的极长推演。
- **K4 = 3**: 3 — 存在明确的陷阱词/隐含前提：起始地址非块对齐时，前几个元素可能位于不同的 Cache 行或块中，影响首次 Miss 的模式；必须识别“直写策略”对写操作 Miss 的影响（通常直写不分配或写分配需确认，题目隐含写分配或仅关注读，需根据常规真题逻辑判断，此处主要陷阱在于地址映射的非整除性）。不是4，因为陷阱属于常规考点范围内的“地址对齐”问题，非深度机制理解。
- **K5 = 2**: 2 — 题目主要考察 Cache 内部机制。虽然题干提到指令 Cache 和数据 Cache，但问题通常聚焦于数据 Cache 的数组访问（或指令流，视具体子问而定，本题通常侧重数据 Cache 的 Miss 计算或两者结构参数）。若涉及指令流，则是单向拼接（PC流向IC），无深度双向耦合。不是3，因为不需要在 IC 和 DC 之间进行复杂的状态传递或相互制约推演。

## 条件利用映射
- **32位地址, 按字节编址**: 用于确定地址总位数，计算 Tag 和 组号 的基准。
- **8路组相联**: 确定每组的块数，影响 LRU 位宽计算和 Miss 率模拟的冲突特性。
- **直写策略**: 影响写操作的 Miss 处理流程（是否更新 Cache 数据、是否更新主存）。
- **LRU替换算法**: 决定在 Cache 满时替换哪一块，直接决定 Miss 计数。
- **数组起始地址/大小**: 用于生成具体的内存访问序列，是模拟 Miss 的核心输入。

## 关键考察点
1. **地址映射的精确性**：能否正确将 32 位地址划分为 Tag、Index、Offset，特别是处理非对齐地址时的块索引变化。
2. **LRU 状态的动态推演**：能否在模拟过程中正确维护组内的 LRU 顺序，这是计算 Miss 数的关键，也是易错点。

## 核心陷阱
- **核心陷阱**: **地址非块对齐**。如果数组起始地址 `Base` 的 `Offset` 不为 0，那么 `Base` 地址对应的 Cache 块可能只包含数组的前几个字节，下一个元素可能落在下一个主存块中。如果学生忽略 Offset，直接假设 `Base` 占据整个块或从块头开始，会导致对前几个元素映射组的判断错误，进而导致整个 LRU 状态链出错，Miss 数计算完全错误。
- **错误路径**: 忽略块内偏移，直接用地 址 / 块大小 取整得到块号，再取模得到组号。正确的做法是先看 Offset，确定当前块还剩多少空间，判断是否跨块。
