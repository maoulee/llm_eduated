# 练习题 Q1 — 嵌套循环时间复杂度分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
函数 fun() 的时间复杂度是多少？
```c
int fun(int n) {
    int count = 0;
    for (int i = 0; i < n; i++)
        for (int j = i; j > 0; j--)
            count = count + 1;
    return count;
}
```
- 选项:
  A: O(n)
  B: O(n^2)
  C: O(n×log(n))
  D: O(n×(log(n×log2(n))))
- 正确答案: B
- 解析（参考）: 通过计算表达式 count = count + 1; 的执行次数可以得出时间复杂度。该表达式的执行次数为 0 + 1 + 2 + 3 + 4 + … + (n-1) 次。因此时间复杂度为：O(0+1+2+3+⋯+n−1) = O(n(n−1)/2) = O(n^2)
- 知识标签: ['数据结构/算法分析']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“时间复杂度”的核心定义以及大O表示法的含义。不是1分因为不能仅靠直觉，必须理解基本操作执行次数与输入规模的关系；不是4分因为不需要辨析多个易混的高级概念（如摊销复杂度等），只需基础定义。
- **K2 = 3**: 评分理由。涉及等差数列求和公式的应用。不是2分因为不是简单的2的幂次或常数计算，需要执行一次代数求和运算；不是4分因为求和公式是高中数学基础，不涉及多级复杂换算。
- **K3 = 2**: 评分理由。推演步骤较少。只需分析两层循环的依赖关系：外层循环确定内层循环的初始值，内层循环执行固定次数。从输入n到输出复杂度，逻辑链条清晰，仅需2-3步推导（识别循环结构 -> 确定单次执行次数 -> 求和）。
- **K4 = 2**: 评分理由。存在常规注意点，但无深层陷阱。主要注意点在于内层循环的起始条件 `j=i` 而非 `j=0` 或 `j=n`，这导致内层循环次数随 `i` 变化。这是标准的嵌套循环分析模式，没有反直觉的隐含前提或复杂的条件分支。
- **K5 = 1**: 评分理由。单系统分析。本题仅涉及单一代码片段的时间复杂度分析，不需要跨越不同子系统（如内存管理、网络协议等）传递状态或数据。

- **雷达形状**: K2计算主导型（K1、K2略高，K3、K4、K5较低，呈现向计算和基础概念倾斜的形状）

## 考察模式
- **模式**: 计算型
- **理由**: 本题的核心解题路径是通过数学计算（等差数列求和）来确定基本操作的执行次数，进而推导时间复杂度。虽然涉及代码阅读，但最终落脚点在于数值计算和渐近符号的转换。

## 选项级分析
- **选项A**: [干扰] — 针对“线性思维”错误认知。这类学生可能只看到了外层循环 `for (int i = 0; i < n; i++)`，忽略了内层循环的存在，或者错误地认为内层循环是常数时间操作。
- **选项B**: [正确] — 正确推导结果。
- **选项C**: [干扰] — 针对“对数混淆”错误认知。这类学生可能看到循环中有递减操作 `j--`，或者联想到二分查找等常见 O(log n) 场景，错误地将嵌套循环与对数复杂度关联。也可能误以为内层循环每次减半（实际是线性递减）。
- **选项D**: [干扰] — 针对“复杂公式堆砌”错误认知。这是一个典型的“看起来很高深”的干扰项。这类学生可能对时间复杂度公式不熟悉，倾向于选择看起来最复杂、包含最多数学符号的选项，或者被 `log(n×log2(n))` 这种复杂结构迷惑，认为复杂代码对应复杂复杂度。

- **干扰策略**: 概念混淆（A与C混淆线性与对数）、视觉干扰（D利用复杂公式制造难度假象）

## 核心陷阱
- **核心陷阱**: 内层循环的迭代次数不是常数，而是依赖于外层循环变量 `i`。许多初学者容易误判内层循环为固定次数或错误地将其视为对数级递减，从而得出 O(n) 或 O(n log n) 的错误结论。关键在于识别出总执行次数是一个等差数列求和。

## 考察能力
一句话概括本题核心考察的能力：能够准确分析嵌套循环中基本操作的执行次数，并运用数学求和公式推导算法的时间复杂度。
