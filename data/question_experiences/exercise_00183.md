## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 `fork`（创建进程）和 `join`（同步等待/计数）这两个核心并发原语的定义。虽然题目给出了定义，但理解其语义（特别是 `join` 的计数递减与阻塞机制）是解题基础，属于标准概念调用。不是4分因为题目直接给出了定义，无需辨析易混概念。
- **K2 = 2**: 评分理由。本题不涉及数值计算，而是逻辑关系的映射。将代码语句映射为优先图中的节点和边，属于低难度的直接转换。
- **K3 = 4**: 评分理由。推演步骤较多且需维护状态。需要跟踪主进程和两个子进程的执行流，理解 `N=2` 和 `M=2` 的初始值如何影响 `join` 的阻塞行为。具体步骤包括：1. 识别进程创建点；2. 追踪各进程执行路径；3. 分析 `join N` 需要等待主进程和 L3 进程（共2个）到达；4. 分析 `join M` 需要等待主进程（通过 S3 后）和 L4 进程（共2个）到达。涉及多步串行推演和中间状态（计数器值）的记忆。
- **K4 = 4**: 评分理由。存在隐含前提和易错陷阱。关键在于理解 `join` 的语义：它不仅是同步点，还是计数器。必须意识到 `join N` 在 `L1` 处执行，而 `L1` 被主进程和 `L3` 分支（执行完 S2 后 goto L1）共同访问。若未识别出 `goto L1` 导致两个进程在 `L1` 汇合，就会错误判断依赖关系。此外，`join` 后值不为0则终止，意味着只有最后一个到达的进程会继续执行后续代码（S3），这也是隐含的控制流逻辑。
- **K5 = 3**: 评分理由。需要在进程创建（fork）和进程同步（join）两个机制间联动。状态（变量 N 和 M 的值）在不同进程间共享并影响执行流，属于单向传数据/状态影响执行路径的情况。

- **雷达形状**: 偏向“机制推演”和“条件路由”的高分型，K1基础适中，K2计算极低，整体呈现中间高、两头低的特征，强调逻辑推理而非记忆或计算。

## 考察模式
- **模式**: 分析论证型
- **理由**: 题目要求根据给定的并发程序代码，分析进程间的执行顺序和依赖关系，并最终论证出正确的优先图结构。这需要考生对代码逻辑进行静态分析，而非简单的公式代入或算法设计。

## 解题思路分析
- **核心思路**: 模拟执行法。通过模拟主进程和子进程的执行流程，确定每个语句（S1-S5）的执行前提，从而构建优先图。
- **关键步骤**:
    1. **初始化**: 识别全局变量 `N=2`, `M=2`。
    2. **进程创建分析**:
       - 主进程执行 `fork L3`，创建子进程 P1，P1 从 L3 开始执行。
       - 主进程执行 `fork L4`，创建子进程 P2，P2 从 L4 开始执行。
       - 主进程继续执行 `S1`。
    3. **子进程路径追踪**:
       - P1 (L3): 执行 `S2`，然后 `goto L1`。
       - P2 (L4): 执行 `S4`，然后 `goto L2`。
    4. **同步点分析 (Join N)**:
       - 主进程执行完 S1 后到达 L1，执行 `join N`。
       - P1 执行完 S2 后到达 L1，执行 `join N`。
       - `N` 初始为 2。两个进程（主进程和 P1）都会执行 `join N`。
       - 只有当两个进程都执行完 `join N` 后，`N` 变为 0，最后一个执行的进程才会继续向下执行 `S3`。
       - **依赖关系**: `S3` 依赖于 `S1` (主进程到达 L1 的前提) 和 `S2` (P1 到达 L1 的前提)。即 `S1 -> S3` 且 `S2 -> S3`。
    5. **同步点分析 (Join M)**:
       - 执行完 `S3` 的进程（无论是主进程还是 P1，取决于调度，但逻辑上视为一个流）到达 L2，执行 `join M`。
       - P2 执行完 `S4` 后到达 L2，执行 `join M`。
       - `M` 初始为 2。两个进程（执行完 S3 的进程和 P2）都会执行 `join M`。
       - 只有当两个进程都执行完 `join M` 后，`M` 变为 0，最后一个执行的进程才会继续向下执行 `S5`。
       - **依赖关系**: `S5` 依赖于 `S3` (执行完 S3 的进程到达 L2 的前提) 和 `S4` (P2 到达 L2 的前提)。即 `S3 -> S5` 且 `S4 -> S5`。
    6. **构建优先图**:
       - S1 和 S2 无前置依赖（除了程序开始）。
       - S4 无前置依赖（除了程序开始）。
       - S3 依赖 S1 和 S2。
       - S5 依赖 S3 和 S4。
- **易错点**:
    1. 忽略 `goto` 语句，误以为 L1 和 L2 只被主进程访问。
    2. 误解 `join` 的语义，认为 `join` 只是简单的屏障，而忽略了它需要所有相关进程都到达才能释放，且只有最后一个进程继续执行。
    3. 错误判断 S3 和 S4 的关系，误以为 S4 必须在 S3 之前或之后，实际上 S4 和 S3 是并行的，它们共同决定 S5 的开始。

## 核心陷阱
- **核心陷阱**: `join` 变量的初始值与访问该 `join` 点的进程数量必须匹配。本题中 `N=2`，对应主进程和 P1 两个进程访问 L1；`M=2`，对应执行完 S3 的进程和 P2 两个进程访问 L2。如果考生没有正确识别出哪些进程会执行 `join`，就会画错依赖边。例如，可能错误地认为 S5 只依赖 S3，而忽略了 S4 的同步作用。

## 考察能力
本题核心考察考生对并发进程中进程创建、执行流控制及同步原语（特别是基于计数的同步）的深入理解与逻辑推演能力。
