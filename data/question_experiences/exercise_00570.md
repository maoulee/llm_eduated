# 练习题 Q — HTTP请求与TCP连接复用机制

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/应用层
- **难度**: 待评估

## 题干原文
位于网络客户端机器 Q 的图形化 HTML 浏览器从 HTTP 服务器 S 访问一个静态 HTML 网页。该静态 HTML 页面中恰好嵌入了一个静态图像，且该图像也存储在 S 上。假设没有缓存机制，以下关于加载该 HTML 网页（包括嵌入图像）的说法中哪一项是正确的？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 HTTP 协议的基本工作流程（请求-响应模型）以及 TCP 连接的概念。不是 2 分因为仅靠直觉无法区分 HTTP 请求次数与 TCP 连接次数的关系，需要明确“资源加载”与“传输通道”两个核心定义。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算或公式代入，属于纯概念逻辑判断。
- **K3 = 3**: 评分理由。推演步骤清晰但需多步：1. 识别资源数量（HTML + 图像 = 2个资源）；2. 确定 HTTP 请求数量（每个资源 1 个请求 = 2 个请求）；3. 判断 TCP 连接复用可能性（同源服务器 + HTTP/1.1 默认持久连接 = 1 个连接）。共 3 步逻辑串联，属于标准推演难度。
- **K4 = 4**: 评分理由。存在明显的隐含前提和易错点。陷阱在于“HTTP 请求”与“TCP 连接”的解耦。许多学生容易混淆“非持久连接”（HTTP/1.0 默认）与“持久连接”（HTTP/1.1 默认）的区别，或者误以为每个 HTTP 请求必须对应独立的 TCP 连接。题目未明确指定 HTTP 版本，但考察的是现代网络环境下的标准行为（即支持复用），需要考生识别出“单个 TCP 连接足够”这一关键隐含条件，避开“必须独立连接”的思维定势。
- **K5 = 3**: 评分理由。涉及应用层（HTTP）与传输层（TCP）的交互。需要理解应用层协议如何利用传输层提供的服务（复用连接），属于典型的跨层单向依赖关系（应用层依赖传输层，但传输层不感知应用层内容）。

- **雷达形状**: K4 陷阱型（K1 基础认知与 K4 条件路由较高，K2 计算极低，整体呈现对概念辨析和隐含条件识别要求高的特征）

## 考察模式
- **模式**: 推理型
- **理由**: 题目并非直接询问定义，而是给定一个具体的网络交互场景（加载含图像的网页），要求考生根据协议规范推导出底层的连接行为和请求数量。需要结合资源解析、协议特性进行逻辑推理。

## 选项级分析
- **选项 A**: [干扰] — 针对“非持久连接”或“HTTP/1.0”的过时认知，或者混淆了 HTTP 请求与 TCP 连接的绑定关系。这类学生可能认为每个 HTTP 事务都需要独立的三次握手，或者误以为浏览器为了并行加载必须建立多个连接（虽然现代浏览器确实会建立多个连接以并行下载，但题目问的是“至少”和“足够”，且强调单服务器场景下的最小开销逻辑，A 选项的“必须”过于绝对且不符合持久连接特性）。
- **选项 B**: [正确] — 准确描述了 HTTP/1.1 持久连接（Persistent Connection）的特性。浏览器先请求 HTML，解析后发现嵌入图像，随后在同一 TCP 连接上发送第二个 HTTP 请求获取图像。
- **选项 C**: [干扰] — 针对对 HTTP 协议机制的误解，认为浏览器可以一次性打包所有资源请求。这类学生可能混淆了 HTTP 请求与 DNS 查询或 TCP 连接建立的过程，或者误以为 HTML 中的 `<img>` 标签可以在初始请求中一并获取，忽略了 HTTP 是基于请求-响应模型的，必须先拿到 HTML 解析出 URL 才能发起后续请求。
- **选项 D**: [干扰] — 针对对 TCP/IP 协议栈基本常识的缺失。这类学生可能误以为 HTTP 可以直接运行在 UDP 上（如 QUIC/HTTP3，但题目语境通常指传统 HTTP/TCP），或者完全误解了面向连接协议的本质。

- **干扰策略**: 概念混淆（混淆 HTTP 请求数与 TCP 连接数）、绝对化陷阱（选项 A 的“必须”）、机制误解（选项 C 的“一次请求”）

## 核心陷阱
**核心陷阱**: 混淆“HTTP 请求的数量”与“TCP 连接的数量”。考生容易陷入两个极端：要么认为每个请求都要新建连接（忽略持久连接），要么认为所有资源可以合并为一个请求（忽略 HTTP 的串行解析特性）。关键在于理解 HTTP/1.1 默认使用持久连接，允许在同一个 TCP 连接上串行发送多个 HTTP 请求。

## 考察能力
本题核心考察考生对 HTTP 协议中**持久连接（Persistent Connection）**机制的理解，以及区分**应用层请求**与**传输层连接**之间复用关系的能力。
