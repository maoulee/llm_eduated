# 练习题 Q1 — 就绪队列容量与CPU数量的关系

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/CPU调度
- **难度**: 待评估

## 题干原文
对于具有 n 个 CPU 的计算机系统，就绪状态中进程的最大数量是（ ）
A: n
B: n²
C: 2n
D: 与 n 无关

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆“就绪状态”的定义以及它与“运行状态”的区别。如果混淆了“同时运行的进程数”和“等待运行的进程数”，就会出错。这属于标准的核心概念辨析，不需要极高深的记忆，但必须清晰。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、公式代入或单位换算，完全属于定性分析。
- **K3 = 1**: 评分理由。解题过程不需要多步推演，只需直接调用概念定义即可得出结论：就绪队列长度受内存限制，而非CPU数量限制。
- **K4 = 4**: 评分理由。存在明显的思维陷阱。题目给出了变量 `n`（CPU数量），诱导考生建立 `n` 与答案之间的数学函数关系（如线性、平方等）。考生必须识别出这是一个“伪相关”条件，即CPU数量只影响并发执行能力，不影响等待队列的理论上限。这种“反直觉”或“打破常规数学建模思维”的要求使得条件路由难度较高。
- **K5 = 1**: 评分理由。本题仅涉及CPU调度子系统内的基本概念，不涉及内存管理、I/O子系统或其他模块的状态联动。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，K2/K3极低）

## 考察模式
- **模式**: 概念型
- **理由**: 题目核心在于考察对操作系统进程状态定义及其物理/逻辑限制的理解，而非计算或复杂逻辑推理。重点在于辨析“运行”与“就绪”的本质区别。

## 选项级分析
- **选项A**: [干扰] — 针对“一一对应”的错误认知。这类学生可能认为每个CPU对应一个就绪进程，或者混淆了“最大并发运行数”（确实是n）与“就绪数”。
- **选项B**: [干扰] — 针对“盲目数学建模”的错误认知。这类学生看到变量 `n`，下意识寻找平方关系，或者误以为多核系统会有某种指数级的队列扩展机制，属于无依据的猜测。
- **选项C**: [干扰] — 针对“线性扩展”的错误认知。这类学生可能认为就绪队列大小是CPU数量的倍数，或者混淆了某些特定调度算法中的参数（如时间片轮转中的某些配置），但本质上仍是错误地建立了 `n` 与队列长度的依赖关系。
- **选项D**: [正确] — 正确认知。就绪队列的大小主要受限于系统内存（PCB的大小和数量）以及调度器的实现，理论上与CPU核心数 `n` 没有直接的函数依赖关系。即使只有1个CPU，也可以有成千上万个进程处于就绪状态。
- **干扰策略**: 概念混淆与伪数学陷阱。通过引入变量 `n`，诱导考生进行错误的数学关联，同时利用“运行状态最大数量为n”这一正确知识点作为干扰源，混淆“运行”与“就绪”的概念。

## 核心陷阱
**核心陷阱**: 混淆“并发执行能力”与“等待队列容量”。考生容易将“最多有n个进程同时运行”这一事实，错误地迁移或类比到“就绪队列的大小”上，从而错误地认为就绪队列大小受n限制。

## 考察能力
本题核心考察考生对进程状态转换机制中“就绪”与“运行”状态物理含义的精准辨析能力，以及排除无关变量干扰的逻辑判断能力。
