# 练习题 Q1 — 二分查找时间复杂度分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/二叉树
- **难度**: 待评估

## 题干原文
在对大小为 n 的已排序数组进行递归二分查找时，最坏情况下执行的算术运算次数是多少？（ ）
A: Θ(√n)
B: Θ(log₂(n))
C: Θ(n²)
D: Θ(n)

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆二分查找的核心性质（每次折半）及其对应的时间复杂度公式。不是4分因为不需要辨析多个易混概念（如与线性查找、插值查找的细微区别），只需掌握核心定义即可。
- **K2 = 1**: 评分理由。本题不涉及具体的数值计算，而是对复杂度量级的定性判断。没有复杂的算术运算或幂次换算，属于概念直接映射。
- **K3 = 2**: 评分理由。推演步骤较少：识别算法为二分查找 -> 确定每次区间减半 -> 得出递归深度为 log₂n -> 确定运算次数与深度成正比。这是一个标准的2-3步逻辑链条，无需多步串行推演或记忆中间状态。
- **K4 = 2**: 评分理由。存在常规注意点，即“最坏情况”和“算术运算次数”。学生需意识到最坏情况对应查找失败或查找最后一个元素，且每次递归仅涉及常数次算术运算（计算mid）。没有深层隐含前提或反直觉陷阱，属于常规考点。
- **K5 = 1**: 评分理由。本题仅涉及单一子系统（二分查找算法本身），无需跨越不同数据结构或模块传递状态，属于单系统内部分析。
- **雷达形状**: K1主导型（概念记忆型）。K1分数最高，其他维度分数较低，表明本题主要考察对基础算法复杂度公式的记忆和理解，而非复杂计算或深层推理。

## 考察模式
- **模式**: 概念型
- **理由**: 题目核心在于考察考生对二分查找算法时间复杂度这一基本概念的记忆和理解。虽然题干提到了“算术运算次数”，但这只是将时间复杂度具体化为操作次数，本质仍是考察 Θ(log n) 这一核心概念，而非通过具体数据计算得出结果。

## 选项级分析
- **选项A**: [干扰] — 针对对算法效率缺乏直观认知的学生。√n 常见于某些特定搜索算法（如分块查找的某些变体）或几何问题，学生可能因混淆不同算法的复杂度量级而误选。
- **选项B**: [正确] — 二分查找每次将搜索空间减半，递归深度为 log₂n，每层执行常数次算术运算，故总次数为 Θ(log₂n)。
- **选项C**: [干扰] — 针对完全混淆算法复杂度的学生。n² 是典型低效算法（如冒泡排序、选择排序）的复杂度，与查找算法无关，属于极端错误选项，用于排除完全无概念的考生。
- **选项D**: [干扰] — 针对将二分查找与线性查找混淆的学生。线性查找的最坏情况复杂度为 Θ(n)，学生若未区分“二分”与“线性”的本质区别，或误以为“最坏情况”意味着遍历所有元素，则会选此项。
- **干扰策略**: 概念混淆。通过提供不同量级的复杂度选项（√n, log n, n, n²），考察考生对常见算法复杂度量级的准确记忆和区分能力。

## 核心陷阱
- **核心陷阱**: 混淆“最坏情况”的含义。部分学生可能误以为“最坏情况”意味着需要检查所有元素，从而误选 Θ(n)。实际上，二分查找的最坏情况是指目标元素不在数组中或位于最后被检查的位置，其比较次数仍由递归深度决定，即 log₂n 级别，而非 n 级别。

## 考察能力
本题核心考察考生对二分查找算法时间复杂度（Θ(log n)）的概念记忆及其在最坏情况下的应用能力。
