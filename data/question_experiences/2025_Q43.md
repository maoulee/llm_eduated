## 题干原文

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。需要熟练掌握Cache组相联映射的地址划分规则（Tag/Index/Offset）、虚拟地址到物理地址的转换逻辑、页表与缺页中断的基本概念。涉及多个核心定义的辨析，如“块内偏移”与“页内偏移”的区别，“Cache组号”与“页号”的对应关系。
- **K2 = 4**: 评分理由。计算过程包含多级换算：十六进制转二进制、十进制偏移量计算、Cache组号提取、缺失率百分比计算、平均访问时间加权计算。特别是第(3)问的平均访问时间计算，需要结合命中率和缺失惩罚进行加权，步骤较多且容易出错。
- **K3 = 4**: 评分理由。解题需要多步串行推演。例如第(3)问，需先确定访问模式（顺序访问），再结合Cache块大小（64B）和数组元素大小（4B）判断每块能容纳的元素个数，进而推导缺失模式（每16个元素缺失1次）。第(4)问需结合页大小（4KB）和数组总大小推导缺页次数，需考虑预取或按需调页的策略隐含条件。
- **K4 = 5**: 评分理由。存在多个隐含前提和陷阱。1. 题目未明确说明Cache替换算法，但根据顺序访问特性，通常假设无冲突或LRU/FIFO不影响顺序访问的缺失率（空间局部性）。2. 题目未明确缺页时的调页策略（是只调入当前页还是预取相邻页），通常默认按需调页（Demand Paging），但需考生意识到这一点。3. “d不在主存”意味着首次访问必然缺页，且需考虑写操作是否触发缺页（通常读缺页，写可能涉及Copy-on-Write或直接分配，此处简化为访问即缺页）。4. Cache缺失率计算中，需区分“读缺失”和“写缺失”，题目中`d[i] = d[i]/x`包含读和写，需判断写操作是否计入缺失率（通常Cache缺失指访问Cache未命中，无论读写）。
- **K5 = 5**: 评分理由。深度耦合。本题将组成原理的Cache机制与操作系统的虚拟内存机制紧密结合。Cache的缺失率受内存访问模式影响，而内存访问模式又受页式管理的影响（如页边界对齐）。第(3)问和第(4)问分别考察了Cache层和OS层的性能指标，且两者通过地址空间（VA/PA）和访问序列紧密关联。考生需在两个子系统间切换思维，理解VA如何映射到Cache Index，以及VA如何映射到Page Frame。
- **雷达形状**: 整体呈高难度分布，K4和K5突出，表明题目不仅考察计算能力，更侧重对系统机制深层理解和隐含条件的挖掘。

## 解题思路分析
- **核心思路**: 
    1. **地址结构分析**：根据Cache参数（大小、路数、块大小）确定地址中Tag、Index、Offset的位数。
    2. **地址计算**：根据数组起始地址和索引计算具体元素的虚拟地址（VA），并提取对应的Cache组号。
    3. **Cache性能分析**：分析循环访问模式，结合Cache块大小确定空间局部性带来的缺失模式，计算缺失率和平均访问时间。
    4. **页式管理分析**：根据页大小和数组分布，计算缺页次数，注意起始地址的对齐情况和访问顺序。

- **关键步骤**:
    1. **Q1**: 
       - 块内偏移：$\log_2(64) = 6$位。
       - Cache总块数：$32KB / 64B = 512$块。
       - 组数：$512 / 8 = 64$组。
       - 组号位数：$\log_2(64) = 6$位。
       - VA中Cache索引位：由于按字节编址，低6位是块内偏移，接下来的6位是组号，即VA[11:6]。
    2. **Q2**: 
       - `d`是int数组，假设int为4字节（32位字长通常对应4字节int）。
       - `d[100]`地址 = $0x01800020 + 100 \times 4 = 0x01800020 + 0x190 = 0x018001B0$。
       - 提取VA[11:6]：$0x018001B0$的二进制低16位为`0000 0001 1011 0000`。
       - VA[11:6]对应二进制`00 0001`（从右数第6位到第11位），即十进制1。
    3. **Q3**: 
       - `d[0]`偏移：起始地址$0x...20$，块大小64B（0x40）。$0x20 \pmod{0x40} = 0x20 = 32$。所以`d[0]`在块内偏移32字节。
       - 缺失率：Cache块64B，每个元素4B，每块存16个元素。顺序访问，每16个元素缺失1次（首次访问该块时缺失）。
       - 总访问次数：2048次读 + 2048次写 = 4096次？或者题目仅问“访问d的Cache缺失率”，通常指内存访问引发的Cache缺失。`d[i] = d[i]/x`，先读`d[i]`，再写`d[i]`。
       - 读缺失：2048个元素，每16个缺失1次，共$2048/16 = 128$次读缺失。
       - 写缺失：写操作通常也检查Cache。如果采用Write-Back或Write-Through，写命中则更新Cache，写缺失则需调入块。由于是顺序访问，写`d[i]`时，`d[i]`所在的块通常已在Cache中（因为刚读过`d[i]`，且块大小覆盖16个元素，后续15个元素的读写都在同一块内）。因此，写操作通常命中（除非块被替换，但顺序访问不会替换刚调入的块）。
       - 总缺失次数：128次（仅读缺失，写命中）。
       - 总访问次数：4096次（2048读+2048写）。
       - 缺失率：$128 / 4096 = 3.125\%$。
       - 平均访问时间：$H \times T_h + M \times T_m$。$H = 1 - 0.03125 = 0.96875$。$T_{avg} = 0.96875 \times 2 + 0.03125 \times 200 = 1.9375 + 6.25 = 8.1875$周期。
    4. **Q4**: 
       - 数组大小：$2048 \times 4B = 8192B = 8KB$。
       - 页大小：4KB。
       - 起始地址：$0x01800020$。页内偏移$0x20$。
       - 第一页剩余空间：$4KB - 0x20 = 4096 - 32 = 4064B$。
       - 数组跨越页数：$8KB$数据，起始偏移32B。
       - 页1：存$4064B$（1016个元素）。
       - 页2：存$4096B$（1024个元素）。
       - 页3：存$4096 - 4064 - 4096$? 不对。总大小8KB。
       - 地址范围：$0x01800020$ 到 $0x01800020 + 8192 - 1 = 0x0180201F$。
       - 页边界：4KB对齐，即$0x1000$。
       - 页1：$0x01800000 - 0x01800FFF$。数组占用$0x01800020 - 0x01800FFF$。
       - 页2：$0x01801000 - 0x01801FFF$。数组占用全部。
       - 页3：$0x01802000 - 0x01802FFF$。数组占用$0x01802000 - 0x0180201F$。
       - 共3页。
       - 缺页次数：若d不在主存，首次访问每页缺页1次。共3次缺页。
