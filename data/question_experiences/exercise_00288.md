# 练习题 Q1 — 停等协议效率与传播延迟计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
一条链路的传输速率为 $10^6$ bit/s，使用大小为 1000 字节的数据分组。假设确认帧的传输延迟可以忽略不计，且其传播延迟与数据分组的传播延迟相同。同时假设节点处的处理延迟可忽略不计。在此配置下，停等协议的效率恰好为 25%。单向传播延迟（以 ms 为单位）的值是（ ）。
- 选项:
  A: 4
  B: 8
  C: 12
  D: 16
- 正确答案: C
- 解析（参考）: 在停等协议中，只有在接收到前一个分组的确认帧后才会发送下一个分组。这会导致链路利用率低下。
已知条件
：
传输速率
$R = 10^6$ bit/s
数据分组大小
$L = 1000$ 字节 $= 8000$ bit
效率
$\eta = 25\%$
计算步骤
：
传输时间
：
$T_{transmission} = \frac{L}{R} = \frac{8000}{10^6} = 0.008$ s $= 8$ ms
总时间开销
：
根据效率公式
$\eta = \frac{T_{transmission}}{T_{total}}$，得：
$T_{total} = \frac{T_{transmission}}{\eta} = \frac{8}{0.25} = 32$ ms
传播延迟计算
：
总时间 $T_{total}$ 包括数据帧传输时间、数据帧传播时间、确认帧传播时间（确认帧传输时间忽略）。
即 $T_{total} = T_{trans} + T_{prop} + T_{prop} = T_{trans} + 2T_{prop}$
$32 = 8 + 2T_{prop}$
$2T_{prop} = 24$
$T_{prop} = 12$ ms

- 知识标签: ['计算机网络/传输层']
- 知识域: CN-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆停等协议（Stop-and-Wait）的效率定义公式 $\eta = \frac{T_{trans}}{T_{total}}$ 以及总时间的构成要素。属于标准的核心概念记忆，不涉及易混概念的深度辨析，但必须准确知道“效率”在传输层的具体定义。
- **K2 = 3**: 评分理由。涉及单位换算（字节转比特，秒转毫秒）和简单的代数运算。虽然计算本身不复杂，但存在多级换算（Byte->bit, s->ms），若粗心容易出错，属于标准难度的计算。
- **K3 = 3**: 评分理由。解题过程需要串行推演：1. 计算传输时间；2. 利用效率反推总周期时间；3. 根据停等协议的时间轴模型，建立总时间与传播延迟的关系方程；4. 求解传播延迟。共3-4步逻辑推导，符合标准推演需求。
- **K4 = 4**: 评分理由。存在隐含前提和易错点。首先，必须意识到“确认帧传输延迟忽略”意味着 $T_{ack\_trans} \approx 0$；其次，必须明确停等协议的总周期 $T_{total}$ 包含“数据传播+确认传播”，即 $2 \times T_{prop}$，而非仅单向。很多学生会忘记乘以2，或者误以为总时间只包含数据帧的时间。这种对协议机制细节的隐含条件识别属于较高难度。
- **K5 = 1**: 评分理由。本题仅涉及传输层协议机制与物理层参数（速率、延迟）的直接计算，不涉及网络层路由、应用层语义或其他子系统的状态联动，属于单系统内部计算。
- **雷达形状**: K4陷阱型（K4显著高于K1/K2/K5，表明题目难点在于对协议机制隐含条件的准确理解，而非单纯计算或记忆）。

## 考察模式
- **模式**: 计算型
- **理由**: 题目给出了具体的数值参数，要求通过公式推导得出一个具体的数值结果。虽然涉及概念理解，但最终落脚点在于定量计算。

## 选项级分析
- **选项A (4)**: [干扰] — 针对“忘记乘以2”且“计算错误”或“混淆公式”的学生。如果学生错误地认为 $T_{total} = T_{trans} + T_{prop}$，则 $32 = 8 + T_{prop} \Rightarrow T_{prop} = 24$，这不是选项。如果学生误以为效率是 $\frac{T_{trans}}{T_{trans} + T_{prop}}$ 且算错，可能得到此值。更可能的情况是，学生计算出 $2T_{prop}=24$ 后，误以为题目问的是往返时间的一半或者其他错误逻辑，或者单纯计算失误。实际上，若学生误用公式 $\eta = \frac{T_{trans}}{T_{trans} + T_{prop}}$ (忽略ACK传播)，则 $0.25 = 8 / (8 + T_{prop}) \Rightarrow 8 + T_{prop} = 32 \Rightarrow T_{prop} = 24$，无此选项。若学生误以为 $T_{total} = 2 T_{trans} + 2 T_{prop}$ 等错误模型，可能凑出此数。此选项主要作为低分段的随机干扰或严重概念混淆项。
- **选项B (8)**: [干扰] — 针对“混淆传输时间与传播延迟”或“忽略ACK传播”的学生。如果学生计算出传输时间 $T_{trans} = 8$ ms，可能直接选B。或者，如果学生错误地认为 $T_{total} = T_{trans} + T_{prop}$ (忽略ACK)，且错误地认为 $T_{total} = 2 T_{trans}$ (效率50%?)，逻辑混乱。更常见的错误是：学生算出 $2T_{prop} = 24$，然后误以为 $T_{prop} = 8$ (计算错误 $24/3$?)。或者，学生误以为效率公式分母只有 $T_{trans} + T_{prop}$，且算出 $T_{prop}=24$，然后除以3？不太像。最可能的错误路径是：学生算出 $T_{trans}=8$，看到选项有8，直接凭直觉选择，或者误以为传播延迟等于传输延迟。
- **选项C (12)**: [正确] — 正确计算结果。$T_{trans}=8$ms, $T_{total}=32$ms, $2T_{prop} = 32-8=24$ms, $T_{prop}=12$ms。
- **选项D (16)**: [干扰] — 针对“忘记减去传输时间”或“公式理解偏差”的学生。如果学生认为 $T_{total} = 2 T_{prop}$ (完全忽略传输时间，这在高速链路近似中有时出现，但此处不可忽略)，则 $2 T_{prop} = 32 \Rightarrow T_{prop} = 16$。这是非常典型的错误，即忽略了数据帧本身的传输时间 $T_{trans}$ 在总周期中的占比，或者错误地认为总时间完全由传播延迟决定。

- **干扰策略**: 计算陷阱与概念混淆。选项B利用了传输时间的数值作为干扰；选项D利用了忽略 $T_{trans}$ 的近似思维或公式记忆偏差；选项A作为低概率干扰。

## 核心陷阱
- **核心陷阱**: **停等协议总周期时间的构成**。学生极易忘记确认帧（ACK）也需要传播时间，从而错误地建立方程 $T_{total} = T_{trans} + T_{prop}$，导致计算出 $T_{prop} = 24$ ms（虽无此选项，但逻辑错误一致）。或者，学生可能忽略数据帧的传输时间 $T_{trans}$，错误地认为 $T_{total} \approx 2 T_{prop}$，从而选出D。正确的模型必须是 $T_{total} = T_{trans} + T_{prop} + T_{prop}$ (因ACK传输时间忽略)。

## 考察能力
本题核心考察考生对**停等协议（Stop-and-Wait）时间轴模型**的深刻理解，特别是能够准确区分并组合**传输延迟**与**传播延迟**，并利用**链路利用率（效率）**公式进行逆向定量计算的能力。
