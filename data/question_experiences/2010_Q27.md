# 2010 Q27 — Peterson 算法互斥与饥饿性分析

## 基本信息
- **年份**: 2010  **题位**: Q27  **题型**: 选择题
- **知识点**: 软件互斥算法, Peterson 算法, 操作系统>软件互斥算法
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
进程 $P_0$ 和 $P_1$ 的共享变量定义及其初值为
```c
boolean flag[2];
int turn = 0;
flag[0] = FALSE;
flag[1] = FALSE;
```
若进程 $P_0$ 和 $P_1$ 访问临界资源的类 C 伪代码实现如下：
进程 P0
```c
void P0() {
    while (TRUE) {
        flag[0] = TRUE;
        turn = 1;
        while (flag[1] && (turn == 1));
        临界区；
        flag[0] = FALSE;
    }
}
```
进程 P1
```c
void P1() {
    while (TRUE) {
        flag[1] = TRUE;
        turn = 0;
        while (flag[0] && (turn == 0));
        临界区；
        flag[1] = FALSE;
    }
}
```
则并发执行进程 $P_0$ 和 $P_1$ 时产生的情形是（ ）。

- 选项:
  A: 不能保证进程互斥进入临界区，会出现“饥饿”现象
  B: 不能保证进程互斥进入临界区，不会出现“饥饿”现象
  C: 能保证进程互斥进入临界区，会出现“饥饿”现象
  D: 能保证进程互斥进入临界区，不会出现“饥饿”现象

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆并识别 Peterson 算法的标准代码结构。如果考生不记得该算法的具体实现细节（flag 和 turn 的配合），仅凭“软件互斥”这一宽泛概念无法解题，因此需要调用核心定义记忆。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行任何算术运算或单位换算。
- **K3 = 4**: 评分理由。需要多步串行推演。考生必须在脑海中模拟两个进程并发执行时的指令交错情况，特别是当两个进程同时设置 `flag` 为 TRUE 并竞争设置 `turn` 时，最后写入 `turn` 的进程会被阻塞，而先写入的进程能进入临界区。这种状态机的推演涉及多个中间状态（flag 设置、turn 覆盖、while 循环判断），步骤较多且需保持逻辑连贯。
- **K4 = 3**: 评分理由。存在常规注意点。考生需要理解 `turn` 变量的语义是“轮到谁”，以及 Peterson 算法中“礼让”机制的本质。陷阱在于误以为 `turn` 只是简单的轮转，或者误以为两个进程同时进入 while 循环会导致死锁（实际上不会，因为 turn 只能有一个值）。
- **K5 = 2**: 评分理由。主要涉及单系统内的进程同步机制。虽然涉及两个进程间的状态交互（通过共享变量），但这属于操作系统同步机制的标准范畴，不涉及跨子系统（如网络、文件系统、硬件中断等）的深度耦合。
- **雷达形状**: K3 推演主导型（K1 基础支撑，K3 较高，K4 中等，K2/K5 低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非直接考查概念定义的记忆（如“什么是 Peterson 算法”），而是给出具体的代码实现，要求考生通过逻辑推理分析其并发执行的行为特征（互斥性、有无饥饿）。考生需要理解代码背后的并发控制逻辑，推导出最终的系统行为。

## 选项级分析
- **选项 A**: [干扰] — 针对认为算法有缺陷的错误认知。这类学生可能认为软件互斥算法都不完美，或者误以为 `turn` 的赋值存在竞态条件导致互斥失败，同时担心无限等待导致饥饿。
- **选项 B**: [干扰] — 针对认为互斥失败但无饥饿的错误认知。这类学生可能意识到算法试图解决互斥，但怀疑其有效性，同时认为只要不互斥就不会有严格的“饥饿”（因为大家都能进，只是乱进）。
- **选项 C**: [干扰] — 针对认为互斥成功但存在饥饿的错误认知。这类学生可能正确识别了互斥性，但误解了 `turn` 的作用，认为 `turn` 会导致某个进程永远被阻塞（例如认为 `turn` 固定指向某一方），从而产生饥饿。这是对 Peterson 算法“公平性”理解的偏差。
- **选项 D**: [正确] — 正确理解 Peterson 算法。该算法通过 `flag` 表示进入意愿，通过 `turn` 解决冲突。当两个进程同时竞争时，`turn` 的最后赋值者将等待，前者进入。这保证了互斥性。同时，由于 `turn` 在每次进入前都会更新，且等待条件依赖于对方的 `flag`，一旦对方退出临界区（`flag` 变 FALSE），等待者即可进入，因此不会出现饥饿。

**干扰策略**: 概念混淆与机制误解。通过组合“互斥性”和“饥饿性”两个维度的真假，制造四个选项。主要干扰点在于考生对 Peterson 算法中 `turn` 变量在解决冲突和保证公平性方面的具体作用理解不深，容易将其与简单的轮转调度或存在死锁风险的算法混淆。

## 核心陷阱
- **核心陷阱**: 误判 Peterson 算法的公平性（饥饿性）。许多考生知道 Peterson 算法能保证互斥，但对其是否能避免饥饿存在疑虑，或者将其与某些可能导致饥饿的自旋锁实现混淆。实际上，Peterson 算法是满足“有限等待”条件的，即一个进程在请求进入临界区后，经过有限次其他进程进入临界区，它必然能进入，因此无饥饿。

## 考察能力
本题核心考察考生对经典软件互斥算法（Peterson 算法）代码实现的逻辑推演能力，以及对其互斥性和公平性（无饥饿）特性的深刻理解。
