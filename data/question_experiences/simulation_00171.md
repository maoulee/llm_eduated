# 模拟题 Q综合题 — TCP序号与确认号机制分析

## 基本信息
- **来源**: 模拟题  **题型**: 综合题
- **科目**: 计算机网络
- **知识点**: CN-5 > TCP协议 > 序号 seq, CN-5 > TCP协议 > 确认号 ack
- **难度**: 待评估

## 题干原文
（9 分）主机 A 向主机 B 连续发送了 3 个 TCP 报文段。第 1 个报文段的序号为 90，第 2 个报文段的序号为 120，第 3 个报文段的序号为 150。请回答：
(1) 第 1、2 个报文段携带了多少字节的数据？
(2) 主机 B 收到第 2 个报文段后，发回的确认中的确认号应该是多少？
(3) 如果主机 B 收到第 3 个报文段后，发回的确认中的确认号是 200，试问 A 发送的第 3 个报文段中的数据有多少字节？
(4) 如果第 2 个报文段丢失，而其他两个报文段正确到达了主机 B，那么主机 B 在第 3 个报文段到达后，发往主机 A 的确认报文中的确认号应该是多少？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 TCP 序号（seq）和确认号（ack）的核心定义，特别是“确认号表示期望收到的下一个字节的序号”这一关键概念。若混淆为“已收到的最后一个字节序号”则无法解题，属于标准的基础概念记忆需求。
- **K2 = 2**: 评分理由。计算过程仅为简单的整数减法（如 120-90=30），不涉及复杂的幂次运算或多级换算，计算难度较低，属于基础算术能力。
- **K3 = 2**: 评分理由。解题逻辑为单步或双步直接推导。例如第(1)问直接由相邻序号差值得出数据长度；第(2)问由接收到的最大连续序号直接得出 ack。无需多步串行推演或记忆复杂的中间状态。
- **K4 = 3**: 评分理由。存在常规注意点，即第(4)问考察 TCP 的累积确认机制（Cumulative ACK）。考生需意识到当中间报文段丢失时，接收方只能确认连续收到的最后一个字节，而非乱序到达的后续报文段。这是一个典型的“隐含前提”，若未掌握累积确认特性易出错。
- **K5 = 1**: 评分理由。本题完全局限于 TCP 传输层内部的序号与确认机制，不涉及 IP 层、应用层或其他子系统的状态传递或耦合，属于单系统内部逻辑。
- **雷达形状**: 偏向基础认知与条件识别的“矮胖型”或“均衡型”，无明显短板，但在跨域联动和复杂推演上得分较低，符合基础概念应用题的特征。

## 考察模式
- **模式**: 计算推导型
- **理由**: 题目通过给定的序号数值，要求考生利用 TCP 协议规则进行简单的数值计算和逻辑推导，得出数据长度和确认号。虽然涉及机制理解，但最终落脚点在于具体的数值结果。

## 解题思路分析
- **核心思路**: 紧扣 TCP 序号（seq）代表本报文段第一个数据字节的编号，确认号（ack）代表期望收到的下一个数据字节的编号。利用 `数据长度 = 下一个报文段 seq - 当前报文段 seq` 以及 `ack = 已正确接收的最后一个字节序号 + 1` 进行推导。
- **关键步骤**:
    1.  **计算数据长度**：利用相邻报文段的序号差值计算。第1段长度 = 120 - 90 = 30；第2段长度 = 150 - 120 = 30。
    2.  **确定正常情况下的 ack**：收到第2段后，已接收 90~149 字节，期望下一个是 150，故 ack=150。
    3.  **逆向推导数据长度**：已知第3段 seq=150，ack=200，说明接收方期望下一个是 200，即已收到 199。故第3段数据范围 150~199，长度 = 200 - 150 = 50。
    4.  **处理丢包情况**：第2段丢失，B 只收到第1段（90~119）。虽然第3段（150~...）到达，但由于 120~149 缺失，TCP 采用累积确认，B 只能确认连续收到的部分，即期望收到 120，故 ack=120。
- **易错点**:
    1.  误认为 ack 是“已收到的最后一个字节序号”，导致计算结果少 1。
    2.  在第(4)问中，误以为收到第3段后 ack 会更新为第3段的下一个序号，忽略了 TCP 的累积确认机制（Cumulative ACK），即只能确认连续字节流。

## 核心陷阱
- **核心陷阱**: **TCP 累积确认机制的理解偏差**。在第(4)问中，许多考生容易忽略“第2个报文段丢失”这一条件对确认号的影响，错误地认为只要收到报文段就会确认该报文段的后续序号。实际上，TCP 确认号始终指向**期望收到的下一个连续字节**，中间有缺失时，确认号不会跳过缺失部分，而是停留在缺失部分的起始位置（即重复确认）。

## 考察能力
本题核心考察考生对 TCP 字节流编号机制、序号与确认号定义的理解，以及在丢包场景下对 TCP 累积确认机制的应用能力。
