# 2023 Q25 — 位图法空间计算

## 基本信息
- **年份**: 2023  **题位**: Q25  **题型**: 选择题
- **知识点**: 位图法, 位图, 操作系统>位图法
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
某系统采用页式存储管理，用位图管理空闲页框。若页大小为 4 KB，物理内存大小为 16 GB，则位图所占空间的大小是（ ）。

A. 128 B
B. 128 KB
C. 512 KB
D. 4 MB

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“位图法”的核心定义，即每个页框对应位图中的1个bit。若不了解位图法的基本原理（1 bit per frame），无法入题。属于标准的基础概念记忆。
- **K2 = 3**: 评分理由。涉及多级单位换算（GB -> KB -> bits -> Bytes）。虽然都是2的幂次，但步骤包含：计算总页框数（除法）、确定总位数、转换为字节（除以8）、转换为KB。对于不熟练的学生，容易在 $2^{22}/8$ 或单位换算上出错，属于标准难度的计算。
- **K3 = 2**: 评分理由。逻辑链条清晰且短：物理内存大小/页大小 = 页框总数 -> 页框总数 = 位图位数 -> 位图位数/8 = 位图字节数。仅需2-3步串行推导，无复杂状态记忆。
- **K4 = 2**: 评分理由。存在常规注意点，即“位图是按位存储，而空间大小通常按字节计算”，需要考生意识到除以8的操作。没有深层隐含前提或反直觉陷阱，属于常规考点。
- **K5 = 1**: 评分理由。本题仅涉及操作系统内存管理中的静态数据结构计算，不涉及与其他子系统（如CPU调度、I/O、文件系统）的状态传递或耦合，属于单模块内部计算。
- **雷达形状**: K2计算主导型（K1/K2/K3均衡偏低，K4/K5极低）。整体难度较低，主要考察基础概念与单位换算的准确性。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的物理参数（内存大小、页大小），利用位图法的映射规则，进行数值计算得出最终的空间占用大小。虽然涉及概念，但解题过程以数学运算和单位换算为主。

## 选项级分析
- **选项A**: [干扰] — 针对**单位混淆**或**计算严重失误**。可能误以为位图大小等于页框数的某种极小值，或者完全搞错了数量级（如误算为 $2^7$ 字节）。这类学生可能对 $2^{22}$ 的数量级没有概念。
- **选项B**: [干扰] — 针对**忘记除以8**或**单位换算错误**。如果考生计算出位图有 $2^{22}$ 位，直接认为 $2^{22}$ 字节（即 4MB）是错的，但如果误以为 $2^{22}$ 位等于 $2^{17}$ KB（即 128KB），可能是计算 $2^{22}/8 = 2^{19}$ 字节后，错误地将 $2^{19}$ 字节当作 $2^{17}$ KB（少除以1024？不对，$2^{19}B = 2^{10}KB = 1024KB = 1MB$，等等，让我们重新检查B的干扰逻辑）。
    - 修正分析：$2^{22}$ 位。
    - 正确路径：$2^{22} / 8 = 2^{19}$ Bytes。$2^{19} B = 2^{19-10} KB = 2^9 KB = 512 KB$。
    - 选项B (128 KB) 的干扰逻辑：可能是考生算出 $2^{22}$ 位，然后错误地除以 64？或者在单位换算时，将 $2^{19}$ Bytes 错误换算。另一种可能是：考生误以为页框数是 $16GB / 4KB = 2^{22}$，然后误以为位图大小是 $2^{22} / 64$ Bytes? 不太像。
    - 更可能的干扰逻辑：考生计算出页框数为 $2^{22}$，然后误以为位图大小是 $2^{22}$ **Bits**，然后错误地转换为 KB。$2^{22}$ bits = $2^{19}$ Bytes = $2^9$ KB = 512 KB。
    - 让我们看选项B 128 KB = $2^7$ KB = $2^{17}$ Bytes = $2^{20}$ Bits。如果考生误算页框数为 $2^{20}$（例如误以为 16GB 是 $2^{32}$ 但页大小是 $2^{12}$，算成 $2^{20}$？不对，$32-12=20$。啊，16GB 是 $2^{34}$ 吗？$16 = 2^4$, $1GB = 2^{30}$, 所以 $16GB = 2^{34}$。$4KB = 2^{12}$。$34-12=22$。页框数 $2^{22}$。
    - 如果考生误以为 16GB = $2^{32}$ (1GB错误认知)，则页框数 $2^{20}$。位图 $2^{20}$ bits = $2^{17}$ Bytes = $2^7$ KB = 128 KB。**这是最可能的错误路径：对GB的位宽认知错误（认为1GB=$2^{30}$但16GB=$2^{32}$? 不，通常错误是认为1GB=$2^{10}MB$但记错指数，或者简单算错 $16/4=4$，然后 $4GB$ 的位图？不对）。**
    - 另一种可能：考生算出 $2^{22}$ 位，然后除以 8 得到 $2^{19}$ 字节，然后错误地认为 $2^{19}$ 字节 = 128 KB（误以为 $2^{19} = 2^7 \times 1024$? 即误以为 $19-10=7$? 不，$19-10=9$。如果考生误以为 $1KB=2^{12}$ Bytes? 不可能）。
    - 最合理的干扰：考生误算页框数。例如，误以为物理内存是 4GB ($2^{32}$)，则页框 $2^{20}$，位图 $2^{20}$ bits = $2^{17}$ Bytes = 128 KB。或者误以为页大小是 16KB?
    - 总结：选项B主要干扰那些**基础单位换算不熟练**或**对GB/KB指数记忆模糊**的学生。
- **选项C**: [正确] — 正确计算结果。$16GB / 4KB = 2^{22}$ 页框。位图 $2^{22}$ bits。$2^{22} / 8 = 2^{19}$ Bytes。$2^{19} / 1024 = 2^9$ KB = 512 KB。
- **选项D**: [干扰] — 针对**忘记除以8**（即混淆位与字节）。考生计算出位图有 $2^{22}$ 位，直接将其当作字节数，或者错误地认为 $2^{22}$ Bytes = 4 MB ($2^{22} B = 2^{12} KB = 2^2 MB = 4 MB$)。这是最常见的错误，即忽略了“位图是按位存储，而空间大小按字节计量”这一关键转换。

- **干扰策略**: 计算陷阱（单位换算遗漏、指数计算错误）。

## 核心陷阱
- **核心陷阱**: **位（bit）与字节（Byte）的转换**。考生容易计算出位图的总位数（$2^{22}$），但忘记除以8转换为字节，或者在从字节转换为KB时指数运算出错。此外，对 $16GB$ 和 $4KB$ 的2的幂次表示（$2^{34}$ 和 $2^{12}$）记忆不准也是潜在陷阱。

## 考察能力
本题核心考察考生对**位图法存储原理**的理解以及**计算机存储单位换算**的准确计算能力。
