# 练习题 Q1 — 递归遍历与链表指针操作

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/链表
- **难度**: 待评估

## 题干原文
当 start 指向以下链表的第一个节点 1→2→3→4→5→6 时，以下函数的输出是什么？（ ）
```c
void fun(struct node *start) {
    if (start == NULL) return;
    printf("%d ", start->data);
    if (start->next != NULL)
        fun(start->next->next);
    printf("%d ", start->data);
}
```
- 选项:
  A: 1 4 6 6 4 1
  B: 1 3 5 1 3 5
  C: 1 2 3 5
  D: 1 3 5 5 3 1
- 正确答案: D
- 解析（参考）: 函数执行流程分析：
前序遍历阶段
首次访问节点时打印数据：
1 → 3 → 5
通过
fun(start→next→next)
跳过相邻节点，形成间隔访问
回溯阶段
到达末尾节点5后，递归栈开始回退
每层递归返回时再次打印当前节点数据：
5 → 3 → 1
完整输出序列
前序遍历结果：
1 3 5
回溯遍历结果：
5 3 1
合并后总输出：
1 3 5 5 3 1
- 知识标签: ['数据结构/链表']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握链表的基本结构（next指针）、递归函数的基本执行流程（压栈与出栈）以及printf的执行时机。不是4分因为不涉及复杂的数据结构变体或晦涩的术语辨析，属于数据结构基础核心概念。
- **K2 = 2**: 评分理由。本题没有数值计算，只有指针的跳转逻辑。单步操作是“取当前节点数据”和“移动指针两步”，逻辑简单，不易出错。
- **K3 = 4**: 评分理由。从输入到输出需要多步串行推演。考生需要在脑海中模拟递归调用栈：1调用3，3调用5，5尝试调用NULL（失败），然后5返回打印，3返回打印，1返回打印。涉及3层递归深度及回溯过程，步骤超过3步且需记忆中间状态（当前在递归树的哪一层），故评为4。
- **K4 = 3**: 评分理由。存在常规注意点陷阱。主要陷阱在于`start->next->next`的边界判断。如果链表长度为偶数，最后一步`start->next`存在但`start->next->next`为NULL，此时递归终止条件`start==NULL`会在下一层触发，或者在本层`if`判断中拦截。本题中5的next是6，6的next是NULL。5调用fun(6->next)即fun(NULL)，直接return。关键在于识别递归终止的精确位置和回溯时的打印顺序。属于“陷阱词”或“隐含前提”级别，需细心。
- **K5 = 1**: 评分理由。单系统内部逻辑。仅涉及链表这一种数据结构内部的递归遍历，不涉及与其他子系统（如树、图、堆栈显式操作等）的状态传递或耦合。
- **雷达形状**: K3推演主导型，K4陷阱辅助。整体呈现中间高（推演复杂度高），两端低（基础记忆和跨域联动要求低）的特征。

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖公式计算，也不单纯考察概念定义，而是要求考生根据给定的代码逻辑，在脑海中构建执行流（递归栈帧的变化），推导出最终的输出序列。核心在于对程序执行过程的逻辑推理。

## 选项级分析
- **选项A**: [干扰] — 针对“步长理解错误”的认知。如果考生误以为步长是3（1->4->7...）或者混淆了索引，可能会得出1,4,6这样的序列。或者误以为递归是`next->next->next`。这类学生可能没有仔细看清`next->next`的含义。
- **选项B**: [干扰] — 针对“回溯逻辑缺失”的认知。考生正确识别了前序遍历的序列（1, 3, 5），但忽略了递归返回后的`printf`语句，或者误以为递归结束后程序直接退出，没有执行回溯部分的打印。这类学生只关注了“去”的过程，忽略了“回”的过程。
- **选项C**: [干扰] — 针对“递归逻辑完全误解”的认知。考生可能将其误认为是普通的迭代遍历，或者只看到了第一次打印，且步长误判为1（1,2,3...）但被截断，或者完全无法理解递归结构，随意猜测了一个看似合理的递增序列。
- **选项D**: [正确] — 正确模拟了递归过程：
    1. `fun(1)`: 打印1，调用`fun(3)`
    2. `fun(3)`: 打印3，调用`fun(5)`
    3. `fun(5)`: 打印5，调用`fun(NULL)` (因为5->next是6, 6->next是NULL)
    4. `fun(NULL)`: 返回
    5. `fun(5)`继续: 打印5，返回
    6. `fun(3)`继续: 打印3，返回
    7. `fun(1)`继续: 打印1，返回
    结果: 1 3 5 5 3 1

- **干扰策略**: 概念混淆（忽略回溯打印）与计算陷阱（步长判断错误）结合。

## 核心陷阱
- **核心陷阱**: **递归回溯时的二次打印**。许多考生容易只关注递归深入时的输出（1 3 5），而忽略函数体末尾的`printf`在递归返回时也会执行，导致漏掉后半部分的输出（5 3 1）。此外，需准确判断递归终止条件，特别是当链表节点数为偶数时，最后一个有效节点（5）的`next->next`为NULL，递归如何正确终止。

## 考察能力
本题核心考察考生对**递归函数执行流程（压栈与出栈）**的理解以及**链表指针操作**的细致模拟能力。
