# 2020 Q45 — 多前驱多后继的进程同步设计

## 基本信息
- **年份**: 2020  **题位**: Q45  **题型**: 综合题
- **知识点**: 同步问题设计, 操作系统>同步问题设计
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
现有 5 个操作 A、B、C、D 和 E，操作 C 必须在 A 和 B 完成后执行，操作 E 必须在 C 和 D 完成后执行，请使用信号量的 wait()、signal() 操作（P、V 操作）描述上述操作之间的同步关系，并说明所用信号量及其初值。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握信号量（Semaphore）的基本概念、P/V 操作的语义以及“同步”与“互斥”的区别。不是 2 分因为仅靠直觉无法正确设置初值和 P/V 位置，必须调用核心定义；不是 4 分因为不涉及复杂概念辨析，属于标准的基础知识应用。
- **K2 = 2**: 评分理由。本题不涉及数值计算，主要是逻辑映射。将“前驱关系”映射为“V 操作”，将“等待前驱”映射为“P 操作”，步骤简单直接，不易出错。
- **K3 = 3**: 评分理由。解题过程包含 3-4 个逻辑步骤：1. 分析依赖关系图（A->C, B->C, C->E, D->E）；2. 为每条依赖边分配信号量；3. 确定信号量初值（均为 0）；4. 在对应进程代码中插入 P/V 操作。属于标准的串行推演。
- **K4 = 2**: 评分理由。存在常规注意点，即“多前驱”需要多个 P 操作，“多后继”需要多个 V 操作。没有深层隐含前提或反直觉陷阱，只要理清依赖关系即可，属于常规注意点。
- **K5 = 1**: 评分理由。本题仅涉及操作系统进程同步单一子系统，不涉及文件系统、内存管理或网络等其他模块的状态传递，属于单系统内部逻辑。
- **雷达形状**: 偏向左侧的均衡型，K1 和 K3 略高，K2 和 K5 较低，整体难度适中，无极端高分项。

## 考察模式
- **模式**: 算法设计型
- **理由**: 题目要求考生根据给定的逻辑约束（先后顺序），设计出具体的代码结构（信号量定义及 P/V 操作位置），属于典型的基于规则的系统行为设计。

## 解题思路分析
- **核心思路**: 利用信号量实现进程间的同步。核心原则是：**前驱进程执行完毕后执行 V 操作（释放资源/发送信号），后继进程执行开始前执行 P 操作（等待资源/接收信号）**。对于“与”逻辑（如 C 需 A 和 B 都完成），需要多个信号量配合。
- **关键步骤**:
    1.  **绘制依赖图**：明确 A->C, B->C, C->E, D->E 四条有向边。
    2.  **定义信号量**：为每条边定义一个信号量，分别命名为 `S_AC`, `S_BC`, `S_CE`, `S_DE`。
    3.  **设置初值**：由于是同步关系，初始时前驱未完成，后继需等待，故所有信号量初值均为 0。
    4.  **编写代码**：
        -   在 A 的末尾 `V(S_AC)`，在 B 的末尾 `V(S_BC)`。
        -   在 C 的开头 `P(S_AC)` 和 `P(S_BC)`，在 C 的末尾 `V(S_CE)`。
        -   在 D 的末尾 `V(S_DE)`。
        -   在 E 的开头 `P(S_CE)` 和 `P(S_DE)`。
- **易错点**:
    1.  **信号量初值错误**：误将同步信号量初值设为 1（这是互斥信号量的常见初值）。
    2.  **P/V 位置颠倒**：在前驱进程中使用 P，在后继进程中使用 V。
    3.  **遗漏同步关系**：例如只处理了 A->C 而忽略了 B->C，导致 C 可能在 B 未完成时就执行。
    4.  **信号量命名混淆**：未清晰区分不同路径的信号量，导致逻辑混乱。

## 核心陷阱
- **核心陷阱**: **“多前驱”与“多后继”的信号量数量对应关系**。考生容易误以为一个进程只需要一个信号量，或者混淆了互斥锁（一个信号量）与同步信号量（依赖关系数 = 信号量数）的区别。本题中 C 有两个前驱，因此需要两个独立的信号量来分别等待 A 和 B 的完成；E 有两个前驱，同样需要两个信号量。

## 考察能力
本题核心考察考生将**进程间的逻辑依赖关系转化为信号量 P/V 操作代码**的能力，以及对**同步机制中“前驱-后继”语义**的深刻理解。
