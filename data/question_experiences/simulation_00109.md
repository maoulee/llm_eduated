# 模拟题 Q1 — 临界区算法互斥性与饥饿性分析

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: OS-2 > 2.3 进程同步 > 临界区, OS-2 > 2.3 进程同步 > 互斥, OS-2 > 2.3 进程同步 > 同步与互斥基本概念
- **难度**: 待评估

## 题干原文
关于临界区问题（critical section problem）的一个算法（假设只有进程 P0 和 P1 可能会进入该临界区）如下（i 为 0 或 1），该算法（ ）。
Repeat
retry: if(turn!=i) turn=i;
if(turn!=i) goto retry;
turn=1-i;
临界区
turn=0;
剩余区
until false;

A. 不能保证进程互斥进入临界区，且会出现“饥饿”
B. 不能保证进程互斥进入临界区，但不会出现“饥饿”
C. 保证进程互斥进入临界区，但会出现“饥饿”
D. 保证进程互斥进入临界区，不会出现“饥饿”

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握临界区问题的三个基本准则（互斥、有限等待/无饥饿、空闲让进）以及进程同步的基本概念。不是4分因为不需要辨析多个复杂的同步原语（如信号量、管程等），仅需理解基本的互斥定义。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行算术运算或单位换算。
- **K3 = 4**: 评分理由。需要在明确规则下多步串行推演。考生必须模拟 P0 和 P1 两个进程在并发执行时的指令交错情况，特别是共享变量 `turn` 的状态变化。从初始状态到发现互斥失效，需要追踪至少 3-5 步的状态变迁，且需记忆中间状态（如 `turn` 被谁修改了），符合 >5步或需记忆中间状态的特征。
- **K4 = 4**: 评分理由。存在隐含前提和反直觉陷阱。题面给出的算法看似有“重试”机制（goto retry），容易让人误以为它能保证互斥（类似 Peterson 算法的变体）。考生必须意识到 `turn` 变量的非原子性操作以及缺乏“标志位（flag）”来声明进入意愿，这是解题必须意识到的深层隐含前提。常规注意点不足以避开此陷阱，属于陷阱词/隐含前提深。
- **K5 = 2**: 评分理由。主要涉及单系统（进程同步）内的状态传递。虽然涉及两个进程 P0 和 P1 通过共享变量 `turn` 进行通信，但这属于进程同步的标准模型，未跨越不同的子系统（如内存管理、文件系统等），提及无关则2，单向传数据则3，此处为简单的状态互影响，但耦合度不高，故评为2。

- **雷达形状**: K3-K4 双高型（推理与陷阱主导）

## 考察模式
- **模式**: 推理型
- **理由**: 本题无法通过直接记忆公式或概念定义得出答案，必须通过逻辑推演，模拟并发执行场景，分析算法在特定执行序列下的行为，从而判断其是否满足互斥和无饥饿条件。

## 选项级分析
- **选项A**: [干扰] — 针对认为“算法既不能互斥又会饥饿”的错误认知。这类学生可能认为既然互斥都做不到，那么调度也是混乱的，从而导致饥饿。实际上，由于每个进程都能通过修改 `turn` 获得进入机会，不存在永远被阻塞的情况。
- **选项B**: [正确] — 正确分析了算法的两个特性：不能保证互斥（因为缺乏有效的进入意愿声明，仅靠 `turn` 无法阻止对方进入），但不会出现饥饿（因为 `turn` 的赋值操作允许进程主动获取进入权，且没有复杂的等待队列导致死锁或活锁）。
- **选项C**: [干扰] — 针对认为“算法能保证互斥但会饥饿”的错误认知。这类学生可能被 `goto retry` 迷惑，认为这是一种忙等待的互斥机制，同时可能错误地认为这种简单的轮转会导致某个进程被跳过。
- **选项D**: [干扰] — 针对认为“算法完美”的错误认知。这类学生可能将算法与 Peterson 算法或 Dekker 算法混淆，误以为这是正确的临界区解决方案。

- **干扰策略**: 概念混淆（与正确算法混淆）+ 渐进陷阱（看似有重试机制，实则逻辑缺陷）

## 核心陷阱
- **核心陷阱**: **误判互斥性**。考生容易看到 `if(turn!=i) goto retry;` 这一行，认为这是一个“检查-设置”的互斥锁机制。然而，关键在于进入临界区前的检查逻辑 `if(turn!=i) turn=i;` 和 `if(turn!=i) goto retry;` 之间没有原子性保证，且没有使用 `flag` 数组来声明“我想进入”。当 P0 和 P1 同时执行时，它们可以互相覆盖 `turn` 的值，导致双方都认为自己获得了进入权（`turn` 最终等于对方的 ID，但检查逻辑有误或执行交错导致双方都通过了检查）。具体来说，参考解析指出 P0 和 P1 可以同时进入，这是因为算法缺乏对“进入意愿”的持久化声明，仅靠 `turn` 无法实现互斥。

## 考察能力
一句话概括本题核心考察的能力：能够通过对并发执行序列的逻辑推演，分析临界区算法是否满足互斥性和有限等待性。
