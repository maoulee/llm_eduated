# 练习题 Q1 — 死锁避免与资源有序分配

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/死锁
- **难度**: 待评估

## 题干原文
三个并发进程 X、Y 和 Z 分别执行访问和更新某些共享变量的不同代码段。进程 X 在进入代码段前对信号量 a、b 和 c 执行 P 操作（即 wait）；进程 Y 对信号量 b、c 和 d 执行 P 操作；进程 Z 对信号量 c、d 和 a 执行 P 操作。每个进程完成代码段的执行后，会对其三个信号量执行 V 操作（即 signal）。所有信号量均为二进制信号量，初始值为 1。以下哪一项表示进程调用 P 操作的无死锁顺序？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握死锁产生的四个必要条件（特别是循环等待）以及信号量 P/V 操作的基本语义。属于标准的基础概念记忆，不涉及复杂公式或易混概念的深度辨析。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需进行幂次运算或多级换算，仅涉及逻辑状态的判断。
- **K3 = 4**: 评分理由。需要在明确规则下多步串行推演。考生必须对每个选项中的进程执行顺序进行模拟，检查是否存在“持有资源并等待其他资源”的情况，进而判断是否形成环路。这需要构建资源分配图或在脑海中模拟状态机，步骤较多且需保持中间状态清晰。
- **K4 = 4**: 评分理由。存在隐含前提和反直觉陷阱。题干未直接给出“资源有序分配法”这一理论，考生需意识到“只要所有进程按同一顺序申请资源，就不会产生循环等待”。同时，选项中的干扰项往往看似合理（如局部有序），但全局存在环路，需要识别这种隐含的逻辑漏洞。
- **K5 = 2**: 评分理由。主要涉及操作系统内部的进程同步与互斥机制，属于单系统内的状态传递，不涉及跨子系统（如文件系统、网络）的深度耦合。

- **雷达形状**: K3/K4 高推演型（逻辑推理与陷阱识别为主）

## 考察模式
- **模式**: 推理型
- **理由**: 题目不要求记忆特定结论，而是要求考生根据死锁产生的条件（循环等待），通过逻辑推理排除可能导致死锁的资源申请顺序，验证哪种顺序能打破循环等待条件。

## 选项级分析
- **选项 A**: [干扰] — 针对“局部有序但全局无序”的错误认知。X(a,b,c), Y(b,c,d), Z(c,d,a)。若 X 持有 a，Y 持有 b，Z 持有 c,d，则 X 等 b，Y 等 c，Z 等 a，形成 a->b->c->a 的循环等待。这类学生可能只检查了相邻进程，忽略了全局环路。
- **选项 B**: [正确] — 唯一无死锁方案。X(b,a,c), Y(b,c,d), Z(a,c,d)。虽然顺序看似杂乱，但关键在于是否存在环路。让我们仔细检查：
    - 实际上，更简单的判断方法是看是否所有进程都遵循某种全局偏序。
    - 让我们重新审视选项 B 的顺序：
        - X: P(b) -> P(a) -> P(c)
        - Y: P(b) -> P(c) -> P(d)
        - Z: P(a) -> P(c) -> P(d)
    - 这里并没有严格的全局统一顺序（如 a<b<c<d）。但是，我们需要检查是否存在循环等待。
    - 假设发生死锁，必须存在环路。
    - 观察资源依赖：
        - X 需要 b, a, c
        - Y 需要 b, c, d
        - Z 需要 a, c, d
    - 如果 X 先运行，它先拿 b。Y 也想拿 b，阻塞。Z 拿 a。
    - 关键在于：是否存在一种调度使得大家互相等待？
    - 让我们看参考解析的逻辑：参考解析认为 B 是无死锁的。通常这类题目考察的是**资源有序分配法**（Resource Ordering）。如果所有进程都按照资源编号从小到大（或从大到小）申请，则不会死锁。
    - 让我们检查选项 B 是否隐含了某种顺序？
        - X: b, a, c (假设 a<b<c<d? 不一定)
        - 实际上，这道题的正确答案 B 的解析在参考中给出的理由是“完成顺序为 Z->X->Y”，这暗示了存在一种可行的执行序列。
        - 更严谨的分析：死锁的必要条件是循环等待。
        - 在 B 中：
            - X 申请顺序: b -> a -> c
            - Y 申请顺序: b -> c -> d
            - Z 申请顺序: a -> c -> d
        - 让我们尝试构建环路：
            - 假设 X 持有 b，等待 a。
            - 谁持有 a？Z 可能持有 a（Z 先申请 a）。如果 Z 持有 a，Z 接下来申请 c。
            - 谁持有 c？X 还没拿到 c，Y 还没拿到 c。
            - 如果 Z 持有 a，等待 c。
            - 如果 Y 持有 b（与 X 冲突，二进制信号量，Y 阻塞在 b），或者 Y 没拿到 b。
            - 让我们看一个具体的死锁场景尝试：
                1. X 执行 P(b)，成功。持有 b。
                2. Z 执行 P(a)，成功。持有 a。
                3. Y 执行 P(b)，失败（X 持有）。Y 阻塞。
                4. X 执行 P(a)，失败（Z 持有）。X 阻塞。
                5. Z 执行 P(c)，成功。持有 a, c。
                6. Z 执行 P(d)，成功。持有 a, c, d。
                7. Z 执行 V(a), V(c), V(d)。释放所有资源。
                8. X 获得 a，继续执行 P(c)（此时 c 已释放），成功。X 持有 b, a, c。
                9. X 执行 V... 释放。
                10. Y 获得 b，继续...
            - 在这个序列中，没有死锁。
            - 是否存在其他序列导致死锁？
                - 死锁需要：X 持 b 等 a；Z 持 a 等 c；Y 持 c 等 b？
                - Y 的申请顺序是 b->c->d。Y 必须先拿到 b 才能申请 c。
                - 所以 Y 不可能“持有 c 等待 b”。Y 必须持有 b 才能去申请 c。
                - 因此，Y 永远不可能成为“持有 c 等待 b”的环节。
                - 同理，X 必须持有 b 才能申请 a。X 不可能“持有 a 等待 b”。
                - Z 必须持有 a 才能申请 c。Z 不可能“持有 c 等待 a”。
                - 让我们检查可能的环路方向：
                    - b -> a -> c -> b ?
                    - X: 持 b 等 a。
                    - Z: 持 a 等 c。
                    - 谁持 c 等 b？
                    - Y 申请顺序 b->c->d。Y 必须先拿 b。如果 Y 没拿到 b，它不会持有 c。
                    - X 申请顺序 b->a->c。X 必须先拿 b。如果 X 没拿到 b，它不会持有 c。
                    - Z 申请顺序 a->c->d。Z 不依赖 b。Z 可以持有 c。但 Z 下一步申请 d，不申请 b。
                    - 所以，没有任何进程在持有 c 的同时等待 b。
                    - 因此，环路 b->a->c->b 无法闭合。
                    - 其他环路？
                    - a -> c -> d -> a ?
                    - Z: 持 a 等 c。
                    - 谁持 c 等 d？Y (b->c->d) 或 Z (a->c->d)。
                    - 如果 Y 持 c 等 d，Y 必须先持 b。
                    - 如果 Z 持 c 等 d，Z 必须先持 a。
                    - 谁持 d 等 a？
                    - 没有进程在持有 d 后申请 a。X 申请 a 在 b 之后，c 之前，不涉及 d。Y 申请 d 最后。Z 申请 d 最后。
                    - 所以 d 是终点，不会形成包含 d 的环路。
                    - 结论：选项 B 中，由于 Y 和 X 都依赖 b 作为第一个资源，而 Z 不依赖 b，且没有进程在持有后续资源时回头申请 b 或 a（除了 X 申请 a，但 X 已持 b），结构上打破了循环等待的可能性。具体来说，**Y 和 X 都先申请 b**，这意味着 b 是瓶颈。一旦 b 被占用，其他想申请 b 的进程阻塞，不会持有其他资源去等待 b。而 Z 不申请 b，Z 可以顺利执行完或阻塞在 a/c/d，但不会形成涉及 b 的环路。

- **选项 C**: [干扰] — 针对“忽视申请顺序依赖性”的错误认知。X(b,a,c), Y(c,b,d), Z(a,c,d)。
    - 场景：X 持 b，等 a。Z 持 a，等 c。Y 持 c，等 b。
    - 检查可行性：
        - X: P(b) 成功。
        - Z: P(a) 成功。
        - Y: P(c) 成功。
        - X: P(a) 失败（Z 持）。
        - Z: P(c) 失败（Y 持）。
        - Y: P(b) 失败（X 持）。
    - 形成 X->a<-Z->c<-Y->b<-X 的循环等待。死锁。

- **选项 D**: [干扰] — 针对“局部有序”的错觉。X(a,b,c), Y(c,b,d), Z(c,d,a)。
    - 场景：X 持 a,b，等 c。Y 持 c，等 b。Z 持 c? 不，Z 先 P(c)。
    - 让我们构造死锁：
        - X: P(a), P(b) 成功。
        - Y: P(c) 成功。
        - Z: P(c) 失败（Y 持）。
        - X: P(c) 失败（Y 持）。
        - Y: P(b) 失败（X 持）。
        - 此时：X 持 a,b 等 c；Y 持 c 等 b。
        - Z 在等 c。
        - 这里 X 和 Y 已经死锁（X 等 Y 的 c，Y 等 X 的 b）。Z 只是旁观者。
    - 形成 X->c<-Y->b<-X 的循环等待。死锁。

- **干扰策略**: 渐进陷阱。选项 A、C、D 都精心设计了能够形成“循环等待”的资源申请顺序，特别是利用了二进制信号量“一次只能一个进程持有”的特性，让考生容易忽略“谁先拿到资源”对后续阻塞状态的影响，从而误以为只要资源不同就不会死锁，或者误以为局部有序即可。

## 核心陷阱
- **核心陷阱**: **循环等待条件的隐蔽性**。考生容易只关注资源是否重复，而忽略了进程申请资源的**顺序**决定了依赖图的方向。只有当依赖图形成闭环时才会死锁。选项 B 通过让多个进程竞争同一个“入口”资源（b），使得其他进程在获得后续资源前就被阻塞，从而物理上切断了形成闭环的路径（即没有进程能在持有“下游”资源的同时等待“上游”资源 b）。

## 考察能力
本题核心考察考生对**死锁产生条件（特别是循环等待）**的理解，以及通过**构建资源分配图**或**模拟进程执行序列**来验证系统安全性的逻辑推理能力。
