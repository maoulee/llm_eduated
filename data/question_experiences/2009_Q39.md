# 2009 Q39 — TCP拥塞控制机制推演

## 基本信息
- **年份**: 2009  **题位**: Q39  **题型**: 选择题
- **知识点**: CN-5 > TCP协议 > TCP拥塞控制
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
一个 TCP 连接总是以 1KB 的最大段长发送 TCP 段，发送方有足够多的数据要发送。当拥塞窗口为 16KB 时发生了超时，如果接下来的 4 个 RTT（往返时间）时间内的 TCP 段的传输都是成功的，那么当第 4 个 RTT 时间内发送的所有 TCP 段都得到肯定应答时，拥塞窗口大小是（）。

A. 7 KB
B. 8 KB
C. 9 KB
D. 16 KB

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 TCP 拥塞控制的核心概念，包括“慢开始”、“拥塞避免”、“超时处理”以及 `ssthresh`（慢开始门限）和 `cwnd`（拥塞窗口）的定义。若仅知道有拥塞控制但不知具体算法细节，无法解题。
- **K2 = 2**: 评分理由。计算过程非常友好，主要涉及 2 的幂次运算（1, 2, 4, 8）和简单的加法（8+1=9）。没有复杂的单位换算或非整数运算，计算错误率极低。
- **K3 = 4**: 评分理由。这是本题的核心难度所在。考生需要在脑海中模拟 4 个 RTT 的状态变迁：
    1. 初始状态重置（超时触发）；
    2. RTT 1：慢开始，cwnd 翻倍；
    3. RTT 2：慢开始，cwnd 翻倍；
    4. RTT 3：慢开始，cwnd 翻倍，此时触及 ssthresh，需判断是否切换算法；
    5. RTT 4：进入拥塞避免，cwnd 线性增加。
    这是一个典型的多步串行推演，且中间涉及算法切换的判断，步骤超过 3 步且需记忆中间状态（ssthresh 的值），故评为 4。
- **K4 = 4**: 评分理由。存在明显的“暗坑”和隐含前提。
    1. **隐含前提**：题目未明确说明“第 4 个 RTT 内发送的所有段都得到肯定应答”意味着该 RTT 结束时的状态更新。考生必须理解 TCP 拥塞窗口是在收到 ACK 后更新的，且“第 4 个 RTT 结束后”指的是第 4 轮传输完成并收到 ACK 后的瞬间状态。
    2. **机制切换点**：关键在于判断在第 3 个 RTT 结束时，cwnd 达到 8KB，等于 ssthresh。此时是继续慢开始还是进入拥塞避免？根据标准 TCP 算法，当 cwnd >= ssthresh 时进入拥塞避免。很多考生会误以为在 cwnd < ssthresh 时才慢开始，或者在 cwnd == ssthresh 时仍执行慢开始（导致第 4 轮变成 16KB），这是主要的陷阱。
- **K5 = 1**: 评分理由。本题完全局限于 TCP 传输层的拥塞控制子系统内部，不涉及 IP 层、应用层或其他网络子系统的状态传递或耦合。

- **雷达形状**: K3/K4 双高型（机制推演与条件路由主导，计算简单，概念基础）

## 考察模式
- **模式**: 推理型
- **理由**: 虽然包含简单的数值计算，但解题的关键不在于算术，而在于对 TCP 拥塞控制算法状态机（State Machine）的逻辑推演。考生必须根据“超时”这一事件触发状态重置，并根据每个 RTT 的反馈（ACK）逐步推导窗口的变化，特别是识别算法从“慢开始”切换到“拥塞避免”的临界点。

## 选项级分析
- **选项 A (7 KB)**: [干扰] — 针对对“拥塞避免”算法理解错误的学生。可能认为拥塞避免是每次增加 1 MSS，但起始点算错，或者误以为超时后 ssthresh 设置错误，导致推演路径偏差。例如，若误以为第 3 个 RTT 就进入了拥塞避免（cwnd=4->5->6->7），则会选此选项。
- **选项 B (8 KB)**: [干扰] — 针对混淆“慢开始”与“拥塞避免”切换时机的学生。如果学生认为当 cwnd 达到 ssthresh (8KB) 时，下一个 RTT 仍然执行慢开始（即 8->16），或者认为在第 3 个 RTT 结束时 cwnd 为 8KB 且不再增加，可能会选此项。更常见的是，学生可能正确推演出前 3 个 RTT 为 1->2->4->8，但误以为第 4 个 RTT 因为达到了 ssthresh 所以保持 8KB 不变，或者误以为第 4 个 RTT 开始执行拥塞避免但只增加了 0（误解加法增大）。
- **选项 C (9 KB)**: [正确] — 正确执行了超时重置（cwnd=1, ssthresh=8），前 3 个 RTT 慢开始（1->2->4->8），第 4 个 RTT 因 cwnd(8) >= ssthresh(8) 进入拥塞避免，执行加法增大（8+1=9）。
- **选项 D (16 KB)**: [干扰] — 针对完全忽略拥塞控制机制或误以为“超时”不影响后续增长的学生。或者学生误以为第 4 个 RTT 仍然处于慢开始阶段（8->16），忽略了 ssthresh 的限制。这是最常见的错误，源于对“慢开始”指数增长无上限的误解，或者忘记了 ssthresh 的作用。

- **干扰策略**: 概念混淆（慢开始 vs 拥塞避免的切换条件）与 计算陷阱（忽略 ssthresh 导致的指数增长延续）

## 核心陷阱
**算法切换的临界点判断**：当拥塞窗口 `cwnd` 增长到等于慢开始门限 `ssthresh` 时，下一个 RTT 是继续执行“慢开始”（指数增长）还是切换到“拥塞避免”（线性增长）？
*   **正确逻辑**：当 `cwnd >= ssthresh` 时，进入拥塞避免。在本题中，第 3 个 RTT 结束时 `cwnd` 变为 8KB，此时 `cwnd == ssthresh` (8KB)。因此，第 4 个 RTT 必须执行拥塞避免算法，即 `cwnd` 增加 1 MSS (1KB)，结果为 9KB。
*   **常见错误**：认为只有 `cwnd > ssthresh` 才切换，或者认为在 `cwnd == ssthresh` 时仍可享受一次慢开始翻倍（导致误选 16KB）。

## 考察能力
本题核心考察考生对 TCP 拥塞控制算法中“慢开始”与“拥塞避免”两种机制的切换条件及窗口变化规律的动态推演能力。
