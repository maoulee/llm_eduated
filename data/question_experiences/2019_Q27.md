# 2019 Q27 — 多级反馈队列调度与等待时间计算

## 基本信息
- **年份**: 2019  **题位**: Q27  **题型**: 选择题
- **知识点**: 处理机调度算法, 多级反馈队列, 操作系统>处理机调度算法
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
系统采用二级反馈队列调度算法进行进程调度。就绪队列 Q1 采用时间片轮转调度算法，时间片为 10ms；就绪队列 Q2 采用短进程优先调度算法；系统优先调度 Q1 队列中的进程，当 Q1 为空时系统才会调度 Q2 中的进程；新创建的进程首先进入 Q1;Q1 中的进程执行一个时间片后，若未结束，则转入 Q2。若当前 Q1，Q2 为空，系统依次创建进程 P1，P2 后即开始进程调度，P1,P2 需要的 CPU 时间分别为 30ms 和 20ms，则进程 P1，P2 在系统中的平均等待时间为（ ）。

A. 25ms
B. 20ms
C. 15ms
D. 10ms

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握多级反馈队列（MFQ）的基本定义、时间片轮转（RR）和短进程优先（SPF/SJF）的调度规则。属于标准的核心概念记忆，不涉及极度生僻的定义辨析。
- **K2 = 2**: 评分理由。计算过程仅涉及简单的加减法和除法（(20+10)/2），数值均为整数且无复杂换算，计算难度较低。
- **K3 = 4**: 评分理由。推演步骤较多且状态变化复杂。需要模拟：P1进入Q1 -> P1执行10ms -> P1降级至Q2 -> P2进入Q1 -> P2执行10ms -> P2降级至Q2 -> Q1空，检查Q2 -> Q2中P2剩余10ms，P1剩余20ms -> SPF规则选P2 -> P2执行完 -> P1执行完。全程需跟踪两个队列的状态、进程的剩余时间及位置转移，步骤超过5步且需记忆中间状态。
- **K4 = 4**: 评分理由。存在明显的隐含前提和机制切换陷阱。陷阱1：“依次创建”意味着P1先于P2进入系统，P1先获得CPU；陷阱2：Q1为空时才调度Q2，这意味着P1和P2必须先在Q1各跑一个时间片，不能直接在Q2比较；陷阱3：降级后的优先级判定依据是“剩余时间”而非“总时间”，且Q2内部遵循SPF。这些条件若未完全识别，极易出错。
- **K5 = 3**: 评分理由。涉及两个子系统（Q1和Q2）之间的状态传递。进程从Q1移动到Q2，状态（剩余时间）随之改变，并在Q2中根据新规则重新排序。属于单向传数据并触发新规则的场景。
- **雷达形状**: K3/K4 高推演陷阱型。本题难点不在于计算或概念背诵，而在于对调度流程的精确模拟和对隐含规则（如降级时机、队列优先级、SPF判定依据）的敏锐捕捉。

## 考察模式
- **模式**: 综合型
- **理由**: 本题结合了概念理解（MFQ结构）、规则应用（RR和SPF的具体行为）以及流程模拟（多步状态推演）。它不是单纯的概念辨析，也不是简单的公式代入，而是要求考生在动态变化的系统状态下，严格按照规则一步步推导出最终结果。

## 选项级分析
- **选项A**: [干扰] — 针对“忽略Q1时间片消耗”或“错误计算P1等待时间”的错误认知。如果学生认为P1在Q2中等待的时间是从P2开始执行算起，但错误地认为P1在Q1中执行的时间不算等待，或者混淆了周转时间和等待时间的定义，可能会得出较大数值。例如，若误以为P1等待了P2的全部20ms加上Q1的10ms等错误逻辑组合。
- **选项B**: [干扰] — 针对“忽略Q2内部SPF规则”或“认为P1先入Q2则P1先执行”的错误认知。如果学生认为P1先降级到Q2，所以P1在Q2中排在P2前面，那么P1将连续执行20ms，P2等待10ms。此时P1等待时间=10(Q1中P2的时间片)+0(Q2中P1先跑)=10ms? 不对，若P1在Q2先跑，P1等待时间仅为在Q1中等待P2的时间片10ms（假设P2在Q1执行时P1在Q2等待？不，P1在Q1执行时P2在Q1等待）。
    - 让我们重新推导错误路径B：若学生认为Q2中P1先执行（因为P1先到Q2）。
    - P1在Q1执行10ms，P2在Q1等待10ms。
    - P1降级Q2，P2进入Q1执行10ms，P1在Q2等待10ms。
    - Q1空，Q2中P1(剩20)和P2(剩10)。若错误认为P1先执行：P1执行20ms，P2在Q2等待20ms。
    - P1总等待 = 10 (在Q1等P2? 不，P1先跑，P1在Q1没等待) + 10 (在Q2等P2跑Q1) = 10ms。
    - P2总等待 = 10 (在Q1等P1) + 20 (在Q2等P1) = 30ms。
    - 平均 = (10+30)/2 = 20ms。这正是选项B。这是典型的“忽略SPF规则，按FIFO处理Q2”的陷阱。
- **选项C**: [正确] — 正确模拟了全过程。
    - P1等待：在Q1中P2执行10ms时等待 + 在Q2中P2执行10ms时等待 = 20ms。
    - P2等待：在Q1中P1执行10ms时等待 = 10ms。
    - 平均 = (20+10)/2 = 15ms。
- **选项D**: [干扰] — 针对“完全忽略Q1阶段”或“仅计算Q2阶段”的错误认知。如果学生只看到Q2中P2比P1短，直接算P2先跑，P1等待10ms，P2等待0ms，平均5ms？不对。可能是计算错误，或者认为P1在Q1执行的10ms不算等待，且P2在Q1执行的10ms也不算等待（错误理解等待时间定义），仅计算Q2中的等待？若仅算Q2：P2先跑，P1等10ms，P2等0ms，平均5ms。选项D是10ms，可能是另一种错误：认为P1等待10ms（Q2中），P2等待10ms（Q1中），平均10ms？这忽略了P1在Q2中还要等P2跑完Q1的时间片吗？不，P1在Q2等待的是P2在Q2执行的时间。
    - 另一种可能：学生误以为P1和P2在Q1并行？不可能。
    - 或者：学生认为P1等待时间 = P2的总执行时间20ms？P2等待时间 = P1的总执行时间30ms？平均25ms（选项A）。
    - 选项D 10ms 可能是：P1等待10ms（仅Q2中P2的时间），P2等待10ms（仅Q1中P1的时间），平均10ms。这忽略了P1在Q2中等待P2从Q1降级下来的过程？不，P1在Q2等待的是P2在Q2执行的时间。P2在Q2执行10ms。P1在Q2等待10ms。P2在Q1等待10ms。P1在Q1等待0ms。总等待 P1=10, P2=10, 平均10。这个错误在于：忽略了P1在Q2中还需要等待P2在Q1中执行的时间片吗？
    - 让我们仔细看时间轴：
        - 0-10ms: P1在Q1执行。P2在Q1等待。
        - 10-20ms: P2在Q1执行。P1在Q2等待。
        - 20-30ms: P2在Q2执行（SPF）。P1在Q2等待。
        - 30-50ms: P1在Q2执行。
    - P1等待时间：10-20ms (10ms) + 20-30ms (10ms) = 20ms。
    - P2等待时间：0-10ms (10ms) = 10ms。
    - 如果学生错误地认为P1在Q2中不需要等待P2在Q1执行的时间（即认为P1降级后Q2立即调度，或者P2在Q1执行时P1不在Q2等待？），或者错误地认为P2在Q2执行时P1已经结束了？
    - 最可能的D选项错误来源：只计算了“直接等待”，忽略了间接等待。或者误以为P1在Q1执行时P2还没创建？题干说“依次创建...后即开始”，通常理解为P1创建，P2创建，然后调度。P1先入队。
    - 还有一种可能：学生认为平均等待时间 = (P1剩余 + P2剩余)/2 ? 无意义。
    - 实际上，D选项 10ms 很可能是将 P1 的等待时间算错为 10ms（只算了Q2中P2执行的时间，忘了P1在Q2中还要等P2从Q1过来的那10ms？不，P1在Q2等待的是P2在Q2执行的时间。P2在Q2执行10ms。P1在Q2等待10ms。P1在Q1等待0ms。总共10ms？不对，P1在10-20ms期间在Q2等待，这是10ms。在20-30ms期间在Q2等待，这是10ms。总共20ms。如果学生只算了20-30ms这10ms，那就是10ms。为什么只算这段？可能认为10-20ms P1在Q1？不，P1已降级。可能认为10-20ms P1在阻塞？错误。
    - 总之，D是计算严重失误或概念混淆的结果。

- **干扰策略**: 概念混淆（Q2内部调度规则）、流程模拟遗漏（忽略Q1到Q2的过渡等待）、计算陷阱（等待时间定义不清）。

## 核心陷阱
**Q2队列内部的调度规则与降级时机的结合**。
1. **降级时机**：进程必须在Q1执行完一个时间片后**立即**降级，而不是等Q1空了再降级。
2. **Q2调度规则**：Q2采用短进程优先（SPF），比较的是**剩余CPU时间**，而非总时间或到达Q2的时间。
3. **等待时间的累积**：等待时间包括在Q1中等待其他进程执行的时间片，以及在Q2中等待其他进程执行的时间。特别是P1在Q2中不仅要等P2在Q2执行的时间，还要等P2在Q1执行的时间（因为P1在Q2中处于就绪状态，而CPU被Q1中的P2占用）。

## 考察能力
本题核心考察考生对**多级反馈队列调度算法动态执行过程的精确模拟能力**，以及对**等待时间**定义的准确理解和多阶段状态跟踪能力。
