# 2019 Q22 — DMA 工作流程与软硬件协同机制

## 基本信息
- **年份**: 2019  **题位**: Q22  **题型**: 选择题
- **知识点**: DMA, 设备驱动程序, 组成原理>DMA
- **题位域**: 待标注  **科目**: 组成原理

## 题干原文
下列关于 DMA 方式的叙述中，正确的是（ ）。
Ⅰ. DMA 传送前由设备驱动程序设置传送参数
Ⅱ. 数据传送前由 DMA 控制器请求总线使用权
Ⅲ. 数据传送由 DMA 控制器直接控制总线完成
Ⅳ. DMA 传送结束后的处理由中断服务程序完成
DMA

A. 仅Ⅰ、Ⅱ
B. 仅Ⅰ、Ⅲ、Ⅳ
C. 仅Ⅱ、Ⅲ、Ⅳ
D. Ⅰ、Ⅱ、Ⅲ、Ⅳ

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。本题需要考生准确记忆并辨析 DMA 工作过程中的四个关键阶段（预处理、数据传送、后处理）以及涉及的主体（CPU/驱动程序、DMA控制器、总线、中断系统）。这不仅仅是单一概念的定义，而是对“DMA 完整生命周期”中多个易混概念（如谁设置参数、谁请求总线、谁处理结束）的综合记忆与辨析。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，属于纯概念性判断。
- **K3 = 3**: 评分理由。考生需要在脑海中构建 DMA 工作的时序逻辑：先由 CPU/驱动初始化（预处理）→ DMA 请求总线 → DMA 接管总线传输 → 传输结束发中断 → CPU 处理中断（后处理）。这是一个包含 3-5 个步骤的串行推演过程，需要理清各步骤的执行主体。
- **K4 = 2**: 评分理由。题目表述较为直接，没有明显的反直觉陷阱或隐含前提。主要的难点在于对“设备驱动程序”这一软件层角色与“DMA 控制器”这一硬件层角色职责边界的清晰认知，属于常规注意点。
- **K5 = 4**: 评分理由。本题深度考察了操作系统（设备驱动程序、中断服务程序）与计算机组成原理（DMA 控制器、总线仲裁）之间的跨域联动。考生必须理解软件如何配置硬件，以及硬件如何通知软件，体现了软硬件协同工作的核心思想。
- **雷达形状**: K1-K5 高分型，呈现“高认知、高跨域、低计算”的特征，属于典型的**机制理解型**题目。

## 考察模式
- **模式**: 综合型
- **理由**: 题目不仅考察 DMA 硬件本身的工作原理（总线请求、数据传输），还结合了操作系统层面的设备驱动程序和中断处理机制，要求考生从系统整体视角理解 I/O 管理的软硬件协同过程。

## 选项级分析
- **选项 A**: [干扰] — 针对认为“DMA 结束后不需要 CPU 介入”或“中断处理不属于 DMA 流程一部分”的错误认知。这类学生可能忽略了 DMA 传输完成后，CPU 需要更新缓冲区指针、唤醒等待进程等后续工作，这些通常在中断服务程序中完成。
- **选项 B**: [干扰] — 针对认为“DMA 控制器不需要请求总线”或“总线使用权是自动获得的”的错误认知。这类学生可能混淆了 DMA 与内存直接映射的概念，忽略了总线仲裁机制，认为 DMA 控制器可以直接随意使用总线。
- **选项 C**: [干扰] — 针对认为“DMA 参数由 CPU 直接通过指令设置，而非驱动程序”或“驱动程序与 DMA 无关”的错误认知。这类学生可能忽略了操作系统抽象层的作用，误以为用户程序或 CPU 指令直接操作 DMA 寄存器，而实际上是由设备驱动程序封装了这些操作。
- **选项 D**: [正确] — Ⅰ、Ⅱ、Ⅲ、Ⅳ 均正确。
  - Ⅰ 正确：DMA 启动前，CPU 执行设备驱动程序，设置源地址、目的地址、传输字节数等参数。
  - Ⅱ 正确：DMA 控制器在需要传输数据时，向总线仲裁器发出总线请求信号。
  - Ⅲ 正确：获得总线控制权后，DMA 控制器直接控制总线进行数据传送，无需 CPU 干预。
  - Ⅳ 正确：传输结束后，DMA 控制器向 CPU 发送中断请求，CPU 响应中断并执行中断服务程序进行后续处理。
- **干扰策略**: 概念混淆。通过拆分 DMA 流程的不同阶段，混淆软件（驱动/中断）与硬件（DMA 控制器/总线）的职责边界，考察考生对系统分层架构的理解。

## 核心陷阱
- **核心陷阱**: **职责边界模糊**。最大的陷阱在于考生容易混淆“CPU/驱动程序”与“DMA 控制器”在 DMA 流程不同阶段的具体职责。例如，误以为 DMA 控制器自己设置参数（Ⅰ错），或误以为 DMA 传输结束后硬件自动完成所有清理工作无需中断（Ⅳ错）。

## 考察能力
本题核心考察考生对 **DMA 传输全过程（预处理、传输、后处理）中软硬件协同工作机制** 的系统性理解能力。
