# 练习题 Q1 — TCP三次握手序列号与标志位机制

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
考虑主机 P 和 Q 之间 TCP 连接建立时遵循的三次握手机制。设 X 和 Y 分别为 P 和 Q 随机选择的 32 位初始序列号。假设 P 向 Q 发送一个 TCP 连接请求报文段，其中 SYN 位=1，序号=X，确认位=0。若 Q 接受该连接请求，则 Q 发送给 P 的 TCP 报文段首部中包含的信息是以下哪一项？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。本题需要准确记忆 TCP 三次握手中第二次握手（SYN+ACK）报文段的具体字段含义，特别是 SYN 位、ACK 位、Seq 和 Ack 的定义。属于标准的核心概念记忆，不涉及复杂辨析，但必须精确。
- **K2 = 2**: 评分理由。涉及简单的算术逻辑：确认号 = 期望收到的下一个字节序号。由于 SYN 标志位占用一个序列号，故 Ack = X + 1。这是非常基础的“+1”操作，属于 2 的幂友好或极简计算，不易出错。
- **K3 = 2**: 评分理由。推演步骤较少。只需识别当前处于握手的第二步，根据第一步的状态（P 发送 SYN, Seq=X）直接推导第二步 Q 的响应。无需多步串行状态保持，逻辑链条短。
- **K4 = 3**: 评分理由。存在常规注意点陷阱。主要陷阱在于“SYN 标志位是否消耗序列号”以及“确认号是 X 还是 X+1”。如果学生误以为 SYN 不消耗序列号，会选 D；如果混淆了 Seq 和 Ack 的对象，会选 A 或 B。这属于典型的协议细节陷阱。
- **K5 = 1**: 评分理由。本题仅涉及传输层 TCP 协议内部的机制，不涉及网络层、应用层或其他子系统的状态传递或耦合，属于单系统内部逻辑。
- **雷达形状**: K4 陷阱型（K1 基础记忆为主，K4 细节陷阱突出，其他维度较低）

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心在于考察对 TCP 协议规范中报文段首部字段定义及三次握手流程中状态转换规则的理解，而非复杂的数值计算或跨层推理。

## 选项级分析
- **选项 A**: [干扰] — 针对“混淆 Seq 与 Ack 对象”及“忽略 ACK 位”的错误认知。学生可能误以为 Q 发送的是对 P 的确认，所以 Seq 应该是 P 的序号相关（错误逻辑），且可能忘记 Q 也需要发送 SYN 来同步自己的序号，或者误以为 ACK 位为 0。
- **选项 B**: [干扰] — 针对“完全混淆握手与挥手”及“标志位错误”的错误认知。FIN 位出现在连接建立阶段是明显的概念错误，SYN=0 也违背了 Q 需要发起同步的事实。这类选项用于排除对 TCP 状态机完全无概念的学生。
- **选项 C**: [正确] — 符合 TCP 规范。Q 发送 SYN+ACK，Seq=Y（Q 的初始序号），Ack=X+1（确认 P 的 SYN，因 SYN 占一个序号，故期望下一个是 X+1），ACK=1，SYN=1，FIN=0。
- **选项 D**: [干扰] — 针对“SYN 不消耗序列号”的经典错误认知。这是最常见的干扰项。许多学生知道 Ack 是确认对方，但忘记 TCP 规定 SYN 和 FIN 标志位各消耗一个序列号，因此误认为 Ack 应该等于 X。

**干扰策略**: 概念混淆（SYN 是否占序号）、标志位状态错误（FIN 出现、ACK 缺失）

## 核心陷阱
- **核心陷阱**: **SYN 标志位消耗一个序列号**。这是本题最大的考点和陷阱。学生必须明确：当 SYN=1 时，该报文段占用一个序列号，因此接收方发送的确认号（Ack）应为发送方的 Seq + 1，而不是 Seq 本身。

## 考察能力
一句话概括本题核心考察的能力：准确理解 TCP 三次握手中报文段首部字段（特别是 Seq、Ack、SYN、ACK）的语义及 SYN 标志位对序列号的影响。
