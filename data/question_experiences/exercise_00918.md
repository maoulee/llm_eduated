# 练习题 Q综合题 — 进程同步与信号量机制

## 基本信息
- **来源**: 练习题  **题型**: 综合题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
某个计算生成两个数组 $a$ 和 $b$，满足以下条件：
对于 $0 \le i < n$，有 $a[i] = f(i)$，且 $b[i] = g(a[i])$。
假设该计算被分解为两个并发进程 $X$ 和 $Y$，其中 $X$ 计算数组 $a$，$Y$ 计算数组 $b$。
两个进程使用两个二进制信号量 $R$ 和 $S$（初始值均为 $0$）。数组 $a$ 由两个进程共享。进程结构如下所示：

进程X:
```c
private i;
for (i = 0; i < n; i++) {
    a[i] = f(i);
    ExitX(R, S);
}
```

进程Y:
```c
private i;
for (i = 0; i < n; i++) {
    EntryY(R, S);
    b[i] = g(a[i]);
}
```

以下哪一项代表 ExitX 和 EntryY 的正确实现？（ ）

A.
```c
ExitX(R, S) { P(R); V(S); }
EntryY(R, S) { P(S); V(R); }
```

B.
```c
ExitX(R, S) { V(R); V(S); }
EntryY(R, S) { P(R); P(S); }
```

C.
```c
ExitX(R, S) { V(R); P(S); }
EntryY(R, S) { V(S); P(R); }
```

D.
```c
ExitX(R, S) { P(S); V(R); }
EntryY(R, S) { V(S); P(R); }
```

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握信号量 P/V 操作的基本语义（P为等待/减1，V为发送/加1）以及二进制信号量的特性（值仅为0或1）。这不是简单的概念记忆，而是需要理解信号量在进程同步中的具体作用机制。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行算术运算或单位换算。
- **K3 = 4**: 评分理由。解题过程需要多步串行推演。首先分析数据依赖关系（X先算a[i]，Y后算b[i]），其次模拟信号量状态变化。需要推演：X执行V(R)唤醒Y -> Y执行P(R)获取权限 -> Y执行V(S)唤醒X -> X执行P(S)获取权限。这是一个典型的“交替执行”或“乒乓”同步模型，涉及状态在两个进程间的多次传递和切换，步骤超过3步且需记忆中间信号量状态。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。
    1. **二进制信号量约束**：题目明确指出是“二进制信号量”，这意味着信号量值不能超过1。如果实现不当（如选项B），信号量值可能累积到n，虽然逻辑上可能不阻塞，但违背了二进制信号量的定义，且在某些严格实现中会报错或行为未定义。
    2. **死锁风险**：需要识别出如果P/V顺序颠倒或配对错误，会导致死锁（如选项A，X等R，Y等S，初始都为0，互相等待）。
    3. **同步粒度**：需要意识到是“逐个元素”同步，而不是“整个数组”同步。
- **K5 = 4**: 评分理由。深度耦合。进程X和进程Y的状态紧密耦合，X的每一步完成都依赖于Y的上一步完成（通过S信号量），Y的每一步开始都依赖于X的当前步完成（通过R信号量）。状态在两个进程间双向传递，形成闭环依赖。
- **雷达形状**: 呈现“哑铃型”或“双峰型”。K1（基础概念）和 K3/K4/K5（推演与机制）较高，而 K2（计算）极低。这表明题目重逻辑推演和机制理解，轻计算。

## 考察模式
- **模式**: 分析论证型
- **理由**: 题目给出了具体的代码框架和约束条件，要求考生通过分析进程间的同步关系，论证哪个选项的信号量操作序列能满足“无死锁”、“正确同步”且“符合二进制信号量定义”的要求。这不是单纯的代码填空，而是对并发控制机制的逻辑验证。

## 解题思路分析
- **核心思路**: 利用信号量实现进程间的**交替同步**（Ping-Pong Synchronization）。
    1. **确定依赖关系**：对于每个 $i$，必须先执行 $X$ 中的 $a[i]=f(i)$，然后才能执行 $Y$ 中的 $b[i]=g(a[i])$。
    2. **确定信号量角色**：
       - $R$ 用于通知 $Y$：$a[i]$ 已准备好，$Y$ 可以开始计算 $b[i]$。
       - $S$ 用于通知 $X$：$b[i]$ 已计算完毕（或 $Y$ 已释放对 $a[i]$ 的潜在占用/逻辑上的轮次结束），$X$ 可以开始计算 $a[i+1]$。
       - *注意*：虽然题目中 $Y$ 只是读 $a[i]$，通常不需要互斥，但为了保持严格的交替顺序（防止 $Y$ 跑太快或 $X$ 跑太快导致逻辑混乱，或者题目隐含了某种缓冲区限制），这里考察的是严格的交替执行。
    3. **模拟执行流程**：
       - 初始状态：$R=0, S=0$。
       - $X$ 执行 $a[0]$。
       - $X$ 需要通知 $Y$：执行 $V(R)$。此时 $R=1$。
       - $X$ 需要等待 $Y$ 完成当前轮次（或等待许可进行下一轮）：执行 $P(S)$。由于 $S=0$，$X$ 阻塞。
       - $Y$ 被 $V(R)$ 唤醒（或原本在 $P(R)$ 处等待）：执行 $P(R)$。此时 $R=0$。
       - $Y$ 执行 $b[0]$。
       - $Y$ 需要通知 $X$ 下一轮可以开始：执行 $V(S)$。此时 $S=1$。
       - $Y$ 需要等待 $X$ 准备好下一个数据：执行 $P(R)$。由于 $R=0$，$Y$ 阻塞。
       - $X$ 被 $V(S)$ 唤醒，继续循环。
    4. **匹配选项**：
       - $ExitX$ 应包含 $V(R)$ 和 $P(S)$。
       - $EntryY$ 应包含 $P(R)$ 和 $V(S)$。
       - 观察选项 C：
         - $ExitX$: $V(R); P(S);$ -> 符合。
         - $EntryY$: $V(S); P(R);$ -> 注意顺序。在 $EntryY$ 中，先 $V(S)$ 还是先 $P(R)$？

           - 如果 $EntryY$ 先 $V(S)$：此时 $S$ 变为 1。然后 $P(R)$ 等待 $X$。
           - 让我们仔细看选项 C 的 $EntryY$: `V(S); P(R);`。

             - $X$ 算完 $a[0]$，执行 $ExitX$: $V(R)$ ($R=1$), $P(S)$ ($S=0$, $X$ 阻塞)。
             - $Y$ 进入 $EntryY$: 执行 $V(S)$ ($S=1$, 唤醒 $X$), 然后 $P(R)$ ($R=1 \to 0$, $Y$ 继续)。
             - $Y$ 算 $b[0]$。
