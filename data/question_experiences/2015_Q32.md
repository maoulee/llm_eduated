# 2015 Q32 — 磁盘SCAN调度算法磁道移动距离计算

## 基本信息
- **年份**: 2015  **题位**: Q32  **题型**: 选择题
- **知识点**: 磁盘调度算法, SCAN, 操作系统>磁盘调度算法
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
某硬盘有 200 个磁道（最外侧磁道号为 0），磁道访问请求序列为：130，42，180，15，199，当前磁头位于第 58 号磁道并从外侧向内侧移动。按照 SCAN 调度方法处理完上述请求后，磁头移过的磁道数是（ ）。

A. 208
B. 287
C. 325
D. 382

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 SCAN 算法（电梯算法）的核心定义：磁头沿一个方向移动，直到到达该方向上的最后一个请求或磁盘端点，然后反转方向。若仅知道 FCFS 或 SSTF 则无法解题，属于标准概念调用。
- **K2 = 3**: 评分理由。涉及简单的加减法运算，但数字非 2 的幂次，且包含两段距离的累加，存在轻微的计算出错风险，属于标准计算难度。
- **K3 = 3**: 评分理由。解题过程包含 3-4 个逻辑步骤：1. 确定当前方向（向内）；2. 筛选该方向上的请求并排序；3. 确定该方向的终点（最大请求号 199，而非物理端点 199 或 0，需辨析 SCAN 与 C-SCAN 或严格端点定义的区别，本题中 199 既是请求也是该方向最远点）；4. 反转方向处理剩余请求。步骤清晰但需串行推演。
- **K4 = 4**: 评分理由。存在显著的隐含前提和易错点。首先，“从外侧向内侧移动”意味着磁道号增大（0->199），学生需具备磁盘物理结构常识。其次，SCAN 算法在到达“该方向最远请求”后是否继续走到物理端点？本题中 199 是请求，也是该方向最远点，若误以为必须走到 199 后再走到 0 或反之，会出错。更关键的陷阱在于对“外侧/内侧”与“磁道号大小”关系的映射，以及对 SCAN 算法终点判断（是到物理边界还是到最远请求？通常 SCAN 指到物理边界，但本题解析暗示到最远请求即反转，或者 199 恰好是边界附近。*注：严格 SCAN 应到物理端点 199，本题 199 是请求，若物理最大是 199，则重合。若物理最大是 199，则从 58->199->15。若物理最大是 199，则 199 是端点。题目说 200 个磁道 0-199，所以 199 是物理内端点。因此必须走到 199。* 陷阱在于学生可能忽略 199 是物理端点，或者搞反内外侧方向）。
- **K5 = 1**: 评分理由。纯操作系统内部模块问题，不涉及文件系统、内存管理或其他子系统联动。
- **雷达形状**: K4 陷阱型（K4 显著高于其他维度，主要考察对算法细节和隐含条件的识别）

## 考察模式
- **模式**: 计算型
- **理由**: 虽然基于概念，但最终答案依赖于对磁头移动路径的精确数值计算，且选项差异较大，旨在通过计算结果验证对算法执行流程的理解。

## 选项级分析
- **选项 A (208)**: [干扰] — 针对 **SSTF（最短寻道时间优先）** 算法的错误认知。若按 SSTF，从 58 出发，最近是 42，然后 15，然后 130，然后 180，然后 199。路径：58->42(16)->15(27)->130(115)->180(50)->199(19)。总距离：16+27+115+50+19 = 227。不对。
    - 另一种可能：只计算了单向距离？58->199 (141) + 199->130 (69) = 210? 接近但不等。
    - 或者是 **C-SCAN** 的某种错误计算？
    - 更可能的错误：误以为 SCAN 只处理当前方向的请求，忽略返回？58->199 (141) + 199->130 (69) = 210? 不对。
    - 让我们重新计算 SSTF: 58->42 (16), 42->15 (27), 15->130 (115), 130->180 (50), 180->199 (19). Sum = 227.
    - 让我们看看 A=208 怎么来的。可能是 58->130 (72) + 130->180 (50) + 180->199 (19) + 199->42 (157) + 42->15 (27) = 325 (这是正确答案)。
    - 如果只算 58->199 (141) + 199->15 (184) = 325。
    - 如果误以为从 58 向外侧（0方向）移动？58->42 (16) -> 15 (27) -> 0 (15) -> 130 (130) -> 180 (50) -> 199 (19). Sum = 16+27+15+130+50+19 = 257.
    - 如果误以为 SCAN 不需要回到另一端的最远请求，只处理完当前方向就停？58->199 (141). 不对。
    - 实际上，A 选项 208 可能是 **LOOK** 算法（不走到物理端点，只走到最远请求）的某种变体错误，或者纯粹的计算错误。
    - *修正*：如果学生搞反了内外侧，认为 0 是内侧，199 是外侧。当前 58 向内侧（0）移动。路径：58->42->15->0(端点)->130->180->199。距离：(58-15) + (15-0) + (199-0) = 43 + 15 + 199 = 257。也不对。
    - 让我们看 B 选项。
- **选项 B (287)**: [干扰] — 针对 **方向判断错误** 或 **部分路径遗漏**。
    - 如果学生认为“从外侧向内侧”意味着磁道号减小（即 0 是内侧，199 是外侧，这是常见的物理直觉错误，因为通常认为 0 是起始/外侧，但题目明确说 0 是最外侧）。如果学生误以为 0 是内侧，199 是外侧。当前 58 向内侧（0）移动。
    - 路径：58 -> 42 -> 15 -> 0 (物理端点) -> 130 -> 180 -> 199。
    - 距离：(58-15) + (15-0) + (199-0) = 43 + 15 + 199 = 257。
    - 如果学生使用 **LOOK** 算法（不走到 0，只走到 15），然后反转去 199。
    - 路径：58 -> 15 (43) -> 199 (184)。总和 227。
    - 让我们尝试构造 287。
    - 58 -> 199 (141)。199 -> 42 (157)。141+157 = 298。
    - 58 -> 130 (72)。130 -> 199 (69)。199 -> 15 (184)。72+69+184 = 325。
    - 也许 B 是 **C-SCAN**？58->199 (141) -> 0 (199) -> 15 (15) -> 42 (27) -> 130 (88) -> 180 (50)。总和巨大。
    - 也许 B 是忽略了 199 是端点，只走到 180？58->180 (122) -> 15 (165) = 287。
    - **Bingo!** 如果学生错误地认为 SCAN 只需要处理完请求序列中的最大号（180，忽略了 199 这个请求，或者看错了序列），或者认为 199 不是请求？不，199 在序列里。
    - 如果学生漏看了 199 这个请求，只看到 130, 42, 180, 15。最大是 180。
    - 路径：58 -> 180 (122) -> 15 (165)。122 + 165 = 287。
    - **结论**：B 选项是针对 **漏看请求项（199）** 或 **错误识别最大请求号** 的干扰项。
- **选项 C (325)**: [正确] — 正确执行 SCAN 算法。
    - 方向：外侧(0) -> 内侧(199)，即磁道号增加。
    - 当前：58。
    - 请求排序：15, 42, 130, 180, 199。
    - 第一阶段（向内）：58 -> 130 -> 180 -> 199。到达物理内端点 199（也是最大请求）。距离：199 - 58 = 141。
    - 第二阶段（向外）：199 -> 42 -> 15。到达最小请求 15。距离：199 - 15 = 184。
    - 总距离：141 + 184 = 325。
- **选项 D (382)**: [干扰] — 针对 **物理端点理解错误** 或 **重复计算**。
    - 如果学生认为 SCAN 必须走到物理端点 0，即使没有请求。
    - 路径：58 -> 199 (141) -> 0 (199) -> 15 (15)。
    - 距离：141 + 199 + 15 = 355。不对。
    - 如果学生认为从 58 先向外（0）？
    - 58 -> 0 (58) -> 199 (199) -> 15 (184)。58+199+184 = 441。
    - 如果学生计算 58->199 (141) + 199->0 (199) + 0->15 (15) + 15->42 (27) ... 太复杂。
    - 让我们看 382 - 325 = 57。
    - 57 接近 58。
    - 如果学生多算了一段 58->0 的距离？
    - 或者，如果学生误以为 SCAN 是双向都要走到物理端点？
    - 58 -> 199 (141) -> 0 (199) -> 15 (15)。总和 355。
    - 如果学生误以为起始点 58 也要算作从 0 开始？
    - 让我们尝试：(199-0) + (199-15) = 199 + 184 = 383。非常接近 382。
    - 如果学生认为磁头从 0 开始扫描到 199，再回到 15？即忽略了当前在 58，假设从 0 开始？
    - 0 -> 199 (199) + 199 -> 15 (184) = 383。
    - 382 可能是 383 的笔
