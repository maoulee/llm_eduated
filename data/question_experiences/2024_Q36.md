# 2024 Q36 — 802.11 CSMA/CA 中 NAV 值的计算与机制理解

## 基本信息
- **年份**: 2024  **题位**: Q36  **题型**: 选择题
- **知识点**: CN-3 > 介质访问控制 > CSMA协议
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
在采用 CSMA/CA 的 802.11 无线局域网中，DIFS = 120 μs，SIFS = 28μs，RTS、CTS 和 ACK 帧的传输时延分别是 3 μs、2 μs 和 2 μs，忽略信号传播时延。若主机 A 欲向 AP 发送一个总长度为 1998 B 的数据帧，无线链路带宽为 54 Mb/s，则隐藏站 B 收到 AP 发送的 CTS 帧时，设置的网络分配向量 NAV 的值是（）
CSMA/CA

A. 326us
B. 354us
C. 385us
D. 513us

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 802.11 MAC 层的关键参数定义（SIFS, DIFS, RTS/CTS/ACK 的作用）以及 NAV 的基本概念。虽然不需要辨析极复杂的易混概念，但必须清楚 NAV 是由持续时间字段（Duration Field）决定的，且不同节点（发送方、接收方、隐藏站）看到的 NAV 含义不同。
- **K2 = 4**: 评分理由。涉及多级单位换算和计算。首先需将数据帧长度（Byte）转换为比特（bit），再结合带宽（Mb/s）计算传输时延（Transmission Time）。计算过程为 $1998 \times 8 / 54$，结果非整数，需保留精度或进行合理近似，且后续需叠加多个时间间隔（SIFS, ACK 时延等），计算链条较长，容易出错。
- **K3 = 3**: 评分理由。需要推演 802.11 四次握手（RTS-CTS-Data-ACK）的时间轴。解题者需要构建从“隐藏站 B 收到 CTS”这一时刻开始，到“整个通信过程结束”的时间序列。这涉及识别当前处于握手的哪一步，并计算剩余步骤所需的时间。
- **K4 = 4**: 评分理由。存在显著的隐含前提和陷阱。
    1. **视角陷阱**：题目问的是“隐藏站 B”收到 CTS 时设置的 NAV。隐藏站 B 听不到 A 的 RTS，只能听到 AP 的 CTS。因此，B 的 NAV 是基于 CTS 帧中的 Duration 字段设置的，该字段表示的是“CTS 发送结束后，直到 ACK 接收完毕”的时间，还是“CTS 发送结束后，直到整个交互结束”？实际上，CTS 中的 Duration 字段通常设置为：$SIFS + Data_{tx} + SIFS + ACK_{tx}$。
    2. **起始点陷阱**：NAV 是从“帧接收结束时刻”开始计时的吗？是的。但题目问的是“收到 CTS 时...设置的值”。通常 NAV 计数器在帧接收完成后立即开始倒数。关键在于理解 CTS 帧中的 Duration 字段具体覆盖了哪些时间段。
    3. **DIFS 的干扰**：题目给出了 DIFS，但对于已经收到 CTS 并设置 NAV 的节点来说，DIFS 是无关信息，用于干扰判断是否需要等待 DIFS。
- **K5 = 2**: 评分理由。主要局限于 MAC 子层内部的机制，不涉及网络层或物理层其他复杂模块的深度耦合，仅涉及 MAC 帧格式中的 Duration 字段解析。

- **雷达形状**: K4 陷阱型（高条件路由需求，中等计算和推演需求）

## 考察模式
- **模式**: 综合型（计算+机制推理）
- **理由**: 本题不仅要求考生掌握 802.11 的协议流程（机制推理），还要求精确计算数据帧的传输时延（计算），并结合特定节点（隐藏站）的视角来确定 NAV 的具体数值（综合应用）。

## 选项级分析
- **选项 A (326us)**: [干扰] — 可能错误地计算了数据帧传输时间，或者遗漏了某个 SIFS 或 ACK 时间。例如，如果误以为 NAV 只包含 Data 和 ACK，或者计算 Data 时延出错。
- **选项 B (354us)**: [正确] — 正确计算了 Data 传输时延，并正确识别了隐藏站 B 在收到 CTS 后，其 NAV 应覆盖的时间段为：$SIFS + Data_{tx} + SIFS + ACK_{tx}$。
    - 计算验证：
        1. Data 长度 = $1998 \text{ B} = 1998 \times 8 \text{ bits} = 15984 \text{ bits}$
        2. 带宽 = $54 \text{ Mb/s} = 54 \times 10^6 \text{ b/s}$
        3. $T_{data} = 15984 / (54 \times 10^6) \text{ s} \approx 296 \mu s$
        4. 隐藏站 B 收到 CTS 后，CTS 帧中的 Duration 字段指示剩余占用时间。根据 802.11 标准，CTS 的 Duration 字段值 = $SIFS + T_{data} + SIFS + T_{ACK}$。
        5. $NAV = 28 + 296 + 28 + 2 = 354 \mu s$。
- **选项 C (385us)**: [干扰] — 可能错误地加上了 RTS 的传输时间，或者误以为 NAV 从 RTS 开始计算，或者错误地包含了 DIFS。例如：$354 + 31$ (无意义) 或 $296 + 28 + 28 + 2 + 31$? 另一种可能是误将 Data 时延算错，或者多加了一个 SIFS。
- **选项 D (513us)**: [干扰] — 可能错误地认为 NAV 需要覆盖从 RTS 开始的全过程，或者错误地加上了 DIFS。例如：$T_{RTS} + SIFS + T_{CTS} + SIFS + T_{Data} + SIFS + T_{ACK}$ 的一部分？或者 $354 + 120 (DIFS) + 39$? 实际上，如果考生误以为隐藏站 B 需要等待 DIFS 才能发送，可能会混淆 NAV 和退避时间。或者计算为 $T_{data} + 3 \times SIFS + T_{ACK} + T_{RTS} + T_{CTS}$? $296 + 84 + 2 + 3 + 2 = 387$? 不对。
    - 让我们看看 $513$ 怎么来的：$296 (Data) + 28 (SIFS) + 2 (ACK) + 28 (SIFS) + 2 (CTS) + 28 (SIFS) + 3 (RTS) + 120 (DIFS)$? 不太像。
    - 另一种常见错误：误以为 NAV = $T_{data} + 2 \times SIFS + T_{ACK} + T_{RTS} + T_{CTS}$? $296 + 56 + 2 + 3 + 2 = 359$。
    - 再试：$T_{data} (296) + SIFS (28) + ACK (2) + SIFS (28) + CTS (2) + SIFS (28) + RTS (3) + DIFS (120)$? 显然太大。
    - 可能是 $T_{data} (296) + 3 \times SIFS (84) + T_{ACK} (2) + T_{RTS} (3) + T_{CTS} (2) + DIFS (120)$? $296+84+2+3+2+120 = 507$。接近。
    - 或者：$T_{data} (296) + SIFS (28) + ACK (2) + SIFS (28) + CTS (2) + SIFS (28) + RTS (3) + DIFS (120)$?
    - 实际上，D 选项 $513$ 可能是 $296 (Data) + 28 (SIFS) + 2 (ACK) + 28 (SIFS) + 2 (CTS) + 28 (SIFS) + 3 (RTS) + 120 (DIFS) + ...$ 这种全加的错误。
    - 更可能的错误路径：误以为 NAV 是从 RTS 发送开始算的总时间，且包含了 DIFS。总时间 = $DIFS + T_{RTS} + SIFS + T_{CTS} + SIFS + T_{Data} + SIFS + T_{ACK} = 120 + 3 + 28 + 2 + 28 + 296 + 28 + 2 = 507$。接近 513。
    - 或者计算 Data 时延误差：$1998 \times 8 / 54 = 296$。如果误算为 $300$? $300 + 56 + 2 + 3 + 2 + 120 = 483$。
    - 无论具体错误路径如何，D 选项明显偏大，通常对应“全周期”或“包含 DIFS”的错误认知。

- **干扰策略**: 概念混淆（NAV 的起始点和覆盖范围）、计算陷阱（单位换算、多步累加）、无关信息干扰（DIFS）。

## 核心陷阱
- **核心陷阱**: **隐藏站视角下的 NAV 定义**。
    1. 隐藏站 B 听不到 RTS，只听到 CTS。
    2. CTS 帧中的 Duration 字段值是多少？它不是从 RTS 开始算的，而是从 CTS 发送结束（或接收结束，取决于具体实现细节，但在考研语境下通常指剩余时间）开始，覆盖 Data 和 ACK 的传输。
    3. 具体公式：$NAV = SIFS + T_{data} + SIFS + T_{ACK}$。
    4. 许多考生会错误地加上 RTS 的时间，或者错误地加上 DIFS，或者错误地认为 NAV 从 RTS 开始计时。

## 考察能力
本题核心考察考生对 802.11 CSMA/CA 协议中 **虚拟载波监听机制（NAV）** 在不同节点（特别是隐藏站）视角下的具体数值计算能力，以及对 **RTS/CTS 握手中 Duration 字段含义** 的深刻理解。
