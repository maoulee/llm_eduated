## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握单链表的基本结构（节点、指针域）以及头指针、尾节点的概念。不记忆这些核心定义无法入题，但无需辨析多个易混概念，属于标准的基础认知需求。
- **K2 = 1**: 评分理由。本题不涉及数值计算，仅涉及指针赋值和逻辑判断，无计算复杂度。
- **K3 = 3**: 评分理由。从输入到输出需3-5步逻辑推演：1. 理解while循环结束后p和q的状态（p指向尾，q指向尾前）；2. 断开旧尾连接（q->next = NULL）；3. 建立新头连接（p->next = head）；4. 更新头指针（head = p）。步骤清晰但需串行执行，属于标准推演。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。必须意识到指针操作的**顺序依赖性**：如果先执行 `head = p`，则原 `head` 丢失，后续 `p->next = head` 将指向自己形成环；如果先执行 `p->next = head` 再 `q->next = NULL` 虽逻辑可行但选项D是标准写法，而选项B和C展示了常见的顺序错误陷阱。此外，需识别 `q` 在循环结束后的非空状态（除非链表只有一个节点，但题目已排除），避免误选将 `q` 置空的选项。
- **K5 = 1**: 评分理由。仅在链表这一单一数据子系统内操作，不涉及跨模块或跨子系统状态传递。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，主要考察对指针操作顺序和隐含状态的敏感度）

## 选项级分析
- **选项A**: [干扰] — 针对“忘记断开旧尾节点”的错误认知。`q = NULL` 是错误的，因为 `q` 是倒数第二个节点，它的 `next` 应该被置为 NULL 以成为新的尾节点，而不是将 `q` 指针本身置空（这会导致内存泄漏或逻辑错误，且未断开链表）。这类学生可能混淆了“指针变量置空”和“指针域置空”。
- **选项B**: [干扰] — 针对“指针操作顺序错误”的错误认知。`head = p` 先执行，导致原头节点地址丢失。随后 `p.next = head` 实际上变成了 `p.next = p`，形成自环。这类学生忽略了变量赋值对后续语句中变量值的影响。
- **选项C**: [干扰] — 针对“逻辑连接错误”的错误认知。`p.next = q` 将尾节点指向了倒数第二个节点，导致链表方向反转或形成环，且 `head = p` 后原链表主体丢失。这类学生可能混淆了前驱和后继的关系，或者试图构建双向链接但逻辑混乱。
- **选项D**: [正确] — 正确执行了三个关键步骤：1. `q.next = NULL` 断开原尾节点，使 `q` 成为新尾；2. `p.next = head` 将原尾节点 `p` 连接到原头节点；3. `head = p` 更新头指针指向新头节点。顺序正确，逻辑严密。
- **干扰策略**: 概念混淆（指针变量vs指针域）、顺序陷阱（赋值顺序导致数据丢失或成环）

## 核心陷阱
- **核心陷阱**: **指针操作的顺序依赖性**。在修改链表结构时，必须先保存或建立新的连接，再断开旧的连接，或者确保在断开连接前已经完成了所有必要的引用。特别是 `head = p` 必须在 `p->next = head` 之前还是之后？如果在 `p->next = head` 之前执行 `head = p`，原 `head` 就找不到了。本题中，`p->next = head` 需要用到旧的 `head` 值，所以 `head = p` 必须放在最后。
