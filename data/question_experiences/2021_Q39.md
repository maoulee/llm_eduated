# 2021 Q39 — UDP/TCP报文传输效率计算

## 基本信息
- **年份**: 2021  **题位**: Q39  **题型**: 选择题
- **知识点**: CN-5 > UDP协议 > UDP报文, CN-5 > TCP协议 > TCP报文段
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
若大小为 12B 的应用层数据分别通过 1 个 UDP 数据报和 1 个 TCP 段传输，则该 UDP 数据报 和 TCP 段实现的有效载荷（应用层数据）最大传输效率分别是（ ）。
TCP首部
UDP

A. 37.5%, 16.7%
B. 37.5%, 37.5%
C. 60.0%, 16.7%
D. 60.0%, 37.5%

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 UDP 首部固定长度（8B）和 TCP 首部最小长度（20B）。这是计算机网络传输层最基础的概念记忆，不涉及复杂辨析，但必须精确无误，故为标准难度。
- **K2 = 2**: 评分理由。计算过程仅为简单的加法（数据+首部）和除法（数据/总长）。数值较小（12, 8, 20, 32），且结果对应常见百分比（60%, 37.5%），属于“2的幂友好”或简单整数运算，不易出错。
- **K3 = 1**: 评分理由。推演步骤极少：识别协议 -> 确定首部开销 -> 计算总长 -> 计算效率。每一步都是直接映射，无需多步串行逻辑或状态保持。
- **K4 = 3**: 评分理由。存在隐含前提和易错点。首先，“最大传输效率”暗示我们要使用最小的首部开销（即 TCP 无选项字段，20B；UDP 固定 8B）。其次，题目问的是“UDP数据报”和“TCP段”层面的效率，而非网络层或链路层，考生需明确边界，排除 IP 首部或以太网帧头的干扰。若误加 IP 首部则全错，故有中等陷阱。
- **K5 = 1**: 评分理由。本题仅涉及传输层内部（UDP 和 TCP 各自独立），不涉及跨层（如网络层、链路层）的状态传递或耦合，属于单系统内的独立计算。
- **雷达形状**: K4陷阱型（基础计算为主，但需警惕边界定义陷阱）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于根据给定的数据长度和协议首部长度，通过公式 `效率 = 有效载荷 / (有效载荷 + 首部开销)` 进行数值计算。虽然涉及概念记忆，但最终落脚点在于数值结果的准确性。

## 选项级分析
- **选项A**: [干扰] — 针对错误认知：可能误以为 TCP 首部也是 8B 或者计算错误。37.5% 是 TCP 的正确值，但 UDP 算成了 37.5%（即总长32B，误加了12B首部？或者混淆了两者）。这类学生可能记混了 UDP 和 TCP 的首部长度，或者在计算 UDP 时错误地使用了 TCP 的开销。
- **选项B**: [干扰] — 针对错误认知：认为 UDP 和 TCP 效率相同。可能误以为两者首部开销一样，或者完全凭感觉猜测。37.5% 是 TCP 的正确值，UDP 也选 37.5% 说明完全忽略了 UDP 首部更短的事实。
- **选项C**: [干扰] — 针对错误认知：UDP 计算正确（60%），但 TCP 计算错误。16.7% 约为 1/6，即 12/72。这可能源于考生错误地加上了 IP 首部（20B）甚至以太网帧头，导致总长变大，效率降低。或者误以为 TCP 首部是 60B？更可能是混淆了层级，计算了网络层或更下层的效率。
- **选项D**: [正确] — UDP: 12/(12+8) = 12/20 = 60%；TCP: 12/(12+20) = 12/32 = 37.5%。符合协议标准首部长度定义。

- **干扰策略**: 概念混淆与层级陷阱。主要干扰项在于是否清楚“UDP数据报”和“TCP段”的定义边界（仅含传输层首部），以及是否准确记忆两种协议的首部最小长度。

## 核心陷阱
- **核心陷阱**: **协议首部长度的准确记忆与层级边界的界定**。
    1.  **TCP 首部可变性**：TCP 首部有选项字段，长度可变，但题目问“最大传输效率”，隐含条件是首部最短，即 20B。若考生误用包含选项的更长首部，效率会偏低。
    2.  **层级边界**：题目明确问的是“UDP 数据报”和“TCP 段”，这意味着只计算传输层开销。若考生下意识加上 IP 首部（20B）或链路层帧头，会导致分母变大，效率计算错误（如选项 C 的 16.7% 可能源于此）。

## 考察能力
准确记忆传输层协议首部结构，并能基于最小开销原则计算特定层级下的数据传输效率。
