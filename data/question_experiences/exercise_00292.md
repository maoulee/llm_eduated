# 练习题 Q1 — Go-Back-N协议窗口与序列号设计

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
考虑一个连接两个相距 8000 公里的系统的网络。该网络的带宽为 500 × 10⁶ 位/秒，媒体的传播速度为 4 × 10⁶ 米/秒。需要为该网络设计一个 Go-Back-N 滑动窗口协议。平均数据包大小为 10⁷ 位。要求网络以满容量运行。假设节点的处理延迟可以忽略不计。那么，序列号字段的最小位数应为（ ）。
- 选项:
  A: 2
  B: 4
  C: 8
  D: 16
- 正确答案: C
- 解析（参考）: 解析
传播时间
= (8000 × 1000) / (4 × 10⁶) = 2 秒
总往返传播时间
= 2 × 2 = 4 秒
单个数据包的传输时间
= 数据包大小 / 带宽 = 10⁷ / (500 × 10⁶) = 0.02 秒
在收到确认之前可发送的数据包总数
= 往返传播时间 / 单个传输时间 = 4 / 0.02 = 200
最大可能窗口大小
= 200
Go-Back-N 协议要求
：最大序列号应比窗口大小多 1 → 需要 201 个序列号
序列号编码需求
：201 个不同值可用 8 位二进制表示（2⁷=128 < 201 ≤ 2⁸=256）
- 知识标签: ['计算机网络/传输层']
- 知识域: CN-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要调用“传播时延”、“传输时延”、“往返时延（RTT）”、“Go-Back-N协议窗口限制”以及“序列号空间与窗口大小的关系”等多个核心概念。仅记忆单一公式无法解题，需理解各概念间的物理意义。不是4分因为概念本身属于标准教材定义，无需辨析极度易混的深层概念。
- **K2 = 3**: 评分理由。涉及单位换算（公里转米、位/秒与位的匹配）和除法运算。虽然计算步骤不复杂，但数值较大（$10^7$, $500 \times 10^6$），且结果非2的整数幂，需要精确计算得出200，而非估算。不是4分因为计算逻辑是线性的，没有多级嵌套换算。
- **K3 = 3**: 评分理由。解题路径清晰：计算传播时延 -> 计算传输时延 -> 计算带宽时延积（或等效窗口大小） -> 应用GBN协议约束 -> 确定序列号位数。共4-5步串行推演。不是4分因为每一步之间的依赖关系明确，无需记忆复杂的中间状态或回溯。
- **K4 = 4**: 评分理由。存在关键隐含前提和易错点。首先，“满容量运行”意味着发送窗口必须足够大以填满管道，即 $W \ge \text{Bandwidth-Delay Product}$。其次，也是最关键的陷阱：Go-Back-N协议中，序列号空间大小 $S$ 必须满足 $S > W$（通常表述为 $S \ge W + 1$ 或 $2^k > W$）。许多学生容易混淆为 $S = W$ 或 $S \ge W$，或者混淆GBN与SR协议的窗口限制条件。此外，需意识到“序列号位数”对应的是 $2^k$，而非直接等于窗口大小。
- **K5 = 2**: 评分理由。主要涉及传输层协议机制与物理层/链路层参数（带宽、距离、速度）的结合。虽然跨越了层级，但数据传递是单向的（物理参数决定传输层窗口设计），没有复杂的子系统状态互影响。提及无关则2，此处物理参数是必要输入，故为2。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，尤其是K1和K2，表明题目难点不在于计算或基础记忆，而在于对协议约束条件的精确理解和陷阱规避）

## 考察模式
- **模式**: 综合型
- **理由**: 本题结合了物理层的时延计算（工程计算）和传输层的协议设计原则（逻辑推理）。考生不仅需要准确计算带宽时延积，还必须正确应用Go-Back-N协议的序列号空间约束条件，属于典型的计算与概念结合的综合题。

## 选项级分析
- **选项A**: [干扰] — 针对完全未掌握概念或计算严重错误的学生。2位仅能表示4个序列号，远小于所需的200，属于极端错误选项。
- **选项B**: [干扰] — 针对计算错误或概念混淆的学生。4位可表示16个序列号。如果学生错误地计算了时延（例如忽略了往返，或单位换算错误），或者误以为窗口很小，可能会选此项。也可能混淆了Stop-and-Wait协议（窗口为1，需2位序列号，但通常用1位即可，若考虑ACK则需2位，此处16远大于1，故不太可能是SW的直接干扰，更可能是计算量级错误）。
- **选项C**: [正确] — 正确计算得到窗口大小约为200，根据GBN协议 $2^k > 200$，最小 $k=8$。
- **选项D**: [干扰] — 针对过度设计或概念混淆的学生。16位可表示65536个序列号。如果学生误用了TCP的序列号空间概念，或者在计算时延积时数量级搞错（例如多算了几个零），或者认为需要极大的冗余，可能会选此项。也可能混淆了“序列号位数”与“窗口大小”的直接数值关系，误以为需要更大的空间。

**干扰策略**: 计算陷阱与概念混淆结合。通过较大的数值计算增加出错概率，同时利用GBN协议中 $S > W$ 这一非直观约束（相比SR协议的 $S \ge 2W$ 或简单 $S=W$ 的误解）设置陷阱。

## 核心陷阱
- **核心陷阱**: Go-Back-N协议中序列号空间大小与发送窗口大小的关系。许多考生容易误记为 $2^k \ge W$ 或 $2^k = W$，而正确的约束是 $2^k > W$（即序列号空间必须严格大于窗口大小，以防止接收方无法区分新帧和旧帧的重传）。在本题中，$W=200$，若误用 $2^k \ge 200$，$2^7=128 < 200$，$2^8=256 \ge 200$，结果看似一样，但若 $W=128$，则 $2^7=128$ 不满足 $>128$，需 $2^8$。本题中 $W=200$，$2^7=128 < 200$，故必须选8位。更深层的陷阱在于是否理解“满容量运行”意味着窗口至少为带宽时延积，且序列号位数需覆盖该窗口。

## 考察能力
一句话概括本题核心考察的能力：考生能否准确计算网络带宽时延积，并正确应用Go-Back-N滑动窗口协议中序列号空间与窗口大小的约束关系进行协议参数设计。
