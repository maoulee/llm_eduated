# 练习题 Q1 — CPU调度策略对利用率的影响分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/CPU调度
- **难度**: 待评估

## 题干原文
一个单处理器计算机系统仅有两个进程，这两个进程交替进行 10ms 的 CPU 计算和 90ms 的 I/O 操作。两个进程几乎同时创建。两个进程的 I/O 可以并行执行。以下哪种调度策略会导致该系统的 CPU 利用率最低（在长时间内）？
- 选项:
  A: 先来先服务调度
  B: 最短剩余时间优先调度
  C: 为两个进程分配不同优先级的静态优先级调度
  D: 时间片轮转调度，时间片为 5ms

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握先来先服务（FCFS）、最短剩余时间（SRTF）、优先级调度、时间片轮转（RR）这四种基本调度算法的核心定义及执行规则。仅靠直觉无法解题，需准确回忆各算法在进程阻塞（I/O）时的行为差异。
- **K2 = 3**: 评分理由。涉及具体的数值计算（10ms, 90ms, 5ms），需要计算CPU空闲时间段和总周期时间。虽然数字简单，但需要精确的时间轴对齐，非2的幂次方运算，存在轻微的计算门槛。
- **K3 = 4**: 评分理由。推演步骤较多。对于RR算法，需要模拟P1运行5ms->切换->P2运行5ms->切换->P1运行5ms->P1阻塞->P2运行5ms->P2阻塞->CPU空闲->P1唤醒->P2唤醒...这一系列状态变化。特别是RR导致两个进程几乎同时进入I/O阻塞，从而造成CPU长时间空闲，这一推演过程需要多步串行思考。
- **K4 = 4**: 评分理由。存在隐含前提和反直觉陷阱。常规思维可能认为“轮转”更公平或更高效，或者认为“I/O并行”意味着系统一直忙碌。陷阱在于识别出RR的小时间片会导致两个进程在极短时间内耗尽CPU时间并**同时**发起I/O请求，从而造成CPU资源的浪费（空闲）。这是典型的“机制副作用”陷阱。
- **K5 = 3**: 评分理由。涉及CPU调度子系统与I/O子系统的交互。需要理解进程在CPU上运行结束后进入I/O阻塞状态，以及I/O完成后的唤醒机制。状态在CPU就绪队列和I/O等待队列之间传递，属于单向传数据/状态影响。

- **雷达形状**: K3/K4 突出型（推演与陷阱主导）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非直接考查公式记忆，也不是单纯的数值计算，而是要求考生根据给定的调度算法规则，推演系统在特定参数下的动态行为（时间轴变化），进而比较不同策略下的系统性能指标（CPU利用率）。核心在于逻辑推演和机制理解。

## 选项级分析
- **选项A**: [干扰] — 针对“FCFS效率低”的刻板印象。FCFS下，P1运行10ms后阻塞，P2立即获得CPU运行10ms后阻塞。此时P1和P2都在做I/O，CPU空闲90ms。但P1 I/O完成后（100ms处），P1立即获得CPU，P2随后。虽然也有空闲，但相比RR，FCFS的空闲期是串行的（P1做完I/O回来，P2还在做，或者P2做完I/O回来，P1还在做，取决于具体时序，但在本题双进程交替模型中，FCFS通常能保持较好的流水线效果，或者至少不会像RR那样造成“同步阻塞”）。*修正分析*：在FCFS下，P1运行10ms，阻塞90ms；P2运行10ms，阻塞90ms。时间轴：0-10 P1, 10-20 P2, 20-110 空闲(P1,P2 I/O), 110-120 P1, 120-130 P2... 利用率 = 20/120 = 16.6%? 等等，让我们重新仔细推演FCFS。
    - FCFS推演：
      - 0-10ms: P1 CPU
      - 10-20ms: P2 CPU
      - 20-110ms: P1 I/O (10+90), P2 I/O (20+90=110结束). CPU空闲。
      - 110ms: P1 I/O完成，P1进入就绪。P2仍在I/O (直到110ms? 不，P2是20ms开始I/O，持续90ms，所以20+90=110ms结束)。
      - 关键点：P1在10ms开始I/O，100ms结束。P2在20ms开始I/O，110ms结束。
      - 100ms时，P1 I/O完成，P1就绪。此时P2仍在I/O (100-110)。CPU调度P1。
      - 100-110ms: P1 CPU。
      - 110ms: P2 I/O完成，P2就绪。P1刚用完10ms CPU，P1阻塞去I/O。
      - 110-120ms: P2 CPU。
      - 120ms: P1 I/O完成 (110+90=200? 不，P1是100ms开始第二次I/O? 不，P1是100ms开始CPU，110ms结束CPU，110ms开始I/O，200ms结束)。P2是110ms开始CPU，120ms结束CPU，120ms开始I/O，210ms结束。
      - 让我们看一个完整周期。
      - 实际上，FCFS下，两个进程会形成一种“接力”。P1做完CPU去I/O，P2做CPU。P1 I/O回来时，P2可能刚做完CPU去I/O，或者P2还在做CPU。
      - 在本题中，CPU时间(10) < I/O时间(90)。
      - FCFS: P1(0-10 CPU) -> P1(10-100 IO). P2(10-20 CPU) -> P2(20-110 IO).
      - 100ms: P1 IO完成。P2还在IO (直到110). CPU空闲? 不，P1就绪，CPU调度P1。
      - 100-110: P1 CPU.
      - 110ms: P1 CPU结束，P1去IO (110-200). P2 IO完成，P2就绪。
      - 110-120: P2 CPU.
      - 120ms: P2 CPU结束，P2去IO (120-210). P1还在IO.
      - 200ms: P1 IO完成。P2还在IO. CPU调度P1.
      - 200-210: P1 CPU.
      - 210ms: P1去IO. P2 IO完成.
      - 210-220: P2 CPU.
      - 观察周期：从100ms到210ms，是一个稳定周期吗？
      - 100-110 (P1 CPU), 110-120 (P2 CPU). 中间无空闲。
      - 120-200 (P1 IO, P2 IO). CPU空闲80ms.
      - 200-210 (P1 CPU), 210-220 (P2 CPU).
      - 所以FCFS的周期是：20ms CPU, 80ms IO (空闲). 利用率 20/100 = 20%.
      - 等等，参考解析说RR是19.05%。FCFS是20%。RR更低。
      - 为什么RR更低？
      - RR (5ms):
        - 0-5 P1, 5-10 P2, 10-15 P1, 15-20 P2.
        - 15ms: P1 CPU结束 (5+5+5=15), P1去IO (15-105).
        - 20ms: P2 CPU结束 (5+5+5+5=20), P2去IO (20-110).
        - 20-105: CPU空闲 (85ms).
        - 105ms: P1 IO完成. P1就绪. P2仍在IO (直到110).
        - 105-110: P1 CPU (5ms). P1还剩5ms CPU.
        - 110ms: P2 IO完成. P2就绪. P1还剩5ms.
        - 110-115: P1 CPU (5ms). P1 CPU结束, 去IO (115-205).
        - 115-120: P2 CPU (5ms). P2还剩5ms.
        - 120-125: P2 CPU (5ms). P2 CPU结束, 去IO (125-215).
        - 125-205: CPU空闲 (80ms).
        - 205ms: P1 IO完成.
        - 205-210: P1 CPU.
        - 210ms: P2 IO完成.
        - 210-215: P1 CPU. P1去IO.
        - 215-220: P2 CPU.
        - 220-225: P2 CPU. P2去IO.
        - 周期分析：从105ms开始进入稳定状态？
        - 105-115: P1 CPU (10ms).
        - 115-125: P2 CPU (10ms).
        - 125-205: 空闲 (80ms).
        - 205-215: P1 CPU (10ms).
        - 215-225: P2 CPU (10ms).
        - 225-305: 空闲 (80ms).
        - 所以RR的稳定周期是：20ms CPU, 80ms 空闲. 利用率 20/100 = 20%?
        - 让我们重新检查参考解析的计算。
        - 参考解析：CPU空闲时间 = 85ms. CPU利用率 = 20/105 = 19.05%.
        - 参考解析的周期是105ms。
        - 让我们看参考解析的逻辑：
          - P1: 0-5, 10-15 (CPU). 15ms开始IO. 15+90=105ms完成.
          - P2: 5-10, 15-20 (CPU). 20ms开始IO. 20+90=110ms完成.
          - 20-105: CPU空闲. (85ms).
          - 105ms: P1完成IO. P1进入就绪.
          - 此时P2还在IO (直到110).
          - 105-110: P1运行5ms. (P1还剩5ms CPU).
          - 110ms: P2完成IO. P2进入就绪.
          - 110-115: P1运行5ms. (P1 CPU完成). P1去IO (115-205).
          - 115-120: P2运行5ms. (P2还剩5ms CPU).
          - 120-125: P2运行5ms. (P2 CPU完成). P2去IO (125-215).
          - 125-205: CPU空闲 (80ms).
          - 205ms: P1完成IO.
          - 205-210: P1运行5ms.
          - 210ms: P2完成IO.
          - 210-215: P1运行5ms. P1去IO.
          - 215-220: P2运行5ms.
          - 220-225: P2运行5ms. P2去IO.
          - 225-305: 空闲.
          - 看起来稳定后的
