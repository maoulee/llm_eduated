# 练习题 Q1 — 应用层协议连接机制辨析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/应用层
- **难度**: 待评估

## 题干原文
在下列协议对中，哪一对的两个协议可以在同一客户端与服务器之间使用多个 TCP 连接？

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。本题需要考生准确记忆并辨析 HTTP、FTP、TELNET、SMTP 四个常见应用层协议在传输层连接管理上的具体行为。不仅仅是知道协议名字，还需要知道它们各自是“单连接”、“多连接”还是“双连接（控制+数据）”。涉及多个易混概念的对比，属于较高程度的基础认知需求。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，完全属于定性分析。
- **K3 = 2**: 评分理由。推演步骤较少。考生只需回忆每个协议的连接特性，然后判断是否满足“多个 TCP 连接”这一条件。逻辑链条短，无需复杂的多步串行推演。
- **K4 = 3**: 评分理由。存在隐含前提和陷阱。陷阱在于对“多个 TCP 连接”的理解。FTP 是典型的“两个连接”（控制+数据），这符合“多个”的定义；而 HTTP 在非持久连接下是“多个连接”，但在持久连接下是“一个连接”。题目问的是“可以”，因此只要存在一种模式（非持久）或多连接机制（FTP）即可。考生容易忽略 HTTP 的非持久模式，或者误以为 FTP 的两个连接不算“多个”（虽然2也是多，但通常语境下多指>1，这里2符合）。更深的陷阱在于 TELNET 和 SMTP 严格限制为单连接，考生若对 SMTP 的管道化或单连接特性记忆模糊，容易误选。
- **K5 = 2**: 评分理由。主要考察应用层协议自身的设计规范，虽然涉及传输层（TCP），但不需要深入分析 TCP 的状态机或跨层复杂的交互细节，属于单系统（应用层协议规范）内的知识调用。
- **雷达形状**: K1 认知主导型，K4 陷阱辅助型。整体呈现为对概念细节记忆和辨析能力的考察，计算和复杂推演需求极低。

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心在于考察考生对计算机网络中常见应用层协议工作机制（特别是连接管理方式）的概念性理解。不需要计算，主要依赖对协议规范的记忆和对比。

## 选项级分析
- **选项 A**: [正确] — HTTP 在非持久连接模式下，每请求一个对象（如图片、脚本）都会建立一个新的 TCP 连接，因此可以使用多个连接；FTP 使用两个独立的 TCP 连接（控制连接和数据连接），也符合“多个”的定义。两者均满足题意。
- **选项 B**: [干扰] — 针对认为 HTTP 总是多连接，但忽略 TELNET 是严格单连接的学生。TELNET 用于远程登录，整个会话期间通常维持一个 TCP 连接。
- **选项 C**: [干扰] — 针对知道 FTP 是多连接，但误以为 SMTP 也是多连接的学生。SMTP 在发送邮件时，虽然可以发送多封邮件，但通常在一个 TCP 连接上完成（支持管道化），且传统上认为其会话基于单个 TCP 连接。即使考虑扩展，其核心特征并非像 FTP 那样强制分离控制与数据通道，也不像 HTTP 非持久那样频繁重建连接。在408语境下，SMTP 通常被视为单连接协议。
- **选项 D**: [干扰] — 针对对 HTTP 和 SMTP 连接特性记忆模糊的学生。虽然 HTTP 可以是多连接，但 SMTP 是单连接，因此该对不满足“两个协议都可以”的条件。

- **干扰策略**: 概念混淆。利用学生对 HTTP 持久/非持久连接的不确定性，以及对 FTP 双连接机制是否算“多个”的犹豫，同时利用 SMTP 和 TELNET 作为典型的单连接协议作为排除项，制造混淆。

## 核心陷阱
- **核心陷阱**: 对“多个 TCP 连接”定义的边界理解以及 HTTP 连接模式的多样性。
    1.  **HTTP 的模式切换**：考生可能只记得 HTTP/1.1 默认持久连接（单连接），从而排除 HTTP。必须意识到题目问的是“可以”，非持久连接（HTTP/1.0 默认或显式关闭 Keep-Alive）下是多连接的。
    2.  **FTP 的连接数**：FTP 使用 2 个连接，2 属于“多个”（>1）。有些考生可能潜意识认为“多个”意味着很多个（如 HTTP 非持久），从而犹豫 FTP 是否符合。
    3.  **SMTP/TELNET 的单连接特性**：必须明确这两个协议在标准会话中仅使用一个 TCP 连接。

## 考察能力
本题核心考察考生对常见应用层协议（HTTP, FTP, SMTP, TELNET）在传输层连接管理策略上的细节记忆与辨析能力，特别是区分单连接、双连接（控制/数据分离）和多连接（非持久）机制。
