# 练习题 Q1 — TCP应用层数据发送上限

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
应用程序层可以向下传递给 TCP 层的最大数据量是多少？（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 TCP 协议的基本特性（面向字节流、可靠传输）以及应用层与传输层交互的基本概念。不是 4 分因为不需要辨析多个易混概念（如 UDP 与 TCP 的区别、MSS 与 MTU 的区别等），只需理解 TCP 对上层数据的“无限制”接收特性。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入。
- **K3 = 2**: 评分理由。需要简单的逻辑推演：应用层数据 -> TCP 层接收 -> TCP 内部处理（分段/窗口控制）。步骤较少，但需要理解 TCP 内部机制（滑动窗口、分段）是自动完成的，而非由应用层直接控制上限。
- **K4 = 4**: 评分理由。存在明显的隐含前提和反直觉陷阱。题干问的是“可以向下传递”的能力上限，而非“一次网络传输”的物理上限。学生容易将“应用层发送”与“IP 层分片”或“以太网帧大小”混淆。必须意识到 TCP 是字节流服务，应用层可以调用 `send()` 发送任意大小的缓冲区，TCP 协议栈会负责后续的分段和流量控制。这是一个典型的“概念边界”陷阱。
- **K5 = 3**: 评分理由。涉及应用层与传输层之间的接口关系。需要理解应用层数据如何进入传输层，以及传输层如何独立于应用层进行内部处理（如 MSS 分割）。属于单向数据传递和状态管理的理解。
- **雷达形状**: K4 陷阱型（K4 显著高于其他维度，K2 极低）

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心在于考察对 TCP 协议服务原语和架构设计的理解，而非计算或复杂推理。重点在于区分“接口能力”与“物理限制”。

## 选项级分析
- **选项 A**: [正确] — 针对正确认知。TCP 提供的是面向字节流的可靠传输服务，应用层进程可以向 TCP 发送任意长度的数据块，TCP 协议栈会根据 MSS（最大报文段长度）和当前拥塞窗口/接收窗口自动将其分割成多个 TCP 报文段进行发送。
- **选项 B**: [干扰] — 针对错误认知：混淆了 TCP 报文段的最大数据部分（Payload）限制。$2^{16}-1$ 字节（65535 字节）是 TCP 头部中“数据偏移”字段决定的最大段长度，或者是 IP 层未分片情况下的最大 TCP 载荷。但这限制的是**单个 TCP 报文段**的大小，而不是应用层**一次性调用**可以传递的总数据量。
- **选项 C**: [干扰] — 针对错误认知：混淆了 TCP 报文段的总长度限制。$2^{16}$ 字节通常指 TCP 头部中“段长度”字段的理论最大值（含头部），同样限制的是单个报文段，而非应用层接口。
- **选项 D**: [干扰] — 针对错误认知：混淆了链路层的 MTU（最大传输单元）。1500 字节是以太网常见的 MTU 值，限制了 IP 数据报的大小，进而间接影响 MSS。但这属于网络层/链路层的物理限制，且 TCP 会自动处理分片（通过调整 MSS），应用层无需关心此限制，更不受此限制直接约束其发送总量。
- **干扰策略**: 概念混淆。利用学生熟悉的数值（65535, 1500）作为干扰项，诱导学生将“协议内部单个单元的限制”误认为是“应用层接口的限制”。

## 核心陷阱
- **核心陷阱**: 混淆“应用层接口能力”与“网络传输单元限制”。学生容易认为应用层发送数据必须适应网络的最小/最大单元，而忽略了 TCP 作为传输层协议，其核心职责之一就是屏蔽底层网络细节，向上层提供无限制的字节流服务。

## 考察能力
一句话概括本题核心考察的能力：理解 TCP 协议面向字节流的服务特性及其对应用层数据发送的透明性。
