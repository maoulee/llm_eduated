# 模拟题 Q综合题 — Cache映射机制与命中率计算

## 基本信息
- **来源**: 模拟题  **题型**: 综合题
- **科目**: 操作系统
- **知识点**: OS-3 > 3.2 虚拟内存管理 > 局部性原理, OS-3 > 3.2 虚拟内存管理 > 时间局部性, OS-3 > 3.2 虚拟内存管理 > 空间局部性
- **难度**: 待评估

## 题干原文
（12 分）以下是计算两个向量点积的程序段：
```c
float Dotproduct(float x[8], float y[8])
{
    float sum = 0.0;
    int i;
    for (i = 0; i < 8; i++)
    {
        sum += x[i] * y[i];
    }
    return sum;
}
```
请回答下列问题：
（1）请分析访问数组 x 和 y 时的时间局部性和空间局部性？
（2）假设数据 Cache 采用直接映射方式，Cache 容量为 32 字节，每个主存块大小为 16 字节；编译器将变量 sum 和 i 分配在寄存器中，内存按字节编址，数组 x 存放在 0000 0040H 开始的 32 字节的连续存储区中，数组 y 则紧跟在 x 后进行存放。该程序数据访问的命中率是多少？要求说明每次访问时 Cache 的命中情况。
（3）将上述（2）中的数据 Cache 改用 2-路组相联映射方式，块大小改为 8 字节，其他条件不变，则该程序数据访问的命中率是多少？
（4）在上述（2）中条件不变的情况下，将数组 x 定义为 float[12]，则数据访问的命中率是多少？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆并区分“时间局部性”与“空间局部性”的定义，以及Cache直接映射、组相联映射的基本概念。属于标准的基础概念调用，不涉及复杂辨析。
- **K2 = 3**: 评分理由。涉及地址计算（如0040H对应的块号）、Cache行数计算（32B/16B=2行）、块内偏移计算等。虽然都是2的幂次运算，但需要结合十六进制地址进行转换，存在一定计算量，属于标准难度。
- **K3 = 4**: 评分理由。解题过程需要多步串行推演：首先确定主存块号，然后根据映射规则确定Cache行号，接着模拟循环中每一次访问（x[i]和y[i]）的Cache状态变化（命中/缺失/替换）。特别是第(2)问中，由于x和y映射到同一Cache行，需要细致推演“冲突缺失”的过程，步骤较多且需保持中间状态。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。例如：(2)中x和y地址连续但映射到同一Cache行导致的“抖动”（Thrashing）；(3)中块大小改变后，映射关系的变化；(4)中数组长度改变导致y的起始地址偏移，从而改变映射关系。考生必须意识到“直接映射”在特定地址分布下的冲突问题，这是典型的隐含前提深坑。
- **K5 = 2**: 评分理由。主要考察Cache子系统内部机制，虽然涉及程序执行流（循环），但主要是单向的数据访问模拟，不涉及CPU流水线、中断或其他子系统间的深度状态耦合。
- **雷达形状**: 呈现“中间高、两头低”的纺锤形或菱形。K1基础适中，K2计算标准，K3推演和K4陷阱识别难度较高，K5跨域联动较低。

## 考察模式
- **模式**: 计算推导型
- **理由**: 题目核心在于通过具体的地址、Cache参数，逐步推导每一次内存访问的结果，最终计算出命中率。虽然第一问是概念分析，但后续三问均依赖于严密的逻辑推导和数值计算。

## 解题思路分析
- **核心思路**: 
    1. **局部性分析**：根据循环访问模式判断时间/空间局部性。
    2. **Cache参数解析**：计算Cache行数、主存块号、映射函数。
    3. **模拟访问过程**：针对循环中的每一次`x[i]`和`y[i]`访问，判断是否命中。
    4. **统计命中率**：命中次数 / 总访问次数。

- **关键步骤**:
    1. **第(1)问**：`x[i]`和`y[i]`在循环中只访问一次，无重复，故时间局部性差；`x`和`y`内部元素连续访问，故空间局部性好。
    2. **第(2)问**：
       - Cache行号 = 2 (32B/16B)。
       - 块大小 = 16B，包含4个float。
       - `x`起始地址0040H，`y`起始地址0050H。
       - `x`的块号：0040H/16 = 0x4，映射到Cache行 0x4 % 2 = 0。
       - `y`的块号：0050H/16 = 0x5，映射到Cache行 0x5 % 2 = 1。
       - *修正思考*：等等，0040H是64，0050H是80。
       - 块大小16B。
       - `x`占用地址 0040H-004FH (64-79)。块号 = 64/16 = 4。Cache行 = 4 % 2 = 0。
       - `y`占用地址 0050H-005FH (80-95)。块号 = 80/16 = 5。Cache行 = 5 % 2 = 1。
       - 如果x映射到行0，y映射到行1，那么它们不会冲突？
       - 让我们重新检查题目答案。答案说命中率为0%。这意味着发生了严重的冲突。
       - 重新计算地址：`x`在0040H。`y`紧跟在`x`后。`x`大小32B。所以`y`从0040H + 32 = 0060H开始？
       - 题目说“数组 x 存放在 0000 0040H 开始的 32 字节... 数组 y 则紧跟在 x 后”。
       - `x`: 0040H - 005FH (32字节)。
       - `y`: 0060H - 007FH (32字节)。
       - 块大小16B。
       - `x`的块：
         - 块0: 0040H-004FH (x[0]-x[3])。块号4。Cache行 4%2=0。
         - 块1: 0050H-005FH (x[4]-x[7])。块号5。Cache行 5%2=1。
       - `y`的块：
         - 块2: 0060H-006FH (y[0]-y[3])。块号6。Cache行 6%2=0。
         - 块3: 0070H-007FH (y[4]-y[7])。块号7。Cache行 7%2=1。
       - 访问顺序：
         - i=0: 访问x[0] (块4, 行0) -> Miss, 加载块4到行0。访问y[0] (块6, 行0) -> Miss, 块6映射到行0，替换块4。
         - i=1: 访问x[1] (块4, 行0) -> Miss (被y[0]替换了), 加载块4到行0。访问y[1] (块6, 行0) -> Miss, 替换块4。
         - ...以此类推。
       - 结论：x和y的对应块都映射到相同的Cache行（x[0-3]和y[0-3]都映射到行0；x[4-7]和y[4-7]都映射到行1）。因此每次访问都会导致前一个块被踢出，命中率为0%。
    3. **第(3)问**：
       - 2路组相联，块大小8B。
       - Cache容量32B，块大小8B -> 总块数4。2路 -> 2组。
       - `x`块大小8B (2个float)。
       - `x`地址0040H。`y`地址0060H。
       - `x[0-1]` (0040-0047): 块号5 (0040/8=5)。组号 5%2=1。
       - `y[0-1]` (0060-0067): 块号15 (0060/8=15)。组号 15%2=1。
       - `x[2-3]` (0048-004F): 块号6。组号 6%2=0。
       - `y[2-3]` (0068-006F): 块号16。组号 16%2=0。
       - 访问i=0: x[0] (块5, 组1) Miss, 加载。y[0] (块15, 组1) Miss, 加载 (2路，组1有2个位置，块5和块15共存)。
       - 访问i=1: x[1] (块5, 组1) Hit。y[1] (块15, 组1) Hit。
       - 访问i=2: x[2] (块6, 组0) Miss, 加载。y[2] (块16, 组0) Miss, 加载。
       - 访问i=3: x[3] (块6, 组0) Hit。y[3] (块16, 组0) Hit。
       - 同理i=4,5,6,7。
       - 总访问16次。Miss: i=0(2次), i=2(2次), i=4(2次), i=6(2次) = 8次Miss。
       - Hit: 8次。命中率 50%。
    4. **第(4)问**：
       - 回到(2)的条件：直接映射，块16B，Cache 2行。
       - `x`变为float[12]，大小48B。
       - `x`地址0040H - 006FH。
       - `y`紧跟`x`，从0070H开始。
       - `x`的块：
         - 块4 (0040-004F): x[0-3]。行0。
         - 块5 (0050-005F): x[4-7]。行1。
         - 块6 (0060-006F): x[8-11]。行0。
       - `y`的块 (从0070H开始):
         - 块7 (0070-007F): y[0-3]。行1。
         - 块8 (0080-008F): y[4-7]。行0。
       - 访问序列：
         - i=0: x[0] (块4, 行0) Miss。y[0] (块7, 行1) Miss。
         - i=1: x[1] (块4, 行0) Hit。y[1] (块7, 行1) Hit。
         - i=2: x[2] (块4, 行0) Hit。y[2] (块7, 行1) Hit。
         - i=3: x[3] (块4, 行0) Hit。y[3] (块7, 行1) Hit。
         - i=4: x[4] (块5, 行1) Miss (替换块7? 不，块5映射到行1，块7也在行1。此时行1存的是块7。访问x[4]需要块5，Miss，替换块7)。
           - 注意：此时y[4]还没访问。
           - 访问x[4] (块5, 行1) -> Miss, 加载块5。
           - 访问y[4] (块8, 行0) ->
