# 练习题 Q1 — 死锁条件与资源竞争分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/死锁
- **难度**: 待评估

## 题干原文
一个系统有 $n$ 个资源 $R_0, \dots, R_{n-1}$ 和 $k$ 个进程 $P_0, \dots, P_{k-1}$。每个进程 $P_i$ 的资源请求逻辑实现如下：
```c
if (i % 2 == 0) {
    if (i < n) request R_i;
    if (i + 2 < n) request R_{i+2};
}
else {
    if (i < n) request R_{n-i};
    if (i + 2 < n) request R_{n-i-2};
}
```
在以下哪种情况下可能发生死锁？（ ）
- 选项:
  A: n=40, k=26
  B: n=21, k=12
  C: n=20, k=10
  D: n=41, k=19

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握死锁产生的必要条件（互斥、占有并等待、非抢占、循环等待），特别是“循环等待”在资源请求图中的体现。不是4分因为不需要辨析多个易混概念，只需理解基本的死锁定义。
- **K2 = 2**: 评分理由。涉及简单的模运算和加减法（如 $i\%2$, $n-i$），计算量极小，属于基础算术，不易出错。
- **K3 = 4**: 评分理由。需要针对每个选项中的 $n$ 和 $k$，推演多个进程（$P_0$ 到 $P_{k-1}$）的具体资源请求序列。特别是需要识别出哪些进程请求了相同的资源，并构建资源分配图或等待图。步骤较多，需跟踪多个进程的状态。
- **K4 = 5**: 评分理由。存在极深的隐含前提和反直觉陷阱。
    1. **陷阱1**：题目问的是“可能发生死锁”，而非“必然发生”。只要存在资源竞争（两个进程请求同一资源）且系统资源不足以同时满足所有请求，就*可能*因调度顺序不当导致死锁。
    2. **陷阱2**：学生容易误以为只有形成严格的“循环等待链”（如 $P_1$ 等 $R_1$, $R_1$ 被 $P_2$ 占, $P_2$ 等 $R_2$...）才算死锁。实际上，在单实例资源模型下，只要有两个进程竞争同一个资源，且该资源被其中一个占用而另一个在等待，若此时没有其他资源可分配给等待者，且占用者也在等待其他资源（或仅仅是因为资源耗尽导致无法推进），即可构成死锁场景。更准确地说，本题的核心在于**资源冲突**。如果所有进程请求的资源都互不相同，则绝不会死锁。只有当不同进程请求**相同**资源时，才*可能*死锁。
    3. **陷阱3**：参考解析指出 $P_{10}$ 和 $P_{11}$ 都请求 $R_{10}$。这揭示了奇偶进程逻辑在特定 $n$ 值下的重叠。学生必须意识到 $n$ 的奇偶性对索引映射的影响。
- **K5 = 1**: 评分理由。仅涉及操作系统内部的进程与资源管理，无跨子系统联动。

- **雷达形状**: K4陷阱型（高条件路由需求，高机制推演需求，低计算需求）

## 考察模式
- **模式**: 推理型
- **理由**: 题目没有直接给出死锁场景，而是给出了资源请求的代码逻辑。考生需要通过逻辑推理，将代码转化为具体的资源请求集合，进而分析这些集合之间是否存在冲突（即是否请求同一资源）。核心在于从代码逻辑推导出资源竞争的可能性。

## 选项级分析
- **选项A**: [干扰] — $n=40, k=26$。
    - 分析：$n=40$ 是偶数。
    - 偶数进程 $P_i$ ($i$ even): 请求 $R_i, R_{i+2}$。索引范围 $0, 2, \dots, 24$ (因为 $i<40$ 且 $i+2<40 \Rightarrow i \le 36$)。
    - 奇数进程 $P_i$ ($i$ odd): 请求 $R_{40-i}, R_{40-i-2}$。
        - $P_1$: $R_{39}, R_{37}$
        - $P_3$: $R_{37}, R_{35}$
        - ...
        - $P_{25}$: $R_{15}, R_{13}$
    - 观察：偶数进程请求偶数索引资源，奇数进程请求奇数索引资源（因为 $40$ 是偶数，$i$ 是奇数，$40-i$ 是奇数）。
    - 结论：偶数进程和奇数进程请求的资源索引奇偶性不同，**永远不会冲突**。因此不可能死锁。
    - 错误认知：学生可能未注意到 $n$ 为偶数时，奇偶进程请求的资源索引奇偶性分离。

- **选项B**: [正确] — $n=21, k=12$。
    - 分析：$n=21$ 是奇数。
    - 偶数进程 $P_i$: 请求 $R_i, R_{i+2}$。
        - $P_0: R_0, R_2$
        - $P_2: R_2, R_4$
        - ...
        - $P_{10}: R_{10}, R_{12}$
    - 奇数进程 $P_i$: 请求 $R_{21-i}, R_{21-i-2}$。
        - $P_1: R_{20}, R_{18}$
        - $P_3: R_{18}, R_{16}$
        - ...
        - $P_{11}: R_{10}, R_8$  (注意：$21-11=10$, $21-11-2=8$)
    - 冲突点：$P_{10}$ (偶数) 请求 $R_{10}$，$P_{11}$ (奇数) 也请求 $R_{10}$。
    - 结论：存在资源竞争。如果 $P_{10}$ 先获得 $R_{10}$ 并等待 $R_{12}$，而 $P_{11}$ 先获得 $R_8$ 并等待 $R_{10}$，且系统中其他资源分配情况导致无法推进，则**可能**发生死锁。
    - 正确认知：识别出 $n$ 为奇数时，奇偶进程的资源请求索引可能重叠。

- **选项C**: [干扰] — $n=20, k=10$。
    - 分析：$n=20$ 是偶数。同选项A的逻辑，偶数进程请求偶数索引，奇数进程请求奇数索引（$20-i$，$i$奇则$20-i$奇）。
    - 结论：无资源冲突，不可能死锁。
    - 错误认知：同A。

- **选项D**: [干扰] — $n=41, k=19$。
    - 分析：$n=41$ 是奇数。
    - 偶数进程 $P_i$: 请求 $R_i, R_{i+2}$。最大 $i=18$ ($P_{18}$ 请求 $R_{18}, R_{20}$)。
    - 奇数进程 $P_i$: 请求 $R_{41-i}, R_{41-i-2}$。
        - $P_1: R_{40}, R_{38}$
        - ...
        - $P_{19}$ 不存在 ($k=19 \Rightarrow P_0 \dots P_{18}$)。最大奇数进程是 $P_{17}$。
        - $P_{17}: R_{24}, R_{22}$。
    - 检查重叠：
        - 偶数进程请求范围：$0, 2, \dots, 20$。
        - 奇数进程请求范围：$41-1=40, 41-3=38, \dots, 41-17=24$。即 $24, 26, \dots, 40$。
    - 结论：偶数进程请求 $0-20$，奇数进程请求 $24-40$。**无重叠**。
    - 错误认知：学生可能认为只要 $n$ 是奇数就一定有重叠，忽略了 $k$ 的大小限制了进程的范围，导致请求区间没有交集。

- **干扰策略**: 概念混淆（奇偶性分离 vs 重叠）、计算陷阱（忽略 $k$ 对进程范围的限制）。

## 核心陷阱
- **核心陷阱**: **资源索引的奇偶性分离与重叠条件**。
    1. 当 $n$ 为偶数时，偶数进程 $P_i$ 请求 $R_i$ (偶)，奇数进程 $P_i$ 请求 $R_{n-i}$ (偶-奇=奇)。两者请求的资源索引奇偶性不同，**绝对不冲突**，因此不可能死锁。这直接排除了 A 和 C。
    2. 当 $n$ 为奇数时，偶数进程请求偶数索引，奇数进程请求 $R_{n-i}$ (奇-奇=偶)。**两者都请求偶数索引资源**，存在冲突可能。
    3. 进一步陷阱：即使 $n$ 为奇数，如果进程数量 $k$ 较少，导致偶数进程请求的低索引资源和奇数进程请求的高索引资源**区间不重叠**，也不会死锁。选项 D 中，$n=41$ (奇)，但 $k=19$，偶数进程最大请求到 $R_{20}$，奇数进程最小请求到 $R_{24}$，中间有空隙，无冲突。只有选项 B 中，$n=21, k=12$，偶数进程 $P_{10}$ 请求 $R_{10}$，奇数进程 $P_{11}$ 请求 $R_{10}$，发生直接冲突。

## 考察能力
本题核心考察考生**将代码逻辑转化为资源请求模型**，并**分析资源竞争条件**（特别是通过奇偶性分析快速排除无冲突情况）的能力。
