# 2014年 Q17 — 指令格式设计与寻址范围计算

## 基本信息
- **年份**: 2014  **题位**: Q17  **题型**: 选择题
- **知识点**: 指令格式设计, 数据寻址方式(基址寻址), 机器数表示范围(补码)
- **考纲对应**: 第四章 指令系统 → 指令格式 → 地址码结构/操作码编码, 第四章 指令系统 → 指令寻址方式 → 有效地址计算, 第二章 数据的表示和运算 → 定点数的表示

## K1-K5 评分与解析
- **K1 = 3**: 3 — 必须准确记忆“基址寻址中偏移量通常为补码”以及“指令字长分配”的基本概念。虽然不涉及复杂定义，但若对基址寻址机制（基址+偏移）不熟悉，无法确定剩余位数用于何处，故高于2；但未涉及极易混淆的冷门细节，故低于4。
- **K2 = 2**: 2 — 仅需简单的减法运算（32-8-4-4=16）和已知的补码范围记忆。数字友好，无复杂计算。若认为需要计算补码真值转换过程则高估，实际上只需回忆16位补码范围结论。
- **K3 = 2**: 2 — 路径唯一且极短：总位数 -> 减去操作码 -> 减去源寄存器 -> 减去基址寄存器 -> 得到偏移量位数 -> 查表/记忆范围。无需多步串行状态推演。
- **K4 = 3**: 3 — 存在明确的陷阱词“基址寻址”和隐含前提“偏移量为有符号数”。若不触发对基址寻址机制本质的理解（即需要正负偏移来访问基址前后的内存），极易误选无符号数范围，属于标准陷阱。
- **K5 = 1**: 1 — 单一知识点（指令格式设计）内部解决，不涉及存储系统、总线或I/O等其他模块的数据传递。
- **雷达形状**: K4陷阱型

## 考察模式
- **模式**: 计算型
- **理由**: 题干给出具体参数（32位指令，16寄存器，8位操作码等），四个选项为具体的数值范围，考生需通过计算位数和查表/记忆范围得出唯一数值结果。

## 选项级分析
- **选项A**: [正确] — 正确计算偏移量位数（16位），并正确识别基址寻址偏移量为补码，范围 [-32768, +32767]。
- **选项B**: [干扰] — 针对认知错误：补码范围边界记反（如认为最大值为 -1 或最小值为 32767 等混乱），或者对补码表示的对称性理解偏差。通常选此项的学生对补码最小值 $-2^{n-1}$ 记忆模糊。
- **选项C**: [干扰] — 针对认知错误：将偏移量误判为无符号数，或者位数计算错误。若误以为基址寻址偏移量必须为正（无符号），则会计算 $0 \sim 2^{16}-1$ 即 $0 \sim 65535$。这是最常见的概念混淆，忽略了基址寻址需要向后访问（负偏移）的能力。
- **选项D**: [干扰] — 针对认知错误：无符号数范围边界记反，或与其他编码（如原码/反码）的范围混淆。可能对应 $0 \sim 65535$ 的某种错误变体，或者单纯为了凑数设计的错误范围。
- **干扰策略**: 并行陷阱（各干扰项独立）

## 核心陷阱
- **核心陷阱**: 基址寻址中偏移量的符号属性判断。基址寻址的核心优势在于支持大地址空间和位置无关代码，因此偏移量通常是有符号数（补码），以支持相对于基址的前后访问。许多学生潜意识认为“地址/偏移”都是无符号的，从而落入无符号数范围的陷阱。
- **错误路径**: 学生正确计算出偏移量占16位，但直接套用“16位二进制数的范围”这一模糊概念，默认其为无符号数（0-65535），忽略了寻址机制中“基址+位移”对负位移的需求。

## 考察能力
本题考察考生对指令格式各字段位数的精确分配能力，以及对基址寻址机制本质（支持负偏移的有符号位移量）的深刻理解。
