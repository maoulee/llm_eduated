# 练习题 Q1 — TCP/UDP 流量与拥塞控制机制辨析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
以下哪些陈述是正确的？
(S1) TCP 同时处理拥塞控制和流量控制
(S2) UDP 处理拥塞控制但不处理流量控制
(S3) 快速重传机制处理拥塞控制但不处理流量控制
(S4) 慢启动机制同时处理拥塞控制和流量控制

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。本题需要考生清晰区分“流量控制”与“拥塞控制”这两个极易混淆的核心概念，并准确记忆 TCP 和 UDP 的功能差异，以及快速重传、慢启动等具体机制的归属。这不仅仅是回忆定义，更是对多个易混概念（Flow Control vs Congestion Control, TCP vs UDP, Specific Mechanisms）的辨析，符合 K1 锚点中“需辨析两个以上易混概念则 4-5”的标准。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，完全属于定性判断，因此计算需求为微弱。
- **K3 = 2**: 评分理由。解题过程主要是对四个陈述进行独立的真假判断，虽然涉及机制原理，但不需要多步串行推演或状态跟踪。只需调用已知知识点对每个陈述进行验证，步骤简单直接。
- **K4 = 3**: 评分理由。存在明显的概念陷阱。例如，S2 中 UDP 是否处理拥塞控制是一个常见的认知误区（部分学生可能误以为 UDP 完全无控制或反之）；S4 中慢启动虽然影响发送速率，但其本质是拥塞控制算法的一部分，而非流量控制（流量控制由接收方窗口 rwnd 决定）。识别这些隐含的前提和机制的本质归属需要一定的深度理解，属于常规注意点与陷阱词的结合。
- **K5 = 2**: 评分理由。题目主要聚焦于传输层内部机制，虽然提到了 TCP 和 UDP 的对比，但不需要跨越网络层、链路层或应用层进行复杂的状态传递或联动分析。提及无关子系统（如网络层拥塞）仅作为背景知识，不构成解题的必要联动。

- **雷达形状**: K1 高认知型（概念辨析主导，无计算，轻度陷阱）

## 考察模式
- **模式**: 概念型
- **理由**: 本题完全依赖于对计算机网络传输层核心概念（流量控制、拥塞控制、TCP/UDP 特性、拥塞控制算法）的定义理解和辨析能力，不涉及数值计算或复杂的逻辑推演链条。

## 选项级分析
- **选项 A**: [干扰] — 针对错误认知：认为 UDP 处理拥塞控制（S2 错误），且可能误认为慢启动涉及流量控制（S4 错误）。这类学生可能混淆了“控制发送速率”这一表象，认为只要控制速率就是流量控制，或者误以为 UDP 有某种隐式的拥塞反馈机制。
- **选项 B**: [正确] — S1 正确（TCP 通过 rwnd 做流量控制，cwnd 做拥塞控制）；S2 错误（UDP 无拥塞控制）；S3 正确（快速重传是拥塞控制/可靠性机制，与接收方窗口无关）；S4 错误（慢启动是拥塞控制算法，与流量控制无关）。
- **选项 C**: [干扰] — 针对错误认知：认为 S1 错误（可能误以为 TCP 只做拥塞控制或只做流量控制），且认为 S4 正确。这类学生可能未能理解 TCP 是同时具备两种控制能力的协议，或者错误地将慢启动归类为流量控制。
- **选项 D**: [干扰] — 针对错误认知：认为 S4 正确。这类学生可能混淆了“拥塞窗口”和“接收窗口”的作用，认为慢启动调整窗口大小就等同于流量控制，忽略了流量控制是由接收方能力决定的这一核心区别。

- **干扰策略**: 概念混淆（主要混淆流量控制与拥塞控制的边界，以及 UDP 的功能边界）

## 核心陷阱
- **核心陷阱**: **混淆“流量控制”与“拥塞控制”的机制归属**。
    - 流量控制（Flow Control）：点对点，防止发送方压垮接收方，由接收方通告窗口（rwnd）决定。
    - 拥塞控制（Congestion Control）：端到端/全局，防止发送方压垮网络，由拥塞窗口（cwnd）决定。
    - 陷阱点：慢启动、快速重传、拥塞避免等算法均属于**拥塞控制**范畴，它们调整的是 cwnd，而非 rwnd。因此 S4 错误，S3 正确（快速重传虽主要解决丢包/乱序，但在 TCP 语境下常与拥塞控制联动，且肯定不属于流量控制）。S2 的错误在于 UDP 是“无连接、不可靠”的，既无流量控制也无拥塞控制。

## 考察能力
本题核心考察考生对传输层流量控制与拥塞控制机制的本质区别、TCP/UDP 协议特性以及具体拥塞控制算法（慢启动、快速重传）功能归属的精准辨析能力。
