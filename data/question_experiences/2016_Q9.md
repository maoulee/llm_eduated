# 2016 Q9 — 跳跃式顺序查找与折半查找的比较

## 基本信息
- **年份**: 2016  **题位**: Q9  **题型**: 选择题
- **知识点**: DS-7 > 7.2 顺序查找和折半查找 > 折半查找, DS-7 > 7.2 顺序查找和折半查找 > 顺序查找
- **题位域**: DS-4  **科目**: 数据结构

## 题干原文
在有 n(n>1000) 个元素的升序数组 A 中查找关键字 x。查找算法的伪代码如下所示。
k = 0;
while (k < n 且 A[k] < x) k = k + 3;
if (k < n 且 A[k] == x) 查找成功；
else if (k - 1 < n 且 A[k - 1] == x) 查找成功；
else if (k - 2 < n 且 A[k - 2] == x) 查找成功；
else 查找失败；
本算法与折半查找算法相比，有可能具有更少比较次数的情形是（）
数组查找
- 选项:
  A: 当 x 不在数组中
  B: 当 x 接近数组开头处
  C: 当 x 接近数组结尾处
  D: 当 x 位于数组中间位置
- 正确答案: B
- 解析（参考）: 此题为送分题。该程序采用跳跃式的顺利查找法查找升序数组中的 X, 显然是 x 越靠前，比较次数才会越少。
- 知识标签: ['DS-7 > 7.2 顺序查找和折半查找 > 折半查找', 'DS-7 > 7.2 顺序查找和折半查找 > 顺序查找']
- 知识域: DS-7

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“顺序查找”和“折半查找”的基本定义及时间复杂度特征。不是2分因为仅靠直觉无法准确对比两者在特定位置下的比较次数，需调用平均/最好/最坏情况的概念；不是4分因为不涉及复杂概念辨析，只需知道折半查找是 $O(\log n)$ 且对位置不敏感，而顺序查找是 $O(n)$ 且对位置敏感。
- **K2 = 2**: 评分理由。无需复杂计算，仅需定性分析。最复杂的单步是理解 `k=k+3` 意味着步长为3，这属于基础逻辑，几乎不会算错。
- **K3 = 2**: 评分理由。推演步骤较少。只需模拟两种算法在“开头”、“中间”、“结尾”三种典型场景下的行为。从输入到输出只需1-2步逻辑判断：折半查找无论在哪都要跳 $\log n$ 次，跳跃查找在开头只需跳几次。
- **K4 = 3**: 评分理由。存在隐含前提和陷阱。陷阱在于学生容易惯性思维认为“折半查找永远比顺序查找快”，从而忽略题目问的是“有可能具有更少比较次数”。需要识别出“跳跃式查找”在特定分布（靠前）下的优势，避开“折半查找最优”的绝对化认知陷阱。
- **K5 = 1**: 评分理由。单系统问题。仅涉及查找算法内部的逻辑比较，无需跨越不同子系统或模块传递状态。
- **雷达形状**: K4陷阱型（K4相对较高，其他维度较低，呈现明显的陷阱识别特征）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不要求精确计算比较次数，而是要求考生根据算法的执行逻辑（步长跳跃 vs 二分跳跃），推理出在不同数据分布下两种算法的性能差异。核心在于理解算法机制对数据位置的依赖性。

## 选项级分析
- **选项A**: [干扰] — 针对“失败情况”的误解。当 x 不在数组中时，折半查找需要执行完整的 $\log_2 n$ 次比较才能确定失败；而跳跃查找如果 x 很小（小于 A[0]），只需1次比较（A[0]<x 为假）即可退出循环并判断失败，确实可能更少。但题目通常考察“查找成功”的典型场景，且若 x 很大，跳跃查找需遍历整个数组，比较次数远多于折半。虽然A在特定子情况（x极小）下成立，但B选项“接近开头”涵盖了x存在且靠前的情况，是更普遍且符合出题意图的“查找成功”场景。此外，若x不在数组中且值很大，跳跃查找需 $n/3$ 次比较，远大于折半。因此A不是“有可能”的最佳概括，或者说B更具代表性。*注：严格来说，若x < A[0]，跳跃查找1次比较，折半查找 $\log n$ 次，A也成立。但考研真题中，B选项“接近开头”通常隐含x存在或x较小，是顺序类查找的优势区间。相比之下，A选项“不在数组中”是一个集合，包含x极大和x极小两种情况，x极大时跳跃查找极慢，因此A作为整体情形不如B准确。*
- **选项B**: [正确] — 针对“位置敏感性”的正确认知。当 x 接近数组开头时，跳跃查找只需很少的几次循环（例如 x 在 A[0]~A[2] 之间，循环0-1次）即可找到或确定范围，比较次数为常数级 $O(1)$。而折半查找无论 x 在哪，都需要 $O(\log n)$ 次比较。当 $n > 1000$ 时，$\log_2 1000 \approx 10$，显然 $1 < 10$，跳跃查找更快。
- **选项C**: [干扰] — 针对“最坏情况”的混淆。当 x 接近数组结尾时，跳跃查找需要遍历大部分数组，比较次数约为 $n/3$，即 $O(n)$。折半查找仍为 $O(\log n)$。此时折半查找远快于跳跃查找。
- **选项D**: [干扰] — 针对“平均情况”的误解。当 x 位于中间时，跳跃查找平均需要 $n/6$ 次比较，折半查找需要 $\log n$ 次。对于 $n > 1000$，$n/6 \gg \log n$，折半查找更快。

- **干扰策略**: 概念混淆。利用考生对“折半查找效率最高”的刻板印象，诱导其排除所有顺序查找相关的选项，或者让考生在A和B之间犹豫，考察对“比较次数”具体量级的敏感度。

## 核心陷阱
- **核心陷阱**: **算法效率的绝对化误区**。许多考生认为折半查找在所有情况下都比顺序查找（及其变种）快。本题陷阱在于指出：对于**位置靠前**的数据，线性扫描（即使是跳跃式）的常数开销远小于折半查找的对数开销。考生需打破“折半查找永远最优”的思维定势，关注 $O(1)$ 与 $O(\log n)$ 在常数项上的巨大差异。

## 考察能力
一句话概括本题核心考察的能力：
**能够根据算法的执行机制（步长与跳转策略），定性分析不同数据分布位置对查找比较次数的影响，并打破对经典算法效率的绝对化认知。**
