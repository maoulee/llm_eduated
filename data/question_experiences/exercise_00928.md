# 练习题 Q1 — fork() 进程创建数量计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
一个进程执行以下代码：
for
(
i

i
<

++

fork

创建的子进程总数是（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 `fork()` 系统调用的核心语义（复制当前进程，父子进程均继续执行后续代码）以及进程树的基本概念。不是1分因为仅靠常识无法解题，需调用操作系统核心定义；不是4分因为不涉及多个易混概念（如 `vfork` 或 `exec`）的深度辨析。
- **K2 = 2**: 评分理由。计算过程本质上是等比数列求和或二进制幂次计算（$2^n - 1$）。对于熟悉计算机基础的学生，2的幂次是非常友好的计算，不易出错。
- **K3 = 3**: 评分理由。需要多步串行推演。考生需要在脑海中模拟循环执行的过程：第0次循环产生1个子进程，第1次循环时原有2个进程各产生1个子进程（共2个），第2次循环时4个进程各产生1个子进程（共4个）... 直到第n-1次。这需要3-5步的逻辑推演来建立通项公式。
- **K4 = 3**: 评分理由。存在常规注意点/陷阱。最大的陷阱在于“创建的子进程总数”与“最终存在的进程总数”的区别。题目问的是“创建的子进程”，即排除初始父进程，答案为 $2^n - 1$；若问“总进程数”则为 $2^n$。此外，需意识到 `fork` 后父子进程都会执行循环体，这是隐含的执行流逻辑。
- **K5 = 1**: 评分理由。单系统内部问题。仅涉及进程管理模块内的进程创建机制，不涉及内存管理、文件系统或I/O子系统的状态传递或耦合。
- **雷达形状**: K3/K4 主导型（推理与陷阱并存）。K1基础适中，K2计算简单，但K3的推演步骤和K4的概念辨析（子进程vs总进程）构成了主要难度。

## 考察模式
- **模式**: 推理型
- **理由**: 虽然结果是一个数值，但解题关键不在于直接套用公式，而在于理解 `fork()` 执行后的控制流分裂机制，并通过逻辑推演得出进程数量的指数级增长规律。

## 选项级分析
- **选项A**: [干扰] — 针对线性思维错误。这类学生认为循环执行n次，每次创建一个进程，所以总共创建n个。他们忽略了 `fork()` 后子进程也会继续执行循环体这一关键机制。
- **选项B**: [正确] — 正确推导结果。初始1个进程，经过n次分裂，总进程数为 $2^n$，减去初始的1个父进程，创建的子进程数为 $2^n - 1$。
- **选项C**: [干扰] — 针对简单倍数误解。这类学生可能误以为每次循环进程数翻倍，但错误地将其理解为线性叠加或简单的2倍关系，或者混淆了 $2n$ 与 $2^n$ 的概念。
- **选项D**: [干扰] — 针对指数偏移错误。这类学生可能记错了公式，或者误以为循环从 $i=1$ 开始，或者混淆了 $2^{n+1}$ 的含义（通常对应 n+1 次 fork）。

**干扰策略**: 概念混淆（线性vs指数）与 计算陷阱（子进程数vs总进程数）。

## 核心陷阱
- **核心陷阱**: **控制流的并发执行理解**与**统计口径的混淆**。
    1.  **并发执行**：很多初学者误以为只有父进程在执行循环，子进程创建后就退出了或不再执行循环。实际上，`fork()` 返回后，父子进程都从 `fork()` 之后继续执行，因此子进程也会参与后续的 `fork()` 调用，导致进程数指数级增长。
    2.  **统计口径**：题目问的是“创建的子进程总数”，而非“最终系统中的进程总数”。总进程数是 $2^n$，子进程数是 $2^n - 1$。

## 考察能力
一句话概括本题核心考察的能力：对 `fork()` 系统调用后父子进程控制流同步执行机制的理解及指数级进程生成的逻辑推演能力。
