# 练习题 Q1 — TCP最大有效载荷计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
TCP 段的最大有效载荷是（ ）：

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆 TCP 头部最小长度（20字节）以及 TCP 序号/确认号字段长度（16位，即最大窗口65535）这两个核心概念。不是4分因为不需要辨析多个易混概念，只需调用标准定义。
- **K2 = 2**: 评分理由。涉及简单的减法运算（65535 - 20 - 20），属于2的幂次附近的整数运算，计算量极小，不易出错。
- **K3 = 1**: 评分理由。从输入到输出仅需一步逻辑：最大载荷 = 最大窗口 - 头部开销。无需多步串行推演。
- **K4 = 4**: 评分理由。存在显著的隐含前提和概念陷阱。题面问的是“TCP段”的有效载荷，但解析中却减去了“IP头部”。这是一个严重的概念混淆陷阱（或者题目本身表述不严谨，将“IP数据报中的TCP有效载荷”与“TCP段的有效载荷”混为一谈，或者考察的是端到端视角下的最大数据量）。考生必须意识到题目可能隐含了“在IP层封装下”或者题目本身存在定义歧义，需要识别出“TCP段”通常指TCP Header + Data，而解析逻辑却是 IP Header + TCP Header + Data 的总限制。*注：严格来说，TCP段（TCP Segment）的最大有效载荷仅受TCP头部长度限制，即65535-20=65515。但本题解析强行引入IP头部，说明题目考察的是“一个IP数据报中，TCP能携带的最大数据量”或者题目表述有误。这种“题面与解析逻辑不一致”或“隐含网络层封装”的条件属于高难度陷阱。*
- **K5 = 3**: 评分理由。需要跨越传输层（TCP）和网络层（IP）两个子系统。虽然主要是单向的数据封装关系，但解题必须理解TCP段是作为IP数据报的载荷存在的，且受IP最大长度（16位总长度字段）的限制。

- **雷达形状**: K4陷阱型（高K4，低K2/K3，中K1/K5）

## 考察模式
- **模式**: 综合型（偏向概念辨析与陷阱识别）
- **理由**: 表面看是简单的减法计算，实则考察对协议分层结构、头部开销以及“段”与“数据报”边界定义的深刻理解。如果仅按字面意思“TCP段”计算，答案应为B；若按解析逻辑（隐含IP封装限制），答案为C。这种模式要求考生不仅会算，还要识别出题目的潜在语境或陷阱。

## 选项级分析
- **选项A**: [干扰] — 针对什么错误认知：认为最大有效载荷等于最大窗口值（65,535）。这类学生忽略了TCP头部本身占用空间，或者混淆了“窗口大小”与“有效载荷”的概念。
- **选项B**: [干扰/理论正确] — 针对什么错误认知：严格遵循“TCP段”定义。TCP段 = TCP Header + Data。最大总长度65535，最小TCP头20，故最大Data = 65515。这类学生概念清晰，但可能未意识到题目隐含了IP层的限制（或题目本身出题不严谨，将IP数据报的最大载荷当作了TCP段的有效载荷）。在标准408考试中，若问“TCP段”，通常选B；若问“IP数据报中TCP数据部分最大长度”，则选C。本题解析选C，说明题目语境隐含了IP层限制。
- **选项C**: [正确] — 针对什么错误认知：无。这是基于解析逻辑（减去IP头和TCP头）得出的答案。这类学生识别出了题目隐含的“IP数据报最大长度限制”这一前提，或者接受了题目将“TCP有效载荷”定义为“应用层数据在IP层视角下的最大长度”。
- **选项D**: [干扰] — 针对什么错误认知：计算错误或头部长度记忆错误。例如误以为TCP或IP头部更大，或者进行了错误的多级换算。

- **干扰策略**: 概念混淆（TCP段 vs IP数据报载荷）与计算陷阱（是否减去IP头）

## 核心陷阱
- **核心陷阱**: **层级边界混淆**。题目问的是“TCP段”的有效载荷，但解析逻辑却减去了“IP头部”。严格定义下，TCP段不包含IP头部。此题的核心陷阱在于考生是否意识到题目实际上是在问“在一个最大长度的IP数据报中，TCP能携带的最大应用层数据量”，或者考生是否会被“TCP段”这个术语误导而只减去TCP头部（选B）。对于408考生，需警惕此类表述不严谨的题目，通常需结合选项分布（B和C同时存在）来判断出题人意图：若考察纯TCP，选B；若考察网络层对传输层的限制，选C。鉴于解析选C，陷阱在于**隐含了IP层的封装开销**。

## 考察能力
一句话概括本题核心考察的能力：在协议分层模型中，准确识别不同层级头部开销对有效载荷的限制，并辨析“TCP段”与“IP数据报”载荷边界的能力。
