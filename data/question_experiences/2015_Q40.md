# 2015 Q40 — HTTP请求报文解析与连接控制

## 基本信息
- **年份**: 2015  **题位**: Q40  **题型**: 选择题
- **知识点**: CN-6 > 万维网 WWW > HTTP协议, CN-6 > 万维网 WWW > HTTP请求报文
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
某浏览器发出的 HTTP 请求报文如下（ ）。
GET /index .html HTTP/1.1
Host: www.test.edu.cn
Connection: close
Cookie: 123456
下列叙述中，错误的是
HTTP
- 选项:
  A: 该浏览器请求浏览 index.html
  B: index.html 存放在 www.test.edu.cn 上
  C: 该浏览器请求使用持续连接
  D: 该浏览器曾经浏览过 www.test.edu.cn

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆 HTTP 请求报文的基本结构及各字段含义（如 GET 方法、Host 字段、Connection 字段、Cookie 字段）。属于标准的基础概念记忆，不涉及复杂公式或深层原理推导。不是 2 分因为需要准确区分 `Connection: close` 和 `keep-alive` 的具体语义，而非仅仅知道有这两个词。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或复杂的逻辑转换。只需对文本信息进行语义匹配。
- **K3 = 1**: 评分理由。推演步骤极少。看到 `GET /index.html` 直接对应选项 A；看到 `Host` 对应选项 B；看到 `Connection: close` 直接判断选项 C 的正误；看到 `Cookie` 对应选项 D。无需多步串行推演。
- **K4 = 3**: 评分理由。存在明显的“陷阱词”和易混淆概念。`Connection: close` 是 HTTP/1.1 的默认行为之外的显式关闭指令，很多学生容易误以为 HTTP/1.1 默认就是持续连接从而忽略该字段，或者混淆 `close` 与 `keep-alive` 的含义。此外，需要理解 Cookie 的存在隐含了“曾经访问过”这一历史状态，这属于隐含前提的识别。
- **K5 = 1**: 评分理由。本题仅涉及应用层 HTTP 协议内部的报文解析，不涉及与其他子系统（如 TCP 传输层、IP 网络层或操作系统内核）的状态联动或数据传递。

- **雷达形状**: K4 陷阱型（K1 基础记忆为主，K4 概念辨析为关键，无计算压力）

## 考察模式
- **模式**: 概念型
- **理由**: 题目核心在于考察考生对 HTTP 协议标准中各个头部字段（Header Fields）定义的理解和记忆。解题过程依赖于对协议规范的直接认知，而非逻辑推理或数学计算。

## 选项级分析
- **选项 A**: [正确叙述] — 针对对 HTTP 请求行（Request Line）的理解。`GET /index.html` 明确表示请求获取资源 `index.html`。学生若不懂 HTTP 请求行结构可能会误选，但这是最基础的知识点。
- **选项 B**: [正确叙述] — 针对对 `Host` 字段的理解。`Host: www.test.edu.cn` 指定了目标服务器的主机名，意味着资源位于该服务器上。这是 HTTP/1.1 引入 Host 字段的主要原因（支持虚拟主机）。
- **选项 C**: [错误叙述/正确答案] — 针对对 `Connection` 字段含义的混淆。题干中明确给出 `Connection: close`，这表示请求完成后关闭连接，即**非持续连接**（Non-persistent connection）。而选项称“请求使用持续连接”，与题干矛盾。这是本题的核心考点，考察 `close` vs `keep-alive` 的区别。
- **选项 D**: [正确叙述] — 针对对 `Cookie` 机制的理解。Cookie 是服务器在之前响应中通过 `Set-Cookie` 发送给客户端，客户端在后续请求中自动携带的。请求报文中出现 `Cookie: 123456`，说明浏览器之前访问过该服务器并接收到了 Cookie，因此“曾经浏览过”是正确的推断。

- **干扰策略**: 概念混淆。利用 HTTP/1.1 默认使用持续连接（keep-alive）的常识，诱导学生忽略显式的 `Connection: close` 字段，或者让学生误以为 `close` 是某种特殊的持续连接模式。同时利用 Cookie 的隐含历史属性作为次要干扰项，增加判断难度。

## 核心陷阱
- **核心陷阱**: **`Connection: close` 与持续连接（Persistent Connection）的概念对立**。
  许多考生知道 HTTP/1.1 默认是持续连接，但忽略了报文头部可以显式覆盖默认行为。`Connection: close` 明确指示连接将在本次事务后关闭，因此选项 C 说“使用持续连接”是错误的。考生需具备“显式配置优于默认配置”的意识，并准确记忆 `close` 代表断开连接。

## 考察能力
本题核心考察考生对 HTTP 请求报文各头部字段语义的精准记忆及辨析能力，特别是对连接控制字段（Connection）和状态保持机制（Cookie）的理解。
