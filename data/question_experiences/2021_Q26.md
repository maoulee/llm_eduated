# 2021 Q26 — 磁盘调度算法(SSTF)

## 基本信息
- **年份**: 2021  **题位**: Q26  **题型**: 选择题
- **知识点**: 磁盘调度算法, 最短寻道时间优先算法, 操作系统>磁盘调度算法
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
某系统中磁盘的磁道数为 200 (0~199), 磁头当前在 184 号磁道上。用户进程提出的磁盘访问请求对应的磁道号依次为 184, 187, 176, 182, 199。若采用最短寻道时间优先调度算法 (SSTF) 完成磁盘访问，则磁头移动的距离（磁道数）是（ ）。

A. 37
B. 38
C. 41
D. 42

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 SSTF（最短寻道时间优先）算法的核心定义：总是选择距离当前磁头位置最近的磁道进行访问。这属于操作系统中磁盘调度部分的标准核心概念，不涉及复杂辨析，但必须明确“最近”是指物理距离而非请求顺序。
- **K2 = 2**: 评分理由。计算过程仅涉及简单的整数加减法（如 $|184-182|=2$），数值较小且均为整数，不存在复杂的幂次运算或多级单位换算，计算出错概率极低。
- **K3 = 3**: 评分理由。解题过程需要串行推演 5 个步骤（对应 5 个请求）。每一步都需要基于上一步的“当前磁头位置”重新计算剩余请求的距离并排序，属于典型的 3-5 步多步推演，需要保持中间状态（当前磁头位置）的准确性。
- **K4 = 2**: 评分理由。存在一个常规注意点：请求队列中第一个请求是 184，与当前磁头位置 184 相同。考生需意识到此时移动距离为 0，且磁头位置不变，继续处理下一个请求。这属于常规逻辑判断，非深层隐含前提或反直觉陷阱。
- **K5 = 1**: 评分理由。本题完全局限于操作系统磁盘调度子系统内部，不涉及文件系统、内存管理或 CPU 调度等其他子系统的状态传递或耦合，属于单系统独立问题。
- **雷达形状**: K3 推演主导型（K3 略高，K1 标准，其余较低，整体呈平稳偏推演特征）

## 考察模式
- **模式**: 推理型
- **理由**: 虽然包含简单的加法计算，但题目的核心难点不在于计算本身，而在于根据 SSTF 算法的动态规则，一步步推演磁头的移动路径。考生必须模拟算法执行过程，确定访问序列，而非直接套用公式。

## 选项级分析
- **选项 A**: [干扰] — 针对**忽略当前磁头位置或计算错误**的认知。如果考生错误地认为从 184 开始，先访问 187 (距离3)，再访问 199 (距离12)，再访问 182 (距离17)，再访问 176 (距离6)，总和 $3+12+17+6=38$ (接近B)，或者在累加过程中出现漏加或减错，可能得到 37。更可能的情况是，考生错误地按照 FCFS（先来先服务）计算：$0+3+11+6+17=37$。
  - *修正分析*：让我们重新计算 FCFS：
    - 184 -> 184: 0
    - 184 -> 187: 3
    - 187 -> 176: 11
    - 176 -> 182: 6
    - 182 -> 199: 17
    - 总和: $0+3+11+6+17 = 37$。
  - 因此，选项 A 是典型的 **FCFS（先来先服务）算法** 的结果。这类学生混淆了调度算法，直接按请求顺序计算。

- **选项 B**: [干扰] — 针对**SSTF 推演中途出错或方向判断失误**的认知。例如，在访问完 182 后，磁头在 182，剩余请求 187, 176, 199。距离分别为 5, 6, 17。最近的是 187。访问 187 后，磁头在 187，剩余 176, 199。距离分别为 11, 12。最近的是 176。访问 176 后，磁头在 176，剩余 199。距离 23。
  - 正确路径：184->184(0)->182(2)->187(5)->176(11)->199(23)。总和 41。
  - 如果考生在 182 处，错误地认为 176 (距离6) 比 187 (距离5) 更近？不可能，5<6。
  - 如果考生在 187 处，错误地认为 199 (距离12) 比 176 (距离11) 更近？不可能，11<12。
  - 另一种可能：考生忽略了第一个请求 184，直接从 184 开始看 187, 176, 182, 199。
    - 184 -> 182 (2)
    - 182 -> 187 (5)
    - 187 -> 176 (11)
    - 176 -> 199 (23)
    - 总和 41。
  - 让我们看看 B=38 怎么来的。可能是 $41-3=38$？或者 $37+1=38$？
  - 还有一种常见的错误路径：184 -> 187 (3) -> 182 (5) -> 176 (6) -> 199 (23)。总和 $3+5+6+23 = 37$ (这是A)。
  - 如果路径是：184 -> 182 (2) -> 176 (6) -> 187 (11) -> 199 (12)。总和 $2+6+11+12 = 31$。
  - 如果路径是：184 -> 187 (3) -> 199 (12) -> 182 (17) -> 176 (6)。总和 $3+12+17+6 = 38$。
  - 这个路径 (184->187->199->182->176) 的逻辑错误在于：在 187 时，剩余 176, 182, 199。距离分别是 11, 5, 12。最近的是 182。如果考生错误地选择了 199（可能看错了数字或距离），就会进入这个分支。或者在 184 时，错误地先选了 187（距离3）而不是 182（距离2）？不，2<3。
  - 最可能的 B 选项来源：考生正确计算了前几步，但在最后一步或某一步加法出错，或者混淆了 SCAN 算法的某些变体。但在 SSTF 中，38 是一个典型的“接近正确答案但有一处逻辑偏差”的干扰项，或者仅仅是随机凑数。不过，考虑到 A 是 FCFS，B 很可能是某种错误的 SSTF 路径或计算失误。

- **选项 C**: [正确] — 正确应用 SSTF 算法。
  - 当前 184。请求：184, 187, 176, 182, 199。
  - 1. 选 184 (距离0)。当前 184。剩余：187, 176, 182, 199。
  - 2. 距离：|187-184|=3, |176-184|=8, |182-184|=2, |199-184|=15。最近 182。移动 2。当前 182。剩余：187, 176, 199。
  - 3. 距离：|187-182|=5, |176-182|=6, |199-182|=17。最近 187。移动 5。当前 187。剩余：176, 199。
  - 4. 距离：|176-187|=11, |199-187|=12。最近 176。移动 11。当前 176。剩余：199。
  - 5. 距离：|199-176|=23。移动 23。
  - 总距离：$0 + 2 + 5 + 11 + 23 = 41$。

- **选项 D**: [干扰] — 针对**SCAN 算法或 C-SCAN 算法混淆**的认知。
  - 如果采用 SCAN（电梯算法），假设磁头向磁道号增加方向移动（或减少，需看题目隐含，通常若无说明需讨论，但 SSTF 无方向性）。
  - 若向大方向：184->187->199 (到边界或无请求则回头)。184->187(3)->199(12)。然后回头 199->182(17)->176(6)。总和 $3+12+17+6=38$ (这是B)。
  - 若向小方向：184->182(2)->176(8)。然后回头 176->187(11)->199(12)。总和 $2+8+11+12=33$。
  - 选项 D (42) 可能是 $41+1$ 的计算错误，或者是某种特定的错误路径。例如，如果在第 4 步，从 187 去 199 (12) 而不是 176 (11)，路径变为 184->182(2)->187(5)->199(12)->176(23)。总和 $2+5+12+23=42$。
  - 这个错误路径的逻辑是：在磁头位于 187 时，剩余请求 176 和 199。距离分别是 11 和 12。考生可能误判 199 更近，或者看错数字，导致选择了 199。这是非常典型的“贪心算法局部最优判断失误”陷阱。

- **干扰策略**: 
  - A: 概念混淆（FCFS vs SSTF）
  - B: 算法混淆（SCAN 单向）或 路径错误
  - D: 局部贪心判断失误（在 187 处选错最近点）

## 核心陷阱
- **核心陷阱**: **动态最近邻的重新评估**。SSTF 算法的关键在于“每一步”都要重新计算剩余请求与“当前磁头位置”的距离。考生容易犯的错误是：
  1. 忽略第一个请求 184 与当前位置相同，导致后续基准点错误。
  2. 在磁头移动到新位置后，没有更新“当前磁头位置”，而是继续基于初始位置 184 计算距离。
  3. 在距离非常接近时（如 11 vs 12），发生判断失误，导致路径分叉，从而得到选项 D。

## 考察能力
本题核心考察考生对 **SSTF 磁盘调度算法动态执行过程** 的模拟能力，以及在多步推演中保持状态（当前磁头位置）准确性的逻辑严谨性。
