# 练习题 Q1 — 双指针/滑动窗口时间复杂度分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
下面函数的时间复杂度是多少？
```c
void fun(int n, int arr[]) {
    int i = 0, j = 0;
    for (; i < n; ++i)
        while (j < n && arr[i] < arr[j])
            j++;
}
```

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“时间复杂度”的基本定义以及大O表示法的含义。不是2分因为仅靠直觉无法准确判断嵌套循环的复杂度，必须调用算法分析的核心概念（基本操作执行次数）。
- **K2 = 2**: 评分理由。本题不涉及复杂的数学计算或公式推导，核心在于逻辑计数。最复杂的步骤是识别j的总移动次数，这属于简单的线性计数，非2幂次或多级换算，故难度较低。
- **K3 = 3**: 评分理由。需要推演代码执行流程。考生需模拟或逻辑推导i和j的变化关系：i从0到n-1递增，j从0开始只增不减。需要理解内层while循环的终止条件对j的影响，以及j的状态在for循环迭代间的保持。这属于3-5步的逻辑推演。
- **K4 = 4**: 评分理由。存在明显的“暗坑”。常规思维容易将嵌套循环直接判定为O(n²)，但本题的关键隐含前提是“j不重置”。考生必须识别出这一反直觉的条件（即内层循环变量在外层循环中保持状态），否则极易落入陷阱。这属于典型的陷阱词/隐含前提深的情形。
- **K5 = 2**: 评分理由。主要涉及单一控制流结构（循环嵌套），虽然涉及两个变量i和j的交互，但不需要跨越不同的数据结构子系统或模块，状态传递仅限于局部变量，耦合度较低。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，呈现明显的陷阱特征）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不能通过简单的公式代入或概念记忆直接得出答案，必须通过分析代码的执行逻辑，推理出变量j在整个程序运行过程中的总变化量，从而推导出时间复杂度。

## 选项级分析
- **选项A**: [正确] — 正确识别了j的单调递增特性。j在整个函数执行过程中最多增加n次（从0到n），而i增加n次。无论arr的内容如何，j++的总执行次数不超过n，i++执行n次，总操作次数与n呈线性关系，故为O(n)。
- **选项B**: [干扰] — 针对“嵌套循环即平方级”的错误认知。这类学生看到for套while，未仔细检查内层循环变量j是否重置，直接套用O(n²)的刻板印象。这是最常见的错误选项。
- **选项C**: [干扰] — 针对“分治/排序算法”的联想错误。这类学生可能看到数组操作就联想到快速排序或归并排序的O(n log n)，或者误以为这是一种特殊的二分查找变体，但实际上代码逻辑并非分治。
- **选项D**: [干扰] — 针对“复杂嵌套”的过度推断。这类学生可能认为逻辑非常复杂，或者混淆了某些高级算法的复杂度，属于随机猜测或严重误解。
- **干扰策略**: 概念混淆（将普通嵌套循环与双指针线性扫描混淆）+ 渐进陷阱（利用视觉上的嵌套结构诱导O(n²)判断）

## 核心陷阱
- **核心陷阱**: **内层循环变量j未重置**。考生容易忽略`int j = 0;`位于for循环外部，导致误判内层循环每次都会从头开始执行，从而错误地选择O(n²)。实际上，j在整个过程中只增不减，构成了典型的“双指针”或“滑动窗口”线性扫描模式。

## 考察能力
一句话概括本题核心考察的能力：识别代码中变量状态保持特性，并据此分析嵌套循环实际执行次数的能力。
