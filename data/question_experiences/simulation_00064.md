# 模拟题 Q1 — DMA数据传送路径

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: OS-5 > 5.1 I/O管理概述 > I/O方式
- **难度**: 待评估

## 题干原文
在 DMA 方式下，数据从内存传送到外设经过的路径是（ ）。

A. 内存 → 数据总线 → 外设
B. 内存 → 数据总线 → DMA → 外设
C. 内存 → CPU → 数据总线 → 外设
D. 外设 → 内存

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 DMA 控制器的核心组件（数据缓冲寄存器）及其在数据通路中的位置。不是 2 分因为仅知道“DMA 不经过 CPU”不足以选出 B，必须知道数据必须经过 DMA 控制器内部缓冲；不是 4 分因为不需要辨析多个易混概念，只需掌握 DMA 的基本硬件结构。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算或单位换算，属于纯概念性路径判断。
- **K3 = 2**: 评分理由。推演步骤较少。只需根据“内存 -> 总线 -> DMA控制器(缓冲) -> 外设”这一固定硬件连接逻辑进行 1-2 步的逻辑映射即可得出结论。
- **K4 = 2**: 评分理由。存在常规注意点，即区分“程序查询/中断方式”与“DMA 方式”的区别。陷阱在于容易忽略 DMA 控制器本身也是一个硬件实体，数据必须经过它，而不仅仅是“绕过 CPU”。没有深层隐含前提或反直觉陷阱。
- **K5 = 3**: 评分理由。涉及 CPU、内存、I/O 总线、DMA 控制器、外设等多个子系统/模块之间的数据流向。需要理解数据如何在这些不同硬件模块间单向传递。

- **雷达形状**: K1 主导的概念记忆型，K4 略有起伏（需避开“无控制器”误区），整体偏向基础概念辨析。

## 考察模式
- **模式**: 概念型
- **理由**: 题目直接考察 DMA 方式下数据传送的硬件路径这一核心定义，不涉及复杂计算或多步逻辑推理，主要依赖对操作系统 I/O 管理硬件架构的记忆和理解。

## 选项级分析
- **选项 A**: [干扰] — 针对“DMA 就是直接内存访问，所以直接连”的错误认知。这类学生可能认为“直接”意味着物理上或逻辑上完全跳过中间环节，忽略了 DMA 控制器作为协调者和缓冲器的存在。
- **选项 B**: [正确] — 符合 DMA 工作原理。数据从内存读出，通过系统总线传输到 DMA 控制器的数据缓冲寄存器，再由 DMA 控制器发送给外设。
- **选项 C**: [干扰] — 针对“所有 I/O 都经过 CPU”的传统错误认知。这类学生可能混淆了程序查询方式或中断方式（数据需经 CPU 寄存器中转）与 DMA 方式的区别，未能掌握 DMA “绕过 CPU”的核心特征。
- **选项 D**: [干扰] — 针对“方向搞反”或“完全无逻辑”的猜测。题干明确是“内存传送到外设”（输出），而此选项是“外设到内存”（输入），且路径描述不完整。

- **干扰策略**: 概念混淆（A vs B，是否经过 DMA 控制器）、机制混淆（C vs B，是否经过 CPU）、方向错误（D）。

## 核心陷阱
- **核心陷阱**: 误以为 DMA 方式下数据可以“凭空”从内存直接到达外设，忽略了 **DMA 控制器（DMAC）** 作为硬件中介的必要性。DMA 虽然不经过 CPU，但必须经过 DMA 控制器，数据在 DMA 控制器内部有缓冲寄存器的暂存过程。

## 考察能力
一句话概括本题核心考察的能力：准确理解并描述 DMA 方式下数据在内存、总线、DMA 控制器及外设之间的硬件传输路径。
