# 2013 Q45 — 生产者-消费者变体（容量限制+互斥访问）

## 基本信息
- **年份**: 2013  **题位**: Q45  **题型**: 综合题
- **知识点**: 同步问题设计, 操作系统>同步问题设计
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
某博物馆最多可以容纳 500 人同时参观，有一个出入口，该出入口一次仅允许一个人通过。参观者的活动描述如下：
cobegin
参观者进程 i:
{
 ...
 进门；
 ...
 参观；
 ...
 出门；
 ...
}
coend
请添加必要的信号量和 P、V（或 wait()、signal()）操作，以实现上述过程中的互斥与同步。要求写出完整的过程，说明信号量的含义并赋初值。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握信号量（Semaphore）的基本概念、P/V操作（wait/signal）的语义，以及互斥锁和同步信号量的区别。这是操作系统并发控制的核心定义，属于标准记忆需求。不是2分因为需要区分两种不同作用的信号量；不是4分因为不涉及复杂概念辨析。
- **K2 = 2**: 评分理由。本题不涉及数值计算，仅涉及信号量初值的设定（500和1）以及P/V操作的顺序排列。逻辑简单直接，无计算错误风险。
- **K3 = 3**: 评分理由。解题过程包含3-4个关键逻辑步骤：1. 识别资源限制（容量500）；2. 识别互斥资源（出入口）；3. 确定P/V操作顺序（先同步后互斥，或先互斥后同步需具体分析临界区）；4. 编写代码。步骤清晰，属于标准推演。
- **K4 = 4**: 评分理由。存在明显的隐含前提和易错陷阱。1. **死锁陷阱**：如果先P(mutex)再P(empty)，当博物馆满员时，第一个进入临界区的人持有mutex但阻塞在empty上，后续人无法进入临界区释放mutex，导致死锁。必须识别出“先检查容量，再竞争入口”或“在临界区内检查容量但需小心”的逻辑。2. **临界区范围**：进门和出门动作本身是互斥的，但“参观”不是。学生容易错误地将整个参观过程都锁住，或者遗漏出门时的互斥保护。
- **K5 = 2**: 评分理由。本题仅涉及操作系统进程同步这一单一子系统，不涉及与其他模块（如文件系统、网络、硬件中断）的深度耦合或状态传递。
- **雷达形状**: 偏向右侧的三角形，K4（条件路由/陷阱识别）突出，K1-K3中等，K2-K5较低。

## 考察模式
- **模式**: 算法设计型
- **理由**: 题目要求考生根据给定的场景描述，设计并编写出包含正确同步机制的并发控制代码。重点在于构造正确的逻辑结构，而非验证已有结论或进行数值计算。

## 解题思路分析
- **核心思路**: 将问题分解为两个独立的同步/互斥需求：
    1.  **容量控制（同步）**：博物馆最多容纳500人，这是一个典型的“生产者-消费者”模型中的缓冲区大小限制，或者说是“有限资源”问题。需要一个信号量 `empty` 表示剩余空位，初值为500。
    2.  **出入口互斥（互斥）**：出入口一次仅允许一人通过，这是一个典型的临界区互斥问题。需要一个信号量 `mutex`，初值为1。
    3.  **组合逻辑**：参观者进入前需先获取空位（P(empty)），然后竞争出入口（P(mutex)）；进门后释放出入口（V(mutex)）；参观结束后，再次竞争出入口（P(mutex)）出门，出门后释放空位（V(empty)）。
- **关键步骤**:
    1.  定义信号量：`semaphore empty = 500;` (表示剩余可容纳人数), `semaphore mutex = 1;` (表示出入口互斥锁)。
    2.  进入阶段：
        - `P(empty)`: 检查是否有空位，若无则等待。
        - `P(mutex)`: 申请进入出入口。
        - `进门`: 执行进门动作。
        - `V(mutex)`: 释放出入口，允许下一个人使用。
    3.  参观阶段：
        - `参观`: 在馆内活动，无需锁。
    4.  离开阶段：
        - `P(mutex)`: 申请使用出入口。
        - `出门`: 执行出门动作。
        - `V(mutex)`: 释放出入口。
        - `V(empty)`: 增加一个空位，唤醒等待进入的进程。
- **易错点**:
    1.  **死锁**：在入口处先 `P(mutex)` 后 `P(empty)`。如果博物馆已满，第一个进程拿到mutex后阻塞在empty，后续进程无法获取mutex，导致所有进程死锁。
    2.  **遗漏互斥**：只做了容量控制，忘记对“进门”和“出门”动作加互斥锁。
    3.  **临界区过大**：将“参观”过程也包含在mutex保护范围内，导致并发度极低，违背了题目“同时参观”的意图。
    4.  **信号量初值错误**：将empty初值设为1或mutex初值设为500。

## 核心陷阱
- **核心陷阱**: **P操作顺序导致的死锁**。
    这是本题最大的陷阱。许多学生会直觉地认为“进门”是一个原子动作，所以先锁门（P(mutex)）再检查人数（P(empty)）。然而，在信号量机制下，如果先执行 `P(mutex)`，进程就持有了互斥锁。此时若执行 `P(empty)` 发现人数已满而阻塞，该进程会一直持有 `mutex` 并等待。其他想进入的进程在 `P(mutex)` 处阻塞，想离开的进程（如果逻辑设计不当）也可能受影响。最关键的是，没有任何进程能进入临界区去执行 `V(empty)`（因为没人能进来也没人能出去更新状态，或者更准确地说，进来的路被堵死了）。
    *修正*：必须先 `P(empty)` 确保有空位，再 `P(mutex)` 进入临界区。或者，如果必须在临界区内判断，需要极其小心地设计，但标准解法是“先同步后互斥”用于资源获取阶段。

## 考察能力
本题核心考察考生对**进程同步与互斥机制的综合应用能力**，特别是识别**资源限制（同步）**与**临界资源访问（互斥）**的区别，以及避免**死锁**的逻辑思维能力。
