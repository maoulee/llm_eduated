# 练习题 Q1 — ALOHA信道负载计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/数据链路层
- **难度**: 待评估

## 题干原文
ALOHA 用户群体每秒产生 70 个请求。若时间被划分为 50 ms 的时隙单元，则信道负载为（ ）。
A: 4.25
B: 3.5
C: 350
D: 450

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆“信道负载（G）”在时隙ALOHA或纯ALOHA语境下的定义，即平均每个时隙产生的分组数（或请求数）。若仅知道吞吐量公式而不知道负载定义，无法解题。属于标准的核心定义记忆。
- **K2 = 3**: 评分理由。涉及单位换算（秒转毫秒）和除法运算。$1000/50 = 20$，$70/20 = 3.5$。虽然计算简单，但涉及非2的幂次换算（50ms），且需先求时隙数再求负载，属于标准的单步代入计算。
- **K3 = 1**: 评分理由。逻辑链条极短：已知速率和时隙长度 -> 计算每秒时隙数 -> 计算每时隙请求数。无需多步串行推演或状态记忆。
- **K4 = 2**: 评分理由。存在常规注意点，即必须识别“信道负载”是针对“时隙”而言的，而不是针对“秒”。如果忽略时隙划分，直接看70，可能会误选。属于常规的单位/定义对齐注意点。
- **K5 = 1**: 评分理由。仅涉及数据链路层的介质访问控制（MAC）子层概念，不涉及网络层、传输层或其他子系统的状态传递。

- **雷达形状**: K2计算主导型，K1基础支撑，整体难度较低，呈扁平状。

## 考察模式
- **模式**: 计算型
- **理由**: 题目给出了具体的数值参数（70个/秒，50ms），要求通过特定的公式（负载 = 请求速率 / 时隙速率）进行数值计算得出结果。虽然涉及概念定义，但最终落脚点在于数值运算。

## 选项级分析
- **选项A**: [干扰] — 针对计算错误。可能是学生将时隙长度误算或除法出错，例如误以为 $70 / (1000/50)$ 算错，或者混淆了纯ALOHA和时隙ALOHA的某些系数（如0.5或1/e等，但此处数值对不上典型系数，更像是随机干扰或严重计算失误）。
- **选项B**: [正确] — 正确计算结果。$G = \lambda \times T_{slot} = 70 \times 0.05 = 3.5$ 或 $G = 70 / (1000/50) = 3.5$。
- **选项C**: [干扰] — 针对单位换算缺失或乘法误用。学生可能直接用 $70 \times 50 = 3500$（数量级不对）或者 $70 \times 5 = 350$（误将50ms看作0.5s或其他错误换算）。更可能是直接用请求数乘以时隙数值（忽略单位），即 $70 \times 50 = 3500$ 的变体，或者误以为负载是每秒总请求数与时隙长度的乘积（无物理意义）。另一种可能是学生忘记除以时隙数，而是做了其他无关乘法。
- **选项D**: [干扰] — 针对完全错误的逻辑。可能是 $70 \times (1000/50) / 2$ 或其他胡乱组合。或者将50ms误认为0.05s后，错误地进行了 $70 / 0.05 = 1400$ 等计算后的取整或误读。实际上D选项450与常见错误路径关联较弱，属于强干扰项，旨在覆盖计算完全失控的学生。

- **干扰策略**: 计算陷阱。主要利用单位不统一（秒 vs 毫秒）以及公式方向错误（乘 vs 除）来设置干扰项。

## 核心陷阱
- **核心陷阱**: **单位不统一与定义混淆**。
    1.  **单位陷阱**：请求速率单位是“个/秒”，时隙长度单位是“ms”。必须先将时间单位统一（1秒 = 1000ms），计算出1秒内有多少个时隙（20个），才能计算每个时隙的平均请求数。
    2.  **定义陷阱**：信道负载 $G$ 的定义是“平均每个时隙产生的分组数”。如果学生误以为负载就是“每秒产生的请求数”（即70），或者误以为负载是“每个请求占用的时隙数”，就会选错。

## 考察能力
本题核心考察学生对**ALOHA协议中“信道负载（G）”定义的准确理解**以及**不同时间单位下的速率换算能力**。
