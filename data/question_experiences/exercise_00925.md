# 练习题 Q1 — 进程同步互斥与进展性判定

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
考虑进程 P1 和 P2 访问临界区时使用的如下方法。共享布尔变量 S1 和 S2 的初始值是随机分配的：
```c
// P1
while (S1 == S2) ;
Critical Section
S1 = S2;

// P2
while (S1 != S2) ;
Critical Section
S2 = !S1;
```
关于上述方案，以下哪项描述是正确的？（ ）
- 选项:
  A: 满足互斥性，但不满足进展性
  B: 满足进展性，但不满足互斥性
  C: 既不满足互斥性，也不满足进展性
  D: 同时满足互斥性和进展性
- 正确答案: A
- 解析（参考）: 互斥性（Mutual Exclusion）
该方案确保：
P1 仅在 S1 != S2 时进入临界区，
P2 仅在 S1 == S2 时进入临界区，
二者永不同时成立，因此保证互斥性。
进展性（Progress）
如果只有一个进程希望进入临界区，且另一个进程不打算进入，那么该进程应该能够进入临界区。但在此方案中，两个变量的更新取决于彼此的退出行为。因此，即使 P1 不想进入临界区，它不更新 S1 也可能阻止 P2 进入。
故不满足进展性。
- 知识标签: ['操作系统/进程管理']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。需要准确记忆并辨析“互斥性”和“进展性”这两个核心同步原语的定义。不仅仅是知道定义，还需要理解“进展性”中隐含的“非阻塞”含义（即一个进程不进入临界区不应阻碍另一个进程）。若混淆了“空闲让进”和“有限等待”，容易误判。
- **K2 = 1**: 评分理由。本题不涉及数值计算，仅涉及布尔逻辑的状态判断，无计算负担。
- **K3 = 4**: 评分理由。需要进行多步状态推演。首先验证互斥性（逻辑互斥），然后构造反例验证进展性（需模拟 P1 不运行、P2 想进入但被 S1 初始值卡住的情景）。推演过程涉及对共享变量状态变化的追踪，步骤较多且需保持逻辑严密。
- **K4 = 5**: 评分理由。存在极强的反直觉陷阱。通常学生容易验证互斥性（因为条件互补），但极易忽略“初始值随机”这一隐含前提对进展性的破坏。题目未明确说明 P1 是否运行，学生需意识到“进展性”要求在任何情况下（包括另一进程死循环或不执行）只要自己请求就能进入，而本题中 P2 的进入完全依赖于 P1 之前的行为或初始状态，这是深层的隐含前提陷阱。
- **K5 = 3**: 评分理由。涉及两个进程 P1 和 P2 通过共享变量 S1, S2 进行状态交互。虽然耦合度不如信号量复杂，但需要理解两个进程代码逻辑对同一组共享状态的依赖关系。
- **雷达形状**: K4 陷阱主导型（K1、K3、K4 较高，K2 极低）。

## 考察模式
- **模式**: 推理型
- **理由**: 本题无法通过直接记忆公式或简单代入得出答案，必须通过逻辑推理，分别验证互斥性和进展性两个性质。特别是进展性的验证，需要构造特定的执行序列（Counter-example）来证伪，属于典型的逻辑推理与反例构造模式。

## 选项级分析
- **选项A**: [正确] — 准确描述了该算法的特性。互斥性由 `while` 条件的互补性保证（`S1==S2` 与 `S1!=S2` 不可能同时为真）；进展性被破坏，因为若初始 `S1==S2`，P2 可以进入，但若初始 `S1!=S2`，P2 将永远阻塞在 `while` 循环中，除非 P1 运行并修改 `S1`。如果 P1 不运行，P2 永远无法进入，违反进展性。
- **选项B**: [干扰] — 针对认为“只要不互斥就能进展”或混淆了互斥与进展定义的学生。这类学生可能错误地认为因为 P2 的条件是 `!=`，所以更容易进入，或者误以为互斥性不满足（实际上互斥性是满足的）。
- **选项C**: [干扰] — 针对完全无法理解代码逻辑，或者错误地认为两个进程可能同时进入临界区的学生。例如，可能误以为 `S1=S2` 和 `S2=!S1` 的赋值操作存在竞态条件导致互斥失败（实际上在进入临界区前的检查是原子的或逻辑上互斥的）。
- **选项D**: [干扰] — 针对只验证了互斥性，就默认进展性也满足的学生。这是最常见的错误，因为许多简单的互斥算法（如 Peterson 算法）是同时满足两者的，学生容易产生思维定势，忽略了本题中“初始值随机”和“单向依赖”带来的进展性问题。
- **干扰策略**: 概念混淆与思维定势。利用学生熟悉的标准算法（如 Peterson）作为锚点，诱导学生认为“看起来像互斥算法”就必然满足所有同步条件，从而忽略对进展性的严格检验。

## 核心陷阱
- **核心陷阱**: **“初始值随机”导致的死锁式阻塞（违反进展性）**。
  学生往往只关注代码逻辑上的互斥（条件互补），而忽略了进展性的定义：**如果一个进程不在临界区，它不应阻止其他进程进入临界区**。
  在本题中，若初始状态 `S1 != S2`，P2 的入口条件 `while (S1 != S2)` 为真，P2 将无限循环。此时，即使 P1 根本不想进入临界区（甚至 P1 已经终止），P2 也无法进入。这种“非请求进程阻碍请求进程”的现象是违反进展性的典型特征。

## 考察能力
本题核心考察考生对进程同步三大必要条件（互斥、进展、有限等待）中**进展性**定义的深度理解，以及在非标准同步算法中通过**构造反例**来验证同步原语正确性的逻辑推理能力。
