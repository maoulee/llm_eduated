# 2010 Q42 — 顺序表循环左移与三次逆置算法

## 基本信息
- **年份**: 2010  **题位**: Q42  **题型**: 综合题
- **知识点**: DS-2 > 2.2 顺序表 > 顺序表基本操作, DS-2 > 2.2 顺序表 > 顺序表存储结构, DS-1 > 1.2 算法和算法评价 > 时间复杂度, DS-1 > 1.2 算法和算法评价 > 空间复杂度
- **题位域**: 待标注  **科目**: 数据结构

## 题干原文
设将 $n$ ($n>1$) 个整数存放到一维数组 $R$ 中。试设计一个在时间和空间两方面都尽可能高效的算法。将 $R$ 中保存的序列循环左移 $p$ ($0<p<N$) 个位置，即将 $R$ 中的数据由 $<x_0, x_1, \cdots, x_{n-1}>$ 变换为 $<x_p, x_{p+1}, \cdots, x_{n-1}, x_0, x_1, \cdots, x_{p-1}>$。要求：
(1) 给出算法的基本设计思想。
(2) 根据设计思想，采用 C 或 C++ 或 Java 语言描述，关键之处给出注释。
(3) 说明你所设计算法的时间复杂度和空间复杂度。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握顺序表的基本存储结构（数组）以及“逆置”这一基本操作的概念。不是2分因为仅靠直觉无法直接得出最优解，需要调用“逆置”这一特定算法原语；不是4分因为不涉及复杂概念辨析，属于数据结构基础操作范畴。
- **K2 = 2**: 评分理由。算法核心是三次逆置，逆置操作本身是简单的双指针交换，计算量极小且无复杂数学换算。最复杂的单步仅是索引计算（如 `n-1`），属于2的幂友好或线性友好型，不易算错。
- **K3 = 3**: 评分理由。解题过程需要明确的三步串行推演：先逆置前p个，再逆置后n-p个，最后整体逆置。从输入到输出需3步逻辑转换，且每一步的状态变化（数组内容的局部反转）需要清晰追踪，符合3-5步的标准难度。
- **K4 = 3**: 评分理由。存在隐含前提和边界条件。首先，题目要求“时间空间尽可能高效”，这排除了使用额外数组（空间O(n)）或逐个移动元素（时间O(n*p)）的朴素解法，考生必须意识到“三次逆置”是标准最优解。其次，需注意 $p$ 可能大于 $n$ 的情况（虽然题干说 $0<p<N$，但严谨算法通常处理 $p=p\%n$），以及逆置函数中左右指针的边界控制（`i < j` 而非 `i <= j`），这些属于常规注意点及陷阱词，故评为3。
- **K5 = 1**: 评分理由。本题完全在“顺序表”这一单一子系统内完成，不涉及链表、树、图等其它数据结构的联动，也不涉及操作系统或网络等跨域知识，属于单系统内部操作。
- **雷达形状**: 整体呈均衡偏低的形状，K1-K3处于标准水平，K4略有突起（因隐含最优解策略的要求），K5极低。无明显短板，属于经典的基础算法设计题。

## 考察模式
- **模式**: 算法设计型
- **理由**: 题目明确要求“设计一个...算法”，并分步骤要求给出设计思想、代码实现及复杂度分析。这是典型的算法设计题，考察考生将数学/逻辑思想转化为具体代码实现的能力，而非单纯的计算或概念辨析。

## 解题思路分析
- **核心思路**: 利用“逆置”操作的性质，通过三次逆置实现循环左移。将数组视为两部分 $A$（前 $p$ 个元素）和 $B$（后 $n-p$ 个元素），原序列为 $AB$，目标序列为 $BA$。利用公式 $(A^{-1}B^{-1})^{-1} = BA$，即先分别逆置 $A$ 和 $B$，再逆置整个数组。
- **关键步骤**:
    1.  **定义逆置函数**：编写一个辅助函数 `Reverse(R, i, j)`，用于将数组 $R$ 中下标从 $i$ 到 $j$ 的元素进行原地逆置。
    2.  **第一次逆置**：调用 `Reverse(R, 0, p-1)`，将前 $p$ 个元素逆置，数组变为 $A^{-1}B$。
    3.  **第二次逆置**：调用 `Reverse(R, p, n-1)`，将剩余 $n-p$ 个元素逆置，数组变为 $A^{-1}B^{-1}$。
    4.  **第三次逆置**：调用 `Reverse(R, 0, n-1)`，将整个数组逆置，数组变为 $(A^{-1}B^{-1})^{-1} = BA$，即完成循环左移。
    5.  **复杂度分析**：时间复杂度为 $O(n)$，因为每个元素最多被访问/交换常数次；空间复杂度为 $O(1)$，仅使用常数个辅助变量。
- **易错点**:
    1.  **边界索引错误**：在调用 `Reverse` 时，参数传递错误，如写成 `Reverse(R, 0, p)` 导致多逆置一个元素。
    2.  **逆置函数实现错误**：在 `Reverse` 函数中，循环条件写成 `i <= j` 导致中间元素被错误交换或死循环，或者交换逻辑写错。
    3.  **未处理 $p \ge n$ 的情况**：虽然题干限制 $0 < p < N$，但在实际工程或更严谨的考试中，若 $p$ 可能大于 $n$，应先执行 $p = p \% n$。
    4.  **空间复杂度误解**：误以为需要开辟新数组，导致空间复杂度变为 $O(n)$，不符合“尽可能高效”的要求。

## 核心陷阱
- **核心陷阱**: **“尽可能高效”的隐含约束**。许多考生容易想到两种朴素解法：
    1.  逐个移动：每次左移1位，循环 $p$ 次。时间复杂度 $O(n \cdot p)$，当 $p$ 接近 $n$ 时退化为 $O(n^2)$。
    2.  额外空间：开辟一个新数组，直接按新顺序拷贝。空间复杂度 $O(n)$。
    题目明确要求“时间和空间两方面都尽可能高效”，这直接排除了上述两种解法，强制考生使用“三次逆置”这一 $O(n)$ 时间、$O(1)$ 空间的经典算法。若考生未能识别此约束，即使代码能运行，也会因复杂度不达标而失分。

## 考察能力
本题核心考察考生对顺序表基本操作的灵活运用能力，以及在特定约束条件下（时间/空间最优）设计高效算法的逻辑推导与代码实现能力。
