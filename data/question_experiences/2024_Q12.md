# 2024 Q12 — 补码截断与符号扩展

## 基本信息
- **年份**: 2024  **题位**: Q12  **题型**: 选择题
- **知识点**: 补码, 类型转换, 组成原理>类型转换, 组成原理>补码
- **题位域**: CO-7  **科目**: 组成原理

## 题干原文
C 语言代码如下：
```c
int i = 32777;
short si = i;
int j = si;
```
执行上述代码段后， j 的值为（ ）。

A. -32777
B. -32759
C. 32759
D. 32777

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 `int` 和 `short` 的位宽定义（通常分别为32位和16位），以及补码表示法的基本概念。不需要辨析多个易混概念，但必须准确记忆数据类型的存储宽度这一核心定义。
- **K2 = 4**: 评分理由。涉及非2的幂次的大数（32777）转换为二进制补码，且需要进行截断和符号扩展后的数值还原计算。虽然可以通过数学技巧（如 $32777 - 65536$）快速求解，但常规二进制转换和补码求值过程较为繁琐，容易在位运算或符号位处理上出错。
- **K3 = 3**: 评分理由。解题过程包含三个明确的串行步骤：1. 将 `int` 转为二进制补码；2. 截断低16位赋值给 `short`；3. 符号扩展回 `int` 并求值。步骤清晰，但每一步都依赖上一步的结果，属于标准的3-5步推演。
- **K4 = 4**: 评分理由。存在显著的隐含前提和陷阱。考生必须意识到 `32777` 超出了 `short` 的正数范围（32767），导致溢出并改变符号位。许多考生可能忽略溢出后的符号变化，或者错误地认为截断只是简单的数值取模而忽略补码的符号位含义。这是一个典型的“反直觉”陷阱，因为数值变小了（截断），但符号变了，最终结果变成了负数。
- **K5 = 3**: 评分理由。涉及从 `int` 到 `short` 再到 `int` 的数据类型转换，属于单向的数据传递和状态改变。虽然跨越了不同宽度的数据类型，但逻辑是线性的，没有复杂的子系统状态互影响。
- **雷达形状**: K4陷阱型。K4（条件路由/陷阱识别）得分最高，表明本题的核心难点不在于复杂的计算或深奥的理论，而在于识别数据类型转换中的溢出和符号扩展规则这一隐含陷阱。

## 考察模式
- **模式**: 综合型
- **理由**: 本题结合了概念认知（数据类型宽度）、机制推演（截断与扩展规则）和具体计算（补码数值转换）。它不是单纯的概念记忆，也不是纯粹的数学计算，而是要求在特定计算机体系结构规则（补码、类型转换）下进行多步逻辑推演和数值计算。

## 选项级分析
- **选项A**: [干扰] — 针对“符号位错误理解”或“简单取反”的错误认知。考生可能意识到结果是负数，但错误地认为截断后的值直接对应原数值的负数，或者在补码转换过程中符号位处理错误。
- **选项B**: [正确] — 正确答案。$32777$ 的二进制补码（32位）为 `0000 0000 0000 0000 1000 0000 0000 1001`。截断低16位得到 `1000 0000 0000 1001`。该 `short` 的符号位为1，表示负数。符号扩展回32位 `int` 时，高位补1，得到 `1111 1111 1111 1111 1000 0000 0000 1001`。该补码对应的真值为 $- (2^{16} - 32777) = - (65536 - 32777) = -32759$。或者通过 $32777 - 65536 = -32759$ 快速验证。
- **选项C**: [干扰] — 针对“忽略符号扩展”或“无符号解释”的错误认知。考生可能正确截断了低16位，但在转回 `int` 时进行了零扩展（即高位补0），或者将 `short` 视为无符号数处理，从而得到正数 $32759$（注意：$32777 \pmod{65536} = 32777$，这里选项C的数值 $32759$ 实际上是 $-32759$ 的绝对值，或者是计算错误导致的接近值，更可能是考生算出了负数但忘了负号，或者混淆了补码求原码的过程）。*修正分析*：$1000 0000 0000 1001$ 作为无符号数是 $32777$。如果考生错误地认为截断后数值不变，可能会选D。如果考生正确计算出补码值但忘记它是负数，可能会选C（如果C是32777的话）。但C是32759，这通常是考生正确计算出负数大小 $32759$ 但漏掉了负号，或者在补码转原码时出错。
- **选项D**: [干扰] — 针对“忽略溢出”或“认为赋值自动调整”的错误认知。考生可能认为 `short` 能容纳 `32777`，或者认为类型转换会自动保持数值不变，从而直接选择原值。

**干扰策略**: 概念混淆与计算陷阱结合。利用考生对 `short` 范围记忆的模糊性（是否记得32767上限），以及对补码符号扩展规则的不熟悉，设置正负号陷阱和数值计算陷阱。

## 核心陷阱
**核心陷阱**: `short` 类型溢出导致的符号位翻转及随后的符号扩展。考生容易忽略 $32777 > 32767$ 这一事实，未能识别出截断后最高位（符号位）变为1，从而在转回 `int` 时错误地进行零扩展或忽略负号，导致结果符号错误或数值错误。

## 考察能力
本题核心考察考生对C语言数据类型底层存储机制（补码表示）、数据截断与符号扩展规则的理解，以及在溢出情况下准确进行二进制数值转换和真值还原的能力。
