# 2009年 Q12 — 数据表示与运算（补码、符号扩展、溢出）

## 基本信息
- **年份**: 2009  **题位**: Q12  **题型**: 选择题
- **知识点**: 补码表示法, 符号扩展规则, 隐式类型转换, 整数加法溢出判断

## K1-K5 评分与解析
- **K1 = 3**: 3 — 必须准确记忆“符号扩展”（Sign Extension）的规则，即短整型向长整型提升时，正数补0、负数补1。若仅知补码概念而不知符号扩展细节，无法正确构建y的32位表示，故不是2；但因有明确的语法规则支撑，非纯死记硬背，故不是4。
- **K2 = 2**: 2 — 涉及将十进制 -9 转换为补码，以及 127 + (-9) 的加法运算。-9 的补码转换较为基础（取反加一），加法结果 118 也在 int 范围内，无复杂进位或多级换算，故不是3；相比完全无计算的题目，涉及进制转换和算术运算，故不是1。
- **K3 = 2**: 2 — 路径唯一：1. 确定数据类型宽度 (int=32, short=16) -> 2. y 符号扩展为 32 位 -> 3. x 与扩展后的 y 进行二进制加法 -> 4. 结果存入 z。步骤清晰且少于3步主要逻辑转折，故不是3；存在明确的运算流程，故不是1。
- **K4 = 4**: 4 — 核心陷阱在于“隐式类型转换”的规则识别。考生极易忽略 `short` 加 `int` 时 `short` 必须升级为 `int` 这一前提，直接对 16 位和 32 位数值进行错位相加或错误扩展（如高位全补0）。若不理解“提升（Promotion）”这一隐含前提，必然掉坑，故属于较高难度的条件路由。
- **K5 = 2**: 2 — 主要涉及“数据表示”子系统内的位宽对齐与算术逻辑运算。虽然题干提到“C语言”和“32位机器”，暗示了编译器/硬件的协同，但解题核心在于数据位级的操作，不涉及存储器、流水线或中断等其他子系统的状态交互，故不是3。
- **雷达形状**: K4陷阱型

## 考察模式
- **模式**: 计算型
- **理由**: 题干给出具体变量值和类型，选项为具体的数值或状态结果，考生需通过正确的底层计算过程得出唯一数值答案。

## 选项级分析
- **选项A**: [干扰] — **错误路径：缺失符号扩展或错误扩展**。考生可能直接将 `short` 型 y (-9) 的 16 位补码 `FF F7` 当作 32 位数的低16位，高16位补 0（即 `00 00 FF F7`，值为 65527），导致计算结果错误。这类学生混淆了“无符号扩展”与“符号扩展”，或忘记负数高位应补 1。
- **选项B**: [干扰] — **错误路径：补码转换错误**。考生可能在计算 -9 的 16 位补码时出错（例如直接写绝对值的二进制 `0000...1001` 或取反未加一），导致后续加法基础数据错误。这类学生基础编码规则掌握不牢。
- **选项C**: [干扰] — **错误路径：溢出误判或位宽混淆**。考生可能认为 `int` + `short` 结果仍为 `short`，或者错误地认为 127 + (-9) 会发生溢出（实际上 118 在 int 范围内）。这类学生对数据类型范围和溢出条件理解模糊。
