# 练习题 Q1 — 并发执行与共享变量竞争条件分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
考虑以下进程 P1 和 P2 的 C 代码。初始值为 a=4，b=0，c=0。
P1:
1. if (a < 0)
2. c = b-a;
3. else
4. c = b+a;

P2:
1. b = 10;
2. a = -3;

如果 P1 和 P2 并发执行，a、b、c 是两个进程的共享变量，两个进程都执行结束后，变量 c 的值不可能是以下选项中的那一个？（ ）
- 选项:
  A: 4
  B: 7
  C: 10
  D: 13
- 正确答案: C
- 解析（参考）: 解析
由于 P1 和 P2 并发执行，所以可能存在多种情况，接下来逐一进行分析：
P1(1,3,4):
a = 4, b = 0, c = b+a = 4
，选项 A 可能
P1(1,3) → P2(1,2) → P1(4):
a = -3, b = 10, c = b+a = 7
，选项 B 可能
P2(1,2) → P1(1,2):
a = -3, b = 10, c = b-a = 13
，选项 D 可能
所以选项 C 是不可能出现的，答案选择 C。
- 知识标签: ['操作系统/进程管理']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“并发执行”、“共享变量”、“指令交错”等核心概念。不是4分因为不需要辨析复杂的同步原语（如信号量、管程），仅涉及基本的并发定义。
- **K2 = 2**: 评分理由。计算极其简单，仅为整数的加减法（如 10+4, 10-3 等）。不是3分因为不存在复杂的数学运算或单位换算，计算错误率极低。
- **K3 = 4**: 评分理由。需要在明确规则（指令可任意交错）下进行多步串行推演。考生必须枚举出所有可能的指令执行序列（Interleaving），并跟踪每一步后 a, b, c 的状态变化。步骤超过5步且需记忆中间状态（特别是 P1 中 if 判断时的 a 值与赋值时的 a/b 值可能不同），因此难度较高。
- **K4 = 4**: 评分理由。存在隐含前提和反直觉陷阱。题面未明确说明指令的原子性，考生必须意识到 `if` 判断和后续赋值不是原子的，且 P2 的修改可能在 P1 判断后、赋值前发生。这是典型的“竞态条件”陷阱，需要避开“顺序执行”的思维定势。
- **K5 = 3**: 评分理由。涉及两个进程（P1, P2）之间的状态传递。P2 修改共享变量 a, b，直接影响 P1 的逻辑分支和计算结果。属于单向传数据影响逻辑，但未涉及复杂的跨子系统耦合。

- **雷达形状**: K3/K4 双高型（推理与陷阱主导）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖公式计算，也不单纯考察概念记忆，而是要求考生基于并发执行的规则，通过逻辑推理枚举所有可能的执行路径，从而确定结果集合。

## 选项级分析
- **选项 A (4)**: [干扰] — 对应 P1 完全在 P2 之前执行的情况（或 P2 在 P1 赋值后才执行，但 P1 判断时 a=4）。此时 P1 读取 a=4 (>=0)，执行 `c = b+a`。若 P2 未执行或 P2 在 P1 赋值后执行，b=0, a=4，则 c=4。这是最直观的“无干扰”情况。
- **选项 B (7)**: [干扰] — 对应 P1 判断时 a=4，但在赋值前 P2 执行了 `b=10, a=-3`。P1 进入 else 分支，执行 `c = b+a`。此时 b=10, a=-3，c = 10 + (-3) = 7。这是典型的“判断与执行间状态改变”陷阱。
- **选项 C (10)**: [正确] — 无论何种交错顺序，都无法得到 c=10。
    - 若走 `c = b+a`：需 b+a=10。已知 b 最终为 10（若 P2 执行），则需 a=0，但 a 初始为 4，P2 改为 -3，无 0 状态；若 P2 未执行，b=0, a=4, c=4。
    - 若走 `c = b-a`：需 b-a=10。已知 b 最终为 10，则需 a=0，同上无 0 状态；若 P2 未执行，b=0, a=4, c=-4。
    - 因此 10 是不可能值。
- **选项 D (13)**: [干扰] — 对应 P2 完全在 P1 之前执行。P1 读取 a=-3 (<0)，进入 if 分支，执行 `c = b-a`。此时 b=10, a=-3，c = 10 - (-3) = 13。这是“P2 先执行”的直观情况。

- **干扰策略**: 枚举遗漏。考生往往只能想到“P1先”、“P2先”两种极端情况（得到4和13），容易忽略“P1判断后、赋值前P2插入”的中间状态（得到7），从而误以为其他数字（如10）可能通过某种复杂交错产生，或者因计算错误选错。

## 核心陷阱
- **核心陷阱**: **指令非原子性与状态不一致**。考生容易错误地认为 `if (a<0) ... c=...` 是一个原子操作，或者认为 P1 读取的 a 和 b 的值在判断和赋值阶段必须保持一致。实际上，P2 可以在 P1 读取 a 进行判断之后、读取 b 和 a 进行赋值之前修改共享变量，导致“判断依据”与“计算数据”来自不同的时间切片。

## 考察能力
一句话概括本题核心考察的能力：在并发环境下，识别共享变量竞态条件并枚举指令交错执行路径的能力。
