# 练习题 — IP分片偏移量计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/网络层
- **难度**: 待评估

## 题干原文
考虑一个长度为 4500 字节的 IP 数据包，其中包含 20 字节的 IPv4 首部和 40 字节的 TCP 首部。该数据包被转发到一个支持最大传输单元（MTU）为 600 字节的 IPv4 路由器。假设所有传出分片中的 IP 首部长度均为 20 字节。假设第一个分片中存储的分片偏移值为 0。第三个分片中存储的分片偏移值是（ ）。注意：这是一个数值类型题目。
- 选项:
  A: 0
  B: 72
  C: 144
  D: 216

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 IP 分片的基本概念，包括 MTU、IP 首部长度、数据载荷、分片偏移量的定义及其单位（8 字节块）。不需要辨析多个易混概念，但必须准确记忆“分片偏移量以 8 字节为单位”这一核心定义。
- **K2 = 3**: 评分理由。涉及简单的算术运算：计算有效载荷大小（MTU - IP Header）、向下取整到 8 的倍数、计算前两个分片的数据量总和、最后除以 8 得到偏移量。虽然计算步骤不多，但涉及非 2 的幂次数的取整和除法，容易因粗心出错，属于标准难度的计算。
- **K3 = 3**: 评分理由。解题过程需要串行推演：1. 确定原始数据载荷；2. 确定每个分片能携带的最大数据量（需考虑 8 字节对齐）；3. 计算前两个分片占用的数据量；4. 转换为偏移量单位。共 3-4 步逻辑推导，属于标准机制推演。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。首先，题目给出了 TCP 首部长度，这是一个典型的干扰项，考生必须意识到路由器分片时不关心传输层首部，将其视为数据载荷的一部分。其次，必须意识到分片的数据长度必须是 8 的倍数（除了最后一个分片），这是解题的关键隐含规则，若忽略此点直接计算会导致错误。
- **K5 = 1**: 评分理由。本题仅涉及网络层（IP 层）的分片机制，虽然提到了 TCP 首部，但并未涉及 TCP 协议本身的机制联动或状态传递，TCP 首部仅作为数据载荷存在，属于单系统内部问题。
- **雷达形状**: K4 陷阱型。K4 得分较高，表明题目主要考察对隐含规则（8 字节对齐）和干扰信息（TCP 首部）的识别与排除能力，而非复杂的跨域联动或极高难度的计算。

## 考察模式
- **模式**: 计算型
- **理由**: 题目最终要求一个具体的数值结果，解题过程依赖于对 IP 分片规则的应用和具体的算术计算，而非单纯的概念辨析或逻辑推理。

## 选项级分析
- **选项 A**: [干扰] — 针对完全误解分片偏移量概念的学生。可能认为所有分片的偏移量都是 0，或者混淆了“标识符”与“偏移量”。
- **选项 B**: [干扰] — 针对计算错误或理解偏差的学生。例如，可能只计算了第一个分片的偏移量（0）加上某个错误值，或者误以为偏移量是字节数而非 8 字节块数（576/8=72，这是第一个分片后的偏移量，即第二个分片的偏移量，如果题目问的是第二个分片，选 B 就对了，但问的是第三个）。或者，学生可能错误地认为每个分片携带 580 字节（未对齐），580*2/8 = 145，接近但不等于任何选项，或者 580/8 取整错误。更可能的错误路径是：计算出每个分片数据为 576 字节，但忘记除以 8，或者只算了一个分片的偏移量（72）。实际上，B 选项 72 正好是第二个分片的偏移量（576/8=72）。如果学生误以为“第三个分片”是指“分片后的第三块数据”或者混淆了分片序号，可能会选 B。
- **选项 C**: [正确] — 正确计算结果。原始数据载荷 = 4500 - 20 = 4480 字节。MTU=600，IP 首部=20，最大数据载荷=580。向下取整到 8 的倍数为 576 字节。第一个分片携带 576 字节，偏移量 0。第二个分片携带 576 字节，偏移量 576/8 = 72。第三个分片携带 576 字节，其起始位置是前两个分片数据之和，即 576 + 576 = 1152 字节。偏移量 = 1152 / 8 = 144。
- **选项 D**: [干扰] — 针对计算错误的学生。可能是将分片数据长度误算为其他值，或者在计算偏移量时未除以 8（1152 接近 216*5? 不太像）。另一种可能是误以为每个分片携带 600 字节数据（忽略 IP 首部），600*2/8 = 150，也不对。或者误以为偏移量是字节数，1152 字节，但选项没有。D 选项 216 可能是 576 * 3 / 8 = 216，即学生错误地计算了前三个分片的总数据量对应的偏移量（即第四个分片的偏移量），或者混淆了“第三个分片的偏移量”与“前三个分片结束后的偏移量”。

**干扰策略**: 概念混淆与计算陷阱。主要利用“TCP 首部是否参与分片”的概念混淆，以及“分片偏移量单位是 8 字节”和“分片数据长度需 8 字节对齐”的计算陷阱。选项 B 和 D 分别对应第二个分片和第四个分片的偏移量，考察学生对“第 N 个分片”起始位置的准确理解。

## 核心陷阱
- **核心陷阱**: 
  1. **TCP 首部的干扰**: 考生容易误以为 TCP 首部需要特殊处理或从数据载荷中扣除，实际上在 IP 分片视角下，TCP 首部只是 IP 数据载荷的一部分。
  2. **8 字节对齐规则**: 分片的数据长度（除最后一个外）必须是 8 的倍数。MTU 600 减去 IP 首部 20 得到 580，必须向下取整为 576。若直接使用 580 计算，结果将错误。
  3. **偏移量单位**: 分片偏移量的单位是 8 字节块，而非字节。计算出的字节偏移量必须除以 8。

## 考察能力
本题核心考察考生对 IP 分片机制中“数据载荷对齐规则”、“分片偏移量单位”以及“网络层与传输层边界”的综合理解与精确计算能力。
