# 练习题 Q1 — 缓存未命中次数计算与空间局部性分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 计算机组成原理/存储系统
- **难度**: 待评估

## 题干原文
某 CPU 具有 32 KB 直接映射缓存，块大小为 128 字节。假设 A 是一个 512×512 的二维数组，每个元素占用 8 字节。考虑以下两个 C 代码段 P1 和 P2：
// P1:
for (i=0; i<512; i++) {
    for (j=0; j<512; j++) {
        x += A[i][j];
    }
}
// P2:
for (i=0; i<512; i++) {
    for (j=0; j<512; j++) {
        x += A[j][i];
    }
}
P1 和 P2 在相同初始状态下独立执行，即数组 A 不在缓存中，且 i、j、x 均在寄存器中。设 P1 经历的缓存未命中次数为 M1，P2 为 M2。
M1 的值是（ ）：
- 选项:
  A: 0
  B: 2048
  C: 16384
  D: 262144
- 正确答案: C
- 解析（参考）: 解析
访问模式分析
[P1] 采用行优先访问（
A[i][j]
）
[P2] 采用列优先访问（
A[j][i]
）
缓存参数计算
缓存块数量 = 总容量 ÷ 块大小 = 32 KB ÷ 128 B = 256
每块可容纳元素数 = 块大小 ÷ 元素大小 = 128 B ÷ 8 B = 16
未命中次数推导
数组总元素数 = 512 × 512 = 262,144
行优先访问时，每块可提供 16 次有效访问
由于缓存容量限制，需替换的块数 = 总元素数 ÷ (每块元素数 × 缓存块数) = 262,144 ÷ (16 × 256) = 64
实际未命中次数 = 每块首次访问触发一次未命中 → 6
- 知识标签: ['计算机组成原理/存储系统']
- 知识域: CO-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握直接映射缓存的基本概念（块大小、缓存行、映射方式）以及C语言二维数组的内存布局（行优先存储）。不需要辨析多个易混概念，但必须准确理解“直接映射”和“块大小”的定义。
- **K2 = 4**: 评分理由。涉及多级换算：总容量->块数，块大小->每块元素数，数组总大小->总访问次数。计算过程包含除法运算，且数字较大（512x512），容易在数量级上出错。特别是需要计算“总未命中次数”而非简单的“冲突次数”，需要结合空间局部性进行除法运算（总元素/每块元素）。
- **K3 = 3**: 评分理由。推演步骤清晰：1. 计算缓存参数；2. 分析P1访问模式；3. 判断是否发生冲突未命中；4. 计算总未命中次数。虽然步骤不多，但需要理解“直接映射”下，当数组大小超过缓存容量时，后续行是否会覆盖前一行。对于P1（行优先），由于每行大小（4KB）大于缓存容量（32KB）？不，每行大小是 512*8=4096B=4KB。缓存32KB。一行占4KB，即32个块。缓存有256个块。一行完全放入缓存后，下一行会映射到不同的缓存行吗？
    *   这里需要仔细推演：
    *   数组元素地址偏移：$A[i][j]$ 的偏移量为 $(i \times 512 + j) \times 8$。
    *   块索引计算：地址 / 块大小 = 地址 / 128。
    *   块索引 = $((i \times 512 + j) \times 8) / 128 = (i \times 512 + j) / 16$。
    *   缓存行数 $N = 256$。
    *   映射索引 = 块索引 % 256。
    *   对于P1，内层循环 $j$ 变化。当 $j$ 增加16时，块索引增加1。
    *   一行有512个元素，即 $512/16 = 32$ 个块。
    *   第 $i$ 行的块索引范围是 $[i \times 32, i \times 32 + 31]$。
    *   映射索引范围是 $[(i \times 32) \% 256, (i \times 32 + 31) \% 256]$。
    *   因为 $32 \times 8 = 256$，所以第 $i$ 行和第 $i+8$ 行的块会映射到相同的缓存行。
    *   但是，P1是顺序访问。访问完第0行（32个块），再访问第1行（32个块，映射索引不同，因为 $32 \% 256 \neq 0$），... 直到第7行。
    *   第8行开始，映射索引与第0行重叠。
    *   关键点：P1是**顺序**访问。当访问第8行时，第0行的数据已经被替换出去了。但是，我们不再需要第0行的数据了！
    *   因此，对于P1，**没有冲突未命中**，只有**强制未命中**（Compulsory Miss）。
    *   总未命中次数 = 总块数 = 总元素数 / 每块元素数 = $262144 / 16 = 16384$。
    *   这个推演需要确认“无冲突”这一关键逻辑，属于中等难度的机制推演。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。
    1.  **陷阱1**：学生可能误以为数组大小（2MB）远大于缓存（32KB），所以会有大量冲突未命中。实际上，对于P1（行优先），由于访问是顺序的，且每行大小（4KB）小于缓存容量（32KB），虽然不同行之间可能存在映射冲突，但由于是顺序扫描，旧数据被替换时已不再需要，因此**没有冲突未命中**。这是最大的反直觉点。
    2.  **陷阱2**：题目问的是M1，但给出了P2。学生可能被P2的列优先访问（高冲突）干扰，或者误以为要比较M1和M2。
    3.  **陷阱3**：直接映射缓存的冲突特性。如果学生不理解直接映射的索引计算，可能会错误地认为只要缓存放不下就有冲突。
- **K5 = 2**: 评分理由。主要涉及存储系统内部机制。虽然提到了C代码（软件层），但核心在于硬件缓存行为。软件访问模式直接影响硬件命中率，属于单向影响，耦合度较低。
- **雷达形状**: K4陷阱型。本题难点不在于计算复杂度（K2），而在于对缓存冲突机制的深刻理解（K4），特别是区分“容量未命中”和“冲突未命中”在顺序访问下的表现。

## 考察模式
- **模式**: 综合型
- **理由**: 本题结合了概念理解（直接映射、块大小）、计算能力（地址映射、未命中计数）和逻辑推理（访问模式对命中率的影响）。它不仅仅是套公式，还需要分析代码执行流与硬件行为的交互。

## 选项级分析
- **选项A (0)**: [干扰] — 针对完全误解缓存机制的学生。认为只要数据在内存中就能访问，或者认为缓存无限大。
- **选项B (2048)**: [干扰] — 针对计算错误或概念混淆的学生。可能误算了块数，或者误以为每行只未命中一次（512行 * 4块/行? 不对）。或者误以为缓存能容纳整个数组的一部分从而大幅减少未命中。例如，误以为每行未命中次数为 $512/16/8 = 4$? $512 \times 4 = 2048$。这可能是误以为每8行才冲突一次，从而错误地减少了未命中计数。
- **选项C (16384)**: [正确] — 正确计算了强制未命中次数。总元素 $512 \times 512 = 262144$。每块16个元素。总块数 $262144 / 16 = 16384$。由于P1是行优先顺序访问，且无有效冲突（旧数据被替换时已无用），故未命中次数等于总块数。
- **选项D (262144)**: [干扰] — 针对完全忽略空间局部性的学生。认为每个元素访问都未命中，即块大小为1字节或缓存失效。

**干扰策略**: 概念混淆与计算陷阱。利用学生对“大数组小缓存”必然导致高冲突的直觉进行误导，同时通过P2的存在增加认知负荷。

## 核心陷阱
**核心陷阱**: **误判冲突未命中**。
学生容易认为数组大小（2MB）远大于缓存（32KB），因此必然存在大量的冲突未命中。然而，对于P1（行优先顺序访问），虽然不同行的数据块可能映射到相同的缓存行，但由于访问是顺序进行的，当第 $i+8$ 行的数据替换掉第 $i$ 行的数据时，第 $i$ 行的数据已经访问完毕，不再需要。因此，P1 **没有冲突未命中**，只有强制未命中。未命中次数仅由总数据量和块大小决定，即 $Total\_Elements / Elements\_Per\_Block$。

## 考察能力
本题核心考察考生对**直接映射缓存机制**、**空间局部性**以及**程序访问模式对缓存命中率影响**的综合分析与计算能力。
