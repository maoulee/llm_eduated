# 练习题 Q1 — 传输层开销与数据包大小计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
假设对于给定的网络层实现，连接建立开销为 100 字节，断开连接开销为 28 字节。如果传输层希望在该网络之上实现数据报服务，并将其开销控制在最低 12.5%，那么传输层需要保持的最小数据包大小是多少？（忽略传输层本身的开销）（ ）
A: 512 字节
B: 768 字节
C: 1152 字节
D: 1024 字节

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要理解“连接建立/断开开销”与“数据报服务”在传输层模拟时的关系。虽然题目明确给出了数值，但考生需具备基础认知：在面向连接的网络层上模拟无连接的数据报服务，通常意味着每次数据传输都需要经历完整的连接建立和断开过程（即每次发送一个数据包都视为一次独立的会话）。若缺乏这一概念认知，无法建立数学模型。
- **K2 = 2**: 评分理由。计算过程非常直接且友好。涉及加法（100+28）和除法（128/0.125）。12.5% 对应 1/8，128 * 8 = 1024，属于 2 的幂次运算，心算即可得出，不易出错。
- **K3 = 1**: 评分理由。逻辑链条极短：总开销 -> 占比公式 -> 求解数据大小。仅需一步代入公式即可，无需多步串行推演或状态记忆。
- **K4 = 3**: 评分理由。存在隐含前提陷阱。题目说“实现数据报服务”，考生必须意识到这意味着“每个数据包独立建立和释放连接”。如果考生误以为可以复用连接（即连接开销分摊到多个包），或者误以为开销仅指头部开销而忽略连接控制开销，就会陷入误区。此外，“忽略传输层本身的开销”也是一个明确的排除干扰条件，需准确识别。
- **K5 = 1**: 评分理由。本题仅涉及传输层与网络层交互的开销计算，属于单一系统内的参数计算，不涉及不同子系统间复杂的状态传递或深度耦合。
- **雷达形状**: K2计算主导型，K4条件识别辅助型。整体难度较低，呈扁平状，但在K4维度有轻微突起（需识别隐含的“每包独立连接”机制）。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的开销数值和百分比约束，利用代数公式反推数据包大小。虽然背景涉及网络协议机制，但解题关键完全依赖于数学计算和对开销定义的准确提取。

## 选项级分析
- **选项A**: [干扰] — 针对计算错误或概念混淆。可能是考生将总开销算错，或者误以为 12.5% 是数据占比而非开销占比，导致计算方向错误。也可能是将 100+28 误算为其他数值。
- **选项B**: [干扰] — 针对部分开销遗漏。考生可能只计算了连接建立开销（100字节），忽略了断开开销（28字节），即 100 / 0.125 = 800，接近但不对；或者只计算了断开开销 28 / 0.125 = 224。更可能的情况是，考生错误地认为开销是 12.5% 的数据量，即 Data = Overhead / 0.125，但计算时出现偏差，或者混淆了“开销占比”的定义（Overhead / (Data + Overhead) vs Overhead / Data）。若按 Overhead / Data = 12.5% 计算，128 / 0.125 = 1024，结果一样。若按 Overhead / Total = 12.5% 计算，128 / 0.125 = 1024 (Total)，Data = 1024 - 128 = 896，无此选项。此选项可能是随机干扰或基于错误公式 100/0.125=800 附近的数值。
- **选项C**: [干扰] — 针对计算错误。可能是将 12.5% 误认为是 1/6 或其他分数，或者在加法步骤出错（如 100+28=120? 120/0.125=960，也不对）。更可能是考生误将 12.5% 当作 1/10 计算，128/0.1 = 1280，接近 1152。或者考生错误地使用了 100+28+128(误加) 等逻辑。
- **选项D**: [正确] — 正确计算结果。总开销 128 字节，占比 12.5% (1/8)，故总大小或数据大小（视定义而定，通常此类题目指数据载荷大小使得开销占比为12.5%，即 Overhead/Data = 12.5% 或 Overhead/Total = 12.5%。若 Overhead/Total = 12.5%，则 Total = 128/0.125 = 1024，Data = 896。若 Overhead/Data = 12.5%，则 Data = 128/0.125 = 1024。根据选项 D 为 1024，且通常“数据包大小”指 Payload 或 Total，结合常见考题习惯，此处应理解为 **开销占数据载荷的比例** 或 **题目定义的开销占比直接对应数据量**。参考解析中 S = 128 / 0.125 = 1024，暗示公式为 Data = Overhead / Ratio。因此 D 是正确答案。
- **干扰策略**: 计算陷阱与概念模糊。主要干扰在于考生是否清楚“开销占比”的分母是“数据大小”还是“总大小”，以及是否遗漏了断开连接的开销。

## 核心陷阱
- **核心陷阱**: **隐含的连接复用假设**。考生容易忽略“在面向连接的网络层上实现数据报服务”意味着**每个数据包都必须独立建立和释放连接**。如果考生潜意识认为可以保持连接打开以发送多个包，就会认为连接开销可以分摊，从而得出错误的最小包大小（会远小于 1024）。此外，另一个陷阱是**遗漏断开连接的开销**，只计算 100 字节，导致结果偏小。

## 考察能力
本题核心考察考生对**传输层服务原语开销**的理解，以及在特定约束条件下进行**协议效率量化分析**的能力。
