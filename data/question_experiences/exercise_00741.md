# 练习题 Q1 — 数组循环左移算法填空

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/数组
- **难度**: 待评估

## 题干原文
数组 A 包含 n 个整数，位于 A[0], A[1]...A[n-1]。要求将数组元素循环左移 k 位，其中 1 <= k <= (n-1)。给出一个不完整的算法，在不使用额外数组的情况下以线性时间完成此操作。请通过填充空白处来完善该算法。假设所有变量均已正确声明。
min = n;
i = 0;
while ( ___________ ){
temp = A[i];
j = i;
while ( ________ ){
A[j] = ________ ;
j = (j + k) % n;
If ( j < min ) then min = j;
}
A[(n + i - k) % n] = _________ ;
i = ___________ ;
}

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握数组循环移位的基本概念以及“原地置换”（In-place Permutation）或“环状替换”算法的核心思想。虽然不需要记忆复杂公式，但必须理解模运算在循环数组索引中的作用，属于标准的基础认知需求。不是4分因为不涉及多个易混高级数据结构的辨析。
- **K2 = 2**: 评分理由。题目中的计算主要是简单的模运算和索引推导，如 `(j + k) % n` 和 `(n + i - k) % n`。这些计算在逻辑上是直接的，不涉及复杂的数值计算或多级换算，属于较低的单步代入需求。
- **K3 = 4**: 评分理由。解题过程需要多步串行推演。首先需识别外层循环控制未处理的起始位置，其次需推导内层循环如何沿着“环”移动并覆盖元素，最后需确定环闭合的条件以及最后一个元素的处理。这需要考生在大脑中模拟算法执行流程，跟踪 `i`, `j`, `min` 和 `temp` 的状态变化，步骤超过3步且需记忆中间状态，故为较高难度。
- **K4 = 5**: 评分理由。本题存在极深的隐含前提和反直觉陷阱。
    1. **反直觉的循环终止条件**：通常循环移位可能想到三次逆置法，但此题强制使用原地置换。内层循环的终止条件 `j != (n+i-k) % n` 非常隐蔽，它实际上是在判断是否回到了当前环的“前驱”位置（即即将覆盖 `temp` 保存的原始值的位置），而非简单的回到起点 `i`。
    2. **Min变量的作用**：`min` 变量用于记录当前已处理的最小索引，外层循环 `i < min` 确保只处理尚未被移动过的元素作为新环的起点。这一逻辑若不深入推演极易选错。
    3. **边界处理**：最后一个元素 `A[(n + i - k) % n]` 的赋值是算法的关键收尾，容易因索引计算错误而掉入陷阱。
- **K5 = 3**: 评分理由。主要涉及数组内部索引与值的状态传递。虽然是在单一数据结构（数组）内操作，但需要在“当前环”的各个位置之间传递数据（通过 `temp` 暂存），并在外层循环和内层循环之间通过 `min` 和 `i` 协调状态，属于单向传数据与状态互影响的中等跨域联动。

- **雷达形状**: K4陷阱型（K4极高，K3较高，K1/K2中等偏低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非简单的概念记忆或公式计算，而是要求考生根据给定的算法框架，通过逻辑推理还原算法的执行细节。考生必须理解“环状替换”算法的数学原理，推导索引变化的规律，并识别循环终止的边界条件。

## 选项级分析
- **选项A**: [干扰] — 针对错误认知：认为外层循环应处理所有元素或条件判断方向错误。`i > min` 在初始化 `i=0, min=n` 时直接为假，导致循环不执行，这是明显的逻辑错误。这类学生可能未仔细检查初始条件。
- **选项B**: [干扰] — 针对错误认知：混淆了内层循环的终止条件。`j != (n+i) mod n` 即 `j != i`。如果内层循环条件是 `j != i`，当 `j` 移动一圈回到 `i` 时循环结束。但在原地置换中，当 `j` 回到 `i` 时，`A[i]` 已经被覆盖（除非是第一个元素，但第一个元素已被存入 `temp`）。更关键的是，如果条件是 `j != i`，当 `j` 指向 `i` 时，我们实际上需要把 `temp` 放回去，但循环体内部是 `A[j] = A[j+k]`，这会导致逻辑混乱。此外，参考解析指出若条件为 `j != i`，由于 `j` 初始为 `i`，循环体可能根本不执行或逻辑错误。实际上，标准的环状替换中，内层循环通常执行 `n/gcd(n,k)` 次，或者直到回到起点。但此题的特殊之处在于它通过 `min` 来管理外层，内层需要精确控制。选项B的终止条件过于简单，无法正确处理环的闭合与 `temp` 的放置。
- **选项C**: [干扰] — 针对错误认知：同A，外层循环条件 `i > min` 错误。且内层条件 `j != (n+i+k) mod n` 逻辑不明，索引计算 `A[(j+k)]` 缺少模运算，会导致数组越界。
- **选项D**: [正确] — 正确逻辑。
    1. `i < min`: 确保只处理未访问过的起始位置。
    2. `j != (n+i-k) % n`: 这是关键。`(n+i-k)%n` 是 `i` 在左移 `k` 位后的“前驱”位置（即原本在 `i` 位置的元素，左移 `k` 位后应该去的位置的前一个位置？不，更准确地说，这是环中最后一个需要被覆盖的位置，或者说，当 `j` 到达这个位置时，下一个位置就是 `i`，此时应停止覆盖，将 `temp` 放入 `i` 的对应位置？让我们仔细看代码：`A[(n+i-k)%n] = temp` 是在内层循环之后执行的。这意味着内层循环负责将环中除最后一个位置外的所有元素向前移动。当 `j` 等于 `(n+i-k)%n` 时，说明 `j` 的下一个位置 `(j+k)%n` 就是 `i`。此时循环应终止，因为 `A[i]` 的值已经保存在 `temp` 中，且 `A[i]` 应该被环中最后一个元素覆盖，而环中最后一个元素正是 `A[(n+i-k)%n]` 移动后的结果？不，代码逻辑是：`A[j] = A[j+k]`。如果 `j` 是 `(n+i-k)%n`，那么 `j+k` 模 `n` 后是 `i`。所以 `A[(n+i-k)%n]` 会被赋值为 `A[i]`（即 `temp` 的原始值，但此时 `A[i]` 可能已被覆盖？不，`temp` 保存了初始 `A[i]`）。等等，代码中 `A[(n+i-k)%n] = temp` 是在循环外。这意味着循环内不能处理 `j = (n+i-k)%n` 的情况，否则 `A[(n+i-k)%n]` 会被 `A[i]` 覆盖，而 `A[i]` 此时可能已经不是原始值了（如果 `i` 在环中不是第一个被处理的？不，`i` 是环的起点）。
    让我们重新梳理 D 的逻辑：
    - `temp = A[i]` 保存起点值。
    - `j = i`。
    - 内层循环：`A[j] = A[(j+k)%n]`。这将 `j+k` 处的值移到 `j` 处。
    - 循环继续直到 `j` 到达某个位置。
    - 循环结束后，`A[(n+i-k)%n] = temp`。
    - 注意：`(n+i-k)%n` 是 `i` 的“前驱”（在左移视角下，或者说，`i` 是 `(n+i-k)%n` 的后继）。
    - 如果内层循环条件是 `j != (n+i-k)%n`，那么当 `j` 变成 `(n+i-k)%n` 时，循环停止。
    - 此时，`A[(n+i-k)%n]` 还没有被赋值（因为循环体是 `A[j] = ...`，当 `j` 等于该值时循环不执行）。
    - 然后执行 `A[(n+i-k)%n] = temp`。
    - 这正好完成了环的闭合：将起点 `i` 的原始值 `temp` 放到了环的最后一个位置（即 `i` 的前驱位置）。
    - 这个逻辑是完美的。
- **干扰策略**: 渐进陷阱。通过外层循环条件的明显错误（A/C）排除一部分，通过内层循环条件的细微差别（B/D）考察对算法细节的深刻理解。B选项看起来更“自然”（回到起点），但实际上会导致逻辑错误或死循环/覆盖错误，而D选项的索引计算看似复杂，实则是算法正确性的关键。

## 核心陷阱
- **核心陷阱**: 内层循环的终止条件 `j != (n+i-k) % n` 以及随后的 `A[(n+i-k) % n] = temp`。考生容易误以为内层循环应执行直到 `j` 回到 `i`，或者误以为 `temp` 应在循环内处理。实际上，该算法采用“留一法”，内层循环将环中除最后一个位置外的所有元素向前移动，最后将保存的 `temp` 填入最后一个位置。识别出 `(n+i-k)%n` 是环中最后一个需要被填充的位置（即 `i` 的前驱）是解题关键。

## 考察能力
本题核心考察考生对**原地数组置换算法**的逻辑推演能力，特别是对**循环不变量**、**索引模运算**以及**边界条件处理**的精确掌握。
