# 2017 Q44 — 指令集架构辨析与机器级代码分析

## 基本信息
- **年份**: 2017  **题位**: Q44  **题型**: 综合题
- **知识点**: 复杂和精简指令集, 标志寄存器, 指令操作码, 组成原理>复杂和精简指令集, 组成原理>指令操作码
- **题位域**: 待标注  **科目**: 组成原理

## 题干原文
在按字节编址的计算机 M 上，题 43 中 f1 的部分源程序（阴影部分）与对应的机器级代码（包括指令的虚拟地址）如下图所示。
int f1(unsigned n)
1 00401020 55 push ebp
... ... ...
 for (unsigned i = 0; i <= n-1; i++) {
... ... ...
20 0040105E 39 4D F4 cmp dword ptr [ebp-0Ch],ecx
... ... ...
 power *= 2;
... ... ...
23 00401066 D1 E2 shl edx,1
... ... ...
 return sum;
... ... ...
35 0040107F C3 ret
其中，机器级代码行包括行号、虚拟地址、机器指令和汇编指令。
请回答下列问题。
(1) 计算机 M 是 RISC 还是 CISC？为什么？
(2) f1 的机器指令代码共占多少字节？要求给出计算过程。
(3) 第 20 条指令 cmp 通过 i 减 n-1 实现对 i 和 n-1 的比较。执行 f1(0) 过程中，当 i=0 时，cmp 指令执行后，进/借位标志 CF 的内容是什么？要求给出计算过程。
(4) 第 23 条指令 shl 通过左移操作实现了 power*2 运算，在 f2 中能否也用 shl 指令实现 power*2？为什么？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 RISC/CISC 的核心区别（指令长度、寻址方式等）以及标志寄存器 CF 的定义。属于标准的基础概念记忆，无需辨析多个易混概念，但需准确调用定义。
- **K2 = 2**: 评分理由。涉及简单的十六进制地址减法计算（107F - 1020 + 1）和位移运算逻辑。计算量小，且为 2 的幂次或简单加减，不易出错。
- **K3 = 2**: 评分理由。推演步骤较少。第 (3) 问需理解 `cmp` 本质是减法，并判断无符号数 0 - (n-1) 在 n=0 时的借位情况，逻辑链条短（1-2 步）。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。
    1. 第 (2) 问需意识到“最后一条指令”可能不止 1 字节，需结合上下文或常识（ret 为 1 字节）确认边界，或者更严谨地通过地址差计算范围。
    2. 第 (3) 问最大的陷阱在于 `n=0` 时 `n-1` 的无符号数表示（即 `0xFFFFFFFF`），以及 `cmp` 对 CF 的影响逻辑（借位即 CF=1）。
    3. 第 (4) 问需识别 `f2` 中 `power` 的数据类型（通常此类对比题中 f2 为有符号或浮点，或涉及溢出处理），若未注意数据类型差异（如 signed vs unsigned 或 double），直接回答“能”则错。题目虽未给出 f2 源码，但考察的是对移位指令适用范围的深层理解（移位仅适用于整数乘法，且需注意符号位和溢出）。
- **K5 = 3**: 评分理由。需要跨越“汇编指令”、“机器码格式”、“CPU 状态寄存器”和“数据类型语义”多个子系统。从汇编代码映射到机器码长度，从算术运算映射到标志位，从高级语言语义映射到底层指令选择。
- **雷达形状**: 偏向 K4（条件路由/陷阱识别）和 K5（跨域联动）的凸起型，K1-K3 较为平缓。

## 考察模式
- **模式**: 分析论证型
- **理由**: 题目不仅要求计算结果，更要求解释“为什么”（如 RISC/CISC 的判断依据、CF 的计算过程、shl 的适用性理由）。重点在于对计算机底层机制的理解和逻辑论证。

## 解题思路分析
- **核心思路**: 结合 x86 汇编指令集特点，从指令格式、地址计算、算术逻辑运算对标志位的影响、以及数据类型与指令的匹配性四个维度进行分析。
- **关键步骤**:
    1.  **判断架构**: 观察给出的机器指令字节数（如 `push ebp` 为 1 字节 `55`，`cmp` 为 3 字节 `39 4D F4`），发现指令长度不固定，符合 CISC 特征。
    2.  **计算代码大小**: 确定函数起始地址 `00401020H` 和结束地址 `0040107FH`。注意 `ret` 指令通常占 1 字节，且地址是字节编址。代码长度 = 结束地址 - 起始地址 + 1（若结束地址指向最后一条指令的第一个字节）。此处需确认 `0040107F` 是 `ret` 的起始地址。`ret` 为 `C3` (1字节)，故下一条指令地址为 `00401080`。长度 = `00401080 - 00401020 = 0x60 = 96` 字节。
    3.  **分析 CF 标志**: `cmp a, b` 执行 `a - b`。当 `n=0` 时，`n-1` 为无符号数 `0xFFFFFFFF` (即 -1 的补码表示，但在无符号比较中视为极大值)。`i=0`。执行 `0 - 0xFFFFFFFF`。由于被减数小于减数，产生借位，故 `CF = 1`。
    4.  **分析 shl 适用性**: `shl` 是逻辑左移，用于无符号整数乘法。若 `f2` 中的 `power` 是有符号整数，左移可能改变符号位导致未定义行为或错误结果（应使用 `sal` 或编译器优化后的其他指令，但在 x86 中 `shl` 和 `sal` 编码相同，主要区别在于语义和溢出检测 `OF`）；若 `power` 是浮点数，则完全不能用移位。通常此类题目中 `f2` 往往涉及有符号数或不同数据类型，需指出移位指令仅适用于整数且需注意符号/溢出问题。
- **易错点**:
    1.  误认为 RISC 指令长度固定是绝对标准，而忽略 x86 是典型的 CISC。
    2.  计算代码大小时忘记加 1 或误判最后一条指令的长度。
    3.  在计算 CF 时，混淆有符号数和无符号数的比较逻辑，或者忘记 `n=0` 时 `n-1` 的无符号表示是 `0xFFFFFFFF`。
    4.  第 (4) 问未看清 `f2` 的具体定义（需结合题 43 的完整上下文，通常 f2 是有符号版本或浮点版本），盲目回答“能”。

## 核心陷阱
- **核心陷阱**: 第 (3) 问中 `n=0` 导致的 `n-1` 无符号溢出表示（`0xFFFFFFFF`），以及由此引发的借位判断。学生容易直接用十进制思维 `0 - (-1) = 1` 而忽略底层二进制补码运算产生的借位标志。第 (4) 问的陷阱在于对 `shl` 指令适用范围的狭隘理解，忽略了数据类型（有符号/浮点）对指令选择的限制。

## 考察能力
本题核心考察考生对计算机指令系统架构特征（CISC/RISC）、机器级代码存储与寻址、算术逻辑运算对 CPU 状态标志位的影响机制，以及高级语言语义到机器指令映射的深层理解能力。
