# 练习题 Q1 — 链表头部插入操作

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/链表
- **难度**: 待评估

## 题干原文
以下链表操作步骤：
p = getnode();
info(p) = 10;
next(p) = list;
list = p;
会实现哪种类型的操作？（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握链表节点的基本结构（数据域、指针域）以及头指针的概念。不是2分因为仅靠直觉无法准确判断指针指向的变化，必须调用“头插法”这一核心定义或机制记忆。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行算术运算或复杂的单位换算。
- **K3 = 3**: 评分理由。需要按照代码顺序进行4步串行推演：1.申请节点；2.赋值；3.新节点指向旧头；4.头指针更新为新节点。这属于标准的3-5步逻辑推演，需清晰理解每一步对内存状态的影响。
- **K4 = 2**: 评分理由。存在常规注意点，即`next(p) = list`和`list = p`的顺序不能颠倒。如果顺序颠倒会导致链表断裂（丢失原链表）。这是链表操作中的常规陷阱，不属于深奥的隐含前提，但需要考生具备基本的操作规范意识。
- **K5 = 1**: 评分理由。本题仅涉及单一的数据结构（链表）内部操作，不涉及与其他子系统（如文件系统、网络协议、操作系统进程管理等）的状态传递或耦合。

- **雷达形状**: K3推演主导型（K1基础支撑，K4轻微陷阱，无计算压力）

## 考察模式
- **模式**: 推理型
- **理由**: 题目给出的是伪代码或具体实现步骤，要求考生通过逻辑推理，将代码行为映射到抽象的数据结构操作概念上。它不是简单的概念回忆（如“什么是链表”），也不是数值计算，而是对过程逻辑的理解和映射。

## 选项级分析
- **选项A**: [干扰] — 针对“栈”与“链表头部操作”的混淆。虽然链表头部插入在逻辑上等同于栈的Push操作，但题目问的是“链表操作步骤”实现的“类型”，且选项B、C、D均为链表具体操作，A选项属于抽象数据结构层面的类比，不如C选项直接描述链表物理操作准确。此外，栈的弹出是Pop，对应链表头部删除，而非插入。
- **选项B**: [干扰] — 针对“插入”与“删除”逻辑的混淆。删除操作通常涉及`p = list; list = list->next; free(p)`，与题干中创建新节点`getnode()`和更新指针指向新节点的行为完全相反。
- **选项C**: [正确] — 准确描述了代码行为。`next(p) = list`将新节点链接到原链表头部，`list = p`将头指针指向新节点，这是标准的头插法。
- **选项D**: [干扰] — 针对“修改”与“插入”的混淆。修改现有节点通常只改变`info`域，不改变指针结构或头指针指向。题干中明显涉及了新节点的创建和指针链路的改变。

- **干扰策略**: 概念混淆（栈操作与链表操作的对应关系）、逻辑反向（插入vs删除）

## 核心陷阱
- **核心陷阱**: 指针操作顺序的敏感性。虽然本题直接问操作类型，但深层陷阱在于如果考生不理解`next(p) = list`必须在`list = p`之前执行，就无法确认这是一个成功的插入操作而非链表断裂。此外，容易将“头部插入”与“栈的弹出（Pop）”混淆，因为栈的Pop对应的是链表头部删除。
