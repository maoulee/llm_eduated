# 练习题 Q1 — 进程状态转换与切换计数

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
就绪队列中有三个进程。当当前运行的进程请求 I/O 时，会发生多少次进程切换？（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“进程状态转换”和“进程切换（Context Switch）”这两个核心概念的定义。不是4分因为不需要辨析多个易混概念（如中断与异常的区别），只需明确I/O请求导致的状态变化即可。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算，无需执行算术运算或单位换算。
- **K3 = 2**: 评分理由。推演步骤较少：1. 当前进程发起I/O -> 2. 状态变为阻塞 -> 3. 调度器选择新进程 -> 4. 新进程投入运行。这是一个标准的2-3步逻辑链条，无需记忆复杂的中间状态序列。
- **K4 = 3**: 评分理由。存在明显的概念陷阱。题目问的是“进程切换次数”而非“状态变更次数”。许多学生会混淆“状态改变”（运行->阻塞，就绪->运行，共2次状态变动）与“上下文切换”（仅发生1次，即从旧进程切换到新进程）。这是一个典型的“陷阱词”或“概念边界”问题，需要考生具备区分微观状态变化和宏观调度动作的能力。
- **K5 = 1**: 评分理由。本题仅涉及CPU调度子系统内的进程状态管理，未涉及内存管理、文件系统或网络等其他子系统的状态传递或耦合。

- **雷达形状**: K4陷阱型（K4显著高于K2/K5，K1/K3处于中等水平）

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心在于考察对“进程切换”这一特定术语在操作系统调度机制中的精确定义，而非通过计算或复杂逻辑推导得出结论。它测试的是考生对基本概念边界的清晰度。

## 选项级分析
- **选项A**: [正确] — 符合操作系统调度原理。当运行进程因I/O阻塞时，CPU空闲，调度程序从就绪队列选取一个进程投入运行，这构成了一次完整的上下文切换（Context Switch）。
- **选项B**: [干扰] — 针对“状态变更”与“进程切换”混淆的错误认知。这类学生可能认为：运行->阻塞是一次变化，就绪->运行是另一次变化，因此误以为有2次切换。或者误以为I/O完成后的唤醒也算在内（虽然题目只问请求I/O时）。
- **选项C**: [干扰] — 针对“就绪队列长度”的误导。这类学生可能被题干中“三个进程”这一数字干扰，错误地认为切换次数与队列中进程数量有关，或者误以为需要遍历队列。
- **选项D**: [干扰] — 针对极端错误认知或胡乱猜测。可能将状态变更、中断处理、I/O操作本身都算作“切换”，或者完全无逻辑的凑数。

- **干扰策略**: 概念混淆（将状态转换次数等同于进程切换次数）+ 数字干扰（利用就绪队列进程数误导）

## 核心陷阱
- **核心陷阱**: 混淆“进程状态转换（State Transition）”与“进程上下文切换（Context Switch）”。
  - **状态转换**是进程控制块（PCB）中状态字段的改变，运行->阻塞和就绪->运行是两次独立的状态字段更新。
  - **进程切换**是指CPU从执行一个进程转而执行另一个进程的过程，涉及保存旧进程上下文和加载新进程上下文。在本题场景中，虽然发生了两次状态字段的更新，但CPU只发生了一次控制权的移交，因此进程切换次数为1。

## 考察能力
一句话概括本题核心考察的能力：准确区分进程状态变更与进程上下文切换的概念边界，并理解I/O阻塞引发的调度机制。
