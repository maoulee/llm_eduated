# 练习题 Q1 — 死锁避免与安全序列判定

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/死锁
- **难度**: 待评估

## 题干原文
一个操作系统有 13 个磁带驱动器。现有三个进程 P1、P2 和 P3。P1 的最大需求为 11 个磁带驱动器，P2 为 5 个，P3 为 8 个。当前 P1 已分配 6 个，P2 已分配 3 个，P3 已分配 2 个。以下哪个执行序列代表安全状态（ ）？
A: P2 → P1 → P3
B: P2 → P3 → P1
C: P1 → P2 → P3
D: P1 → P3 → P2

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“安全状态”、“最大需求”、“已分配资源”、“可用资源”以及“银行家算法”的核心定义。不是2分因为仅靠直觉无法解题，必须明确知道安全序列的定义是存在一个序列使得每个进程都能获得所需资源并释放；不是4分因为不需要辨析多个易混概念（如死锁检测与死锁避免的区别在此题中不直接作为考点，而是直接应用算法）。
- **K2 = 2**: 评分理由。计算过程仅为简单的加减法（13-11=2, 11-6=5等），数字较小且均为整数，不涉及复杂的幂次或单位换算，计算出错概率极低。
- **K3 = 4**: 评分理由。需要在明确规则（银行家算法）下进行多步串行推演。对于每个选项，都需要模拟资源分配、检查是否满足需求、更新可用资源、释放资源，直到所有进程完成或发现阻塞。每个选项平均需要3-4步状态更新，且需要记忆中间状态（当前可用资源数），步骤较多，容易在中间步骤出错。
- **K4 = 3**: 评分理由。存在常规注意点，即“安全序列”的定义是“存在”一个序列，而题目问的是“哪个序列代表安全状态”，实际上是在验证给定的序列是否为合法的安全序列。陷阱在于如果第一个进程无法满足，该序列直接非法，无需继续；如果满足，必须继续验证后续进程。隐含前提是进程执行完后会释放其占用的所有资源。
- **K5 = 1**: 评分理由。本题仅涉及操作系统中的资源管理模块，不涉及文件系统、内存管理或I/O子系统的跨域联动，属于单系统内部逻辑。
- **雷达形状**: K3推演主导型，K1基础支撑，K2计算简单，K4中等陷阱，K5无跨域。整体呈现为典型的算法模拟题型特征。

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非单纯的概念记忆或简单计算，而是要求考生根据银行家算法的规则，对给定的进程执行序列进行逻辑推演和状态模拟，判断其是否构成安全序列。核心在于“模拟执行过程”并验证每一步的可行性。

## 选项级分析
- **选项A**: [正确] — 初始可用资源为2。P2需2个（5-3=2），2>=2，满足，P2执行后释放3个，可用变为2+3=5。P1需5个（11-6=5），5>=5，满足，P1执行后释放6个，可用变为5+6=11。P3需6个（8-2=6），11>=6，满足。序列合法。
- **选项B**: [干扰] — 初始可用资源为2。P2需2个，满足，执行后可用变为5。P3需6个（8-2=6），5<6，不满足，P3阻塞。序列非法。这类学生可能误以为只要总资源够就行，或者在计算P3需求时出错。
- **选项C**: [干扰] — 初始可用资源为2。P1需5个（11-6=5），2<5，不满足，P1阻塞。序列非法。这类学生可能忽略了初始可用资源很少，或者误以为P1已分配6个就可以直接运行，混淆了“已分配”和“还需分配”。
- **选项D**: [干扰] — 初始可用资源为2。P1需5个，2<5，不满足，P1阻塞。序列非法。同C，考察对初始状态可用资源的准确计算。
- **干扰策略**: 计算陷阱与顺序依赖。选项C和D利用P1需求较大但初始可用资源少的特点，设置“首步即死”的陷阱；选项B利用P2执行后资源增加但仍不足P3需求的中间状态，设置“中途阻塞”的陷阱。

## 核心陷阱
- **核心陷阱**: 初始可用资源的计算错误以及对“安全序列”验证过程的误解。许多学生可能忘记计算初始可用资源（13 - (6+3+2) = 2），或者误以为只要总资源大于总需求就是安全状态，而忽略了资源分配的时序性和中间状态的阻塞风险。此外，容易混淆“最大需求”和“还需资源”，直接用最大需求与可用资源比较，导致错误判断。

## 考察能力
一句话概括本题核心考察的能力：准确应用银行家算法进行资源分配模拟，并通过多步状态推演验证进程执行序列的安全性。
