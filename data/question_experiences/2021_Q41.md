# 2021 Q41 — 图论欧拉路径判定与邻接矩阵遍历

## 题干原文

- **K3 = 2**: 评分理由。算法逻辑线性且简单：遍历顶点 -> 遍历邻接矩阵行 -> 统计度数 -> 判断奇偶 -> 统计奇度顶点总数 -> 返回结果。步骤清晰，无需多步串行推演或记忆中间复杂状态。

## 解题思路分析
- **核心思路**: 利用邻接矩阵的性质，通过遍历矩阵的每一行来计算每个顶点的度，统计度为奇数的顶点个数，最后根据欧拉路径的判定定理（奇度顶点数为0或2）返回结果。
- **关键步骤**:
    1. 初始化计数器 `count = 0`。
    2. 外层循环遍历所有顶点 `v` (从 0 到 `numVertices - 1`)。
    3. 内层循环遍历邻接矩阵的第 `v` 行，统计非零元素个数，得到顶点 `v` 的度 `degree`。
    4. 判断 `degree` 是否为奇数，若是，`count++`。
    5. 循环结束后，判断 `count` 是否等于 0 或 2。
    6. 若满足条件返回 1，否则返回 0。
- **易错点**:
    1. **循环边界错误**：内层循环应遍历列索引 `j` 从 0 到 `numVertices - 1`，而非 `numEdges`。参考答案中的伪代码变量命名 `e` 容易误导，实际应遍历矩阵的列。
    2. **忽略连通性前提**：虽然题目已说明是“无向连通图”，但部分考生可能习惯性地先写连通性判断算法，导致代码冗长且可能出错（尽管本题不需要）。
    3. **条件判断遗漏**：只判断了奇度顶点数为2，忽略了为0（欧拉回路也是欧拉路径的一种特殊情况，题目定义包含所有边且长度为|E|的路径，欧拉回路符合此定义）的情况。
    4. **空间复杂度分析错误**：误认为需要额外开辟数组存储度数，实际上只需几个整型变量，空间复杂度应为 O(1)。

## 核心陷阱
- **核心陷阱**: **邻接矩阵遍历的列索引范围**。许多考生容易混淆 `numVertices`（顶点数）和 `numEdges`（边数）。在邻接矩阵中，判断顶点 `v` 的度，需要遍历 `Edge[v][0...numVertices-1]`，而不是 `Edge[v][0...numEdges-1]`。此外，需明确题目已给定“连通图”，无需额外验证连通性，否则会增加不必要的代码量和潜在错误。
