# 练习题 Q1 — 进程同步与死锁避免

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
三个并发进程 X、Y 和 Z 分别执行不同的代码段，这些代码段访问并更新某些共享变量。在进入其代码段之前，进程 X 对信号量 a、b 和 c 执行 P 操作（即 wait）；进程 Y 对信号量 b、c 和 d 执行 P 操作；进程 Z 对信号量 c、d 和 a 执行 P 操作。每个进程在其代码段执行完成后，会对其三个信号量执行 V 操作（即 signal）。所有信号量均为二进制信号量，初始值为 1。以下哪一项代表了进程调用 P 操作的无死锁顺序？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握信号量 P/V 操作的基本语义（申请/释放资源）以及死锁产生的四个必要条件（特别是循环等待）。属于标准的核心概念记忆，无需辨析极度易混概念，但必须准确理解“二进制信号量”和“初始值为1”意味着互斥锁。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需进行幂次运算或复杂换算，仅涉及逻辑状态的判断。
- **K3 = 4**: 评分理由。需要在明确规则下多步串行推演。考生需要在脑海中构建进程调度序列，模拟不同进程获取资源的先后顺序，并检查是否存在“持有资源并等待其他资源”导致的循环依赖。这需要跟踪多个进程的状态变化，步骤较多且需记忆中间状态（谁持有了什么锁）。
- **K4 = 4**: 评分理由。存在隐含前提和反直觉陷阱。题面未直接说明“按顺序加锁可避免死锁”，考生必须意识到“破坏循环等待条件”是解题关键。此外，选项中的顺序看似随机，考生需识别出“全局有序加锁”这一隐含的最优策略，避开局部看似合理但全局死锁的陷阱。
- **K5 = 2**: 评分理由。主要涉及进程管理子系统内部的同步机制。虽然涉及多个进程间的交互，但不需要跨越内存管理、文件系统等不同子系统传递状态，耦合度较低。
- **雷达形状**: K3/K4 高推演陷阱型。本题难点不在于计算，而在于对并发执行序列的逻辑推演以及对死锁条件的敏锐识别。

## 考察模式
- **模式**: 推理型
- **理由**: 题目要求从给定的选项中推理出一种不会导致死锁的执行顺序。这需要考生运用死锁避免的理论（如资源有序分配法），对每个选项进行逻辑验证，排除存在循环等待风险的选项，而非简单的概念回忆或数值计算。

## 选项级分析
- **选项 A**: [干扰] — 针对“未察觉循环依赖”的错误认知。X: P(a)P(b)P(c), Y: P(b)P(c)P(d), Z: P(c)P(d)P(a)。若调度顺序为 X 获取 a，Y 获取 b，Z 获取 c 和 d，此时 X 等待 b（被 Y 持），Y 等待 c（被 Z 持），Z 等待 a（被 X 持），形成 X->Y->Z->X 的循环等待。这类学生可能只看了单个进程的内部顺序，忽略了进程间的交互。
- **选项 B**: [正确] — 符合“资源有序分配”原则。观察所有进程获取信号量的顺序：
    - X: b -> a -> c (注意：这里原题解析可能有误，让我们重新仔细检查选项B的顺序)
    - 让我们重新审视选项 B 的具体顺序：
        - X: P(b) P(a) P(c)
        - Y: P(b) P(c) P(d)
        - Z: P(a) P(c) P(d)
    - 等等，让我们看全局顺序。如果我们将信号量排序为 a < b < c < d。
    - 选项 B 中：
        - X 先 P(b)，再 P(a)。这是**逆序**获取（b > a）。
        - Y 先 P(b)，再 P(c)，再 P(d)。这是**顺序**获取（b < c < d）。
        - Z 先 P(a)，再 P(c)，再 P(d)。这是**顺序**获取（a < c < d）。
    - 让我们重新分析死锁可能性。死锁的关键是**循环等待**。
    - 如果所有进程都按照**相同的全局顺序**申请资源，则不会产生死锁。
    - 让我们看选项 B 是否真的无死锁。
        - 假设调度：X 获取 b。Y 获取 b (阻塞，因为 b 是二进制信号量，初始为1，X 拿了 Y 就得等)。
        - 所以 X 必须释放 b 或者 Y 必须等 X 释放。
        - 如果 X 获取 b 后，去获取 a。此时 Y 在等 b。
        - Z 获取 a (阻塞，因为 X 拿了 a)。
        - 此时状态：X 持有 {b, a}，Y 等待 b，Z 等待 a。
        - X 继续获取 c。X 持有 {b, a, c}。
        - X 执行完，释放 c, a, b。
        - Y 获取 b，然后获取 c，然后获取 d。Y 执行完。
        - Z 获取 a，然后获取 c，然后获取 d。Z 执行完。
        - 看起来 B 是安全的，因为 X 先拿 b 和 a，虽然顺序是 b->a，但 Y 和 Z 并没有形成针对 X 的循环。
        - 关键在于：**是否存在一种调度序列导致死锁？**
        - 在 B 中：
            - X: b, a, c
            - Y: b, c, d
            - Z: a, c, d
            - 假设 X 获取 b。Y 尝试获取 b -> 阻塞。
            - Z 尝试获取 a。X 还没获取 a。Z 获取 a。
            - X 获取 a。Z 已经持有 a，X 尝试获取 a -> 阻塞。
            - 此时：X 持有 b，等待 a。Z 持有 a，等待 c (下一步)。Y 等待 b。
            - Z 获取 c。Z 持有 a, c。
            - Z 获取 d。Z 持有 a, c, d。
            - Z 释放 a, c, d。
            - X 获取 a。X 持有 b, a。
            - X 获取 c。X 持有 b, a, c。
            - X 释放。
            - Y 获取 b...
            - 看起来 B 确实没有死锁。因为 Y 和 Z 在获取第一个资源时，如果冲突，会阻塞，从而打破潜在的循环。
            - 更严谨的判断方法是看**资源请求图**是否有环。
            - 在 B 中，X 请求 b 然后 a。Y 请求 b 然后 c。Z 请求 a 然后 c。
            - 如果 X 持有 b，Y 等待 b。X 请求 a。Z 持有 a (假设 Z 先运行)，Z 请求 c。
            - 这里没有形成闭环。因为 Y 只依赖 b，Z 只依赖 a (初始)。X 依赖 b 和 a。
            - 实际上，选项 B 的正确性在于它**避免了所有进程同时持有部分资源并等待其他进程持有的资源形成闭环**。
            - 让我们对比其他选项为什么错。
- **选项 C**: [干扰] — 针对“局部有序但全局无序”的错误认知。X: b->a->c, Y: c->b->d, Z: a->c->d。
    - 场景：X 获取 b。Y 获取 c。Z 获取 a。
    - X 等待 a (被 Z 持)。Y 等待 b (被 X 持)。Z 等待 c (被 Y 持)。
    - 形成 X->Z->Y->X 的循环等待。死锁。
- **选项 D**: [干扰] — 针对“部分进程有序”的错误认知。X: a->b->c, Y: c->b->d, Z: c->d->a。
    - 场景：X 获取 a, b。Y 获取 c。
    - X 等待 c (被 Y 持)。Y 等待 b (被 X 持)。
    - 形成 X->Y->X 的循环等待。死锁。

- **干扰策略**: 渐进陷阱。选项 A、C、D 都构造了经典的循环等待场景，考生若不能模拟出特定的并发执行序列（即“最坏情况”下的调度），就容易误判。选项 B 通过让进程在获取第一个资源时产生阻塞（如 Y 等 X 的 b，或 Z 等 X 的 a），从而串行化了关键路径，避免了循环。

## 核心陷阱
- **核心陷阱**: **循环等待条件的隐蔽性**。考生容易只检查单个进程内部的 P 操作顺序是否“看起来”有序，而忽略了不同进程之间 P 操作顺序的交叉组合可能形成的全局循环依赖。必须通过构造“最坏调度序列”来验证死锁可能性。

## 考察能力
本题核心考察考生对**死锁产生条件（特别是循环等待）**的理解，以及运用**资源有序分配法**或**状态推演法**分析并发进程同步安全性的能力。
