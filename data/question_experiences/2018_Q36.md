# 2018 Q36 — 停等协议信道利用率与帧长计算

## 基本信息
- **年份**: 2018  **题位**: Q36  **题型**: 选择题
- **知识点**: CN-3 > 可靠传输机制 > 停止-等待协议, CN-3 > 可靠传输机制 > 信道利用率计算
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
主机甲采用停 - 等协议向主机乙发送数据，数据传输速率是 3 kbps，单向传播延时是 200 ms，忽略确认帧的传输延时。当信道利用率等于 40% 时，数据帧的长度为（ ）。
ARQ协议
信道利用率

A. 240 比特
B. 400 比特
C. 480 比特
D. 800 比特

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆“信道利用率”的定义公式（有效传输时间/总周期时间），以及停等协议的基本工作流程。属于标准的核心概念记忆，不涉及复杂辨析。
- **K2 = 3**: 评分理由。涉及单位换算（kbps 与 ms 的匹配）和简单的代数方程求解。虽然计算量不大，但单位不统一（比特/秒 vs 毫秒）需要考生进行标准化处理，属于标准难度的单步代入计算。
- **K3 = 2**: 评分理由。逻辑链条较短：确定有效时间 -> 确定总周期时间 -> 建立等式 -> 求解。只需2-3步串行推演，无需记忆中间状态或复杂的状态机跳转。
- **K4 = 4**: 评分理由。存在明显的隐含前提和易错点。首先，“忽略确认帧的传输延时”意味着确认帧的发送时延为0，但确认帧的**传播时延**依然存在且必须计入总周期；其次，停等协议的总周期包含“数据发送+数据传播+确认发送+确认传播”，考生极易遗漏确认帧的传播时延或错误地认为忽略确认帧传输延时意味着忽略所有确认相关时延。这是一个典型的陷阱词与隐含前提结合的情况。
- **K5 = 1**: 评分理由。本题仅涉及数据链路层的可靠传输机制，未跨越网络层、传输层或其他子系统，属于单系统内部计算。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，主要难点在于对题目条件的精准解读和隐含条件的挖掘）

## 考察模式
- **模式**: 计算型
- **理由**: 题目给出了具体的数值参数（速率、延时、利用率），要求通过建立数学模型（方程）求解未知量（帧长）。虽然基于协议原理，但最终落脚点在于数值计算。

## 选项级分析
- **选项A**: [干扰] — 针对**遗漏确认帧传播时延**的错误认知。如果考生认为总周期 = 数据发送时延 + 数据传播时延（即忽略了ACK回来的时间），或者错误地认为忽略确认帧传输延时意味着忽略ACK的所有时间，可能会算出较小的帧长。具体计算：若 $T_{cycle} = T_{trans} + T_{prop}$，则 $0.4 = T_{trans} / (T_{trans} + 0.2)$，解得 $T_{trans} \approx 0.133s$，帧长 $\approx 400$ bit（接近B，非A，A可能是更严重的计算错误或单位错误）。实际上，若完全忽略传播时延只算发送，或者公式记反，可能得到极小值。更可能的错误路径是：误以为利用率 = 发送时延 / (发送时延 + 2*传播时延) 但计算出错。
- **选项B**: [干扰] — 针对**遗漏确认帧传播时延**的典型错误。若考生错误地认为总周期 $T = T_{trans} + T_{prop}$（即只算去程，没算回程ACK的传播），则 $0.4 = \frac{x/3000}{x/3000 + 0.2}$，解得 $x/3000 = 0.1333$， $x = 400$。这是最常见的错误，因为学生容易忘记ACK也需要时间传回来。
- **选项C**: [干扰] — 针对**单位换算错误**或**公式记忆偏差**。例如将 3 kbps 当作 3000 bps 但时间单位未统一，或者在计算 $T_{prop}$ 时只算了一次单向传播而忘记乘以2（虽然B选项已经覆盖了漏掉ACK传播的情况，C可能是计算过程中的中间值错误，或者误用了 $T_{cycle} = T_{trans} + T_{prop}$ 但系数搞错）。另一种可能是误以为利用率是 50% 或其他数值时的结果。
- **选项D**: [正确] — 正确计算结果。
  - 有效时间 $T_{trans} = L / 3000$
  - 总周期 $T_{cycle} = T_{trans} + T_{prop} + T_{ack\_trans} + T_{ack\_prop}$
  - 已知 $T_{ack\_trans} = 0$， $T_{prop} = T_{ack\_prop} = 0.2s$
  - $T_{cycle} = L/3000 + 0.2 + 0 + 0.2 = L/3000 + 0.4$
  - 利用率 $U = T_{trans} / T_{cycle} = \frac{L/3000}{L/3000 + 0.4} = 0.4$
  - 解方程：$L/3000 = 0.4 \times (L/3000 + 0.4) \Rightarrow L/3000 = 0.4L/3000 + 0.16 \Rightarrow 0.6L/3000 = 0.16 \Rightarrow L = \frac{0.16 \times 3000}{0.6} = \frac{480}{0.6} = 800$ bit。
- **干扰策略**: 概念混淆（是否包含ACK传播时延）与计算陷阱（单位换算）。选项B是强干扰项，专门针对忽略ACK回程时间的考生。

## 核心陷阱
**“忽略确认帧的传输延时”不等于“忽略确认帧的传播延时”**。
考生极易将“传输延时（发送时延）”与“传播延时”混淆，或者因为题目说忽略确认帧的传输延时，就潜意识里忽略了确认帧存在的事实，从而在计算总周期时漏掉了确认帧从乙回到甲的传播时延（200ms）。停等协议的总周期必须包含数据去程和确认回程的完整往返时间。

## 考察能力
在理解停等协议工作机制的基础上，准确区分发送时延与传播时延，并能根据题目特定条件（忽略某一时延）构建正确的信道利用率数学模型进行求解的能力。
