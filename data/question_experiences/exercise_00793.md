# 练习题 Q1 — 死锁检测与资源分配模拟

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/死锁
- **难度**: 待评估

## 题干原文
考虑一个具有 4 种资源的系统：R1（3 个单位）、R2（2 个单位）、R3（3 个单位）、R4（2 个单位）。系统采用非抢占式资源分配策略。在任意时刻，如果请求无法完全满足，则不会被处理。
有三个进程 P1、P2 和 P3 独立执行时的资源请求如下：
t=0: 请求 2 个单位的 R2 
t=1: 请求 1 个单位的 R3 
t=3: 请求 2 个单位的 R1 
t=5: 释放 1 个单位的 R2 和 1 个单位的 R1 
t=7: 释放 1 个单位的 R3 
t=8: 请求 2 个单位的 R4 
t=10: 完成
进程 P1
t=0: 请求 2 个单位的 R3 
t=2: 请求 1 个单位的 R4 
t=4: 请求 1 个单位的 R1 
t=6: 释放 1 个单位的 R3 
t=8: 完成
进程 P2
t=0: 请求 1 个单位的 R4 
t=2: 请求 2 个单位的 R1 
t=5: 释放 2 个单位的 R1 
t=7: 请求 1 个单位的 R2 
t=8: 请求 1 个单位的 R3 
t=9: 完成
进程 P3
若所有三个进程从时间 t=0 开始并发运行，以下哪项陈述是正确的？
- 选项:
  A: 所有进程都能完成且无死锁
  B: 仅 P1 和 P2 会陷入死锁
  C: 仅 P1 和 P3 会陷入死锁
  D: 所有三个进程都会陷入死锁
- 正确答案: A
- 解析（参考）: 分析过程
按照时间轴逐步模拟资源分配：
t=0: P1 获取 R2(2), P2 获取 R3(2), P3 获取 R4(1)
t=1: P1 获取 R3(1)
t=2: P2 获取 R4(1), P3 获取 R1(2)
t=3: P1 获取 R1(2)
t=4: P2 获取 R1(1)
t=5: P1 释放 R2(1) + R1(1)，此时可用资源 R2=1, R1=1
t=7: P1 释放 R3(1)，P3 获取 R2(1)
t=8: P1 获取 R4(2)，P3 获取 R3(1)
t=9: P3 完成
t=10: P1 完成
关键验证点
所有资源请求均能按需分配
不存在循环等待条件（各进程
- 知识标签: ['操作系统/死锁']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握死锁产生的四个必要条件（互斥、占有并等待、非抢占、循环等待）以及资源分配的基本概念（请求、分配、释放）。虽然不涉及复杂公式，但必须准确理解“非抢占”和“请求无法完全满足则不处理”的含义，属于标准的基础认知需求。
- **K2 = 2**: 评分理由。本题不涉及复杂的数学计算，主要是简单的整数加减法（资源数量的增减）。计算量极小，且数字均为个位数，不易出错，属于较低的单步代入需求。
- **K3 = 5**: 评分理由。这是本题的核心难点。考生需要在脑海中或草稿纸上构建一个时间轴，从 t=0 到 t=10，每一步都要检查当前可用资源是否满足进程的请求。这涉及多步串行推演，且每一步的状态（可用资源向量、各进程持有资源向量）都会影响下一步的结果。推演步骤超过 10 步，且需要记忆中间状态，属于极高的机制推演需求。
- **K4 = 4**: 评分理由。存在隐含前提和易错点。首先，题目未明确说明进程请求的优先级或调度顺序，考生需意识到在资源充足时，多个进程可能同时获得资源（如 t=0 时 P1, P2, P3 同时请求且资源足够）。其次，关键在于识别“死锁”并非必然发生，而是取决于资源释放的时间点。如果考生误以为只要存在资源竞争就会死锁，或者忽略了 t=5 时 P1 释放资源从而打破潜在死锁的关键节点，就会掉入陷阱。这种对动态资源状态变化的敏感度要求较高。
- **K5 = 1**: 评分理由。本题仅涉及操作系统中的资源管理和死锁检测模块，不涉及文件系统、内存管理或进程调度等其他子系统的联动，属于单系统内部的状态推演。

- **雷达形状**: K3 推演主导型（K3 极高，K4 较高，K1 标准，K2/K5 较低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不是简单的概念记忆或公式计算，而是要求考生根据给定的规则（资源分配策略）和初始条件，通过逻辑推理和状态模拟，预测系统的最终行为（是否死锁）。它考察的是对动态过程的理解和推演能力。

## 选项级分析
- **选项 A**: [正确] — 通过详细的时间轴模拟，发现所有进程的资源请求都能在某个时间点得到满足，且没有进程因等待资源而永久阻塞。P1 在 t=5 释放资源是关键，它使得 P3 能在 t=7 获得 R2，进而让 P3 在 t=9 完成，释放资源供 P1 使用。
- **选项 B**: [干扰] — 针对认为 P1 和 P2 会互相等待资源的错误认知。P1 需要 R1，P2 也需要 R1，但 P3 在 t=2 获取了 R1，P1 在 t=3 获取了 R1，P2 在 t=4 获取了 R1。实际上，由于资源总量充足且释放及时，P1 和 P2 并未形成循环等待。选此项的学生可能只看到了 P1 和 P2 对 R1 的竞争，而忽略了 P3 的作用和资源释放的时间点。
- **选项 C**: [干扰] — 针对认为 P1 和 P3 会陷入死锁的错误认知。P1 需要 R4，P3 需要 R4，但 P2 在 t=0 获取了 R4，P2 在 t=8 之前并未释放 R4（实际上 P2 在 t=8 请求 R3，t=9 完成，但 P2 在 t=0 获取的 R4 何时释放？题目中 P2 的释放记录只有 t=5 释放 R1。等等，让我们重新检查 P2 的资源持有情况。P2 在 t=0 请求 R4(1)，t=2 请求 R1(2)，t=5 释放 R1(2)。P2 何时释放 R4？题目中 P2 的列表没有明确写出释放 R4 的时间，但 P2 在 t=9 完成。通常完成时会释放所有资源。然而，P1 在 t=8 请求 R4(2)。此时 P2 持有 R4(1)，P3 在 t=0 请求 R4(1) 但被阻塞？不，t=0 时 R4 总量 2，P2 请求 1，P3 请求 1，两者都能满足。所以 t=0 时 P2 持有 R4(1)，P3 持有 R4(1)。t=8 时 P1 请求 R4(2)，此时 R4 全部分配给 P2 和 P3。P1 需要等待。P3 在 t=9 完成，释放 R4(1) 和 R3(1)。此时 R4 可用 1。P2 在 t=9 完成，释放 R4(1)。此时 R4 可用 2。P1 在 t=10 完成。这里的关键是 P1 在 t=8 请求 R4(2) 时，R4 是否可用？t=0: P2 拿 1, P3 拿 1. R4 用完。t=8: P1 请求 2。此时 P2 和 P3 都还活着。P3 在 t=9 完成，P2 在 t=9 完成。所以 P1 在 t=8 请求时，必须等待 P2 或 P3 释放。P3 在 t=9 释放，P2 在 t=9 释放。所以 P1 在 t=9 之后可以获得 R4。因此不会死锁。选此项的学生可能误以为 P1 在 t=8 请求 R4 时，P2 和 P3 都不释放，导致 P1 永远等待，而忽略了 P2 和 P3 会在 t=9 完成并释放资源。
- **选项 D**: [干扰] — 针对认为资源竞争必然导致死锁的极端错误认知。选此项的学生可能没有进行详细模拟，而是看到多个进程竞争有限资源，就主观判断会发生死锁。

- **干扰策略**: 渐进陷阱。通过设置多个资源竞争点（R1, R2, R3, R4），诱导考生认为竞争会导致死锁。实际上，关键在于资源释放的时间点是否打破了循环等待。

## 核心陷阱
- **核心陷阱**: 忽略资源释放的动态性。考生容易静态地看待资源需求，认为只要存在资源竞争（如 P1, P2, P3 都请求 R4），就会发生死锁。而实际上，死锁的避免依赖于进程在完成前释放资源，从而让其他进程得以继续执行。本题中，P1 在 t=5 释放资源，P3 和 P2 在 t=9 释放资源，这些释放操作打破了潜在的循环等待链。

## 考察能力
本题核心考察考生对操作系统中资源分配动态过程的模拟能力，以及对死锁产生条件（特别是循环等待）在时间维度上的深入理解。
