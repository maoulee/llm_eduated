# 练习题 Q1 — C-SCAN磁盘调度算法与寻道距离计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/I/O管理
- **难度**: 待评估

## 题干原文
假设磁盘读写头当前位于磁道 45（总磁道范围为 0-255）且向正方向移动。已按顺序接收到以下磁道请求：40、67、11、240、87。使用优化的 C-SCAN 算法处理这些请求的顺序是什么？总寻道距离是多少？
- 选项:
  A: 600
  B: 810
  C: 505
  D: 550
- 正确答案: C
- 解析（参考）: C-SCAN 扫描类似于电梯的工作方式。它从最近的端点开始扫描，并一直移动到系统的末端。到达最底端或顶端后，会跳转到另一端并继续沿相同方向移动。需要注意的是，这种大跨度跳跃不计入磁头移动距离。
解法
磁盘队列：40、67、11、240、87，当前磁头位于磁道 45。优化的 C-SCAN 处理请求的顺序如下图所示。总寻道距离计算如下：
(67-45) + (87-67) + (240-87) + (255-240) + (255-0) + (11-0) + (40-11)
= 22 + 20 + 153 + 15 + 255 + 11 + 29
= 505
- 知识标签: ['操作系统/I/O管理']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 C-SCAN（循环扫描）算法的核心定义，特别是“单向移动”、“到达端点后跳回另一端”以及“跳回过程不计入寻道距离”这三个关键特征。若混淆为 SCAN 或 C-LOOK，则无法解题。属于标准概念记忆需求。
- **K2 = 3**: 评分理由。涉及多次整数减法运算及累加。虽然数字不大，但步骤较多（7段距离相加），且包含一个特殊的“全量程跳跃”计算（255-0），容易在计算过程中出现粗心错误。非2的幂次友好型计算，属于标准计算难度。
- **K3 = 4**: 评分理由。推演步骤较多且需保持状态。首先需对请求队列排序；其次需根据当前磁头位置（45）和移动方向（正）确定第一段服务序列（45->67->87->240）；接着需判断是否到达物理边界（255），从而触发跳转逻辑；最后处理剩余请求（0->11->40）。整个过程涉及“排序-分段-边界判断-跳转-续接”多步串行推演，且需记忆中间状态（当前磁头位置），故评分较高。
- **K4 = 4**: 评分理由。存在明显的隐含前提和易错陷阱。
    1. **边界处理陷阱**：C-SCAN 必须扫到物理端点（255）才能跳转，即使没有请求在 255 附近。许多学生误以为扫到最大请求（240）就跳转，导致少算 (255-240) 的距离。
    2. **跳转距离陷阱**：必须明确“跳回”动作（255->0）在物理上发生，但在计算“寻道距离”时通常不计入（或题目隐含不计，参考解析中明确写了+255，这里需注意：参考解析中 `(255-0)` 被加进去了？让我们仔细看解析：`+ (255-0)`。等等，通常 C-SCAN 的“跳回”是不计入寻道时间的，因为它是瞬间完成的。但是，**参考解析中明确计算了 `(255-0)` 即 255 的距离**。这是一个非常关键的歧义点或特定教材定义。
    *修正分析*：重新审视参考解析：`(255-240) + (255-0) + (11-0)`。解析中确实加了 255。这意味着该题定义的“总寻道距离”包含了从最大磁道回到最小磁道的物理移动距离，或者该题使用的是某种变体。但在标准 408 考研中，C-SCAN 的跳回通常**不计入**寻道距离。
    *再次核对标准 408 考点*：在王道、天勤等主流 408 教材中，C-SCAN 的寻道距离计算**不包含**从一端跳回另一端的距离。
    *然而*，本题参考解析明确给出了 `+ (255-0)`。如果按照标准 408 考点，答案应该是 `505 - 255 = 250`。但选项中没有 250。选项 C 是 505。这说明**本题的“陷阱”或“设定”是：跳回距离计入总距离**，或者题目问的是“磁头移动的总物理距离”而非标准的“寻道开销”。
    *或者*，另一种可能是解析写错了？让我们看选项。如果跳回不计入：22+20+153+15+11+29 = 250。无此选项。如果跳回计入：505。有选项 C。
    *结论*：本题的 K4 难度极高，因为考生需要识别出“本题语境下跳回距离计入”这一反常规（相对于标准 408 考点）或特定教材的定义，或者考生会陷入“到底计不计数”的纠结。如果考生死记“跳回不计入”，会找不到答案。如果考生灵活计算所有物理移动，则能选 C。这属于“隐含前提深”或“反直觉”的陷阱。
- **K5 = 1**: 评分理由。仅涉及磁盘调度子系统内部逻辑，无需跨越其他模块（如内存管理、进程调度）进行状态传递。

- **雷达形状**: K4 陷阱型（高 K4，中高 K3，标准 K1/K2）。本题的核心难点不在于计算本身，而在于对 C-SCAN 算法边界条件和“跳回距离是否计入”这一特定规则的理解与适配。

## 考察模式
- **模式**: 综合型（计算+规则推演）
- **理由**: 题目不仅要求考生记忆 C-SCAN 的概念，还需要通过多步推演确定服务序列，并进行具体的数值计算。同时，选项设计针对了常见的规则理解偏差（如是否扫到端点、跳回是否计入），具有典型的综合考察特征。

## 选项级分析
- **选项 A (600)**: [干扰] — 可能源于错误的服务顺序或重复计算。例如，如果考生错误地认为从 240 直接跳回 0 后，又错误地处理了 40 和 11 的顺序，或者在计算中多加了某些段。也可能源于将 SCAN 算法的距离错误套用。
- **选项 B (810)**: [干扰] — 数值较大，可能源于完全错误的算法理解，例如将每次请求都视为从 0 开始，或者错误地计算了多次全量程跳跃。
- **选项 C (505)**: [正确] — 符合参考解析的逻辑：服务顺序为 45->67->87->240->255(端点)->0(跳回)->11->40。距离计算为 (67-45)+(87-67)+(240-87)+(255-240)+(255-0)+(11-0)+(40-11) = 22+20+153+15+255+11+29 = 505。
- **选项 D (550)**: [干扰] — 可能源于计算错误，或者在跳转逻辑上出现了偏差，例如错误地认为从 240 跳回 0 的距离是 240 而不是 255，或者在后续请求处理上出错。

- **干扰策略**: 概念混淆（C-SCAN vs SCAN vs C-LOOK）与 计算陷阱（跳回距离的处理）。

## 核心陷阱
**核心陷阱**: **C-SCAN 的“跳回”行为及其距离计算**。
1. **必须扫到物理端点**：即使最大请求是 240，磁头也必须移动到 255 才能触发跳转。很多考生会误以为到 240 就回头，从而少算 (255-240)=15 的距离。
2. **跳回距离是否计入**：这是本题最大的争议点和陷阱。标准 408 理论中，C-SCAN 的跳回（255->0）是瞬间完成的，**不计入**寻道距离。但本题参考解析和正确选项 C 表明，**本题要求计入跳回距离**（或者题目问的是物理移动总距离）。考生若死守“跳回不计入”的教条，会计算出 250，发现无选项，从而陷入困惑。考生需根据选项反推题目意图，或识别出该题特定语境下的规则。

## 考察能力
本题核心考察考生对磁盘调度算法（特别是 C-SCAN）执行流程的精细化推演能力，以及在面对特定边界条件（端点处理、跳回距离定义）时的灵活分析与计算能力。
