# 练习题 Q1 — 进程同步与信号量机制

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
以下代码包含两个可以并行运行的线程（生产者和消费者）。此外，S 和 Q 是配备标准 P 和 V 操作的二进制信号量。
semaphore S = 1, Q = 0;
integer x;
producer:
while (true) do
P(S);
x = produce();
V(Q);
done
consumer:
while (true) do
P(Q);
consume(x);
V(S);
done
关于上述程序，以下哪项是正确的？（ ）
- 选项:
  A: 进程可能发生死锁
  B: 其中一个线程可能发生饥饿
  C: 生产者生成的部分项目可能会丢失
  D: 生产者生成并存储在’x’中的值将在生产者生成新值之前被消费

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握信号量（Semaphore）的基本定义、P/V操作（wait/signal）的语义以及二进制信号量作为互斥锁或同步工具的作用。不需要辨析多个复杂概念，但必须准确理解 `P(S)` 减1阻塞、`V(S)` 加1唤醒的核心机制。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需进行幂次运算或多级换算，仅涉及逻辑状态的判断。
- **K3 = 4**: 评分理由。需要多步串行推演。考生必须在脑海中模拟生产者和消费者交替执行的过程：初始状态 -> 生产者P(S)成功 -> 生产 -> V(Q) -> 消费者P(Q)成功 -> 消费 -> V(S) -> 生产者再次P(S)... 需要跟踪两个信号量 S 和 Q 的值变化以及变量 x 的状态流转，步骤超过3步且需记忆中间状态（如 S=0, Q=1 时的阻塞情况）。
- **K4 = 3**: 评分理由。存在常规注意点陷阱。考生容易混淆“互斥”与“同步”的区别，或者误以为单缓冲区必然导致数据覆盖（丢失）。需要识别出 `S` 初始为1代表缓冲区空位，`Q` 初始为0代表缓冲区数据，从而避开“死锁”或“数据丢失”的直觉陷阱。
- **K5 = 3**: 评分理由。涉及两个进程（生产者、消费者）之间的状态传递。生产者通过 `V(Q)` 向消费者传递“有数据”的状态，消费者通过 `V(S)` 向生产者传递“有空位”的状态。这是典型的单向数据流伴随双向状态同步，属于中等程度的跨域联动。

- **雷达形状**: K3推演主导型（K3较高，K1中等，其余较低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖死记硬背的概念定义，也不涉及复杂计算，而是要求考生根据给定的代码逻辑和信号量初始值，推演进程执行的时序和状态变化，从而判断程序行为的正确性。

## 选项级分析
- **选项A**: [干扰] — 针对“信号量使用不当会导致死锁”的错误认知。这类学生可能认为两个进程互相等待对方释放资源就会死锁。但实际上，初始状态 S=1, Q=0，生产者先执行 P(S) 成功，不会阻塞；消费者执行 P(Q) 会阻塞直到生产者 V(Q)。这是一个标准的同步流程，不存在循环等待条件，因此不会死锁。
- **选项B**: [干扰] — 针对“并发竞争导致饥饿”的错误认知。这类学生可能认为如果调度器一直调度生产者，消费者就会饿死。但在该代码中，生产者生产一次后必须 V(Q) 唤醒消费者，且生产者下一次 P(S) 前必须等待消费者 V(S)（因为缓冲区只有一个位置 x）。这种严格的交替机制保证了公平性，不会发生饥饿。
- **选项C**: [干扰] — 针对“单缓冲区变量会被覆盖”的错误认知。这类学生看到 `integer x` 是全局变量，担心生产者还没等消费者读完就写了新值。但代码中 `P(S)` 和 `V(S)` 构成了对缓冲区空位的互斥/同步控制。生产者只有拿到 S（空位）才能写，写完释放 Q；消费者只有拿到 Q（数据）才能读，读完释放 S。因此，生产者写新值前，消费者必然已经读走了旧值，数据不会丢失。
- **选项D**: [正确] — 正确描述了程序的同步行为。由于 S 初始为1，Q 初始为0，且缓冲区只有一个变量 x，生产者必须等待消费者消费完（V(S)）才能进行下一次生产（P(S)）。这意味着“生成-消费”是严格交替进行的，前一个值一定在被覆盖前被消费。

- **干扰策略**: 概念混淆（混淆互斥与同步、误解单缓冲区的覆盖风险）

## 核心陷阱
- **核心陷阱**: 误判单缓冲区（变量 x）的数据安全性。考生容易忽略信号量 S 和 Q 构成的严格同步链，直觉上认为全局变量 x 在并发下会被覆盖，从而错误选择 C。实际上，信号量机制强制实现了“生产-消费-生产”的串行化逻辑，保证了数据完整性。

## 考察能力
一句话概括本题核心考察的能力：能够根据信号量的初始值和 P/V 操作位置，准确推演多进程同步执行时序及数据一致性保障机制。
