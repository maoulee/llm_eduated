# 2016 Q46 — 处理机调度算法与饥饿现象分析

## 基本信息
- **年份**: 2016  **题位**: Q46  **题型**: 综合题
- **知识点**: 处理机调度算法, 操作系统>处理机调度算法
- **题位域**: 待标注  **科目**: 操作系统

## 题干原文
某进程调度程序采用基于优先数 (priority) 的调度策略，即选择优先数最小的进程运行，进程创建时由用户指定一个 nice 作为静态优先数。为了动态调整优先数，引入运行时间 cpuTime 和等待时间 waitTime，初值均为 0。进程处于执行态时，cpuTime 定时加 1，且 waitTime 置 0；进程处于就绪态时，cpuTime 置 0，waitTime 定时加 1。请回答下列问题。
(1) 若调度程序只将 nice 的值作为进程的优先数，即 priority=nice，则可能会出现饥饿现象，为什么？
(2) 使用 nice、cpuTime 和 waitTime 设计一种动态优先数计算方法，以避免产生饥饿现象，并说明 waitTime 的作用。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“静态优先级调度”、“饥饿现象”、“动态优先级调整”等核心概念。虽然不涉及复杂公式记忆，但需要理解优先级数值大小与调度顺序（最小优先）之间的逻辑关系，属于标准的基础认知需求。
- **K2 = 1**: 评分理由。本题不涉及具体的数值计算或复杂的数学推导，仅需定性分析变量间的增减关系，无计算负担。
- **K3 = 3**: 评分理由。需要进行多步逻辑推演：首先理解静态优先级的缺陷（高优先级进程持续占用CPU导致低优先级进程无法运行），其次推导动态调整机制（运行时间增加应降低优先级/增大数值，等待时间增加应提高优先级/减小数值），最后综合构建公式。这是一个典型的3-5步逻辑链条。
- **K4 = 3**: 评分理由。存在隐含前提和易错点。题目明确指出“选择优先数最小的进程运行”，这意味着要“提高”一个进程的调度机会，必须使其 priority 数值“变小”。许多学生容易惯性思维认为“提高优先级”就是数值变大，从而在公式符号上出错（如写成 +waitTime）。识别这一反直觉的数值逻辑是解题关键。
- **K5 = 2**: 评分理由。主要局限于处理机调度子系统内部，涉及进程状态（执行态/就绪态）与调度参数（priority）之间的单向影响，未涉及内存、I/O等其他子系统的深度耦合。

- **雷达形状**: 呈现“中间高、两头低”的橄榄型或菱形特征。K1和K3适中，K2极低，K4和K5较低。表明本题重在概念理解与逻辑构建，而非计算或跨域复杂交互。

## 考察模式
- **模式**: 分析论证型
- **理由**: 题目要求解释现象产生的原因（为什么会出现饥饿），并基于给定变量设计算法逻辑（设计计算公式）。这需要对操作系统调度机制的原理进行深入分析和逻辑论证，而非单纯的代码实现或数值计算。

## 解题思路分析
- **核心思路**: 
  1. **第一问**：紧扣“静态”二字。静态优先级一旦确定不再改变，若系统中存在大量高优先级（数值小）进程，低优先级（数值大）进程将永远无法获得CPU，从而定义出“饥饿”。
  2. **第二问**：构建动态平衡机制。目标是让长期运行的进程优先级降低（数值变大），让长期等待的进程优先级提高（数值变小）。
     - `nice` 是基础。
     - `cpuTime` 增加代表进程已运行很久，应惩罚，故 priority 应增大，系数为正。
     - `waitTime` 增加代表进程等待很久，应奖励，故 priority 应减小，系数为负。
     - 组合公式：`priority = nice + k1*cpuTime - k2*waitTime`。

- **关键步骤**:
  1. 明确调度规则：Priority 越小，越先运行。
  2. 分析饥饿成因：静态优先级导致资源分配不公，低优先级进程无限期推迟。
  3. 确定变量作用方向：
     - 运行时间 (`cpuTime`) 越长 -> 优先级应越低 -> Priority 数值应越大 -> 正相关。
     - 等待时间 (`waitTime`) 越长 -> 优先级应越高 -> Priority 数值应越小 -> 负相关。
  4. 构建线性组合公式，并解释 `waitTime` 通过减小 Priority 数值来提升调度概率，从而防止饥饿。

- **易错点**:
  1. **符号错误**：混淆“优先级高”与“Priority数值大”。题目规定“优先数最小”运行，因此提高调度权意味着减小 Priority 数值。学生常错误地给 `waitTime` 加上正号。
  2. **概念混淆**：将 `cpuTime` 和 `waitTime` 的作用搞反，或者未能解释清楚为什么动态调整能避免饥饿（即未能指出“等待时间增加会导致优先级数值下降，最终低于其他进程”这一动态过程）。
  3. **忽略系数**：虽然题目允许合理公式，但最好引入系数 $k1, k2$ 以体现调节比例，否则可能被认为设计过于简单。

## 核心陷阱
- **核心陷阱**: **优先级数值大小与调度优先级的反向关系**。
  题目设定“选择优先数最小的进程运行”，这与日常语境中“优先级越高越好”的直觉相反。在构建公式时，若要“避免饥饿”（即让等待久的进程先运行），必须使其 Priority 数值**变小**。因此，`waitTime` 前必须是**负号**，`cpuTime` 前必须是**正号**。这是本题最大的逻辑陷阱。

## 考察能力
本题核心考察考生对**处理机调度算法中静态与动态优先级机制的理解**，以及**通过变量关系建模以解决系统公平性（饥饿）问题**的逻辑设计能力。
