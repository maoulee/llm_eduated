# 练习题 Q1 — 矩阵转置算法分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/数组
- **难度**: 待评估

## 题干原文
设 A 是一个 n x n 的矩阵。考虑以下程序。预期输出是什么？
```c
void fun(int A[][N]) {
    for (int i = 0; i < N; i++)
        for (int j = i + 1; j < N; j++)
            swap(A[i][j], A[j][i]);
}
```
- 选项:
  A: 矩阵 A
  B: 矩阵 A 的对角线
  C: 矩阵 A 的转置
  D: 以上都不是
- 正确答案: C
- 解析（参考）: 解析：在函数 fun 中，通过双重循环遍历矩阵的上三角区域（即 i < j 的位置）。对于每个元素 A[i][j]，将其与 A[j][i] 交换。这一操作实际上将矩阵的行和列互换位置，最终得到的是矩阵 A 的转置矩阵。因此，正确答案是 (C)。
- 知识标签: ['数据结构/数组']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“矩阵转置”的定义（行变列，列变行）以及二维数组在内存中的基本访问逻辑。不是2分因为仅靠直觉难以确定循环边界 `j=i+1` 的具体含义，需调用转置概念；不是4分因为不涉及易混概念辨析（如稀疏矩阵压缩存储等）。
- **K2 = 2**: 评分理由。本题无复杂数值计算，仅需理解 `swap` 操作的语义。最复杂的单步是理解 `A[i][j]` 和 `A[j][i]` 的索引对应关系，属于基础索引映射，不易出错。
- **K3 = 3**: 评分理由。需要推演双重循环的执行过程。从输入到输出需理解：1. 外层循环控制行；2. 内层循环从对角线右侧开始；3. 交换操作的影响范围。这属于3-5步的逻辑推演，需确认交换是否覆盖所有非对角线元素且不重复交换。
- **K4 = 3**: 评分理由。存在隐含前提和潜在陷阱。陷阱在于内层循环起始条件 `j = i + 1`。如果学生误以为 `j` 从 `0` 或 `i` 开始，会得出错误结论（如原地转置失败或重复交换）。识别“只交换上三角”以避免重复交换是解题关键，属于常规注意点但需警惕。
- **K5 = 1**: 评分理由。单系统问题。仅涉及二维数组这一种数据结构，不涉及与其他子系统（如链表、树、图或操作系统资源）的状态传递或耦合。
- **雷达形状**: K4陷阱型（K4略高，K1/K3中等，K2/K5低）。主要难点在于对循环边界条件的逻辑推演和陷阱识别。

## 考察模式
- **模式**: 推理型
- **理由**: 题目不要求记忆特定公式或进行数值计算，而是要求考生阅读代码，理解循环结构和交换逻辑，进而推导出算法对数据结构的最终影响。核心在于“代码行为 -> 数据结构变化”的逻辑映射。

## 选项级分析
- **选项A**: [干扰] — 针对“代码无效”或“原地操作无变化”的错误认知。这类学生可能认为 `swap` 只是临时交换，或者误以为循环没有实际执行，或者认为矩阵本身不可变。
- **选项B**: [干扰] — 针对“只关注对角线”的错误认知。这类学生可能被 `i` 和 `j` 的关系迷惑，或者误以为代码只处理了 `i==j` 的情况（实际上代码跳过了对角线），或者认为输出只保留了对角线元素。
- **选项C**: [正确] — 正确识别了 `A[i][j]` 与 `A[j][i]` 交换且仅遍历上三角区域，实现了行列互换。
- **选项D**: [干扰] — 针对“不确定”或“认为代码有bug”的认知。这类学生可能担心 `N` 未定义，或者认为原地转置需要额外空间，或者无法确定循环边界是否导致错误。
- **干扰策略**: 概念混淆。通过设置看似相关但逻辑错误的选项（如只关注对角线、认为无变化），考察学生对转置算法核心逻辑（对称交换、避免重复）的掌握程度。

## 核心陷阱
- **核心陷阱**: 内层循环的起始条件 `j = i + 1`。
  - **陷阱解析**: 如果 `j` 从 `0` 开始，会导致元素被交换两次（恢复原状）；如果 `j` 从 `i` 开始，对角线元素会被自己交换（无影响但多余）。`j = i + 1` 确保只遍历上三角，每个非对角线元素对 `(i, j)` 和 `(j, i)` 只交换一次，从而正确实现转置。考生若忽略此边界条件，可能误判算法效果。

## 考察能力
一句话概括本题核心考察的能力：
**理解并推演基于索引交换的二维数组原地转置算法逻辑，特别是循环边界对算法正确性的影响。**
