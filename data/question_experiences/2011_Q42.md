# 2011 Q42 — 双序列中位数查找（分治/二分策略）

## 基本信息
- **年份**: 2011  **题位**: Q42  **题型**: 综合题
- **知识点**: DS-1 > 1.2 算法和算法评价 > 算法效率度量, DS-1 > 1.2 算法和算法评价 > 时间复杂度, DS-1 > 1.2 算法和算法评价 > 空间复杂度
- **题位域**: 待标注  **科目**: 数据结构

## 题干原文
一个长度为 L（L ≥ 1） 的升序序列 S ，处在第 $\lceil L/2 \rceil$ 个位置的数称为 S 的中位数。例如，若序列 S1 = (11,13,15,17,19)，则 S1 的中位数是 15 。两个序列的中位数是含它们所有元素的升序序列的中位数。例如，若序列 S2 = (2,4,6,8,20)，则 S1 和 S2 的中位数是 11 。现有两个等长的升序序列 A 和 B ，试设计一个在时间和空间两方面都尽可能高效的算法，找出两个序列 A 和 B 的中位数。要求：
(1) 给出算法的基本设计思想。
(2) 根据设计思想，采用 C 或 C++ 或 Java 语言描述，关键之处给出注释。
(3) 说明你所设计算法的时间复杂度和空间复杂度。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“中位数”的定义以及“升序序列”的基本性质。虽然概念基础，但题目对“两个序列的中位数”定义进行了特定化（合并后的中位数），考生需准确理解这一复合定义，而非简单记忆单个序列的中位数公式。
- **K2 = 2**: 评分理由。本题不涉及复杂的数值计算，主要涉及索引的计算（如 `mid = (low + high) / 2`）和比较操作。计算量极小，几乎不存在因计算错误导致失分的情况。
- **K3 = 4**: 评分理由。解题过程需要多步逻辑推演。首先需识别出暴力归并法（$O(N)$）不符合“尽可能高效”的要求，进而推导出分治策略。在分治过程中，需要根据两个中位数的大小关系（$a < b, a > b, a = b$）进行不同的区间裁剪，并递归或迭代处理，逻辑链条较长且需保持状态一致性。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。
    1. **效率陷阱**：题目强调“时间和空间两方面都尽可能高效”，若使用归并排序思路（$O(N)$时间，$O(N)$空间）只能得部分分，必须意识到 $O(\log N)$ 才是目标。
    2. **边界陷阱**：在裁剪区间时，必须保证两个序列剩余部分的长度相等，且中位数的定义在子序列中依然适用（即始终取 $\lceil L/2 \rceil$ 位置）。若处理不当，可能导致索引越界或逻辑错误。
    3. **奇偶性陷阱**：虽然题目给定等长，但在递归过程中，若长度变为1，需特殊处理。
- **K5 = 2**: 评分理由。主要是在数据结构（数组/序列）内部进行操作，涉及两个序列 A 和 B 的状态同步更新（指针或索引的移动），属于同一子系统内的双向状态交互，未跨越到操作系统、网络等其他领域。
- **雷达形状**: 呈现“中间高、两头低”的纺锤形或菱形。K1基础认知适中，K2计算极低，K3推演和K4条件路由较高，K5跨域联动较低。这符合典型算法设计题的特征：重逻辑、重策略、轻计算。

## 考察模式
- **模式**: 算法设计型
- **理由**: 题目明确要求“设计一个...算法”，并分三步要求：设计思想、代码实现、复杂度分析。这是标准的算法设计综合题，考察考生从问题抽象到具体实现再到理论评估的全过程能力。

## 解题思路分析
- **核心思路**: 采用**分治法（Divide and Conquer）**或**二分查找**的思想。通过比较两个序列各自的中位数，每次排除掉不可能包含最终中位数的一半元素，从而将问题规模减半，直到序列长度缩减为1或2。
- **关键步骤**:
    1. **初始化**：设置两个序列 A 和 B 的查找区间 `[lowA, highA]` 和 `[lowB, highB]`，初始为整个序列。
    2. **循环/递归条件**：当两个区间的长度大于1时，继续执行以下步骤。
    3. **求中位数**：分别求出当前区间 A 和 B 的中位数 `midA` 和 `midB`。注意中位数位置索引为 `low + (high - low + 1) / 2`（向上取整）。
    4. **比较与裁剪**：
       - 若 `midA == midB`：则 `midA` 即为所求，返回。
       - 若 `midA < midB`：说明最终中位数在 A 的后半部分和 B 的前半部分。舍弃 A 的前半部分（包括 `midA`），舍弃 B 的后半部分（不包括 `midB`，因为 `midB` 可能比最终中位数大，但需保留边界以维持长度平衡，具体实现中通常保留 `midB` 或根据长度奇偶性调整，标准解法通常保留 `midB` 所在的左半部分，舍弃右半部分，同时 A 舍弃左半部分）。*修正：标准解法中，若 $a < b$，中位数在 $[a, b]$ 之间。A 中 $a$ 及其左侧元素均小于等于 $a$，肯定小于最终中位数（除非相等），故舍弃 A 的左半部分；B 中 $b$ 及其右侧元素均大于等于 $b$，肯定大于最终中位数，故舍弃 B 的右半部分。*
       - 若 `midA > midB`：对称处理，舍弃 A 的右半部分，舍弃 B 的左半部分。
    5. **终止条件**：当区间长度缩减为1时，返回 `min(A[lowA], B[lowB])`。
- **易错点**:
    1. **中位数索引计算错误**：混淆向下取整和向上取整，导致选取的元素不是定义中的中位数。
    2. **裁剪范围错误**：在 $a < b$ 时，错误地舍弃了 B 的左半部分或 A 的右半部分。
    3. **长度不等处理**：虽然题目保证初始等长，但在递归/迭代过程中，若裁剪策略不当，可能导致两个序列剩余长度不等，破坏算法前提。
    4. **空间复杂度**：若使用递归实现，需注意栈空间开销；若使用迭代实现，空间复杂度为 $O(1)$，更符合“空间高效”的要求。

## 核心陷阱
- **核心陷阱**: **“高效”的定义与归并法的诱惑**。
    许多考生第一反应是将两个序列归并成一个新序列，然后取中位数。这种方法时间复杂度为 $O(N)$，空间复杂度为 $O(N)$（若创建新数组）或 $O(1)$（若仅指针移动但不实际合并）。然而，题目要求“时间和空间两方面都尽可能高效”，暗示存在 $O(\log N)$ 的解法。未能跳出归并思维，仅使用 $O(N)$ 算法，将无法获得满分。此外，在分治裁剪时，必须严格保证每次裁剪后两个序列的剩余长度依然相等，否则后续的中位数定义将失效。

## 考察能力
本题核心考察考生**在约束条件下（时间/空间高效）运用分治策略优化算法设计的能力**，以及对**算法复杂度分析**和**边界条件处理**的严谨性。
