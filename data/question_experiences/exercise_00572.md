# 练习题 Q1 — HTTP Cookie 本质与安全属性辨析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/应用层
- **难度**: 待评估

## 题干原文
以下关于 HTTP Cookie 的陈述中，哪一项是不正确的？（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要调用“Cookie 的本质定义”这一核心概念。不是 2 分因为仅靠常识无法区分“代码”与“数据”，需明确记忆 Cookie 是纯文本键值对而非可执行代码；不是 4 分因为无需辨析多个易混概念（如 Session 与 Cookie 的区别），只需掌握 Cookie 单一定义即可。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或协议字段解析，无需执行代入计算。
- **K3 = 1**: 评分理由。无需多步串行推演。解题过程为直接的概念匹配：判断“Cookie 是代码”这一陈述的真伪，一步到位。
- **K4 = 3**: 评分理由。存在常规陷阱。题干问“不正确”，且选项 A 利用了大众对“Cookie 危害性”的模糊认知（知道它不安全，但误以为是因为它是代码）。考生需避开“因为不安全所以是代码”的逻辑陷阱，识别出“不安全”与“是代码”无必然因果关系。
- **K5 = 1**: 评分理由。仅涉及应用层 HTTP 协议中的 Cookie 机制，未涉及传输层、网络层或操作系统内核等其他子系统的状态传递或耦合。
- **雷达形状**: K1 主导型（概念记忆为主），K4 略有突起（存在语义陷阱），整体呈现低计算、低推演的特征。

## 考察模式
- **模式**: 概念型
- **理由**: 题目核心在于考察考生对 HTTP Cookie 基本定义（数据格式、存储位置、功能）的准确记忆与理解，而非通过计算或复杂逻辑推理得出结论。

## 选项级分析
- **选项A**: [正确选项/错误陈述] — 针对“Cookie 是恶意代码”的错误认知。这类学生通常听说过 Cookie 涉及隐私泄露或 XSS 攻击，因此潜意识认为它是一种“代码片段”。实际上，Cookie 只是服务器发送给客户端的纯文本字符串（键值对），本身不具备可执行性，不能直接危害系统安全，其风险在于被窃取或篡改后导致的会话劫持或隐私泄露。
- **选项B**: [干扰/正确陈述] — 针对对 HTTP 协议交互过程不熟悉的学生。Cookie 确实是通过 HTTP 响应头（Set-Cookie）和请求头（Cookie）在服务器与客户端之间传递的，进入用户的浏览器（操作区域）存储。
- **选项C**: [干扰/正确陈述] — 针对对 Cookie 属性不了解的学生。Cookie 确实包含 `Expires` 或 `Max-Age` 字段，用于定义过期时间，这是其基本属性之一。
- **选项D**: [干扰/正确陈述] — 针对对 Cookie 应用场景不了解的学生。Cookie 最经典的应用之一就是记录用户登录状态、偏好设置以及跟踪浏览行为（如广告追踪），这是其设计初衷之一。
- **干扰策略**: 概念混淆。利用“安全性”与“代码属性”之间的强关联错觉进行干扰。考生容易因为知道 Cookie 有安全风险，就错误地将其归类为“代码”，从而忽略了其“纯数据”的本质。

## 核心陷阱
- **核心陷阱**: **“安全性”与“可执行性”的概念混淆**。陷阱在于让考生误以为“危及安全”等同于“是代码片段”。实际上，纯数据（如 Cookie）若被恶意利用（如 CSRF、Session Hijacking）同样危及安全，但这不改变其非代码的本质。

## 考察能力
一句话概括本题核心考察的能力：准确区分 HTTP Cookie 作为“纯文本数据”的本质属性与其在网络安全中潜在风险之间的逻辑关系。
