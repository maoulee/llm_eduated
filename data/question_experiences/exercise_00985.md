# 练习题 Q1 — 双链表指针交换与反转逻辑推演

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握双链表的基本结构（prev/next指针含义）以及指针操作的基本语法。不是4分因为不需要辨析多个易混的高级概念，只需理解标准的双链表定义。
- **K2 = 2**: 评分理由。单步操作仅为指针赋值和交换，没有复杂的数值计算。不是1分因为涉及指针指向的变化，比简单的数值代入稍复杂。
- **K3 = 4**: 评分理由。需要在明确规则下进行多步串行推演。链表有6个节点，虽然逻辑重复，但考生需要在脑海中或草稿纸上模拟至少3-4次循环迭代，跟踪`current`、`temp`以及节点内部指针的变化，步骤较多且需记忆中间状态。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。最关键的陷阱在于循环结束后`head_ref`的更新逻辑。许多学生可能只关注了节点内部指针的交换，而忽略了最后`*head_ref = temp->prev`这一步对头指针的重定向。此外，`current = current->prev`这一行在指针交换后，实际上是指向“原next”节点，这种逻辑反转容易出错。
- **K5 = 1**: 评分理由。单系统内部操作。仅涉及链表这一种数据结构内部的指针操作，不涉及与其他子系统（如树、图、栈等）的状态传递或耦合。
- **雷达形状**: K3/K4 双高型（推演与陷阱主导）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖公式记忆或复杂计算，而是要求考生通过代码逻辑，逐步推演数据结构状态的变化。核心在于理解指针交换对链表拓扑结构的影响，属于典型的代码阅读与逻辑推理题。

## 选项级分析
- **选项A**: [干扰] — 针对“两两交换”的错误认知。这类学生可能误以为代码是交换相邻节点的位置（如1和2换，3和4换），而不是整个链表的反转。这是将“反转”与“两两交换”概念混淆。
- **选项B**: [干扰] — 针对“头指针未更新”或“逻辑中断”的错误认知。结果以6结尾，但头部是5，说明链表断裂或头指针指向错误。这类学生可能正确执行了部分反转，但在最后一步头指针更新时出错，或者误以为`temp`指向的是倒数第二个节点。
- **选项C**: [正确] — 正确执行了全链表反转，且头指针正确指向原尾节点6。
- **选项D**: [干扰] — 针对“局部反转”或“指针交换逻辑错误”的认知。前部分正确（6-3），但后部分（1-2）顺序错误。这类学生可能在推演过程中，对最后几个节点的指针交换逻辑产生混乱，或者误以为`current`的移动方式导致最后两个节点未被正确处理。
- **干扰策略**: 概念混淆（A）、状态追踪失误（B、D）

## 核心陷阱
- **核心陷阱**: **头指针的最终重定向逻辑**。
  代码中`while`循环负责交换每个节点的`prev`和`next`，这完成了链表内部连接的反转。但是，`head_ref`（头指针）本身在循环中并未直接更新。循环结束后，`current`为NULL，`temp`指向原链表的最后一个节点（即新链表的第一个节点的前驱，但在反转逻辑中，这里的`temp`在最后一次迭代中保存的是原尾节点的`prev`，即原倒数第二个节点？不，让我们仔细推导：
  
  *推导修正*：
  1. `current`=1. `temp`=NULL. `1.prev`=2, `1.next`=NULL. `current`=2.
  2. `current`=2. `temp`=1. `2.prev`=3, `2.next`=1. `current`=3.
  ...
  5. `current`=6. `temp`=5. `6.prev`=NULL, `6.next`=5. `current`=NULL.
  循环结束。此时`temp`=5。
  执行 `*head_ref = temp->prev`。此时`temp`是节点5。节点5在反转后，其`prev`指向6（因为5的prev和next交换了，原next是6，现prev是6）。
  所以 `*head_ref` = 6。
  
  陷阱在于：如果不仔细看最后两行代码，或者错误地认为`temp`在循环结束时指向NULL或头节点，就会选错。很多学生知道是反转，但不知道头指针具体指向哪个节点，容易凭直觉选C，但如果逻辑不清，可能会在B和D之间犹豫。真正的陷阱是**理解`temp`在循环结束时的状态以及`temp->prev`在反转后的含义**。
