# 2020 Q36 — 停等协议信道利用率计算

## 基本信息
- **年份**: 2020  **题位**: Q36  **题型**: 选择题
- **知识点**: CN-3 > 可靠传输机制 > 停止-等待协议, CN-3 > 可靠传输机制 > 信道利用率计算
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
假设主机采用停等协议向主机乙发送数据帧，数据帧长与确认帧长均为 1000B。数据传输速率是 10kbps，单项传播延时是 200ms。则甲的最大信道利用率（ ）。
ARQ协议
信道利用率

A. 80%；
B. 66.7%；
C. 44.4%；
D. 40%

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆“停止-等待协议”的工作流程（发送-等待-接收-确认）以及“信道利用率”的定义（有效传输时间/总周期时间）。属于标准的核心概念记忆，不涉及复杂辨析。
- **K2 = 3**: 评分理由。涉及单位换算（Byte 到 bit，kbps 到 bps 或 ms 到 s），计算发送时延 $t_{frame} = \frac{1000 \times 8}{10 \times 10^3} = 0.8s = 800ms$。虽然计算本身简单，但单位不统一（B, kbps, ms）增加了出错概率，属于标准难度的单步代入。
- **K3 = 3**: 评分理由。需要推演一个完整的通信周期：发送数据帧 -> 数据传播 -> 发送确认帧 -> 确认传播。共4个阶段的时间累加。步骤清晰但需按顺序串行执行，属于3-5步的标准推演。
- **K4 = 4**: 评分理由。存在明显的隐含前提和易错点。
    1. **确认帧的处理**：题目明确给出“确认帧长均为1000B”，这意味着确认帧也有发送时延，且必须计入周期。很多学生习惯性地忽略确认帧的发送时间或认为其极短可忽略，这是最大的陷阱。
    2. **信道利用率的定义主体**：题目问的是“甲”的利用率。在停等协议中，甲发送数据后必须等待乙的确认。因此分母是甲从开始发送数据到收到确认的总时间。如果误以为是双向信道利用率或忽略确认帧发送时间，会导致错误。
    3. **单位陷阱**：10kbps 是 $10 \times 10^3$ bps 还是 $10 \times 2^{10}$ bps？在计算机网络考研中，通常默认 $1k=1000$，但需考生具备这种常识判断。
- **K5 = 1**: 评分理由。本题仅涉及数据链路层的可靠传输机制，不涉及网络层、传输层或其他子系统的状态联动，属于单系统内部计算。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，主要考察对协议细节和隐含条件的识别）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的参数（帧长、速率、时延）计算具体的数值结果。虽然基于协议原理，但最终落脚点是数学计算和单位换算。

## 选项级分析
- **选项A**: [干扰] — 针对**忽略确认帧发送时延**的错误认知。
    - 错误推导：$T = t_{data} + 2 \times t_{prop} = 800 + 200 + 200 = 1200ms$（错误地认为确认瞬间完成或忽略确认发送）。
    - 或者：$T = t_{data} + t_{prop} + t_{prop} = 1200ms$。
    - 利用率 $= 800 / 1200 \approx 66.7\%$ (对应B，见下)。
    - 若误算为 $T = 800 + 200 = 1000ms$ (只算单程传播)，则 $800/1000 = 80\%$。这通常是因为完全忽略了回程的任何时间（传播+确认发送）。
- **选项B**: [干扰] — 针对**忽略确认帧发送时延，但计入往返传播时延**的错误认知。
    - 错误推导：认为确认帧极短，发送时间为0。
    - $T = t_{data\_send} + t_{prop} + t_{prop} = 800 + 200 + 200 = 1200ms$。
    - 利用率 $= 800 / 1200 = 2/3 \approx 66.7\%$。
    - 这是最常见的错误，因为实际网络中ACK通常很短，学生容易形成思维定势忽略其发送时延，但本题特意给出ACK长度，旨在考察严谨性。
- **选项C**: [干扰] — 针对**计算错误或公式混淆**的错误认知。
    - 可能来源：$800 / (800+200+800) = 800/1800 \approx 44.4\%$。漏加了一个传播时延（例如只加了去程传播，忘了回程传播，或者反之）。
- **选项D**: [正确] — 正确计算。
    - $t_{send} = 1000 \times 8 / 10000 = 0.8s = 800ms$。
    - $T = t_{send\_data} + t_{prop} + t_{send\_ack} + t_{prop} = 800 + 200 + 800 + 200 = 2000ms$。
    - 利用率 $= 800 / 2000 = 40\%$。

- **干扰策略**: 概念混淆（是否计入ACK发送时延）与计算陷阱（单位换算、漏项）。

## 核心陷阱
**确认帧（ACK）的发送时延不可忽略**。
题目明确给出了确认帧的长度（1000B），这与数据帧相同。在停等协议中，发送方必须等待确认帧**完全接收**才能发送下一帧。因此，总周期 $T$ 必须包含：数据帧发送时间 + 数据传播时延 + **确认帧发送时间** + 确认传播时延。许多考生受实际网络中ACK较短的影响，习惯性忽略ACK的发送时间，从而选择B。

## 考察能力
考察考生对停止-等待协议完整工作周期的理解，以及在给定具体参数下，严谨进行单位换算和时间累加计算的能力。
