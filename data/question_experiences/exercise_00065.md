# 练习题 Q1 — 寄存器分配与代码优化

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/CPU调度
- **难度**: 待评估

## 题干原文
在一种仅支持寄存器作为操作数的处理器上执行以下代码段。该处理器的每条指令最多可包含两个源操作数和一个目标操作数。假设在此代码段执行完毕后，所有变量都不再使用。
```c
c = a + b;
d = c * a;
e = c + a;
x = c * c;
if (x > a) {
    y = a * a;
} else {
    d = d * d;
    e = e * e;
}
```
假设处理器仅有两个通用寄存器，并且编译器唯一允许的优化是代码移动（code motion），即在不改变程序语义的前提下移动指令位置。请问，在编译生成的代码中，最少需要进行多少次存储器溢出（即中间结果需要写入内存）？（ ）
- 选项:
  A: 0
  B: 1
  C: 2
  D: 3
- 正确答案: B
- 解析（参考）: 解析
r1: a, r2: b → c = a + b
r1: a, r2: c → x = c * c
r1: a, r2: x → 必须将 c 存入内存（因无法预知 x > a 的分支）
r1: y, r2: x → y = a * a
最佳情况下的最小溢出次数为 1 次（当执行 x > a 分支时）
由于只有两个寄存器可用，在计算 x = c * c 后，若要继续执行后续逻辑，必须将中间结果 c 存入内存以腾出寄存器空间。这是唯一不可避免的存储器溢出操作。
- 知识标签: ['操作系统/CPU调度']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“寄存器溢出（Spill）”、“代码移动（Code Motion）”以及“寄存器分配”的基本概念。虽然不涉及复杂的公式记忆，但需要理解编译器后端优化的基本术语和硬件约束（仅2个寄存器、仅寄存器操作数）。不是4分因为不需要辨析多个易混的高级编译优化概念，核心概念较为单一。
- **K2 = 1**: 评分理由。本题几乎没有数值计算，主要是逻辑状态的跟踪。不涉及幂次、换算等计算过程。
- **K3 = 4**: 评分理由。需要在明确规则（2寄存器、代码移动）下进行多步串行推演。考生必须模拟指令执行流，跟踪每个变量的“活跃区间（Live Range）”，并判断在每一步是否需要寄存器。特别是需要推演“代码移动”如何改变变量的活跃期，从而减少溢出。步骤较多且需记忆中间状态（哪些变量在寄存器中，哪些在内存中）。
- **K4 = 5**: 评分理由。存在极深的隐含前提和反直觉陷阱。
    1. **隐含前提**：题目问的是“编译生成的代码中...最少”，这意味着我们要寻找一种**静态的**指令排列方式，使得在**所有可能的执行路径**中，溢出次数都不超过该值，或者更准确地说，是寻找一种编译策略，使得最坏情况下的溢出最少？不，题目问的是“最少需要进行多少次”，结合选项和常规考法，通常指在最优的代码移动策略下，**必然发生**的溢出次数。
    2. **反直觉/陷阱**：很多学生会忽略“代码移动”的作用，直接按顺序执行，发现需要多次溢出。或者，学生可能认为`if-else`分支中，只要走一条路，另一条路的溢出就不算？不，编译器生成的代码必须包含所有分支的指令。关键在于：`c`在计算`x`之后，在`if`分支中不再使用，但在`else`分支中，`d`和`e`依赖于`c`（间接依赖，因为`d`和`e`是用`c`算出来的，但`d`和`e`本身已经计算完毕存储在寄存器或内存中？注意：`d=c*a`, `e=c+a`。如果`d`和`e`保留在寄存器中，则`else`分支不需要`c`。如果`d`和`e`被溢出，则需要从内存读取。
    3. **核心难点**：识别出`c`的活跃期可以通过代码移动被截断。`c`用于计算`d, e, x`。`x`用于判断。`d, e`用于`else`。`a`全程活跃。`b`仅在第一步活跃。通过移动`x=c*c`到`d, e`计算之后，或者调整顺序，可以优化寄存器使用。最关键的陷阱在于理解“代码移动”允许我们将`x`的计算推迟，或者将`d, e`的计算提前，从而让`c`在不再需要时尽早释放寄存器。
- **K5 = 2**: 评分理由。主要涉及编译器优化（属于系统软件/编译原理范畴）与硬件资源（寄存器）的交互。虽然标签是OS，但实质是编译原理中的寄存器分配问题。在OS考试中，这属于“指令执行与资源管理”的交叉领域，但并未深度耦合OS的其他子系统（如内存管理、进程同步等），主要是单点资源约束。

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖死记硬背的概念，也不依赖复杂的数学计算，而是要求考生在给定的严格约束（2寄存器、代码移动）下，通过逻辑推理和状态模拟，找出最优的指令调度方案。核心在于对“变量活跃性”和“寄存器压力”的动态分析。

        1. `r1=a, r2=b`

        4. `e = c+a` -> `r1=e` (r1=e, r2=c)  [假设e存入r1]
