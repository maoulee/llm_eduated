# 2021年 Q16 — Cache行容量计算（含有效位与脏位）

## 基本信息
- **年份**: 2021  **题位**: Q16  **题型**: 选择题
- **知识点**: Cache地址映射, Cache行结构, Write Back策略
- **考纲对应**: 第三章 存储系统 -> 高速缓冲存储器 Cache -> Cache地址映射, Cache写策略

## 题干原文
[2021年考研真题第16题]	若计算机主存地址为32位，按字节编址，Cache数据区大小为32KB,主存块大小为32B,采用直接映射方式和回写(Write Back)策略，则Cache行的位数至少是

## K1-K5 评分与解析
- **K1 = 3**: 3 — **标准**。必须准确记忆“直接映射”、“回写策略”、“Cache行结构（Tag+Index+Data+Valid+Dirty）”等核心概念定义。若不知道回写需要脏位、映射需要标记位，完全无法入题。不是4分，因为不需要辨析极易混淆的冷门细节，这些都是Cache章节的基础高频考点。
- **K2 = 4**: 4 — **较高**。单步计算本身不复杂，但涉及多级单位统一换算（KB->B, B->bits）以及多个字段的累加。特别是数据区位数计算 $32B \times 8 = 256$ 位，容易与字节数混淆；Tag位计算 $32-10-5=17$ 也容易出错。一旦中间某一步（如Index位数或Data位数）算错，最终结果全盘皆输。
- **K3 = 3**: 3 — **标准**。需按固定流程走完步骤：1. 计算块大小和Cache总块数；2. 确定地址划分（Offset, Index, Tag）；3. 确定额外位（Valid, Dirty）；4. 累加所有位数。路径唯一，步骤约4-5步。
- **K4 = 4**: 4 — **较高**。隐含前提很深，必须依靠对机制本质的理解才能路由。陷阱在于“回写(Write Back)”策略隐含了需要**脏位(Dirty Bit)**，而“直接映射”隐含了需要**标记位(Tag)**和**有效位(Valid Bit)**。若仅凭直觉认为Cache行只有数据和Tag，或者漏掉Valid位，就会掉坑。这是典型的机制隐含条件陷阱。
- **K5 = 1**: 1 — **微弱**。单一知识点内部解决（Cache结构），不涉及CPU流水线、中断等其他系统的状态传递。
- **雷达形状**: K4陷阱型

## 考察模式
- **模式**: 计算型
- **理由**: 题干给出具体参数，4个选项为不同的计算结果，学生需通过分步计算得出唯一正确答案。

## 选项级分析
- **选项A**: [正确] — 正确计算了Data(256位) + Tag(17位) + Index(0位,因直接映射行号隐含在地址中不作为行内存储,或者理解为行号由地址直接索引,行内只需存Tag) + Valid(1位) + Dirty(1位) = 275位。*注：严格来说，Cache行存储的是Tag, Data, Valid, Dirty。Index用于寻址该行，不存储在行内。*
- **选项B**: [干扰] — 针对**漏算有效位或脏位**的错误认知。例如只算了Tag和Data，或者只算了Dirty漏了Valid。通常结果为 256+17=273 或 256+17+1=274 附近。适合基础薄弱，对Cache行结构记忆不全的学生。
- **选项C**: [干扰] — 针对**计算错误或漏算更多**的错误认知。例如将数据区按字节计算未乘8，或者Tag计算错误。适合粗心大意或单位换算不清的学生。
- **选项D**: [干扰] — 针对**标记位计算错误**的错误认知。例如错误计算Index位数导致Tag位数错误，或者混淆了主存地址总位数与Tag位数的关系。适合对地址划分逻辑不清的学生。
- **干扰策略**: 嵌套陷阱

## 核心陷阱
- **核心陷阱**: **回写策略隐含的脏位（Dirty Bit）与Cache行必备的有效位（Valid Bit）的遗漏**。
- **错误路径**: 学生往往能正确计算出Tag位数（17位）和数据位数（256位），但容易忽略“直接映射”下每行必须有一个Valid位来判断该行数据是否有效，以及“回写”策略下必须有一个Dirty位来标记数据是否被修改过（以便写回主存）。漏掉这两个1位的小项，导致最终答案偏差。

## 考察能力
精准掌握Cache行内部结构组成及其与映射方式、写策略的对应关系，并能进行细致的位数累加计算。
