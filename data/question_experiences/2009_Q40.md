# 2009 Q40 — FTP 控制连接与数据连接的分离机制

## 基本信息
- **年份**: 2009  **题位**: Q40  **题型**: 选择题
- **知识点**: CN-6 > 应用层 > 文件传输协议 FTP
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
FTP 客户和服务器间传递 FTP 命令时，使用的连接是（）。

A. 建立在 TCP 之上的控制连接
B. 建立在 TCP 之上的数据连接
C. 建立在 UDP 之上的控制连接
D. 建立在 UDP 之上的数据连接

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。本题需要调用 FTP 协议的核心定义，即“双连接机制”（控制连接与数据连接分离）以及底层传输协议的选择（TCP）。这属于标准的基础概念记忆，不需要辨析多个易混的高级概念，但必须准确记忆 FTP 的基本架构。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，完全属于定性判断。
- **K3 = 1**: 评分理由。解题过程无需多步串行推演，直接根据“传递 FTP 命令”这一关键词，映射到“控制连接”这一概念即可，逻辑链条极短。
- **K4 = 2**: 评分理由。存在常规注意点，即区分“命令”与“数据”分别走哪条连接。虽然 FTP 的双连接机制是经典考点，但对于初学者来说，容易混淆控制连接和数据连接的用途，属于常规的概念辨析陷阱，而非深层隐含前提。
- **K5 = 1**: 评分理由。本题仅涉及应用层 FTP 协议自身的内部机制，不需要跨越传输层、网络层或其他应用层协议进行状态联动分析。

- **雷达形状**: K1 主导型（基础概念记忆型），K4 略有凸起（概念辨析）。整体呈现低计算、低推演、重记忆的特征。

## 考察模式
- **模式**: 概念型
- **理由**: 题目直接询问协议的具体实现细节（连接类型），考察的是对 FTP 协议架构（控制/数据分离）及底层依赖（TCP）的记忆和理解，不涉及复杂逻辑推理或计算。

## 选项级分析
- **选项 A**: [正确] — 针对正确认知。FTP 为了保证可靠性，使用 TCP 协议；同时，FTP 采用带外传送控制信息，即使用独立的控制连接（默认端口 21）来传递命令和响应。
- **选项 B**: [干扰] — 针对“混淆控制与数据连接”的错误认知。这类学生知道 FTP 使用 TCP，也隐约记得有两条连接，但记反了用途，误以为命令走数据连接，或者认为所有交互都走同一条连接。
- **选项 C**: [干扰] — 针对“混淆传输层协议”的错误认知。这类学生可能知道 FTP 有控制连接，但错误地认为应用层协议可以使用 UDP，或者将 FTP 与 TFTP（简单文件传输协议，基于 UDP）混淆。
- **选项 D**: [干扰] — 针对“双重错误认知”的错误认知。既选错了传输层协议（UDP），又选错了连接类型（数据连接）。通常作为陪跑选项，排除掉知道 TCP 但记错连接类型的学生，以及知道控制连接但记错协议的学生。

- **干扰策略**: 概念混淆。通过混合“TCP/UDP”和“控制/数据”两个维度的属性，构建四个组合，考察考生对 FTP 协议两个核心特征（基于 TCP、双连接分离）的精准掌握。

## 核心陷阱
- **核心陷阱**: **TFTP 与 FTP 的混淆** 以及 **控制连接与数据连接功能的混淆**。
    1. 考生容易将 FTP（File Transfer Protocol，基于 TCP，双连接）与 TFTP（Trivial File Transfer Protocol，基于 UDP，单连接）搞混，从而误选 UDP 选项。
    2. 考生容易忘记 FTP 的“带外控制”特性，误以为命令和数据走同一条连接，或者记反了哪条连接传命令。

## 考察能力
准确记忆并区分 FTP 协议的双连接架构（控制连接传命令、数据连接传文件）及其底层传输协议（TCP）的能力。
