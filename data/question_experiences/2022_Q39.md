# 2022 Q39 — TCP连接释放时间计算

## 基本信息
- **年份**: 2022  **题位**: Q39  **题型**: 选择题
- **知识点**: CN-5 > TCP协议 > TCP连接释放
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
假设客户 C 和服务器 S 已建立一个 TCP 连接，通信往返时间 RTT = 50 ms, 最长报文段寿命 MSL= 800ms, 数据传输结束后，C 主动请求断开连接。若从 C 主动向 S 发出 FIN 段时刻算起，则 C 和 S 进入 CLOSED 状态所需的时间至少分别是 ( )。

A. 850 ms, 50 ms
B. 1650 ms, 50 ms
C. 850 ms, 75 ms
D. 1650 ms, 75 ms

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。需要精确记忆 TCP 四次挥手的完整状态机转换过程，特别是 `TIME-WAIT` 状态的持续时间（2MSL）以及 `FIN-WAIT-2` 和 `CLOSE-WAIT` 在“最少时间”场景下的处理逻辑。不仅仅是知道有四次挥手，还要知道每个状态对应的触发条件和持续时间定义。
- **K2 = 3**: 评分理由。涉及简单的算术运算（1.5 RTT, 1 RTT + 2 MSL），但单位统一和系数提取（如 1.5 倍 RTT）需要一定的细心程度，属于标准难度的计算。
- **K3 = 4**: 评分理由。推演步骤较多且需串行执行：1. C 发 FIN；2. S 收 FIN 并立即回 FIN+ACK（合并第2、3步）；3. C 收 FIN+ACK 并回 ACK；4. C 等待 2MSL；5. S 收 ACK 后关闭。需要清晰地在脑海中构建时间轴，区分 C 和 S 两个端点的状态变化时间点。
- **K4 = 5**: 评分理由。存在极强的隐含前提和反直觉陷阱。
    1. **“至少”的含义**：意味着服务器 S 收到 FIN 后没有数据要发，因此可以将 ACK 和 FIN 合并发送（即第2步和第3步合并），这是解题的关键前提，题干未明说但必须意识到。
    2. **S 的关闭时间**：很多学生误以为 S 也要等 2MSL 或等待 C 的确认，实际上 S 在收到 C 对 S-FIN 的 ACK 后即可进入 CLOSED（在合并发送场景下，S 发送 FIN 后，收到 C 的 ACK 即完成，无需等待 MSL）。
    3. **C 的关闭时间**：必须包含 2MSL 的等待时间，这是为了处理最后一个 ACK 丢失的情况，容易遗漏。
- **K5 = 2**: 评分理由。主要局限于 TCP 传输层内部的状态机逻辑，不涉及网络层或应用层的复杂交互，属于单系统内的状态流转。
- **雷达形状**: K4 陷阱主导型（K4 极高，K1/K3 较高，K2 中等）

## 考察模式
- **模式**: 综合型（推理+计算）
- **理由**: 本题不仅要求考生记忆 TCP 释放的协议细节（概念），还需要根据“最少时间”这一约束条件进行逻辑推理（确定是否合并报文），最后结合给定的 RTT 和 MSL 数值进行精确的时间轴计算。

## 选项级分析
- **选项 A**: [干扰] — 针对错误认知：认为 C 只需要等待 1 MSL 或者计算错误。850ms = 50 + 800，可能是误以为 C 只需要等 1 MSL，或者误以为 S 的时间计算有误。这类学生可能混淆了 MSL 的作用或次数。
- **选项 B**: [干扰] — 针对错误认知：S 的时间计算错误。50ms 是 1 RTT，可能误以为 S 在收到 C 的 FIN 后，经过一个 RTT 就能关闭，忽略了 S 发送 FIN 并收到 ACK 的过程，或者误以为 S 不需要发送 FIN（半关闭误解）。
- **选项 C**: [干扰] — 针对错误认知：C 的时间计算错误。850ms 同样对应 C 只等 1 MSL 的错误逻辑。同时 S 的时间 75ms 是正确的，说明考生可能掌握了 S 的逻辑但搞错了 C 的 TIME-WAIT 时长。
- **选项 D**: [正确] — C: 1650ms (1 RTT + 2 MSL = 50 + 1600), S: 75ms (1.5 RTT = 75)。符合“最少时间”假设下的标准推导。

**干扰策略**: 概念混淆与计算陷阱。主要利用考生对 `TIME-WAIT` 状态持续时间（2MSL vs 1MSL）的记忆模糊，以及对服务器端关闭流程（是否合并报文、何时进入 CLOSED）的逻辑推演不清来设置干扰项。

## 核心陷阱
**核心陷阱**: 
1. **服务器 S 的“最少时间”逻辑**：必须意识到在“最少时间”假设下，S 收到 FIN 后无数据发送，会将 ACK 和 FIN 合并发送。因此 S 进入 CLOSED 的时间点是在它发出 FIN 并收到 C 的 ACK 之后。时间轴为：T=0 C发FIN -> T=25ms S收FIN并发FIN+ACK -> T=50ms C收FIN+ACK并发ACK -> T=75ms S收ACK进入CLOSED。即 1.5 RTT。
2. **客户端 C 的 TIME-WAIT 时长**：C 在发送最后一个 ACK 后，必须进入 `TIME-WAIT` 状态并等待 2MSL。因此 C 进入 CLOSED 的时间是 T=50ms (收到S的FIN) + 2MSL (等待) = 50 + 1600 = 1650ms。注意，这里的 1 RTT 是指从 C 发 FIN 到 C 收到 S 的 FIN+ACK 的时间，之后才开始计时 2MSL。

## 考察能力
本题核心考察考生对 TCP 连接释放状态机（特别是 TIME-WAIT 状态机制）的深度理解，以及在特定约束条件（最少时间、报文合并）下进行多端点时间轴推演的能力。
