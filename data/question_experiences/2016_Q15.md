# 2016年 Q15 — Cache缺失率计算(循环访问数组)

## 基本信息
- **年份**: 2016  **题位**: Q15  **题型**: 选择题
- **知识点**: Cache 地址映射方式（直接映射）, Cache 性能指标（命中率/缺失率）, 存储器局部性原理（空间局部性）
- **考纲对应**: 第三章 存储系统 → 高速缓冲存储器 Cache → Cache 地址映射, Cache 基本概念（命中率）

## 题干原文
[2016年考研真题第15题]有如下C语言程序段：
 for(k=0;k<1000;k++) a[k]=a[k]+32;
 若数组a及变量k均为int型，int型数据占4B,数据Cache采用直接

## K1-K5 评分与解析
- **K1 = 3**: 3 — 必须准确记忆 Cache 直接映射（Direct Mapping）的机制、块（Block）的概念以及“读/写均视为访问 Cache”的规则才能入题。若对 Cache 基本工作原理模糊（如认为只有写才需要检查 Cache），则无法解题。高于 2 分是因为不能仅凭常识或模糊概念推导，必须精确理解硬件行为；低于 4 分是因为不涉及冷门细节或极易混淆的深层概念辨析（如写回 vs 写直达在本题缺失率计算中的特定影响，虽然涉及但属于标准流程）。
- **K2 = 3**: 3 — 需代入常规公式或逻辑进行计算：确定块大小（16B）容纳的数据元素个数（4个int），计算总访问次数（2000次），并根据局部性原理推导命中/缺失比例。涉及非 2 的幂次的除法（1000/4=250 块，但需注意循环步长与块大小的对齐关系，实际上是每 4 个元素一组，每组 8 次访问，1 次缺失）。虽然计算量不大，但需结合逻辑推理，非简单一步心算，故为 3 分。
- **K3 = 3**: 3 — 需按固定流程走完推演：1. 确定 Cache 块大小与数据类型关系 -> 2. 分析单次循环内的内存访问模式（读 a[k] 和 写 a[k]）-> 3. 结合直接映射特性，模拟第一个元素访问时的状态（缺失，调入整块）-> 4. 推导后续同一块内元素的访问状态（命中）。路径唯一，步数适中，属于标准的过程模拟。
- **K4 = 3**: 3 — 存在明确的陷阱词和隐含前提：1. 陷阱在于“每次循环有两次访存（读+写）”，许多学生容易只算一次；2. 隐含前提是直接映射中，当 k 递增时，只要不跨越块边界，后续访问均命中。若不触发对“块内局部性”和“直接映射冲突”的正确路由，容易陷入“每次访问都缺失”或“只算读取缺失”的错误。
- **K5 = 1**: 1 — 单一知识点内部解决，仅涉及 Cache 子系统与存储器层次结构中的数据访问规律，不涉及指令系统、ALU 或其他子系统的状态耦合。
- **雷达形状**: K3/K4 均衡型（侧重机制推演与陷阱识别）

## 考察模式
- **模式**: 代码数据分析型
- **理由**: 题干给出具体的 C 语言循环代码和数据定义，要求考生基于硬件机制（Cache）分析该代码执行过程中的性能指标（缺失率），选项为分析得出的具体数值结论。

## 选项级分析
- **选项A**: [干扰] — 针对“忽略写操作也是 Cache 访问”或“错误计算总访问次数”的认知错误。这类学生可能只考虑了读取 `a[k]` 的一次缺失，或者错误地认为写操作不经过 Cache（在写直达或写回策略下，写操作通常都涉及 Cache 检查或更新，且本题语境下通常假设写分配或写直达均会导致首次访问缺失）。若学生误以为只有读才计入缺失，或总次数算错，可能选此项。

## 核心陷阱
- **核心陷阱**: “一次循环包含两次访存”与“Cache 块的空间局部性”的双重陷阱。

## 考察能力
本题考查考生将高级语言代码映射到底层硬件行为（Cache 映射与局部性）的能力，以及对 Cache 缺失率计算中“访存总次数”与“局部性带来的批量命中”关系的精确量化分析能力。
