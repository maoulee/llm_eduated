# 2017 Q37 — 路由协议封装方式

## 基本信息
- **年份**: 2017  **题位**: Q37  **题型**: 选择题
- **知识点**: CN-4 > 路由协议 > RIP协议, CN-4 > 路由协议 > OSPF协议, CN-4 > 路由协议 > BGP协议
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
直接封装 RIP、OSPF、BGP 报文的协议分别是（ ）。

A. TCP、UDP、IP
B. TCP、IP、UDP
C. UDP、TCP、IP
D. UDP、IP、TCP

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。本题属于典型的概念记忆与辨析题。考生需要准确记忆三种主流路由协议（RIP, OSPF, BGP）各自使用的上层封装协议。这不仅仅是单一概念的记忆，而是需要对三个易混淆概念进行精确匹配。若未形成清晰的知识网络，极易在 UDP 和 IP 之间产生混淆（特别是 OSPF 直接封装在 IP 中这一特殊点），因此认知需求较高。不是5分因为不需要深层原理推导，纯靠记忆即可。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入。
- **K3 = 1**: 评分理由。解题过程无需多步串行推演，属于“检索-匹配”型思维，一步到位。
- **K4 = 3**: 评分理由。存在常规注意点/陷阱。主要陷阱在于 OSPF 的封装方式。许多学生习惯性地认为所有应用层或控制层协议都运行在 TCP 或 UDP 之上，从而忽略 OSPF 作为链路状态协议，为了减少开销和延迟，直接封装在 IP 数据报中（协议号 89）。此外，RIP 使用 UDP 1723 端口，BGP 使用 TCP 179 端口，这些细节若记忆模糊，容易选错。
- **K5 = 2**: 评分理由。虽然涉及网络层（IP）、传输层（TCP/UDP）和路由协议（应用层/控制层）的跨层关系，但题目仅考察静态的封装关系，不涉及动态的状态传递或复杂的跨层交互机制。提及了不同层级，但逻辑是单向且独立的。

- **雷达形状**: K1 主导型（高记忆、低计算、中陷阱）。图形呈现为左侧（K1）突出，右侧（K2-K3）极低，K4 中等高度的形状。

## 考察模式
- **模式**: 概念型
- **理由**: 题目核心在于考察考生对计算机网络中不同路由协议底层实现机制（即封装协议）的静态知识掌握程度，不涉及动态过程分析或定量计算。

## 选项级分析
- **选项A**: [干扰] — 针对错误认知：认为 RIP 用 TCP（可靠传输），OSPF 用 UDP，BGP 用 IP。这类学生可能混淆了 BGP 的可靠性需求（需 TCP）和 RIP 的简单性（UDP），同时错误地认为 OSPF 需要传输层支持。
- **选项B**: [干扰] — 针对错误认知：认为 RIP 用 TCP，OSPF 用 IP，BGP 用 UDP。这类学生正确识别了 OSPF 直接封装 IP，但完全搞反了 RIP 和 BGP 的传输层需求，可能误以为 BGP 像 RIP 一样简单，或者 RIP 需要像 BGP 一样可靠。
- **选项C**: [干扰] — 针对错误认知：认为 RIP 用 UDP，OSPF 用 TCP，BGP 用 IP。这类学生正确识别了 RIP 使用 UDP，但错误地给 OSPF 加上了 TCP 头（增加了不必要的开销），并错误地认为 BGP 直接封装在 IP 中（忽略了 BGP 需要可靠连接的特性）。
- **选项D**: [正确] — RIP 使用 UDP（端口 520），OSPF 直接封装在 IP 中（协议号 89），BGP 使用 TCP（端口 179）。

- **干扰策略**: 概念混淆。通过打乱三种协议与三种封装方式（TCP, UDP, IP）的对应关系，利用考生对“可靠性”与“封装层级”的模糊认知进行干扰。特别是利用 OSPF 不经过传输层这一反直觉（相对于常见应用协议）的特性作为主要区分点。

## 核心陷阱
- **核心陷阱**: **OSPF 的封装层级**。大多数网络协议（如 HTTP, DNS, RIP, BGP）都运行在 TCP 或 UDP 之上，但 OSPF 为了效率和实时性，直接封装在 IP 数据报中，不经过传输层。这是本题最大的失分点和区分点。其次是 BGP 必须使用 TCP 以保证路由信息更新的可靠性，这一点常被初学者忽略。

## 考察能力
准确记忆并区分 RIP、OSPF、BGP 三种路由协议在 TCP/IP 协议栈中的封装位置及传输层依赖关系。
