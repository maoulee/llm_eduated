# 练习题 Q1 — 滑动窗口协议链路利用率计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/数据链路层
- **难度**: 待评估

## 题干原文
考虑在发送方和接收方之间通过全双工无差错链路运行的滑动窗口流量控制协议。假设以下条件：
接收方处理数据帧所需时间可忽略不计。
发送方处理确认帧所需时间可忽略不计。
发送方有无限数量的数据帧可供发送。
数据帧大小为 2,000 比特，确认帧大小为 10 比特。
链路每个方向的数据速率为 1 Mbps（= 10⁶ 比特/秒）。
链路单向传播延迟为 100 ms。
为了实现 50% 的链路利用率，发送方窗口大小（以帧数为单位）的最小值（四舍五入到最接近的整数）是（  ）。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆并理解“链路利用率”、“滑动窗口协议”、“传输时延”、“传播时延”等核心概念，以及它们之间的基本关系公式。不是4分因为不需要辨析多个易混的高级协议细节（如Go-Back-N与Selective Repeat的具体差异对本题计算无影响，仅涉及通用窗口机制）。
- **K2 = 4**: 评分理由。计算过程涉及非2的幂次运算（2010/10^6），且包含多级换算（比特转秒，毫秒转秒），最后还需进行除法和小数处理。虽然步骤不多，但数值不友好，容易在计算精度或单位换算上出错，属于较高难度的单步/多步混合计算。
- **K3 = 2**: 评分理由。推演步骤较少：1. 计算总传输时延；2. 代入利用率公式；3. 求解N。逻辑链条短，无需复杂的中间状态记忆或多步串行推演。
- **K4 = 4**: 评分理由。存在显著的隐含前提和陷阱。首先，必须意识到“全双工”且“无差错”意味着ACK可以立即发送，但ACK的传输时延虽然小，在计算“一个完整周期”时，通常有两种理解：一种是简化模型（忽略ACK传输时延，只算RTT+Tx_data），另一种是精确模型（考虑ACK传输时延）。参考解析采用了将ACK传输时延计入总周期的方式（或者更准确地说，参考解析的公式 `effi = N / (1 + 2Tp/Tx)` 中的 Tx 被定义为 `2010/1Mbps`，这实际上是将一个数据帧和一个ACK帧的传输时间合并考虑，或者隐含了ACK紧随数据之后发送且占用信道时间的假设）。更关键的陷阱在于对“链路利用率”定义的理解：是指发送方发送数据的时间占比，还是整个信道被有效利用的时间占比？参考解析的逻辑是：在一个周期内，发送N个帧的时间是有效时间，总周期时间由第一个帧的发送开始到第N个帧的ACK收到为止。这里最大的陷阱是**是否将ACK的传输时延计入分母的总时间**，以及**公式中Tx的定义**。参考解析中 `Tx = 2010/1Mbps` 暗示它将数据帧和ACK帧视为一个整体单元或者认为ACK传输也占用了发送方的发送时间（这在物理上是不准确的，ACK是接收方发送的，但在计算发送方窗口的周转时间时，ACK的传输时延确实会延迟发送方收到ACK的时刻，从而延迟发送方发送下一批帧的时刻）。如果学生忽略ACK传输时延，或者错误地只计算数据帧传输时延，结果会偏差。此外，“四舍五入到最接近的整数”也是一个常见的舍入陷阱（50.25 -> 50 还是 51？题目要求最接近，50.25离50更近，但参考答案给的是51，这提示我们需要重新审视参考解析的逻辑或题目隐含的“最小值”含义——通常窗口大小取整是向上取整以保证利用率，但题目明确说“四舍五入到最接近”，这里存在题目表述与常规工程实践（向上取整）的冲突，或者参考解析的计算细节有特定假设。*注：根据常规408考题逻辑，若要求“最小窗口大小以实现至少50%利用率”，应向上取整；若仅数学计算“最接近整数”，50.25应为50。但既然参考答案是A(51)，说明题目可能隐含“向上取整”或参考解析中的计算值实际大于50.5。让我们复核计算：`1 + 2*100/2.01 = 1 + 200/2.01 = 1 + 99.502 = 100.502`。`N = 0.5 * 100.502 = 50.251`。数学上最接近是50。若选51，可能是题目意指“最小整数窗口使得利用率>=50%”，此时需向上取整。这是一个典型的**条件路由陷阱**：对“最小值”和“四舍五入”指令的冲突解读。*
- **K5 = 1**: 评分理由。仅涉及数据链路层内部的流量控制机制，不涉及网络层、传输层或其他子系统的状态传递。

- **雷达形状**: K4陷阱型（高K4，中高K2，中等K1）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于将给定的物理参数（帧长、带宽、延迟）代入特定的性能公式（链路利用率公式）进行数值计算，并处理边界条件（取整）。

## 选项级分析
- **选项A (51)**: [正确] — 对应参考解析的结果。尽管数学上50.25四舍五入为50，但在计算机网络窗口大小的语境下，通常为了保证“达到”某个利用率阈值，需要向上取整（Ceiling）。或者参考解析的计算模型中，分母的总时间计算方式导致N略大于50.5。此选项考察学生对“最小窗口大小”工程意义的理解（即必须满足条件，故向上取整）或对特定公式计算的精确执行。
- **选项B (50)**: [干扰] — 针对数学四舍五入规则的直观反应。学生计算出50.25后，直接四舍五入得到50。如果题目严格遵循“四舍五入到最接近的整数”，此选项在数学上更合理。但作为“最小窗口大小以实现50%利用率”，50帧时的利用率为 `50 / 100.502 ≈ 49.75% < 50%`，不满足条件。因此，选B的学生忽略了“实现50%利用率”这一约束条件的方向性（>=50%）。
- **选项C (25)**: [干扰] — 针对公式记忆错误或计算错误的学生。可能错误地使用了 `N = (1 + Tp/Tx) / 2` 或者忽略了因子2（单向延迟vs往返延迟），或者误以为利用率公式是 `N / (1 + Tp/Tx)` 且未乘以2。也可能是将100ms误认为往返延迟。
- **选项D (52)**: [干扰] — 针对过度保守或计算误差的学生。可能在计算 `200/2.01` 时估算过大，或者在取整时为了保险起见多取了1。

- **干扰策略**: 计算陷阱（四舍五入 vs 向上取整）、概念混淆（单向延迟 vs 往返延迟）、公式误用。

## 核心陷阱
- **核心陷阱**: **“最小窗口大小”与“四舍五入”指令的语义冲突及利用率阈值的边界判断**。
  1. **阈值方向性**：题目要求“实现50%的链路利用率”，意味着利用率 $\eta \ge 50\%$。计算出的理论最小N为50.25。若取N=50，$\eta \approx 49.75\% < 50\%$，不满足条件。因此，工程上的“最小窗口大小”应为51（向上取整）。
  2. **指令歧义**：题目括号内注明“四舍五入到最接近的整数”，这在数学上指向50。但结合“最小值”和“实现...利用率”的语境，出题人意图显然是考察满足条件的最小整数（即向上取整）。学生若机械执行“四舍五入”会选B，若理解“满足条件的最小整数”会选A。这是典型的**条件路由陷阱**。
  3. **ACK时延的处理**：参考解析将ACK传输时延计入总周期（通过Tx=2010bit体现），这是计算发送方周转时间的关键。若忽略ACK传输时延，Tx=2ms，则 `N = 0.5 * (1 + 200/2) = 50.5`，四舍五入为51，向上取整也为51。两种模型在此处结果趋同，但理解模型不同。

## 考察能力
本题核心考察学生在数据链路层流量控制场景下，准确构建链路利用率数学模型、处理非整数计算结果并结合工程约束（满足阈值的最小整数）进行决策的能力。
