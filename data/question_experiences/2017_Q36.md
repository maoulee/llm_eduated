# 2017 Q36 — IP特殊地址的源/目的属性辨析

## 基本信息
- **年份**: 2017  **题位**: Q36  **题型**: 选择题
- **知识点**: 网络号和主机号, 计算机网络>网络号和主机号
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
下列 IP 地址中，只能作为 IP 分组的源 IP 地址但不能作为目的 IP 地址的是（ ）。
网络号和主机号

A. 0.0.0.0
B. 127.0.0.1
C. 200.10.10.3
D. 255.255.255.255

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。本题高度依赖对 IPv4 特殊地址（0.0.0.0, 127.x.x.x, 255.255.255.255, 私有地址等）定义的精确记忆。不仅要知道这些地址是什么，还要知道它们在 TCP/IP 协议栈中作为“源”和“目的”时的具体语义差异。需辨析多个易混概念（如全0地址与全1地址的区别，回环地址的双向性），故为较高难度。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、子网掩码换算或二进制转换，完全属于概念定性判断。
- **K3 = 1**: 评分理由。解题过程为直接的“定义匹配”，无需多步逻辑推演或状态机分析。看到地址 -> 回忆定义 -> 判断源/目的属性 -> 得出结论，一步到位。
- **K4 = 3**: 评分理由。存在隐含的协议细节陷阱。许多学生知道 0.0.0.0 是特殊地址，但容易忽略它在 DHCP 初始化阶段或某些特定路由协议中作为“源地址”的合法场景，或者误以为它绝对不能出现在任何数据包中。同时，需避开“255.255.255.255 只能做目的”的直觉陷阱（虽然它主要做目的，但题目问的是“只能做源”）。这里的陷阱在于对“只能”二字的严格逻辑约束以及对 0.0.0.0 作为源地址这一非日常场景的认知盲区。
- **K5 = 1**: 评分理由。仅涉及网络层 IP 地址的基本语义，无需跨越传输层、应用层或数据链路层进行状态联动分析。
- **雷达形状**: K1 主导型（高记忆/辨析需求，低计算/推演需求）

## 考察模式
- **模式**: 概念型
- **理由**: 题目核心在于考察考生对 IPv4 协议中特殊保留地址的定义及其在数据包封装（源/目的字段）中的具体使用规则的记忆和理解，不涉及算法推导或复杂计算。

## 选项级分析
- **选项A**: [正确] — 0.0.0.0/32。在主机尚未配置 IP 地址（如 DHCP 启动初期）或某些特定路由协议（如 OSPF 的某些报文）中，0.0.0.0 可以作为源 IP 地址，表示“本主机”或“未知源”。但它绝对不能作为目的 IP 地址，因为路由器无法路由到“无地址”的目标，且接收方无法识别该目的地址指向自己。
- **选项B**: [干扰] — 127.0.0.1。这是回环地址（Loopback）。它既可以作为源地址（本机进程间通信），也可以作为目的地址（本机接收）。因此不符合“不能作为目的”的条件。这类学生可能误以为回环地址只用于测试，忽略了其双向通信的本质。
- **选项C**: [干扰] — 200.10.10.3。这是一个标准的公网 C 类 IP 地址。它既可以作为源，也可以作为目的。这类学生可能因对 IP 分类不熟，误以为这是私有地址或特殊地址，或者完全排除法失败后乱选。
- **选项D**: [干扰] — 255.255.255.255。这是受限广播地址。它通常只能作为目的 IP 地址（用于向本地网络所有主机发送广播），而不能作为源 IP 地址（因为源地址需要标识发送者，广播地址无法标识具体发送者）。这与题目要求的“只能作为源”正好相反。这类学生容易混淆 0.0.0.0 和 255.255.255.255 的角色，或者记反了它们的源/目的限制。

- **干扰策略**: 概念混淆与反向陷阱。利用 0.0.0.0 和 255.255.255.255 在“全0”和“全1”上的对称性，以及它们在源/目的属性上的互斥性（一个主要做源，一个主要做目的）来制造混淆。

## 核心陷阱
- **核心陷阱**: 对 0.0.0.0 作为“源地址”合法性的认知缺失。大多数初学者认为 0.0.0.0 是“无效地址”或“默认路由”，从而认为它既不能做源也不能做目的，或者误以为它像 255.255.255.255 一样只能做目的。实际上，在 TCP/IP 协议栈的特定阶段（如 DHCP Discover 报文），0.0.0.0 是合法的源地址。

## 考察能力
精准记忆并辨析 IPv4 特殊地址在数据包源/目的字段中的语义约束及协议例外情况。
