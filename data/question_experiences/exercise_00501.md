# 练习题 Q1 — 组相联Cache地址映射与关联度计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 计算机组成原理/存储系统
- **难度**: 待评估

## 题干原文
考虑一个大小为 2KB（1KB = 2¹⁰ 字节）的组相联高速缓存，其缓存块大小为 64 字节。假设该缓存是字节可寻址的，并使用 32 位地址访问缓存。如果标记字段的宽度为 22 位，则该缓存的关联度（每组中有的 cache 块数量）是（ ）。
- 选项:
  A: 2
  B: 4
  C: 1
  D: 8
- 正确答案: A
- 解析（参考）: 计算缓存行数
行数 = 缓存大小 / 块大小 = 2¹¹ B / 2⁶ B = 2⁵
确定组号位数
地址总位数 = 32 位
标记位 = 22 位
偏移量位 = log₂(块大小) = 6 位
组号位 = 32 - 22 - 6 = 4 位
计算组数
组数 = 2^{组号位} = 2⁴ = 16
求解关联度
关联度 = 行数 / 组数 = 2⁵ / 2⁴ = 2
- 知识标签: ['计算机组成原理/存储系统']
- 知识域: CO-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握Cache地址划分的三个核心概念：标记（Tag）、组索引（Index/Set）、块内偏移（Offset）。这不是简单的定义记忆，而是需要理解这三个部分在32位地址中的构成关系，属于标准的基础认知需求。
- **K2 = 2**: 评分理由。计算过程主要涉及2的幂次运算（如 $2^{11}/2^6$, $32-22-6$），均为整数且为2的幂，计算量极小，不易出错，属于较低的单步代入需求。
- **K3 = 3**: 评分理由。解题需要多步串行推演：第一步由Cache总大小和块大小求出总行数；第二步由地址总长、标记位和块大小求出组索引位数；第三步由组索引位数求出组数；第四步由总行数和组数求出关联度。共4步逻辑推导，属于标准的机制推演需求。
- **K4 = 2**: 评分理由。题目条件明确，没有明显的隐含前提或反直觉陷阱。唯一的“注意点”是确认“字节可寻址”意味着偏移量基于字节计算，这是常规注意点，不属于深层陷阱。
- **K5 = 1**: 评分理由。本题完全局限于存储系统内部的Cache映射机制，不涉及CPU流水线、中断、内存管理或其他子系统的状态传递，属于单系统内部计算。
- **雷达形状**: K3推演主导型（K1-K3均衡，K4-K5低）

## 考察模式
- **模式**: 计算型
- **理由**: 虽然涉及概念理解，但最终答案依赖于通过已知参数（Cache大小、块大小、地址位数、标记位数）进行一系列数学推导和计算得出。核心在于建立“地址结构”与“Cache物理结构”之间的数量关系。

## 选项级分析
- **选项A**: [正确] — 正确执行了所有步骤：总行数32，组索引4位（16组），关联度=32/16=2。
- **选项B**: [干扰] — 针对**计算错误**或**概念混淆**。学生可能错误地计算组索引位数，例如误以为标记位22位加上偏移6位后剩余4位是其他含义，或者在计算总行数时出错（如误算为64行，64/16=4）。另一种可能是混淆了“组数”和“关联度”，如果算出组数是16，可能误选接近的数字，但更常见的是在减法步骤出错，如 $32-22=10$，误以为索引是10位（不可能，因为总地址才32，且偏移6，标记22，剩4），或者错误地认为关联度等于组索引位数（4）。
- **选项C**: [干扰] — 针对**概念混淆**。学生可能误以为这是直接映射Cache（Direct Mapped），直接映射的关联度为1。或者学生计算出组索引为4位，误以为关联度就是1（因为直接映射每组1块），忽略了题目明确说是“组相联”。
- **选项D**: [干扰] — 针对**计算错误**。学生可能在计算总行数时出错，例如将2KB误认为4KB（64行），则 $64/16=4$（选B）；或者将块大小64B误认为32B（偏移5位），则索引位=$32-22-5=5$位，组数32，总行数64，关联度2（仍为A）。若学生误算偏移量为5位（32B块），且误算总行数为64（4KB Cache），则 $64/32=2$。更可能的错误路径是：误以为标记位22位对应的是主存块号，而忽略了地址结构。或者简单地将 $2^{11}/2^6 = 32$ 行，误以为组数是8（$2^3$），则 $32/8=4$（选B）。若选D，可能是误算组索引为3位（8组），$32/8=4$（选B）... 等等，选D（8）的情况可能是：误算总行数为64（4KB），组索引4位（16组），$64/16=4$（选B）。若选D，可能是误算组索引为2位（4组），$32/4=8$。这通常源于对地址位数的错误分配，例如误以为标记位是24位，则索引=$32-24-6=2$位，组数4，关联度$32/4=8$。
- **干扰策略**: 概念混淆（直接映射vs组相联）与计算陷阱（地址位数分配错误）

## 核心陷阱
- **核心陷阱**: **地址字段的正确划分**。学生容易忘记“块内偏移”占用的位数，直接用 $32 - 22 = 10$ 位作为组索引，导致组数计算错误（$2^{10}=1024$组，关联度 $32/1024 < 1$，逻辑矛盾，但学生可能强行计算或选错）。或者混淆“组索引位数”与“组数”的关系，以及“总行数”与“Cache大小”的关系。

## 考察能力
本题核心考察考生对**组相联Cache地址映射结构**的理解，以及通过**地址位数分解**推导Cache物理参数（行数、组数、关联度）的综合计算能力。
