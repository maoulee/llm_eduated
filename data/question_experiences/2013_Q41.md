# 2013 Q41 — 顺序表主元素查找（摩尔投票法）

## 基本信息
- **年份**: 2013  **题位**: Q41  **题型**: 综合题
- **知识点**: 顺序表, 数据结构>顺序表
- **题位域**: 待标注  **科目**: 数据结构

## 题干原文
已知一个整数序列 $A = (a_0, a_1, \dots, a_{n-1})$，其中 $0 \le a_i < n (0 \le i < n)$。
若存在 $a_{p_1} = a_{p_2} = \dots = a_{p_m} = x$ 且 $m > n/2 (0 \le p_k < n, 1 \le k \le m)$，则称 $x$ 为 $A$ 的主元素。
例如 $A = (0, 5, 5, 3, 5, 7, 5, 5)$，则 $5$ 为主元素；又如 $A = (0, 5, 5, 3, 5, 1, 5, 7)$，则 $A$ 中没有主元素。
假设 $A$ 中的 $n$ 个元素保存在一个一维数组中，请设计一个尽可能高效的算法，找出 $A$ 的主元素。若存在主元素，则输出该元素；否则输出 $-1$。要求：
(1) 给出算法的基本设计思想。
(2) 根据设计思想，采用 C、C++ 或 Java 语言描述算法，关键之处给出注释。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“顺序表”的基本存储结构以及“主元素”（Majority Element）的定义。虽然不需要记忆复杂公式，但必须理解 $m > n/2$ 这一核心约束条件，属于标准的基础概念调用。不是2分因为仅靠直觉无法确定最优解法，需调用特定算法知识。
- **K2 = 2**: 评分理由。算法核心逻辑涉及简单的计数器加减和变量赋值，没有复杂的数学计算或多级换算。最复杂的单步操作仅为 `count++` 或 `count--`，属于较低的计算需求。
- **K3 = 3**: 评分理由。解题过程分为两个明确的串行阶段：第一阶段通过摩尔投票法（Moore Voting Algorithm）筛选出候选主元素；第二阶段遍历数组验证候选元素是否真的满足 $m > n/2$。从输入到输出需经过“筛选-验证”两步逻辑推演，属于标准的多步推演。
- **K4 = 4**: 评分理由。存在显著的隐含前提和陷阱。许多考生容易只完成第一阶段（选出候选者）而忽略第二阶段（验证）。因为摩尔投票法选出的候选者不一定是主元素（例如数组为 `[1, 2, 3]`，候选者可能是3，但3不是主元素）。识别出“必须验证”这一隐含条件是解题的关键，属于较深的隐含前提。
- **K5 = 1**: 评分理由。本题仅在单一的数据结构（顺序表/数组）内部进行操作，不涉及不同子系统间的数据传递或状态耦合，属于单系统问题。
- **雷达形状**: 呈现“中间高、两头低”的橄榄型或菱形特征。K1和K5较低，K2较低，K3中等，K4较高。表明本题难点不在于基础记忆或复杂计算，而在于对算法逻辑完整性的把握和对陷阱的规避。

## 考察模式
- **模式**: 算法设计型
- **理由**: 题目明确要求“设计一个尽可能高效的算法”，并要求给出设计思想和代码实现。这属于典型的数据结构算法设计题，考察考生对时间复杂度和空间复杂度的优化能力。

## 解题思路分析
- **核心思路**: 采用**摩尔投票法（Moore Voting Algorithm）**。利用主元素出现次数超过一半的特性，通过“同加异减”的策略在 $O(n)$ 时间内筛选出候选主元素，然后再遍历一次数组统计该候选元素的实际出现次数，以确认其是否真正为主元素。总时间复杂度为 $O(n)$，空间复杂度为 $O(1)$。
- **关键步骤**:
    1.  **初始化**: 设置候选元素 `candidate` 和计数器 `count`。
    2.  **筛选阶段**: 遍历数组。
        - 若 `count == 0`，则将当前元素设为 `candidate`，`count` 置为 1。
        - 若当前元素等于 `candidate`，则 `count++`。
        - 若当前元素不等于 `candidate`，则 `count--`。
    3.  **验证阶段**: 再次遍历数组，统计 `candidate` 出现的次数 `num`。
    4.  **判断**: 若 `num > n/2`，返回 `candidate`；否则返回 -1。
- **易错点**:
    1.  **遗漏验证步骤**: 直接返回筛选出的 `candidate`，导致在不存在主元素时返回错误结果。
    2.  **边界条件处理**: 未考虑数组为空或长度为0的情况（虽然题目隐含 $n$ 个元素，但健壮性代码需考虑）。
    3.  **效率低下**: 使用双重循环暴力统计每个元素的出现次数，导致时间复杂度退化为 $O(n^2)$，不符合“尽可能高效”的要求。

## 核心陷阱
- **核心陷阱**: **摩尔投票法选出的候选者未必是主元素**。
    题目中给出的例子 $A = (0, 5, 5, 3, 5, 1, 5, 7)$ 没有主元素。如果只执行筛选阶段，算法可能会输出 5（取决于遍历顺序和抵消情况），但 5 的出现次数并未超过 $n/2$（这里 $n=8$，5出现了4次，$4 \ngtr 4$）。因此，**必须**进行第二遍遍历来验证候选者的真实频次。这是本题最大的失分点。

## 考察能力
本题核心考察考生在受限空间复杂度（$O(1)$）下，利用数学性质优化时间复杂度（$O(n)$）的算法设计能力，以及对算法正确性边界条件的严谨验证意识。
