# 练习题 Q未知 — 网络层传输效率与有效载荷速率计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/网络层
- **难度**: 待评估

## 题干原文
继续上一题，问应用数据传输到主机 HC 的速率是多少？忽略错误、确认和其他开销。（ ）
A: 325.5 Kbps
B: 354.5 Kbps
C: 409.6 Kbps
D: 512.0 Kbps

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要调用“有效载荷（Payload）”、“协议开销（Overhead）”以及“传输效率”的核心定义。不是4分因为不需要辨析多个易混概念（如吞吐量与带宽的区别在此题语境下较明确），只需识别哪些字节属于应用层数据。
- **K2 = 3**: 评分理由。涉及两级换算：首先计算有效载荷占比（180/260），然后乘以链路速率（512 Kbps）。虽然不是复杂的幂次运算，但涉及小数除法与乘法，且结果需保留一位小数，存在轻微的计算误差风险，属于标准难度的单步代入。
- **K3 = 2**: 评分理由。推演步骤较少：识别总包长 -> 识别有效数据长 -> 计算比例 -> 计算速率。仅需2-3步串行逻辑，无需记忆中间状态或复杂的状态机推演。
- **K4 = 4**: 评分理由。存在显著的隐含前提和陷阱。首先，题目注明“继续上一题”，意味着关键数据（如链路速率512 Kbps、包结构260字节等）依赖于上下文，若脱离上下文无法解题。其次，最大的陷阱在于“应用数据”的定义，学生极易混淆“IP数据报长度”、“TCP段长度”与“应用层数据长度”。必须意识到260字节中包含了IP和TCP首部，只有180字节是真正的应用数据。这是一个典型的“隐含前提深”的陷阱。
- **K5 = 3**: 评分理由。需要跨越网络层（IP首部）和传输层（TCP首部）到应用层的数据封装关系。虽然主要是单向的数据剥离（从总包中剥离出应用数据），但需要理解不同层级的封装结构，属于单向传数据/状态识别。

- **雷达形状**: K4陷阱型（K4显著高于其他维度，主要难点在于识别隐含条件和数据定义）

## 考察模式
- **模式**: 综合型（偏向计算与概念辨析）
- **理由**: 本题不仅要求简单的数值计算，更核心的是考察对网络协议栈封装结构的理解（即区分不同层级的数据长度）。它结合了概念辨析（什么是应用数据）和定量计算（效率折算），因此属于综合型。

## 选项级分析
- **选项A**: [干扰] — 针对错误认知：可能误用了错误的包长或数据长比例。例如，如果学生错误地认为首部开销更大，或者在计算 180/260 时出现严重计算错误，可能会得到此数值。也可能混淆了比特与字节的换算关系。
- **选项B**: [正确] — 正确计算：$180 / 260 \times 512 \approx 0.6923 \times 512 \approx 354.45$ Kbps，四舍五入为 354.5 Kbps。
- **选项C**: [干扰] — 针对错误认知：可能误将 TCP 首部或 IP 首部的大小计算错误，或者使用了错误的有效载荷长度。例如，若误以为有效载荷是 200 多字节，或者混淆了某些固定首部长度（如 IP 20 + TCP 20 = 40，若误算为其他值）。另一种可能是计算了 $200/260 \times 512$ 之类的错误比例。
- **选项D**: [干扰] — 针对错误认知：直接选择了链路速率（512 Kbps）。这类学生忽略了协议开销，认为链路速率等于应用层数据传输速率，未理解“有效载荷”与“总包长”的区别。这是最常见的概念性错误。

- **干扰策略**: 概念混淆（选项D，忽略开销）与 计算陷阱（选项A/C，比例计算错误）

## 核心陷阱
- **核心陷阱**: **“应用数据”的定义边界**。学生必须明确区分“网络层数据报长度”、“传输层段长度”和“应用层报文长度”。题目给出的260字节是包含IP和TCP首部的总长度，而只有180字节是应用数据。若未剥离协议开销，直接以512 Kbps作答（选D）或错误计算比例，即为掉入陷阱。此外，“继续上一题”的依赖性也是一个潜在陷阱，要求考生具备上下文关联能力。

## 考察能力
一句话概括本题核心考察的能力：
**在多层协议封装环境下，准确识别有效载荷占比并计算实际应用层数据传输速率的能力。**
