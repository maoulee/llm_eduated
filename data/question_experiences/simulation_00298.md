## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆并准确区分三种经典调度算法（FCFS, SJF, HRRN）的定义及适用场景，特别是HRRN的响应比公式 $R = (W+S)/S$。不是4分因为不涉及复杂概念辨析，属于标准核心定义记忆。
- **K2 = 3**: 评分理由。涉及多次加减乘除运算，特别是带权周转时间的除法运算（如 7/6, 11/4 等），非整数结果容易在手动计算时出错，且需保留小数位，计算量适中但容错率低。
- **K3 = 4**: 评分理由。解题过程是多步串行推演。对于每种算法，都需要模拟时间轴，逐个确定进程执行顺序。特别是HRRN算法，需要在每个调度点动态计算剩余就绪进程的响应比，步骤超过5步且需维护中间状态（当前时间、已执行进程、剩余就绪队列）。
- **K4 = 4**: 评分理由。存在显著的隐含前提和陷阱。1. **非抢占式假设**：题目未明确说明是否抢占，但根据408考研惯例及SJF/HRRN通常作为非抢占式算法考察（除非注明SRTF/HRRT），需默认非抢占。2. **就绪时刻的影响**：在SJF和HRRN中，必须严格检查“当前时刻”哪些进程已经就绪，不能简单按服务时间排序，这是最大的暗坑。3. **HRRN的动态性**：响应比随等待时间增加而增加，需理解其动态变化特性。
- **K5 = 1**: 评分理由。本题仅涉及处理机调度子系统，不涉及内存管理、文件系统或I/O子系统的状态传递或耦合，属于单系统内部计算。
- **雷达形状**: 呈现“中间高、两头低”的纺锤形或菱形。K1基础认知标准，K2计算量适中，K3推演和K4条件路由难度较高，K5跨域联动极低。

## 考察模式
- **模式**: 计算推导型
- **理由**: 题目要求基于给定的输入数据（就绪时间、服务时间），通过特定的算法逻辑（FCFS/SJF/HRRN）进行逐步模拟和数值计算，最终得出统计指标（平均周转时间、平均带权周转时间）。核心在于“模拟执行过程”和“数值计算”。

## 解题思路分析
- **核心思路**: 
  1. 明确三种调度算法的调度原则。
  2. 针对每种算法，画出甘特图或列出时间轴，确定进程的执行顺序。
  3. 根据执行顺序，计算每个进程的周转时间（完成时间 - 到达时间）和带权周转时间（周转时间 / 服务时间）。
  4. 求平均值。

- **关键步骤**:
  1. **FCFS (先来先服务)**: 按就绪时刻排序。若就绪时刻相同，通常按题目给定顺序或PID排序。本题就绪时刻均不同，直接按时间顺序 P1->P2->P3->P4->P5 执行。
  2. **SJF (短作业优先)**: 
     - 时刻0: 只有P1就绪，执行P1 (0-3)。
     - 时刻3: P1结束。此时就绪队列有P2(就绪2)。P3(4), P4(6), P5(8)未就绪。只能选P2。执行P2 (3-9)。
     - 时刻9: P2结束。此时P3(4), P4(6), P5(8)均已就绪。比较服务时间：P5(2) < P3(4) < P4(5)。选P5。执行P5 (9-11)。
     - 时刻11: P5结束。剩余P3(4), P4(5)。选P3。执行P3 (11-15)。
     - 时刻15: P3结束。剩余P4。执行P4 (15-20)。
     - 顺序: P1 -> P2 -> P5 -> P3 -> P4。
  3. **HRRN (高响应比优先)**:
     - 时刻0: 只有P1，执行P1 (0-3)。
     - 时刻3: P1结束。只有P2就绪。执行P2 (3-9)。
     - 时刻9: P2结束。P3, P4, P5就绪。计算响应比 $R = (等待+服务)/服务$:
       - P3: 等待=9-4=5, 服务=4, R=(5+4)/4 = 2.25
       - P4: 等待=9-6=3, 服务=5, R=(3+5)/5 = 1.6
       - P5: 等待=9-8=1, 服务=2, R=(1+2)/2 = 1.5
       - 最大为P3。执行P3 (9-13)。
     - 时刻13: P3结束。剩余P4, P5。
       - P4: 等待=13-6=7, 服务=5, R=(7+5)/5 = 2.4
       - P5: 等待=13-8=5, 服务=2, R=(5+2)/2 = 3.5
       - 最大为P5。执行P5 (13-15)。
     - 时刻15: P5结束。剩余P4。执行P4 (15-20)。
     - 顺序: P1 -> P2 -> P3 -> P5 -> P4。
     *(注：此处需仔细核对参考答案的逻辑，参考答案中HRRN的顺序似乎有误或我需重新审视。让我们重新检查参考答案的HRRN部分。参考答案解析截断了，但给出的结果是平均周转8.0。让我们手动验证一下我的推导 vs 参考答案可能的逻辑。)*
     *修正检查*: 
     参考答案给出的HRRN平均周转是8.0。
     我的推导顺序: P1(3), P2(9), P3(13), P5(15), P4(20).
     周转时间:
     P1: 3-0=3
     P2: 9-2=7
     P3: 13-4=9
     P5: 15-8=7
     P4: 20-6=14
     平均: (3+7+9+7+14)/5 = 40/5 = 8.0。
     带权:
     P1: 1.0
     P2: 7/6 ≈ 1.17
     P3: 9/4 = 2.25
     P5: 7/2 = 3.5
     P4: 14/5 = 2.8
     平均: (1+1.17+2.25+3.5+2.8)/5 = 10.72/5 = 2.144 ≈ 2.14。
     结果与参考答案一致。说明我的推导顺序 P1->P2->P3->P5->P4 是正确的。
     
- **易错点**:
  1. **SJF/HRRN的就绪判断**: 在时刻T，只能从“到达时间 <= T”的进程中选择。很多学生忽略到达时间，直接对所有进程排序。
  2. **HRRN的计算**: 忘记响应比公式，或计算等待时间时出错（等待时间 = 当前时刻 - 到达时间）。
  3. **小数精度**: 带权周转时间通常保留两位小数，中间计算过程建议保留更多位数以减少误差。
  4. **FCFS的简单性**: 虽然简单，但容易在计算周转时间时混淆“完成时间”和“服务时间”。

## 核心陷阱
- **核心陷阱**: **动态就绪队列的筛选**。在SJF和HRRN算法中，考生极易犯的错误是忽略进程的“就绪时刻”，试图在进程尚未到达时就对其进行调度或比较。例如在时刻3，P3、P4、P5尚未到达，此时只能调度P2，而不能因为P5服务时间短就跳过P2去调度P5（除非是抢占式，但本题默认为非抢占）。此外，HRRN算法中，响应比是动态变化的，必须在每个调度决策点重新计算，而非一次性计算。

## 考察能力
本题核心考察考生对操作系统中三种经典非抢占式进程调度算法执行流程的模拟能力，以及在动态环境下准确计算性能评价指标（周转时间、带权周转时间）的严谨性与计算能力。
