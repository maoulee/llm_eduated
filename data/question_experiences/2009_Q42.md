# 2009 Q42 — 链表倒数第k个结点查找

## 基本信息
- **年份**: 2009  **题位**: Q42  **题型**: 综合题
- **知识点**: DS-2 > 2.3 链表的链式表示 > 链表共同概念, DS-2 > 2.3 链表的链式表示 > 链表基本操作
- **题位域**: 待标注  **科目**: 数据结构

## 题干原文
已知一个带有表头结点的单链表，结点结构为：
| data | link |
假设该链表只给出了头指针 list。在不改变链表的前提下，请设计一个尽可能高效的算法，查找链表中倒数第 k 个位置上的结点（k 为正整数）。若查找成功，算法输出该结点的 data 域的值，并返回 1；否则，只返回 0。要求：
(1) 描述算法的基本设计思想；
(2) 描述算法的详细实现步骤；
(3) 根据设计思想和实现步骤，采用程序设计语言描述算法（使用 C、C++ 或 Java 语言实现），关键之处请给出简要注释。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握单链表的基本结构（头结点、指针域、数据域）以及“倒数第k个”的定义。不是4分因为不需要辨析复杂的链表变体（如循环链表、双向链表），只需标准单链表概念。
- **K2 = 2**: 评分理由。本题不涉及数值计算，仅涉及指针的移动和计数器的比较。单步操作极其简单（p=p->link），几乎不可能出错，属于低难度代入。
- **K3 = 3**: 评分理由。解题过程需要多步串行推演：初始化双指针 -> 快指针先走k步 -> 检查快指针是否越界 -> 双指针同步移动 -> 检查结束条件。整个过程逻辑链条清晰，但步骤在3-5步之间，属于标准推演难度。
- **K4 = 4**: 评分理由。存在明显的隐含前提和边界陷阱。首先，题目要求“尽可能高效”，隐含了O(n)时间复杂度和O(1)空间复杂度的要求，排除了先遍历求长度再遍历找位置的O(2n)思路（虽然也是O(n)，但常数因子大，且通常双指针法被视为更优解）。其次，必须处理k大于链表长度的情况（即快指针走到NULL时慢指针还未开始或刚开始的异常处理），以及k=0或负数的非法输入（虽题干说k为正整数，但健壮性代码需考虑）。这些边界条件的识别是本题的主要难点。
- **K5 = 1**: 评分理由。本题完全局限于数据结构中的单链表模块内部，不涉及操作系统、计算机网络或计算机组成原理等其他科目的知识联动，属于单系统问题。
- **雷达形状**: 呈现“中间高、两头低”的橄榄型或菱形。K1和K2较低，K5最低，K3和K4较高，表明本题重在逻辑实现和边界处理，而非基础记忆或跨学科知识。

## 考察模式
- **模式**: 算法设计型
- **理由**: 题目明确要求设计算法，包括描述思想、步骤和代码实现。核心在于考察考生对链表遍历技巧（双指针法/快慢指针法）的掌握程度，以及如何通过空间换时间（虽然这里空间也是O(1)，但通过增加指针变量优化了遍历次数）来提升效率。

## 解题思路分析
- **核心思路**: 利用“双指针法”（或称快慢指针法）。设置两个指针 `p` 和 `q`，初始都指向头结点的下一个结点（第一个有效结点）。让 `p` 指针先向前移动 `k` 步。此时，`p` 和 `q` 之间相隔 `k-1` 个结点（或者说 `p` 领先 `k` 个位置）。然后 `p` 和 `q` 同时向后移动，直到 `p` 指向链表末尾（NULL）。此时，`q` 所指的结点即为倒数第 `k` 个结点。
- **关键步骤**:
    1.  **初始化**: `p = head->link`, `q = head->link` (假设head是头指针，指向头结点)。
    2.  **快指针先行**: 循环 `k` 次，每次 `p = p->link`。在循环中需检查 `p` 是否为 NULL，若为 NULL 说明链表长度小于 `k`，直接返回 0。
    3.  **同步移动**: 当 `p` 不为 NULL 时，`p` 和 `q` 同时向后移动 (`p = p->link`, `q = q->link`)。
    4.  **结果判定**: 当 `p` 为 NULL 时，`q` 即为所求结点。输出 `q->data` 并返回 1。
    5.  **异常处理**: 若在步骤2中 `p` 提前变为 NULL，说明 `k` 值过大，返回 0。
- **易错点**:
    1.  **头结点处理**: 题目明确有“表头结点”，初始指针应指向 `head->link` 还是 `head` 需要仔细审题。通常双指针法若从第一个有效结点开始，`p` 走 `k` 步后，若 `p` 为 NULL，则倒数第 `k` 个是第一个结点；若 `p` 不为 NULL，则继续同步。另一种常见写法是 `p` 和 `q` 都从头结点开始，`p` 先走 `k` 步，这样逻辑更统一，但需注意 `k` 的定义（倒数第1个是最后一个结点）。
    2.  **边界条件**: 当 `k` 等于链表长度时，`p` 走完 `k` 步后应为 NULL，此时 `q` 应指向第一个结点。若代码逻辑错误，可能导致 `q` 指向头结点或越界。
    3.  **空指针解引用**: 在移动指针前未检查 `p` 是否为 NULL，导致程序崩溃。
    4.  **效率误解**: 有些考生会先遍历一遍求长度 `n`，再遍历到 `n-k+1` 位置。虽然时间复杂度也是 O(n)，但遍历了两遍，不如双指针法一遍遍历高效，不符合“尽可能高效”的要求。

## 核心陷阱
- **核心陷阱**: **边界条件的完整性与“高效”的定义**。
    1.  **k > 链表长度**: 很多考生只考虑了正常情况，忽略了当 `k` 大于链表实际长度时，快指针 `p` 会提前变为 NULL，此时应返回 0 而不是继续执行同步移动（否则 `q` 会越界或指向错误位置）。
    2.  **头结点的干扰**: 题目强调“带有表头结点”，如果考生将 `p` 和 `q` 初始化为 `head`（头结点），那么 `p` 需要走 `k` 步还是 `k+1` 步？如果初始化为 `head->link`，逻辑又不同。必须统一标准。通常推荐 `p` 和 `q` 都从头结点开始，`p` 先走 `k` 步，这样当 `p` 到达 NULL 时，`q` 正好在倒数第 `k` 个结点（假设倒数第1个是最后一个结点）。或者 `p` 和 `q` 从第一个有效结点开始，`p` 先走 `k-1` 步。关键在于逻辑自洽。
    3.  **效率陷阱**: 使用两次遍历（先求长，再定位）虽然正确，但在考研评分标准中，通常认为双指针一次遍历是“更优”或“标准”的高效解法。

## 考察能力
本题核心考察考生对单链表遍历技巧的灵活运用能力，特别是通过双指针法优化时间复杂度的算法设计能力，以及对边界条件（如链表长度不足、空指针）的严谨处理能力。
