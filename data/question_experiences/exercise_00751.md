# 练习题 Q1 — 数组反转算法逻辑分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/数组
- **难度**: 待评估

## 题干原文
考虑以下程序。预期输出是什么？
```c
void fun(int arr[], int start, int end) {
    while (start < end) {
        int temp = arr[start];
        arr[start] = arr[end];
        arr[end] = temp;
        start++;
        end--;
    }
}
```
- 选项:
  A: 成对交换元素
  B: 排序元素
  C: 反转数组
  D: 无
- 正确答案: C
- 解析（参考）: 该函数通过交换首尾元素逐步向中间移动，最终实现数组反转
- 知识标签: ['数据结构/数组']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 2**: 评分理由。需要识别基本的数组操作（交换）和循环结构，属于基础认知。不是1分因为需要理解指针/索引移动的含义，不仅仅是记忆定义。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行算术运算，单步代入需求极低。
- **K3 = 3**: 评分理由。需要在脑海中模拟 `start` 和 `end` 指针的移动过程以及元素交换的状态变化。虽然逻辑简单，但需要多步串行推演（至少3-4步才能看出规律），符合标准推演难度。
- **K4 = 2**: 评分理由。存在常规注意点，即循环终止条件 `start < end` 确保了中间元素不被错误交换或重复交换。没有深层隐含前提或反直觉陷阱，属于常规注意点。
- **K5 = 1**: 评分理由。仅在数组这一单一数据系统内操作，不涉及不同子系统间的数据传递或状态耦合。
- **雷达形状**: K3主导型（推理推演为主，基础认知为辅，无计算压力）

## 考察模式
- **模式**: 推理型
- **理由**: 题目不要求记忆特定公式或进行数值计算，而是要求考生通过阅读代码逻辑，推演程序执行后的最终状态（数组内容的变化），属于典型的代码逻辑推理。

## 选项级分析
- **选项A**: [干扰] — 针对“只看到交换动作，未看到整体效果”的错误认知。这类学生可能注意到代码中有 `swap` 操作，但忽略了 `start++` 和 `end--` 带来的全局性影响，认为只是局部交换。
- **选项B**: [干扰] — 针对“混淆反转与排序”的概念混淆。这类学生可能知道数组操作常涉及排序，或者误以为交换相邻或特定元素能导致有序，忽略了该算法不具备比较逻辑，无法实现排序。
- **选项C**: [正确] — 准确描述了算法的整体行为：首尾交换并向中间收敛，最终结果是数组逆序。
- **选项D**: [干扰] — 针对“完全无法理解代码”或“认为代码有语法错误/无输出”的极端情况。由于函数是 `void` 且无打印语句，部分学生可能误以为“无输出”即选D，忽略了题目问的是“预期输出（效果/行为）”而非控制台打印。
- **干扰策略**: 概念混淆（反转vs排序）与 局部视角陷阱（仅关注交换动作）

## 核心陷阱
- **核心陷阱**: 混淆“局部交换动作”与“全局算法效果”。考生容易只看到 `swap` 而忽略指针移动带来的累积效应，或者误将“反转”与“排序”混淆。此外，需注意题目问的是程序的功能/效果，而非是否有打印输出。

## 考察能力
一句话概括本题核心考察的能力：
具备阅读基础C语言代码并推演数组指针移动与元素交换逻辑的能力，能够准确识别经典数组反转算法。
