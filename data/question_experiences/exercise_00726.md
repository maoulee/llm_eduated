# 练习题 Q1 — 带宽延迟积与滑动窗口优化

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/数据链路层
- **难度**: 待评估

## 题干原文
A 站使用 32 字节的数据包通过滑动窗口协议向 B 站发送消息。A 与 B 之间的往返延迟为 80ms，路径上的瓶颈带宽为 128kbps。A 应使用的最佳窗口大小是多少？（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆“带宽延迟积（BDP）”的概念及其与滑动窗口大小的关系。如果不了解 BDP 是衡量链路利用率的指标，或者不知道窗口大小应至少等于 BDP 才能充分利用带宽，则无法解题。这属于标准的核心定义记忆。
- **K2 = 4**: 评分理由。涉及多级单位换算。需要将 kbps 转换为 bit/s，ms 转换为 s，bit 转换为 byte，最后计算包的数量。虽然数字本身（128, 80, 32）对 2 的幂友好，但单位换算链条较长（kbps -> bit/s -> bit -> byte -> packet），容易在换算系数（1000 vs 1024，8 bit/byte）上出错，属于较高难度的单步代入。
- **K3 = 2**: 评分理由。逻辑推演步骤较少。核心逻辑是：计算管道容量（BDP） -> 除以单个数据包大小 -> 得到窗口大小。这是一个线性的、单向的计算过程，不需要复杂的状态机推演或多步串行逻辑。
- **K4 = 2**: 评分理由。存在常规注意点。主要陷阱在于“往返延迟（RTT）”与“单向延迟”的区别，以及“kbps”中的 k 是 1000 还是 1024（在计算机网络带宽计算中通常取 1000，但在存储中取 1024，此处需根据上下文判断，通常考研题中带宽 k=1000，但即便按 1024 算，128*1024*0.08/8/32 = 40.96，取整也是 41 或 40，影响不大；更关键的隐含条件是“最佳窗口大小”意味着要填满管道，即窗口大小 >= BDP/包大小）。此外，需意识到滑动窗口协议中，发送方在收到 ACK 前可以连续发送的包数即为窗口大小。
- **K5 = 1**: 评分理由。单系统考察。仅涉及数据链路层/网络层的传输机制，不涉及与其他子系统（如应用层、物理层具体编码等）的深度耦合或状态传递。

- **雷达形状**: K2 计算主导型，K1 基础支撑，K4 轻微陷阱。整体呈现以计算和单位换算为核心的特征。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的带宽、延迟和包大小，利用公式计算出理论上的最佳窗口大小。虽然涉及概念（BDP），但最终答案依赖于精确的数值计算和单位换算。

## 选项级分析
- **选项 A (20)**: [干扰] — 针对“单向延迟”错误认知。如果学生误将往返延迟（RTT=80ms）当作单向延迟（RTT/2=40ms）进行计算，BDP 减半，窗口大小也减半，得到 20。这是最常见的错误之一。
- **选项 B (40)**: [正确] — 正确计算结果。BDP = 128,000 bps * 0.08 s = 10,240 bits = 1,280 Bytes。窗口大小 = 1,280 / 32 = 40。
- **选项 C (160)**: [干扰] — 针对“单位换算错误”或“公式混淆”。可能错误地将带宽单位 kbps 直接当作 KB/s 或其他错误换算，或者误以为窗口大小需要是 BDP 的倍数而非相等。另一种可能是计算时未将 bit 转换为 byte，导致结果偏大（10240/32 = 320，接近 D，但 C 可能是其他换算错误，如 128*80/32 = 320，若再除以 2 得 160？或者误用 128kbps=16KB/s, 16*0.08=1.28KB=1280B, 1280/32=40... 这个选项可能是针对未除以 8 但做了其他错误操作的学生，或者误将 RTT 当作 320ms 等）。更可能的陷阱是：如果学生忘记将 bit 转为 byte，直接 10240/32 = 320 (选项D)。如果学生误以为 128kbps = 128KB/s，则 128*1024*0.08/32 = 327.68，接近 320。选项 C 可能是针对某些特定的错误换算路径，例如误将 80ms 当作 0.8s 等。
- **选项 D (320)**: [干扰] — 针对“未进行 bit 到 byte 转换”的错误认知。计算 BDP 得到 10,240 bits，如果直接除以包大小 32（误以为包大小也是 bit 或者忘记转换单位），得到 320。这是非常典型的单位陷阱。

- **干扰策略**: 计算陷阱（单位换算错误、单向/往返延迟混淆）。

## 核心陷阱
- **核心陷阱**: **单位换算与延迟定义的双重陷阱**。
    1.  **单位换算**: 必须将带宽 (kbps) 转换为 bit/s，将 BDP (bits) 转换为 Bytes，再除以包大小 (Bytes)。最容易错的是忘记除以 8 (bit to byte)，导致结果扩大 8 倍（对应选项 D 的 320 是 40 的 8 倍）。
    2.  **延迟定义**: 必须使用往返延迟 (RTT) 来计算 BDP，因为滑动窗口协议中，发送方需要等待 RTT 时间才能收到第一个 ACK 并释放窗口空间。如果误用单向延迟，结果会减半（对应选项 A 的 20）。

## 考察能力
本题核心考察考生对**带宽延迟积（BDP）**概念的理解，以及在滑动窗口协议背景下，通过**多步单位换算**计算理论最佳窗口大小以最大化链路利用率的能力。
