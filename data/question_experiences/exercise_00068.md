# 练习题 Q1 — 寄存器分配与活跃变量分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机组成原理
- **知识点**: 操作系统/CPU调度
- **难度**: 待评估

## 题干原文
以下程序使用六个临时变量 a、b、c、d、e、f：
a = 1;
b = 10;
c = 20;
d = a + b;
e = c + d;
f = c + e;
b = c + e;
e = b + f;
d = 5 + e;
return d + f;
假设所有操作都从寄存器获取操作数，执行此程序时无需溢出（spilling）所需的最少寄存器数量是多少？
- 选项:
  A: 2
  B: 3
  C: 4
  D: 6
- 正确答案: B
- 解析（参考）: 所有给定表达式最多使用 3 个变量，因此我们永远不需要超过 3 个寄存器。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“寄存器分配”、“活跃变量（Live Variable）”、“死变量（Dead Variable）”以及“溢出（Spilling）”等核心概念。虽然不涉及复杂公式，但必须理解寄存器分配的基本规则（即只有当变量不再被使用时，其占用的寄存器才能被复用）。
- **K2 = 2**: 评分理由。本题不涉及数值计算，而是逻辑状态的跟踪。没有复杂的算术运算，主要在于判断变量的生命周期。
- **K3 = 4**: 评分理由。需要多步串行推演。必须逐行跟踪代码执行，维护一个“当前活跃变量集合”，并在每一步判断是否有变量变为“死变量”从而释放寄存器。步骤较多（10行代码），且中间状态容易混淆，属于典型的3-5步以上且需记忆中间状态的推演。
- **K4 = 3**: 评分理由。存在隐含前提和陷阱。最大的陷阱在于变量名的复用（如 `b` 和 `e` 被重新赋值）。考生容易误以为重新赋值就是“新变量”，而忽略了旧值的“死亡”时机。此外，需意识到 `return d + f` 意味着 `d` 和 `f` 在最后一行之前都是活跃的。
- **K5 = 2**: 评分理由。主要涉及编译器后端/操作系统资源管理中的单一模块（寄存器分配），虽然题干归类为OS/CPU调度，但本质是编译原理中的寄存器分配问题，跨域联动需求较低，主要是单系统内的状态管理。
- **雷达形状**: K3推演主导型，伴随K4陷阱特征。

## 考察模式
- **模式**: 推理型
- **理由**: 本题不是简单的概念记忆或公式代入，而是要求考生模拟编译器或操作系统的寄存器分配过程，通过逻辑推理确定在任意时刻同时存活的变量最大数量。

## 选项级分析
- **选项A**: [干扰] — 针对低估活跃变量数量的错误认知。这类学生可能认为每次加法只需要2个操作数寄存器，忽略了结果需要暂存，或者错误地认为变量可以立即被覆盖。
- **选项B**: [正确] — 正确识别了最大活跃变量数为3。
- **选项C**: [干扰] — 针对高估活跃变量数量的错误认知。这类学生可能没有仔细检查变量的“死亡”时机，例如在 `d = a + b` 后，误以为 `a` 和 `b` 仍然活跃，或者在 `b = c + e` 时没有意识到旧的 `b` 已经死亡，导致认为需要更多寄存器来保存所有历史值。
- **选项D**: [干扰] — 针对完全不懂寄存器复用机制的错误认知。这类学生可能简单地数出程序中出现了6个不同的变量名（a,b,c,d,e,f），从而认为需要6个寄存器，完全忽略了变量生命周期的重叠情况。
- **干扰策略**: 概念混淆（变量名 vs 活跃变量）、计算陷阱（简单计数 vs 最大并发数）。

## 核心陷阱
- **核心陷阱**: **变量复用的生命周期判断**。
  具体体现在：
  1. `d = a + b` 之后，`a` 和 `b` 是否还活跃？（`a` 不再使用，`b` 在后续 `b = c + e` 之前不再使用，但需注意 `b` 在 `d=a+b` 后确实不再作为右值出现，直到被重新赋值。实际上，在 `d=a+b` 后，`a` 立即死亡，`b` 也立即死亡，因为后续没有语句读取 `a` 或 `b` 的旧值。等等，让我们仔细检查代码：
     - `a=1` (a活)
     - `b=10` (a,b活)
     - `c=20` (a,b,c活) -> 此时3个
     - `d=a+b` (a,b,c,d活? 不，a和b在计算完d后，后续语句 `e=c+d`, `f=c+e`... 都没有用到a和b。所以a和b在 `d=a+b` 这一行结束后就死了。此时活跃的是 c, d。寄存器可以复用。)
     - `e=c+d` (c,d,e活) -> 此时3个
     - `f=c+e` (c,e,f活? c在 `f=c+e` 后还活吗？下一句 `b=c+e` 用到了c。所以c还活。e还活。f刚生成。此时活跃：c, e, f。3个。)
     - `b=c+e` (c,e,b活? c在 `b=c+e` 后还活吗？下一句 `e=b+f` 不用c。再下一句 `d=5+e` 不用c。最后 `return d+f` 不用c。所以c在 `b=c+e` 后死亡。e还活（用于下一句）。b刚生成。此时活跃：e, b。注意：f还活吗？`e=b+f` 用到了f。所以f还活。此时活跃：e, b, f。3个。)
     - `e=b+f` (b,f,e活? b在 `e=b+f` 后死亡。f还活吗？`d=5+e` 不用f。`return d+f` 用f。所以f还活。e刚生成。此时活跃：f, e。2个。)
     - `d=5+e` (e,d活? e在 `d=5+e` 后死亡。f还活。d刚生成。此时活跃：f, d。2个。)
     - `return d+f` (d,f活。2个。)
  
  最大活跃数确实是3。陷阱在于考生容易在 `d=a+b` 后忘记释放 `a` 和 `b`，或者在 `b=c+e` 时混淆新旧 `b` 的生命周期。

## 考察能力
一句话概括本题核心考察的能力：**在动态执行过程中，准确追踪变量生命周期并计算最大并发活跃变量数的能力。**
