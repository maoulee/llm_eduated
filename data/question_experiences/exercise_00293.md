# 练习题 Q1 — TCP发送窗口计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
在一条 TCP 连接中，当前拥塞窗口大小为 Congestion Window = 4 KB。接收方通告的窗口大小为 Advertise Window = 6 KB。发送方已发送的最后一个字节是 LastByteSent = 10240，接收方已确认的最后一个字节是 LastByteAcked = 8192。发送方当前的窗口大小是（ ）。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆 TCP 发送窗口大小的核心定义公式：`Send Window = min(CWND, RWND) - (LastByteSent - LastByteAcked)`。这属于传输层的核心概念，非基础术语记忆，但也不是复杂的概念辨析，属于标准的核心定义调用。
- **K2 = 2**: 评分理由。涉及单位换算（KB 到 Byte）和简单的减法运算。由于数值均为 2 的幂次（4KB=4096, 6KB=6144, 10240-8192=2048），计算过程非常友好，不易出错，属于较低难度的单步代入。
- **K3 = 2**: 评分理由。解题步骤清晰且线性：1. 确定有效窗口上限（min）；2. 计算已发送未确认数据量（Bytes in Flight）；3. 相减得到可用窗口。总共 3 步，逻辑直接，无需多步串行推演或状态回溯。
- **K4 = 3**: 评分理由。存在一个常见的认知陷阱：学生容易混淆“发送窗口大小（Send Window Size）”与“可用发送窗口（Available Window / Free Space）”。题目问的是“发送方当前的窗口大小”，在 TCP 协议语境及本题解析逻辑中，通常指**当前允许发送的新数据的空间**（即有效窗口减去已占用部分）。如果学生认为“窗口大小”仅指 `min(CWND, RWND)` 而不减去已发送数据，则会选错。此外，需识别 `LastByteSent` 和 `LastByteAcked` 的含义，避免误用。
- **K5 = 1**: 评分理由。本题完全局限于传输层内部机制，不涉及网络层路由、链路层帧结构或应用层协议交互，属于单系统内部计算。
- **雷达形状**: K4 陷阱型（K1/K2/K3 较低，K4 中等偏高，主要考察对“窗口大小”定义的精确理解及陷阱规避）

## 考察模式
- **模式**: 计算型
- **理由**: 题目提供了具体的数值参数，要求考生根据 TCP 协议规定的公式进行数值计算，最终得出一个具体的字节数。虽然涉及概念理解，但最终落脚点在于定量计算。

## 选项级分析
- **选项 A**: [干扰] — 针对**计算错误**或**概念混淆**。如果学生计算出 Bytes in Flight = 2048，但错误地认为可用窗口就是 Bytes in Flight，或者在减法时出错（如 4096 - 2048 = 2048，这是正确答案，等等，这里 A 是 2048，B 是 4096。让我们重新检查计算：min(4096, 6144) = 4096。Bytes in Flight = 10240 - 8192 = 2048。Available = 4096 - 2048 = 2048。**等等，参考答案给的是 B (4096)？** 
    *   *自我修正与深度分析*：让我们仔细审视题目和参考答案。
    *   标准 TCP 发送窗口（Send Window）通常定义为：`min(CWND, RWND)`。这是发送方**被允许**拥有的最大窗口。
    *   而**可用**发送窗口（Available Window）或**当前可发送**的数据量是：`Send Window - (LastByteSent - LastByteAcked)`。
    *   题目问的是“发送方当前的窗口大小”。在计算机网络教材（如谢希仁版）中，“发送窗口”通常指 `min(CWND, RWND)` 这个上限值，而“当前可发送”才需要减去已发送未确认的。
    *   **但是**，参考解析明确指出：“可用窗口大小等于有效窗口上限减去已传输数据量... 4096 - 2048 = 2048”。**然而参考答案选的是 B (4096)**。
    *   这里存在**题目与解析/答案的严重矛盾**，或者我对“窗口大小”的理解需要结合特定语境。
    *   让我们再看一眼解析文本：“最终可用窗口大小... 即 4096”。解析里写的是 `4096 - 2048` 但结果写成了 `4096`？不对，解析最后一句是“即 4096”。这显然是解析写错了，或者题目问的其实是 `min(CWND, RWND)`？
    *   如果题目问的是“发送窗口大小（Send Window Size）”，通常指 `min(CWND, RWND)`，即 4096。此时 Bytes in Flight 不影响窗口大小的**定义**，只影响**可用空间**。
    *   如果题目问的是“当前可发送的字节数”，则是 2048。
    *   鉴于参考答案是 B (4096)，且解析中虽然提到了减法，但最后结论似乎强行指向 4096（或者解析本身有笔误，把 2048 写成了 4096，或者把减法逻辑搞反了）。
    *   **更可能的解释**：在很多考研真题语境中，“发送窗口大小”指的是 `min(CWND, RWND)` 这个**限制值**，而不是实时可用的空闲空间。实时可用的叫“可用窗口”或“空闲窗口”。题目问“发送方当前的窗口大小”，指的是协议规定的窗口上限。
    *   **修正后的选项分析**：
    *   **选项 A (2048)**: [干扰] — 针对**过度计算**或**概念混淆**。学生计算出了 `Available Window` (4096 - 2048 = 2048)。如果题目问的是“当前还能发送多少字节”，选 A。但题目问的是“窗口大小”，通常指上限。
    *   **选项 B (4096)**: [正确] — 针对**核心概念**。`Send Window = min(CWND, RWND) = min(4096, 6144) = 4096`。这是发送方被允许的最大窗口大小。
    *   **选项 C (6144)**: [干扰] — 针对**忽略拥塞控制**。学生只看了接收方窗口 `AWND = 6KB`，忽略了 `CWND` 的限制，或者误以为取最大值。
    *   **选项 D (8192)**: [干扰] — 针对**完全错误**。可能是 `LastByteAcked` 的数值，或者 `4KB + 4KB` 等无意义组合。

    *   *注：参考解析中的文字描述“可用窗口大小等于...减去...即4096”存在明显的逻辑或笔误（4096-2048!=4096）。但根据答案 B，本题考察的显然是 `min(CWND, RWND)` 这一静态窗口上限，而非动态可用空间。或者，题目中的“窗口大小”在某些教材定义下确实指代上限。*
    *   *为了符合“参考答案 B”和“解析逻辑的修正”*：我将假设题目考察的是 **Send Window Size (上限)**，而非 Available Window。解析中的减法部分可能是为了迷惑，或者解析本身有误。但在 K4 分析中，我会指出这个歧义。
    *   *再次核对常见考研题*：通常问“发送窗口大小”指 `min(CWND, RWND)`。问“当前可发送”才减。
    *   **干扰策略**: 概念混淆（窗口上限 vs 可用空间）、忽略最小值原则。

## 核心陷阱
- **核心陷阱**: **“窗口大小”定义的歧义**。考生容易将“发送窗口大小（Send Window Size，即 `min(CWND, RWND)`）”与“当前可用发送窗口（Available Window，即 `Send Window - BytesInFlight`）”混淆。本题根据答案 B 判断，考察的是前者（上限），而解析中提到的减法逻辑与答案 B 矛盾（若按解析逻辑算出 2048 应选 A），这本身是一个巨大的命题/解析陷阱。在实际考试中，若遇到此类矛盾，通常“窗口大小”指上限，“可发送量”指剩余空间。

## 考察能力
一句话概括本题核心考察的能力：准确区分 TCP 发送窗口的**上限定义**（由拥塞窗口和接收窗口共同决定）与**实时可用空间**，并能正确执行单位换算与最小值选取。
