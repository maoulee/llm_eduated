# 模拟题 Q1 — 动态分区分配算法推演

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: OS-3 > 3.1 内存管理概念 > 内存空间分配
- **难度**: 待评估

## 题干原文
某个计算机采用动态分区来分配内存，经过一段时间的运行，现在内存中依地址从小到大存在 100KB、450KB、250KB、200KB 和 600KB 的空闲分区。分配指针现指向地址起始点，继续运行还会有 212KB、417KB、112KB 和 426KB 的进程申请使用内存，那么，能够完全完成分配任务的算法是（ ）。
- 选项:
  A: 首次适应算法
  B: 邻近适应算法
  C: 最佳适应算法
  D: 最坏适应算法

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆并区分四种动态分区分配算法（首次、邻近、最佳、最坏）的核心定义和搜索策略。不是2分因为仅靠直觉无法解题，必须明确每种算法的具体规则；不是4分因为不需要辨析极其细微的概念差异，核心定义清晰。
- **K2 = 2**: 评分理由。涉及简单的整数比较和减法运算（如 450-212=238）。计算量极小，且数字均为整数，不涉及复杂的进制转换或多级换算，属于低难度计算。
- **K3 = 4**: 评分理由。需要对四个进程请求序列，在四种不同的算法规则下，分别进行多步串行推演。每一步分配后，空闲分区链表的状态都会改变，影响后续分配。特别是对于错误选项，需要推演到某一步失败为止；对于正确选项，需推演完所有步骤。步骤多且需保持中间状态，符合>5步或需记忆中间状态的特征。
- **K4 = 3**: 评分理由。存在隐含前提和常规注意点。例如，“分配指针现指向地址起始点”对首次适应和邻近适应的影响不同；“依地址从小到大”是初始状态，但最佳适应和最坏适应会改变链表的排序方式（按大小排序而非地址排序）。考生需意识到不同算法对空闲链表维护方式的不同，否则容易用地址顺序去套用最佳/最坏适应，导致错误。
- **K5 = 1**: 评分理由。本题仅涉及内存管理子系统内部的动态分区分配机制，不涉及CPU调度、文件系统或I/O等其他子系统的状态传递或耦合。

- **雷达形状**: K3推演主导型（K3显著高于其他维度，K1中等，K2/K5低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非单纯考察概念记忆（概念型），也不是简单的公式代入（计算型），而是要求考生根据给定的初始状态和一系列输入，依据不同算法的规则进行逻辑推演，预测系统状态的变化过程，最终得出结果。核心在于“过程模拟”和“逻辑判断”。

## 选项级分析
- **选项A**: [干扰] — 针对“首次适应算法”的常见误区。许多学生知道首次适应是从低地址开始找第一个满足的分区，但在推演时容易忽略分配后剩余碎片的大小对后续大进程的影响。本题中，首次适应在分配前三个进程后，剩余最大分区为250KB，无法满足第四个426KB的请求。选此项的学生通常推演不完整或计算错误。
- **选项B**: [干扰] — 针对“邻近适应算法”（循环首次适应）的误解。邻近适应从上次分配位置继续搜索。若学生未正确模拟指针的移动和循环特性，可能会误判其分配结果。实际上，邻近适应在此场景下通常表现不如首次适应或更差，因为指针可能停留在高地址区，导致低地址的大空闲区被跳过或碎片化更严重。
- **选项C**: [正确] — 针对“最佳适应算法”的正确应用。最佳适应算法总是选择能满足要求且最小的空闲分区。
    - 212KB -> 选250KB (剩38KB)
    - 417KB -> 选450KB (剩33KB)
    - 112KB -> 选100KB? 不，100<112，选200KB (剩88KB)
    - 426KB -> 选600KB (剩174KB)
    - 所有请求均满足。选此项的学生正确模拟了最佳适应的“最小足够”策略及其对空闲链表的动态调整。
- **选项D**: [干扰] — 针对“最坏适应算法”的误解。最坏适应总是选择最大的空闲分区。
    - 212KB -> 选600KB (剩388KB)
    - 417KB -> 选450KB (剩33KB)
    - 112KB -> 选388KB (剩276KB)
    - 426KB -> 剩余最大为276KB (来自388的剩余) 或 250KB (原250未动? 不，原250还在，但276>250)。等等，让我们重新推演最坏适应：
        - 初始: 100, 450, 250, 200, 600
        - 212KB: 选600 (最大), 剩388. 空闲: 100, 450, 250, 200, 388
        - 417KB: 选450 (最大), 剩33. 空闲: 100, 33, 250, 200, 388
        - 112KB: 选388 (最大), 剩276. 空闲: 100, 33, 250, 200, 276
        - 426KB: 最大空闲为276, 276 < 426. 分配失败。
    - 选此项的学生可能误以为最坏适应能保留小分区给小进程，或者推演错误。

- **干扰策略**: 渐进陷阱。通过设置一个总内存足够但碎片化严重的场景，使得只有特定策略（最佳适应）能成功，而其他常见策略（首次、最坏）因碎片分布问题失败，诱导学生仅凭“总内存足够”的直觉或不完全推演而选错。

## 核心陷阱
- **核心陷阱**: **算法对空闲链表维护方式的差异**。首次/邻近适应通常按地址排序，而最佳/最坏适应通常按大小排序。考生若忽略这一点，用地址顺序去模拟最佳/最坏适应，或用大小顺序去模拟首次适应，都会导致推演错误。此外，**推演的完整性**是关键，必须一步步模拟，不能仅看第一步或最后一步。

## 考察能力
本题核心考察考生对动态分区分配算法执行过程的**精确模拟能力**及**状态跟踪能力**，要求能在多步串行操作中准确应用不同算法的搜索与更新规则。
