# 模拟题 Q1 — 指令执行流程与取指阶段

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: OS-1 > 1.3 操作系统的运行环境 > 处理器运行状态
- **难度**: 待评估

## 题干原文
在计算机体系结构中，CPU 内部包括程序计数器 PC、存储器数据寄存器 MDR、指令寄存器 IR 和存储器地址寄存器 MAR 等。若 CPU 要执行的指令为：MOV RO, #100（即将数值 100 传送到寄存器 RO），则 CPU 首先完成的操作是（ ）。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆 CPU 执行指令的基本周期（取指、译码、执行）以及各寄存器（PC, MAR, MDR, IR）在取指阶段的标准流向。属于核心定义记忆，不涉及复杂辨析。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算或单位换算，无需执行计算步骤。
- **K3 = 2**: 评分理由。推演步骤较少。只需识别“首先”意味着进入“取指阶段”，并回忆取指阶段的第一步动作（PC -> MAR）。虽然涉及多步流程，但题目只问第一步，逻辑链条短。
- **K4 = 3**: 评分理由。存在明显的“语义陷阱”。题干给出了具体指令 `MOV RO, #100`，考生容易受指令语义干扰，直接思考“执行”阶段的操作（如立即数加载），而忽略了 CPU 执行任何指令前必须先“取指”这一隐含前提。需要考生具备“先取指后执行”的宏观意识来避开陷阱。
- **K5 = 3**: 评分理由。涉及 CPU 内部寄存器（PC, MAR）与内存控制器之间的数据传递。虽然主要是单向的地址传递，但体现了 CPU 与内存子系统间的交互机制。
- **雷达形状**: K4 陷阱型（K1 基础记忆为主，K4 条件识别为关键得分点，K2 极低）

## 考察模式
- **模式**: 概念型
- **理由**: 本题主要考察对 CPU 指令执行周期中“取指阶段”硬件操作流程的概念理解，而非复杂的逻辑推理或数值计算。重点在于区分“指令语义”与“硬件执行流程”的区别。

## 选项级分析
- **选项 A**: [干扰] — 针对“望文生义”的错误认知。考生看到 `MOV RO, #100`，直接理解为将 100 送入 RO，忽略了这是指令执行阶段（Execute）的结果，而非 CPU 启动时的第一步。这类学生通常混淆了“指令含义”和“硬件动作”。
- **选项 B**: [干扰] — 针对“流程顺序混淆”的错误认知。MDR（存储器数据寄存器）用于暂存从内存读出的数据（指令或数据）。在取指阶段，数据确实会进入 MDR，但这发生在地址送入 MAR 之后。选此项的学生可能记得取指涉及 MDR，但记不清先后顺序，或者误以为立即数 100 需要先经过 MDR。
- **选项 C**: [正确] — 符合标准取指流程。CPU 执行指令的第一步是取指，取指的第一步是将 PC（程序计数器）中的地址送入 MAR（存储器地址寄存器），以便访问内存。
- **选项 D**: [干扰] — 针对“寄存器功能误解”的错误认知。IR（指令寄存器）用于存放当前正在执行的指令。PC 中存的是地址，IR 中存的是指令内容，两者不能直接传输。选此项的学生可能对寄存器功能理解模糊，认为 PC 直接指向 IR。

**干扰策略**: 语义干扰（用具体指令内容诱导考生跳过取指阶段）+ 流程顺序混淆（打乱取指内部步骤）

## 核心陷阱
**“指令语义”与“硬件流程”的混淆**。
题干给出具体的 `MOV` 指令，诱导考生直接思考该指令的功能（数据传送），从而忽略 CPU 执行**任何**指令前都必须经历的通用前置步骤——**取指阶段**。考生必须意识到，无论指令内容是什么，CPU 首先要做的永远是“找到这条指令”，即 `PC -> MAR`。

## 考察能力
考察考生对 CPU 指令执行周期中“取指阶段”硬件数据流向的准确记忆，以及在具体指令语境下剥离语义干扰、回归底层硬件机制的能力。
