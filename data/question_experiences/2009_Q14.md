# 2009年 Q14 — Cache组相联映射计算

## 基本信息
- **年份**: 2009  **题位**: Q14  **题型**: 选择题
- **知识点**: Cache映射方式(组相联), 主存地址结构(块号/块内偏移), Cache容量计算
- **考纲对应**: 第三章 存储器层次结构 → Cache → 映射方式(全相联/直接映射/组相联)

## 题干原文
[2009年考研真题第14题]某计算机的Cache 共有16块，采用2路组相联映射方式（即每组2块）。每个主存块大小为32B,按字节编址。主存129号单元所在主存块应装入到的Cache 组号是。
A

## K1-K5 评分与解析
- **K1 = 3**: 3 — 必须准确记忆“组相联映射”的定义（主存块号 mod 组数 = Cache组号）以及“块内地址”、“主存块号”与“主存地址”的区别。若概念模糊（如误以为直接对地址取模），无法入题。不是2分，因为“2路组相联”的具体含义（每组2块）需明确才能算出组数；不是4分，因为概念属于核心基础，非冷门细节。
- **K2 = 2**: 2 — 仅需两步简单整数运算：1）主存块号计算（129 // 32 = 4）；2）组号计算（4 % 8 = 4）。数字友好（32, 129, 16均为常规数），无复杂小数或幂次换算。不是1分，因为涉及除法取整和模运算，非纯心算常识；不是3分，因为计算量极小，不涉及非2的幂或复杂公式。
- **K3 = 3**: 3 — 需按固定“说明书”走完流程：1. 确定块大小 -> 2. 计算主存块号 -> 3. 确定Cache组数 -> 4. 计算映射组号。路径唯一，步骤清晰（3-5步）。不是2分，因为涉及两个阶段的状态转换（地址->块号->组号）；不是4分，因为无需维持动态状态或处理冲突替换，仅是静态映射计算。
- **K4 = 3**: 3 — 存在明确的陷阱词/点：1）“按字节编址”隐含地址与块大小的换算关系；2）“2路组相联”隐含组数的计算方式；3）编号从0开始还是1开始（虽本题结果4 mod 8=4不敏感，但概念上需知主存块号通常从0计数）。不触发这些规则（如误用地址直接mod组数）就会出错。不是2分，因为“块大小”和“映射方式”是强约束条件；不是4分，因为陷阱较为显性，属于常规考点而非深层隐含前提。
- **K5 = 1**: 1 — 单一知识点（Cache映射）内部解决，不涉及总线、中断、指令流水线等其他系统的数据交互。
- **雷达形状**: K3推演型 (兼具 K1概念型特征)

## 考察模式
- **模式**: 计算型
- **理由**: 题干给出具体参数（地址、块大小、Cache规模、相联度），要求通过确定性的公式计算得出唯一的数字结果。

## 选项级分析
- **选项A**: [干扰] — 针对“地址直接映射”错误认知。学生可能直接用主存地址129对Cache总块数16或组数8取模，或者未除以块大小。129 % 16 = 1, 129 % 8 = 1，若选项中有1则为此类；若选项为3，可能是计算主存块号时出错（如 129/32 误算为 3.xx 取整为3）。针对未掌握“主存块号”概念，混淆“地址”与“块号”的学生。
- **选项B**: [正确] — 正确结果。逻辑：Block_Size=32B -> Block_Index = floor(129/32) = 4。Cache_Total_Blocks=16, Associativity=2 -> Num_Sets = 16/2 = 8。Set_Index = 4 % 8 = 4。
- **选项C**: [干扰] — 针对“组数计算错误”或“直接映射混淆”。若误以为每组1块（直接映射），组数为16，4%16=4（巧合相同）；若误算组数为其他值，或误将块号加1（从1开始编号）导致 5%8=5。针对对“路数”和“组数”关系理解不清的学生。
- **选项D**: [干扰] — 针对“除法未取整”或“余数混淆”。129/32 = 4.03125，若学生误将小数部分放大或误用余数（129%32=1）进行后续运算，或误算主存块号为6（如误记块大小为16B? 129/16=8，也不对）。通常D选项6可能来自错误的组数计算（如误以为4组？4%4=0? 不对）。更可能是将主存块号计算错误，例如误以为129位于第6块（无明确逻辑，属随机干扰或极端计算错误）。针对计算粗心或概念完全混乱的学生。
- **干扰策略**: 并行陷阱（各干扰项独立）

## 考察能力
本题考查考生对Cache组相联映射机制中“地址结构划分”及“组号计算逻辑”的规范化应用能力，重点在于区分地址层次（块内、组号、标记）并正确执行整数除法与模运算。
