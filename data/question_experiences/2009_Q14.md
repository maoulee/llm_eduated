# 2009年 Q14 — Cache组相联映射计算

## 基本信息
- **年份**: 2009  **题位**: Q14  **题型**: 选择题
- **知识点**: Cache组相联映射, 主存块号计算, Cache组号计算
- **考纲对应**: 第三章 存储系统 → 高速缓冲存储器 Cache → Cache地址映射 → 组相联映射

## 题干原文
[2009年考研真题第14题]某计算机的Cache 共有16块，采用2路组相联映射方式（即每组2块）。每个主存块大小为32B,按字节编址。主存129号单元所在主存块应装入到的Cache 组号是。
A

## K1-K5 评分与解析
- **K1 = 3**: 3 — 必须准确记忆“组相联映射”中组号的计算公式（主存块号 mod 组数），以及“主存块号”的定义（地址/块大小），概念模糊无法入题。不是2分，因为不能靠常识推导；不是4分，因为不涉及冷门细节或极易混淆的底层硬件信号。
- **K2 = 2**: 2 — 仅需两步简单计算：129/32取整得4，4 mod 8得4。数字友好，无复杂换算。不是1分，因为有明确的除法取整和取模运算；不是3分，因为不涉及非2幂次或小数运算。
- **K3 = 3**: 3 — 需按固定流程走完：地址->块号->组数->组号。路径唯一，步骤清晰（3-5步）。不是2分，因为涉及两个转换阶段（块化、映射）；不是4分，因为无需动态状态更新或长程推演。
- **K4 = 2**: 2 — 存在常规注意点（如地址从0开始、块号向下取整），但408考生基本不会踩坑，陷阱不深。不是1分，因为有“129/32=4.03”这种可能导致编号错误的细微陷阱；不是3分，因为题干没有明确的陷阱词诱导用错公式。
- **K5 = 1**: 1 — 单一知识点（Cache映射）内部解决，不涉及主存-辅存或CPU指令流的跨域联动。
- **雷达形状**: K3推演型

## 考察模式
- **模式**: 计算型
- **理由**: 题干提供具体参数，选项为具体的计算结果，解题核心在于执行正确的算术转换流程。

## 选项级分析
- **选项A**: [正确] — 正确计算：129 // 32 = 4 (主存块号)，16块/2路=8组，4 % 8 = 4。针对掌握完整映射流程的学生。
- **选项B**: [干扰] — 可能错误地认为块号从1开始编号（(129/32向上取整)+1? 或 129/32+1?），或者在取模时出错。针对对“0起始编号”概念模糊的学生。
- **选项C**: [干扰] — 可能错误计算了Cache的组数（例如误以为16块就是16组，4%16=4，若其他选项不同则此项无意义；或者误算块号）。针对对“路数”和“组数”关系理解不清的学生。
- **选项D**: [干扰] — 可能将主存块大小或Cache总块数搞混，例如用129直接对8取模（129%8=1），或者用错误的块号（如129/16?）。针对无法正确执行“地址转块号”第一步的学生。
- **干扰策略**: 并行陷阱（各干扰项独立）

## 核心陷阱
- **核心陷阱**: 主存块号的计算是否向下取整（整数除法），以及Cache组数的计算（总块数/路数）。
- **错误路径**: 学生可能直接使用地址129对组数取模，忽略了“先求块号”这一中间转换步骤；或者在计算块号时未考虑地址从0开始，导致块号偏移。

## 考察能力
考察学生在Cache组相联映射场景下，准确执行“物理地址->主存块号->Cache组号”多层转换计算的能力。
