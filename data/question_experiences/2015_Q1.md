# 2015 Q1 — 递归调用与栈帧顺序

## 基本信息
- **年份**: 2015  **题位**: Q1  **题型**: 选择题
- **知识点**: 栈, 数据结构>栈
- **题位域**: DS-1  **科目**: 数据结构

## 题干原文
已知程序如下：
```cpp
int S(int n) {
    return (n <= 0) ? 0 : S(n - 1) + n;
}
void main() {
    cout << S(1);
}
```
程序运行时使用栈来保存调用过程的信息，自栈底到栈顶保存的信息依次对应的是（ ）。

- 选项:
  A: main() → S(1) → S(0)
  B: S(0) → S(1) → main()
  C: main() → S(0) → S(1)
  D: S(1) → S(0) → main()
- 正确答案: A
- 解析（参考）: 递归调用函数时，在系统栈里保存的函数信息需满足先进后出的特点，依次调用了 main()，S(1)，S(0)，故栈底到栈顶的信息依次是 main()，S(1)，S(O)。
- 知识标签: ['栈', '数据结构>栈']
- 知识域: CO-4

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“函数调用栈”、“栈底/栈顶定义”以及“递归执行流程”这三个核心概念。仅靠直觉无法准确判断，必须明确栈的生长方向（通常向下或向上，但逻辑上后进者在顶）和调用顺序。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需进行算术运算或复杂的公式代入，仅涉及逻辑顺序的排列。
- **K3 = 3**: 评分理由。需要推演递归调用的具体步骤：main调用S(1) -> S(1)调用S(0) -> S(0)返回。这是一个3步的串行推演过程，需要清晰地在脑海中构建调用链。
- **K4 = 2**: 评分理由。存在常规注意点，即“栈底”对应最早进入的函数，“栈顶”对应最后进入的函数。若混淆栈底栈顶定义或递归终止条件，容易出错，但陷阱较浅，属于基础概念辨析。
- **K5 = 1**: 评分理由。本题仅涉及数据结构中的栈与程序运行时的调用机制，属于单一知识域内的直接应用，无需跨越操作系统、编译原理等其他模块进行深度耦合分析。
- **雷达形状**: K3推演主导型（K1基础认知与K3机制推演均衡，K2极低，无显著陷阱K4）

## 考察模式
- **模式**: 推理型
- **理由**: 题目并非直接考查栈的定义记忆，而是要求考生根据给定的代码逻辑，推理出程序运行时的动态行为（函数调用序列），并将其映射到静态的数据结构（栈）状态上。

## 选项级分析
- **选项A**: [正确] — 符合递归调用顺序。main最先执行（栈底），接着调用S(1)（中间），S(1)内部调用S(0)（栈顶）。自底向上为 main -> S(1) -> S(0)。
- **选项B**: [干扰] — 针对“栈顶/栈底方向混淆”或“逆序思维”的错误认知。这类学生可能知道调用顺序是 main->S(1)->S(0)，但错误地认为栈顶是先进入的元素，或者将返回顺序误认为是栈的存储顺序。
- **选项C**: [干扰] — 针对“递归展开顺序误解”的错误认知。这类学生可能认为S(0)是递归的终点，所以应该先出现，或者混淆了递归的“递”与“归”阶段，错误地认为S(0)在S(1)之前被压栈。
- **选项D**: [干扰] — 针对“忽略main函数”或“完全逆序”的错误认知。这类学生可能只关注了S函数的递归，忽略了main是入口，或者完全颠倒了栈的生长方向。
- **干扰策略**: 概念混淆（栈底/栈顶定义）、顺序颠倒（调用顺序 vs 返回顺序）

## 核心陷阱
- **核心陷阱**: **栈底与栈顶的定义混淆**以及**递归调用链的构建**。考生容易混淆“先进先出”（队列）与“先进后出”（栈）的区别，或者错误地认为栈顶是程序执行的起点（main），而实际上栈顶是当前正在执行或最后被调用的函数（S(0)）。

## 考察能力
一句话概括本题核心考察的能力：理解递归函数调用过程中系统栈帧的压栈顺序及栈底/栈顶的逻辑对应关系。
