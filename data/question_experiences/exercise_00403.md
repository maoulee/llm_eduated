# 练习题 Q1 — 递归时间复杂度分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
考虑以下两个函数。它们的时间复杂度是多少？
```c
int fun1(int n) {
    if (n <= 1) return n;
    return 2 * fun1(n - 1);
}
int fun2(int n) {
    if (n <= 1) return n;
    return fun2(n - 1) + fun2(n - 1);
}
```
- 选项:
  A: fun1() 和 fun2() 都是 $O(2^n)$
  B: fun1() 是 $O(n)$，fun2() 是 $O(2^n)$
  C: fun1() 是 $O(2^n)$，fun2() 是 $O(n)$
  D: fun1() 和 fun2() 都是 $O(n)$
- 正确答案: B
- 解析（参考）: fun1() 分析
递归关系式：$T(n) = T(n-1) + C$
时间复杂度：$O(n)$（线性递归）
fun2() 分析
递归关系式：$T(n) = 2T(n-1) + C$
时间复杂度：$O(2^n)$（指数级递归树）
关键区别
：
fun1() 每次递归仅调用自身一次，形成单链递归结构；
fun2() 每次递归调用自身两次，形成二叉树状递归结构，导致子问题数量呈指数增长。
- 知识标签: ['数据结构/算法分析']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握递归时间复杂度的基本定义及递归树/递推公式的概念。不是2分因为不能仅靠直觉，需明确区分“返回值的大小”与“执行的操作次数”这两个核心概念。
- **K2 = 2**: 评分理由。计算过程简单，fun1为线性累加，fun2为指数累加，无需复杂的多级换算或高精度计算，属于标准的2的幂次友好型估算。
- **K3 = 2**: 评分理由。推演步骤较少。对于fun1，只需识别出单层递归调用；对于fun2，只需识别出双层递归调用并建立递推式 $T(n)=2T(n-1)$。无需多步串行推演或记忆大量中间状态。
- **K4 = 4**: 评分理由。存在明显的认知陷阱。题目中 `2 * fun1(...)` 和 `fun2(...) + fun2(...)` 在数学结果上等价，极易误导考生认为两者复杂度相同。考生必须避开“返回值增长快则复杂度高”的直觉陷阱，识别出“函数调用次数”才是决定复杂度的关键隐含前提。
- **K5 = 1**: 评分理由。单系统考察，仅涉及算法分析模块，无需跨越数据结构、操作系统等其他子系统传递状态。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，表明本题主要考察对易混淆概念的辨析能力而非计算或推演深度）

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心不在于复杂的代码执行模拟或数学计算，而在于对“时间复杂度”这一概念本质的理解。它考察考生是否真正理解时间复杂度衡量的是“基本操作执行的次数”，而非“函数返回值的量级”。

## 选项级分析
- **选项A**: [干扰] — 针对“返回值决定复杂度”的错误认知。这类学生看到 `2 * ...` 和 `... + ...` 都导致结果翻倍，误以为两者的计算量都随结果呈指数增长，或者混淆了空间复杂度/返回值大小与时间复杂度。
- **选项B**: [正确] — 正确识别了fun1是线性递归（调用栈深度n，每层常数时间），fun2是指数递归（递归树节点数 $2^n$）。
- **选项C**: [干扰] — 针对“完全混淆”或“反向直觉”的错误认知。这类学生可能认为fun1中有乘法所以更复杂，或者完全随机猜测。
- **选项D**: [干扰] — 针对“忽略递归分支”的错误认知。这类学生可能只看到了 `n-1` 的递减，认为两者都是简单的线性递减，忽略了fun2中两次调用的叠加效应。
- **干扰策略**: 概念混淆（利用数学等价性掩盖计算过程差异）

## 核心陷阱
**数学等价性与计算复杂度的混淆**。
`2 * fun1(n-1)` 和 `fun2(n-1) + fun2(n-1)` 在最终返回值上是完全一样的，但前者只执行了一次递归调用，后者执行了两次。考生容易误以为“结果一样，过程就一样”，从而忽略递归树中节点数量的指数级爆炸。

## 考察能力
能够透过代码表象（返回值计算逻辑），准确识别递归调用结构（单链 vs 二叉树），并据此推导时间复杂度。
