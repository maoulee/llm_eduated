# 练习题 Q1 — 轮转调度时间片与切换开销约束分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/CPU调度
- **难度**: 待评估

## 题干原文
考虑 n 个进程以轮转方式共享 CPU。假设每次进程切换需要 s 秒，那么轮转时间 q 必须满足什么条件才能使进程切换带来的开销最小化，同时保证每个进程至少每 t 秒能获得一次 CPU 使用权？（ ）
A: $q \le \frac{t - ns}{n - 1}$
B: $q \ge \frac{t - ns}{n - 1}$
C: $q \le \frac{t - ns}{n + 1}$
D: $q \ge \frac{t - ns}{n + 1}$

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握轮转调度（RR）的基本概念，特别是“时间片（q）”、“上下文切换开销（s）”以及“响应时间/周转时间约束（t）”的定义。不需要辨析多个易混概念，但必须理解RR调度中进程轮流执行的机制。
- **K2 = 3**: 评分理由。涉及代数不等式的推导。虽然计算本身不复杂（线性方程），但需要正确处理分子分母中的 $n$ 和 $n-1$ 的关系，且涉及不等号方向的判断，属于标准难度的代数运算。
- **K3 = 4**: 评分理由。这是本题的核心难点。考生需要在脑海中构建一个完整的调度周期模型：从进程P1开始执行，到P1再次获得CPU，中间经历了哪些步骤？需要推演出：P1执行q秒 -> 切换s秒 -> P2执行q秒 -> 切换s秒 ... -> Pn执行q秒 -> 切换s秒 -> P1再次获得CPU。这是一个多步串行推演过程，步骤超过3步，且需要准确计数切换次数和执行次数。
- **K4 = 4**: 评分理由。存在显著的隐含前提和易错点。
    1. **切换次数陷阱**：在一个完整的轮转周期中，n个进程各执行一次，共发生n次上下文切换（每个进程执行完后都要切换，包括最后一个进程切换回第一个进程）。很多学生容易误认为是n-1次切换。
    2. **不等号方向陷阱**：题目要求“保证每t秒获得一次”，意味着总耗时必须**小于等于**t，从而推导出q的上限。若理解反了，会选成大于等于。
    3. **分母陷阱**：总执行时间是 $(n-1)q$ 还是 $nq$？注意，当P1再次获得CPU时，其他n-1个进程已经执行完毕，而P1自己还没开始新一轮执行，所以限制P1等待时间的是其他n-1个进程的执行时间加上所有切换时间。
- **K5 = 1**: 评分理由。本题仅涉及CPU调度子系统内部的状态流转，不涉及内存管理、I/O调度或其他子系统的联动。

- **雷达形状**: K3/K4 突出型（推理与陷阱主导）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非直接套用公式，而是要求考生根据调度算法的运行机制，自行推导时间约束关系。核心在于对调度过程的时间轴建模能力。

## 选项级分析
- **选项A**: [正确] — 正确推导结果。
    - 推导逻辑：
      1. 设进程P1在时刻0开始执行。
      2. P1执行q秒，时刻q结束，发生切换，耗时s。时刻 $q+s$。
      3. 接下来P2, P3, ..., Pn依次执行。
      4. 题目要求P1“至少每t秒能获得一次CPU”，即P1再次被调度到的时刻 $\le t$。
      5. P1再次被调度到，意味着P2到Pn这 $n-1$ 个进程都执行完了，并且完成了相应的切换。
      6. 注意：P1执行完后切换（1次s），P2执行完后切换（1次s）... Pn执行完后切换（1次s，切换回P1）。总共n次切换。
      7. 但是，P1再次获得CPU的时刻，是Pn执行结束并切换完成之后。
      8. 时间轴分析：
         - P1执行: $q$
         - 切换1: $s$
         - P2执行: $q$
         - 切换2: $s$
         - ...
         - Pn执行: $q$
         - 切换n: $s$ (此时P1获得CPU)
         - 总时间 $T = n \times q + n \times s$。
         - **等等，让我们重新审视参考解析的逻辑**。参考解析认为方程是 $q(n-1) + ns \le t$。
         - 让我们仔细模拟：
           - T=0: P1开始。
           - T=q: P1结束，切换。
           - T=q+s: P2开始。
           - T=q+s+q: P2结束，切换。
           - ...
           - 要让P1再次运行，必须等到P2...Pn都跑完。
           - P2...Pn 共 $n-1$ 个进程。
           - 这 $n-1$ 个进程的执行时间总和：$(n-1)q$。
           - 切换次数：P1切出(1), P2切出(1)... Pn切出(1)。共n次切换。
           - 所以P1再次获得CPU的时刻 = P1执行时间(q) + P1切换(s) + [P2...Pn的执行时间 $(n-1)q$] + [P2...Pn的切换时间 $(n-1)s$] + [Pn切回P1的切换时间 s] ?
           - 不，通常“获得CPU使用权”指的是调度器选中它的那一刻。
           - 让我们看参考解析的方程：$q(n-1) + ns \le t$。
           - 这个方程隐含的意思是：P1等待的时间（从P1结束到P1再次开始）$\le t - q$？或者总周期 $\le t$？
           - 如果总周期 $\le t$，则 $nq + ns \le t \Rightarrow q \le (t-ns)/n$。选项里没有这个。
           - 如果是指P1的**响应时间**（从就绪到执行）？不，题目说“每t秒能获得一次”，通常指轮转周期。
           - 让我们重新解读参考解析：“当当前进程再次获得 CPU 时，会有 (n-1) 个进程已经运行过一次... 发生了 n 次上下文切换”。
           - 参考解析的方程 $q(n-1) + ns \le t$ 实际上计算的是：**除了P1自己这次执行的时间q之外，剩下的时间必须留给其他进程和切换**。
           - 也就是说，P1在t秒内，必须完成：其他n-1个进程的执行 + 所有n次切换。
           - 即：$t \ge q (\text{P1的执行}) + (n-1)q (\text{其他进程执行}) + ns (\text{所有切换})$ ? 不对，这样就是 $nq + ns \le t$。
           - 让我们看选项A的分母是 $n-1$。这意味着不等式左边是 $q(n-1)$。
           - 这暗示了约束条件可能是：**P1的等待时间（Waiting Time）或者 轮转周期中除去P1自身执行时间的部分**？
           - 或者，题目中的“每t秒能获得一次”被解释为：P1执行完后，必须在t秒内再次执行？即 $t$ 是间隔时间？
           - 如果 $t$ 是间隔时间（从P1结束到P1再次开始），那么：
             - P1结束时刻：$q$。
             - P1再次开始时刻：$q + s + (n-1)q + (n-1)s + s$? 
             - 让我们梳理切换：
               1. P1 -> P2 (s)
               2. P2 -> P3 (s)
               ...
               n. Pn -> P1 (s)
             - 从P1结束到P1再次开始，中间经历了：
               - P1->P2切换 (s)
               - P2执行 (q)
               - P2->P3切换 (s)
               - ...
               - Pn执行 (q)
               - Pn->P1切换 (s)
             - 中间有 $n-1$ 个进程执行，共 $(n-1)q$。
             - 中间有 $n$ 次切换（P1切出，P2切出...Pn切出），共 $ns$。
             - 所以间隔时间 $W = (n-1)q + ns$。
             - 题目说“每t秒能获得一次”，如果理解为“两次获得CPU的时间间隔 $\le t$”，则 $q + W \le t \Rightarrow nq + ns \le t$。
             - 如果理解为“等待时间 $\le t$”或者“从某时刻起t秒内必须执行”，通常RR的约束是周期。
             - **但是**，既然正确答案是A，且解析给出 $q(n-1) + ns \le t$，这说明题目的“每t秒能获得一次”被定义为：**在一个长度为t的时间窗口内，必须包含一次完整的调度循环中除自身外的所有开销，或者说，P1的执行时间q不计入这个“等待/间隔”的硬性约束t中？**
             - 更可能的解释是：题目中的 $t$ 指的是**最大响应时间**或**最大等待时间**的某种变体，或者解析中的 $t$ 实际上是指**轮转周期减去P1自身执行时间**？
             - 不，最合理的解释是：题目问的是“保证每个进程至少每t秒能获得一次CPU”，通常指周期 $T \le t$。但如果答案是A，则必须满足 $(n-1)q + ns \le t$。
             - 这意味着 $t$ 被定义为：**其他进程执行时间 + 所有切换时间**。即 $t$ 是P1的**等待时间**（Waiting Time）上限？
             - 在RR中，平均等待时间确实与 $(n-1)q/2$ 有关，但最坏情况等待时间是 $(n-1)q + ns$（如果刚错过调度）。
             - 如果题目意思是“最坏情况下，进程等待不超过t秒”，那么：
               - 最坏等待时间 = 其他n-1个进程执行完 + 所有切换。
               - $W_{max} = (n-1)q + ns$。
               - 要求 $W_{max} \le t$。
               - 则 $(n-1)q \le t - ns \Rightarrow q \le \frac{t - ns}{n - 1}$。
             - 这与选项A完全吻合。
             - **结论**：题目中的“每t秒能获得一次”在此语境下（结合答案）应理解为**最大等待时间不超过t**，或者**两次执行之间的间隔（不含自身执行时间）不超过t**。这是RR调度中常见的“响应时间”约束分析。

- **选项B**: [干扰] — 针对不等号方向错误。学生可能认为q越大越好（减少切换频率），从而忽略“保证每t秒获得”的紧迫性约束，误选大于等于。
- **选项C**: [干扰] — 针对分母错误。学生可能误以为切换次数是 $n+1$ 或者进程数是 $n+1$，或者在推导时错误地认为总共有 $n+1$ 个时间段。
- **选项D**: [干扰] — 针对分母和不等号双重错误。

- **干扰策略**: 概念混淆（等待时间vs周期时间）、计算陷阱（切换次数n vs n-1）、不等号方向误判。

## 核心陷阱
- **核心陷阱**: **切换次数的计数**与**时间窗口的定义**。
    1. 在一个轮转周期中，n个进程执行，必然伴随n次上下文切换（每个进程执行结束后都要切换，包括最后一个切换回第一个）。很多学生容易漏掉最后一次切换或误算为n-1次。
    2. 对“每t秒获得一次”的理解。结合答案反推，这里考察的是**最坏等待时间**（Worst-case Waiting Time）约束，即 $W_{max} = (n-1)q + ns \le t$。如果理解为总周期 $T \le t$，则答案应为 $q \le (t-ns)/n$，但这不在选项中。因此，识别出题目考察的是“等待时间”而非“总周期”是解题关键，或者识别出解析中 $q(n-1)$ 代表的是“其他进程的执行时间”。

## 考察能力
本题核心考察考生对轮转调度算法中**时间片、上下文切换开销与进程等待时间之间定量关系**的建模与推导能力。
