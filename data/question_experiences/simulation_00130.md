# 模拟题 Q1 — 递归调用次数统计

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: DS-1 > 1.2 算法和算法评价 > 算法基本概念
- **难度**: 待评估

## 题干原文
设有一个递归算法如下：
```c
int X(int n) {
    if (n <= 3) return 1;
    else return X(n - 2) + X(n - 4) + 1;
}
```
试问计算 `X(5)` 时需要调用（ ）次 `X` 函数。

- 选项:
  A: 2
  B: 3
  C: 4
  D: 5
- 正确答案: B
- 解析（参考）: 【解析】
计算 X(5) 时，首先调用 X(5) 一次。由于参数 n=5 大于 3，执行 else 分支，需要递归调用 X(n-2) 即 X(3) 和 X(n-4) 即 X(1)。
调用 X(3) 时，因为 3≤3，直接返回 1，不再递归，此次调用计一次。调用 X(1) 时，同样因为 1≤3，直接返回 1，也不再递归，此次调用也计一次。
因此，总共调用了三次 X 函数：分别是 X(5)、X(3) 和 X(1)。对应选项为 B.3。
- 知识标签: ['DS-1 > 1.2 算法和算法评价 > 算法基本概念']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握递归函数的基本执行流程概念（入口、基线条件、递归步骤）。不是2分因为仅靠直觉无法准确计数，必须理解“调用”包含初始调用和所有子调用；不是4分因为不涉及复杂的递归树优化或尾递归辨析，属于标准的基础概念应用。
- **K2 = 2**: 评分理由。计算过程极其简单，仅涉及整数减法（5-2=3, 5-4=1）和加法计数（1+1+1=3）。没有复杂的数值运算，不易出错。
- **K3 = 2**: 评分理由。推演步骤很少。从 X(5) 出发，只需展开一层即可到达基线条件（X(3) 和 X(1) 均满足 n<=3）。总共只有3个节点，无需记忆中间状态或进行多步串行推演。
- **K4 = 3**: 评分理由。存在一个常见的认知陷阱：学生容易忽略“初始调用”本身也算一次调用，或者误以为只有进入 `else` 分支才算有效调用。此外，需识别 `n<=3` 这个基线条件，避免错误地继续递归（如误以为 X(3) 还会调用 X(1) 和 X(-1)）。这属于常规注意点，但具有一定的迷惑性。
- **K5 = 1**: 评分理由。本题完全局限于单个递归函数内部的状态流转，不涉及不同子系统、模块或数据结构之间的状态传递与耦合。

- **雷达形状**: K4陷阱型（K1、K3、K5较低，K4相对突出，主要考察对“调用次数”定义的准确理解和基线条件的识别）

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心不在于复杂的算法逻辑推导或大规模计算，而在于对“函数调用”这一基本概念在递归语境下的准确定义。它测试的是考生是否理解递归执行栈的基本行为：每次进入函数体都算一次调用，无论是否立即返回。

## 选项级分析
- **选项A**: [干扰] — 针对“忽略初始调用”或“只计算递归分支”的错误认知。这类学生可能认为只有 `X(3)` 和 `X(1)` 是真正的“工作”，或者误以为 `X(5)` 只是发起者不算在内，从而得出 2 次。
- **选项B**: [正确] — 正确统计了 X(5)、X(3)、X(1) 三次调用。
- **选项C**: [干扰] — 针对“基线条件判断错误”或“过度递归”的错误认知。这类学生可能误以为 `n<=3` 不是终止条件，或者错误地认为 `X(3)` 还会继续递归（例如误算成 `X(3)` 调用 `X(1)` 和 `X(-1)`），导致多算一次。
- **选项D**: [干扰] — 针对“完全误解递归结构”或“盲目猜测”的错误认知。可能将递归深度与调用次数混淆，或者错误地展开了更多层级的无效递归。

- **干扰策略**: 概念混淆（对“调用次数”定义的理解偏差）与 计算陷阱（基线条件判断失误）

## 核心陷阱
- **核心陷阱**: **忽略初始调用** 或 **误判基线条件**。
  1. 许多初学者容易忘记将最外层的 `X(5)` 计入总调用次数。
  2. 部分学生可能没有仔细检查 `n<=3` 的条件，错误地认为 `X(3)` 或 `X(1)` 还会继续向下递归，从而增加调用次数。

## 考察能力
一句话概括本题核心考察的能力：准确理解递归函数执行流程中“函数调用”的定义及基线条件的终止作用。
