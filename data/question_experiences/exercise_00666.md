# 练习题 Q1 — 滑动窗口协议最佳窗口大小计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/数据链路层
- **难度**: 待评估

## 题干原文
A 站使用 32 字节的数据包通过滑动窗口协议向 B 站发送消息。A 和 B 之间的往返延迟为 80 ms，路径上的瓶颈带宽为 128kbps。A 应使用的最佳窗口大小是多少？（ ）
- 选项:
  A: 20
  B: 40
  C: 160
  D: 320
- 正确答案: B

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆并理解“带宽时延积”（Bandwidth-Delay Product）与“最佳窗口大小”之间的关系，以及滑动窗口协议中利用率公式 $U = \frac{n}{1+2a}$ 或等效的 $n \ge \text{BDP}$ 概念。这属于标准的核心定义记忆，非基础术语辨析，但也非极高难度的深层机制记忆。
- **K2 = 3**: 评分理由。涉及单位换算（字节转比特，kbps转bps，ms转s）和除法运算。虽然数字较小（32, 128, 80），但存在多级单位换算（Byte -> bit, kbps -> bps, ms -> s），若粗心容易出错，属于标准难度的计算。
- **K3 = 2**: 评分理由。解题步骤清晰且线性：1. 计算传输时延 $T_{trans}$；2. 计算传播时延 $T_{prop}$（由RTT推导）；3. 计算带宽时延积或代入利用率公式求解 $n$。步骤在3步以内，逻辑直接，无需复杂的状态推演。
- **K4 = 3**: 评分理由。存在隐含前提和易错点。首先，“往返延迟”通常指RTT，需考生意识到单向传播时延 $T_{prop} = RTT / 2$（忽略处理时延等）。其次，“最佳窗口大小”在理论计算中通常指使链路利用率达到100%的最小整数窗口，即 $n \ge \text{BDP}$。若考生误将RTT直接当作单向传播时延，或混淆 $a$ 的定义，会落入陷阱。此外，选项B（40）略小于理论精确值（41），需考生具备“选择最接近且合理的整数”的工程思维，而非死扣理论极值。
- **K5 = 1**: 评分理由。本题仅涉及数据链路层/网络层的滑动窗口机制，未跨越其他子系统（如应用层、物理层硬件细节等），属于单系统内部参数计算。
- **雷达形状**: K2计算主导型，伴随K4条件识别。整体呈现中间高（K2, K4），两头低（K1, K5）的特征，K3较低。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的物理参数（带宽、时延、包长）进行数值计算，得出协议参数（窗口大小）。虽然涉及概念，但最终落脚点在于精确的数值推导。

## 选项级分析
- **选项A (20)**: [干扰] — 针对**单位换算错误**或**时延理解错误**。如果考生误将单向传播时延当作RTT（即认为 $T_{prop}=80ms$），或者在计算带宽时延积时漏掉了因子2（仅计算单向BDP），可能会得到较小的数值。例如，若误算 $T_{prop}=80ms$，则 $a=40$，$n \approx 41$，此选项偏差较大；更可能的错误是计算 $BDP = 128k \times 0.04s = 5120 bits = 640 Bytes$，若误以为窗口单位是Byte且除以2（错误逻辑）或其他计算失误。实际上，若考生忘记将RTT除以2得到单向传播时延，直接算 $a = T_{prop}/T_{trans} = 80/2 = 40$，则 $n \approx 41$，这反而指向B。若考生误以为 $T_{prop} = RTT$ 且公式用错，可能得到更小值。另一种可能是计算 $BDP$ 时单位搞错，比如 $128 \times 10^3 \times 0.08 / 8 = 1280$ bits = 160 Bytes，若再除以2（错误地认为窗口是单向？）得80，也不对。最可能的错误路径是：计算 $T_{trans} = 2ms$，误用 $RTT=80ms$ 作为 $2T_{prop}$ 但忘记除以2，或者在计算 $a$ 时出错。更简单的错误：直接算 $BDP = 128kbps \times 80ms = 10240 bits = 1280 Bytes$，然后除以32得40？不对，这是正确答案的路径。若选A，可能是计算 $BDP$ 时用了 $40ms$ 但带宽单位搞错，或者认为窗口大小只需覆盖单向时延的一半等错误认知。
- **选项B (40)**: [正确] — 正确计算路径：
  1. 帧大小 $L = 32 \text{ Bytes} = 256 \text{ bits}$。
  2. 带宽 $R = 128 \text{ kbps} = 128,000 \text{ bps}$。
  3. 传输时延 $T_{trans} = L/R = 256 / 128,000 = 0.002 \text{ s} = 2 \text{ ms}$。
  4. 往返时延 $RTT = 80 \text{ ms}$，故单向传播时延 $T_{prop} = 40 \text{ ms}$。
  5. 带宽时延积（以帧为单位）：$BDP_{frames} = \frac{R \times RTT}{L} = \frac{128,000 \times 0.08}{256} = \frac{10,240}{256} = 40$。
  或者使用 $a$ 参数：$a = T_{prop} / T_{trans} = 40 / 2 = 20$。
  最佳窗口大小 $n \ge 1 + 2a = 1 + 40 = 41$。
  选项中40最接近41，且在实际工程中，窗口大小通常取整数，40能覆盖绝大部分时延积，是最佳选择。
- **选项C (160)**: [干扰] — 针对**时延定义混淆**。如果考生误将 $RTT$ 当作单向传播时延 $T_{prop}$ 来计算 $a$，即 $a = 80/2 = 40$，则 $n = 1 + 2(40) = 81$，接近不了160。如果考生计算 $BDP$ 时，误用 $RTT$ 直接乘带宽得到总比特数，再除以帧大小，但忘记 $RTT$ 包含往返，或者错误地认为窗口需要覆盖 $4 \times T_{prop}$？另一种常见错误：计算 $BDP$ 时，$128kbps \times 80ms = 10240 bits$。$10240 / 256 = 40$ 帧。如果考生误以为窗口大小需要是 $BDP$ 的4倍（错误记忆公式），或者将 $RTT$ 误认为是 $4 \times T_{prop}$ 且计算混乱。更可能的错误是：考生计算出 $BDP = 40$ 帧，但误以为题目问的是字节数？$40 \times 32 = 1280$，不对。若考生误算 $T_{trans}$ 为 $0.5ms$（单位换算错），则 $a=80$，$n=161$，接近160。这是典型的**单位换算错误**导致的干扰。
- **选项D (320)**: [干扰] — 针对**数量级错误**或**公式完全错误**。可能是将带宽单位 kbps 当作 bps 计算，或者将时延 ms 当作 s 计算，导致结果放大1000倍或100倍。例如，若误算 $T_{trans} = 256/128 = 2s$（忽略k和ms），则 $a$ 极小，窗口为1。若误算 $BDP$ 时，$128 \times 80 = 10240$，若误以为帧大小是32 bits（而非bytes），则 $10240/32 = 320$。这是典型的**字节与比特混淆**陷阱。

- **干扰策略**: 概念混淆（字节vs比特）、单位换算陷阱（ms vs s, kbps vs bps）、公式参数误解（RTT vs $T_{prop}$）。

## 核心陷阱
- **核心陷阱**: **单位换算与字节/比特混淆**。
  1. 帧大小32字节需转换为256比特，若误用32比特计算，结果会差8倍（指向D选项320）。
  2. 带宽128kbps需转换为128,000bps，时延80ms需转换为0.08s。
  3. 往返时延RTT与单向传播时延 $T_{prop}$ 的关系：$T_{prop} = RTT/2$。在计算 $a$ 或 $BDP$ 时，需明确公式中使用时延的定义。若使用 $BDP = R \times RTT$，则计算出的比特数对应的是往返期间可发送的数据量，即窗口大小应至少为 $BDP/L$。若使用 $a = T_{prop}/T_{trans}$，则 $n = 1+2a$。两种方法结果一致，但中间变量易错。

## 考察能力
本题核心考察考生对**带宽时延积（BDP）**概念的理解，以及在滑动窗口协议背景下，进行**多单位换算**和**协议参数优化计算**的能力。
