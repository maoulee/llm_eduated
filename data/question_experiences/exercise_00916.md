# 练习题 Q1 — 原子操作与忙等待信号量的死锁分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
原子操作 fetch-and-set x, y 无条件地将内存位置 x 设置为 1，并在不允许任何其他访问内存位置 x 的情况下获取 x 的旧值并存储进入 y。考虑以下对二进制信号量的 P 和 V 函数的实现：
void P(binary_semaphore *s) {
    unsigned y;
    unsigned *x = &(s->value);
    do {
        fetch-and-set x, y;
    } while (y);
}
void V(binary_semaphore *s) {
    S->value = 0;
}
以下哪一项是正确的？（ ）
- 选项:
  A: 如果在 P 中禁用上下文切换，该实现可能无法正常工作
  B: 可以使用普通加载/存储指令代替 fetch-and-set 操作
  C: V 的实现是错误的
  D: 代码未实现二进制信号量
- 正确答案: A
- 解析（参考）: 解释：
P() 函数的工作原理
使用 fetch-and-set 操作将内存位置 x（即 s->value）设置为 1，并读取其旧值到 y。
如果 y 不为 0，则进入 while 循环，持续尝试获取锁。
死锁风险分析
若未启用上下文切换（即无法调度其他进程），则当前进程会陷入无限循环，无法退出 P()。
此时，由于没有其他进程能执行 V() 将 s->value 置为 0，循环条件始终成立，导致死锁。
- 知识标签: ['操作系统/进程管理']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“原子操作”、“二进制信号量”、“忙等待（自旋锁）”以及“上下文切换”这几个核心概念的定义。不需要记忆复杂的公式，但必须理解 fetch-and-set 的硬件级原子性含义。
- **K2 = 1**: 评分理由。本题不涉及数值计算，无需执行任何算术运算或单位换算。
- **K3 = 4**: 评分理由。需要进行多步逻辑推演：1. 理解 P 操作的自旋机制；2. 理解 V 操作的释放机制；3. 模拟“禁用上下文切换”这一极端条件下的执行流；4. 推导出当前进程独占 CPU 导致其他进程无法运行，进而无法执行 V 操作，最终导致死锁的因果链。步骤较多且涉及状态依赖。
- **K4 = 5**: 评分理由。存在极强的隐含前提和反直觉陷阱。通常我们认为“禁用上下文切换”是为了保证临界区原子性，但在这里，它破坏了并发系统的基本假设（即其他进程有机会运行）。考生必须意识到“忙等待”依赖于“其他进程能运行以释放锁”这一隐含前提，否则极易误判。
- **K5 = 3**: 评分理由。涉及进程管理（调度/上下文切换）与同步机制（信号量/原子指令）之间的联动。虽然主要是在进程管理内部，但需要理解调度器状态对同步原语正确性的影响，属于单向的状态影响（调度状态影响同步结果）。
- **雷达形状**: K4 陷阱型（高 K3/K4，低 K1/K2）。本题难点不在于概念记忆或计算，而在于对极端边界条件（禁用上下文切换）下系统行为的多步逻辑推演和隐含前提识别。

## 考察模式
- **模式**: 推理型
- **理由**: 题目不要求直接回忆定义或进行计算，而是要求考生基于给定的代码实现和特定的系统约束（禁用上下文切换），推演系统运行的动态过程，从而判断其正确性。

## 选项级分析
- **选项A**: [正确] — 针对对“忙等待”机制依赖条件的理解。如果禁用上下文切换，当前进程在 `while(y)` 中死循环，CPU 不会被释放，其他持有锁或需要执行 V 操作的进程无法获得 CPU 时间片，导致系统死锁。这是忙等待信号量（自旋锁）在非抢占式或单核无调度环境下的典型缺陷。
- **选项B**: [干扰] — 针对对“原子性”重要性的忽视。普通加载/存储指令不是原子的，在并发环境下会出现竞态条件（Race Condition），导致多个进程同时通过 P 操作进入临界区，破坏互斥性。这类学生可能认为只要逻辑对就行，忽略了硬件指令的原子性要求。
- **选项C**: [干扰] — 针对对 V 操作实现的误解。虽然标准的 V 操作通常包含唤醒等待队列的逻辑，但在纯忙等待（自旋）实现中，V 操作只需将信号量值重置为 0 即可，因为 P 操作是通过不断检查值来获知锁是否释放的。这类学生可能混淆了“阻塞型信号量”和“忙等待型信号量”的 V 操作实现差异。
- **选项D**: [干扰] — 针对对信号量定义的僵化理解。虽然该实现效率低且存在死锁风险（在特定条件下），但它确实实现了二进制信号量的互斥功能（在正常调度环境下）。这类学生可能因为看到潜在的死锁风险就否定其作为信号量实现的资格，或者认为必须包含阻塞队列才是信号量。
- **干扰策略**: 概念混淆（B选项混淆原子指令与普通指令）、实现细节差异（C选项混淆阻塞与自旋实现）、以偏概全（D选项因极端情况否定整体功能）。

## 核心陷阱
- **核心陷阱**: **“忙等待”对“上下文切换”的隐性依赖**。考生容易只关注代码逻辑本身的互斥性，而忽略了操作系统调度机制对并发原语正确性的支撑作用。在禁用上下文切换的情况下，自旋锁退化为死锁，这是本题最关键的考点。

## 考察能力
本题核心考察考生对**并发控制原语底层实现机制**与**操作系统调度机制**之间耦合关系的深度理解，以及在极端边界条件下进行**系统行为推演**的能力。
