# 练习题 Q1 — HTTP非持久连接数计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
假设您通过网页浏览器向 Web 服务器请求了一个网页。初始时浏览器缓存为空，且浏览器配置为以
非持久模式
发送 HTTP 请求。该网页包含文本和五张非常小的图片。在浏览器中完全显示该网页所需的最小 TCP 连接数是（  ）。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆“HTTP非持久连接”的核心定义，即每个对象（Object）都需要独立的TCP连接。若混淆为持久连接或并行连接，则无法解题。属于标准的核心概念记忆。
- **K2 = 2**: 评分理由。计算过程仅为简单的加法（1 + 5 = 6），不涉及复杂换算或多级计算，属于低难度单步代入。
- **K3 = 1**: 评分理由。推演步骤极少，直接从“非持久模式”定义映射到“对象数量”，无需多步串行逻辑或状态记忆。
- **K4 = 3**: 评分理由。存在常规注意点陷阱。考生需识别“文本”本身也是一个HTTP对象，且需确认“最小”连接数在非持久模式下即为对象总数（因为非持久模式不支持并行，必须串行，故最小=最大=总数）。若忽略文本对象或误以为非持久模式可并行，则会出错。
- **K5 = 1**: 评分理由。本题仅涉及应用层（HTTP）与传输层（TCP）的直接映射关系，不涉及网络层、链路层或其他子系统的状态传递或深度耦合。
- **雷达形状**: K1主导型（概念记忆为主，辅以少量陷阱识别）

## 考察模式
- **模式**: 概念型
- **理由**: 题目核心在于考察对HTTP协议两种工作模式（非持久 vs 持久）下TCP连接建立机制的理解，而非复杂的数值计算或逻辑推理。

## 选项级分析
- **选项A**: [正确] — 对应正确认知：非持久模式下，每个对象（1个HTML文本 + 5张图片 = 6个对象）各需1个TCP连接，共6个。
- **选项B**: [干扰] — 针对错误认知：考生可能误以为HTML文本不需要TCP连接（错误），或者误以为非持久模式下可以并行打开部分连接导致计算偏差，或者混淆了DNS查询等前置步骤（虽然题目问的是TCP连接，但有时学生会把DNS UDP包误算或漏算TCP握手细节，但在408语境下，B选项更可能是混淆了“6个对象”与“7个连接”的某种错误逻辑，例如误以为需要额外的控制连接，或者将“最小”误解为持久连接下的1个连接但算错了对象数？不，B=7通常没有直接的理论对应，可能是随机干扰或混淆了其他协议开销。但在某些语境下，如果学生误以为每个对象需要2个连接（如误记TCP握手为独立连接？不合理）。更可能的干扰源是：学生记错了非持久连接的定义，或者混淆了“6个对象”与“7”这个数字（如1个主连接+5个图片+1个什么？）。实际上，B选项作为干扰项，往往针对那些对“对象”计数不清（如漏算文本得5，多选得7？）或混淆了持久连接并行度（如2个并行连接，6/2=3? 不对）。在408真题中，常见干扰是混淆非持久（N个）和持久（1个或2个）。B=7可能是为了干扰那些认为“文本+5图+1个额外开销”的学生。
- **选项C**: [干扰] — 针对错误认知：可能混淆了HTTP/1.1默认持久连接下的并行连接数限制（如浏览器默认6个并行连接），或者误以为非持久模式下每个对象需要更多连接。
- **选项D**: [干扰] — 针对错误认知：完全错误的计算，可能将DNS、TCP握手、HTTP请求响应等所有交互步骤都算作“连接”，或者纯粹的数字凑整。

**干扰策略**: 概念混淆（非持久 vs 持久）、对象计数遗漏（漏算HTML文本）。

## 核心陷阱
- **核心陷阱**: 忽略HTML文本本身也是一个需要通过HTTP请求获取的对象。许多学生只计算图片数量（5张），从而误选5（若选项中有）或产生其他错误计算。此外，需明确“非持久模式”意味着**串行**且**每个对象独立连接**，不存在并行优化，因此“最小”连接数即为对象总数。

## 考察能力
一句话概括本题核心考察的能力：准确理解HTTP非持久连接机制中“每个对象对应一个TCP连接”的规则，并能正确识别网页组成对象的数量。
