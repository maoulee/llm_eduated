# 模拟题 Q1 — IPv4 TTL超时处理机制

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: CN-4 > IPv4 > 生存时间 TTL
- **难度**: 待评估

## 题干原文
路由器中发现 TTL 值为 0 的分组，将进行（ ）处理，并向源主机返回（ ）的 ICMP 报文。

A. 返回发送方，源点抑制
B. 继续转发，改变路由
C. 丢弃，时间超过
D. 本地提交，终点不可达

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。本题需要记忆两个核心概念：TTL为0时的动作（丢弃）以及对应的ICMP报文类型（时间超过）。这属于标准的定义记忆，不涉及复杂辨析，但需要准确对应“动作”与“报文类型”两个知识点。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，完全属于定性判断。
- **K3 = 2**: 评分理由。推演步骤极少：识别TTL=0 -> 执行丢弃 -> 触发ICMP报错。这是一个标准的、线性的协议处理流程，无需多步串行推演或状态保持。
- **K4 = 2**: 评分理由。存在常规注意点，即区分不同类型的ICMP报文（如终点不可达、源点抑制、重定向等）。虽然题目没有设置深层隐含前提，但考生需具备区分常见ICMP类型的意识，属于常规考点陷阱。
- **K5 = 2**: 评分理由。主要涉及网络层（IPv4）内部机制，虽然ICMP属于网络层辅助协议，但并未跨越到传输层或应用层进行深度状态联动，仅提及“向源主机返回”，属于单向的信息反馈，耦合度较低。
- **雷达形状**: K1主导的记忆型，整体呈低分均衡状，无明显高分突出项，属于基础概念考察题。

## 考察模式
- **模式**: 概念型
- **理由**: 题目直接考察协议规范中的具体行为定义和报文类型对应关系，不涉及计算或复杂逻辑推理，主要依赖对教材中TTL机制和ICMP报文类型的记忆与理解。

## 选项级分析
- **选项A**: [干扰] — 针对“源点抑制”概念混淆。这类学生可能记得ICMP有流量控制功能，或者误以为TTL耗尽需要通知源主机停止发送（类似拥塞控制），从而错误关联到“源点抑制”。实际上源点抑制用于拥塞控制，而非TTL超时。
- **选项B**: [干扰] — 针对“路由动态调整”的错误认知。这类学生可能认为TTL为0意味着路径有问题，路由器应该自动寻找新路径（改变路由）。实际上，IP是无连接且尽力而为的服务，路由器不会因单个分组TTL耗尽而改变路由表，且TTL为0必须丢弃，不能继续转发。
- **选项C**: [正确] — 符合IPv4协议规范。TTL减至0时，路由器丢弃分组，并发送ICMP Type 11（时间超过）报文给源主机。这是traceroute工具的工作原理基础。
- **选项D**: [干扰] — 针对“终点不可达”概念混淆。这类学生可能混淆了“中间节点丢弃”和“目的地不可达”。终点不可达（ICMP Type 3）通常发生在分组到达目的地但无对应进程，或下一跳不可达时，而不是在中间路由器因TTL耗尽丢弃时。

- **干扰策略**: 概念混淆。通过列举其他常见的ICMP报文类型（源点抑制、重定向、终点不可达）作为干扰项，考察考生对特定场景下ICMP报文类型的精准匹配能力。

## 核心陷阱
- **核心陷阱**: 混淆不同ICMP报文类型的触发场景。考生容易将“时间超过”（TTL耗尽）与“终点不可达”（目的地问题）或“源点抑制”（拥塞问题）混淆。关键在于明确TTL耗尽是中间路由器的行为，且目的是防止环路，因此对应的是“时间超过”报文。

## 考察能力
