# 练习题 Q1 — TCP连接建立与系统调用映射

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
以下哪个系统调用会导致发送 SYN 数据包？（ ）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆核心定义。考生必须准确记忆 `socket`, `bind`, `listen`, `connect` 这四个基础系统调用的具体功能及其在 TCP 连接生命周期中的位置。不记忆这些概念无法入题，但只需辨析一个核心概念（connect 触发握手）即可，无需辨析多个易混深层概念，故为标准难度。
- **K2 = 1**: 评分理由。微弱。本题不涉及任何数值计算、单位换算或公式代入，属于纯概念判断。
- **K3 = 2**: 评分理由。较低。推演步骤极少。逻辑链条为：识别“发送 SYN” -> 对应“TCP 三次握手第一步” -> 对应“客户端发起连接” -> 对应系统调用 `connect`。仅需 1-2 步逻辑映射，无需多步串行推演或记忆中间状态。
- **K4 = 2**: 评分理由。较低。存在常规注意点。考生需意识到题目隐含的前提是“客户端行为”（因为服务器端不主动发送 SYN 发起连接，而是响应 SYN）。虽然题干未明说“客户端”，但“发送 SYN”这一动作在标准 TCP 语境下默认指向连接发起方。这是一个常规的网络常识注意点，而非深层陷阱。
- **K5 = 3**: 评分理由。单向传数据/状态映射。本题考察的是应用层/内核接口（系统调用）与传输层协议行为（TCP 报文段）之间的映射关系。需要跨越“操作系统 API”和“网络协议栈”两个子系统，理解 API 调用如何触发底层协议状态机的变化。

- **雷达形状**: K1-K5 分布呈现“概念主导型”。K1 和 K5 相对较高，K2 极低，K3 和 K4 处于低位。整体形状偏向左侧（基础认知与跨域映射），无明显计算或复杂推理峰值。

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心在于考察考生对 TCP 协议机制与操作系统网络编程接口（API）之间对应关系的记忆和理解。不涉及计算，也不涉及复杂的逻辑推理，主要依赖对“三次握手”过程及“系统调用功能”这两个核心知识点的直接映射。

## 选项级分析
- **选项 A**: [干扰] — 针对“套接字创建即连接”的错误认知。部分初学者可能误以为创建 socket 就建立了连接，或者混淆了 socket 创建与连接建立的概念。这类学生可能认为只要有了 socket 就能通信，从而误选。
- **选项 B**: [干扰] — 针对“服务器端配置即连接”的错误认知。`bind` 是服务器端将 IP 和端口绑定到套接字，属于被动准备阶段，不涉及任何网络报文的发送。选此项的学生可能混淆了“准备接收”和“主动发起”的区别。
- **选项 C**: [干扰] — 针对“监听即建立连接”的错误认知。`listen` 使套接字进入被动打开状态，准备接收连接请求，同样不发送 SYN。选此项的学生可能误以为“监听”意味着开始与客户端交互，或者混淆了 `listen` 与 `accept` 甚至 `connect` 的功能。
- **选项 D**: [正确] — `connect` 是客户端用于发起 TCP 连接的调用。在 TCP 协议中，发起连接的第一步就是发送 SYN 报文段。这是标准的 API 与协议行为映射。

- **干扰策略**: 概念混淆。通过列出 TCP 服务器端和客户端常用的四个基础系统调用，利用考生对“连接建立过程”中各阶段对应 API 的不熟悉，制造混淆。特别是 `listen` 和 `connect` 都涉及“连接”二字，容易让基础不牢的考生产生语义上的联想错误。

## 核心陷阱
- **核心陷阱**: 混淆“被动打开”（服务器端 bind/listen）与“主动打开”（客户端 connect）的协议行为。考生若不清楚 SYN 是“主动发起连接”的标志，可能会在 B、C、D 之间犹豫，特别是误以为 `listen` 会主动去“听”从而发送某种信号。

## 考察能力
本题核心考察考生对 TCP 三次握手机制与操作系统网络系统调用（API）之间映射关系的准确记忆与理解能力。
