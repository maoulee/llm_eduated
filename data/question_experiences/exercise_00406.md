# 练习题 Q1 — 递归函数空间复杂度分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
考虑以下 C 函数：
```c
double foo(int n) {
    int i;
    double sum;
    if (n == 0) return 1.0;
    else {
        sum = 0.0;
        for (i = 0; i < n; i++)
            sum += foo(i);
        return sum;
    }
}
```
上述函数的空间复杂度是（ ）：
- 选项:
  A: O(1)
  B: O(n)
  C: O(n!)
  D: O(n^n)

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“递归调用栈”与“空间复杂度”的核心定义。不是2分因为不能仅靠直觉，必须明确区分时间复杂度（调用次数）与空间复杂度（最大栈深度）的概念差异。
- **K2 = 1**: 评分理由。无需进行复杂的数值计算或公式推导，只需定性分析递归深度。
- **K3 = 2**: 评分理由。推演步骤较少：1. 识别递归结构；2. 确定最大递归深度；3. 映射到空间复杂度。不需要多步串行推演或记忆大量中间状态。
- **K4 = 4**: 评分理由。存在显著的“隐含前提”和“反直觉”陷阱。题面中的 `for` 循环暗示了巨大的时间开销（指数级或阶乘级），极易误导考生将时间复杂度的量级（如 $O(n!)$ 或 $O(2^n)$）错误地迁移到空间复杂度上。考生必须意识到“空间复杂度取决于最大递归深度，而非总调用次数”，这是一个需要避开暗坑的高难度条件路由。
- **K5 = 1**: 评分理由。本题仅涉及单一子系统（递归调用机制），无需跨越不同模块或处理复杂的状态耦合。
- **雷达形状**: K4陷阱型（K4显著高于其他维度，呈现明显的陷阱特征）

## 考察模式
- **模式**: 推理型
- **理由**: 本题不依赖死记硬背的公式，也不依赖繁琐的计算，而是要求考生理解递归执行的底层机制（栈帧分配与释放），并通过逻辑推理区分“累积的计算量”与“并发的内存占用量”。

## 选项级分析
- **选项A**: [干扰] — 针对认为“局部变量固定，故空间为常数”的错误认知。这类学生忽略了递归过程中栈帧的累积效应，误以为每次调用只占用常数空间且立即释放，未考虑最坏情况下的栈深度。
- **选项B**: [正确] — 正确识别了递归的最大深度为 $n$（当 $i=n-1$ 时调用 `foo(n-1)`，进而调用 `foo(n-2)`...直到 `foo(0)`），因此最大栈深度为 $O(n)$。
- **选项C**: [干扰] — 针对混淆“时间复杂度”与“空间复杂度”的错误认知。该函数的时间复杂度确实非常高（接近 $O(n!)$ 或 $O(2^n)$ 量级，具体取决于实现细节，但远大于多项式），考生容易将巨大的时间开销误认为是空间开销。
- **选项D**: [干扰] — 针对对递归爆炸式增长缺乏具体量级概念，但知道“很大”的错误认知。类似于C，是时间复杂度量级的错误迁移。
- **干扰策略**: 概念混淆（将时间复杂度的量级混淆为空间复杂度）

## 核心陷阱
**时间复杂度与空间复杂度的概念混淆**。
题目中的 `for` 循环导致递归调用次数呈指数级或阶乘级增长，这构成了巨大的时间复杂度。然而，空间复杂度仅由**递归树的最大深度**决定。由于递归是串行执行的（前一个 `foo(i)` 返回后才执行下一个），栈空间不会累积所有调用，只会累积当前调用链的深度。最大深度发生在调用 `foo(n-1)` 时，深度为 $n$。考生极易被循环带来的“巨大工作量”误导，从而选择表示巨大数量的选项 C 或 D。

## 考察能力
准确区分递归算法中“总调用次数（时间）”与“最大递归深度（空间）”的能力。
