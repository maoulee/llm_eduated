# 2010 Q36 — ICMP拥塞控制机制

## 基本信息
- **年份**: 2010  **题位**: Q36  **题型**: 选择题
- **知识点**: CN-4 > IPv4 > ICMP差错报告报文
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
若路由器 R 因为拥塞丢弃 IP 分组，则此时 R 可向发出该 IP 分组的源主机发送的 ICMP 报文类型是（ ）。
ICMP

A. 路由重定向
B. 目的不可达
C. 源点抑制
D. 超时

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。本题属于标准的基础概念记忆。考生需要准确记忆 ICMP 五种差错报告报文（终点不可达、源点抑制、时间超过、参数问题、改变路由）的具体触发场景。虽然不需要复杂的推导，但必须区分“拥塞”与“不可达”、“超时”等概念，因此高于微弱记忆，属于标准定义辨析。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、单位换算或公式代入，完全属于定性判断，计算需求为微弱。
- **K3 = 1**: 评分理由。解题过程为单步映射：识别关键词“拥塞丢弃” -> 匹配对应 ICMP 类型“源点抑制”。无需多步串行推演或状态记忆，机制推演需求为微弱。
- **K4 = 2**: 评分理由。存在常规注意点，即“源点抑制”（Source Quench）在现代网络中已较少使用（被 TCP 拥塞控制取代），但在 IPv4 协议标准及 408 考研大纲中仍是考点。考生需避开“因为现在不用所以不考”或“拥塞就是不可达”的常规误区，属于常规注意点级别。
- **K5 = 1**: 评分理由。本题仅涉及网络层 ICMP 协议内部的报文类型定义，未涉及传输层（如 TCP 窗口）、链路层或其他子系统的状态联动，属于单系统内部知识，跨域联动需求为微弱。
- **雷达形状**: K1 主导型（概念记忆型）。K1 处于标准水平，其余维度均为低分，呈现典型的“知识点直接考查”特征，无明显计算或复杂推理负担。

## 考察模式
- **模式**: 概念型
- **理由**: 题目直接考查 ICMP 协议中特定报文类型的定义及其触发条件，属于对协议规范中具体条款的记忆与理解，不涉及算法执行或复杂逻辑推理。

## 选项级分析
- **选项A**: [干扰] — 针对“路由优化”错误认知。路由重定向（Redirect）是路由器告诉主机“你发给我的包，其实应该发给另一个更优的路由器”，用于优化路由路径，而非处理拥塞。选此项的学生可能混淆了“网络状态异常”与“路由路径优化”。
- **选项B**: [干扰] — 针对“结果导向”错误认知。目的不可达（Destination Unreachable）通常是因为找不到路由、端口关闭或分片重组失败等导致数据包无法送达。虽然拥塞最终可能导致丢包，但 ICMP 协议中专门针对“拥塞”这一特定原因定义了“源点抑制”，而非通用的“不可达”。选此项的学生可能认为“丢包了就是不可达”，忽略了 ICMP 报文的细分语义。
- **选项C**: [正确] — 源点抑制（Source Quench）。当路由器或主机因拥塞而丢弃数据报时，向源点发送此报文，通知源点降低发送速率。这是 IPv4 中用于拥塞控制的机制（尽管在现代 TCP/IP 中主要依赖 TCP 自身的拥塞控制，但在 ICMP 协议定义中依然存在）。
- **选项D**: [干扰] — 针对“时间相关”错误认知。超时（Time Exceeded）通常发生在 IP 分组的 TTL（生存时间）减为 0 时，或者分片重组超时。选此项的学生可能将“拥塞导致的延迟”与“TTL 超时”混淆，或者误以为拥塞会导致 TTL 耗尽。

- **干扰策略**: 概念混淆。利用 ICMP 几种差错报文在“导致丢包”或“网络异常”这一宏观结果上的相似性，考查考生对微观触发条件（拥塞 vs 路由错误 vs TTL 耗尽）的精确区分。

## 核心陷阱
- **核心陷阱**: **“拥塞”与“不可达”的语义混淆**。许多考生直觉上认为路由器丢包了，对源主机来说就是“目的不可达”，从而误选 B。实际上，ICMP 协议设计者为了区分“永久性/结构性错误”（如不可达）和“暂时性/流量性错误”（如拥塞），专门设计了“源点抑制”报文。此外，需警惕“源点抑制”在现代实际网络中已废弃的常识干扰，但在考研理论体系中它依然是标准答案。

## 考察能力
准确记忆并区分 ICMP 五种差错报告报文的具体触发场景，特别是识别“拥塞”对应的专用报文类型。
