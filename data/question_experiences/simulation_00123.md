# 模拟题 Q1 — TCP拥塞控制多轮次推演

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: CN-5 > TCP协议 > TCP拥塞控制
- **难度**: 待评估

## 题干原文
第一次传输时，设 TCP 的拥塞窗口的慢启动门限初始值为 8（单位为报文段），当拥塞窗口上升到 12 时，网络发生超时，TCP 开始慢启动和拥塞避免，那么第 12 次传输时拥塞窗口大小为（ ）。
- 选项:
  A: 5
  B: 6
  C: 7
  D: 8
- 正确答案: B
- 解析（参考）: 【解析】
首先，根据 TCP 拥塞控制机制，初始慢启动门限 ssthresh=8，拥塞窗口 cwnd 从 1 开始。在慢启动阶段，cwnd 每轮次翻倍：第 1 次传输 cwnd=1，第 2 次传输 cwnd=2，第 3 次传输 cwnd=4，第 4 次传输 cwnd=8（达到 ssthresh，进入拥塞避免）。拥塞避免阶段每轮次 cwnd 加 1：第 5 次传输 cwnd=9，第 6 次传输 cwnd=10，第 7 次传输 cwnd=11，第 8 次传输 cwnd=12。此时网络发生超时，超时后将 ssthresh 设置为当前 cwnd 的一半，即 12/2=6，cwnd 重置为 1。
超点后
- 知识标签: ['CN-5 > TCP协议 > TCP拥塞控制']
- 知识域: CN-5

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要准确记忆 TCP 拥塞控制的四个核心变量（cwnd, ssthresh, 慢启动, 拥塞避免）及其触发条件（超时 vs 重复ACK）。属于标准的核心定义记忆，不涉及复杂辨析，但必须精确。
- **K2 = 2**: 评分理由。计算过程仅为简单的整数加法（+1）和乘法（x2）以及除法（/2），数值较小且均为整数，无复杂换算，计算错误概率低。
- **K3 = 4**: 评分理由。从输入到输出需要经历两个阶段的串行推演：第一阶段从第1次到第8次传输（跨越慢启动和拥塞避免两个子阶段），第二阶段从第9次到第12次传输（新的慢启动阶段）。总共涉及8个时间步长的状态追踪，且中间有一次状态重置（超时事件），步骤较多，需记忆中间状态。
- **K4 = 4**: 评分理由。存在明显的隐含前提和陷阱。1. “第N次传输”指的是第N个RTT（往返时间）发送的数据量，而非报文段数量。2. 超时后的处理规则：ssthresh = cwnd/2，cwnd = 1（这是关键陷阱，若误记为cwnd=ssthresh则全错）。3. 慢启动与拥塞避免的切换点判断（cwnd >= ssthresh时进入拥塞避免，还是cwnd > ssthresh？通常教材定义为达到ssthresh后下一轮进入拥塞避免，或当cwnd=ssthresh时按线性增长，本题解析逻辑为第4次cwnd=8等于ssthresh，第5次开始线性增长，需严格遵循题目隐含的教材版本逻辑）。
- **K5 = 1**: 评分理由。本题仅涉及 TCP 传输层内部的拥塞控制算法，不涉及 IP 层、应用层或其他子系统的状态传递，属于单系统内部逻辑推演。
- **雷达形状**: K3-K4 双高型（推演与陷阱主导）。K1基础适中，K2计算简单，但K3的多步状态追踪和K4的规则细节陷阱构成了主要难度。

## 考察模式
- **模式**: 推理型
- **理由**: 虽然包含简单的数值计算，但核心难点不在于算术，而在于对 TCP 拥塞控制算法流程的逻辑推演。考生需要在脑海中模拟 TCP 连接在不同 RTT 下的状态变化，处理“超时”这一中断事件，并重新初始化状态，这属于典型的算法流程推理。

## 选项级分析
- **选项A**: [干扰] — 针对“慢启动计数错误”或“拥塞避免起始点错误”。如果学生认为第4次传输后cwnd=8，第5次cwnd=9...第8次cwnd=12超时，重置后ssthresh=6, cwnd=1。然后第9次cwnd=1, 第10次cwnd=2, 第11次cwnd=4, 第12次cwnd=8? 不对，这是D。如果学生认为超时后cwnd重置为ssthresh(6)，然后第9次6, 第10次7, 第11次8, 第12次9? 也不对。A选项(5)可能源于对慢启动指数增长理解偏差，例如认为第9次1, 第10次2, 第11次3(误以为线性), 第12次4? 或者计算步数少算一步。更可能的错误路径：超时后ssthresh=6, cwnd=1。第9次(1), 第10次(2), 第11次(4), 第12次(8) -> 选D。若选A，可能是将第12次误算为第11次的状态，或者在拥塞避免阶段计算错误。
- **选项B**: [正确] — 正确推演结果。
  - 阶段1:
    - T1: cwnd=1
    - T2: cwnd=2
    - T3: cwnd=4
    - T4: cwnd=8 (达到ssthresh=8)
    - T5: cwnd=9 (拥塞避免, +1)
    - T6: cwnd=10
    - T7: cwnd=11
    - T8: cwnd=12 (发生超时)
  - 事件处理: 超时 -> ssthresh = 12/2 = 6, cwnd = 1
  - 阶段2:
    - T9: cwnd=1 (慢启动)
    - T10: cwnd=2 (慢启动, 1*2)
    - T11: cwnd=4 (慢启动, 2*2)
    - T12: cwnd=6? 等等，慢启动是翻倍。T11是4，T12应该是8？
    - **重新检查解析逻辑**: 
      - 标准TCP慢启动：cwnd每RTT翻倍。
      - T9: cwnd=1
      - T10: cwnd=2
      - T11: cwnd=4
      - T12: cwnd=8? 
      - 但是，如果T11结束时cwnd=4，T12开始时cwnd=8。
      - 让我们看选项。如果答案是B(6)，那么T12的cwnd必须是6。
      - 什么情况下T12是6？
      - 可能性1：题目中的“第12次传输”指的是第12个报文段？不，通常指RTT。
      - 可能性2：慢启动在达到ssthresh时停止翻倍。新的ssthresh=6。
      - T9: cwnd=1
      - T10: cwnd=2
      - T11: cwnd=4
      - T12: 此时cwnd=4 < ssthresh=6，继续慢启动翻倍 -> cwnd=8? 
      - 如果答案是6，说明T12时进入了拥塞避免？或者T11时已经触发了某种限制？
      - 让我们回顾经典教材（如谢希仁或Kurose）：
        - 慢启动：cwnd = 1, 2, 4, 8...
        - 当 cwnd >= ssthresh 时，进入拥塞避免。
        - 在本题中，新 ssthresh = 6。
        - T9: cwnd=1
        - T10: cwnd=2
        - T11: cwnd=4
        - T12: 此时 cwnd=4。下一轮（T13）才会变成8。但在T12这一轮传输中，窗口大小是多少？
        - 通常题目问“第N次传输时拥塞窗口大小”，指的是第N个RTT**开始**时的窗口大小，或者该RTT内**使用**的窗口大小。
        - 如果是指T12这一轮**使用**的窗口：
          - T9使用1
          - T10使用2
          - T11使用4
          - T12使用8 (因为4*2=8，且8>6，所以在T12这一轮中，可能前半段慢启动后半段拥塞避免？不，RTT粒度通常不细分)。
        - **关键点**：很多国内教材/考题对于“慢启动”的定义是：当 cwnd < ssthresh 时，cwnd = cwnd * 2。当 cwnd >= ssthresh 时，cwnd = cwnd + 1。
        - 让我们看T11结束时的状态：cwnd=4。
        - 进入T12：因为 4 < 6，所以执行慢启动，cwnd 变为 4*2 = 8。
        - 但是，如果在T12这一轮中，cwnd 变成了 8，而 ssthresh 是 6。
        - 有些题目逻辑是：如果翻倍后超过 ssthresh，则截断为 ssthresh？或者进入拥塞避免？
        - 如果 T12 的 cwnd 被限制为 ssthresh (6)，则答案为 B。
        - 这种逻辑是：慢启动增长到接近 ssthresh 时，一旦超过或达到，立即切换。
        - 具体步骤：
          - T11 发送 4 个报文。收到 ACK 后，cwnd 更新。
          - 更新规则：若 cwnd < ssthresh, cwnd *= 2; 若 cwnd >= ssthresh, cwnd += 1。
          - T11 开始时 cwnd=4。4 < 6。所以 T11 发送 4 个。
          - T11 结束后，计算 T12 的 cwnd。4 * 2 = 8。
          - 此时 8 > 6。
          - 如果题目逻辑是“第12次传输时”指的是**第12个RTT开始时的窗口值**，那就是8。选D。
          - 如果题目逻辑是“第12次传输时”指的是**第12个RTT结束后的窗口值**？不，通常问的是该轮次的大小。
          - 让我们再看一种常见的考题陷阱：**“第N次传输”对应的是第N个RTT**。
          - 如果答案是B(6)，唯一的解释是：在T12这一轮，窗口大小被认定为6。
          - 为什么是6？
          - 可能是因为：T11结束时cwnd=4。T12开始时，按照慢启动应该变8。但是因为ssthresh=6，所以**不能超过ssthresh**？或者**一旦达到ssthresh就进入拥塞避免**？
          - 如果 T12 的 cwnd 计算为：min(4*2, ssthresh) = 6？这不是标准TCP。
          - 或者，T11 的 cwnd 是 4。T12 的 cwnd 是 4+1=5? (误以为T11就进入拥塞避免？4<6，不可能)。
          - 或者，T10 cwnd=2, T11 cwnd=4, T12 cwnd=6? (线性增长？2->4->6? 这是斐波那契？不对)。
          - **重新审视标准答案B(6)的合理性**：
            - 很多模拟题存在瑕疵。但如果必须选B，最可能的逻辑是：
            - T9: 1
            - T10: 2
            - T11: 4
            - T12: 此时 cwnd 应该翻倍为 8。但是，因为 ssthresh=6，有些教材或题目设定为：**当慢启动使 cwnd 超过 ssthresh 时，将其调整为 ssthresh**，或者**在达到 ssthresh 的那一轮，按 ssthresh 发送**。
            - 另一种可能：题目中的“第12次传输”是指**第12个报文段**？
              - 如果是指报文段：
              - T1: 1 (累计1)
              - T2: 2 (累计3)
              - T3: 4 (累计7)
              - T4: 8 (累计15) -> 第12个报文段在T4中
