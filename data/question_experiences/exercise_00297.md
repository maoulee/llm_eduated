# 练习题 Q1 — TCP三次握手状态机与丢包影响

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/传输层
- **难度**: 待评估

## 题干原文
对于 TCP 连接建立的三次握手的过程。以下哪些陈述是正确的？
(S1) 服务器发送的 SYN+ACK 丢失将无法建立连接
(S2) 客户端发送的 ACK 丢失将无法建立连接
(S3) 在无数据包丢失的情况下，服务器状态机将经历 LISTEN → SYN_RCVD → SYN_SENT → ESTABLISHED 的转换
(S4) 在无数据包丢失的情况下，服务器状态机将经历 LISTEN → SYN_RCVD → ESTABLISHED 的转换

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。需要准确记忆 TCP 状态机的具体状态名称（LISTEN, SYN_RCVD, ESTABLISHED 等）以及三次握手中每个阶段对应的状态转换。不仅仅是知道“三次握手”这个概念，还需要辨析 S3 和 S4 中细微的状态路径差异，属于对核心定义的深度辨析。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、公式代入或单位换算，完全属于定性分析。
- **K3 = 3**: 评分理由。需要在脑海中模拟 TCP 连接建立的过程（输入：发送/接收报文；输出：状态变化）。虽然步骤不多（3步握手），但需要串行推演客户端和服务器的交互逻辑，特别是针对 S1 和 S2 的丢包场景，需要推演后续重传或连接终止的逻辑链条。
- **K4 = 4**: 评分理由。存在明显的隐含前提和反直觉陷阱。
    1. **S2 的陷阱**：常规思维认为“三次握手缺一不可”，但 TCP 协议规定，如果客户端在发送 ACK 后立即发送数据，该数据包的序列号隐含了对 SYN+ACK 的确认，因此 ACK 丢失不一定导致连接无法建立（只要数据能发出去）。这是一个典型的“反直觉”或“协议细节”陷阱。
    2. **S3/S4 的陷阱**：需要识别服务器端的状态机路径。服务器不会进入 SYN_SENT（这是客户端主动发起连接时的状态），这是一个常见的概念混淆点。
- **K5 = 2**: 评分理由。主要考察传输层内部的状态机逻辑，虽然涉及客户端和服务端两个实体，但属于同一协议栈内的交互，未跨越网络层或应用层进行深度耦合分析，仅提及了基本的交互关系。
- **雷达形状**: K4 陷阱型（K1 和 K4 较高，K2 极低，呈现明显的非计算、重逻辑辨析特征）

## 考察模式
- **模式**: 推理型
- **理由**: 题目不仅要求记忆状态转换图，更要求基于协议机制对“丢包”这一异常情况进行逻辑推演，并辨析状态机路径的正确性。特别是 S2 的判断，需要理解 TCP 确认机制的本质（累积确认/数据携带确认），而非死记硬背步骤。

## 选项级分析
- **选项 A (S2 和 S3)**: [干扰] — 针对认为“三次握手每一步都绝对不可丢”的错误认知，以及混淆客户端与服务端状态机的学生。S2 错误在于忽略了数据报文可替代 ACK 的情况；S3 错误在于服务器不会进入 SYN_SENT 状态。
- **选项 B (S1 和 S4)**: [正确] — S1 正确，因为 SYN+ACK 丢失导致客户端不知道服务器已同意连接，客户端会超时重传 SYN，若一直丢失则连接无法建立（从客户端视角看连接未建立，且服务器处于半开状态，最终超时关闭，故宏观上“无法建立连接”是合理的描述，或者说连接建立过程失败）。S4 正确，准确描述了服务器端的标准状态流转。
- **选项 C (S1 和 S3)**: [干扰] — 针对知道 S1 正确，但记错服务器状态机的学生。S3 中的 SYN_SENT 是客户端状态，服务器在被动打开时不会进入此状态。
- **选项 D (S2 和 S4)**: [干扰] — 针对知道 S4 正确，但误以为 ACK 丢失会导致连接失败的学生。这是最常见的误区，认为三次握手必须完整收到三个包才能建立连接。

**干扰策略**: 概念混淆（客户端/服务器状态机混淆）+ 渐进陷阱（对“连接建立”定义的严格性 vs 宽松性理解，以及对 ACK 作用的刻板印象）。

## 核心陷阱
- **核心陷阱**: **S2 的“ACK 丢失”误区**与 **S3 的“服务器状态”误区**。
    1. 许多学生认为三次握手必须完整接收三个报文，因此误选 S2。实际上，TCP 允许通过发送数据来隐含确认（ACK 可以捎带在第一个数据段中），因此单纯的 ACK 报文丢失并不必然导致连接建立失败（只要后续数据能发出并被接收）。
    2. 混淆客户端和服务端的初始状态。服务器被动打开，从 LISTEN 开始；客户端主动打开，从 CLOSED 开始，发送 SYN 后进入 SYN_SENT。服务器永远不会进入 SYN_SENT。

## 考察能力
本题核心考察对 TCP 状态机转换路径的精确记忆以及对 TCP 确认机制（特别是 ACK 与数据报文关系）的深层逻辑理解能力。
