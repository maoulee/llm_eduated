# 2021 Q42 — 排序算法稳定性与复杂度分析

## 基本信息
- **年份**: 2021  **题位**: Q42  **题型**: 综合题
- **知识点**: DS-8 > 8.6 各种内部排序算法的比较及应用 > 排序算法比较
- **题位域**: 待标注  **科目**: 数据结构

## 题干原文
已知某排序算法如下：
```c
void cmpCountSort(int a[], int b[], int n) {
    int i, j, *count;
    count = (int *)malloc(sizeof(int) * n); //C++ 语言：count = new int[n];
    for (i = 0; i < n; i++) count[i] = 0;
    for (i = 0; i < n - 1; i++)
        for (j = i + 1; j < n; j++)
            if (a[i] < a[j])
                count[j]++;
            else
                count[i]++;
    for (i = 0; i < n; i++)
        b[count[i]] = a[i];
    free(count); // C++ 语言：delete count;
}
```
请回答下列问题。
(1) 若有 int a[] = {25, -10, 25, 10, 11, 19}, b[6]; ，则调用 cmpCountSort(a, b, 6) 后数组 b 中的内容是什么？
(2) 若 a 中含有 n 个元素，则算法执行过程中，元素之间的比较次数是多少？
(3) 该算法是稳定的吗？若是，则阐述理由；否则，修改为稳定排序算法。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握排序算法的基本概念（如稳定性定义、时间复杂度计算基础），但不需要记忆复杂的公式或辨析多个易混的高级概念。属于标准的基础认知需求。
- **K2 = 2**: 评分理由。第(2)问的比较次数计算本质上是双重循环的迭代次数，即 $n(n-1)/2$，这是一个非常标准的数学代入，计算难度低，不易出错。
- **K3 = 4**: 评分理由。第(1)问需要手动模拟算法执行过程，涉及6个元素的两两比较和计数更新，步骤较多（约15次比较和相应的计数更新），且第(3)问需要理解算法逻辑并推导出修改方案，属于多步串行推演，需记忆中间状态（count数组的变化）。
- **K4 = 4**: 评分理由。存在明显的隐含陷阱。第(1)问中，当 $a[i] == a[j]$ 时，代码执行 `else count[i]++`，这意味着相等元素中，下标较小的元素计数增加，导致其在最终数组中的位置靠后（因为 `b[count[i]] = a[i]`，count越大位置越靠后，或者说count代表比它小的元素个数？需仔细推导：若count代表比它小的个数，则count越大越靠后。这里逻辑是：若 $a[i] < a[j]$，$a[j]$ 比 $a[i]$ 大，$count[j]$ 加1；若 $a[i] \ge a[j]$，$count[i]$ 加1。这意味着 $count[k]$ 统计的是有多少个元素 $x$ 满足 $x \le a[k]$ 且 $x$ 在 $a[k]$ 之前？不，仔细看逻辑：$count[j]++$ 当 $a[i] < a[j]$，即 $a[j]$ 大于前面的某个元素；$count[i]++$ 当 $a[i] \ge a[j]$，即 $a[i]$ 大于等于后面的某个元素。最终 $b[count[i]] = a[i]$。这实际上是一个基于“逆序对”或“相对大小”的计数。关键在于相等元素的处理：$a[0]=25, a[2]=25$。当 $i=0, j=2$ 时，$25 < 25$ 为假，执行 `else count[0]++`。这导致 $a[0]$ 的计数增加。这种非直观的逻辑处理是主要的暗坑。
- **K5 = 2**: 评分理由。主要涉及单一的数据结构（数组）和排序逻辑，没有跨越不同的子系统或模块进行复杂的状态传递。

- **雷达形状**: 偏向于“推演与陷阱”型，K3和K4较高，K1和K2较低，K5中等偏低。

## 考察模式
- **模式**: 分析论证型
- **理由**: 题目不仅要求计算结果，更要求分析算法的性质（稳定性）并进行改进，重点在于对算法逻辑的深度理解和论证。

## 解题思路分析
- **核心思路**: 
    1. **模拟执行**：对于第(1)问，严格按照代码逻辑，逐步更新 `count` 数组，最后根据 `count` 值将 `a` 中元素放入 `b`。
    2. **复杂度分析**：对于第(2)问，识别出双重循环结构，直接计算比较次数。
    3. **稳定性判定与修改**：对于第(3)问，通过第(1)问的结果或逻辑分析判断稳定性。若不稳定，需调整相等元素的处理逻辑，确保相等元素的相对顺序不变。

- **关键步骤**:
    1. **第(1)问**：
       - 初始化 `count` 为全0。
       - 遍历 $i$ 从 0 到 4，$j$ 从 $i+1$ 到 5。
       - 比较 $a[i]$ 和 $a[j]$，更新 `count`。
       - 特别注意 $a[0]=25$ 和 $a[2]=25$ 的比较：$i=0, j=2$ 时，$25 < 25$ 为假，`count[0]++`。
       - 最终 `count` 数组决定了 `b` 中的位置。
    2. **第(2)问**：
       - 外层循环 $n-1$ 次，内层循环 $n-1-i$ 次。
       - 总比较次数 = $\sum_{i=0}^{n-2} (n-1-i) = \frac{n(n-1)}{2}$。
    3. **第(3)问**：
       - 观察相等元素 $a[0]$ 和 $a[2]$ 在 `b` 中的位置。
       - 原算法中，相等元素的处理导致相对顺序可能颠倒（或不稳定）。
       - 修改：在比较时，若 $a[i] == a[j]$，应保证下标小的元素排在前面（或后面，取决于计数逻辑）。通常稳定排序要求相等元素保持原相对顺序。原算法中 `else count[i]++` 使得 $a[i]$ 的计数增加，若计数代表“比它小的元素个数”，则计数越大位置越后。需仔细推导原算法 `count` 的物理意义。
       - 实际上，原算法 `count[k]` 统计的是有多少个元素 $a[m]$ 满足：若 $m < k$ 且 $a[m] \ge a[k]$，则 $count[k]$ 不增（因为 $i=m, j=k$ 时 $a[m] \ge a[k]$ 走 else $count[m]++$）；若 $m < k$ 且 $a[m] < a[k]$，则 $count[k]++$。若 $m > k$ 且 $a[k] < a[m]$，则 $count[m]++$；若 $m > k$ 且 $a[k] \ge a[m]$，则 $count[k]++$。
       - 简化理解：`count[i]` 最终等于比 $a[i]$ 小的元素个数 + (某些相等元素的处理)。
       - 修改策略：将 `if (a[i] < a[j])` 改为 `if (a[i] <= a[j])` 或调整 `else` 分支，确保相等元素中，下标小的 `count` 值小（或大，视放置逻辑而定），从而保持相对顺序。

- **易错点**:
    1. **模拟错误**：在手动模拟 `count` 数组更新时，容易搞混 `count[i]` 和 `count[j]` 的更新条件，特别是相等元素的情况。
    2. **稳定性理解偏差**：误以为只要数值正确就是稳定，忽略了相等元素的相对位置。
    3. **修改算法错误**：修改时未彻底解决相等元素的问题，或修改后破坏了排序的正确性。

## 核心陷阱
- **核心陷阱**: **相等元素的处理逻辑**。原算法在 $a[i] == a[j]$ 时执行 `count[i]++`，这会导致相等元素中，下标较小的元素其 `count` 值增加。由于 `b[count[i]] = a[i]`，`count` 值越大，元素在 `b` 中的位置越靠后（假设 `count` 代表排名）。因此，原算法中相等元素的相对顺序会被颠倒（下标小的反而排在后面），导致算法**不稳定**。考生需准确识别这一细节，并在修改时确保相等元素的 `count` 值与其原始下标顺序一致（即下标小的 `count` 小，或下标大的 `count` 大，取决于具体实现，但必须保持单调性以维持稳定性）。
