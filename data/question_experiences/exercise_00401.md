# 练习题 Q1 — 欧几里得算法复杂度分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
在以下 C 函数中，假设 $n \ge m$。
```c
int gcd(n, m) {
    if (n % m == 0) return m;
    n = n % m;
    return gcd(m, n);
}
```
该函数会进行多少次递归调用？

- 选项:
  A: O(log(n))
  B: O(n)
  C: O(log(log(n)))
  D: O(sqrt(n))
- 正确答案: A
- 解析（参考）: 上述代码是用于计算最大公约数（GCD）的欧几里得算法的实现。欧几里得算法的核心思想是：若 $a > b$，则 $gcd(a, b) = gcd(b, a \mod b)$。在最坏情况下，递归次数与斐波那契数列相邻两项的比值有关，其时间复杂度为 $O(\log n)$。因此，选项 A 正确。
- 知识标签: ['数据结构/算法分析']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要识别出代码实现的是“欧几里得算法”（辗转相除法），并回忆该算法的时间复杂度结论。不是2分因为不能仅靠直觉，需要调用特定的算法知识储备；不是4分因为不需要辨析多个易混算法（如更相减损术与辗转相除法的细微区别），核心概念单一。
- **K2 = 1**: 评分理由。本题不涉及具体的数值代入计算，而是询问渐进时间复杂度（Big-O），无需执行算术运算。
- **K3 = 2**: 评分理由。虽然算法本身是递归的，但题目问的是复杂度量级而非具体步数。考生只需知道“最坏情况下的递归深度”这一结论即可，无需手动模拟多步递归过程。若需模拟具体数字的递归过程则K3会升高，但此处考察的是理论界限。
- **K4 = 3**: 评分理由。存在隐含前提：必须意识到题目问的是“最坏情况”或“上界”（Big-O表示法通常指最坏情况或平均情况的上界）。如果考生误以为每次取模都能减半（$n/2$），虽然也是 $O(\log n)$，但推导逻辑不同；如果考生不知道斐波那契数列是最坏情况，可能会在 $O(n)$ 和 $O(\log n)$ 之间犹豫。陷阱在于对“最坏情况”的敏感度。
- **K5 = 1**: 评分理由。本题仅涉及单一算法模块（GCD）的分析，不涉及数据结构与算法之间的交互，也不涉及操作系统、网络等其他领域的知识联动。
- **雷达形状**: K1主导型（概念记忆与识别为主），K4有一定突起（需识别最坏情况隐含条件），整体偏向基础理论考察。

## 考察模式
- **模式**: 概念型
- **理由**: 本题核心在于识别代码对应的经典算法（欧几里得算法），并回忆其已知的理论复杂度结论。虽然代码以C语言形式给出，但解题关键不在于代码执行细节的模拟，而在于对算法性质的认知。

## 选项级分析
- **选项A**: [正确] — 欧几里得算法的时间复杂度为 $O(\log(\min(n, m)))$，由于 $n \ge m$，即 $O(\log m)$，而在最坏情况下（斐波那契数列相邻项），递归次数与输入值的对数成正比。这是标准结论。
- **选项B**: [干扰] — 针对认为算法效率低下的错误认知。这类学生可能混淆了“更相减损术”（每次相减，最坏情况 $O(n)$）与“辗转相除法”（每次取模，效率更高）。或者误以为递归深度可能与数值大小线性相关。
- **选项C**: [干扰] — 针对对对数增长极快有误解的学生。$O(\log \log n)$ 通常出现在二分查找的二分查找（如索引的索引）或某些特定数据结构操作中，GCD算法没有达到如此高的效率。
- **选项D**: [干扰] — 针对对复杂度量级模糊的学生。$\sqrt{n}$ 常见于试除法求素数或某些分解算法，与GCD的取模机制无关。
- **干扰策略**: 概念混淆。主要利用考生对“减法版GCD”和“取模版GCD”效率差异的不熟悉，以及对对数复杂度具体应用场景的模糊记忆。

## 核心陷阱
- **核心陷阱**: 混淆“更相减损术”与“辗转相除法”的复杂度。更相减损术（$gcd(a,b) = gcd(a-b, b)$）在最坏情况下（如 $gcd(n, 1)$）需要 $n-1$ 次递归，复杂度为 $O(n)$；而本题代码使用的是取模运算（$n \% m$），这是辗转相除法，其复杂度为对数级。考生若未仔细区分代码中的 `%` 运算符，极易误选 B。

## 考察能力
本题核心考察考生对经典算法（欧几里得算法）代码实现的识别能力及其时间复杂度理论结论的记忆与理解。
