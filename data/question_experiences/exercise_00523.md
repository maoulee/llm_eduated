## 题干原文
某 CPU 具有 32 KB 直接映射缓存，块大小为 128 字节。假设 A 是一个 512×512 的二维数组，每个元素占用 8 字节。考虑以下两个 C 代码段 P1 和 P2：
// P1:
for (i=0; i<512; i++) {
    for (j=0; j<512; j++) {
        x += A[i][j];
    }
}
// P2:
for (i=0; i<512; i++) {
    for (j=0; j<512; j++) {
        x += A[j][i];
    }
}
P1 和 P2 在相同初始状态下独立执行（即数组 A 不在缓存中，i、j、x 寄存器中）。设 P1 经历的缓存未命中次数为 M1，P2 为 M2。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握直接映射缓存的基本结构（块大小、缓存行数）、空间局部性概念以及C语言二维数组的内存布局（行优先）。不需要辨析多个易混概念，但必须准确理解“直接映射”和“块大小”的定义。
- **K2 = 3**: 评分理由。涉及多级换算：KB到Byte，Byte到元素个数，总元素数到块数。虽然都是2的幂次，但需要计算缓存行数（256）和每块元素数（16），并判断是否发生冲突未命中。计算量适中，但步骤较多。
- **K3 = 4**: 评分理由。推演过程复杂。对于P1，需推演行内访问的空间局部性（1次未命中加载16个元素，后续15次命中）；对于P2，需推演列访问时的地址间隔，判断是否导致缓存行冲突（Conflict Miss）。特别是P2中，由于数组宽度（512*8=4KB）是缓存行数（256行，每行128B，总容量32KB）的倍数关系，需推演是否所有访问都未命中。这里需要多步逻辑判断：地址间隔 -> 映射行号 -> 是否冲突。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。陷阱1：P2是否真的全部未命中？需要验证地址间隔导致的冲突。陷阱2：P1中，当i变化时，新行是否会替换旧行？由于缓存只有256行，而数组有512行，当i从0变到256时，A[0]行会被A[256]行替换。但在P1的内层循环中，我们只关心当前行的访问。关键在于P2的列访问，步长为512*8=4096字节。缓存行索引由地址的低几位决定。需识别出列访问的步长恰好导致每次访问都映射到同一个缓存行（或少数几个行），从而产生严重的冲突未命中。这是典型的“反直觉”或“隐含前提深”的情况，学生容易误以为P2也有空间局部性。
- **K5 = 2**: 评分理由。主要涉及存储子系统内部机制，不涉及CPU流水线、中断等其他子系统的深度耦合。仅提及寄存器，但未涉及寄存器分配策略等复杂联动。

- **雷达形状**: K3/K4 突出型（推理与陷阱主导）

## 考察模式
- **模式**: 综合型
- **理由**: 本题结合了概念理解（缓存结构、数组布局）、计算能力（未命中次数统计）和逻辑推理（冲突未命中的判定）。它不是简单的公式代入，而是需要模拟缓存行为。

## 选项级分析
- **选项A**: [干扰] — 针对认为P1或P2完全命中或完全未命中的极端错误认知。如果学生认为P1完全命中（忽略冷启动和行替换），M1=0，则比值为0。或者认为P2完全命中（错误理解局部性），M2=0，比值无穷大（无此选项）。
- **选项B**: [正确] — 正确计算了P1的空间局部性带来的命中率提升，以及P2的冲突未命中导致的低命中率。M1 = 512*512/16 = 16384 (假设行内连续访问，每16个元素1次未命中，且忽略行间替换对当前行访问的影响，实际上P1中每行访问时，该行数据在缓存中，直到下一行开始。由于缓存行数256 < 数组行数512，当i>=256时，A[i]会替换A[i-256]。但在内层循环j遍历时，A[i]行始终在缓存中，因为内层循环只访问A[i]行。所以P1的未命中次数确实是总元素数/每块元素数 = 262144/16 = 16384。P2中，A[j][i]，j变化，步长为512*8=4096字节。缓存行索引 = (地址 / 128) % 256。地址 = Base + j*4096 + i*8。行索引 = (Base/128 + j*32 + i*8/128) % 256。由于j*32 % 256，当j增加1，行索引增加32。256/32=8，所以每8次j变化，行索引循环一次？不，直接映射缓存，行索引由地址的中间位决定。地址偏移量是4096字节。4096 / 128 = 32个块。缓存有256行。32和256的最大公约数是32。这意味着访问会映射到256/32=8个不同的缓存行？不，让我们仔细算。
  缓存行号 = (Address / BlockSize) % NumLines
  BlockSize = 128 B. NumLines = 256.
  P2访问 A[j][i]. 地址 = Base + j * 512 * 8 + i * 8.
  当i固定，j变化时，地址增量 = 4096 B.
  块增量 = 4096 / 128 = 32.
  行号增量 = 32 % 256 = 32.
  所以，对于固定的i，当j从0到511变化时，访问的缓存行号序列为：H0, H0+32, H0+64, ..., H0+32*511.
  由于模256，行号会在 {H0, H0+32, ..., H0+224} 这8个行之间循环。
  但是，直接映射缓存中，如果多个地址映射到同一行，会发生冲突。
  这里，j=0映射到行R，j=1映射到行R+32，...，j=8映射到行R+256=R。
  所以，每8次访问，就会回到同一个缓存行。
  但是，缓存行中存放的是哪个数据？
  当j=0时，加载A[0][i]到行R。
  当j=1时，加载A[1][i]到行R+32。
  ...
  当j=8时，加载A[8][i]到行R。此时，行R中原有的A[0][i]被替换。
  下一次访问A[0][i]（在下一个i循环？不，P2是外层i，内层j。所以对于固定的i，j从0到511。
  访问序列：A[0][i], A[1][i], ..., A[511][i].
  这些地址映射到8个不同的缓存行。
  每个缓存行被访问512/8 = 64次。
  例如，行R被A[0][i], A[8][i], A[16][i]...访问。
  第一次访问A[0][i]，未命中，加载到行R。
  第二次访问A[8][i]，未命中（因为A[8][i]不在缓存中，且映射到行R，替换A[0][i]）。
  第三次访问A[16][i]，未命中，替换A[8][i]。
  所以，对于P2，每次访问都是未命中！因为步长导致的冲突使得缓存行不断被新数据替换，而旧数据在再次被访问前已被替换。
  因此，M2 = 512 * 512 = 262144。
  M1 = 512 * 512 / 16 = 16384。
  M1/M2 = 16384 / 262144 = 1/16。
  选项B正确。
- **选项C**: [干扰] — 针对计算错误。可能误以为每块元素数是8（块大小128/元素大小16？错，元素大小8），或者误以为缓存行数是128等。或者误以为P2的未命中次数是P1的8倍。
- **选项D**: [干扰] — 针对比值颠倒。学生可能计算的是M2/M1，或者误以为P2比P1快。

- **干扰策略**: 计算陷阱（M1/M2 vs M2/M1）、概念混淆（空间局部性 vs 冲突未命中）

## 核心陷阱
- **核心陷阱**: P2的列访问模式导致的**冲突未命中（Conflict Miss）**。学生容易误以为P2也有某种形式的局部性，或者错误计算冲突频率。关键在于识别出列访问的步长（4KB）与缓存结构（128B块，256行）的关系，导致每次访问都替换掉之前映射到同一行的数据，从而造成100%未命中。同时，P1中虽然缓存行数（256）小于数组行数（512），但由于内层循环连续访问同一行，该行数据在缓存中保持有效直到内层循环结束，因此P1仅受空间局部性影响，未命中率为1/16。
