# 练习题 Q1 — 子网划分与主机地址计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 计算机网络
- **知识点**: 计算机网络/网络层
- **难度**: 待评估

## 题干原文
在子网 200.10.11.144/27 中，可分配给主机的最后一个 IP 地址的第四字节（十进制）是（ ）
- 选项:
  A: 158
  B: 255
  C: 222
  D: 223

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握 CIDR 表示法、子网掩码、网络地址、广播地址及可用主机地址范围等核心概念。属于标准的基础概念记忆，不涉及易混概念的深度辨析。
- **K2 = 3**: 评分理由。涉及十进制转二进制、二进制位运算（确定主机位）、二进制转十进制。虽然 27 位掩码对应的块大小 32 是 2 的幂，但需要手动进行位操作或心算，存在一定计算量，属于标准难度的单步/多步简单计算。
- **K3 = 2**: 评分理由。解题步骤清晰且线性：1. 确定掩码长度；2. 确定块大小或主机位位数；3. 计算广播地址；4. 减去 1 得到最大主机地址。步骤在 3 步以内，逻辑直接，无需复杂的状态记忆或多步串行推演。
- **K4 = 4**: 评分理由。存在明显的“暗坑”。题干问的是“可分配给主机的**最后一个** IP 地址”，而非“广播地址”或“子网掩码对应的最大地址”。许多学生容易计算出广播地址（159）后直接选择，或者混淆“最后一个可用地址”与“子网内最大数值地址”。此外，参考解析中提到的“/31”说法有误（应为/27子网内的地址），但核心陷阱在于区分“广播地址不可用”这一隐含前提。
- **K5 = 1**: 评分理由。本题仅涉及网络层子网划分单一知识点，无需跨越传输层、应用层或其他子系统，无状态传递需求。
- **雷达形状**: K4 陷阱型。基础概念和计算难度适中，但陷阱维度（K4）显著突出，主要考察对“可用主机地址”定义的精确理解。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的 CIDR 前缀长度，通过二进制转换和位运算计算出特定的 IP 地址数值。虽然涉及概念，但最终答案依赖于精确的计算过程。

## 选项级分析
- **选项 A**: [正确] — 144 + 32 - 1 (广播) - 1 (网络号? 不，是广播减1) = 158。正确计算了 /27 子网的广播地址为 159，因此最后一个可用主机地址为 158。
- **选项 B**: [干扰] — 针对完全不懂子网划分，误以为 C 类地址默认掩码或最大值为 255 的学生；或者误将主机位全 1 当作可用地址且计算错误的极端情况。
- **选项 C**: [干扰] — 针对计算错误的学生。例如，可能误将 /27 当作 /26（块大小 64），144+64-1=207（不对）；或者误算二进制位。更可能的错误路径是：误以为主机位有 5 位，最大值 31，144+31=175（也不对）。此选项可能是随机干扰或针对特定错误算法（如误用 /25 或其他掩码）。*注：经复核，若误以为掩码是 /26，广播是 207，最大主机 206。若误以为掩码是 /28，块大小 16，144+16-1=159(广播)，最大主机 158。选项 C 222 可能是针对 /27 误算为其他掩码或完全错误的二进制转换结果。* 实际上，222 是 11011110，与 144 (10010000) 差异较大，可能是针对将网络位和主机位搞反或严重计算失误的学生。
- **选项 D**: [干扰] — 针对混淆“广播地址”与“最大主机地址”的学生。/27 子网，144 起始，块大小 32，范围 144-175。广播地址是 175？不对，144+31=175。等等，让我重新计算一下。
    - 掩码 /27，即 255.255.255.224。
    - 块大小 = 2^(32-27) = 2^5 = 32。
    - 子网起始地址：144 是 32 的倍数吗？32*4=128, 32*5=160。144 在 128-159 之间？不，144/32 = 4.5。
    - 让我们看二进制：144 = 10010000。
    - /27 意味着前 27 位是网络位。第四字节前 3 位是网络位（因为 24+3=27）。
    - 144 的二进制：`100` `10000`。前 3 位 `100` 固定。
    - 该子网的网络地址：`100` `00000` = 128。
    - 该子网的广播地址：`100` `11111` = 128 + 31 = 159。
    - 可用主机范围：129 - 158。
    - 最后一个可用主机地址：158。
    - 选项 D 是 223。223 = 11011111。这看起来像是 /27 掩码的十进制值（255-32+1? 不，255-31=224，掩码是 224）。或者 223 是 11011111，可能是误将掩码值或补码搞混。
    - 修正选项分析：
        - **选项 D (223)**: 可能是针对误将子网掩码的第四字节（224）减 1 或其他错误计算。或者，如果学生错误地认为 /27 的主机位是后 5 位，但起始地址算错。
        - **选项 C (222)**: 类似 D，可能是计算掩码或广播地址时的严重偏差。
        - **更常见的干扰项通常是广播地址 159**。但本题选项中没有 159。
        - 让我们再看一眼选项：A:158, B:255, C:222, D:223。
        - 223 和 222 非常接近 224（掩码值）。可能干扰策略是让学生混淆“掩码值”、“广播地址”和“主机地址”。
        - 或者，如果学生错误地计算子网：比如认为 144 是网络号，掩码 /27，块大小 32，广播 144+31=175。最大主机 174。选项里没有。
        - 如果学生认为 /27 意味着主机位 5 位，最大值 31。144+31=175。
        - 为什么会有 222/223？
        - 224 是 /27 的掩码第四字节。223 是 224-1。222 是 224-2。
        - 可能干扰策略：学生记住了 /27 对应掩码 224，然后随意减 1 或减 2 作为“最大地址”的猜测。

- **干扰策略**: 概念混淆与数值猜测。选项 B 是常识性最大值干扰；选项 C 和 D 接近子网掩码的数值（224），利用学生对掩码数值的记忆进行干扰，诱导未进行实际地址范围计算的学生选择。

## 核心陷阱
- **核心陷阱**: **“可用主机地址”与“广播地址”的区别**，以及**子网起始地址的正确判定**。
    1.  必须识别出 144 所在的 /27 子网范围是 128-159（因为 144 的二进制前 3 位是 100，对应网络位，主机位全 0 是 128，全 1 是 159）。
    2.  必须知道广播地址（159）不可分配给主机。
    3.  因此最后一个可用地址是 158。
    4.  如果误以为 144 是网络号（实际上 128 才是该子网的网络号，144 只是子网内的一个地址），计算结果会完全不同（144+31=175，最大主机 174，无此选项，说明题目设计排除了这种错误，或者学生必须正确识别子网边界）。
    5.  参考解析中提到“网络地址的第四字节为 144”，这是**错误**的表述。144 是子网内的一个 IP，该子网的网络地址是 200.10.11.128。但解析后续计算“前三位固定为 100...剩余位最大...10011110”是正确的逻辑（基于 144 的二进制结构推导该子网的边界）。解析的文字描述有瑕疵，但计算逻辑指向正确。考生需自行纠正“144 是网络地址”这一错误前提，意识到 144 属于 128-159 这个子网。

## 考察能力
本题核心考察考生对 CIDR 子网划分机制的理解，特别是通过二进制位运算确定子网边界、广播地址及可用主机地址范围的精确计算能力。
