# 练习题 Q1 — 进程同步与死锁分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
两个进程 P1 和 P2 需要访问一段代码的临界区。考虑以下同步构造：其中 wants1 和 wants2 是初始化为 false 的共享变量。关于上述结构，以下哪个陈述是正确的？

```c
// P1
while (true) {
    wants1 = true;
    while (wants2 == true);
    /* Critical Section */
    wants1 = false;
}
/* Remainder section */

// P2
while (true) {
    wants2 = true;
    while (wants1 == true);
    /* Critical Section */
    wants2 = false;
}
/* Remainder section */
```

- 选项:
  A: 它不能确保互斥
  B: 它不能确保有限等待
  C: 它要求进程以严格交替的方式进入临界区
  D: 它不能防止死锁，但能确保互斥
- 正确答案: D
- 解析（参考）: 有限等待定义：在某个进程请求进入其临界区后到该请求被满足之前，其他进程进入其临界区的次数存在一个上限。互斥机制分析：互斥用于防止对共享资源的同时访问。通过临界区实现，即进程或线程访问共享资源的代码段。解决方案：两个进程 P1 和 P2 需要访问代码的临界区。此处 wants1 和 wants2 是初始化为 false 的共享变量。互斥验证：当 wants1 和 wants2 同时为 true 时，两个进程都会进入 while 循环并相互等待对方完成，这会导致无限循环从而引发死锁。假设 P1 在临界区（意味着 wants1=true，wants2 可以是 true 或 false...

- 知识标签: ['操作系统/进程管理']
- 知识域: OS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“互斥”、“死锁”、“有限等待”这三个核心概念的定义。不是4分因为不需要辨析多个易混的高级同步算法（如Peterson、Dekker等）的细微差别，只需理解基本逻辑。
- **K2 = 1**: 评分理由。本题不涉及数值计算，仅涉及逻辑状态的判断。
- **K3 = 4**: 评分理由。需要进行多步串行推演。考生必须在脑海中模拟 P1 和 P2 的执行时序，特别是当两者几乎同时执行 `wants = true` 时的状态变化。需要追踪共享变量 `wants1` 和 `wants2` 的状态，并判断 `while` 循环的条件是否满足，步骤超过3步且需记忆中间状态。
- **K4 = 4**: 评分理由。存在隐含前提和反直觉陷阱。常规思维可能认为“只要检查对方标志位就能互斥”，但本题的陷阱在于“同时设置标志位”导致的死锁（Deadlock），而非简单的互斥失败。考生必须意识到“忙等待”在双方都等待对方释放资源时会形成循环等待，这是典型的死锁四条件之一。
- **K5 = 2**: 评分理由。仅在进程管理子系统内部，涉及两个进程间的状态交互，没有跨越内存管理、文件系统等其他子系统。

- **雷达形状**: K3/K4 高推演陷阱型（K1中等，K2极低，K3/K4较高，K5低）

## 考察模式
- **模式**: 推理型
- **理由**: 题目不要求记忆特定算法的代码，而是给出一段伪代码，要求考生通过逻辑推理分析其并发执行时的行为（互斥性、死锁可能性）。重点在于对并发时序和共享状态变化的动态分析。

## 选项级分析
- **选项A**: [干扰] — 针对“互斥失败”的错误认知。这类学生可能认为，如果 P1 和 P2 同时进入临界区，互斥就失败了。但实际上，由于 `while (wants2 == true)` 的存在，如果 P2 已经设置了 `wants2=true`，P1 会被阻塞；反之亦然。除非两者在设置 `wants` 之前都进入了临界区（不可能，因为设置 `wants` 是进入前的第一步），否则不会同时进入。因此互斥是成立的（在不死锁的前提下）。
- **选项B**: [干扰] — 针对“饥饿/有限等待”的混淆。虽然该算法确实不保证有限等待（如果 P2 一直循环，P1 可能永远进不去，但这通常发生在 P2 不退出临界区或快速重入的情况，但在本题的死锁场景下，有限等待的问题被死锁掩盖了）。然而，选项 D 指出了更致命的缺陷（死锁），且 B 选项通常用于描述 Peterson 算法等无死锁但可能饥饿的场景，或者用于描述该算法在非死锁情况下的缺陷。但在单选题中，死锁是更优先的否定性特征。更重要的是，如果发生死锁，进程永远无法进入，这不仅仅是“有限等待”的问题，而是“永远等待”。
- **选项C**: [干扰] — 针对“严格交替”的误解。这类学生可能将本题与“严格交替”算法（如使用 turn 变量）混淆。本题没有 turn 变量，如果 P1 连续两次请求，而 P2 不请求，P1 可以连续进入两次（只要 P2 的 `wants2` 为 false）。因此它不要求严格交替。
- **选项D**: [正确] — 正确识别了算法的两个关键特性：1. 能确保互斥（只要不进入死锁状态，同一时刻只有一个进程能跳过 while 循环）；2. 不能防止死锁（当 P1 和 P2 几乎同时设置 `wants` 为 true 时，双方都在 while 循环中等待对方，形成死锁）。

- **干扰策略**: 概念混淆（将死锁与互斥失败混淆）、渐进陷阱（先让你觉得互斥没问题，再考察死锁这一更深层的并发问题）

## 核心陷阱
- **核心陷阱**: **死锁（Deadlock）的识别**。许多考生能看出该算法能实现互斥（因为进入临界区前必须检查对方标志），但容易忽略当两个进程**同时**将各自的 `wants` 标志设为 `true` 时，会陷入相互等待的无限循环。这是典型的“循环等待”死锁场景。考生需区分“互斥失败”（两个进程同时在临界区）和“死锁”（两个进程都在临界区外等待，谁也进不去）。

## 考察能力
一句话概括本题核心考察的能力：
**在并发环境下，通过分析共享变量的状态变化和进程执行时序，识别同步算法中潜在的互斥保证与死锁风险的能力。**
