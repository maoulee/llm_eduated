# 练习题 Q1 — 银行家算法与安全序列判定

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/死锁
- **难度**: 待评估

## 题干原文
系统共有 9 个某类资源，当前处于安全状态，如下表所示。以下哪个进程执行顺序是安全的？（ ）

- 选项:
  A: (P4, P1, P3, P2)
  B: (P4, P2, P1, P3)
  C: (P4, P2, P3, P1)
  D: (P3, P1, P2, P4)

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握银行家算法的核心概念（Max, Allocation/Used, Need, Available）以及安全序列的定义。属于标准的基础概念记忆，不涉及易混概念的深度辨析，但必须准确理解各矩阵含义。
- **K2 = 3**: 评分理由。涉及简单的加减法运算（计算Need矩阵和Available资源变化）。虽然数值较小，但每一步都需要精确计算剩余资源，非2的幂次友好型计算，属于标准难度的单步代入。
- **K3 = 4**: 评分理由。需要在明确规则下进行多步串行推演。对于每个选项，都需要模拟进程执行、资源释放、再分配的过程。特别是当第一个进程执行后，剩余资源是否满足后续进程的需求，需要记忆中间状态（Available的变化），步骤超过3步且需保持状态一致性。
- **K4 = 3**: 评分理由。存在常规注意点，即“安全序列”的定义是存在*至少一个*序列使得所有进程能完成，而题目要求判断*给定*序列是否安全。陷阱在于学生可能误以为只要第一个进程能运行就是安全的，或者忽略了资源释放后的累积效应。需要识别“当前可用资源”是动态变化的这一隐含前提。
- **K5 = 1**: 评分理由。本题仅涉及操作系统中的死锁预防模块，不涉及内存管理、文件系统或CPU调度等其他子系统的状态传递，属于单系统内部逻辑。
- **雷达形状**: K3推演主导型（K3较高，K1/K2中等，K4有一定陷阱，K5极低）

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非简单的公式代入或概念回忆，而是要求考生根据银行家算法的规则，对给定的进程执行序列进行动态模拟和逻辑验证。考生需要推演资源分配与释放的连锁反应，判断序列的合法性，属于典型的算法逻辑推理。

## 选项级分析
- **选项A**: [干扰] — 针对“只看首项”的错误认知。P4的Need为3，Available为3，P4可以运行。但P4运行后释放4个资源，Available变为3+4-3=4（注意：P4已用1，释放后总可用为原可用3+P4已用1=4？不，银行家算法中，进程运行完释放的是其Max资源，即Available += Allocation。初始Available=3。P4运行需3，满足。P4完成后，Available = 3 - 3 + 4 = 4。此时P1需5，4<5，阻塞。P3需3，4>=3，P3可运行。P3完成后，Available = 4 - 3 + 5 = 6。此时P1需5，6>=5，P1可运行。P1完成后，Available = 6 - 5 + 7 = 8。此时P2需5，8>=5，P2可运行。等等，让我重新仔细计算一下A选项。
    *   初始 Available = 9 - (2+1+2+1) = 3.
    *   Need: P1=5, P2=5, P3=3, P4=3.
    *   序列 A: (P4, P1, P3, P2)
    *   1. 选 P4: Need=3 <= Avail=3. OK. P4 运行结束，释放 Max=4. New Avail = 3 - 3 + 4 = 4.
    *   2. 选 P1: Need=5 > Avail=4. **Fail**. P1 无法运行。
    *   因此 A 错误。学生若未仔细计算第二步，或误以为P4释放后资源足够P1，则会选错。
- **选项B**: [干扰] — 针对“计算失误”或“顺序混淆”。
    *   序列 B: (P4, P2, P1, P3)
    *   1. 选 P4: Need=3 <= Avail=3. OK. New Avail = 4.
    *   2. 选 P2: Need=5 > Avail=4. **Fail**. P2 无法运行。
    *   因此 B 错误。
- **选项C**: [干扰] — 针对“局部最优”误区。
    *   序列 C: (P4, P2, P3, P1)
    *   1. 选 P4: Need=3 <= Avail=3. OK. New Avail = 4.
    *   2. 选 P2: Need=5 > Avail=4. **Fail**. P2 无法运行。
    *   因此 C 错误。
- **选项D**: [正确] — 符合安全序列定义。
    *   序列 D: (P3, P1, P2, P4)
    *   1. 选 P3: Need=3 <= Avail=3. OK. P3 运行结束，释放 Max=5. New Avail = 3 - 3 + 5 = 5.
    *   2. 选 P1: Need=5 <= Avail=5. OK. P1 运行结束，释放 Max=7. New Avail = 5 - 5 + 7 = 7.
    *   3. 选 P2: Need=5 <= Avail=7. OK. P2 运行结束，释放 Max=6. New Avail = 7 - 5 + 6 = 8.
    *   4. 选 P4: Need=3 <= Avail=8. OK. P4 运行结束，释放 Max=4. New Avail = 8 - 3 + 4 = 9.
    *   所有进程均可完成，故 D 正确。
- **干扰策略**: 渐进陷阱。选项A、B、C均以P4开头，因为P4的Need最小（3），最容易通过第一步检查。这诱导学生认为只要第一个能跑，后面大概率也能跑，或者在第二步计算时出现粗心错误（如忘记更新Available）。

## 核心陷阱
- **核心陷阱**: **动态资源更新的遗漏**。许多学生在验证序列时，只检查了第一个进程是否满足条件，或者在计算后续进程的可用资源时，忘记将前一个进程释放的资源（Max值）加回Available中，导致误判后续进程无法满足需求。此外，混淆“Used”和“Max”也是常见错误，需明确进程完成后释放的是Max资源。

## 考察能力
本题核心考察考生对银行家算法中安全序列验证过程的动态模拟能力，以及对资源分配与释放机制的精确计算能力。
