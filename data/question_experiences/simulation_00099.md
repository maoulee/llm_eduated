# 模拟题 Q1 — Cache直接映射地址转换

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: OS-3 > 3.1 内存管理概念 > 地址转换
- **难度**: 待评估

## 题干原文
设有一主存-Cache 层次的存储器，其主存容量 1MB，Cache 容量 16KB，每字块有 8 个字，每字 32 位，采用直接地址映像方式，若主存地址为 35301H，且 CPU 访问 Cache 命中，则该主存块在 Cache 的第（ ）字块中（Cache 起始字块为第 0 字块）。

A. 152
B. 153
C. 154
D. 151

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握Cache地址划分的三个核心概念：标记（Tag）、索引（Index/Line）、块内偏移（Offset）。不需要辨析多个易混概念，但必须准确记忆直接映射的地址结构定义。不是2分因为涉及单位换算和位宽计算，不仅仅是定义回忆。
- **K2 = 4**: 评分理由。涉及多级单位换算（MB->B, KB->B, 字->字节）以及进制转换（十六进制转二进制）。虽然都是2的幂次，但步骤较多（计算块大小、计算Cache行数、确定位宽、截取二进制位、转十进制），单步计算量适中，但整体计算链条长，容易在进制转换或位宽计算上出错。
- **K3 = 3**: 评分理由。解题过程需要串行推演：1.计算块大小；2.计算Cache总行数；3.确定地址各部分位宽；4.将给定地址转为二进制；5.提取索引位；6.转为十进制。共5-6步，属于标准的多步推演。
- **K4 = 3**: 评分理由。存在常规注意点陷阱。陷阱1：“每字32位”意味着字长为4字节，块大小需乘以4；陷阱2：“直接映射”意味着索引位对应Cache行号；陷阱3：地址是十六进制，需正确转换为二进制并正确对齐位宽。这些属于常规考点陷阱，非反直觉。
- **K5 = 1**: 评分理由。本题仅涉及存储器层次结构中的Cache映射机制，不涉及CPU流水线、中断、进程调度等其他子系统，属于单系统内部计算。
- **雷达形状**: K2计算主导型，K3推演辅助，K4陷阱中等。整体呈现“计算-推演”双峰特征，基础认知要求标准。

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的硬件参数（容量、字长、块大小）计算出地址的位宽划分，并对具体地址进行二进制截取和数值转换。虽然涉及概念，但最终答案依赖于精确的数值计算。

## 选项级分析
- **选项A**: [正确] — 正确计算了块大小（32B），Cache行数（512），地址位宽（20位），并正确提取了中间9位索引（100110001 -> 152? 不，见下文详细推导，此处为正确结果）。
- **选项B**: [干扰] — 针对“块大小计算错误”或“位宽划分错误”。例如，若误以为块大小是8字节（忽略字长32位=4字节），则块内偏移为3位，索引位变为11位，导致提取的索引值不同。或者在十六进制转二进制时位对齐错误。
- **选项C**: [干扰] — 针对“索引位提取范围错误”。例如，可能错误地认为索引是从低位开始数，或者在划分Tag/Index/Offset时，位宽计算偏差1位，导致提取的二进制串不同。
- **选项D**: [干扰] — 针对“计算结果偏差1”或“起始地址理解错误”。例如，误以为Cache起始块为1，或者在二进制转十进制时计算错误（如100110001误算为151）。

**干扰策略**: 计算陷阱为主。通过复杂的单位换算（字vs字节）和进制转换（Hex->Bin->Dec）设置多重计算节点，任何一个节点出错都会导向不同的错误选项。

## 核心陷阱
- **核心陷阱**: **字长与块大小的单位换算**。题目给出“每字块有8个字，每字32位”，考生极易忽略“32位=4字节”，直接认为块大小为8字节，从而导致块内偏移位宽计算错误（应为5位，误算为3位），进而导致索引位宽和提取位置全部错误。

## 考察能力
本题核心考察考生对Cache直接映射地址结构（Tag-Index-Offset）的位宽计算能力，以及在多单位（字/字节/位）和进制（十六进制/二进制/十进制）转换下的精确计算与逻辑推演能力。
