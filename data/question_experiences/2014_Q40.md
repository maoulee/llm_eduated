# 2014 Q40 — Web访问协议栈与SMTP排除

## 基本信息
- **年份**: 2014  **题位**: Q40  **题型**: 选择题
- **知识点**: CN-6 > 万维网 WWW > HTTP协议, CN-6 > 电子邮件 > SMTP
- **题位域**: 待标注  **科目**: 计算机网络

## 题干原文
使用浏览器访问某大学 Web 网站主页时，不可能使用到的协议是（ ）。
HTTP
- 选项:
  A: PPP
  B: ARP
  C: UDP
  D: SMTP
- 正确答案: D
- 解析（参考）: 当接入网络时可能会用到
PPP 协议
，A 可能用到；当计算机不知道某主机的 MAC 地址时用 IP 地址查询相应的 MAC 地址时会用到
ARP 协议
，B 可能用到；当访问 Web 网站时，若 DNS 缓冲没有存储相应域名的 IP 地址，用域名査询相应的 IP 地址时要使用
DNS 协议
，而 DNS 是基于 UDP 协议的，所以 C 可能用到；
SMTP
只有使用邮件客户端发送邮件，或是邮件服务器向别的邮件服务器发送邮件时才会用到，单纯的访问 Web 网页不可能用到，选 D。
- 知识标签: ['CN-6 > 万维网 WWW > HTTP协议', 'CN-6 > 电子邮件 > SMTP']
- 知识域: CN-6

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆HTTP、SMTP、PPP、ARP、DNS等基础协议的定义及所属层级。不是4分因为不需要辨析极度易混的概念（如TCP与UDP的细微差别），只需知道SMTP是邮件协议即可排除。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算或单位换算，属于纯概念判断。
- **K3 = 3**: 评分理由。需要构建从“用户点击链接”到“页面显示”的完整网络交互流程推演。步骤包括：物理层接入(PPP) -> 链路层地址解析(ARP) -> 应用层域名解析(DNS/UDP) -> 应用层网页请求(HTTP/TCP)。需要3-5步的逻辑串联才能确认哪些协议“可能”被用到。
- **K4 = 4**: 评分理由。存在显著的隐含前提和陷阱。陷阱在于“不可能”与“可能”的界限，以及DNS对UDP的依赖。许多学生知道HTTP用TCP，但容易忽略DNS查询通常使用UDP，从而误选C。同时，需要意识到PPP是接入层协议，虽然不直接参与Web内容传输，但在“访问”这一整体动作中是基础设施。
- **K5 = 4**: 评分理由。需要跨越多个子系统：数据链路层(PPP/ARP)、网络层/传输层(DNS/UDP)、应用层(HTTP/SMTP)。需要理解不同层级协议在同一个业务场景下的协同工作状态，特别是DNS作为HTTP的前置依赖，其底层协议选择对解题至关重要。
- **雷达形状**: K4陷阱型（高条件路由需求，中等机制推演，低计算需求）

## 考察模式
- **模式**: 综合型
- **理由**: 本题不仅考察单一协议的定义，而是考察在一个完整的网络应用流程（Web浏览）中，各层协议是如何协同工作的。它要求考生具备全局视角，将物理接入、链路寻址、域名解析、应用传输等环节串联起来，判断哪些环节必然或可能发生，从而排除无关协议。

## 选项级分析
- **选项A**: [干扰] — 针对“协议层级隔离”的错误认知。部分学生认为PPP是底层接入协议，与上层的Web浏览无关。实际上，如果用户通过拨号或某些宽带方式接入互联网，PPP是建立连接的基础，因此“可能”用到。
- **选项B**: [干扰] — 针对“ARP作用范围”的模糊认知。学生可能认为ARP只在局域网内有效，或者认为IP地址已知就不需要ARP。实际上，只要涉及以太网通信，且MAC地址缓存未命中，就必须使用ARP，这是Web访问中极大概率发生的事件。
- **选项C**: [干扰] — 针对“DNS底层协议”的记忆偏差。这是最强的干扰项。学生知道HTTP基于TCP，容易惯性思维认为Web访问全程使用TCP，从而忽略DNS查询通常基于UDP。若未复习DNS细节，极易误选C。
- **选项D**: [正确] — 针对“协议功能边界”的清晰认知。SMTP（简单邮件传输协议）专用于电子邮件的发送。Web浏览使用的是HTTP/HTTPS协议。两者功能完全独立，除非网页中嵌入了邮件发送功能且用户主动触发，否则单纯“访问主页”绝不会调用SMTP。
- **干扰策略**: 概念混淆（C选项利用TCP/UDP的常见搭配混淆）与 范围界定（A/B选项利用底层协议与上层应用的距离感制造干扰）

## 核心陷阱
**DNS依赖UDP的隐蔽性**。
考生往往聚焦于HTTP协议本身（基于TCP），而忽略了Web访问的前置步骤——域名解析（DNS）。DNS主要使用UDP协议，这使得UDP在Web访问场景中是“可能”被用到的。若考生未能建立起“Web访问 = DNS解析 + HTTP请求”的完整模型，就会错误地认为UDP不可能被用到，从而误选C。

## 考察能力
具备网络协议栈分层协同的全局视野，并能准确区分不同应用层协议（HTTP vs SMTP）的功能边界及底层依赖关系。
