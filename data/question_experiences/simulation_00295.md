# 模拟题 Q1 — 旋转数组最小值查找

## 基本信息
- **来源**: 模拟题  **题型**: 综合题
- **科目**: 数据结构
- **知识点**: DS-7 > 7.2 顺序查找和折半查找 > 折半查找, DS-7 > 7.2 顺序查找和折半查找 > 折半查找过程
- **难度**: 待评估

## 题干原文
（13 分）将一个数组最开始的若干个元素搬到数组的末尾，称之为数组的旋转。输入一个已排好序数组的一个旋转，求该旋转数组的最小元素。如，数组 {3, 4, 5, 1, 2} 为有序数组 {1, 2, 3, 4, 5} 的一个旋转数组，该数组的最小值为 1。
（1）给出算法的基本设计思想。
（2）根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释。
（3）说明你所设计算法的时间复杂度和空间复杂度。

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“旋转数组”的定义以及“折半查找（二分查找）”的基本概念。虽然不需要记忆复杂的公式，但必须理解旋转数组由两个有序子序列构成这一核心性质，属于标准的基础认知需求。不是4分因为不需要辨析多个易混的高级概念。
- **K2 = 2**: 评分理由。算法中涉及指针移动和中间值计算，计算量极小，主要是逻辑判断而非数值计算。最复杂的单步操作仅为 `mid = low + (high - low) / 2`，属于非常基础的整数运算，不易出错。
- **K3 = 4**: 评分理由。解题过程需要多步串行推演。考生需要在脑海中模拟二分查找的过程，特别是处理 `nums[mid] > nums[high]` 和 `nums[mid] < nums[high]` 两种分支的边界变化，以及循环终止条件 `low == high` 的推导。这不仅仅是套用模板，需要理解每一步缩小搜索范围的逻辑依据，步骤较多且需保持状态一致性。
- **K4 = 5**: 评分理由。本题存在极高的条件路由需求和隐含前提陷阱。
    1. **隐含前提**：常规二分查找比较 `mid` 与目标值，而此处需比较 `mid` 与 `high`（或 `low`），这是反直觉的转换。
    2. **陷阱词/边界**：当 `nums[mid] == nums[high]` 时，无法直接判断最小值在左还是右（例如 `[1, 0, 1, 1, 1]` 和 `[1, 1, 1, 0, 1]`），必须通过 `high--` 来退化处理，这是本题最大的难点和易错点。若忽略此情况，算法在存在重复元素时会失效。
    3. **反直觉**：最小值不一定在中间，且数组并非完全有序，需要识别出“部分有序”的特性来切换查找机制。
- **K5 = 1**: 评分理由。本题仅涉及单一的数据结构（数组）和单一的算法模块（查找），不需要跨越不同子系统或模块传递状态，属于单系统问题。
- **雷达形状**: 呈现明显的“右侧突出”形状。K1、K2、K5较低，K3较高，K4极高。表明本题基础门槛不高，计算简单，但对逻辑推演的严密性和对特殊边界条件（重复元素）的处理能力要求极高。

## 考察模式
- **模式**: 算法设计型
- **理由**: 题目要求考生根据特定问题背景（旋转数组），设计一个高效的查找算法，并用代码实现，同时分析复杂度。这不仅仅是验证已知算法，而是要求对经典算法（二分查找）进行适应性改造（改进的二分查找），符合算法设计型题目的特征。

## 解题思路分析
- **核心思路**: 利用旋转数组“由两个有序子数组组成”且“前一个子数组的所有元素大于等于后一个子数组的所有元素”这一特性，将问题转化为在部分有序数组中查找边界点的问题。采用改进的二分查找法，通过比较中间元素与右边界元素的大小关系，逐步缩小搜索范围，直至找到最小值。
- **关键步骤**:
    1. 初始化指针 `low = 0`, `high = n - 1`。
    2. 循环条件 `low < high`。
    3. 计算 `mid`。
    4. 比较 `nums[mid]` 与 `nums[high]`：
       - 若 `nums[mid] > nums[high]`：说明 `mid` 位于第一个有序子数组，最小值在 `mid` 右侧，`low = mid + 1`。
       - 若 `nums[mid] < nums[high]`：说明 `mid` 位于第二个有序子数组，最小值可能是 `mid` 或在 `mid` 左侧，`high = mid`。
       - 若 `nums[mid] == nums[high]`：无法判断最小值位置，但 `high` 指向的元素不是唯一的最小值候选（或者即使是最小值，`high-1` 处也可能有相同值），故 `high--` 缩小范围。
    5. 循环结束，`low == high`，返回 `nums[low]`。
- **易错点**:
    1. 比较对象错误：习惯性地比较 `nums[mid]` 与 `nums[low]` 或目标值，导致逻辑混乱。
    2. 边界更新错误：在 `nums[mid] < nums[high]` 时，错误地写成 `high = mid - 1`，导致漏掉 `mid` 本身可能是最小值的情况。
    3. 忽略相等情况：未处理 `nums[mid] == nums[high]` 的情况，导致在包含重复元素的旋转数组中陷入死循环或返回错误结果。
    4. 循环终止条件：使用 `low <= high` 可能导致越界或逻辑错误，应使用 `low < high`。

## 核心陷阱
- **核心陷阱**: **重复元素导致的二分失效**。当 `nums[mid] == nums[high]` 时，传统的二分逻辑无法判断最小值在左半部分还是右半部分。例如数组 `[1, 0, 1, 1, 1]` 和 `[1, 1, 1, 0, 1]`，`mid` 指向的值都等于 `high` 指向的值，但最小值位置不同。此时必须采用 `high--` 的策略，虽然这会将最坏时间复杂度退化为 O(n)，但能保证算法的正确性。这是区分普通二分查找与旋转数组查找的关键陷阱。

## 考察能力
本题核心考察考生对**二分查找算法的变体应用能力**，以及在**部分有序数据结构**中处理**边界条件**和**重复元素**的逻辑严密性。
