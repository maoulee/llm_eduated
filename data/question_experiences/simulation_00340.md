# 模拟题 Q综合题 — 文件目录系统FCB分解法性能分析

## 基本信息
- **来源**: 模拟题  **题型**: 综合题
- **科目**: 操作系统
- **知识点**: OS-4 > 4.2 文件系统的实现 > 文件目录系统, OS-4 > 4.2 文件系统的实现 > 目录实现
- **难度**: 待评估

## 题干原文
（7 分）在实现文件系统时，为加快文件目录的检索速度，可利用“文件控制块分解法”。假设目录文件存放在磁盘上，每个盘块有 512 字节。文件控制块占 64 字节，其中文件名占 8 个字节。通常将文件控制块分解成两部分，第一部分占 16 字节（包括文件名和文件内部号），第二部分占 48 字节（包括文件内部号和文件其他描述信息）。
（1）假设某一目录文件共有 254 个文件控制块，试分别给出采用分解法前和分解法后，查找该目录文件的某一个文件控制块的平均访问磁盘次数。（访问每个文件的概率相同）
（2）一般地，若目录文件分解前占用 $n$ 个盘块，分解后改用 $m$ 个盘块存放文件名和文件内部号部分，请给出访问磁盘次数减少的条件。（假设 $m$ 和 $n$ 个盘块中都正好装满）

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握“文件控制块（FCB）”、“盘块大小”、“FCB分解法”等核心概念。不是4分因为不需要辨析多个易混概念，只需理解FCB分解的基本原理（将索引信息与属性信息分离）。
- **K2 = 4**: 评分理由。涉及非2的幂次除法（512/64=8, 512/16=32）以及加权平均值的计算。特别是第(1)问中，最后一块未满的情况需要单独处理，计算量较大且容易出错；第(2)问涉及代数推导。
- **K3 = 4**: 评分理由。解题过程包含多个串行步骤：1. 计算每块容纳FCB数量；2. 计算总盘块数及分布；3. 建立概率模型计算平均访问次数；4. 对比两种情况。步骤超过3步，且中间状态（如最后一块的FCB数量）需准确记忆和传递。
- **K4 = 4**: 评分理由。存在隐含前提和陷阱。1. “平均访问磁盘次数”在顺序查找下，不仅取决于块数，还取决于目标在块内的位置分布（虽然本题简化为块级别平均，但需意识到是顺序扫描）；2. 第(1)问中254个FCB不能整除每块容量，必须处理“最后一块未满”的边界条件，这是最大的暗坑；3. 第(2)问中“正好装满”的假设简化了问题，但若忽略分解后查找逻辑的变化（先查第一部分，再查第二部分），容易推导错误。
- **K5 = 2**: 评分理由。主要局限于文件系统内部的数据结构优化，不涉及内存管理、进程调度等其他子系统的深度耦合。仅提及磁盘存储，属于单系统内的逻辑优化。
- **雷达形状**: 偏向计算与推演型，K2和K3较高，K4因边界条件陷阱也较高，K1和K5相对较低。整体呈“中间高、两头低”的纺锤形或菱形。

## 考察模式
- **模式**: 计算推导型
- **理由**: 题目核心在于通过具体的数值计算（第1问）和代数不等式推导（第2问）来量化评估一种文件系统优化策略（FCB分解）的效果。重点考察对数据结构存储效率与I/O开销之间关系的数学建模能力。

## 解题思路分析
- **核心思路**: 
    1. **分解前**：计算每个盘块能存放的FCB数量，确定总盘块数。由于是顺序查找，平均访问次数等于所有可能位置的访问次数之和除以总FCB数。注意最后一块可能未满。
    2. **分解后**：FCB分为两部分。查找过程变为两步：先在“第一部分目录”中查找文件名和内部号，找到后再去“第二部分目录”中查找完整FCB。平均访问次数 = 查找第一部分的平均次数 + 查找第二部分的平均次数（通常假设找到第一部分后，第二部分也在同一块或相邻块，或者题目隐含第二部分也是顺序存储且通过内部号定位，但根据经典FCB分解法，通常第一部分构成索引，第二部分构成数据。若题目未明确第二部分如何组织，通常假设第一部分查找成功后，仍需访问一次磁盘读取第二部分，或者第二部分也按顺序存储。*注：根据参考答案逻辑，分解后的平均次数计算较为复杂，通常假设第一部分查找平均次数为 $L_1$，找到后需再访问一次磁盘读取第二部分，或者第二部分也分散存储。但观察参考答案 $695/127 \approx 5.47$，而分解前 $2080/127 \approx 16.37$。让我们重新审视参考答案的逻辑。*
    
    *修正思路以匹配参考答案*：
    参考答案中分解后平均次数为 $695/127$。
    分解前：254个FCB，每块8个。31块满，第32块6个。
    平均次数 = $\frac{1}{254} [ \sum_{i=1}^{31} 8 \times i + 6 \times 32 ] = \frac{1}{254} [ 8 \times \frac{31 \times 32}{2} + 192 ] = \frac{1}{254} [ 3968 + 192 ] = \frac{4160}{254} = \frac{2080}{127}$。正确。
    
    分解后：
    第一部分（16字节）：每块 $512/16=32$ 个。254个第一部分需 $\lceil 254/32 \rceil = 8$ 块。
    前7块满（每块32个），第8块 $254 - 7 \times 32 = 254 - 224 = 30$ 个。
    查找第一部分的平均次数 $E_1 = \frac{1}{254} [ \sum_{i=1}^{7} 32 \times i + 30 \times 8 ] = \frac{1}{254} [ 32 \times \frac{7 \times 8}{2} + 240 ] = \frac{1}{254} [ 32 \times 28 + 240 ] = \frac{1}{254} [ 896 + 240 ] = \frac{1136}{254} = \frac{568}{127}$。
    
    第二部分（48字节）：每块 $512/48 \approx 10.66$，即每块10个。
    254个第二部分需 $\lceil 254/10 \rceil = 26$ 块。
    前25块满（每块10个），第26块 $254 - 250 = 4$ 个。
    
    *关键点*：FCB分解法的查找逻辑是：先在第一部分目录中顺序查找文件名，找到对应的“文件内部号”。然后，利用“文件内部号”去第二部分目录中查找完整的FCB。
    如果第二部分目录也是顺序存储的，那么找到内部号后，还需要在第二部分目录中顺序查找该内部号对应的FCB。
    但是，通常FCB分解法中，第一部分和第二部分是通过“文件内部号”关联的。如果第二部分也是顺序存储，那么查找第二部分的平均次数取决于第二部分目录的大小。
    
    让我们看参考答案的数值：$695/127 \approx 5.47$。
    刚才算出 $E_1 = 568/127 \approx 4.47$。
    如果总次数是 $E_1 + E_2$，那么 $E_2$ 应该是 $127/127 = 1$？这意味着找到第一部分后，只需要再访问1次磁盘？
    这通常意味着：第二部分目录被组织成可以直接通过内部号定位，或者题目隐含假设“找到第一部分后，直接读取包含该FCB第二部分的盘块”。但在顺序查找的假设下，这不太合理，除非第二部分非常小或者有特殊索引。
    
    *另一种常见的FCB分解法解释*：
    有些教材认为，分解后，第一部分构成一个独立的目录文件，第二部分构成另一个。查找时，先读第一部分目录找到内部号，再读第二部分目录。
    如果参考答案是 $695/127$，而 $E_1 = 568/127$，差值是 $127/127 = 1$。
    这暗示：**查找第二部分的平均磁盘访问次数为1次**。
    为什么是1次？可能是因为题目假设第二部分目录中，每个盘块存放的FCB数量较多，或者更可能的是：**题目隐含假设在找到内部号后，可以直接定位到第二部分所在的盘块（例如通过内部号计算偏移，或者第二部分目录很小只需读一次？）** 
    不，更合理的解释是：在经典的FCB分解法题目中，有时假设第二部分目录也是顺序查找，但可能题目中的“平均访问磁盘次数”定义不同，或者参考答案有特定的简化假设。
    
    *重新检查计算*：
    如果第二部分也是顺序查找：
    第二部分每块10个FCB。254个FCB占26块。
    $E_2 = \frac{1}{254} [ \sum_{j=1}^{25} 10 \times j + 4 \times 26 ] = \frac{1}{254} [ 10 \times \frac{25 \times 26}{2} + 104 ] = \frac{1}{254} [ 3250 + 104 ] = \frac{3354}{254} = \frac{1677}{127} \approx 13.2$。
    总次数 $E_1 + E_2 = \frac{568 + 1677}{127} = \frac{2245}{127} \approx 17.6$。这比分解前还慢！显然不对。
    
    *必须匹配参考答案的逻辑*：
    参考答案分解后平均次数 $695/127$。
    $695/127 = 5.47$。
    $E_1 = 568/127 = 4.47$。
    差值 $1$。
    这说明：**在找到第一部分后，只需要再访问1次磁盘即可获取完整FCB。**
    这通常发生在：**第二部分目录中，每个盘块存放的FCB数量足够多，或者通过内部号可以直接计算出第二部分所在的盘块号（即第二部分也是按内部号排序或哈希，或者题目假设第二部分查找开销忽略不计/固定为1）**。
    但在408考研语境下，更常见的解释是：**FCB分解法中，第一部分目录用于快速定位，第二部分目录通常假设可以通过内部号直接寻址（Direct Addressing）或者题目简化模型认为找到索引后只需一次I/O读取数据块**。
    或者，还有一种可能：**题目中的“分解后”指的是将FCB拆开后，第一部分和第二部分分别存储，但查找时，一旦在第一部分找到内部号，就认为已经“找到”了文件，后续的读取是文件内容读取而非目录检索？不，题目问的是“查找该目录文件的某一个文件控制块”**。
    
    *最可能的408标准解法逻辑*：
    很多老题或模拟题中，对于FCB分解法，假设**第二部分目录也是顺序存储，但查找第二部分的平均次数被简化处理**，或者**题目隐含第一部分查找成功后，第二部分所在的盘块可以通过内部号直接计算得出（即第二部分目录是连续分配且按内部号顺序存放，内部号即索引）**。如果内部号是连续的0,1,2...，那么知道内部号 $k$，就可以直接计算它在第二部分目录中的盘块号，从而只需1次磁盘访问读取该盘块。
    **结论**：解题时需识别出“找到内部号后，可直接定位第二部分盘块，故第二部分访问次数为1”这一隐含条件。
