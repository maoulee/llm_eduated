# 练习题 Q1 — 直接映射缓存地址映射计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 计算机组成原理/存储系统
- **难度**: 待评估

## 题干原文
考虑一个具有 64 个块且块大小为 16 字节的直接映射缓存。字节地址 1206 会映射到哪个块号（ ）？

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆直接映射缓存的核心公式（Cache Index = (Memory Block Number) % Cache Size）以及块大小与字节地址的关系。属于标准的核心定义记忆，不涉及易混概念的深度辨析。
- **K2 = 3**: 评分理由。涉及整数除法（1206/16）和取模运算（75%64）。虽然数字较小，但1206不是16的倍数，需要进行非整除的除法计算，且结果需进一步取模，属于标准的单步代入计算，存在轻微的计算出错风险。
- **K3 = 2**: 评分理由。解题逻辑清晰，分为两步：先求内存块号，再求缓存行号。步骤明确，无需多步串行推演或记忆中间复杂状态，属于较低难度的机制推演。
- **K4 = 2**: 评分理由。题目条件明确（直接映射、64块、16字节块大小），没有明显的隐含前提或反直觉陷阱。唯一的“注意点”是区分“内存块号”和“缓存块号”，这是常规考点，不属于深层陷阱。
- **K5 = 1**: 评分理由。本题仅涉及存储系统内部的缓存映射机制，不需要跨越CPU、I/O或其他子系统传递状态，属于单系统内部计算。
- **雷达形状**: K2计算型（K1和K2略高，K3-K5较低，整体偏向基础计算）

## 考察模式
- **模式**: 计算型
- **理由**: 题目核心在于通过给定的参数（地址、块大小、缓存容量）应用固定公式进行数值计算，而非概念辨析或复杂逻辑推理。

## 选项级分析
- **选项A**: [干扰] — 针对“地址越界”或“映射失败”的错误认知。学生可能误以为地址必须小于缓存总容量（64*16=1024）才能映射，或者认为1206超出了某种范围。实际上缓存通过映射函数可以访问任意内存地址。
- **选项B**: [干扰] — 针对“直接取模”的错误认知。学生可能直接用字节地址对缓存块数取模：1206 % 64 = 6。这是忽略了“块大小”这一关键因素，未先将地址转换为块号。
- **选项C**: [正确] — 正确执行了“地址/块大小”得到内存块号75，再“75%64”得到缓存行号11。
- **选项D**: [干扰] — 针对“计算错误”或“混淆位偏移”的错误认知。可能是计算 1206 / 16 时出错，或者误用了其他进制转换逻辑。例如，若误算 1206/16 ≈ 75.375，取整错误或其他算术失误可能导致此结果；或者混淆了Tag和Index的计算。
- **干扰策略**: 概念混淆（选项B，忽略块大小直接取模）与计算陷阱（选项D，算术错误）相结合。

## 核心陷阱
- **核心陷阱**: 忽略“块大小”导致的直接取模错误。许多学生容易记住“取模”这个动作，但忘记取模的对象是“内存块号”而非“字节地址”。即错误地使用 `Address % Cache_Size` 而不是 `(Address / Block_Size) % Cache_Size`。

## 考察能力
一句话概括本题核心考察的能力：掌握直接映射缓存中，从物理字节地址到缓存行号（Index）的映射计算逻辑及公式应用。
