# 模拟题 Q1 — 递归函数执行流程与嵌套调用

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 数据结构/程序设计基础
- **知识点**: 递归函数的执行机制、嵌套函数调用、三元运算符
- **难度**: 中等

## 题干原文
执行完下列语句段后，i 值为（ ）。
```c
int f(int x) {
    return ((x > 0) ? x * f(x - 1) : 2);
}
int i;
i = f(f(1));
```
- 选项:
  A: 2
  B: 4
  C: 8
  D: 无限递归
- 正确答案: B

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握递归函数的基本概念（基准情况与递归步骤）以及C语言中三元运算符的语法。不是1分因为不能仅靠直觉，需理解代码逻辑；不是4分因为不涉及复杂的数据结构或算法概念辨析。
- **K2 = 2**: 评分理由。计算过程涉及简单的整数乘法（1*2, 2*2），数值极小，属于“2的幂友好”或极小整数运算，几乎不可能出现计算错误。
- **K3 = 3**: 评分理由。从输入到输出需要多步串行推演：先计算内层 `f(1)` -> `f(0)` 得到2，再计算外层 `f(2)` -> `f(1)` -> `f(0)` 得到4。总共涉及4次函数调用和2次乘法运算，步骤在3-5步之间，符合标准推演难度。
- **K4 = 2**: 评分理由。存在常规注意点，即必须理解嵌套调用 `f(f(1))` 的执行顺序（先内后外）。没有深层隐含前提或反直觉陷阱，只要遵循函数调用规则即可避开。
- **K5 = 1**: 评分理由。单系统内部逻辑，不涉及不同子系统间的数据传递或状态耦合，纯粹是单一函数内部的递归逻辑。
- **雷达形状**: K3推演主导型。K1和K3处于中等水平，K2和K5较低，K4略低，整体呈现以逻辑推演为核心的特征。

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非直接考察某个静态概念的定义，也不是复杂的数值计算，而是要求考生模拟计算机执行代码的过程，通过逻辑推理追踪函数调用的栈帧变化和返回值传递，属于典型的程序执行流程推理。

## 选项级分析
- **选项A**: [干扰] — 针对只计算了内层 `f(1)` 就停止，或者误以为外层 `f` 只是简单返回内层结果的学生。这类学生可能忽略了外层 `f` 也需要根据参数重新执行递归逻辑。
- **选项B**: [正确] — 正确执行了 `f(1)=2`，进而计算 `f(2)=2*f(1)=2*2=4`。
- **选项C**: [干扰] — 针对错误理解递归基准情况的学生。例如，误以为 `f(0)` 返回 1（阶乘常见误区），导致 `f(1)=1`, `f(2)=2*1=2` (不对，若f(0)=1则f(1)=1, f(2)=2*1=2，此选项逻辑较难直接对应常见错误，更可能是误算 `f(2) = 2 * f(1)` 时，将 `f(1)` 误算为 4，或者误以为 `f(x)` 是 `x! * 2` 且算错了阶乘值。另一种可能是误以为 `f(1)` 返回 1，然后 `f(1)` 在外层被当作 1 传入，但外层是 `f(2)`。最可能的错误路径是：误以为 `f(0)` 返回 1，则 `f(1)=1`，`f(2)=2*1=2` (选A)；或者误以为 `f(x)` 是 `x * (x-1) * ... * 2`，即 `f(2) = 2 * 1 * 2 = 4` (正确)。若选C，可能是误以为 `f(1)` 返回 2，然后外层 `f(2)` 计算时，错误地认为 `f(1)` 在第二次调用时值变了，或者简单地将 `2 * 2 * 2` 算作 8（多乘了一次）。
- **选项D**: [干扰] — 针对未识别出递归终止条件（`x <= 0` 时返回 2）的学生。这类学生可能认为 `x` 会一直减下去直到溢出，或者误以为 `x=0` 时还会继续调用 `f(-1)`。

- **干扰策略**: 概念混淆（递归终止条件）、计算陷阱（嵌套调用顺序）、渐进陷阱（只算一半）。

## 核心陷阱
- **核心陷阱**: 嵌套递归调用的执行顺序与状态隔离。考生容易混淆内层 `f(1)` 的计算结果与外层 `f(2)` 中再次调用 `f(1)` 的关系，或者未能正确识别 `x=0` 时的基准返回值是 2 而非 1 或 0。

## 考察能力
本题核心考察考生对递归函数执行流程的模拟能力，特别是嵌套调用时的参数传递与返回值处理逻辑。
