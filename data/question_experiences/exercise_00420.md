# 练习题 Q1 — 递归函数执行与阶乘计算

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
当以下递归函数被调用时，n=5 的输出是什么？（ ）
```c
int foo(int n) {
    if (n == 0) return 1;
    else return n * foo(n - 1);
}
```
- 选项:
  A: 1
  B: 5
  C: 120
  D: 720
- 正确答案: C
- 解析（参考）: 给定的递归函数计算非负整数 n 的阶乘。当函数以 n=5 调用时，函数会检查 n 是否等于 0。由于 n 不等于零，它返回 n 乘以将 n-1 作为输入调用相同函数的值。递归调用会持续进行直到达到基准情况（n==0）。foo(5) 的计算过程如下：
foo(5) = 5 * foo(4)
foo(4) = 4 * foo(3)
foo(3) = 3 * foo(2)
foo(2) = 2 * foo(1)
foo(1) = 1 * foo(0)
foo(0) = 1
逐步代入计算：
将 foo(0)=1 代入 foo(1): foo(1) = 1 * 1 = 1
将 foo(1)=1 代入 foo(2): foo(2) = 2 * 1 = 2
...
最终 foo(5) = 120。

- 知识标签: ['数据结构/算法分析']
- 知识域: DS-1

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要识别代码结构为标准的递归阶乘实现。不是1分因为不能仅凭直觉猜测，需理解 `if-else` 分支和递归调用的基本语义；不是4分因为不涉及复杂概念辨析，是数据结构/算法中最基础的递归模型。
- **K2 = 3**: 评分理由。涉及多级乘法运算（5*4*3*2*1）。不是2分因为不是简单的2的幂或单次运算，容易在手动计算时出错；不是4分因为数值较小，无需复杂换算或高精度计算。
- **K3 = 3**: 评分理由。从输入 n=5 到输出结果，需要经历 5 层递归展开和 5 层回溯计算。符合“3-5步”的标准推演难度。若 n 更大则难度上升，但 n=5 处于标准区间。
- **K4 = 2**: 评分理由。存在常规注意点，即递归终止条件 `n==0` 返回 1 而非 0。若误认为返回 0 则结果为 0（无此选项），或误认为 `n==1` 终止则逻辑不同。属于常规递归陷阱，非深层隐含前提。
- **K5 = 1**: 评分理由。单系统内部逻辑，不涉及不同子系统间的数据传递或状态耦合。

- **雷达形状**: K3/K2 主导型（推演与计算并重，基础认知适中）

## 考察模式
- **模式**: 计算型
- **理由**: 虽然涉及递归逻辑（推理），但最终落脚点在于通过模拟执行过程得出具体数值结果。考生必须实际执行或心算递归展开后的乘法序列，而非仅判断算法复杂度或正确性。

## 选项级分析
- **选项A**: [干扰] — 针对“递归终止条件误解”或“完全未执行递归”的错误认知。这类学生可能只看到了 `return 1` 或认为递归最终都归约为 1，忽略了累乘过程。
- **选项B**: [干扰] — 针对“忽略递归累乘，仅返回输入值”的错误认知。这类学生可能误以为函数只是返回 n，或者只执行了一次 `n * foo(n-1)` 但未深入展开，或者混淆了阶乘与恒等函数。
- **选项C**: [正确] — 正确执行递归逻辑：$5! = 5 \times 4 \times 3 \times 2 \times 1 = 120$。
- **选项D**: [干扰] — 针对“多乘一次”或“起始值错误”的计算陷阱。这类学生可能误算为 $6! = 720$，或者在回溯时错误地将某一步的结果加倍，属于典型计算失误干扰项。

- **干扰策略**: 计算陷阱（D选项）与概念简化（A、B选项）结合

## 核心陷阱
- **核心陷阱**: 递归展开层数与回溯累乘的对应关系。考生容易在手动模拟时漏乘某一项，或错误地认为递归深度直接等于结果（如选B），或混淆阶乘定义（如选D）。

## 考察能力
一句话概括本题核心考察的能力：对递归函数执行流程的模拟能力及基本算术运算的准确性。
