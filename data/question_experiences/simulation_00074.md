# 模拟题 Q1 — I/O中断产生时机

## 基本信息
- **来源**: 模拟题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: OS-5 > 5.1 I/O管理概述 > I/O中断
- **难度**: 待评估

## 题干原文
I/O 中断是 CPU 与通道协调工作的一种手段，所以在（ ）时，便要产生中断。

A. CPU 执行“启动 I/O”指令而被通道拒绝接收
B. 通道接收了 CPU 的启动请求
C. 通道完成了通道程序的执行
D. 通道在执行通道程序的过程中

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要记忆“通道完成执行后向CPU发送中断”这一核心定义。不是2分因为仅靠常识无法判断，必须掌握通道与CPU交互的具体协议；不是4分因为不需要辨析多个易混的复杂概念，只需识别标准流程。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算或单位换算，属于纯概念理解。
- **K3 = 2**: 评分理由。推演步骤较少：1. 通道接收启动指令；2. 通道独立执行I/O操作；3. 执行完毕，发送中断。这是一个标准的线性流程，无需多步复杂逻辑推导。
- **K4 = 3**: 评分理由。存在常规注意点陷阱。学生容易混淆“启动时”和“完成时”的中断需求，或者误以为“执行过程中”随时中断。需要识别“协调工作”隐含的“异步通知完成”这一前提，避开“接收请求即中断”的直觉错误。
- **K5 = 3**: 评分理由。涉及CPU与通道（I/O子系统）两个模块间的状态传递。CPU发出启动命令，通道执行，完成后通过中断信号将状态传回CPU，属于典型的单向数据/状态传递场景。
- **雷达形状**: K1-K5分布呈现“概念主导型”，K1和K4略高，K2极低，K3和K5中等。整体偏向基础概念辨析与机制理解。

## 考察模式
- **模式**: 概念型
- **理由**: 题目直接考察操作系统中I/O管理的基本工作机制，特别是通道模式下中断产生的具体时机，不涉及计算或复杂推理，主要依赖对教材核心概念的准确记忆和理解。

## 选项级分析
- **选项A**: [干扰] — 针对“异常处理”认知。这类学生可能认为任何非正常状态（如拒绝）都需要立即通知CPU，虽然异常中断确实存在，但题干强调的是“协调工作”的常规手段，且“拒绝接收”通常发生在启动阶段，并非通道执行后的标准协调点。
- **选项B**: [干扰] — 针对“握手确认”认知。这类学生可能将“接收请求”误解为需要立即中断CPU以确认接收。实际上，通道接收启动指令后是独立执行，无需立即中断CPU，否则就失去了通道减轻CPU负担的意义。
- **选项C**: [正确] — 符合通道工作标准流程。通道独立执行完通道程序后，必须通过中断通知CPU操作结束，以便CPU进行后续处理（如唤醒等待进程、检查状态等），这是CPU与通道协调的核心环节。
- **选项D**: [干扰] — 针对“过程监控”认知。这类学生可能认为CPU需要实时监控通道执行过程。实际上，通道执行过程中是独立的，除非发生错误等特殊情况，否则不会在“执行过程中”随意产生中断，否则会造成频繁的中断开销，违背I/O优化的初衷。
- **干扰策略**: 概念混淆。利用“启动”、“接收”、“执行中”、“完成”四个不同阶段，混淆中断产生的必要性和时机，考察学生对“异步I/O”和“中断开销”平衡点的理解。

## 核心陷阱
- **核心陷阱**: 混淆“启动I/O”与“完成I/O”的中断需求。学生容易误以为通道接收请求（选项B）或开始执行（选项D）时需要中断CPU进行确认或同步，忽略了通道设计的初衷是让CPU在I/O操作期间去执行其他任务，仅在操作**完成**或**出错**时才通过中断进行协调。

## 考察能力
一句话概括本题核心考察的能力：准确理解通道模式下CPU与I/O设备异步工作时的中断触发时机及协调机制。
