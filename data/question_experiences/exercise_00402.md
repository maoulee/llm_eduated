# 练习题 Q1 — 嵌套循环时间复杂度分析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 数据结构
- **知识点**: 数据结构/算法分析
- **难度**: 待评估

## 题干原文
考虑以下函数：
```c
int unknown(int n) {
    int i, j, k = 0;
    for (i = n / 2; i <= n; i++)
        for (j = 2; j <= n; j = j * 2)
            k = k + n / 2;
    return k;
}
```
该函数的时间复杂度是多少？（ ）
- 选项:
  A: O(n^2)
  B: O(n log n)
  C: O(n^3)
  D: O(n^3 log n)

## K1-K5 评分与解析
- **K1 = 3**: 评分理由。需要掌握大O表示法的定义以及基本循环结构（线性增长、指数增长）对应的复杂度概念。不是2分因为仅靠直觉无法准确区分 $n$ 和 $\log n$ 的层级，需要调用“对数级循环”这一核心定义。
- **K2 = 2**: 评分理由。计算过程非常标准且友好。外层循环次数为 $n/2$，内层循环次数为 $\log_2 n$，均为2的幂或线性关系，不涉及复杂的数学推导或多级换算，不易算错。
- **K3 = 2**: 评分理由。推演步骤清晰且简短。第一步分析外层循环，第二步分析内层循环，第三步相乘。总共只需2-3步逻辑串联，无需记忆中间状态或进行长链条推演。
- **K4 = 2**: 评分理由。存在常规注意点，即外层循环起始点为 $n/2$ 而非 $0$，但这不影响量级判断（$\Theta(n)$）。没有深层隐含前提或反直觉陷阱，属于常规考点。
- **K5 = 1**: 评分理由。单系统问题。仅涉及单一代码片段的时间复杂度分析，无需跨越不同数据结构或算法模块传递状态。
- **雷达形状**: 均衡偏基础型（K1-K3为主，无明显短板或极高难点，属于标准的基础计算题）

## 考察模式
- **模式**: 计算型
- **理由**: 本题核心在于通过数学计算确定循环执行次数，进而得出渐近时间复杂度。虽然涉及概念，但最终落脚点在于具体的次数乘积计算。

## 选项级分析
- **选项A**: [干扰] — 针对错误认知：认为内层循环也是线性增长 $O(n)$。这类学生可能忽略了 `j = j * 2` 的指数增长特性，误以为内层循环执行 $n$ 次，导致计算为 $n \times n = n^2$。
- **选项B**: [正确] — 正确推导：外层循环执行 $n/2$ 次（$O(n)$），内层循环执行 $\log_2 n$ 次（$O(\log n)$），总复杂度为 $O(n \log n)$。
- **选项C**: [干扰] — 针对错误认知：严重高估复杂度。可能将内层循环误判为 $O(n^2)$ 或对外层循环有误解，或者纯粹猜测高阶多项式。
- **选项D**: [干扰] — 针对错误认知：混淆了多项式与对数的组合。可能误以为内层循环是 $O(n^2 \log n)$ 或其他复杂组合，属于对复杂度层级缺乏直观感知的学生所选。
- **干扰策略**: 概念混淆（线性 vs 对数）与计算陷阱（忽略系数或起始点导致的量级误判）

## 核心陷阱
- **核心陷阱**: 内层循环变量 `j` 的更新方式 `j = j * 2`。考生容易将其误判为线性递增（如 `j++`），从而将 $O(\log n)$ 误算为 $O(n)$，导致最终结果错误地选为 $O(n^2)$。此外，外层循环从 `n/2` 开始，部分考生可能纠结于常数系数，但大O表示法忽略常数，需明确其量级仍为 $O(n)$。

## 考察能力
准确识别不同循环结构（线性、对数）的执行次数，并能正确组合嵌套循环的时间复杂度。
