# 练习题 Q1 — 进程同步三要素辨析

## 基本信息
- **来源**: 练习题  **题型**: 选择题
- **科目**: 操作系统
- **知识点**: 操作系统/进程管理
- **难度**: 待评估

## 题干原文
考虑以下两个进程的同步解决方案。
进程 0
进入：循环 while (turn == 1);
（临界区）
退出：turn = 1;
进程 1
进入：循环 while (turn == 0);
（临界区）
退出：turn = 0;
共享变量
turn
初始化为零。以下哪一项是正确的？（ ）
- 选项:
  A: 这是一个正确的双进程同步解决方案。
  B: 该方案违反了互斥要求。
  C: 该方案违反了进展要求。
  D: 该方案违反了有限等待要求。

## K1-K5 评分与解析
- **K1 = 4**: 评分理由。本题高度依赖对“进程同步三大必要条件”（互斥、进展、有限等待）的精确定义记忆。若考生仅模糊记得“同步”概念，无法区分这三个术语的具体含义，极易误判。需要辨析“进展（Progress）”与“有限等待（Bounded Waiting）”这两个易混概念，属于较高认知需求。
- **K2 = 1**: 评分理由。本题不涉及任何数值计算、幂次运算或单位换算，完全属于逻辑判断，计算需求微弱。
- **K3 = 3**: 评分理由。解题过程需要多步串行推演：1. 识别算法结构（Peterson算法的简化版/交替法）；2. 模拟初始状态（turn=0）；3. 假设P1想进入但P0不运行的场景；4. 判断P1是否被阻塞；5. 对照“进展”定义得出结论。步骤在3-5步之间，属于标准推演难度。
- **K4 = 4**: 评分理由。存在显著的隐含前提和反直觉陷阱。题面未明确说明“P0可能永远不运行”，但这是判断“进展”问题的关键隐含条件。此外，许多学生会直觉认为“轮流执行”就是公平的，从而忽略“单方面意愿被另一方状态绑架”这一深层逻辑陷阱，属于隐含前提较深的情况。
- **K5 = 1**: 评分理由。本题仅涉及进程管理中的同步机制，未跨越内存管理、文件系统或I/O等其他子系统，属于单系统内部逻辑，跨域联动需求微弱。
- **雷达形状**: K1-K4高位型（概念辨析与逻辑陷阱主导），K2-K5低位型。呈现典型的“理论深度型”特征，非计算导向。

## 考察模式
- **模式**: 推理型
- **理由**: 本题并非直接考查定义背诵（概念型），也不是数值计算（计算型），而是要求考生将给定的代码逻辑映射到抽象的同步理论定义上，通过构造特定场景（如P0不运行）来验证理论条件是否满足，属于典型的逻辑推理与映射分析。

## 选项级分析
- **选项A**: [干扰] — 针对“算法看起来像轮流执行，所以应该是正确的”这一错误认知。这类学生往往只看到了代码的对称性，忽略了同步算法必须满足的严格数学定义，误以为“能运行”等于“正确”。
- **选项B**: [干扰] — 针对“互斥”概念的误解。由于`turn`变量在同一时刻只能为0或1，确实保证了只有一个进程能通过while循环，因此互斥是满足的。选此项的学生可能误以为简单的变量赋值无法保证原子性或互斥，或者混淆了互斥与进展的概念。
- **选项C**: [正确] — 正确识别出该算法是“严格交替法”（Strict Alternation）。当P1希望进入临界区而P0不希望进入（或P0尚未启动）时，P1会被`while (turn == 0)`阻塞，因为`turn`初始为0，只有P0执行完退出后才会将`turn`设为1。这违反了“进展”要求：即当没有进程在临界区且至少有一个进程希望进入时，不应由那些不在临界区的进程决定谁进入。
- **选项D**: [干扰] — 针对“有限等待”与“进展”的混淆。有限等待要求进程在有限次尝试后必须进入。在该算法中，一旦P0运行一次，P1就能进入，等待次数是有限的（最多等待P0运行一次）。选此项的学生可能认为“P1要等P0”就是无限等待，未能区分“等待时间/次数有限”与“能否进入取决于对方”的区别。
- **干扰策略**: 概念混淆。主要利用“进展”和“有限等待”在字面意思上的相似性，以及“轮流执行”带来的公平性错觉，诱导考生排除正确答案。

## 核心陷阱
- **核心陷阱**: **“进展”与“有限等待”的定义混淆**以及**对“严格交替法”缺陷的忽视**。
  考生容易误以为只要进程最终能进去（有限等待满足），算法就是好的。实际上，该算法最大的问题是**控制权依赖**：P1能否进入完全取决于P0是否愿意退出并修改`turn`。如果P0不运行，P1即使急需进入也无法进入，这直接违反了“进展”原则（Progress Condition）。

## 考察能力
一句话概括本题核心考察的能力：
能够准确区分进程同步三大必要条件（互斥、进展、有限等待）的定义，并能通过代码逻辑推演识别经典同步算法（如严格交替法）的理论缺陷。
